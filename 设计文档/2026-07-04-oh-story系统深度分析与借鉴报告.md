## 〇、执行摘要(先给结论)

**两者是两种形态,不是替代关系**:
- **oh-story** = "惊艳的结构化写作知识资产 + 轻到一行 `npx skills add` 可装的多端插件"(Claude Code + 文件系统 + skill 编排,无独立后端/DB)。
- **scribe3** = 重后端、有状态、可查询、有事务约束的写作引擎。

**scribe3 的护城河已被实读实锤(继续加深即可)**:oh-story 的"状态追踪/限知/伏笔弧光"是靠 Markdown + LLM 纪律硬凑的**伪状态机**——demo 里 `伏笔.md` 的"预计回收章节"列几乎全是 `[待补充]`、状态冻结在导入时刻、`时间线.md` 全是不可运算的相对时标字符串。它连"第47章角色X是否知道事实Y"都答不了,只能重读推断,规模化(续到80章/伏笔200条)必然漂移。**scribe3 的 DB 状态层 + 限知引擎(配角不批发真相/POV漂移检测/focalizer锚)正是 oh-story 做不到的。**

**scribe3 该学的,是 oh-story 的「写作工艺 + 流程编排 + 确定性质控」,而非它的状态实现**。全部可搬内容均为**题材无关、零/低 LLM 依赖、与 scribe3 已有机制同构(补而非重)**。

**一个关键架构发现**:scribe3 已经建好一个 **per-work 题材层接缝**(`store.py:seed_craft_rules`、`enums.py:CraftRuleKind`、`craft.py:build_craft_block(rules)`、`critique.py` 的 `extra_patterns`、MCP `s3_craft_rule_*`),但**只填了「乱世铜炉」8 条升华正则 + 法器四件套,是空着的**。oh-story 的题材包/词表/检测规则正好填这个缝。

**Top 借鉴一句话**:① 三个 deslop 脚本移植进 critique.py(最高性价比、当天可落地);② story-import 逆向导入(scribe3 底座已备 80%,且能补掉 oh-story 逆向账本"冻结快照"的致命短板 = 把别人做不稳的做扎实的获客能力);③ 对标模块化闭环(把素材库从静态资产升级为写作时被主动消费的驱动器);④ 字数预算/章节定位/连续性状态机(纯 prompt 工艺,零成本)。

## 一、oh-story 系统全景

### 1.1 定位与信条
"网文写作方法论的可执行化"——把"扫榜找方向 · 拆爆款提模块 · 商业化写作"的专业作者三步流程,做成插件。核心信条:**"套路 = 确定性的情绪满足"**。

### 1.2 13 个 skill 的编排关系

```
   环境部署 ──▶ story-setup(部署 hooks/agents/rules,一次性)
   意图路由 ──▶ story(按关键词分发)

   ── 长篇线 ────────────────────────────────────────────────
   long-scan ─▶ long-analyze ─▶ long-write ─▶ review ─▶ deslop
   (真机扫榜    (拆爆款Stage0-6   (5 Phase:选题    (4 agent   (确定性
    选题决策)    情绪模块/节奏/文风) →设定→大纲→正文→质检) 对抗审+平台rubric) 去AI味)
                      │                ▲
                      └─ story-import ──┘ (已有小说→拆解→迁成可续写工程)

   ── 短篇线(独立参考栈,4 题材包)─────────────────────────
   short-scan ─▶ short-analyze ─▶ short-write ─▶ review ─▶ deslop

   ── 通用/工具 ─────────────────────────────────────────────
   story-cover(GPT-Image-2封面) · browser-cdp(登录态爬虫) · explorer/researcher(查询agent)
```

长短篇是**两条真分线**:短篇 v0.6.21 已把长篇继承的 references 全删,建了专属 `short-format/short-craft/short-deslop` + 4 题材包(追妻火葬场/复仇打脸/总裁豪门/宅斗宫斗)。

### 1.3 支撑编排的四层机制

| 层 | 内容 | 时机/阻断性 |
|---|---|---|
| **对标真相源** | analyze 产出 `情绪模块.md`+`节奏.md`+`文风.md`,write 每章"模块召回"消费;**冲突以权威文件为准,拆文报告只是投影**(canonical read order) | 写作时 |
| **7 分级 agent** | Opus(架构)/Sonnet(写作)/Haiku(只读检索/拆章);全链路 fallback:agent 不可用降级 solo/direct 并报告 | 编排层 |
| **8 hooks** | `guard-outline-before-prose.sh`(**exit 2 阻断**:无细纲禁写正文)、`check-prose-after-write.sh`(落盘后硬信号兜底)、`detect-story-gaps.sh`、`validate-story-commit.sh` | Session/Pre/PostToolUse |
| **确定性脚本** | 3 个 Node 脚本(check-ai-patterns/check-degeneration/normalize-punctuation),**4 skill 里字节完全一致**,CI 守恒;全部 **report-only 永不改写**(安全动作=回炉重生成把 finding 当约束喂回) | 收尾/落盘 |

**质检元原则(scribe3 最该学)**:同一套"轻量确定性网"在 Claude(bash+python)/Codex(python)/OpenCode(TS) 三处各实现一份,`test-prose-net-parity.sh` 锚定逐字一致;检测器 **report-only 永不改写**,负例专防误伤网文体裁手法(弹幕刷屏/短句排比/对话复沓/纯台词×3)。

### 1.4 demo 产出质量(实读评估)

| demo | 评分 | 关键证据 |
|---|---|---|
| 长篇正文《让你管账号…》20章 | 正文 3.5/5,大纲+追踪 4/5 | ~2200字/章标准番茄爽文;真在执行 `文风.md` 的 `【】` 播报格式;但第20章连续三个"一时间"起句+弹幕墙同质化(AI腔)。卷纲逐章打压力级/情绪强度双数值,**自带元级批判**("第16-20连5章同母题=疲劳源") |

| 短篇拆书《曾将爱意私藏》8500字 | 4.5/5(结构化最高) | **唯一机器可读产出**:`_meta.json.structure_counts` 配门控阈值表(beats≥4✓/hooks≥3✓,代码可判);54 情节节点每个带情绪 -9~+9 强度,可直接画情感曲线 |

## 三、可借鉴清单(分三类,含 scribe3 落点)

### A. 直接复用 —— 确定性检测规则/词表(→ `scribe3/critique.py`)

#### A1. 三个 deslop 脚本移植成 critique.py 函数【最高性价比·当天可落地】
源:`skills/story-deslop/scripts/{check-ai-patterns.js, check-degeneration.js, normalize-punctuation.js}`
- **否定翻转句检测** `findNotIsComparisons` → 补 scribe3 `critique.py` 的 `_NOT_A_BUT_B`(现只命中破折号变体,**漏掉「不是A是B / 不是A而是B / 不是A，是B」三种无破折号变体**——中文 AI 头号指纹)。附带一整套**假阳性护栏**别人已踩坑填好:`是不是`(疑问)/`只是可是于是倒是`(连词尾)/`不是A就是B/也是B`(either-or)/`…是吗吧嘛`(反问尾)——自己写必翻车,直接搬。
- **退化检测** `check-degeneration.js` → 新增 `find_degeneration`,查**模型自己发现不了**的:紧邻整行复读(≥8字)/全文同长句≥3次、末尾截断(末行无收尾标点)、占位/拒绝语泄漏(`作为AI`/`我无法继续`/乱码`�`/英文AI腔)、**工程词泄漏**(tier1 `细纲/情节点/卷纲/字数目标/章首钩子`=blocking;tier2 `第N章/本章/伏笔/读者/任务描述`=advisory)。**工程词泄漏直击 scribe3 已知痛点**(从 beats/outline 写 draft,工程词漏进正文是真实退化路径,现管线不查)。
- **确定性标点归一** `normalize-punctuation.js` → scribe3 落章后机械标点收尾:按上下文把 `……/——/--` 替换成 `。/，/：/到`(数字区间)或删除,YAML/代码块/引号感知。这是唯一"会改写"的脚本,可作**建议替换**而非仅标记。

#### A2. 引号剥离豁免 `stripQuoted`(跨检测器方法论升级)
源:两个 Node 脚本共用的 `stripQuoted()`(剥 `「」『』【】""''`)。→ 改造 scribe3 现有 `find_repetitions`/`find_parallelism`/`find_structural_repeats`,让**纯台词/弹幕复沓、对话排比不误报,混合行引号外仍判**。这是 oh-story 防"通俗网文合法重复被误杀"的核心手法,**直接降低 scribe3 检测器假阳性**。

#### A3. 中文禁用词分级表 + 白名单 → 扩容 `find_ai_tics`
源:`skills/story-deslop/references/banned-words.md`。**★★★★★最毒「不是A(而)是B」** + 一级词表(按情态/动作/表情/心理/判断/形容/过渡分类:`仿佛/犹如/一丝/一抹`、`深吸一口气/缓缓/不禁`、`眼中闪过/嘴角勾起`、`心中一动/心头一震`、`不容置疑/显而易见`…)+ 二级语境敏感(`突然/好像/瞬间`)。配 `.deslop-whitelist` **子串豁免**防误伤设定术语/绰号/地名。纯数据搬运、低风险。

#### A4. 上帝视角标志词 → 并入限知泄露 `find_leaks`
源:`skills/story-deslop/references/anti-ai-writing.md` 模式8。词表 `她不知道的是/殊不知/多年以后/冥冥之中/仿佛预示着 / 之所以…是因为/原来/这意味着 / 演得真好/他就是这样…的人`。→ `她不知道的是/殊不知` 正是 scribe3"知情 POV 倒灌"的**确定性语言指纹**,补足纯语言层漏网。与 scribe3 限知引擎同一哲学的文字层落地。

#### A5. AI味6指标整章定档聚合层
源:`skills/story-deslop/SKILL.md`「AI味打分客观指标」——禁用词密度/连续排比段数/心理词占比/对话标签密度/平均段落句数/重复描写密度,各配轻/中/重阈值,取最高档定章级。→ scribe3 critique 是**分项检测,缺这套整章聚合定档层**。新增聚合函数。

#### A6. 弱化副词密度(统计型)+ 碎句号节奏
源:`anti-ai-writing.md` 模式2(`微微/淡淡/缓缓/轻轻` 每千字>3=AI签名)+ `check-ai-patterns.js` 碎句号(连续≥6短叙述句每句可见字≤5)。→ scribe3 有排比检测但无"副词密度"和"碎句号"两种节奏维度,碎句号复用 A2 引号剥离防对话误伤。

### B. 直接复用 —— 写作工艺(纯 prompt/结构,零成本移植)

#### B1. 情节点字数预算契约 → 节拍/演绎阶段【根治欠字反复回炉】
源:`skills/story-long-write/references/artifact-protocols.md`。每情节点标 **密/疏 + 字数预算**(密≥250/慢镜头爽点400-600/疏≈40),各点求和 **Σ∈[章目标, ×1.1]**,末尾写 `预算合计:X字`;写后按预算定位欠账密点一次性重写。→ scribe3 节拍阶段无此机制,防均匀注水/挤牙膏。

#### B2. 章节定位六型 + 卷级张弛配额 → 破"每章都逼成强钩子"
源:`skills/story-long-write/references/outline-structure-theory.md`。每章打 `压力级1-5` + `chapter_role`(高压/推进/修炼/关系回收/低压/信息整理),卷内占比配额(高压15-20%/低压≤10%/信息整理≤5%),铁律"同情绪母题别连超2-3章"。→ 做成 scribe3 **卷级分布检测 + 相邻章母题去重滑窗**(CHANGELOG #198 盲评证明有效)。低压/关系章允许无显性爽点但保留追读拉力。

#### B3. 连续性追踪状态机 → brief.py + 伏笔台账(补角色/关系维度)
源:`skills/story-long-write/references/plot-core-methods.md`「连续性追踪与节奏管理」。给角色/支线/伏笔/关系维护 `heat∈{hot,warm,cold,archived}` + `last_touch_chapter`;**有效触碰判定**(推进/施压/改变关系/产生后果才算,提名字/空头回调不算);回顾阈值(核心角色3-5章/主要支线4-6章/活跃伏笔2次错过);冷却章节数(conflict_thrill最多连2章、每5章必含bond_deepening)。→ 纯时序、题材无关,与 scribe3 `promise_touch`/`salience_gap` 同构,**补齐伏笔台账缺的角色/关系维度**。brief.py 章前拉"该warm却cold"的实体强制回收。

#### B4. 4级情绪表达层级 + 失败模式阈值 → find_emotion_telling 升级
源:`style-craft.md` 4级情绪rubric(直写→思想→神态→动作)+ `emotional-methods.md` 失败模式阈值(太平=连续≥5节无转折/太赶=转折铺垫<3节/烂尾=反转后交代>2000字)。→ 把 scribe3 `find_emotion_telling` 从 0/1 升级成 **4级评分**;失败模式阈值 = 新增跨章节奏检测。

#### B5. 反转工具箱 + 悬念/伏笔边界 → beats 结构字段 + 反转 rubric
源:`reversal-toolkit.md`(7类反转,已与 `_meta.json.reversal_type` 枚举对齐)+ `story-short-analyze/references/hooks-suspense.md`「悬念vs伏笔」边界表。→ beats 记 `{reversal_type, setup_clues[≥3], reveal_position_pct}`;`critique.py` 建 `build_reversal_rubric_prompt` 机检(铺垫<3处/揭示>300字/引入前文未现新信息/位置越出最佳区间);**"叙述者必须真诚相信自己视角"固化为 focalizer 引擎硬约束**;短期悬念独立于长期伏笔分账(scribe3 现混在伏笔台账)。

### C. 新能力/新轴(scribe3 空白,底座部分已备)

#### C1. 对标模块化重组闭环 ⭐最高价值
源:`skills/story-long-write/SKILL.md:367-377` + `story-long-analyze/references/output-templates.md`(情绪模块卡 EM/RH/TR schema)。**不是"写得好",而是"拆爆款→提炼可复现的情绪模块+节奏→写作时每章按情绪召回1个模块+1条节奏"闭环**。关键:`情绪模块.md`/`节奏.md` 是**权威真相源,拆文报告只是投影,冲突以权威为准**。→ 把 scribe3"真素材库"从静态资产升级为**写作时被主动消费的驱动器**:扩 `material` 一个 kind(情绪模块卡),brief.py 章前按目标情绪召回。**引入 canonical-read-order 纪律**(谁是真相源/谁是投影/冲突怎么裁决)。

#### C2. story-import 拆书导入 ⭐战略价值最高·底座已备80%
源:`skills/story-import/`(角色状态6步反推、伏笔逆向提取、追踪生成依赖链)+ `story-long-analyze/references/material-decomposition.md`(事实保真三硬约束)。作者贴已发布前 N 章 → 自动反推 bible+状态账本+对标 → 从 N+1 章无缝续写。**scribe3 `ingest.py:ingest_chapter` 已是单章逆向内核,schema 比 import 更强**(promise 有 payoff_min/max 区间+tier+红鲱鱼)。搬运方向=**用 import 逆向流程填 scribe3 已有更强 schema**:
- 角色状态6步 → `store.py:reverse_current_state(char_id)`(对 char_states 取 max(chapter));待回收伏笔 → 复用 `promises_with_lifecycle` 筛 open,**字段一一对齐**(import「埋设章节」=`setup_chapter`、「预计回收」=`payoff_min/max`、「已埋/已回收」=`status`、「重要度」=`tier`);
- 唯一真新工作量:**弧光锚 ghost/lie/truth/want/need 逆向**(LLM 从整书弧线专抽);
- 必带"事实保真 + `[待补充]`禁编造"纪律防设定污染。
- **战略点**:scribe3 的 DB 状态层恰好补掉 oh-story 逆向账本"冻结在导入快照"的致命短板——把别人做不稳的功能做扎实,是极强的获客/迁移能力。

#### C3. 三平台留存商业轴 → critique.py 补空白轴
源:`skills/story-review/references/rubrics/{qidian,fanqie,zhihu}.md` + S1-S4 映射 + verdict 门槛。→ scribe3 `build_tension_rubric_prompt` 只有**内在戏剧轴**(dramatic_question/outcome_grammar/value_shift/hook)、返布尔无严重度无裁决。新增 `build_platform_rubric_prompt(prose, platform)`:确定性指标(爽点密度每3000字/情绪节点每1000字/字数区间)进 `brief.py:tension_deterministic`,预估指标(追读比/完读率/跳失率)走 LLM;叠 **S1-S4 严重度 + APPROVE/CONCERNS/REJECT 汇总层**,把布尔检测项升级成可决策结论。按 work 的 `target_platform` 选表。

#### C4. 选题立项前置 → project_charter 节点
源:`skills/story-long-scan/references/{topic-decision.md, reader-profiling.md}`。选题四步(能爆原因/市场验证/差异化/可行性+风险)+ 可行性三档硬规则(`[数据稀疏]`<15条不许给"高")+ 9维读者画像 + 70/20/10 元素法。→ scribe3 **完全空白**,可做 `project_charter` 节点,画像下沉为写作/critique 门禁参数。爬虫属基础设施可跳过(除非做"选题→写作"完整漏斗)。

#### C5. 四个题材包填满 craft_rule 接缝 + 短篇模式开关
源:`skills/story-short-write/references/genre-styles/`(追妻火葬场/复仇打脸/总裁豪门/宅斗宫斗)+ `short-craft.md` 情绪判据 + `short-deslop.md` 别删清单。→ **scribe3 已建好 `craft_rule` 接缝却只填了乱世铜炉**。每题材包做成 per-work bundle:金句/招式→`build_craft_block` 注入,"别删清单"→`find_purple_prose`/`find_emotion_telling` 的 `extra_patterns` 豁免;并加**"短篇/题材模式"开关反转 `find_emotion_telling` 与 `ENGINES["restraint"]`**(短篇要直写情绪+审判金句,否则被长篇克制引擎全线误杀)。让 scribe3 跨出长篇克制美学、能写多题材的低成本前提。

#### C6. 封面生成(story-cover)+ 兜底网门控范式
- 封面:`skills/story-cover/`(GPT-Image-2 一次出含标题封面 + 平台尺寸裁剪),作者刚需的"最后一公里"交付物,与写作引擎解耦、接入成本低,外围低优先。
- **兜底网门控范式**(机制非规则):`check-prose-after-write.sh` 的"过度捕获门 + 硬信号子集 + 非阻塞静默 + report-only 回炉重生成"四原则 + 字数欠账(对细纲字数目标<90%)。→ scribe3 `/chat/write` 落章后、ingest 前挂一道硬信号轻量网,命中即把 finding 当约束回炉重写该章(对齐 scribe3 已验证的 continue-steer)。"过度捕获门 + 静默放行 + 非阻塞"三原则直接照搬。

### D. 形态层"轻量化"启发
- **确定性质控做成"无服务独立脚本"**:oh-story 3 检测器纯 Node、任何 CLI 都能跑、不碰后端。scribe3 若某些兜底检测压在后端,抽成可独立运行小脚本(pre-commit/落盘钩子)能降耦合加复用。
- **七角色职责边界体系**(`story-setup/references/templates/agents/`):带"拥有/不拥有/升级路径"的多智能体分工 + **成本分档**(只读检索用 haiku/架构用 opus)。→ scribe3 每步 LLM 调用可按创作/检索/核对分配模型档位省成本;单体主编若要多角色编排,这是最佳蓝本。

## 五、明确不要搬 / scribe3 已更优

**不要搬(题材错配)**:genre-catalog/genre-writing-formulas 的爽点/打脸/金手指/后宫骨架是短篇通俗向,与 scribe3 严肃/志怪文学定位最错配,直接搬会把 scribe3 拉回爽文向。部分套路桥段(标志性动作库/驱逐台词库)反而应作 **critique 的反面词表(陈词滥调检测)**,不作生成模板。

**scribe3 已更优、跳过**:
- **状态追踪/限知/伏笔弧光**:oh-story 是伪状态机(Markdown/无schema/冻结快照/规模化漂移),scribe3 DB 有状态 + 限知引擎可判定——**确认护城河,继续加深**。
- **工作流硬强制**:oh-story 只能 bash hook exit 2 近似阻断,scribe3 后端可原生真状态机硬强制。
- story-explorer 的 context_load ≈ `brief.py`;state-tracking「只保留不知道就会写错的信息」≈ `brief.py:select_injection`(M6 三态注入更工程化);subtext/sensory/dialogue 潜台词技法已在 `ENGINES` 覆盖。

**两条哲学一致的印证(佐证非搬运)**:deslop 的 Gate G「锁死深度限知,作者就没位置跳出来说教」与 scribe3 focalizer 引擎同源;cross-book-recall「副对标文风不读防污染」与 scribe3 信息屏障同源。
