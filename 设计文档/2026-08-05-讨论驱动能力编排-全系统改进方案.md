# 讨论驱动能力编排 · 全系统改进方案

> **日期**：2026-08-05  
> **状态**：方案（待 goal 拆批落地）  
> **范围**：**全部**正典能力域（不限角色设定）  
> **约束**：不违背对话驱动写铁律（讨论 → 结构化提案 → 人批 → 落库 → 只读刷新）  
> **前序**：`2026-07-22-对话驱动写入-禁表单直填` · `2026-08-05-写作导演Director` · `AGENTIC_BOUNDARY_DECISION`

---

## 0. 一句话目标

> 作者只负责**聊、批、选**；系统负责**听懂话题 → 打开对的舞台 → 调用对的读写工具 → 生成可批提案 → 落库后跟焦刷新**。  
> 智能做在**编排层**；落库仍做人闸。**禁止**「聊天原文自动变正典」。

---

## 1. 问题诊断（深度）

### 1.1 作者心智 vs 系统实际

| 作者以为 | 系统实际 |
|----------|----------|
| 聊到哪，系统在办哪 | 大多只是**回话**；UI 不跟、工具不跟 |
| 「接受/好」= 已写入设定/大纲 | **口头同意 ≠ 写库**；须 MCP 写工具 + 批准 |
| 所有能力都该统一逻辑 | 通道分裂：正则分流 / 两套流 / 种子话术 / Pilot / 导演 P0 各管一段 |

### 1.2 现状能力栈（分层）

```text
┌─────────────────────────────────────────────────────────────┐
│ UI 舞台（设定/章阶段/伏笔/旅程…）  ← 几乎只靠人手点，不跟聊  │
├─────────────────────────────────────────────────────────────┤
│ 前端分流 shouldUseHermesRun（正则）                         │
│   写意图词 → Hermes Run(可写)  |  否则 → chat/write        │
├─────────────────────────────────────────────────────────────┤
│ 组装链 write_assemble：注入设定/意图/章/phase（上下文）       │
├─────────────────────────────────────────────────────────────┤
│ 模型 function call → MCP s3_*（读自由 / 写须审批）           │
├─────────────────────────────────────────────────────────────┤
│ Surreal 正典  +  live/SSE 刷新（不保证 focus 到对象）        │
└─────────────────────────────────────────────────────────────┘
```

旁路（未统一）：

- `seedChief*` / `s3-chief-seed`：UI 按钮塞话术，**不保证**模型真调工具  
- Pilot 状态机：章流水线，**不驱动**设定/伏笔/关系编排  
- Director P0：只**看见**进度 + 预填聊天，**不调**工具、不跟焦  
- 正文 `⟦PROPOSAL⟧`：只改手稿，**不进**设定库  

### 1.3 根因（五条）

| # | 根因 | 后果 |
|---|------|------|
| R1 | **无统一意图对象**（WorkPackage） | 每条消息临时猜，无「当前在办补角色/改大纲」 |
| R2 | **通道与工具白名单割裂** | 讨论流常无写工具；写意图靠关键词，漏检就只聊天 |
| R3 | **模型可空口答应** | 无「本步必须 function call」硬约束 |
| R4 | **UI 与执行脱节** | 无 `director.focus` / 批准后跟焦 |
| R5 | **提案粒度偏工具而非作者语义** | 缺批量 WriteProposal 卡（2026-07-22 已设计未全落地） |

### 1.4 不是问题的部分（勿推倒）

- 正典写必须审批（`commit_if_approved`）——正确  
- 限知 / secret 门控——正确  
- 素材作者直管、非正典——正确  
- 上下文组装已能注入大量设定——讨论「瞎编」主因是**空库/未强制写**，不是完全没注入

## 2. 目标体验（统一逻辑，覆盖全域）

### 2.1 作者只做三件事

1. **说**：自然语言（或点旅程「继续」预填）  
2. **批**：一张（或一批）写入提案  
3. **选**：正文提案接受/弃用  

系统保证：

- 知道**当前工作包**（补角色 / 起大纲 / 埋伏笔…）  
- **舞台自动**打开对应只读页  
- **工具白名单**只允许本包相关 s3_*  
- 聊完该写时**必须出提案**，禁止「已记下」空话  
- 批准后**自动刷新并 focus** 刚写入对象  

### 2.2 端到端示例（全域同构）

| 讨论内容 | 工作包 | UI 自动 | 允许写工具（示例） |
|----------|--------|---------|-------------------|
| 主角欲望/恐惧 | `codex.character` | 设定→该角色 | add/patch_character, set_char_anchors |
| 两势力对立 | `codex.faction` | 设定→势力 | add/patch_faction, entity_relation |
| 本书红线 | `intent.northstar` | 北极星面板 | set_intent |
| 第 12 章大纲 | `chapter.outline` | 章·大纲 | patch_chapter_meta/plan |
| 节拍字数 | `chapter.beats` | 章·节拍 | patch_chapter_plan |
| 场景真相 | `chapter.deduce` | 章·演绎 | patch 演绎相关 |
| 埋/还伏笔 | `promise.*` | 伏笔详情/简报 | plant/advance/patch/abandon… |
| 母题回响 | `motif.*` | 母题 | add/patch_motif |
| 卷结构 | `structure.volume` | 手稿树 | add/patch_volume, reorder… |
| 改正文 | `prose.*` | 草稿/正文 | 正文 PROPOSAL（非 MCP 世界写） |
| 关系推进 | `relation.*` | 角色/关系 | add_character_relation, evolve… |
| 声线 OOC | `voice.*` | 声线 | set_voice_profile, resolve_flag… |

**同一逻辑**：`Intent → WorkPackage → Stage + ToolAllowlist → Proposal → Approve → FocusRefresh`。

## 3. 目标架构

### 3.1 五层模型

```text
L0  旅程/进度     WorkflowSnapshot（书站 + 章 pilot + blockers）     [P0 已有雏形]
L1  工作包编排    WorkPackage 状态机 + 意图分类                     [核心新增]
L2  执行通道      DiscussionRun | WorldWriteRun | ProseWrite         [统一入口]
L3  工具与门控    MCP 读 / 写 + WriteProposal 批量审批              [强化]
L4  舞台投影      ui_directive：entry/phase/node/right_tab          [程序强制]
```

### 3.2 核心对象

#### A. `WorkPackage`（当前在办什么）

```json
{
  "id": "wp_…",
  "domain": "codex.character",
  "status": "discussing|proposing|awaiting_approval|applied|parked",
  "focus": {"type": "character", "id": "role:沈砚", "label": "沈砚"},
  "goal": "补齐欲望/恐惧/表层目标",
  "tool_allowlist": ["s3_patch_character", "s3_set_char_anchors", "s3_get_*…"],
  "tool_denylist_extra": [],
  "ui_directive": {"entry": "codex", "node": {"type": "character", "id": "role:沈砚"}},
  "required_outcome": "write_proposal|prose_proposal|read_only_advice",
  "source": "user_msg|director_next|blocker|seed_button"
}
```

规则：

- **任意时刻最多 1 个 active WorkPackage**（可挂起队列）  
- 讨论消息默认绑定 active 包；作者可说「先放下，改谈伏笔」切换  
- `required_outcome=write_proposal` 时：本回合结束若无写工具调用 → **系统补强**（见 §5）

#### B. `WriteProposal`（作者语义提案，多 op）

对齐 2026-07-22，全系统统一：

```json
{
  "id": "prop_…",
  "summary": "登记角色沈砚并设锚点",
  "work_package_id": "wp_…",
  "ops": [
    {"tool": "s3_add_character", "args": {}, "label": "新建·沈砚", "risk": "medium"},
    {"tool": "s3_set_char_anchors", "args": {}, "label": "弧光锚", "risk": "medium"}
  ],
  "ui_after": {"focus": "character:role:沈砚"}
}
```

UI：**一张卡**——全部批准 / 全部拒绝 / 剔掉单条。  
批准 = 顺序执行 `commit_if_approved`（或批量事务策略见 §7）。

#### C. `CapabilityCatalog`（域注册表，单一真相）

每个 domain 登记：

| 字段 | 含义 |
|------|------|
| `domain` | 如 `codex.character` |
| `match` | 关键词 + 实体链接 + 可选分类器标签 |
| `read_tools` | 进入包时建议先读 |
| `write_tools` | 允许写入白名单 |
| `ui` | entry / 默认 phase / node 模板 |
| `completeness` | 最低完备检查（缺什么进 blockers） |
| `seed_templates` | 预填聊天句 |

**所有域同一注册方式**，扩展新能力 = 加一条 catalog，不写散落 if。

## 5. 意图识别与通道统一（智能放哪）

### 5.1 三级意图（由稳到智）

| 级 | 机制 | 用途 |
|----|------|------|
| L1 确定性 | 实体链接（@角色）、当前 focus、active WorkPackage、按钮 seed | 默认优先 |
| L2 规则 | 扩展版 domain 词典（替代仅 hermesRunIntent 二元） | 冷启动 |
| L3 模型 | 小分类器 / 主编首步 `director.classify` tool | 歧义消解 |

**禁止**仅靠自由聊天「感觉该写了」。

### 5.2 统一发送入口 `DirectorSend`

取代「前端正则二选一」为：

```text
DirectorSend(msg):
  1. resolve_intent → WorkPackage (create|continue|switch)
  2. apply ui_directive（先切舞台，再请求）
  3. build_run_config:
       tool_allowlist, force_write_proposal?, phase, chapter
  4. 一律走可观测 Run（或 Discussion 带只读工具）
  5. 回合结束 policy:
       if required_outcome=write_proposal and no write calls:
         emit system nudge + 一键「生成写入提案」
```

`shouldUseHermesRun` **降级**为 catalog 的一小段匹配，不再是唯一真理。

### 5.3 「强制产出」策略（反空口）

当 WorkPackage.`required_outcome == write_proposal`：

1. Instructions 声明：本步结束前必须调用白名单内写工具（或显式 `s3_propose_noop` 说明为何不写）  
2. 服务端回合审计：无写调用且无 noop → 状态 `incomplete`，UI 黄条  
3. 一键补救：`「根据以上讨论生成写入提案」` → 结构化抽取 → WriteProposal 卡  

智能 = **检测偷懒 + 补救**，不是默默当写成功。

## 6. UI 跟焦协议（程序强制）

### 6.1 `ui_directive` 事件总线

```json
{
  "entry": "codex|manuscript|…",
  "phase": "outline|beats|deduce|draft|final|null",
  "node": {"type": "character", "id": "role:沈砚"},
  "right_tab": "chief",
  "layout_mode": "collaboration|reading",
  "highlight": ["field:fear"]
}
```

来源：

- WorkPackage 激活  
- WriteProposal 批准成功（`ui_after`）  
- 旅程「继续」  

实现：扩展现有 `onSel` / `s3-chapter-phase` / `s3-right-tab` / `s3-open-capability`，**单一 `s3-ui-directive` 汇总**。

### 6.2 防抖与用户控制

- 3s 内最多自动 focus 1 次  
- 「钉住当前页」开关：导演不抢焦点  
- 专家模式：关闭自动跟焦

## 7. 写入与审批（全域统一）

### 7.1 单一作者可见写路径

```text
讨论/工具调用 → WriteProposal(ops[]) → 人批 → commit_if_approved* → live 刷新 → focus
```

正文：

```text
讨论/生成 → ProseProposal → 接受/弃用 → 手稿
```

### 7.2 批量与原子性

| 策略 | 适用 |
|------|------|
| 尽力而为 + 失败条目标红重试 | 默认（跨工具难事务） |
| 同实体多字段合并单工具 | 优先（patch 一次） |
| 宪法级（finalize） | 永远单独 approve |

### 7.3 与 seed 按钮关系

所有「让主编…」按钮改为：

1. 激活对应 WorkPackage  
2. 下发 ui_directive  
3. 预填 **强制提案** 话术（含工具名）  
4. 走 DirectorSend  

禁止只 `sessionStorage` 塞一句希望模型自觉。

## 8. 与 Pilot / 旅程 / 经验压力 的咬合

| 模块 | 角色 |
|------|------|
| **WorkflowSnapshot** | 显示「书站 + 章 lane + next_step」；next_step **生成/切换** WorkPackage |
| **Pilot** | 章流水线执行器（outline→…→finalize）；包 `chapter.*` 完成度驱动 pilot 推进建议 |
| **经验压力** | blockers 来源（问诊项、六格空洞、重读）；blocker 点击 → 开对应 WorkPackage |
| **设定完备 s3_setting_completeness** | 世界站 / codex 包的完备输入 |

原则：**Pilot 不管设定细节；Catalog 管域；Snapshot 管导航；三者共享 WorkPackage。**

## 9. 智能程度分层（诚实预期）

| 层级 | 能力 | 推荐实现 |
|------|------|----------|
| L0 规则 | 关键词 + @实体 + 当前 focus | 必须，默认 |
| L1 状态 | WorkPackage 状态机 | 必须 |
| L2 约束解码 | 工具白名单 + 强制提案审计 | 必须 |
| L3 分类模型 | 歧义意图分类 | 可选增强 |
| L4 全自动写库 | 无审批写入 | **禁止**（正典） |

「很智能」= L0–L3 做好；**不是**取消审批。

## 10. 分期落地（完善可执行）

### 包 A · 编排骨架（2–3 周）—— **最高优先级**

1. `CapabilityCatalog` 数据文件 + 加载器  
2. `WorkPackage` store（按 work 持久化，可 settings 或 Surreal）  
3. `DirectorSend` 后端入口（或前端先调后迁）  
4. `ui_directive` 总线 + 批准后 focus  
5. 替换/收编 `shouldUseHermesRun`  

**验收**：聊「写入角色 X 的恐惧」→ 自动开角色页 → 出审批 → 批准 → 库中有字段且页刷新。

### 包 B · WriteProposal 统一卡（2 周）

1. 多 op 提案 UI  
2. 全域写工具结果归一为 proposal  
3. seed 按钮改走包 B  

**验收**：一句多意图（角色+关系+北极星）→ 一张卡三条 → 可剔条批准。

### 包 C · 域铺满 Catalog（2–3 周）

按 §4 注册全部 domain；每个 domain 至少：match、tools、ui、一条 e2e 冒烟。

### 包 D · 完备与旅程咬合（1–2 周）

1. completeness 钩子进 Snapshot blockers  
2. next_step 只推荐「完备缺口」或 pilot 下一步  
3. 世界站未达最低完备时，弱化「直接大纲」主 CTA  

### 包 E · 智能增强（可选）

1. 意图分类模型 / 主编 `director.classify`  
2. 空口检测自动补救文案  
3. 专家模式开关

## 11. 风险与非目标

### 风险

| 风险 | 缓解 |
|------|------|
| 自动 focus 打扰 | 钉住页、防抖、可关 |
| 白名单过窄模型卡住 | 包内提供「升级工具」需二次确认 |
| 批量写部分失败 | 明确尽力而为 + 失败列表 |
| Catalog 膨胀 | 域按文件拆分，禁止抄工具表 |

### 非目标

- 取消审批自动改正典  
- 用第二套进度库替代 pilot  
- Scrivener 式全功能对标  
- 聊天原文直接解析灌库（无结构化提案）  

---

## 12. 成功标准（产品 + 技术）

| KR | 定义 |
|----|------|
| KR1 | 作者完成「新角色进库」无需打开表单编辑器，仅聊+批 |
| KR2 | 任一 Catalog 域：从讨论到只读页可见 ≤ 3 次点击（含批准） |
| KR3 | 空口答应率：required_outcome=write 的回合无写调用 < 10%（有补救后） |
| KR4 | 批准后 2s 内 focus 到对象（live 可达时） |
| KR5 | 不增加未审批正典写入路径 |

---

## 13. 决策摘要（供拍板）

| 决策 | 内容 |
|------|------|
| D1 | 全域统一 **WorkPackage + Catalog + WriteProposal + UI directive**，不单做角色 |
| D2 | 智能在编排与约束，不在无闸自动写 |
| D3 | 收编正则分流与 seed 话术，禁止多套真相 |
| D4 | Pilot/旅程/经验只产 WorkPackage，不各自偷偷写库 |
| D5 | 落地顺序 A→B→C→D→E |
