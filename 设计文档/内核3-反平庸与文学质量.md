## § 1 · 在回路中的位置与职责

### 1.1 为什么是内核,不是模块

旧版设计(17-文学质量机制设计)把文学质量放在"18 选 1"的平级功能模块里,排在连贯性、记忆、检索之后。这是**定位的根本错误**。

从设计哲学 §1 的矩阵来看:G7(结构)、G8(世界自洽)是"写得对",是 table stakes——那是门槛层的职责。**G1–G6(张力/情感真实/人物活/新鲜/主题/文字质感)才是"写得好",才是区分平庸与优秀的分界线。** 而这些恰好是 LLM 的结构性弱点:趋均值、无持久意图、训练偏好"完整显性最可能"。

更关键的是:**AI 全程主笔,无人在 prose 上兜底。** 没有编辑、没有作家在最终正文上把关。这意味着:

> **"反平庸"不能是事后检查,必须是生成的默认目标函数。**

这正是哲学文档 §4 原则 3 的表述。**本内核的存在就是让这条原则真正落地**,而不只是一条设计格言。

### 1.2 职责边界

**本内核负责**:

| 职责 | 说明 |
|---|---|
| 把"好小说"拆成 AI 可干预的维度 | G1–G6 → 具体的、有把手的操作点 |
| 反 AI 腔规则库(Anti-Slop Engine) | 病症分类 → 正则+LLM 双检 → 自动修复或标记 |
| 主动制造意外与张力 | 生成时就要求意外性、克制、延迟满足;不只是事后检查 |
| 文风 steering | StyleExemplar few-shot + style_descriptors + TasteModel 注入 |
| 文学评改环(Critique-Revise Loop) | 写得"好"的闭环评改;区别于门槛层的一致性校验 |
| 与内核1/2 的耦合 | 从 AuthorIntent 取北极星;从 TasteModel 取品味参数 |
| 诚实面对无银弹 | 效果须靠工程6 自建度量验证;不粉饰 |

**本内核不负责**:

- 一致性校验、伏笔追踪 → 门槛1
- 可度量指标的生产(H1/H2/H3/M 系列) → 工程6
- 角色 VoiceProfile 的维护 → 门槛2
- 初稿生产 → 实现2(本内核在实现2 之上或之内工作)
- TasteModel 的持久学习更新 → 内核2

### 1.3 在协作回路中的位置

```
        人(想象 + 意见)
             │
             ▼
    ┌─────────────────────────────────────────────────────┐
    │               内核层(系统心脏)                        │
    │  内核1: 捕获意图 ──→ AuthorIntent / OptionSet / Feed │
    │  内核2: 品味模型 ──→ TasteModel / StyleExemplar      │
    │  内核3: 反平庸  ──→ ★ 本文档                         │
    │    ↑ 从内核1 取"写这本书要让读者感受什么"(北极星)        │
    │    ↑ 从内核2 取"这个作者觉得什么是好/坏"(口味参数)      │
    │    ↓ 向实现2 注入:Anti-Slop约束 + Steering + 评改结果  │
    │    ↓ 向工程6 喂:SlopReport + CritiqueReport(供度量)   │
    └─────────────────────────────────────────────────────┘
             │
             ▼
    实现2(写作生成) ← 反平庸约束在此注入,不是写完再补救
             │
             ▼
    门槛层(连贯性/伏笔/一致) ← 写得对,后台静默运转
```

**最关键的架构决策**:反平庸的注入点在**写作生成(实现2)内部**,而不是在它完成之后。"生成时就要求"与"生成后再检查"是两种完全不同的质量策略——前者是内核的姿态,后者是门槛的姿态。

## § 2 · 设计目标与百万字挑战

### 2.1 设计目标

| 目标 | 描述 | 证据级别 |
|---|---|---|
| Anti-Slop 密度下降 | 经本内核处理后,病症命中率下降 ≥50%(自建度量基准) | 【设计决策,须工程6验证】 |
| 文风连续性 | StyleExemplar 与正文 embedding 余弦相似度均值 ≥0.75(每50章检测) | 【设计决策】 |
| 意外性提升 | 人评"意外但合理"比率(H2 pleasure 子项)裸生成 vs 经内核3处理后可测量提升 | 【设计决策,须工程6验证】 |
| 评改轮次可控 | 平均评改轮次 ≤2;终止条件明确;不无限循环 | 【设计决策】 |
| 北极星命中率 | AuthorIntent.reader_feeling 在评改后被 CritiqueAgent 判定"体现"的比率上升 | 【设计决策,须工程6验证】 |

### 2.2 六大百万字挑战

**① 趋均值是 LLM 的结构性问题,不是 Prompt 调参能根治的**
next-token 预测的本质是"最可能"——好故事要"出人意料又合理",与最可能相反。任何单一 Prompt 在百万字规模下都会被训练分布拉回均值。**需要系统性对抗,不是一次性修正。**【已核实 arXiv 2310.00785,BooookScore 发现连贯但平淡的权衡】

**② 文风漂移:第1章和第300章可能已是两个作者**
长程生成中 LLM 逐渐偏离初始文风,读者会产生"换人写了"的感觉。需要周期性文风基准对齐。【设计决策,参考主题漂移研究 arXiv 2508.03137】

**③ 审美疲劳:好风格重复也会变坏**
百万字连载中,即使初始文风良好,反复生成同样模式会让读者麻木。需要在统一性内引入有限变奏。【稳定知识:编辑学共识】

**④ AI 腔的累积效应**
单章命中率低,百万字累积后仍产生大量"AI感"。且 AI 腔有特定的模式分布(某些套语被旗舰模型过度强化),需要规则库持续维护。【设计决策+稳定知识】

**⑤ "好"的标准因人因书而异**
玄幻修仙的"好文笔"和纯文学的"好文笔"截然不同。系统不能有一套固化标准——必须从内核2 的 TasteModel 动态取参。【设计决策】

**⑥ 反平庸与成本的矛盾**
旗舰评改环每轮增加成本,百万字下不可能对每章豪华处理。需要分级质量档,按章节战略重要性分配资源。【设计决策】

### 2.3 核心诚实声明

> 【设计决策+稳定知识】"让 LLM 写出真正好看的小说"在学术与产业界均无银弹。本内核的机制是系统工程投入,不是质量保证。效果的唯一判断标准是工程6 的自建度量——尤其是人评 H1/H2/H3。**凡本文档做出效果声称的地方,均须视为待验证假设。**

## § 3 · 详细设计

### 3.1 "好小说"G1–G6 的 AI 可干预拆解

这是本内核设计的出发点。把哲学文档 §1 的读者体验目标,拆成 AI 写作时有把手的操作维度:

#### 3.1.1 G1 张力(放不下)→ 延迟满足 + 信息差控制

**LLM 的结构性问题**:训练偏好"完整作答",倾向尽快解决冲突、提前泄底——与"憋着不说"相反。

**可干预维度**:

| 维度 | 检测方式 | 干预手段 |
|---|---|---|
| 章末钩子质量 | rubric 维度 `hook_sharpness` | Prompt 要求章末留"未解决的问题",禁止"完满结尾" |
| 信息差密度 | LLM 判断:读者已知 vs 角色已知的不对称 | 写作 Prompt 注入"在此场景中,读者应知道什么但主角不知道" |
| 冲突解决时机 | LLM 判断:是否过早消解张力 | Anti-Slop 规则 T1_PREMATURE_RESOLUTION |
| 悬念句式 | 规则检测 | Exemplar 注入有悬念感的结尾示范 |

**生成时注入(不是事后检查)的关键 Prompt 要素**:

```
【张力约束】
本章处于{chapter.structure_position_label}。
叙事张力原则:
- 冲突不在本章完全解决;结尾留至少一个未答之问
- 如果读者此时知道某事而主角不知,保持并延伸这个信息差
- 禁止在情节高峰之后立即加入"他终于明白了…"式的情绪总结
- 章末最后一段应制造期待感,而非满足感
```

#### 3.1.2 G2 情感真实(被击中)→ Show not Tell + 具体性

**LLM 的结构性问题**:趋向显性情感表达、金句升华——训练数据里"被点赞的情感表达"多是显性的。

**可干预维度**:Show not Tell(Anti-Slop F类)、感官细节密度、情感通过行为渗透而非直说。

**干预手段**:Anti-Slop F 类规则库 + rubric 维度 `show_not_tell` + `sensory_detail` + 改写指令("用身体感觉替代情绪词")。

#### 3.1.3 G3 人物活着(令人记住)→ 角色内在一致性 + 欲望驱动

**LLM 的结构性问题**:角色易"功能化"——为情节服务,不为性格服务;无持久人格,只有上下文。

**可干预维度**:角色声音唯一性、行为的欲望驱动(而非情节驱动)、人物魅力(character_presence rubric)。

**干预手段**:VoiceProfile few-shot(来自门槛2)+ character 级别 StyleExemplar + rubric 维度 `character_presence` + 写作 Prompt 注入"此场景中{character.name}的行动动机来自{character.motivation},而非来自情节需要"。

#### 3.1.4 G4 新鲜(猜不到)→ 主动制造意外性

**LLM 的结构性问题**:next-token 趋均值——默认产出"最可能"的故事走向,这正是套路的来源。

**这是内核3 最核心的职责,详见 §3.3。**

#### 3.1.5 G5 主题有重量(说了点什么)→ 北极星贯穿

**LLM 的结构性问题**:无持久意图;倾向把主题"说出来"而非"渗进去"。

**可干预维度**:主题通过场景/选择渗透(而非通过说教直说)、AuthorIntent.reader_feeling 在评改中检验。

**干预手段**:每章写作 Prompt 注入 AuthorIntent.reader_feeling("本书要让读者感受到{intent}——本章应在哪个具体时刻令读者感受到一丝这种感受,且不说出这两个字");评改 rubric 增加 `intent_resonance` 维度检查。

#### 3.1.6 G6 文字有质感(值得一读再读)→ 反 AI 腔 + 文风 steering

**LLM 的结构性问题**:AI 腔——辞藻堆砌、万能过渡、排比癖、总结升华、回归训练均值。

**这是内核3 的基础工程,详见 §3.2(反 AI 腔)和 §3.4(文风 steering)。**

### 3.2 反 AI 腔规则库(Anti-Slop Engine)

#### 3.2.1 设计原则

规则库不是"把 AI 文本改成人写的"——这做不到。它是**降低最常见、最高频的 AI 腔密度**,让正文不在显眼处暴露生成痕迹。

**双检架构**:正则/关键词快速扫描(成本低、速度快)→ 对候选命中调用 LLM 语义判断(准确率高、成本高)。两者配合,避免纯规则的高误判率和纯 LLM 的高成本。

**修复策略分三级**:
- `auto_fix`:置信度 ≥0.85 的 high severity 命中,自动调 LLM 改写,无需人工干预
- `flag_and_suggest`:medium severity 或置信度 <0.85,标记 + 生成改写建议,进入评改环
- `inject_exemplar`:句式类问题(节奏单调等),注入对应场景的 StyleExemplar 范本辅助改写

#### 3.2.2 病症分类表(完整规则库)

【稳定知识+设计决策】基于对当前主流 LLM 写作输出的系统观察整理。此分类非已核实研究结论——随模型迭代需持续更新。

| 类别 | 病症ID | 病症名称 | 典型表现 | 严重度 | 修复策略 |
|---|---|---|---|---|---|
| **A 空洞辞藻** | A1_EMPTY_ELEVATION | 堆砌形容词 | 连用"深邃/澄澈/凛冽/磅礴"等无具体图像支撑的形容词 | high | flag_and_suggest |
| **A 空洞辞藻** | A2_ABSTRACT_ABSTRACT | 无名状情绪 | "一种难以名状的情绪"/"说不清道不明的感觉" | high | auto_fix |
| **B 万能过渡** | B1_UNIVERSAL_TRANSITION | 万能衔接句 | "就在这时…"/"话音刚落…"/"空气似乎凝固了" | medium | auto_fix |
| **B 万能过渡** | B2_CHAPTER_OPEN_CLICHE | 章节开头套语 | "阳光透过窗户洒落"/"夜幕降临" 作为章节第一句 | medium | flag_and_suggest |
| **C 排比癖** | C1_OVER_PARALLELISM | 无节奏排比 | 连续三组及以上的排比句(非修辞需要) | medium | flag_and_suggest |
| **C 排比癖** | C2_TRIPLE_DESCRIPTOR | 三连描述符 | "眼神深邃而坚定,神情沉稳而从容,气质冷峻而内敛" | high | auto_fix |
| **D 句式病** | D1_NOT_BUT_OVERUSE | "不是…而是" 癖 | 频繁用"不是…而是…"结构作为过渡/强调 | medium | flag_and_suggest |
| **D 句式病** | D2_IN_THIS_MOMENT | "在这一刻"句式 | "在这一刻(他/她)…"/"此刻他终于…" 频繁出现 | medium | auto_fix |
| **E 总结升华** | E1_FORCED_ELEVATION | 强行哲学升华 | 情节段落末尾插入人生感悟,可删除而不损失情节信息 | high | auto_fix |
| **E 总结升华** | E2_THOUGHT_SUMMARIZE | 内心总结 | "他终于明白了生命的意义在于…" / "此刻他意识到…" | high | auto_fix |
| **F 情感直说** | F1_EMOTION_TELLING | 直说情绪 | "他感到愤怒"/"巨大的悲伤涌上心头" 作为独立信息 | high | flag_and_suggest |
| **F 情感直说** | F2_INNER_MONOLOGUE_DUMP | 心理清单 | 大段内心独白直接罗列心理活动而无行为/感官锚定 | medium | flag_and_suggest |
| **G 套话比喻** | G1_CLICHE_SIMILE | 死比喻 | "心跳如鼓"/"热血沸腾"/"如雷贯耳"/"冷汗直流" | medium | auto_fix |
| **G 套话比喻** | G2_GENERIC_NATURE | 无差别自然比喻 | "如同秋日落叶"/"宛若春风拂面" 等无差别比喻 | low | flag_and_suggest |
| **H 冗余解释** | H1_OVERKILL_EXPLAIN | 展示后解释 | 已用行为展示,又用叙述重复解释一遍 | medium | auto_fix |
| **H 冗余解释** | H2_MOTIVATION_LECTURE | 动机说教 | 人物行动后附加"因为他知道…所以他才…" | high | auto_fix |
| **I 角色模板** | I1_REACTION_TEMPLATE | 表情包式反应 | 所有角色震惊时都"眼睛微微睁大",愤怒时都"拳头握紧" | medium | flag_and_suggest |
| **J 句式单调** | J1_MONOTONOUS_SYNTAX | 节奏僵化 | 连续超过5句主谓宾结构相同,无节奏变化 | medium | inject_exemplar |
| **K 对话 AI 腔** | K1_DIALOGUE_ROBOTIC | 对话书面化 | 对话过度书面完整,缺乏口语停顿/省略/潜台词 | high | flag_and_suggest |
| **K 对话 AI 腔** | K2_DIALOGUE_PREACH | 对话说教 | 角色对话连续>100字,结构化论点,读来像论文摘要 | high | auto_fix |
| **T 张力泄露** | T1_PREMATURE_RESOLUTION | 过早解决冲突 | 冲突/矛盾在引入后立即被解决,张力消失 | high | flag_and_suggest |
| **T 张力泄露** | T2_SPOILER_HINT | 叙述者预告 | 全知叙述者提前暗示结果("他不知道这将是最后一次") | medium | flag_and_suggest |
| **L 填充性描写** | L1_FILLER_SCENE | 过场填充 | 对推进情节/人物无任何贡献的环境/时间流逝描写 | medium | flag_and_suggest |
| **M 数字化思维** | M1_LIST_THINKING | 清单式叙述 | 用"首先…其次…最后…"结构组织小说叙述(非对话/说明文语境) | high | auto_fix |

**完整规则库约35–50条**,以上为核心子集。完整库以 `slop_rules.json` 维护,支持运行时扩展。

#### 3.2.3 规则库数据结构

```python
@dataclass
class SlopRule:
    rule_id:              str             # 唯一标识,如 "E1_FORCED_ELEVATION"
    category:             str             # 类别(A-M,见上表)
    symptom_name:         str             # 病症名称
    severity:             Literal["high", "medium", "low"]
    # 检测方法
    patterns:             List[str]       # 正则表达式列表(快速预筛)
    keywords:             List[str]       # 关键词列表(快速预筛)
    use_llm_judge:        bool            # 是否需要 LLM 语义判断
    llm_judge_prompt_key: str             # LLM 判断 prompt 模板键
    # 触发条件
    min_density_per_k:    float           # 触发的最低密度(次/千字;0=单次即触发)
    context_sensitive:    bool            # 是否需要上下文才能判断
    # 豁免条件
    whitelist_conditions: List[str]       # 豁免场景描述
    # 修复策略
    fix_strategy:         Literal["auto_fix", "flag_and_suggest", "inject_exemplar"]
    fix_instruction:      str             # 传给改写 Agent 的指令模板
    # 自动修复置信度门槛(低于此值不自动修复)
    auto_fix_confidence_threshold: float  # 默认 0.85

# 命中记录
@dataclass
class SlopHit:
    rule_id:         str
    severity:        str
    segment_id:      UUID          # 命中所在 Segment(00 §4.2)
    char_offset:     int
    matched_text:    str           # 命中片段(前后30字)
    fix_instruction: str
    confidence:      float         # 0–1;LLM 判断时为模型置信度;规则命中=1.0
    fix_strategy:    str
    auto_fixed:      bool          # 是否已自动修复
    revised_text:    str | None    # auto_fix 后的改写结果

# 报告
@dataclass
class SlopReport:
    chapter_id:       UUID
    generated_at:     datetime
    total_hits:       int
    hits_by_severity: Dict[str, int]
    slop_density:     float              # hits/千字
    hits:             List[SlopHit]
    pass_threshold:   bool               # slop_density < 阈值
    auto_fixed_count: int                # 已自动修复数量
```

#### 3.2.4 双检流程(AntiSlopDetector)

```python
async def scan(
    chapter_id: UUID,
    segments:   List[Segment],
    auto_fix:   bool = True,
    tier:       QualityTier = QualityTier.STANDARD,
) -> SlopReport:
    """
    双检流程:规则库快速扫描 → LLM 语义判断 → 分级处理
    """
    full_text = "\n".join(s.text for s in segments)
    all_hits: List[SlopHit] = []

    for rule in _get_active_rules(tier):  # LITE 档只启用 high severity 规则
        # Step 1: 正则/关键词快速预筛(成本极低)
        candidates = _rule_scan(full_text, segments, rule)
        if not candidates:
            continue

        # Step 2: LLM 语义判断(仅对需要语义理解的规则)
        if rule.use_llm_judge:
            validated = await _llm_validate_hits(candidates, rule, segments)
        else:
            validated = candidates

        # Step 3: 密度阈值过滤(min_density=0 则不过滤)
        if rule.min_density_per_k > 0:
            density = len(validated) / (len(full_text) / 1000)
            if density < rule.min_density_per_k:
                continue  # 密度未达阈值,视为可接受

        all_hits.extend(validated)

    # 按 severity 排序(high 优先处理)
    all_hits.sort(key=lambda h: {"high": 0, "medium": 1, "low": 2}[h.severity])

    # Step 4: 自动修复(仅 high severity + 置信度达标)
    if auto_fix:
        for hit in all_hits:
            rule = get_rule(hit.rule_id)
            if (rule.fix_strategy == "auto_fix"
                    and hit.confidence >= rule.auto_fix_confidence_threshold):
                hit.revised_text = await _auto_fix_hit(hit, segments, full_text)
                hit.auto_fixed = (hit.revised_text is not None)

    slop_density = len(all_hits) / (len(full_text) / 1000) if full_text else 0
    return SlopReport(
        chapter_id=chapter_id,
        generated_at=datetime.utcnow(),
        total_hits=len(all_hits),
        hits_by_severity={
            "high":   sum(1 for h in all_hits if h.severity == "high"),
            "medium": sum(1 for h in all_hits if h.severity == "medium"),
            "low":    sum(1 for h in all_hits if h.severity == "low"),
        },
        slop_density=round(slop_density, 3),
        hits=all_hits,
        pass_threshold=slop_density < SLOP_DENSITY_THRESHOLD,  # 默认 2.0/千字
        auto_fixed_count=sum(1 for h in all_hits if h.auto_fixed),
    )
```

### 3.3 主动制造意外与张力(对抗 next-token 趋均值)

#### 3.3.1 核心认知:好故事的两重矛盾

哲学文档 §2 能力矩阵揭示了一个根本矛盾:

> **next-token 预测的本质是"最可能"——但好故事的本质是"出人意料又合理"。**

这个矛盾不能靠 Prompt 完全解决,但可以通过**系统性的生成干预**显著缓解。关键是:必须在**写作时**就要求意外性、克制和延迟满足——而不是写完之后检查。

#### 3.3.2 生成时的意外性要求注入

在实现2 的写作 Prompt 中,本内核注入以下约束块(按场景类型动态调整):

```
【反趋均值约束(Anti-Mediocrity Constraints)】

目标函数:本章不是要写"合理的故事推进",而是要写"让读者猜不到下一步,但回看觉得必然"。

具体要求:
1. 【意外性检查】写出第一个情节走向后,先停下来问:读者预期的是什么?
   然后找一个"意外但合理"的替代——至少考虑两个走向再选。
2. 【具体性优先】禁止抽象陈述。把每个情绪/状态/关系换成一个可见的具体细节:
   不是"他感到紧张",而是"他把茶杯往桌上推了半寸又推了回来"。
3. 【克制原则】给读者留白。凡是可以不说的,就不说。
   情绪不直说,主题不点明,动机不解释(如果行为本身已经说明)。
4. 【延迟满足】张力由此章创造,不由此章解决。
   读者在章末应有一个"等等——这意味着……"的悬念停顿。
5. 【人物驱动】行动来自角色的欲望/恐惧/矛盾,不来自"情节需要角色做这件事"。
```

#### 3.3.3 多方案意外性(与内核1 的 OptionSet 耦合)

内核1 的协作回路在**关键决策点**产出 OptionSet(2–4 个有差异的方案)供人选。本内核的职责是确保这些方案本身不平庸:

```python
def validate_option_set_diversity(option_set: OptionSet) -> OptionSetDiversityReport:
    """
    检查 OptionSet 中的方案是否足够有差异(不只是参数不同的同一个故事)。
    至少一个方案应在以下至少一个维度上"意外":
    - 情节走向与最可能预期相反
    - 情感色调与场景语境相反
    - 决策代价被放大到令人不适
    - 引入一个此前未出现的新元素
    """
    options = option_set.options  # jsonb: List[{text, diff, cost}]
    
    # LLM 判断:这批选项有没有一个是真正"意外"的?
    diversity_report = _llm_check_option_diversity(options, option_set.decision_point)
    
    if not diversity_report.has_surprising_option:
        # 触发内核1 重新生成:要求至少一个方案"打破读者预期"
        return OptionSetDiversityReport(
            pass_diversity=False,
            suggestion="至少一个选项应提供与常规叙事预期相反的走向",
            regenerate_hint="option_B_should_surprise"
        )
    return OptionSetDiversityReport(pass_diversity=True)
```

**与内核1 的接口**:`OptionSet.options` 中每个选项的生成调用本内核的 `anti_mediocrity_constraints` 注入;内核1 的 OptionSet 创建流程在完成后调用 `validate_option_set_diversity` 确保至少一个方案不平庸。

#### 3.3.4 意外性的三种具体形式

【稳定知识:叙事学共识】意外性不是随机——是在已建立的期望框架内的违反:

**① 期望反转(Expectation Inversion)**:读者预期 A,给出 B,但 B 在回看时完全合理。
- 实现:写作 Prompt 要求"在场景结束前,角色或读者预期的结果是什么?写一个不同的结果。"

**② 代价放大(Cost Amplification)**:选择是对的,但代价比预期更重——让读者感受到真实。
- 实现:Prompt 注入"本章的选择/行动应让某个角色付出意料之外的代价。"

**③ 信息不对称(Information Asymmetry)**:读者知道角色不知道的事情,或反之。
- 实现:Prompt 注入"此场景中存在哪个信息差?在写作中保持并延伸它,不要提前消解。"

### 3.4 文风 Steering 机制

#### 3.4.1 三层 Steering 架构

文风注入不是单点操作,而是三层叠加:

```
层1: AuthorIntent 北极星(来自内核1)
     → 写这本书要让读者感受什么
     → 约束所有生成的情感基调

层2: TasteModel 品味参数(来自内核2)
     → positive_exemplars(正例范本)
     → negative_list(AI腔黑名单/反例)
     → learned_preferences(学习到的偏好)

层3: StyleExemplar few-shot(本内核管理)
     → 当前场景类型的具体范本
     → style_descriptors 描述符
     → 来自内核2 TasteModel.positive_exemplars 的子集
```

**层1 提供"写什么感觉",层2 提供"这个作者觉得什么是好/坏",层3 提供"具体怎么写"。** 三层缺一会导致:无层1 → 主题漂移;无层2 → 不懂作者口味;无层3 → 有方向无示范。

#### 3.4.3 ExemplarInjector — 选取与注入

```python
def select_exemplars(
    chapter_id:    UUID,
    bundle:        ContextBundle,      # 来自实现2 的上下文包
    scene_type:    str,                # 动作/对话/内心独白/场景描写/转场/冲突
    taste_model:   TasteModel,         # 来自内核2
    max_exemplars: int = 2,
    token_budget:  int = 800,
) -> List[StyleExemplar]:
    """
    选取策略(优先级从高到低):
    1. TasteModel.positive_exemplars 中的范本(作者明确喜欢的)
    2. scope="work" 的作品级范本
    3. 按 scene_type 过滤 style_descriptors 匹配的范本
    4. 按与当前章大纲 embedding 的余弦相似度排序
    5. 按 token_budget 截断
    """
    # 优先从 TasteModel 正例中找
    taste_positive_ids = set(
        ex["exemplar_id"] for ex in (taste_model.positive_exemplars or [])
        if ex.get("exemplar_id")
    )
    
    # 查询候选范本
    candidates = db.query(StyleExemplar).filter(
        or_(
            StyleExemplar.work_id == bundle.work_id,
            StyleExemplar.scope == "global",
        ),
        StyleExemplar.deleted_at.is_(None)
    ).all()

    # 场景类型过滤
    scene_matched = [c for c in candidates if _scene_type_match(c.style_descriptors, scene_type)]
    pool = scene_matched if scene_matched else candidates

    # 偏好排序:TasteModel 正例 > 余弦相似度
    chapter_embedding = get_chapter_embedding(chapter_id)
    pool.sort(key=lambda e: (
        1.0 if e.id in taste_positive_ids else 0.0,  # 优先正例
        cosine_similarity(e.embedding, chapter_embedding),
    ), reverse=True)

    # token 截断
    selected = []
    used = 0
    for e in pool:
        tok = count_tokens(format_exemplar(e))
        if used + tok <= token_budget and len(selected) < max_exemplars:
            selected.append(e)
            used += tok

    return selected


def format_for_prompt(
    exemplars:   List[StyleExemplar],
    taste_model: TasteModel,
) -> str:
    """
    格式化范本注入块。同时注入来自 TasteModel 的负面清单。
    """
    if not exemplars and not taste_model.negative_list:
        return ""

    lines = [
        "═══════════════════════════════════════",
        "【文风范本与品味约束】",
        "═══════════════════════════════════════",
    ]

    if exemplars:
        lines.append("以下段落展示目标文风,请在保持情节的前提下模仿其语感、节奏和意象密度:")
        for i, e in enumerate(exemplars, 1):
            lines.append(f"\n▸ 范本{i}({e.label})")
            lines.append(f"  风格标签:{_format_descriptors_brief(e.style_descriptors)}")
            lines.append(f"  示范文本:")
            lines.append(f"  「{e.sample_text}」")

    # 来自 TasteModel 的负面清单
    neg = taste_model.negative_list or []
    if neg:
        lines.append("\n【此作者的负面清单(明确不喜欢,必须避免)】")
        for item in neg[:8]:  # 最多注入8条,防止 token 膨胀
            lines.append(f"  ✗ {item.get('description', '')}")

    lines.append("\n注意:范本仅供风格参考,不得复制其情节内容。")
    return "\n".join(lines)
```

#### 3.4.5 文风漂移检测(DriftDetector)

```python
def detect_style_drift(
    work_id:           UUID,
    window_size:       int = 20,
    baseline_chapters: int = 10,
) -> StyleDriftReport:
    """
    检测近 window_size 章的文风是否偏离作品基准文风。
    方法:Segment embedding 质心余弦距离。
    触发:每50章自动执行 OR 作者手动触发。
    """
    all_chapters = get_work_chapters_done(work_id)
    if len(all_chapters) < baseline_chapters + window_size:
        return StyleDriftReport(drift_detected=False, reason="章数不足")

    baseline_segs  = get_segments_for_chapters([c.id for c in all_chapters[:baseline_chapters]])
    recent_segs    = get_segments_for_chapters([c.id for c in all_chapters[-window_size:]])
    baseline_centroid = compute_centroid([s.embedding for s in baseline_segs])
    recent_centroid   = compute_centroid([s.embedding for s in recent_segs])
    drift_distance    = 1.0 - cosine_similarity(baseline_centroid, recent_centroid)

    # 【设计决策】阈值须在实际作品上验证校准
    if drift_distance >= 0.20:
        level = "critical"
        action = "刷新范本库:重新提取近期高分章节作为新范本,并加强注入权重"
    elif drift_distance >= 0.12:
        level = "warning"
        action = "补充范本:检查近20章与早期章节的风格差异,必要时补充 StyleExemplar"
    else:
        level = "normal"
        action = ""

    return StyleDriftReport(
        work_id=work_id, drift_distance=drift_distance,
        baseline_chapters=baseline_chapters, recent_window=window_size,
        level=level, suggestion=action,
        drift_detected=(level != "normal"),
    )
```

#### 3.4.6 风格变奏引擎(VariationEngine)— 对抗审美疲劳

【设计决策】百万字下,好风格重复也会令人疲劳。在统一性内引入有限变奏:

```python
VARIATION_STRATEGIES = [
    {
        "id":             "rhythm_variation",
        "trigger_check":  lambda stats: _all_same(stats, "rhythm", n=5),
        "inject":         "本章节奏变奏建议:较前几章适当加快/放缓节奏,多用短句和行动驱动段落"
    },
    {
        "id":             "sensory_rotation",
        "trigger_check":  lambda stats: _dominant_channel(stats, n=3) == "视觉",
        "inject":         "本章感官通道建议:减少视觉描写,增加听觉/触觉/嗅觉细节"
    },
    {
        "id":             "pov_distance_variation",
        "trigger_check":  lambda stats: _all_same(stats, "pov_distance", n=4),
        "inject":         "本章视角距离建议:在某个段落适当使用中距离叙事,给读者短暂的呼吸感"
    },
    {
        "id":             "dialogue_density_variation",
        "trigger_check":  lambda stats: _avg_dialogue_density(stats, n=3) > 0.5,
        "inject":         "本章建议:适当减少对话密度,增加场景描写和内心独白"
    },
    {
        "id":             "tension_pattern_variation",
        "trigger_check":  lambda stats: _all_same(stats, "tension_pattern", n=4),
        "inject":         "本章张力变奏建议:若近期均为持续低压,尝试快速切换节奏;若均为间歇爆发,尝试持续积压"
    },
]

def compute_variation_hints(work_id: UUID, recent_n: int = 5) -> str:
    recent_stats = get_recent_chapter_style_stats(work_id, n=recent_n)
    hints = [
        s["inject"] for s in VARIATION_STRATEGIES
        if s["trigger_check"](recent_stats)
    ]
    return "\n".join(hints) if hints else ""
```

### 3.5 文学评改环(Literary Critique-Revise Loop)

#### 3.5.1 与门槛层的根本区别

| 维度 | 门槛1 一致性校验 | **内核3 文学评改环** |
|---|---|---|
| 关注点 | 写得**对**不对(逻辑/设定/时间线) | 写得**好不好**(美学/文笔/感染力) |
| 评判标准 | 规则性,可判真假 | 主观美学 rubric |
| 触发时机 | 每章必做,后台静默 | 按质量档,显形执行 |
| 产出 | ConsistencyFlag[] | CritiqueReviseResult |
| 成本 | 低(主要规则匹配) | 高(旗舰 LLM 多轮) |
| 与内核的关系 | 保证不崩(table stakes) | 追求好(内核价值) |

#### 3.5.2 8 维 Rubric(评改维度定义)

【稳定知识】维度来自经典文学创作批评框架,转化为可操作 0–5 分量表:

| 维度ID | 维度名称 | 0分锚点 | 5分锚点 | 是否必须达标 |
|---|---|---|---|---|
| `show_not_tell` | Show not Tell | 通篇直说情绪,无感官细节 | 情绪完全通过行为/感官渗透,无一句直说 | 必须(REQUIRED) |
| `sensory_detail` | 感官细节 | 无具体感官描写,全是抽象表述 | 多感官交织,每个场景均有可感知细节 | 建议(SOFT) |
| `dialogue_quality` | 对白质量 | 对话机器人腔,说教,无个性 | 有独特声音,潜台词丰富,推动关系/情节 | 必须(REQUIRED) |
| `imagery_rhythm` | 意象与节奏 | 无意象或全套话,节奏单调 | 原创意象,句式富于变化,有呼吸感 | 建议(SOFT) |
| `emotional_tension` | 情绪张力 | 平铺叙述,无情绪温度 | 内在矛盾/压力,读者随角色紧张/感动 | 建议(SOFT) |
| `subtext_whitespace` | 潜台词与留白 | 什么都说透,无悬想空间 | 大量潜台词,每处留白都有意义 | 建议(SOFT) |
| `scene_blocking` | 场景调度 | 人物漂浮,场景无实体感 | 动作与空间关系清晰,场景有电影感 | 建议(SOFT) |
| `intent_resonance` | 北极星共鸣 | 完全感受不到作者意图 | 至少一个具体时刻令人感受到 reader_feeling | 必须(REQUIRED) |

**`intent_resonance` 是新增关键维度**,在旧版中缺失。它与内核1 的 AuthorIntent 直接耦合——评改 Agent 评判"本章有没有哪个具体时刻令读者感受到{reader_feeling}"。这是文学质量评改与作者意图保持对齐的关键接口。

**终止条件**:

```python
def should_stop(
    report:          CritiqueReport,
    revision_count:  int,
    max_revisions:   int,
    pass_threshold:  int = 3,     # 0–5分量表,≥3为及格
) -> Tuple[bool, str]:
    if revision_count >= max_revisions:
        return True, "max_revisions_reached"
    
    required_dims = ["show_not_tell", "dialogue_quality", "intent_resonance"]
    soft_dims     = ["sensory_detail", "imagery_rhythm", "emotional_tension",
                     "subtext_whitespace", "scene_blocking"]
    
    required_pass = all(
        report.dimensions[d]["score"] >= pass_threshold
        for d in required_dims if d in report.dimensions
    )
    soft_pass = (
        sum(1 for d in soft_dims if report.dimensions.get(d, {}).get("score", 0) >= pass_threshold)
        >= len(soft_dims) // 2  # 半数软要求达标即可
    )
    overall_pass = report.overall_score >= pass_threshold - 0.5

    if required_pass and (soft_pass or overall_pass):
        return True, "pass"
    return False, "continue"
```

**默认参数(【设计决策】)**:

```python
MAX_REVISIONS_STANDARD = 1   # STANDARD档最多1轮
PASS_THRESHOLD         = 3   # 0–5分,≥3为及格
```

### 3.7 分级质量档(Quality Tier)

#### 3.7.1 质量档定义

【设计决策】百万字下对每章豪华评改不可行。按章节战略重要性分配资源:

| 档位 | 标识符 | 触发条件 | 本内核执行内容 | 额外 LLM 调用 |
|---|---|---|---|---|
| 旗舰档 | `PREMIUM` | 卷首章/卷尾章/全书转折章(StructureBeat=climax/resolution/midpoint)/作者手动标记 | Anti-Slop 全量双检 + 完整评改环(最多2轮) + 高权重范本注入 + OptionSet 多样性验证 | 4–6次 |
| 标准档 | `STANDARD` | 普通情节推进章(默认) | Anti-Slop 双检(high+medium severity) + 评改环(最多1轮,仅检查 REQUIRED 维度) | 2–3次 |
| 轻量档 | `LITE` | 过渡章/铺垫章/每5章放一章(节省成本) | 仅 Anti-Slop 规则库扫描(无 LLM 判别) + 范本注入(无评改环) | 0次 |
| 跳过档 | `SKIP` | 作者标记"已手工润色完成" OR 工程6 的人评 H1≥4 | 不触发内核3 | 0次 |

#### 3.7.2 TierRouter

```python
def route_quality_tier(
    chapter:      Chapter,
    author_flags: Dict[str, bool],
    human_eval:   Optional[HumanEvalRecord],   # 来自工程6
    qa_result:    WritingQAResult,              # 来自实现2
) -> QualityTier:
    # SKIP(最高优先级)
    if author_flags.get("manually_polished"):
        return QualityTier.SKIP
    if human_eval and human_eval.h1_readability >= 4:
        return QualityTier.SKIP

    # PREMIUM
    beat_targets = chapter.beat_targets or {}
    is_key_beat = any(
        b.get("beat_type") in ["climax", "resolution", "midpoint", "arc_finale", "epiphany"]
        for b in beat_targets.get("beats", [])
    )
    if (is_key_beat
            or author_flags.get("premium_requested")
            or chapter.seq == 1
            or _is_volume_boundary(chapter)):
        return QualityTier.PREMIUM

    # LITE(每5章一次)
    if chapter.seq % 5 == 0:
        return QualityTier.LITE

    # STANDARD(默认)
    return QualityTier.STANDARD
```

| STANDARD | ~70%(350章) | 2次 | 3k–5k/次 | ~2.8M |
| LITE | ~15%(75章) | 0次 | 忽略 | 0 |
| SKIP | ~5%(25章) | 0次 | 0 | 0 |

## § 6 · 失败模式与缓解

### 6.1 评改 Agent 产出失控

**风险**:Critique Agent 输出 JSON 格式错误;Revise Agent 改写稿严重偏离情节。

**缓解**:
- Critique Agent 强制 JSON 输出 + schema 校验;解析失败时降级为无评改(记 `critique_failed=True`)
- Revise Agent 改写稿做字数检查:偏差 >30% 时丢弃,保留原稿 + 标记 `revision_discarded`
- 改写稿快速跑门槛1 一致性扫描:若出现新的 ConsistencyFlag,丢弃改写结果保留原稿

### 6.2 Anti-Slop 自动修复引入新问题

**风险**:修复 high severity 命中时,改写结果破坏上下文衔接或引入新的 AI 腔。

**缓解**:
- 自动修复仅对 `confidence ≥ 0.85` 命中(低置信度只标记)
- 修复后重新扫描:新增命中时丢弃修复结果,保留原文并标记 `auto_fix_reverted`
- 前端展示 diff,作者可一键回滚任何自动修复

### 6.3 文风 steering 同质化

**风险**:StyleExemplar 范本注入后,全书章节语感越来越相似(过度对齐到范本)。

**缓解**:
- VariationEngine 检测单一风格持续过长,注入变奏指令
- 范本注入权重随使用次数递减(同一范本注入 ≥10 次后降低权重 30%)
- 范本库保持多样性:至少3–5个不同场景类型的范本;工程6 监控范本使用分布

### 6.4 North Star 漂移:评改分高但不忠于意图

**风险**:评改环优化出了"好文字",但偏离了 AuthorIntent.reader_feeling。

**缓解**:
- `intent_resonance` 维度为 REQUIRED,评改循环不终止直到它达标
- Revise Agent Prompt 中北极星约束在 `[SYSTEM]` 区首部出现(高优先级)
- 作者可在前端任何时候刷新 AuthorIntent,内核3 下次运行自动使用新意图

### 6.5 百万字文风漂移纠正成本高

**风险**:第300章发现文风 critical 漂移时已积累大量偏差章节。

**缓解**:
- 每50章自动检测(而非全书结束后)
- warning 级只更新范本库权重(不强制重写已有章节)
- critical 级在前端醒目提示作者,建议从下一章开始重新校准
- 基准期始终固定为前10章(不随全书推进而滚动,防止基准漂移)

### 6.6 质量档路由失准

**风险**:TierRouter 路由错误,把重要章节路由到 LITE/SKIP。

**缓解**:
- 作者在前端可手动覆盖质量档(`author_flags["premium_requested"]`)
- 实现3 在卷尾章节自动提升 PREMIUM(不依赖 beat 标记)
- 前端展示每章当前质量档,作者可见可调整

### 6.7 Anti-Slop 规则与模型升级脱节

**风险**:新模型发布后旧有的 AI 腔模式消失,规则库误判正常文本。

**缓解**:
- 规则库以 `slop_rules.json` 维护(运行时可更新,无需重新部署)
- 工程6 监控各规则的 false positive rate;超过 15% 时自动降低该规则优先级
- 每季度人工 review 规则库(工程7 路线图任务)

## § 7 · MVP vs 完整版

### 7.1 MVP 阶段(最简可运行版本)

**目标**:验证"反 AI 腔扫描 + 基础范本注入 + 北极星约束"是否能让人评 H1 可测量提升。

**包含**:
- Anti-Slop 规则库:A/E/F/K 四类最高危规则(约15条),纯正则/关键词,无 LLM 判别
- 写作时北极星约束注入(AuthorIntent.reader_feeling 简单模板化注入)
- StyleExemplar 基础 CRUD + 静态 style_descriptors 注入
- 质量档:仅 PREMIUM/LITE 两档
- 评改 rubric:仅 `show_not_tell` + `dialogue_quality` + `intent_resonance` 三维度
- 文风范本注入(最多1个范本,800 token 预算)

**不包含**:
- LLM 语义判别(全部用规则)
- 完整8维度 rubric
- TasteModel 动态耦合(使用静态配置)
- 文风漂移检测
- VariationEngine
- OptionSet 多样性验证
- 自动修复(仅标记)

### 7.2 增强版阶段

**新增**:
- LLM 语义判别(E1/F1/K2 类全量 LLM 判断)
- 完整8维度 rubric
- STANDARD 质量档完整流程
- 与内核2 TasteModel 动态耦合
- 文风漂移检测(DriftDetector)
- 自动修复(auto_fix,high severity + 置信度 ≥0.85)
- OptionSet 多样性验证

### 7.3 完整版阶段

**新增**:
- VariationEngine(风格变奏,对抗审美疲劳)
- 完整 Anti-Slop 规则库(35–50条)

- 工程6 实时质量仪表板数据喂入
- 每季度规则库 review 工作流

## § 9 · 开放问题

> 【需实验验证】= 须工程6 自建度量实测;【需设计决策】= 须团队讨论;【理论未知】= 目前无已知答案

### 9.1 文学质量的度量与校准

**Q1**【需实验验证】LiteraryCritiqueAgent 的 rubric 分数与人评 H1/H2 的 Pearson 相关系数是多少?若 |r| < 0.4,需重新设计 rubric 维度或改进 Prompt。

**Q2**【需实验验证】经过1–2轮评改环后,H1_readability 平均提升能否达到 +0.5 分(1–5 量表)?这是判断评改环 ROI 是否合理的关键指标。

**Q3**【理论未知】用 LLM 评判"好文学"是否稳定?不同模型(甚至同一模型的不同调用)对 rubric 的打分是否有足够一致性?若不稳定,评改环的质量控制价值大打折扣。

### 9.2 反 AI 腔规则库

**Q4**【需实验验证】Auto-fix 是否会产生"修了一个、冒出新的"的问题?修复稿的 slop_density 比原稿是否有概率更高?需追踪 `auto_fix_reverted` 比率。

**Q5**【需设计决策】规则库应静态(代码库维护)还是动态(数据库,运行时更新)?静态简单但难以个性化;动态灵活但增加复杂度。MVP 建议静态,增强版切换。

**Q6**【需实验验证】LLM 语义判别的 false positive rate(把好文字误判为 AI 腔)能否控制在 15% 以下?若过高,需提高 `min_density` 阈值或改用纯规则。

### 9.3 北极星耦合

**Q7**【需设计决策】`intent_resonance` 维度的评分对 AuthorIntent 描述质量高度敏感——如果作者的 `reader_feeling` 填写得很模糊("让读者感动"),评改 Agent 能否给出有意义的评分?是否需要对 AuthorIntent 的填写质量做预检?

**Q8**【需实验验证】北极星约束注入写作 Prompt 后,是否实际提升了 `intent_resonance` 维度的得分?还是只是让 Agent 在评改时更容易给高分(评改者偏见)?
