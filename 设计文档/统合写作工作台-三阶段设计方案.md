# 统合写作工作台 — 三阶段设计方案

## 背景

当前 scribe3 有两个写作视图，功能重叠、定位模糊：

| 视图 | 左面板 | 中区 | 右面板 |
|------|--------|------|--------|
| WriteLayout (写作台) | 大纲/事件/母题 | ProseEditor + DraftCard | WriteChat + DeducePanel |
| DeduceLayout (推演台) | 大纲/事件/母题 | ProseEditor (无生成按钮) | 帧/Irony/QC/伏笔/在场/意图 |

推演台与写作台职责不清——两个视图都有 ProseEditor，两个都有事件/帧面板，推演台没有主编对话而是靠 `/render` 生成（已删除）。

业界参考（Scrivener/Dabble/AI写作10步法）指向一个共同模式：

> **设计→草稿→校验**，三阶段线性推进，但同一界面完成。

## 核心理念

**统合推演与写作为单一写作工作台**，通过阶段切换区分活动，而非通过视图隔离。

```
推演 (Plan)  →  草稿 (Draft)  →  正文 (Final)
  设计事件        主编生成          修改/QC/存
  检查帧          作者编辑          回写入库
```

左栏 = 数据支撑（随阶段改变内容）
中栏 = 产物（事件卡片 → 草稿编辑器 → 正文编辑器）
右栏 = 主编对话（始终在线，角色随阶段切换）

## 二、三阶段详述

### 阶段 1: 推演（Plan）

**目标**：确认本章"可写"——事件就位，视角有料，伏笔有指向。

**中区**：事件画布（Corkboard 风格）
- 事件由**主编在右侧对话建议** → 以卡片形式出现在中区 → 作者点「采用」则确认加入
- 时间线排列的事件卡片：`[序号] 谁在哪做什么 → 导致什么变化`
- 事件卡片可点击查看/编辑详情（人物、地点、目标、动机）
- 卡片底部显示关联的"看见/得知"边（知识传导到哪了）

**左面板 tabs**：
- 📋 事件列表（点击聚焦到卡片）
- 👁 知识帧（此视角截至本章所知的事）
- 📌 伏笔（本章需回收/埋设的伏笔）

**右面板**：主编规划对话
- 初始提示："你是主编，帮我设计第N章事件。视角是[name]。当前帧中有[X]条已知事实。需要回复的伏笔：[...]"
- 主编调用 `s3_list_promises`、`s3_project_frame` 等工具
- 主编建议/创建事件 → 事件卡片出现在中区

**阶段切换条件**：至少1个事件 + 视角已选定 → 可进入草稿

---

### 阶段 2: 草稿（Draft）

**目标**：基于推演设计产出初稿。

**中区**：ProseEditor + DraftCard
- DraftCard：主编生成新草稿时以浮层卡片展示，点击「采用」则覆盖当前编辑器内容，**同时自动保存一个草稿版本到后端**
- ProseEditor：草稿可手动再编辑，内容自动从后端恢复最新版本（刷新不丢）
- 提示文字："主编对话生成草稿。散文只含 [name] 知道的事。"

**左面板 tabs**：
- 👁 知识帧（写的时候参考：这个角色知道什么）
- 🎭 戏剧反讽（读者知道但角色不知道的——避免角色说出不该说的话）
- 👥 在场角色（本章在场的角色，其他角色不能凭空出现）

**右面板**：主编写作对话
- 主编调用 `s3_project_frame(focalizer, chapter)` → 拿到帧
- 主编调用 `s3_dramatic_irony(focalizer, chapter)` → 拿反讽
- 根据帧 + 事件 + 反讽生成草稿
- 生成结果以 proposal 形式出现在中区的 DraftCard

**阶段切换条件**：有草稿内容 → 可进入正文

---

### 阶段 3: 正文（Final）

**目标**：修改定稿 → 保存 → QC → 回写。

**中区**：ProseEditor（正文模式）
- 默认展示上一阶段的草稿内容
- 可继续编辑修改
- 「存为正文」按钮 → 触发 save → auto-QC → 回写入口

**左面板 tabs**：
- ✅ QC 结果（repetition / structural / purple）
- 🔒 限知泄露检查（find_leaks）
- 🔗 因果完整（causal_complete）
- 📌 伏笔状态（哪些回收了，哪些延期）
- 💾 **版本历史**：草稿生成的各版本 + 正文保存的各版本

**右面板**：主编校验对话
- 主编调用 `s3_qc_chapter(chapter)` → 显示 QC 结果
- 主编调用 `s3_find_leaks(prose, focalizer, chapter)` → 显示泄露
- 如有问题，主编建议修改方向
- 「存为正文」按钮：存稿 + 自动 QC + 泄漏检查
- 「回写」按钮：调用 `/ingest?seq=N` → 知识入库

## 三、版本管理

### 设计原则

基础但实用——不做 git 级 diff，做**可回溯的时间线**。

### 草稿版本

每次作者在 DraftCard 上点「采用」主编生成的草稿，自动在后端保存一个草稿版本。页面刷新后，最新草稿版本自动恢复到编辑器。

```
草稿版本历史（本章）
┌─────────────────────────────────────────┐
│ v3 · 刚刚 · 主编生成 / 作者采用         │
│     "压缩开头，充实身体描写"             │
│     字数: 6142 · 句长: 23 · 对话: 12次  │
│     [回看] [恢复到此版本]               │
│                                         │
│ v2 · 3分钟前 · 主编生成 / 作者采用      │
│     字数: 5280 · 句长: 19 · 对话: 8次   │
│     [回看]                              │
│                                         │
│ v1 · 8分钟前 · 主编首次生成 / 作者采用  │
│     [回看]                              │
└─────────────────────────────────────────┘
```

只有最新版本可恢复（覆盖当前编辑器内容）。旧版本只可回看。

### 正文版本

每次「存为正文」记录一个版本：

```
正文版本历史
┌─────────────────────────────────────────┐
│ v2 · 2分钟前 · 作者定稿                 │
│     QC: rep=0 struct=0 purple=0 leaks=0│
│     [回看]                              │
│                                         │
│ v1 · 5分钟前 · 初次定稿                 │
│     QC: rep=3 struct=1 leaks=0          │
│     [回看]                              │
└─────────────────────────────────────────┘
```

### 存储方式

后端新增 `chapter_version` 表：

```sql
DEFINE TABLE chapter_version SCHEMAFULL;
DEFINE FIELD work     ON chapter_version TYPE string;
DEFINE FIELD seq      ON chapter_version TYPE int;
DEFINE FIELD prose    ON chapter_version TYPE string;
DEFINE FIELD stage    ON chapter_version TYPE string;  -- 'draft' | 'final'
DEFINE FIELD summary  ON chapter_version TYPE string;  -- 生成/修改摘要
DEFINE FIELD stats    ON chapter_version TYPE object;  -- { words, avg_sentence, dialog_count }
DEFINE FIELD qc       ON chapter_version TYPE object;  -- { repetition, structural, purple, leaks }
DEFINE FIELD created_at ON chapter_version TYPE datetime;
DEFINE INDEX cv_work_seq ON chapter_version COLUMNS work, seq;
```

### 回看机制

前端弹窗（Modal）展示该版本的完整文本，只读，底部有「恢复到此版本」按钮。

## 四、数据流

```
                  ┌──────────────┐
                  │   SurrealDB  │
                  └──────┬───────┘
           ┌─────────────┼─────────────┐
           │             │             │
      GET /entities  GET /frame   POST /save-chapter
      GET /facts     GET /irony   POST /ingest
      GET /events    GET /qc      GET /chapter-versions
      GET /promises  GET /causal  GET /chapter-version/:id
                     GET /leaks
           │             │             │
           ▼             ▼             ▼
    ┌──────────┐  ┌──────────┐  ┌──────────┐
    │  左面板   │  │  中区     │  │  右面板   │
    │ 数据展示  │  │ 产物编辑  │  │ 主编对话  │
    └──────────┘  └──────────┘  └─────┬────┘
                                      │
                                 POST /chat/write
                                      │
                                 Hermes agent
                                 (s3_project_frame,
                                  s3_find_leaks,
                                  s3_qc_chapter 等)
```

**阶段切换不触发任何保存**——阶段是纯 UI 状态。只有「存为正文」才持久化。

## 五、实现要点

### 代码变更

| 操作 | 文件 |
|------|------|
| 重写 WriteLayout.jsx | 加入阶段状态、事件画布、版本面板 |
| 删除 DeduceLayout.jsx | 功能并入 WriteLayout |
| 新增 EventCard 组件 | 推演阶段中区的事件卡片 |
| 新增 VersionPanel 组件 | 左面板的版本历史 tab |
| 新增 `/chapter-versions` 端点 | 查询版本列表 |
| 新增 `/chapter-version/:id` 端点 | 查询单个版本内容 |
| 新增 `/save-draft` 端点 | 采用草稿时写入 chapter_version(stage='draft') |
| 新增 `/latest-draft?seq=N` 端点 | 返回最新草稿版本，用于页面刷新恢复 |
| 修改 `save-chapter` 端点 | 存稿时同时写入 chapter_version 表 |
| 迁移 032 | 创建 chapter_version 表 |
| 修改 App.jsx | 移除 deduce 视图路由 |

### 不变的部分

- Shell 框架（左/中/右三区拖拽布局）
- ProseEditor（正文编辑器）
- WriteChat（主编对话组件）
- DraftCard（提案浮层卡片）
- DeducePanel（帧/Irony/QC 数据面板）→ 变为左面板的 tabs
- 后端 FastAPI 端点（除新增/修改以外保持不动）

### 前端状态设计

```js
const [versions, setVersions] = useState([])            // 版本列表

// 阶段切换时，左面板 tabs 和右面板主编角色自动切换
// 推演→草稿：把事件数据发给主编作为写作上下文
// 草稿→正文：保存当前草稿版本,准备 QC
```

### 后端 MCP 侧（Hermes agent SKILL.md 更新）

主编在三个阶段的不同角色：

| 阶段 | 主编角色 | 可用 MCP 工具 |
|------|---------|--------------|
| 推演 | 规划师 | s3_project_frame, s3_list_promises, s3_character_state, s3_graph_recall |
| 草稿 | 写手 | s3_project_frame, s3_dramatic_irony, s3_character_state, s3_craft_rule_list |
| 正文 | 编审 | s3_qc_chapter, s3_find_leaks, s3_discipline_check, s3_causal_complete |

## 六、与业界模式的对应

| 业界模式 | scribe3 对应 |
|---------|-------------|
| Scrivener Corkboard（索引卡） | 推演阶段的事件画布 |
| Scrivener Binder（大纲列表） | 左面板大纲 tab |
| AI 10步法 "Planner → Draft → Beat Check" | 推演 → 草稿 → 正文 |
| Story Tracker（事实/物品/承诺追踪） | 左面板的事实 + 伏笔 tab |
| Beat Check（7项评分） | 正文阶段的 QC + 泄露检查 |
| Continuity Check（连续性检查） | ingest 回写后的因果完整检查 |
| Dabble Plot Grid（情节网格） | 推演阶段的事件卡片时间线 |
