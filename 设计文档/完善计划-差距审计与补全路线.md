## 0. 一句话结论(初次审计)

当前系统是一个**扎实的「协作回路 MVP + 门槛骨架 + 薄前端」**:数据契约层、伏笔状态机、规则版一致性/反AI腔、协作回路最小闭环(想象→出稿→意见→diff→接受→偏好回流)、卷树/版本恢复/影响分析雏形,这些**真实可用且有单测**。

但设计文档描述的是一个**远更宏大的系统**,其「机制层/引擎层/Agent 层」大面积停留在 **schema 占位** 或 **写给 LLM 看的自然语言提示**。`完整开发计划.md` 标记的 P0–P4 是对的——但那只覆盖了全部设计文档约 **1/4** 的雄心。本审计揭示其余 3/4 的真实状态。

## 2. 七个系统性问题(根因)

1. **「死表」现象**:`taste_models / agent_memory / agent_skills / discussion_threads / memory_entries / timeline_events / char_states / entity_relations / materials / material_refs` 在 schema 齐全,全代码库零读写。给人「数据模型已完成」的错觉。
2. **「引擎」被降级为「提示词」**:OutlineAgent/PlanningAgent/WritingAgent/ReviewAgent/SummaryAgent/CritiqueAgent 等全部不存在为代码,实际是单个 Hermes 对话 + 1 份 SKILL.md + 单次 `_volc_complete`。
3. **RAG 未接入 REST 写作路径**:`embed/VecStore/index_segment/search_book` 只在 `server.py`(MCP)。Web 前端走 REST,`save_segments` 从不向量化 → 向量库恒空,RAG 召回不可能命中。
4. **反平庸是「事后检查」而非「生成时目标函数」**——与内核3 核心架构决策相反。无文学评改环。
5. **品味是空壳**:信号采集真实,但从不形成 TasteModel,注入写作时退化成一句写死的话 → 护城河「越用越懂你的书」不成立。
6. **两条门槛铁律被违背**:① 生成后自动校验(save_prose 后不触发 check);② 后台隐形自动追踪伏笔(全靠人手点按钮)。
7. **平台基建缺位**:LLM 接入层、异步task/SSE、横切约定(分页/幂等/error_code)、可观测、eval/CI 全空 → 一切上层功能与百万字规模的地基风险。

## 4. 优先级与里程碑

```
C0 校准地基 ──▶ C1 价值层 ─┬─▶ C2 记忆一致性 ──▶ C6 度量验收
(让声称为真)  (写得好,脸)  │   (百万字尺度)
                            └─▶ C3 编排平台 ──▶ C4 素材库 ──▶ C5 前端深化
                                (可靠性地基)
```

- **里程碑 N1「写得更好」= C0 + C1**:生成内容真正受品味/反平庸/想象/评改影响。这是第一性原理的最高优先,也是当前最薄、最该先补的层。
- **里程碑 N2「记得住·不崩坏」= C2**(依赖 C3-1 LLM 层先起):百万字一致性成立。
- **里程碑 N3「可靠·可观测」= C3 + C6-1**:异步/成本/故障隔离/日志,达生产门槛。
- **里程碑 N4「素材·全前端·验收」= C4 + C5 + C6-2/3/4**:补齐素材库、2b 精设前端、质量门禁与验收硬门。

**建议起步顺序(最高杠杆先做)**:C3-1(LLM 层,几乎所有上层依赖它)→ C0-1/C0-2(RAG 接通+自动校验)→ C1-1/C1-2(品味真学真注入)→ C1-3(评改环)→ C2-1(滚动摘要)。
