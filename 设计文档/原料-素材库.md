### 1.2 铁律:素材是"喂给想象的原料",不是"想象本身"

**素材库与内核1(想象捕获)是相邻但本质不同的两个层**:

| 维度 | 内核1 · Imagination(想象) | 原料层 · Material(素材) |
|---|---|---|
| **来源** | 作者的原创创意冲动、脑海中浮现的意图 | 外部世界收集来的文字/图片/资料/他人作品片段 |
| **目的** | 直接驱动 AI 写作("我想要这个场景") | 为想象提供燃料("这条资料可以激发那个想象") |
| **处理方式** | 被内核1结构化为 Imagination 实体,直接调度进写作 | 经采集→处理→提炼,作为软参考注入写作上下文 |
| **进入AI prompt的方式** | 通过 AuthorIntent / Imagination 作为强约束 | 通过 MaterialSnippet 作为灵感参考(软约束) |
| **数据实体** | `Imagination`, `AuthorIntent` (§00 §4.1) | `Material`, `MaterialRef`, `StyleExemplar` (§00 §4.4) |

**核心职责三条流向**:

```
原料(Material)
   │
   ├── ① [检索注入] → 写作时 MaterialSnippet 进 ContextBundle → 实现4(记忆检索)协同
   │                   作用:触发想象、提供细节参考、注入新鲜感
   │
   ├── ② [提炼·设定] → SettingItem 导入门槛2(设定圣经)
   │                    作用:把未确立的世界观草稿升格为"已确立的设定事实"
   │
   └── ③ [提炼·文风] → StyleExemplar 供内核3(反平庸与文学质量)
                        作用:把文风原料变成 few-shot 范本,驱动写作对抗 AI 腔
```

### 1.3 不负责什么(边界清单)

| 不在原料层边界内 | 由哪一层/哪个文档负责 |
|---|---|
| 已提炼设定项的 CRUD / 一致性校验 | 门槛2-设定圣经 |
| ContextBundle 的 token 裁剪与排序主逻辑 | 实现4-记忆与检索 |
| StyleExemplar 的 few-shot steering 执行 | 内核3-反平庸与文学质量 |
| 正文版本快照与分支管理 | 工程4-版本与回流 |
| LLM 调用路由与成本控制 | 工程3-LLM接入与成本 |
| 一致性检测与 ConsistencyFlag 维护 | 门槛1-连贯性保障 |
| 图片渲染/CDN 存储 | 基础设施层(原料层只管元数据与引用追踪) |
| 版权合规执法 | 用户自行负责;原料层只提供标注字段 |
| Imagination / AuthorIntent 的捕获与调度 | 内核1-作者协作回路 |

## §2 设计目标与百万字挑战

### 2.1 设计目标(七条)

1. **低摩擦采集,不打断创作流**:任何入口 2–3 步内完成,不强迫作者在采集时做完整标注。"先存,后处理"是铁律。
2. **处理自动化,减少人工整理负担**:LLM 异步生成 `auto_summary` + `auto_tags` + `embedding`,让作者的手头积累自动变为可检索的原料。
3. **精准召回,避免"存了不用"**:写作时基于当前章节大纲语义召回最相关素材;usage_count + 时效信号防止高质量素材被沉压。
4. **提炼流转,原料→设定→文风**:保留从灵感原料到成稿的完整溯源链,每一步转化都有 MaterialRef 记录。
5. **跨作品可复用,全局库 + 作品库并存**:名字库、文风范本、意象库等可跨作品沿用,避免反复整理。
6. **出处可查,版权自知**:每条素材记录来源、每次引用/提炼均有追踪记录。
7. **百万字下不崩,素材库不变噪声源**:规模、索引、归档机制保障长期使用时检索质量不退化。

### 2.2 百万字尺度下的具体挑战

| 挑战 | 量化估算 | 应对机制 |
|---|---|---|
| 素材规模膨胀 | 百万字创作周期积累 500–3000 条素材 | 向量检索 + 标签过滤双路召回;不全量扫描 |
| 相关性推断噪声 | 碎片化文本 embedding 质量参差 | 写入时 LLM 生成 `auto_summary` + `auto_tags` 提升 embedding 信号密度 |
| "存了不用"长期沉积 | 大量 processed 素材 usage_count=0 | `usage_count` 排序加权 + `last_used_at` 时效衰减 + `archived` 状态 + 周期性"沉积素材提醒" |
| 图片素材语义检索困难 | 图片无直接文本语义 | 强制填写 `alt_text` + `caption`,对文本字段计算 embedding;"以文搜图" |
| 全局库 vs 作品库的召回污染 | A 作品素材在 B 作品写作时被召回 | `work_id=NULL` 全局素材降权 `scope_weight=0.6`;作品级素材 `scope_weight=1.0` |
| token 预算中素材挤占核心槽位 | 素材是"软参考",不应压缩设定/记忆预算 | ContextBundle 中独立字段 `material_snippets`,专属预算 `material_token_budget`(默认 600 token),与设定/记忆槽位物理隔离 |
| 素材提炼后追溯断链 | 设定项来自哪条素材?素材用进哪章? | `MaterialRef` 双向查询:正向(素材→引用处)/ 反向(章节→来源素材) |

> **【设计决策】**:百万字场景素材规模 < 3000 条,PostgreSQL 16 + pgvector HNSW 索引单实例完全可承载,无需独立向量库。遵循 §00 §3 原则9(ponytail:先验证子机制再递归组合)。

## §3 详细设计

### 3.1 素材类型体系(Material.type 枚举)

#### 3.1.1 type 枚举与各自的 content JSONB 结构

`Material.type` 枚举共 10 个值。每种类型 `content` 字段的 JSONB 结构如下——这是本文档最核心的设计部分。

---

**① type = `inspiration`(灵感碎片)**

突发的情节/人物/场景构想;梦里的画面;随手记录的感受。与 Imagination 的区别:这是作者收集到自己脑海之外触发的灵感碎片,而非直接下达给 AI 的创意指令。

```jsonc
{
  "text": "两个老对手在酒馆偶遇,没有打架,只是沉默地对饮。其中一人眼里是疲倦,另一人眼里是释然。这一幕可以用作卷三高潮之后的降温场景。",

  // ── 可选增强字段 ──
  "emotion_tags": ["疲倦", "释然", "对峙"],   // 情感标签
  "potential_use": "卷三降温场景",             // 作者设想的用途(可空)
  "is_scene_sketch": true,                    // 是否为场景素描
  "target_character_hint": null,              // 与哪个角色相关(可空)
  "urgency": "medium"                         // low/medium/high:作者主观觉得有多急迫要用
}
```

**嵌入文本**(计算 embedding 时使用):
`{title 若有} + auto_summary + text 前 300 字`

---

**② type = `reference`(参考资料)**

现实世界的资料性内容:历史事件、地理常识、民俗、科学知识、新闻、文化背景。浅度资料,通常短于 1000 字。

```jsonc
{
  "text": "宋代官员公服颜色制度:一品至四品着朱红色公服;五品至七品着绿色;八品九品着青色。腰带材质也有对应等级区分。",

  "source_type": "historical",   // historical / scientific / geographic / cultural / legal / other
  "reliability": "verified",     // verified(有明确来源可核实) / unverified(网络碎片)
  "key_facts": [                 // LLM 处理时提取的关键事实列表,便于快速扫描
    "一品至四品:朱红",
    "五品至七品:绿",
    "八品九品:青"
  ],
  "applicable_scenes": ["朝堂场景", "官场描写"]  // 适用场景提示
}
```

---

**③ type = `research`(深度研究)**

为作品专项调研的系统性资料:古代官制、武器工艺、医学知识、历史事件详考。通常 500–3000 字,有来源体系。

```jsonc
{
  "text": "（较长的系统性研究内容,可能 500-3000 字）古代炼丹术的基本流程:采药→洗净→炮制→配伍→炼制→收丹。炉火温度控制是关键……",

  // 允许分段结构化,便于注入时选择性截取
  "sections": [
    { "heading": "采药与炮制", "text": "……" },
    { "heading": "炼制工艺",   "text": "……" },
    { "heading": "危险与禁忌", "text": "……" }
  ],

  "sources": [
    { "title": "《道家养生文化研究》", "author": "某某",    "page": "42"           },
    { "url":   "https://example.com/alchemy",               "accessed": "2026-05-10" }
  ],

  "word_count":    850,
  "research_date": "2026-05-10",
  "reliability":   "verified",    // 与 reference 一样的可靠性字段

  // LLM 处理时提取的核心摘要(存在 auto_summary 中,此处可留空)
  "key_conclusions": ["炼丹需控制三阶段温度", "丹毒风险来自汞铅配比"]
}
```

---

**④ type = `snippet`(正文片段/试写稿)**

作者自己写的但尚未安排进章节的片段;试写稿;被删掉的段落。这是最接近"作者自产原料"的类型——可能日后被直接引用进正文。

```jsonc
{
  "text": "夜风从破窗灌入,吹得烛火东倒西歪。他没有抬头,只是把手边的酒杯往前推了推——不是邀请,是警告。",

  "word_count": 44,
  "draft_purpose":       "测试人物的非语言交流描写",
  "target_chapter_hint": null,         // 设想用在哪一章(可空)
  "writing_style_notes": "简洁,动作代替台词",
  "is_deleted_from_draft": false,      // 是否是从正文删除的段落
  "source_chapter_id":   null,         // 若是从正文划选存的,记录源 chapter_id
  "quality_self_rating": null          // 作者自评 1-10(可选)
}
```

---

**⑤ type = `quote`(金句/名言/摘录)**

他人作品中摘录的优质句子;诗词;精彩对白。主要价值在于文字本身——引发共鸣或激发改写灵感。

```jsonc
{
  "text": "人生得一知己足矣,斯世当以同怀视之。",

  "attribution":    "鲁迅赠瞿秋白",
  "source_work":    "信件",
  "source_author":  "鲁迅",
  "language":       "zh",                // zh / en / ja / other
  "quote_type":     "prose",             // prose / poetry / dialogue / aphorism
  "use_inspiration": "可作为主角与挚友决裂后的内心独白引用或化用",
  "copyright_safe":  true                // 是否版权安全(用户自判断)
}
```

---

**⑥ type = `name`(人名/地名/词汇库)**

备用人名、地名、门派名、物品名、法术名、称谓。可以是一批名字的集合,也可以是单个词汇。

```jsonc
{
  "items": [
    {
      "name":         "凌霄",
      "category":     "人名",          // 人名 / 地名 / 门派 / 物品 / 法术 / 称谓 / 其他
      "gender_hint":  "中性偏男",
      "meaning_note": "取「凌云壮志,直上霄汉」意",
      "atmosphere":   null,
      "used":         false,           // 是否已在作品中使用
      "used_for":     null             // 若已用,用在了哪个角色/地点
    },
    {
      "name":         "烬云城",
      "category":     "地名",
      "atmosphere":   "废墟感,战后余生",
      "meaning_note": null,
      "used":         false,
      "used_for":     null
    },
    {
      "name":         "碎星决",
      "category":     "法术",
      "power_level":  "中期功法",
      "atmosphere":   "凌厉、碎裂感",
      "used":         false,
      "used_for":     null
    }
  ],

  "batch_source": "手工整理",           // 这批名字的来源说明
  "naming_style":  "古风·武侠",        // 命名风格
  "count":        3
}
```

**注**:`name` 类型的 embedding 对 items 中所有 name + meaning_note + atmosphere 的拼接文本计算。

**⑦ type = `place_idea`(地点构想)**

尚未进入设定圣经的地点/场景灵感:文字描述、氛围词、空间感受、关联图片。

```jsonc
{
  "text": "一座建在悬崖边缘的废弃瞭望塔。四面都是深渊,只有一座摇摇欲坠的铁链桥连接对岸。塔内有百年前某个流浪剑客留下的刻字。",

  "atmosphere_words": ["孤立", "危险", "历史感", "神秘"],
  "potential_role":   "决斗 / 独处 / 重要谈话 / 秘密揭示",
  "spatial_notes":    "悬崖高度约千米;塔高三层;桥长约百米",
  "climate_feel":     "四季风大,常年大雾",
  "associated_characters": [],   // 构想与哪些角色相关

  // 关联图片素材的 material_id 列表(type=image 的素材)
  "image_refs": [],

  // 是否希望提炼为设定项
  "refinement_candidate": true
}
```

---

**⑧ type = `image`(图片素材)**

参考图/氛围图/人物外貌参考/场景参考。图片本体存对象存储,此处只存元数据。

```jsonc
{
  "storage_key":    "materials/img/uuid-xxxx.jpg",   // 对象存储路径(S3/OSS key)
  "mime_type":      "image/jpeg",
  "file_size_bytes": 1245678,
  "dimensions":     { "width": 1920, "height": 1080 },

  // ── 核心检索字段:这两个字段的文本用于计算 embedding ──
  "alt_text": "一座被雪覆盖的山顶古寺,正殿大门紧闭,门前积雪未被扰动",
  "caption":  "氛围参考:圣地/隐世门派的感觉",

  "image_category": "scene_ref",   // scene_ref / character_ref / object_ref / map / mood_board
  "color_palette":  ["冷白", "深灰", "枯木棕"],
  "mood_tags":      ["寂静", "神秘", "压迫感"],
  "linked_to":      null           // 关联的地点/角色素材 ID(可空)
}
```

**注**:图片素材在写作时只注入 `alt_text`(文本描述),不注入图片 URL。完整版当写作模型支持多模态时,可考虑注入图片本体。

**⑨ type = `worldbuilding`(世界观素材)**

尚未提炼进设定圣经的世界观构想:势力体系草稿、历史背景、魔法体系想法、宗教、经济逻辑。这是"候补设定",等待人工确认后提炼为 SettingItem。

```jsonc
{
  "text": "这个世界的「修炼之气」并非来自天地自然,而是来自远古战场上无数亡灵的怨念结晶。越是道德底线低的修炼者,往往越容易突破瓶颈——因为他们的精神污染与怨气更契合。这是整个体系的暗面。",

  "worldbuilding_category": "magic_system",
  // magic_system / history / geography / politics / religion / economy / social / lore / other

  "refinement_status": "draft",
  // draft(草稿,随时可改) / candidate(已考虑提炼) / refined(已提炼为设定项)

  // LLM 处理时或用户手动填写的结构化摘要
  "structured_draft": {
    "core_concept":   "修炼之气=亡灵怨念结晶",
    "implications":   ["道德底线影响修炼速度", "修炼者普遍精神受损"],
    "open_questions": ["怨念是否可以被净化?", "正道修炼者如何应对?"],
    "conflicts_with": []  // 与已有设定项的潜在冲突(系统自动检测后填充)
  },

  "target_setting_type": "rule"   // 希望提炼为哪种 SettingItem.type(可空)
}
```

---

**⑩ type = `style_sample`(文风范本原料)**

他人作品或作者自己试写的文风参考原文,待提炼为 `StyleExemplar` 供内核3使用。这是文风素材的原始状态——提炼后才能成为真正驱动写作的 StyleExemplar。

```jsonc
{
  "text": "刀光一闪,人头落地。没有迟疑,没有悲悯。杀人对他来说不比切菜更难——这才是真正可怕的地方。",

  "source_work":   "《某某小说》",
  "source_author": "佚名",

  // 作者自己标注的文风特征(可选;LLM 处理时也会自动分析)
  "style_features_noted": ["简洁暴力美学", "冷静旁观视角", "结尾回旋"],
  "applicable_character_types": ["冷酷杀手型", "道德灰色区主角"],
  "applicable_scene_types":     ["战斗场景", "处决场景"],

  "is_self_written":  false,   // 是否是作者自己写的试写稿
  "copyright_risk":   "medium", // low / medium / high(用户自评)

  // 提炼状态
  "distilled":        false,   // 是否已提炼为 StyleExemplar
  "exemplar_id":      null     // 提炼后的 StyleExemplar.id
}
```

#### 3.1.2 素材状态机

```
            ┌──────────────────────────────────────────────┐
            │                   raw                        │
            │  刚采集:内容已存,LLM 尚未处理                  │
            │  可参与手动引用,不参与自动向量召回              │
            └──────────┬─────────────────────┬─────────────┘
                       │                     │
            [后台 LLM 处理]           [用户手动归档]
                       │                     │
                       ▼                     ▼
            ┌──────────────────┐   ┌──────────────────────┐
            │    processed     │   │      archived         │
            │  有 auto_summary │   │  不参与日常召回         │
            │  有 auto_tags    │   │  出处追踪记录保留        │
            │  有 embedding    │   │  可通过搜索查询          │
            │  参与向量召回     │   └──────────────────────┘
            └──────────┬───────┘
                       │
            [提炼为设定项/StyleExemplar]
                       │
            MaterialRef 记录转化关系
            素材 status 维持 processed(不改状态)
```

- **`raw`**:刚采集,最低要求只有 `content.text` 或 `content.storage_key`。LLM 处理任务待触发。
- **`processed`**:已有 `auto_summary`、`auto_tags`、`embedding`,参与写作时的向量召回。被提炼后状态不变——提炼记录在 MaterialRef 中。
- **`archived`**:主动归档,从日常召回排除。保留出处追踪记录。支持查询但降权。

### 3.2 数据模型细化

#### 3.2.1 Material 表——完整字段

遵从 §00 §4.4 规范,以下为完整字段定义:

```sql
-- §00 §4.4 规范基线:
-- Material : id, owner_id, work_id→Work(nullable), type(...枚举...),
--            title, content(jsonb), source, tags(jsonb), embedding, status, created_at

CREATE TABLE materials (
    id              UUID PRIMARY KEY DEFAULT uuid_generate_v7(),
    owner_id        UUID NOT NULL,               -- 用户 ID
    work_id         UUID REFERENCES works(id),   -- NULL = 用户全局素材库
    type            TEXT NOT NULL CHECK (type IN (
                        'inspiration', 'reference', 'research',
                        'snippet', 'quote', 'name', 'place_idea',
                        'image', 'worldbuilding', 'style_sample'
                    )),

    -- ── 基础内容字段 ──
    title           TEXT,                        -- 可选,采集时可留空
    content         JSONB NOT NULL DEFAULT '{}', -- 按 type 分支,见 §3.1.1
    source          TEXT,                        -- 来源说明:URL/书名/文件名/对话
    source_url      TEXT,                        -- 网页剪藏时的原始 URL(机器可读)
    copyright_note  TEXT,                        -- 版权/授权说明(用户自填)

    -- ── 标签字段 ──
    tags            JSONB NOT NULL DEFAULT '[]', -- 用户手动标签 ["武侠","人名"]
    auto_tags       JSONB DEFAULT '[]',          -- LLM 自动生成的标签(辅助检索)

    -- ── 处理字段(LLM 处理后填充) ──
    auto_summary    TEXT,                        -- LLM 生成的 ≤100 字摘要
    embedding       VECTOR(1536),               -- pgvector;对 title+auto_summary+内容摘要计算

    -- ── 状态与生命周期 ──
    status          TEXT NOT NULL DEFAULT 'raw'
                        CHECK (status IN ('raw', 'processed', 'archived')),

    -- ── 使用统计(防止"存了不用") ──
    usage_count     INTEGER NOT NULL DEFAULT 0,  -- 被引用/使用次数
    last_used_at    TIMESTAMPTZ,                 -- 最后一次被引用的时间

    -- ── 采集元信息 ──
    capture_method  TEXT,                        -- 'manual'/'paste'/'web_clip'/'file_upload'/'chat_save'/'selection'
    work_context_hint TEXT,                      -- 采集时的作品上下文提示(辅助 LLM 处理)

    -- ── 审计字段 ──
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at      TIMESTAMPTZ                  -- 软删除
);

-- ── 索引 ──
CREATE INDEX idx_mat_owner_work     ON materials(owner_id, work_id);
CREATE INDEX idx_mat_type_status    ON materials(type, status) WHERE deleted_at IS NULL;
CREATE INDEX idx_mat_tags           ON materials USING GIN(tags);
CREATE INDEX idx_mat_auto_tags      ON materials USING GIN(auto_tags);
CREATE INDEX idx_mat_usage          ON materials(usage_count DESC, last_used_at DESC);
CREATE INDEX idx_mat_created        ON materials(created_at DESC);
-- pgvector HNSW 索引(百万字场景素材 < 3000 条,HNSW 优于 IVFFlat)
CREATE INDEX idx_mat_embedding      ON materials
    USING hnsw(embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64);
```

#### 3.2.2 MaterialRef 表——出处追踪

`MaterialRef` 是原料层的核心审计实体——记录"每条素材被用在哪里、怎么用的"。

```sql
-- §00 §4.4 规范基线:
-- MaterialRef : id, material_id→Material, used_in, target_id, ref_type, relevance, created_at

CREATE TABLE material_refs (
    id              UUID PRIMARY KEY DEFAULT uuid_generate_v7(),
    material_id     UUID NOT NULL REFERENCES materials(id),

    -- ── 引用目标类型 ──
    used_in         TEXT NOT NULL CHECK (used_in IN (
                        'chapter',        -- 素材被引用/注入到某章
                        'segment',        -- 素材被引用到某具体段落
                        'setting_item',   -- 素材被提炼为某个 SettingItem
                        'character',      -- 素材被提炼为某角色的属性/灵感来源
                        'style_exemplar', -- 素材被提炼为 StyleExemplar
                        'foreshadow'      -- 素材为某条伏笔提供灵感来源
                    )),
    target_id       UUID NOT NULL,       -- 对应 used_in 类型的目标记录 UUID

    -- ── 引用方式 ──
    ref_type        TEXT NOT NULL CHECK (ref_type IN (
                        'manual_cite',      -- 作者手动引用("把这条素材用进本章")
                        'ai_inject',        -- 写作时 AI 自动注入(MaterialSnippet 进入 prompt)
                        'distill_setting',  -- 提炼为 SettingItem
                        'distill_style',    -- 提炼为 StyleExemplar
                        'inspire_foreshadow'-- 作为伏笔灵感来源
                    )),

    -- ── 检索元信息 ──
    relevance       FLOAT,               -- ai_inject 时的相关性分数
    inject_position TEXT,               -- ai_inject 时在 prompt 中的位置标识

    -- ── 人工备注 ──
    human_note      TEXT,               -- 如"参考了这条素材写了第三段"

    -- ── 审计 ──
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by      TEXT NOT NULL DEFAULT 'human'  -- 'human' / 'ai'
);

CREATE INDEX idx_mref_material  ON material_refs(material_id);
CREATE INDEX idx_mref_target    ON material_refs(used_in, target_id);
CREATE INDEX idx_mref_ref_type  ON material_refs(ref_type);
```

### 3.3 采集:多入口低摩擦 Capture 系统

#### 3.3.1 七个采集入口

```
┌─────────────────────────────────────────────────────────────────┐
│                  素材采集入口(Capture Entrypoints)               │
│                                                                 │
│  ① 手动录入          前端素材库面板 → "新建素材"完整表单          │
│  ② 粘贴快速录入      编辑器内 Cmd+Shift+S 弹出轻量浮层            │
│  ③ 网页剪藏          粘贴 URL 后端抓取(MVP) / 浏览器扩展(完整版)  │
│  ④ 文件/图片上传     支持 .txt / .md / .docx / .pdf / .jpg / .png │
│  ⑤ 对话中随手存      AI 对话面板 → "存为素材"按钮                │
│  ⑥ 正文划选存料      编辑器划选 → 右键"存为素材" → type=snippet   │
│  ⑦ 批量导入          CSV / JSON 批量导入(完整版)                  │
└─────────────────────────────────────────────────────────────────┘
```

#### 3.3.2 核心原则:"先存,后处理"

**【设计决策】** 采集时只要求"能存下来",不强迫作者在采集瞬间完成完整标注:

```
采集时(最低要求):
  - type(必填,可选"不确定" → 系统默认 inspiration)
  - content.text 或 content.storage_key(至少有一个内容字段)
  - source(可选,可留空)

处理时(异步后台,不打断写作):
  - LLM 生成 auto_summary(≤ 100 字)
  - LLM 生成 auto_tags(4-8 个)
  - 计算 embedding
  - 状态 raw → processed
```

#### 3.3.3 关键入口的技术实现

**入口②:粘贴快速录入(高频核心入口)**

```
快捷键 Cmd+Shift+S 弹出浮层:
  ┌──────────────────────────────────────┐
  │ 存为素材                          ×  │
  │                                      │
  │ 内容(粘贴或输入):                   │

  │                                      │
```

**入口④:文件/图片上传**

```python
async def upload_material_file(
    file:            UploadFile,
    owner_id:        UUID,
    work_id:         UUID | None,
    user_type_hint:  str | None = None,

    if file.content_type.startswith("image/"):

        return await create_material(MaterialCreate(
            type    = 'image',
            content = {
                "storage_key":    storage_key,
                "mime_type":      file.content_type,

            capture_method = 'file_upload',
            status         = 'raw',
            ...
        ))
    else:
        text_content  = await extract_text_from_file(file)  # txt/md 直读;docx/pdf 解析
        inferred_type = user_type_hint or _infer_type_from_text(text_content)

            capture_method = 'file_upload',
```

### 3.4 处理流程:raw → processed

#### 3.4.1 异步处理流水线

```
Material(status=raw)
         │
         ▼
[ProcessingQueue]  ← 异步任务队列(Celery / FastAPI BackgroundTasks)
         │
         ├─ Step 1: 内容预处理
         │     文本截断(超长 research 取前 2000 字 + 最后 300 字)
         │     name 类型:将 items[].name/meaning_note/atmosphere 展平为可检索文本
         │     image 类型:若 alt_text 为空则暂跳过 LLM 步骤,标记待补充
         │
         ├─ Step 2: LLM 辅助提炼(调用 工程3-LLM接入与成本 的 LLM 路由)
         │     生成 auto_summary(≤ 100 字,聚焦核心信息+关键实体+适用场景)
         │     生成 auto_tags(4-8 个:实体名/类别/情感/场景)
         │     若 type=worldbuilding:填充 content.structured_draft
         │     若 type=style_sample:预分析 style_features_noted(可选)
         │
         ├─ Step 3: Embedding 计算
         │     嵌入文本 = (title if title) + auto_summary + content_preview[:300]
         │     调用 工程3 embedding 接口 → 存入 embedding 字段
         │
         └─ Step 4: 状态更新
               status: raw → processed
               updated_at: NOW()
               (失败则维持 raw,最多重试 3 次)
```

### 3.5 检索注入:写作时的素材召回

#### 3.5.1 召回在回路中的时机

```
WritingAgent 生成前 → 实现4(记忆与检索)拼装 ContextBundle
                                        │
                      ┌─────────────────┴─────────────────────┐
                      │  assembleContext 各槽位:               │
                      │  · 设定摘要(门槛2)                     │
                      │  · 人物状态(门槛2)                     │
                      │  · 章节记忆(实现4)                     │
                      │  · 伏笔追踪(门槛1)                     │
                      │  · 【素材片段】← 本模块提供            │  ← 独立槽位
                      │    material_snippets[]                 │
                      │    material_token_budget (默认 600)    │
                      └────────────────────────────────────────┘

原料层提供: queryRelevantMaterials(work_id, chapter_id, draft_outline)
            → MaterialSnippet[] (摘要+标签,不含完整 content)
```

**关键设计**:素材是"软参考"——有独立 `material_token_budget`,不与设定/记忆槽位竞争 token。作者可随时将预算调为 0 关闭素材注入。

#### 3.5.2 两路召回 + RRF 融合

```python
async def query_relevant_materials(
    work_id:               UUID,
    owner_id:              UUID,
    chapter_id:            UUID,
    draft_outline:         str,
    top_k:                 int  = 10,
    material_token_budget: int  = 600,
    type_filter:           list[str] | None = None,
    exclude_archived:      bool = True,
) -> list[MaterialSnippet]:
    """
    路 A:向量语义检索
          draft_outline → embedding → pgvector 余弦相似度
    路 B:标签关键词匹配
          从大纲提取实体名/关键词 → 匹配 tags + auto_tags(GIN 索引)

    融合:RRF(k=60) + usage_count 轻微权重加成
    后处理:
      - 图片类降权(除非大纲明确涉及外貌/场景描写)
      - archived 排除
      - 全局素材 scope_weight=0.6,作品素材 scope_weight=1.0
      - token 预算截断
    """
```

**路 A:向量语义检索(SQL)**

```sql
SELECT
    m.id, m.type, m.title, m.auto_summary, m.tags, m.auto_tags,
    m.source, m.usage_count, m.last_used_at,
    1 - (m.embedding <=> :query_embedding) AS vec_score
FROM materials m
WHERE (m.work_id = :work_id OR m.work_id IS NULL)
  AND m.owner_id  = :owner_id
  AND m.status    = 'processed'
  AND m.deleted_at IS NULL
  AND (:type_filter IS NULL OR m.type = ANY(:type_filter))
ORDER BY m.embedding <=> :query_embedding
LIMIT :top_k * 2;
```

**路 B:标签关键词匹配(SQL)**

```sql
SELECT m.id,
       (SELECT COUNT(*) FROM JSONB_ARRAY_ELEMENTS_TEXT(m.tags || m.auto_tags) AS t
        WHERE t = ANY(:keywords))::FLOAT / ARRAY_LENGTH(:keywords, 1) AS tag_score
FROM materials m
WHERE (m.work_id = :work_id OR m.work_id IS NULL)
  AND m.owner_id  = :owner_id
  AND m.status    = 'processed'
  AND m.deleted_at IS NULL
  AND (m.tags ?| :keywords OR m.auto_tags ?| :keywords)
ORDER BY tag_score DESC
LIMIT 20;
```

**RRF 融合**:

```python
def merge_material_results(
    vec_results: list[tuple[UUID, float]],
    kw_results:  list[tuple[UUID, float]],
    materials:   dict[UUID, MaterialRow],
    k:           int = 60,
) -> list[tuple[UUID, float]]:
    """
    RRF 融合 + usage_count 轻微权重
    combined_score = rrf_score
                   + 0.05 * log(1 + usage_count)          # 防马太效应,权重轻
                   + scope_bonus(0 if work_id else -0.1)   # 全局素材轻微降权
    """
    rrf: dict[UUID, float] = {}
    for rank, (mid, _) in enumerate(vec_results, 1):
        rrf[mid] = rrf.get(mid, 0.0) + 1.0 / (k + rank)
    for rank, (mid, _) in enumerate(kw_results, 1):
        rrf[mid] = rrf.get(mid, 0.0) + 1.0 / (k + rank)
    for mid in rrf:
        mat = materials[mid]
        rrf[mid] += 0.05 * math.log(1 + mat.usage_count)
        if mat.work_id is None:      # 全局库素材降权
            rrf[mid] -= 0.10
    return sorted(rrf.items(), key=lambda x: -x[1])
```

#### 3.6.2 沉积素材检测

```python
async def get_unused_materials(
    owner_id:       UUID,
    work_id:        UUID | None,
    days_threshold: int = 30,
    status_filter:  list[str] = ['processed'],
) -> list[MaterialSummary]:
    """
    返回:past N 天内未被引用、usage_count=0 的 processed 素材
    前端:在作者切换到新卷/新章节时展示"待激活素材"提醒

```

**四项防沉积机制**:

1. **`usage_count` 召回加权**:被引用过的素材在相关性相近时略微优先(防止高质量素材沉底)
2. **"待激活提醒"**:前端在作者切换新卷/新章节时,提示"你有 X 条素材可能与本卷相关但尚未使用"
3. **`archived` 主动归档**:确认不再使用的素材可归档,从日常召回排除,出处记录保留
4. **周期性"素材健康度报告"**:每卷完成后可触发 `get_unused_materials`,生成未使用素材汇总

#### 3.6.3 版权与来源标注

- `material.source`:自由文本,记录"来自哪里"(书名/URL/文件名/对话)
- `material.source_url`:网页剪藏时的原始 URL,机器可读
- `material.copyright_note`:用户自填的版权说明("CC BY-SA"/"商业禁用"/"自创")
- `StyleExemplar.source_material_id`:追溯"这个文风范本来自哪条素材"
- **注**:系统不做版权执法,只提供字段记录与展示;版权合规由用户自行负责。

### 3.8 百万字下的规模管理

#### 3.8.1 规模估算与 PostgreSQL 承载评估

| 维度 | 估算量 | PostgreSQL 承载 |
|---|---|---|
| 素材总条数(用户全局库) | 500–3000 条 | 轻松,单表 |
| 其中 type=image 的图片素材 | 50–500 条 | 元数据在 PG,图片本体在对象存储 |
| embedding 向量数(1536 维) | 500–3000 个 | pgvector HNSW < 3000 条时延迟 < 5ms |
| MaterialRef 记录 | 1000–10000 条 | 轻松 |
| StyleExemplar | 20–200 个 | 轻松 |

> **【设计决策】**:无需独立素材数据库。PostgreSQL 16 + pgvector 单实例完全可承载百万字场景的素材数据量。

#### 3.8.2 图片素材的特殊处理

- **存储**:图片本体上传对象存储(S3/OSS);数据库只存元数据
- **检索**:图片不直接向量化;对 `alt_text + caption` 计算文本 embedding,"以文搜图"
- **注入**:写作时只注入 `alt_text`(文本描述),不注入图片 URL。完整版若写作模型支持多模态则可注入图片 URL,但 MVP 维持文本方案

#### 3.8.3 全局库 vs 作品库的隔离

```
work_id = NULL   全局素材库(跨作品复用:名字库/文风范本/通用意象)
                 检索时 scope_weight = 0.6(降权避免跨作品污染)

work_id = :wid   作品级素材库(专属于当前作品)
                 检索时 scope_weight = 1.0(优先)

WHERE 条件:
  (m.work_id = :work_id OR m.work_id IS NULL)
```

## §6 失败模式与缓解

### 6.1 采集阶段

| 失败模式 | 表现 | 缓解机制 |
|---|---|---|
| 网页剪藏抓取失败 | robots.txt 禁止 / 需登录 / JS 渲染页面 | 降级为"仅保存 URL",提示用户手动粘贴;status=raw 保留 |
| 文件解析失败 | PDF 扫描版 / 加密文件 / 格式损坏 | 提示"无法解析,请手动粘贴内容";仍创建素材记录保留文件名 |
| 图片上传超大 | 用户上传 50MB 原图 | 后端限制 20MB / 自动压缩;前端提示 |
| 采集时无作品上下文 | 没有 work_id | 询问"关联到哪个作品?"(可跳过,存为全局素材 work_id=NULL) |

### 6.2 处理阶段

| 失败模式 | 表现 | 缓解机制 |
|---|---|---|
| LLM 处理超时/失败 | auto_summary / auto_tags 为空 | 维持 raw 状态,最多 3 次重试;超过后前端显示"处理失败,点击重试" |
| LLM auto_tags 质量差 | 标签无意义或过宽泛 | 用户可在素材卡片上手动编辑/删除/补充标签 |
| Embedding 计算失败 | 向量未写入 | 无法参与向量召回;前端显示"未索引"状态;支持用户触发重处理 |
| 内容过长导致截断 | research 类 3000 字被截断 | 取前 2000 字 + 最后 300 字送入 LLM;完整内容保留在 content.text |

### 6.3 检索与注入阶段

| 失败模式 | 表现 | 缓解机制 |
|---|---|---|
| 召回素材与写作内容不相关 | 噪声注入干扰 WritingAgent | `material_token_budget` 可配置为 0;作者可在写作面板手动关闭素材推荐 |
| 图片素材 alt_text 为空 | 无法参与检索,注入内容为空 | 创建图片素材时 alt_text 为前端强制填写;MVP 不支持多模态注入 |
| 素材挤占核心 token 预算 | 写作质量下降 | 素材有独立专属预算,与设定/记忆槽位物理隔离,互不竞争 |
| LLM 逐字复制素材原文 | 生成文本剽窃素材 | Prompt 明确说明"触发灵感,无需逐字复用";ReviewAgent 检查与素材的 n-gram 重叠率 |

### 6.4 提炼阶段

| 失败模式 | 表现 | 缓解机制 |
|---|---|---|
| 提炼为设定项的结构不完整 | LLM 生成 content JSONB 缺少必要字段 | "预览提炼结果"步骤提示用户补充,不自动强制写入 门槛2 |
| 素材与已有设定冲突 | 提炼后与 SettingItem 现有内容矛盾 | 提炼前调用 门槛2 validate 预检;发现冲突提示用户确认 |
| 提炼操作无法撤销 | 用户误提炼 | MaterialRef 保留记录;设定项可在 门槛2 软删除;素材状态维持 processed 可再次操作 |

### 6.5 长程崩坏:百万字素材库沉积

| 失败模式 | 表现 | 缓解机制 |
|---|---|---|
| 素材库膨胀,检索质量下降 | 3000 条素材中大量噪声 | 定期"素材健康度报告";鼓励用户归档已过期素材 |
| 全局库跨作品污染 | A 作品素材在 B 作品写作时被召回 | 全局素材 scope_weight=0.6 降权;作品级优先 |
| 标签体系失控 | 每位用户标签各自为政,无法标准化 | 系统提供推荐标签维度(不强制);auto_tags 提供标准化补充 |

## §9 开放问题

### 9.1 素材注入对写作质量的实际影响

**问题**:MaterialSnippet 注入究竟能提升多少生成质量?是否有负面影响(LLM 直接复制素材原文)?

**建议验证**:通过 工程6-质量度量 A/B 对比:同一章节,有素材注入 vs 无素材注入,对比新鲜感/意外性/文字质感评分;同时检测生成文本与素材原文的 n-gram 重叠率。

### 9.2 type='image' 的多模态注入可行性

**问题**:MVP 只注入 `alt_text` 文本。完整版是否应支持将图片 URL 直接注入给支持多模态的写作模型?

**待定**:取决于 工程3-LLM接入与成本 的多模态模型选型。若写作模型支持视觉输入,则可直接注入图片;否则维持文本 alt_text 方案。

### 9.3 素材提炼的自动化程度

**问题**:LLM 辅助提炼为设定项时,高置信度情况下是否可"自动写入 + 低优先级标黄待确认"?

**当前设计**:必须经用户确认。

**待讨论**:误提炼率评估后,可考虑对明确是地名/人名定义的高置信度提炼开放自动写入选项。

### 9.4 素材相似度去重

**问题**:用户可能重复录入内容相近的素材。是否应在采集时自动检测相似度?

**待设计**:创建素材时检索 embedding 相似度 > 0.92 的素材,提示"发现可能重复"。MVP 不实现,完整版纳入。

### 9.5 素材与伏笔联动深度

**问题**:灵感碎片(inspiration)常常直接对应一条伏笔的灵感来源。`MaterialRef.used_in` 枚举是否纳入 `foreshadow` 类型?

**当前状态**:`ref_type` 中已预置 `inspire_foreshadow` 扩展点(见 §3.2.2)。需要与 门槛1-连贯性保障 对齐枚举值后确认。

### 9.6 material_token_budget 最优值

**问题**:默认 600 token 的素材预算是否合理?不同写作场景(战斗章节 vs 情感章节)最优配置可能不同。

**建议**:收集"素材注入后对生成内容是否有贡献"的用户反馈(采纳率),结合 工程6-质量度量 的评分曲线,动态调整各场景下的默认预算。

### 9.7 素材库与 Imagination 的协同边界

**问题**:当一条灵感碎片(Material.type=inspiration)与一个 Imagination 实体描述的内容非常接近时,两者是否应该自动关联?还是由用户手动操作?

**待设计**:可以在"快速录入灵感素材"时提供"同时转为 Imagination"选项,让作者一步将外部触发的灵感碎片直接升格为内核1的创意指令。这涉及 内核1-作者协作回路 的接口扩展。
