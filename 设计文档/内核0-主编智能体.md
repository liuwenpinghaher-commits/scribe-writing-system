# 内核0 · 主编智能体(Chief Editor Agent)

> **这是系统的中枢,也是你唯一直接对话的对象。** 其余所有文档(内核1–3、实现、门槛、原料、工程)都是它的"能力"与"器官"。
> 它的定位:一个**读完你全书、记得你所有写作与素材、能随时全网检索、会主动思考并优化整个系统**的最强责编/主编——但你永远拍板。
> 本文取代上一轮提出但未落地的"讨论闸"提案,把"对话式交互"正式并入主编设计。

---

## 1. 在回路中的位置

主编是**协作回路([内核1](内核1-作者协作回路.md))的指挥**。你和它对话;它调动一切去实现你的想象、并在你思考不完善/全文有缺陷/有更优解时与你讨论。

```
            你(想象 + 意见 + 拍板)
                  ▲  │
       讨论/提议  │  │ 对话
                  │  ▼
        ┌──────────────────────┐
        │   主编智能体 (内核0)    │  ← 统一人格;你对话的对象
        │  规划·写作·评议·主动·优化 │
        └──────────┬───────────┘
   通过"工具/检索/记忆/子Agent"获得"全面",而非把一切塞进上下文
        ┌──────────┼───────────────────────────────┐
        ▼          ▼            ▼          ▼         ▼
    内核1 回路  内核2 品味   内核3 反平庸  实现层    门槛层+原料
    (想象/意见) (懂你的书)  (写得好)    (规划/写作/ (连贯/设定/
                                       记忆检索)  素材)
                        + 工具:全网搜索 · 跨会话记忆 · 主动引擎 · 自我优化
```

**它不负责什么**:不替你做"什么是好"的最终判断(那是你的品味);不绕过你直接对外发布;不在未经批准时改动系统自身的关键流程。

## 2. 设计目标与百万字挑战

你要的是"掌握全书+全部写作+全部素材+随时全网+主动优化一切"的主编。第一性的矛盾是:

> **"全面" vs "上下文装不下"**:100 万字 ≈ 150–200 万 token,远超任何模型窗口(Hermes 4 / GPT 128K、Claude 200K)。

**结论(有证据):"全面"必须靠工具+检索+分层记忆+按需子Agent 实现,绝不能靠"把一切塞进上下文"或"堆一堆 Agent"。**
- Google Research 2025《Scaling Agent Systems》:并行任务多 Agent **+81%**,串行任务 **−39%~−70%**——盲目多 Agent 有害。【已核实】[来源](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)
- Anthropic《Building Effective Agents》:**默认从单 LLM+检索开始**,仅在更简单方案不够时才上 Agentic 复杂度;**工具质量比 prompt 更重要**。【已核实】[来源](https://www.anthropic.com/research/building-effective-agents)

所以主编 = **一个统一人格的编排 Agent**,深度来自下面的"工具+记忆+检索+子Agent 骨架"。

## 3. 详细设计

### 3.1 "全面"的四个来源(不是塞上下文)

| 来源 | 让主编"掌握" | 实现 |
|---|---|---|
| **检索(Select)** | 全书正文/设定/伏笔/时间线/素材 | 实现4 检索 + 原料库,按需召回进 ContextBundle |
| **分层记忆(Write/Compress)** | 你的写作历史、个人偏好、过往讨论、流程经验 | §3.3 五层记忆命名空间 |
| **工具(Act)** | 全网搜索、一致性校验、伏笔扫描、派子Agent | §3.2 工具箱 |
| **按需子Agent(Isolate)** | 可并行的重活(多线索研究、批量章节) | §3.9 单体 vs 多Agent 决策 |

> 采用 2025 上下文工程共识框架 **Write / Select / Compress / Isolate**。【已核实】[mem0 指南](https://mem0.ai/blog/context-engineering-ai-agents-guide)

### 3.2 工具箱(主编的"手")

工具设计遵循 Anthropic《Writing Tools for Agents》:**少而精、描述严格、参数无歧义、防呆、可并行**;工具 schema 按需检索而非一次性全塞。【已核实】[来源](https://www.anthropic.com/engineering/writing-tools-for-agents)

| 工具 | 作用 | 背后 |
|---|---|---|
| `search_book(query, scope)` | 召回本书相关正文/设定/事件 | 实现4 |
| `search_materials(query)` | 召回素材 | 原料库 |
| `recall_memory(namespace, query)` | 读跨会话记忆 | §3.3 |
| `web_search(query)` / `web_fetch(url)` | 全网检索/取证(结果须 sanitize 防注入) | 外部 |
| `check_consistency(scope)` / `scan_foreshadow(scope)` | 全文体检 | 门槛1 |
| `propose_options(decision_point)` | 产出多方案 OptionSet | 内核1 |
| `dispatch_subagent(role, task, context)` | 派专业子Agent | §3.9 |
| `propose_skill(name, spec)` | 提议新技能/流程优化(待你批准) | §3.6 |

**联网搜索上限**:单任务工具调用设上限(业界推荐 10–15 次)防失控循环;搜索结果回灌前清洗。【已核实】

### 3.3 跨会话记忆(主编的"脑海")

采用业界共识的五层 + 命名空间隔离(防膨胀/防串味):

```
working  (工作记忆)  : 当前任务进度、scratchpad —— 任务结束即清
session  (会话记忆)  : 本次对话
episodic (情节记忆)  : 过往讨论/决定/被你否决的方案 —— "上次你说不要狗血反转"
semantic (语义记忆)  : 关于【书】(主线/设定摘要)、【你】(偏好=内核2)、【素材】、【流程】的稳定知识
meta     (元记忆)    : 哪种做法对你有效 —— "对这本书,先给3个方案你最满意"
```

- 落地:MVP 用 PostgreSQL(LangGraph Store 模式:线程内 checkpointer + 跨线程 store);规模化再评估图记忆(Zep/Graphiti 在关系推理上更强)。【已核实】[mem0 记忆现状](https://mem0.ai/blog/state-of-ai-agent-memory-2026)
- **生产四坑须防**:记忆膨胀(去重)、过时数据(可变属性用确定性 key 覆写)、命名空间冲突、提取幻觉(结构化输出 + 置信度 >0.8 才存)。【已核实】
- 你点名的"掌握历史、个人记忆、素材、流程"全部落在 episodic + semantic + meta 三层。

### 3.4 对话式交互:主编是"读完全书的责编",不是打字机

研究证实:**共创/责编模式 > 代笔**(用户要控制权+可见贡献+所有权);**AI 当"挑战者/提问者"而非"直接改写者"能保护作者声音**。【已核实】[arXiv 2504.12488](https://arxiv.org/pdf/2504.12488) · [GhostWriter](https://arxiv.org/abs/2402.08855)

主编对你的每个输入(想象/意见),不是默默执行,而是先**评议**:

```
你输入(// 即时捕获, 零摩擦)
   └─▶ 主编评议:对照 北极星 + 全书状态(检索/伏笔/时间线) + 你的品味 + craft
          ├─ 无实质问题 ──▶ 直接执行(保持心流)
          └─ 有冲突/缺陷/更优解 ──▶ 发起讨论 DiscussionThread:
                · 指出问题 + 证据(具体到第X章伏笔/某设定/北极星红线)
                · 标注 硬冲突(确定) / 软建议(观点) 的置信度
                · 给 1–N 个备选 + 各自代价
                · 多轮对话收敛 → 你拍板(可一键"就按我说的"覆盖)
                     └─▶ 执行
```

**关键分工(这修正了设计哲学的一个偏差)**:

> **AI 弱在"品味判断"(什么是好),但强在"全局判断"(这个想法跟全书冲不冲突、合不合)——因为它读得完、记得住 100 万字,而你做不到。**
> 所以:**硬冲突由主编主导**(它有全书证据)、**好坏由你主导**(品味)。讨论就是两者交汇的地方。

**防过度打扰**:讨论分级触发(只在有实质内容时发起);你可设"挑战强度"(心流模式=全捕获攒着回头议 / 深思模式=逐条议)。

### 3.5 主动引擎(行业最大空白 = 你的差异化)

研究确认:**主动的全文分析(揪出没回收的伏笔、弧线断裂、主题偏离)是全行业最大空白**,现有产品全被动。【已核实,见调研报告第五节】主编要做这件事,但遵循"提议而非打断"五原则。【已核实】[MindStudio](https://www.mindstudio.ai/blog/what-is-proactive-ai-agents-shifting-reactive-anticipatory)

- **触发**:混合模式——Cron(每写完 N 章/每日做一次全文体检)+ 事件(改了关键设定即触发受影响范围复查)。
- **产出**:`ProactiveInsight`(洞察)——如"你 30 章前埋的伏笔A 已 80 章未回收""最近 5 章主线在偏离北极星""配角B 的动机断了""这条线索可以和主线并起来更有张力"。
- **分级行动**(按置信度×风险):多数只**告知**、部分**起草备选**、极少**直接做**(且可撤销)。**低误报优先**(频繁误报的主动 AI 会被无视——"狼来了"效应)。
- **不打断**:以安静的"主编札记"呈现,你有空再看;绝不弹窗打断写作心流。

### 3.6 自我优化(你点名的"主动优化现有系统所有部分")

主编可**反思并提议优化系统自身**——不限于书,也包括流程、提示、技能、记忆结构。借鉴 Hermes Agent 的"自主技能创建+自我改进闭环",但**加约束**(防失控自主,arXiv 2502.02649 明确警告全自主 Agent 风险【已核实】):

- 主编可 `propose_skill` / 提议流程改动(如"我发现你总在卷尾卡壳,建议加一个'卷尾钩子专项工作流'")。
- **人审批门**:任何对系统流程/技能/权限的改动,必须你批准才生效;主编只能提议+给收益论证,不能自行改关键配置。
- 所有自我改动进版本与审计(可回滚)。

### 3.7 模型路由:多模型,Hermes 是其中关键一员

不押注单一模型。按"任务性质"路由(对齐[工程3](工程3-LLM接入与成本.md)):

| 任务 | 推荐 | 理由 |
|---|---|---|
| 全局编辑判断 / 复杂情节逻辑 / 顶级文笔 | **前沿闭源(Claude Opus 等)** | 推理深度与文笔上限最高【已核实:第三方评测 Hermes 通用基准不及前沿】 |
| 贴合你文风的起草 / 暗黑题材 / 隐私敏感 / 海量低成本生成 | **Hermes 4(自托管 + LoRA)** | **开源权重→在你作品上 LoRA→"懂你的书"护城河**;低拒绝;本地零边际成本【已核实】 |
| 规划/审校/摘要/抽取等高频轻活 | 快模型 | 成本 |

> **个性化路线(有证据)**:`Prompt → RAG → LoRA → 蒸馏`,"微调接口、检索内容"。语料稀缺先 RAG+对比样本(实测 +15% 风格贴合);需稳定文风控制再上薄 LoRA;有偏好数据(你的接受/否决)再 DPO/KTO。【已核实】[arXiv 2504.08745](https://arxiv.org/abs/2504.08745) · [个性化综述](https://arxiv.org/pdf/2411.00027)

### 3.8 反同质化(保护你的声音)——硬约束

AI 会把写作拉向"中立平均"("麦当劳化/大抚平",arXiv 实测【已核实】[arXiv 2508.01491](https://arxiv.org/pdf/2508.01491))。主编必须主动对抗:
- few-shot 注入**你的**范本 + **对比样本**(让模型看到"不是你风格"的反例);
- 对你的作品 LoRA(§3.7);
- 多样性约束解码;
- **AI 当挑战者而非改写者**(§3.4);
- 每段 AI 贡献**可见可追溯**,让你能主动抵抗被同化。

### 3.9 单体 vs 多Agent:何时拆(有证据的纪律)

主编对你是**单一人格**,但内部按任务性质决定是否拆子Agent:

| 任务 | 形态 | 依据 |
|---|---|---|
| 串行/强依赖(逐章推进、改一处连锁校验) | **主编单体直跑** | 多 Agent 在串行上 −39~−70%【已核实】 |
| 可真并行(多线索资料调研、批量独立章节、多视角评审) | **派子Agent(sub-agent-as-tools)** | 并行任务 +81%【已核实】 |

> 铁律:**默认单体;只有任务能真正并行才拆**。不为"显得高级"而堆 Agent。

## 6. 失败模式与缓解

| 风险 | 缓解 |
|---|---|
| **谄媚/自证陷阱**(模型为自己的错误辩护) | 评议用**不同的批评模型或外部验证(检索/校验工具)**,而非自我反思空转【已核实:self-consistency trap】 |
| **过度主动/误报刷屏** | 分级触发 + 低误报优先 + 安静札记不打断 |
| **过度反思退化/成本爆炸** | 反思设轮次上限 + 置信度早停 + 批评用小模型 |
| **失控自主**(自行改系统) | 最小权限 + 关键改动人审批门 + 全审计可回滚【已核实 arXiv 2502.02649】 |
| **碾平你的声音** | §3.8 反同质化硬约束 |
| **上下文噪音/串味** | 记忆命名空间隔离 + 子Agent 最小上下文 |

## 7. MVP vs 完整版

- **MVP**:主编 = 单体编排 Agent + 核心工具(search_book/web_search/propose_options)+ 基础记忆(session+semantic,PostgreSQL)+ 对话式评议(内核1 回路)。模型:前沿闭源驱动即可跑通。**不上**子Agent、不上 Hermes 自托管、不上自我优化。
- **增强版**:加主动引擎(Cron 全文体检 → ProactiveInsight)、episodic/meta 记忆、可并行子Agent、Hermes LoRA 个性化起步。
- **完整版**:自我优化闭环(propose_skill + 人审批)、图记忆、多模型成本路由成熟、反同质化全套。
- **Hermes Agent 框架**:可在 MVP/增强阶段作为**运行底座选型之一**评估(它原生提供记忆/子Agent/MCP/Cron/工具注册),与"自建 FastAPI 编排"二选一或混用——决策见 §8。

## 8. 证据与引用(含 Hermes 裁决)

**Hermes 裁决(基于联网核实):**
- **Hermes Agent 是真实独立框架**(MIT、模型无关、原生记忆/子Agent/MCP/Cron/70+工具/自我改进):[官网](https://hermes-agent.nousresearch.com/) · [GitHub](https://github.com/NousResearch/hermes-agent)。**裁决:架构强参考;MVP 可评估作运行底座;但不硬绑产品**(你已有自建栈,且框架抽象会带来锁定)。
- **Hermes 4 模型**(开源权重、MIT、128K、混合推理、强可操纵、低拒绝、创意写作好;但通用/推理基准不及前沿):[Hermes 4 报告 arXiv 2508.18255](https://arxiv.org/pdf/2508.18255) · [HF](https://huggingface.co/NousResearch/Hermes-4-70B)。**裁决:当多模型里的"个性化+隐私+低成本+低拒绝"专用模型**(§3.7),不当唯一大脑。
- 【需复核】Hermes 的 RefusalBench、"创意写作领先"多为自报或社区定性,缺严格第三方对比;Hermes Agent 的 star 数等运营数据随时间变化,使用前复核。

**架构与方法(已核实):** Scaling Agent Systems(并行+81%/串行−39~−70%)[Google](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/);Building Effective Agents [Anthropic](https://www.anthropic.com/research/building-effective-agents);Writing Tools for Agents [Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents);上下文工程 Write/Select/Compress/Isolate [mem0](https://mem0.ai/blog/context-engineering-ai-agents-guide);记忆现状 [mem0](https://mem0.ai/blog/state-of-ai-agent-memory-2026);全自主风险 [arXiv 2502.02649](https://arxiv.org/pdf/2502.02649)。

**交互与个性化(已核实):** 共创>代笔 [arXiv 2504.12488](https://arxiv.org/pdf/2504.12488);GhostWriter [arXiv 2402.08855](https://arxiv.org/abs/2402.08855);RAG+作者特征+15% [arXiv 2504.08745](https://arxiv.org/abs/2504.08745);同质化"大抚平" [arXiv 2508.01491](https://arxiv.org/pdf/2508.01491);异构递归规划 [arXiv 2503.08275](https://arxiv.org/pdf/2503.08275)。

**诚实声明:** "主动全文分析"是研究空白,主编这部分多为【设计决策】,须靠[工程6](工程6-质量度量.md)自建度量验证;"让 AI 写得好/不被同化"无银弹。

## 9. 开放问题

1. MVP 究竟"自建 FastAPI 编排" vs "基于 Hermes Agent 框架",需做一次小型技术验证(spike)再定。
2. Hermes LoRA 个性化:多少作者语料才够、如何避免过拟合致通用能力退化,需实验。
3. 主动引擎的"札记"频率与误报阈值,需用你的真实使用数据校准。
4. 全局判断 vs 品味判断的边界,在实践中会模糊(有些"硬冲突"其实是你故意为之的伏笔/不可靠叙事)——评议须能被你一句"这是故意的"训练。
