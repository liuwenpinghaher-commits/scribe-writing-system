## § 1 · 在回路中的位置与职责

```
  人(想象 + 意见)
      │
      ▼
┌─────────────────────────────────────────────────────────┐
│  TIER 0  前端层 ← 人在环暂停点,多方案选择,意见提交         │
├─────────────────────────────────────────────────────────┤
│  TIER 1  编排层 ← 协作回路的"神经系统":驱动 AI 主笔全流程  │
├──────────┬──────────┬──────────┬──────────┬─────────────┤
│  内核服务 │  实现服务 │  门槛服务 │  原料服务 │  评估服务   │ TIER 2
├─────────────────────────────────────────────────────────┤
│  TIER 3  LLM 接入层 (多模型路由 / 缓存 / 成本)            │
├─────────────────────────────────────────────────────────┤
│  TIER 4  数据层 (PostgreSQL + pgvector + Redis)          │
└─────────────────────────────────────────────────────────┘
```

**工程层的核心任务**:让协作回路能跑起来——让内核服务(Imagination/AuthorIntent/TasteModel/FeedbackNote)成为编排的一等参数,让 AI 的每一次生成都带着"这个作者的想象与品味",让人在环暂停在架构上有明确支撑点。

**架构铁律**(所有文档遵守):

| # | 铁律 |
|---|------|
| A1 | Agent 不直接读写 DB;一律通过 TIER 2 服务接口 |
| A2 | TIER 2 服务无状态;所有状态持久化在 TIER 4 |
| A3 | 章生成必须异步;前端触发后立即返回 task_id |
| A4 | LLM 调用全部经 TIER 3;TIER 2 不直连 LLM API |
| A5 | 前端不做业务逻辑;不持有设定写入权 |
| A6 | 内核实体(Imagination/AuthorIntent/TasteModel/FeedbackNote)是编排的一等输入,非可选附件 |

## § 2 · 设计目标与百万字挑战

### 2.1 非功能指标

| 编号 | 目标 | 优先级 | 验收条件 |
|------|------|--------|---------|
| G-01 | 百万字长篇角色/设定/时间线不崩坏 | P0 | MVP 连续跑通 5 万字;完整版目标 100 万字 |
| G-02 | 章生成 P95 ≤ 120s(2000–4000 字) | P0 | 含检索/生成/审校全链路 |
| G-03 | 协作回路闭合:人的每次意见可回流为 PreferenceSignal | P0 | FeedbackNote → TasteModel 更新端到端演示 |
| G-04 | 人在环暂停点:关键决策处 OptionSet 必须等人选择 | P0 | OptionSet.chosen_option_id = null 时任务暂停 |
| G-05 | AI 产出可解释:每段生成可展开引用的内核输入与设定 | P1 | 前端可查看 ContextBundle 来源 |
| G-06 | 数据不丢失:Snapshot 永不物理删除,可任意回滚 | P0 | Snapshot 软删除 + parent_id 链覆盖测试 |
| G-07 | 成本可控:百万字 LLM 累计成本有上界估算与监控 | P1 | cost_meter 仪表盘,MVP 后阶段上线 |

### 2.2 百万字五大架构挑战

| 挑战 | 根因 | 架构响应 |
|------|------|---------|
| **上下文放不下** | 100 万字 ≈ 150–200 万 token,超所有模型窗口 | 无状态服务 + 按需检索;assembleContext 是核心接口,非上下文传递【已核实 arXiv 2505.12572】 |
| **一致性熵增** | 角色/设定/时间线随章积累,任意生成可能与前文冲突 | 独立一致性引擎异步校验;ConsistencyFlag 持久化;人工裁决回流【已核实 arXiv 2603.05890 / 2503.23512】 |
| **主题漂移** | 长程生成逐渐偏离 AuthorIntent | AuthorIntent 强制注入每次生成;分层合并摘要重锚主线【已核实 arXiv 2508.03137】 |
| **检索质量** | 朴素向量检索丢失实体演变(角色先得后失某能力) | MVP 带时间戳关系表;完整版升级 E²RAG 实体-事件双图【已核实 arXiv 2506.05939】 |
| **成本积累** | 百万字 × (检索+生成+审校) token 量是真实约束 | 多模型路由(写作→旗舰,规划/审校→快模型);prompt 前缀缓存;增量校验 |

### 3.2 各层职责边界

#### TIER 0 · 前端层

| 职责 | 说明 |
|------|------|
| 想象输入面板 | 随时捕获作者想象碎片 → POST `/imaginations`;Imagination.type 枚举见 §4 |
| OptionSet 选择面板 | 显示 AI 给出的 2–4 个方案;人选择后 PATCH OptionSet.chosen_option_id;**这是人在环暂停点** |
| 意见提交框 | FeedbackNote.nl_critique 自然语言提交;低摩擦;驱动 AI 重写 |
| 大纲树导航 | Work/Volume/Chapter 树形增删改序 |
| 正文编辑器 | Tiptap 富文本;diff/批注/版本切换 |
| AI 面板 | 触发生成;SSE 进度;context 引用展示 |
| 设定/一致性/伏笔侧栏 | 查看 ConsistencyFlag;裁决(确认/驳回);伏笔状态 |

**不负责**:业务逻辑;直接调用 LLM;持有设定写入权。

#### TIER 1 · 编排层

```
职责划分:
  api_gateway    ← 认证/鉴权;请求校验;任务提交;SSE 管理
  orchestrator   ← 协作回路主控:调度 Agent 序列;管理人在环暂停;驱动反思循环
  task_worker    ← Celery Worker;消费 generate_chapter 任务
  sse_manager    ← Redis pub/sub → SSE 推送进度事件

Agent 序列(标准章生成路径):
  ImaginationAgent → 结构化本章相关 Imagination → 注入大纲规划
  OutlineAgent     → 生成/确认章大纲 + 若关键节点产出 OptionSet(人在环暂停)
  WritingAgent     → AI 主笔:按 AuthorIntent + TasteModel + ContextBundle 写正文
  ReviewAgent      → 审校 OOC/钩子/风格;驱动反思重写循环(最多 MAX_REFLECT_ROUNDS=3)

不负责:算法细节(交 TIER 2);LLM 调用细节(交 TIER 3)
```

### 3.4 同步/异步边界

#### 同步(REST 请求-响应,时延 < 500ms)

```
Work/Volume/Chapter CRUD(元数据)
Character/SettingItem 查看与编辑
ConsistencyFlag 裁决(确认/驳回)
Snapshot 查看与切换
FeedbackNote 提交(接收即返回,解析异步)
OptionSet 查看与选择(PATCH chosen_option_id)
Imagination 捕获(接收即返回,结构化异步)
QualityReport 查看(已完成时)
```

#### 异步(任务队列,时延不可控)

```
generate_chapter          核心异步任务;P50≈60s P95≈120s P99≈180s
generate_volume_outline   卷大纲生成
recheck_consistency       一致性全量重校验
rebuild_memory_summary    记忆重摘要
batch_evaluate            批量评估
export_epub_docx          导出任务
imagination_structurize   Imagination 结构化(提交后异步)
feedback_parse            FeedbackNote 解析(提交后异步)
taste_model_update        TasteModel 增量更新(章定稿后异步)
```

#### 异步任务接口模式

```python
# 提交
POST /api/tasks/generate-chapter
Body: { chapter_id: UUID, opts: GenerateChapterOpts }
Response 202: { task_id: UUID, status: "queued" }

# SSE 订阅(主路径)
GET /api/tasks/{task_id}/stream
→ event: progress  data: { stage: str, pct: int }
→ event: paused    data: { reason: "option_set_pending", option_set_id: UUID }  ← 人在环暂停
→ event: complete  data: { chapter_id, snapshot_id, word_count }
→ event: error     data: { code, message }

# 轮询(兜底)
GET /api/tasks/{task_id}
Response: { task_id, status, stage, progress_pct, result, error }
```

```
       └────────────────────────────┘  │                          │
              │                        │                          │
              │ 人选择(PATCH chosen)    │                          │
              │ → 任务恢复 RUNNING      │                          │
              ▼                        ▼                          │
    ┌─────────────────────────────────────────────────────────────┐
    │  RUNNING (续)                                               │
    │                                                             │
    │  S3: CONTEXT_ASSEMBLE                                       │
    │    retrieval_service.assembleContext(chapter_id)            │
    │    → ContextBundle (含内核实体 + 设定 + 记忆 + 伏笔)          │
    │    SSE: { stage: "context_assemble", pct: 30 }              │
    │                   │                                         │
    │                   ▼                                         │
    │  S4: WRITING (AI 主笔)                                      │
    │    WritingAgent.generate(                                   │
    │      outline, context_bundle,                               │
    │      author_intent, taste_constraints,  ← 内核一等输入       │
    │      imagination_snippets                                   │
    │    ) → draft_text                                           │
    │    SSE: { stage: "writing", pct: 60 } (流式推进)             │
    │                   │                                         │
    │                   ▼                                         │
    │  S5: REVIEW_AND_CHECK (asyncio.gather 并行)                 │
    │    a) ReviewAgent.review(draft_text) → review_result        │
    │    b) consistency_engine.check() → ConsistencyFlag[]        │
    │    c) foreshadow_service.scanForeshadow() → Foreshadow[]    │
    │    SSE: { stage: "review", pct: 78 }                        │
    │                   │                                         │
    │          review pass?     review fail                       │
    │               │                │                            │
    │               │      reflect_count < MAX_REFLECT_ROUNDS(3)? │
    │               │           │ Yes           │ No              │
    │               │    WritingAgent.rewrite()  │ 带标注继续       │
    │               │    → 回 S5 入口            │                 │
    │               ▼                            ▼                │
    │  S6: PERSIST_AND_UPDATE                                     │
    │    a) version_service.createSnapshot(chapter_id, text)      │
    │    b) story_bible_service.validate(chapter_id)              │
    │    c) [异步子任务] ExtractAgent.extract()                    │
    │    d) [异步子任务] SummaryAgent.updateMemory()               │
    │    e) [异步子任务] TasteUpdateAgent.emitSignal()  ← 回流品味 │
    │    f) [异步子任务] evaluation_service.evaluate()             │
    │    g) Chapter.status = "reviewing"                          │
    │    SSE: { stage: "done", pct: 100 }                         │
    └─────────────────────────────────────────────────────────────┘

终态:
  COMPLETED  → Chapter.status="reviewing",等人审阅
  PAUSED     → OptionSet 待选,任务挂起等恢复   ← 人在环暂停
  FAILED     → 保留 error_code/detail;draft 保留 Redis TTL=24h
  CANCELLED  → 清理中间态,不产生 Snapshot
  RETRYING   → 可重试错误(LLM 超时等),最多 MAX_RETRY=3

状态转换:
  QUEUED    → RUNNING   (Worker 拾取)
  RUNNING   → PAUSED    (OptionSet 产出,等人选择)
  PAUSED    → RUNNING   (人选择 → PATCH chosen_option_id)
  RUNNING   → COMPLETED (全阶段成功)
  RUNNING   → RETRYING  (可重试错误)
  RUNNING   → FAILED    (不可重试 或 超过重试次数)
  RUNNING   → CANCELLED (用户取消信号)
  RETRYING  → RUNNING   (重试开始)
  RETRYING  → FAILED    (重试耗尽)
  COMPLETED/FAILED/CANCELLED/PAUSED(超时) 为终态
```

**失败回退摘要**:

| 场景 | 响应 |
|------|------|
| LLM 超时 | TIER3 指数退避;3次全败 → FAILED;ContextBundle 保 Redis TTL=1h 支持重试 |
| 一致性引擎异常 | 降级:本章校验标 pending;主任务继续;后台异步重试 |
| DB 写入失败(S6) | 回滚 Snapshot;draft 保 Redis TTL=24h;前端展示手动重试入口 |
| ReviewAgent 持续 fail | 超 MAX_REFLECT_ROUNDS → 带 issue 标注继续;人工审阅可见问题列表 |
| Worker 崩溃 | Celery acks_late=True;未 ack 任务自动重投;最多 MAX_RETRY=3 |
| OptionSet 超时未选 | PAUSED 状态保留;人选择后恢复;不自动超时取消 |

### 3.8 技术栈定型与取舍

| 层 | 选型 | 核心理由 | 不选什么(为什么) |
|---|------|---------|----------------|
| **前端框架** | React + TypeScript + Vite | 生态成熟;类型安全;Vite HMR 快 | Next.js — Scribe 是 SPA 工具,不需 SSR |
| **富文本编辑器** | Tiptap (ProseMirror) | 支持协同(Yjs)、自定义节点、批注、diff | Slate.js — 插件生态弱;Quill — 扩展性不足;Draft.js — Meta 停维;不自建 — 性价比极低 |
| **后端框架** | Python 3.12 + FastAPI | LLM/向量生态第一公民;Pydantic v2;原生 async | Node.js — AI SDK 摩擦大;Django — async 不如 FastAPI;Go — 与 AI 生态隔离 |
| **数据库** | PostgreSQL 16 + pgvector | JSONB 半结构;事务完整;向量同库无双写问题 | 见下方独立讨论 |
| **任务队列** | Celery + Redis | 最成熟 Python 异步队列;重试/优先级/链式任务;Redis 复用 | FastAPI BackgroundTasks — 不跨进程不持久;Kafka — 复杂度远超需要 |
| **LLM 接入** | 多 Provider 抽象 + 模型路由 | 不锁定单一 Provider;成本控制关键 | 直调 SDK — 无法统一计量/降级/路由 |

**MVP 不上独立向量库(Qdrant/Weaviate/Pinecone)**【设计决策】:
- pgvector 与业务数据同事务边界,无双写一致性问题
- HNSW 索引对单作品百万级向量的 kNN 延迟在毫秒级,足够
- 多一个服务 = 多一套认证/备份/运维
- 迁移触发条件:pgvector kNN P95 > 200ms 且调优无效

**MVP 不上 Neo4j**【设计决策】:
- EntityRelation + TimelineEvent 关系表可实现 E²RAG MVP
- 多跳图查询在 MVP 阶段不是性能瓶颈
- 迁移触发条件:图查询 P95 > 500ms 且 JOIN 优化无效

**MVP 不上微服务**【设计决策】:
- TIER 2 服务作同进程 Python 模块,import 调用
- 接口契约已定义;拆独立进程只需换 HTTP 客户端
- 迁移触发条件:单服务 CPU 持续 > 80% 或任务积压 > 10

## § 7 · 失败模式与缓解

### 长程崩坏类

| 失败 | 根因 | 缓解 |
|------|------|------|
| **意图漂移** | AuthorIntent 未注入 → AI 拖回均值 | AuthorIntent 强制每次生成;intent_service.toPromptFragment() 在 S1 必须执行,不可跳过 |
| **品味遗忘** | TasteModel 未更新或未注入 | TasteUpdateAgent 异步更新;taste_service.toWritingConstraints() 在 S1 必须执行 |
| **主题漂移** | MemoryEntry 增量积累偏差 | 卷级分层合并摘要重锚主线;AuthorIntent 全程锚定【已核实 arXiv 2508.03137】 |
| **设定遗忘** | token 预算裁剪关键设定 | 核心设定标 pinned=true;assembleContext() 优先保留 |
| **角色 OOC** | CharState 未更新 | ExtractAgent 每章定稿后同步更新 CharState;ReviewAgent 专项检测 |
| **伏笔堆积** | planted 过多,top-K 覆盖不到 | planted 超 30 章未触发 → 提升 retrieval 权重;"即将超时"优先级 |

### 系统可靠性类

| 失败 | 缓解 |
|------|------|
| Worker 崩溃 | Celery acks_late=True;visibility_timeout 重投;MAX_RETRY=3 |
| LLM 限流/超时 | 指数退避重试;provider_fallback 自动降级 |
| DB 写入失败 | S6 原子事务;draft 保 Redis TTL=24h;前端重试入口 |
| pgvector 超时 | HNSW 索引初始化;kNN 超时上限 200ms;降级关键词检索 |
| SSE 断开 | Redis 存 task progress;前端重连后 GET /tasks/{id} 恢复 |
| OptionSet 孤悬 | 任务 PAUSED 状态持久化;人操作后恢复;不自动超时取消 |

### 数据一致性类

| 失败 | 缓解 |
|------|------|
| Segment 向量与文本不同步 | 同一 PG 事务:text + embedding 一起写 |
| ConsistencyFlag 与章版本错配 | Flag 带 snapshot_id 引用;人审时可见"基于哪个版本" |
| MemoryEntry 基于过期文本 | updated_at 时间戳显示在摘要前;人可感知新鲜度 |
| TasteModel 未反映最新反馈 | PreferenceSignal 带 created_at;TasteModel.version 自增;可追溯 |

## § 8 · MVP vs 完整版

### MVP(0–3 个月):闭合协作回路,跑通 5 万字

```
架构形态:
  + 单机 Docker Compose
  + TIER 2 同进程 Python 模块
  + 任务队列:FastAPI BackgroundTasks 起步;并发>1 切 Celery+Redis
  + pgvector 同库存储
  + 关系表实现 EntityRelation/TimelineEvent(无 Neo4j)

⭐ 内核服务 MVP 必须实现(协作回路核心):
  + imagination_service:capture / getForChapter / 基础结构化
  + intent_service:get / update / toPromptFragment
  + taste_service:getModel / applySignal(基础版) / toWritingConstraints
  + feedback_service:submit / 基础 parse / emitSignal

Agent MVP:
  + ImaginationAgent(简化版:直接注入捕获片段)
  + OutlineAgent(生成大纲;关键节点产出 OptionSet)
  + WritingAgent(AI 主笔;注入内核实体;无反思循环)
  + 无 ReviewAgent、无 SummaryAgent

一致性:基础版(角色 OOC + 明显设定冲突)
伏笔:手动录入,无自动扫描
评估:人工审阅

MVP 验收:
  - 协作回路闭合:Imagination 输入 → AI 注入生成 → FeedbackNote → TasteModel 更新
  - OptionSet 人在环暂停正常工作
  - 端到端:大纲→章生成→Snapshot 保存→编辑器可查
  - 章生成 P95 ≤ 120s
  - 连续 10 章无明显角色 OOC
```

### 增强版(3–6 个月):十万字,对抗中长程崩坏

```
新增:
  + ReviewAgent + 反思/重写循环(最多 3 轮)
  + SummaryAgent + MemoryEntry 增量更新
  + ExtractAgent + 实体/事件自动抽取
  + TasteUpdateAgent 完整版(从意见/选择/diff 全面学习)
  + 一致性引擎 v2:19 类 checklist(门槛1)
  + 伏笔服务:F-T-P 三元组 + scanForeshadow()
  + pgvector kNN:assembleContext() 改为语义检索
  + Celery 任务队列(若 MVP 用 BackgroundTasks 则切换)
  + 评估服务 v1:钩子覆盖率 + 伏笔回收率
  + cost_meter 成本计量
```

### 完整版(6–12 个月):冲击百万字

```
新增:
  + E²RAG 实体-事件双图(检索服务升级)
  + 混合记忆:全局分层合并 + 近期增量
  + 多模型路由完整版(写作旗舰 / 规划快模型)
  + StyleExemplar 深度整合(文风范本驱动生成)
  + 若 pgvector 瓶颈:迁 Qdrant
  + 若图查询瓶颈:引入 Neo4j
  + Kubernetes 水平扩展
  + 可观测性完整方案(工程7)
```

## 技术基线修订(2026-06,经核实,详见 [工程8 核实更新](工程8-HermesAgent复用方案.md))

进一步复用、减少自建,**MVP 技术基线调整**:

- **存储**:MVP = **单个 SQLite + sqlite-vec**(关系数据 + 向量同库),优先复用 Hermes `qmd` 技能做混合检索;**不起 PostgreSQL/pgvector**。规模化(向量 >~50万 / 多租户并发 / 单文件瓶颈)再迁 pgvector,[实现4](实现4-记忆与检索.md) 检索接口契约不变。前文出现的"PostgreSQL+pgvector"为**规模化目标态**,非 MVP。
- **运行底座**:编排/工具/记忆/Cron/子Agent/沙箱 = 复用 **Hermes Agent**(对齐 工程8),非自建。
- **Chat UI**:复用现成(Hermes Desktop / Open WebUI / LobeChat 插件);自建仅限小说专用面板(对齐 [工程2](工程2-交互与编辑器.md))。
- **不变**:无状态服务、检索压缩而非塞上下文、人在环异步、内核服务一等地位。
