## §1 在协作回路中的位置与职责

### 1.1 回路视角:这个模块做什么

```
        ┌──────── 人(作者) ────────┐
        │  ① 想象 / AuthorIntent    │
        │  ③ 意见 / FeedbackNote     │
        └───────┬──────────▲────────┘
                │           │ OptionSet(选项) + Segment(成稿)
                ▼           │
   ┌─────── 写作生成 ← ─ 你在这里 ────┐
   │  消费内核1/2/3 + 实现1/4 的全部上游结果  │
   │  AI 写下全部正文文字                    │
   │  关键段产出 OptionSet(2-4方案)          │
   │  接 FeedbackNote.parsed_directive 重做  │
   └────────────────────────────────────────┘
                │
                ▼
      Segment[] → 实现3 编排 / 实现4 索引 / 门槛1 校验
```

**一句话**:写作生成是回路中唯一产出正文字符的环节。它消费内核(想象/品味/反平庸)、规划(大纲/beat)、记忆(ContextBundle),把这些喂给 LLM,AI 写下全部正文;关键处产出多方案交作者选;作者的意见通过 FeedbackNote 驱动定向重写。

|---|---|---|

### 2.2 百万字挑战

**(a) 上下文爆炸** — 100 万字 ≈ 150-200 万 token,远超任何模型窗口。本模块依赖实现4 检索压缩而非"塞全文"策略。【已核实 arXiv 2505.12572、2506.16445】

**(b) AuthorIntent 漂移** — 长程生成会逐渐偏离北极星(reader_feeling / core_emotional_arc)。每次生成必须将 AuthorIntent 锚定在 [SYSTEM] 区不可裁剪位置。【已核实 arXiv 2508.03137】

**(c) 品味模型冷启动** — 早期章节 TasteModel 样本少,预测力弱。MVP 阶段允许全局 TasteModel 降级替代;后期以 work-level 为主。【设计决策】

**(d) Imagination 消耗与调度** — 作者积累的 Imagination 碎片需要在合适章节精准注入,不能全部倾倒。依赖内核1 的调度标记(scheduled_for)。【设计决策】

**(e) 风格/声音漂移** — AI 长程生成文风自然飘移。VoiceProfile + StyleExemplar 每章注入是缓解手段。【稳定知识】

**(f) 内容去冗** — 百万字连载同类描写易重复。每章注入"已交代/已使用意象禁止列表"(实现4 提供)。【设计决策】

**(g) 节奏疲劳** — 长程钩子密度塌陷。beat_targets + 自反思中的钩子强检是护栏。【稳定知识】

**(h) OptionSet 生成成本** — 关键场景产出 3-4 方案会放大 token 消耗 3-4x。需要策略性识别"关键处"而非每段都给选项。【设计决策】

## §3 详细设计

### 3.1 模块内部架构

```
WritingEngine
├── IntentLoader              # 加载 AuthorIntent + 相关 Imagination + TasteModel
│   ├── AuthorIntentFetcher   # 读 AuthorIntent(北极星)
│   ├── ImaginationMatcher    # 检索与本章相关的 Imagination(embedding 匹配)
│   └── TasteModelFetcher     # 读 TasteModel(work-level 优先,fallback 全局)
├── WritingContextBuilder     # Token 预算管理 + 上下文三区组装
│   ├── SystemZoneBuilder     # [SYSTEM]:北极星/品味/反平庸/角色声音/文风
│   ├── ContextZoneBuilder    # [CONTEXT]:设定/记忆/伏笔/时间线/前章正文/素材/Imagination
│   └── InstructionZoneBuilder# [INSTRUCTION]:beat/钩子/爽点/去冗/字数/输出格式
├── WritingAgent              # 核心生成
│   ├── DraftGenerator        # 初稿生成(LLM 调用)
│   ├── OptionSetGenerator    # 多方案生成(关键处触发)
│   ├── WritingReflector      # 内部自反思(借鉴 StoryWriter【已核实 2506.16445】)
│   └── DraftReviser          # 按反思/FeedbackNote 定向修订
├── FeedbackProcessor         # 处理 FeedbackNote → 定向重写
│   ├── DirectiveParser       # 解析 parsed_directive(已由内核1 完成)
│   ├── TargetLocator         # 定位重写靶区(segment/paragraph/scene)
│   └── DirectedRewriter      # 定向重写(不从头生成)
├── SegmentSplitter           # 正文 → Segment[] 切割
├── SegmentIndexer            # 向量化 + 通知实现4 建索引
├── WritingQA                 # 轻量自查(交实现3 编排前)
└── ActionDispatcher          # 人机协同动作集
    ├── ContinueAction        # 续写
    ├── RewriteAction         # 改写
    ├── ExpandAction          # 扩写
    ├── CondenseAction        # 缩写
    ├── SwitchPOVAction       # 换视角
    └── ToneShiftAction       # 调语气
```

### 3.2 主生成流程伪代码

```python
# WritingEngine.generate_chapter(chapter_id, options) → GenerationResult

def generate_chapter(chapter_id: UUID, options: GenerationOptions) -> GenerationResult:

    chapter = db.get(Chapter, chapter_id)
    work    = db.get(Work, chapter.work_id)

    # ── Step 1: 加载内核层输入 ─────────────────────────────────────
    # 内核1: 北极星 + 相关想象
    author_intent: AuthorIntent = IntentLoader.fetch_author_intent(work.id)
    # author_intent 字段:
    #   .reader_feeling       要让读者感受什么 ← 注入 [SYSTEM]
    #   .core_emotional_arc   核心情感弧线
    #   .why_write            写作动机
    #   .central_promise      核心承诺
    #   .do_not_betray        红线(jsonb)← 生成时不可违背

    imaginations: List[Imagination] = IntentLoader.match_imaginations(
        chapter_id  = chapter_id,
        chapter_seq = chapter.seq,
        top_k       = 5,          # 取相关性 top-5 碎片
    )
    # 检索策略:embedding 近似 + scheduled_for 精确匹配 + status in (captured/structured/scheduled)
    # 匹配后将相关碎片的 structured(jsonb) 注入 [CONTEXT]

    # 内核2: 品味模型
    taste_model: TasteModel = IntentLoader.fetch_taste_model(
        owner_id = work.owner_id,
        work_id  = work.id,      # work-level 优先,无则 fallback 全局
    )
    # taste_model 字段:
    #   .positive_exemplars  正面样本 ← 注入 [SYSTEM] 作 few-shot
    #   .negative_list       AI腔黑名单 ← 注入 [SYSTEM] 作 negative constraint
    #   .learned_preferences 学习到的偏好 ← 影响 [INSTRUCTION] 细节规则

    # 内核3: 反平庸约束(由内核3 文档定义的静态+动态规则集)
    anti_mediocrity_rules: AntiMediocrityRuleSet = AntiMediocrityEngine.get_rules(
        work_id     = work.id,
        chapter_seq = chapter.seq,
    )
    # 包含:反 AI 腔规则/意外性要求/克制原则/具体性要求/禁用模式列表
    # 这些规则在 [SYSTEM] 直接硬编码约束,而非事后检查

    # ── Step 2: 组装 ContextBundle(实现4 检索服务) ────────────────
    bundle: ContextBundle = retrieval_service.assemble_context(
        chapter_id   = chapter_id,
        draft_outline = chapter.outline,
        token_budget  = options.context_token_budget,  # 默认 16K
    )
    # bundle 包含(详见实现4):
    #   .setting_items       相关设定项(相关性 top-K)
    #   .rolling_summary     三层摘要(global/volume/recent)
    #   .foreshadows         本章应处理的伏笔
    #   .timeline_events     相关事件
    #   .recent_segments     前 1-2 章末尾 Segment(连续性)
    #   .voice_profiles      本章出场角色 VoiceProfile
    #   .known_info_list     近 5 章已充分交代信息(去冗)
    #   .overused_imagery    近 5 章高频意象(去冗)
    #   .materials           相关素材片段(原料层)

    # ── Step 3: 决策:标准章 vs 关键章(OptionSet 触发判断) ────────
    is_key_decision_point: bool = is_key_chapter(chapter, work)
    # 关键章定义:卷高潮章 / beat_target 包含 character_decision / 情节岔路点
    # 关键章 → 触发 OptionSetGenerator(多方案)
    # 标准章 → 走单路径 DraftGenerator

    # ── Step 4: 构建 Prompt(三区) ─────────────────────────────────
    prompt: WritingPrompt = WritingContextBuilder.build(
        work               = work,
        chapter            = chapter,
        bundle             = bundle,
        author_intent      = author_intent,
        imaginations       = imaginations,
        taste_model        = taste_model,
        anti_mediocrity_rules = anti_mediocrity_rules,
        is_key_chapter     = is_key_decision_point,
    )
    # token 合规检查(详见 §3.4)
    prompt = WritingContextBuilder.enforce_budget(prompt, options)

    # ── Step 5a: 标准章 → 初稿生成 ───────────────────────────────
    if not is_key_decision_point:
        draft: str = DraftGenerator.generate(
            prompt      = prompt,
            max_tokens  = options.target_output_tokens,
            temperature = options.temperature,
        )
        option_set = None

    # ── Step 5b: 关键章 → 多方案生成 ─────────────────────────────
    else:
        option_set: OptionSet = OptionSetGenerator.generate(
            prompt       = prompt,
            num_options  = options.num_options,     # 默认 3
            chapter      = chapter,
            work         = work,
        )
        # option_set.options: 2-4 个方案,每个含:
        #   .id           方案 ID
        #   .text         完整正文草稿
        #   .approach     一句话叙事策略说明
        #   .strengths    优势
        #   .tradeoffs    代价/风险
        #   .divergence   与其他方案的核心差异
        # 将 option_set 返回给内核1 → 展示给作者选择(暂停等待选择)
        # 作者选择后:draft = option_set.options[chosen].text
        # 此处流程:若 options.auto_select=True(调试用),取第1个;否则挂起等待
        if options.auto_select:
            draft = option_set.options[0].text
        else:
            # 保存 OptionSet,通知编排引擎等待作者决策
            db.save(option_set)
            orchestrator.pause_for_decision(chapter_id, option_set.id)
            return GenerationResult(option_set=option_set, pending=True)

    # ── Step 6: 内部自反思 ────────────────────────────────────────
    # 借鉴 StoryWriter 动态压缩历史+生成后反思【已核实 arXiv 2506.16445】
    # 借鉴 reader simulator 反馈视角【已核实 arXiv 2508.03137】
    reflection: ReflectionReport = WritingReflector.reflect(
        draft          = draft,
        chapter        = chapter,
        bundle         = bundle,
        author_intent  = author_intent,
        taste_model    = taste_model,
        anti_mediocrity_rules = anti_mediocrity_rules,
    )

    # ── Step 7: 按反思修订(最多 MAX_INTERNAL_REVISIONS 轮) ────────
    MAX_REVISIONS = options.max_internal_revisions   # 默认 2
    revision_count = 0
    while not reflection.pass_threshold and revision_count < MAX_REVISIONS:
        draft = DraftReviser.revise_by_reflection(
            draft      = draft,
            reflection = reflection,
            prompt     = prompt,
        )
        reflection = WritingReflector.reflect(
            draft=draft, chapter=chapter, bundle=bundle,
            author_intent=author_intent, taste_model=taste_model,
            anti_mediocrity_rules=anti_mediocrity_rules,
        )
        revision_count += 1
    # 超出轮数未通过 → metadata 标注 reflection_incomplete=True,交实现3 决策

    # ── Step 8: 切割 Segment + 建索引 ───────────────────────────
    segments: List[Segment] = SegmentSplitter.split(chapter_id, draft, "ai")
    SegmentIndexer.index(segments)    # 向量化 + 写库 + 通知实现4

    # ── Step 9: 更新 Imagination 状态 ───────────────────────────
    for img in imaginations:
        if img.status != "used":
            db.update(Imagination, img.id, {"status": "used"})

    # ── Step 10: 更新 PreferenceSignal(被动学习) ────────────────
    # 若有 option_set 且作者选了方案,记录 PreferenceSignal
    if option_set and option_set.chosen_option_id:
        preference_service.record_option_choice(
            work_id    = work.id,
            option_set = option_set,
        )
        # → 实现到内核2 TasteModel 更新回路

    # ── Step 11: 轻量写作自查 ────────────────────────────────────
    qa: WritingQAResult = WritingQA.check(segments, chapter, bundle, reflection)
    db.update(Chapter, chapter_id, {
        "status":       "reviewing",
        "word_count":   qa.word_count,
        "hook_text":    extract_hook_text(segments[-1]),
        "hook_strength": reflection.hook_strength,
    })

    return GenerationResult(
        segments          = segments,
        qa_result         = qa,
        reflection_report = reflection,
        option_set        = option_set,
        metadata = {
            "token_usage":           prompt.token_count,
            "latency_ms":            ...,
            "revision_count":        revision_count,
            "reflection_incomplete": not reflection.pass_threshold,
            "imaginations_consumed": [img.id for img in imaginations],
        }
    )
```

### 3.3 意见→重做流程(FeedbackProcessor)

这是协作回路的主交互路径:作者提意见 → AI 定向重写(不从头生成),产出新 Snapshot。

```python
# FeedbackProcessor.process(feedback_note_id) → Snapshot

def process_feedback(feedback_note_id: UUID) -> Snapshot:

    note: FeedbackNote = db.get(FeedbackNote, feedback_note_id)
    # note.nl_critique       作者的自然语言批评(已存)
    # note.parsed_directive  由内核1 解析的结构化指令(已存)
    # note.target_type       segment / chapter / option / setting / outline
    # note.target_id         指向具体实体

    directive = note.parsed_directive
    # directive 结构(由内核1 FeedbackParser 负责,本模块直接消费):
    # {
    #   "operation":    "rewrite_segment" | "rewrite_scene" | "adjust_tone"
    #                   | "strengthen_emotion" | "fix_ooc" | "cut_verbosity"
    #                   | "deepen_character" | "restructure_beats" | "add_tension",
    #   "scope":        "paragraph" | "segment" | "scene" | "chapter_section",
    #   "target_ids":   [uuid, ...],  # 具体 Segment id 列表
    #   "constraints":  ["保留情节事实", "不改变人物决定", ...],
    #   "emphasis":     ["更克制", "更具体", "强化悬念", ...],
    #   "anti_patterns": ["不要升华", "避免排比", ...],  # 追加黑名单
    # }

    # 定位靶区
    target_segments: List[Segment] = TargetLocator.locate(
        target_type = note.target_type,
        target_id   = note.target_id,
        directive   = directive,
    )

    # 加载写作上下文(与原始生成共享策略,但裁剪更激进保节省 token)
    chapter   = db.get(Chapter, target_segments[0].chapter_id)
    work      = db.get(Work, chapter.work_id)
    author_intent = IntentLoader.fetch_author_intent(work.id)
    taste_model   = IntentLoader.fetch_taste_model(work.owner_id, work.id)
    bundle = retrieval_service.assemble_context(
        chapter_id   = chapter.id,
        draft_outline = chapter.outline,
        token_budget  = FEEDBACK_CONTEXT_BUDGET,  # 比正常生成更小
    )

    # 构建定向重写 Prompt
    rewrite_prompt: str = DirectedRewritePromptBuilder.build(
        target_segments    = target_segments,
        directive          = directive,
        author_intent      = author_intent,
        taste_model        = taste_model,
        chapter            = chapter,
        bundle             = bundle,
        original_nl_critique = note.nl_critique,
    )

    # 执行定向重写(不是从头生成,保留靶区前后文锚定)
    new_text: str = DraftReviser.directed_rewrite(
        prompt      = rewrite_prompt,
        max_tokens  = estimate_output_tokens(target_segments),
        temperature = 0.80,
    )

    # 切割新 Segment + 更新索引
    new_segments = SegmentSplitter.split(chapter.id, new_text, "ai")
    SegmentIndexer.reindex(old_segment_ids=[s.id for s in target_segments],
                           new_segments=new_segments)

    # 产出新 Snapshot(版本树节点)
    old_snapshot = db.get_latest_snapshot(chapter.id)
    new_snapshot = Snapshot(
        chapter_id  = chapter.id,
        content     = assemble_chapter_text(chapter.id, new_segments),
        created_by  = "ai",
        parent_id   = old_snapshot.id if old_snapshot else None,
        branch_label = f"feedback_{note.id[:8]}",
    )
    db.save(new_snapshot)

    # 回写 FeedbackNote
    db.update(FeedbackNote, note.id, {"resulted_snapshot_id": new_snapshot.id})

    # 回流 PreferenceSignal(意见本身是一条偏好信号)
    preference_service.record_feedback(
        work_id  = work.id,
        note     = note,
        snapshot = new_snapshot,
    )

    return new_snapshot
```

### 3.4 WritingContextBuilder — Token 预算管理

#### 3.4.1 预算分区设计

```
总预算(MODEL_CONTEXT_LIMIT,如 128K token)
─────────────────────────────────────────────────────────────────────
[SYSTEM 区 — 固定,不可裁剪]
├─ AUTHOR_INTENT_BUDGET:       800  token  北极星(reader_feeling/arc/promise/红线)
```

#### 3.4.2 动态裁剪优先级

当 CONTEXT 区组装超出模式预算时,按以下优先级裁剪:

```
不可裁剪(绝对保留):
  1. AUTHOR_INTENT      ← 北极星是一切生成的灵魂,丢失即违反 L2
  2. TASTE_EXEMPLAR     ← 品味 few-shot 注入,丢失即品味失联
  3. ANTI_MEDIOCRITY    ← 反平庸规则,丢失即回退平庸
  4. FORESHADOW         ← 百万字长程一致性,丢失无法回收
  5. OUTLINE+INSTRUCTION← 无大纲即无方向

可按相关性裁剪(低分先裁):
  6. IMAGINATIONS       裁前保留 status=scheduled 的,其余按 embedding 相关性
  7. MATERIALS          按 relevance_score 倒序裁
  8. SETTING            按 relevance_score 倒序,仅保留 top-K
  9. TIMELINE           保留最近 10 条事件
  10. MEMORY_RECENT     近 3 章摘要缩短为 1 章
  11. MEMORY_VOLUME     缩至 200 token 摘要
  12. RECENT_SEGMENTS   从前章末尾倒序截断
  13. MEMORY_GLOBAL     最后才压缩,因为是北极星漂移的后备锚
```

```python
def build(work, chapter, bundle, author_intent, imaginations,
          taste_model, anti_mediocrity_rules, is_key_chapter) -> WritingPrompt:

    # 固定区:先占空间
    system_zone = SystemZoneBuilder.build(
        work, author_intent, taste_model, anti_mediocrity_rules,
        bundle.voice_profiles
    )
    instr_zone = InstructionZoneBuilder.build(
        chapter, bundle, is_key_chapter
    )
    fixed_tokens = count_tokens(system_zone) + count_tokens(instr_zone) + OUTPUT_RESERVE + BUFFER

    remaining = MODEL_CONTEXT_LIMIT - fixed_tokens

    # 可裁剪区:贪心填充
    context_parts = [
        ("imaginations",     format_imaginations,   imaginations),
        ("materials",        format_materials,       bundle.materials),
        ("global_memory",    format_global_memory,   bundle.rolling_summary.global_summary),
        ("volume_memory",    format_volume_memory,   bundle.rolling_summary.volume_summary),
        ("recent_memory",    format_recent_memory,   bundle.rolling_summary.recent_chapters),
        ("setting",          format_settings,        bundle.setting_items),
        ("timeline",         format_timeline,        bundle.timeline_events),
        ("foreshadow",       format_foreshadows,     bundle.foreshadows),     # 不可裁但放这里计算
        ("recent_segments",  format_recent_segments, bundle.recent_segments),
    ]

    context_zone_parts = {}
    for key, formatter, items in context_parts:
        rendered  = formatter(items)
        n_tokens  = count_tokens(rendered)
        if n_tokens <= remaining:
            context_zone_parts[key] = rendered
            remaining -= n_tokens
        else:
            trimmed = trim_by_relevance(items, max_tokens=remaining)
            context_zone_parts[key] = formatter(trimmed)
            remaining = 0  # 耗尽后续跳过

    context_zone = ContextZoneBuilder.assemble(context_zone_parts)
    return WritingPrompt(
        system      = system_zone,
        context     = context_zone,
        instruction = instr_zone,
        token_count = count_tokens(system_zone) + count_tokens(context_zone) + count_tokens(instr_zone),
    )
```

### 5.2 OptionSetGenerator 详细设计

```python
def generate(prompt: WritingPrompt, num_options: int,
             chapter: Chapter, work: Work) -> OptionSet:

    # 构建多方案生成专用 Prompt
    # [SYSTEM][CONTEXT] 区复用 prompt,在 [INSTRUCTION] 末尾追加多方案指令
    multi_option_instruction = f"""
═══════════════════════════════════════════════════════
【多方案生成指令】
═══════════════════════════════════════════════════════
本章是关键决策节点。请产出 {num_options} 个**差异化**的写法方案。

每个方案必须是完整章节草稿(不是摘要),并在草稿前附一段"方案说明":
  - approach:    本方案的核心叙事策略(一句话)
  - strengths:   这个写法的优势(对读者体验的具体贡献)
  - tradeoffs:   这个写法的代价/风险(什么被牺牲了)
  - divergence:  与其他方案的核心差异在哪里

差异化要求——{num_options} 个方案之间必须在以下维度有实质差异:
  · 叙事策略(正面交锋 vs 迂回 vs 留白)
  · 情绪基调(紧绷 vs 克制 vs 爆发 vs 反讽)
  · 信息揭示节奏(提前揭示 vs 延迟揭示 vs 误导)
  · 聚焦对象(主角视角 vs 对手视角 vs 旁观者)
  · 场景选择(室内密闭 vs 开放场景 vs 动态场景)

禁止:方案之间只改改词汇/句式而核心叙事策略相同——那不是差异化。

输出格式(严格遵守):
---OPTION_1_START---
[方案说明]
approach: <一句话>
strengths: <优势>
tradeoffs: <代价>
divergence: <与其他方案的核心差异>
[正文]
<完整章节正文>
---OPTION_1_END---

---OPTION_2_START---
...
---OPTION_2_END---
"""

    raw_output: str = llm.complete(
        agent_role  = "WritingAgent_OptionSet",
        prompt      = WritingPrompt(
            system      = prompt.system,
            context     = prompt.context,
            instruction = prompt.instruction + multi_option_instruction,
        ),
        max_tokens  = options.target_output_tokens * num_options,
        temperature = 0.92,   # 多方案需要更高多样性
    )

    # 解析多方案输出
    parsed_options = parse_option_blocks(raw_output)

    option_set = OptionSet(
        id              = uuid7(),
        work_id         = work.id,
        decision_point  = {
            "chapter_id":  str(chapter.id),
            "chapter_seq": chapter.seq,
            "trigger":     compute_trigger_reason(chapter, work),
        },
        options         = [
            {
                "id":         str(uuid7()),
                "text":       opt.text,
                "approach":   opt.approach,
                "strengths":  opt.strengths,
                "tradeoffs":  opt.tradeoffs,
                "divergence": opt.divergence,
            }
            for opt in parsed_options
        ],
        chosen_option_id  = None,
        choose_rationale  = None,
    )
    db.save(option_set)
    return option_set
```

## §7 内部自反思(WritingReflector)

### 7.3 自反思通过门槛

```python
def compute_pass(r: ReflectionReport) -> bool:
    # 强制失败(任一满足即 fail)
    if r.intent_alignment.red_line_violated:
        return False                     # 违背红线
    if not r.hook.present:
        return False                     # 无章尾钩子
    uncovered_beats = sum(1 for v in r.beat_coverage.values() if not v)
    if uncovered_beats > 1:
        return False                     # 超过1个 beat 未覆盖
    if r.intent_drift_risk > 0.65:
        return False                     # 北极星偏离严重
    if len(r.ooc_flags) > 2:
        return False                     # OOC 过多
    if len(r.ai_style_flags) > 3:
        return False                     # AI 腔过重(黑名单命中 > 3 处)

    # 综合评分
    score = (
        r.intent_alignment.intent_score * 0.30
        + r.hook.strength               * 0.20
        + (1 - r.intent_drift_risk)     * 0.20
        + r.specificity_score           * 0.15
        + r.surprise_score              * 0.15
    )
    return score >= 0.60
```

## §8 动作集(ActionDispatcher)

### 8.1 动作总览

| 动作 | 标识符 | 触发场景 | 输入粒度 | 输出 |
|---|---|---|---|---|
| 续写 | `continue` | 正文结尾需延伸 | 末段 + 方向指令 | 新 Segment[] |
| 改写 | `rewrite` | 段落不满意 | 选中 Segment[] + 改写要求 | 替换后 Segment[] + Snapshot |
| 扩写 | `expand` | 情节点需深化 | 选中 Segment[] + 扩写方向 | 扩展后 Segment[] + Snapshot |
| 缩写 | `condense` | 段落冗长 | 选中 Segment[] + 目标字数 | 压缩后 Segment[] + Snapshot |
| 换视角 | `switch_pov` | 换主 POV 角色 | 选中 Segment[] + 目标角色 | 新视角 Segment[] + Snapshot |
| 调语气 | `tone_shift` | 情感基调需调整 | 选中 Segment[] + 目标语气 | 调整后 Segment[] + Snapshot |

每个动作执行后:
1. 产生新 Snapshot(parent_id 指向上一个)

3. 记录 PreferenceSignal(revision_diff 类型)→ 内核2 TasteModel 更新

| `Chapter`(更新) | `status="reviewing"`, `word_count`, `hook_text`, `hook_strength` | 写作完成后更新 |
| `PreferenceSignal` | `source`, `signal(jsonb)`, `polarity` | 每次选择/重做自动记录 |
| `Imagination`(更新) | `status="used"` | 消耗掉的想象碎片 |

## §11 失败模式与缓解

### FW-01: 北极星漂移(AuthorIntent Drift)

**表现**:生成内容逐渐偏离 `reader_feeling` / `core_emotional_arc`。

**根因**:长程生成中 AuthorIntent 信息在上下文中被稀释;模型对"整体意图"的持久记忆有限。

**缓解**:
- [SYSTEM] 区 AUTHOR_INTENT_BUDGET 不可裁剪,每章必须注入
- WritingReflector 中 `intent_drift_risk > 0.65` 强制修订
- 每 10 章由实现3 编排发起"北极星对齐评估"(调用工程6 度量)

### FW-02: 品味失联(TasteModel 未生效)

**表现**:生成内容命中 TasteModel.negative_list 黑名单;positive_exemplars 风格未被学习。

**根因**:TasteModel 样本量少(冷启动);黑名单条目描述过于抽象。

**缓解**:
- 冷启动期使用内核3 内置反平庸规则作兜底(与 TasteModel 叠加)
- WritingReflector 的 `ai_style_flags` 命中数 > 3 即触发修订
- 黑名单条目要求具体(带引用例子,不只是抽象标签)

### FW-03: OptionSet 差异化不足

**表现**:生成的 2-4 个方案之间只有词汇/句式差异,叙事策略实质相同。

**根因**:LLM 在高约束下趋中,难以自主维持大差异。

**缓解**:
- OptionSet 生成温度更高(0.92 vs 正常 0.88)
- [INSTRUCTION] 区明确要求在"叙事策略/情绪基调/信息揭示节奏/聚焦对象/场景选择"五维度有差异
- WritingReflector 对 OptionSet 各方案单独评分,若差异度 < 阈值则重生成 1 次【设计决策】

### FW-04: 意见重做漂移(Directed Rewrite 改多了)

**表现**:定向重写改动了靶区之外的内容,破坏了上下文连续性。

**根因**:LLM 自由度过高,重写时扩展了范围。

**缓解**:
- Prompt 明确约束"不更改靶区外任何内容"
- 重写后自动计算 diff,靶区外变更超过 5% 则触发报警,提示作者确认

### FW-05: Imagination 注入过载

**表现**:注入了太多 Imagination 碎片,导致正文方向性混乱或 token 超支。

**根因**:top-k 取得过大;多条 Imagination 之间方向矛盾。

**缓解**:
- IMAGINATIONS_BUDGET 上限控制(1500 token)
- 优先 `status=scheduled` 且 `scheduled_for` 精确匹配本章的碎片
- 内核1 在排期时负责冲突检测,不把互相矛盾的碎片同时调度到同一章

### FW-06: 角色 OOC(Out of Character)

**表现**:角色言行与 VoiceProfile 严重不符;跨章后性格遗失。

**根因**:VoiceProfile 在长 prompt 中被模型忽略;置于过靠前的位置。

**缓解**:
- VoiceProfile 注入在 [SYSTEM] 区末段(紧邻生成任务)
- WritingReflector 专项 OOC 检测 + 内部修订
- 门槛1 做跨章 OOC 深度校验

### FW-07: 章尾钩子缺失

**表现**:章节以平静收尾,无追读驱动力。

**根因**:模型训练偏向"完结感"收尾;指令注入强度不足。

**缓解**:
- [INSTRUCTION] 区钩子要求独立区块强调
- WritingReflector `hook.present=false` 触发内部修订
- WritingQA `qa_pass=false` + `force_hook=True` 时触发 `force_append_hook`

### FW-08: Token 超预算

**表现**:ContextBundle + [SYSTEM] + [INSTRUCTION] 合计超出模型窗口。

**根因**:设定内容异常冗长;VoiceProfile 角色数量过多;Imagination 碎片过多。

**缓解**:
- `WritingContextBuilder.enforce_budget` 动态裁剪(§3.4.2)
- 单 SettingItem 内容摘要字段上限 500 token
- 出场角色 ≥ 4 人时,非核心角色用 VoiceProfile 精简版(≈80 token/角色)

### FW-09: 百万字内容去冗失效

**表现**:同类描写、同类信息在多章中重复出现。

**根因**:每章上下文独立,无全局去重意识。

**缓解**:
- [INSTRUCTION] 区注入实现4 提供的"近 5 章已交代信息禁止列表"和"高频意象禁止列表"
- WritingReflector 的 `repetition_flags` 触发修订
- 实现4 维护"已充分交代信息"列表并随章节滚动更新

## §12 MVP vs 完整版

### 12.1 MVP(目标:跑通单章写作闭环,5-10 万字不崩)

**本模块 MVP 范围**:
- ✅ 完整 §3.2 生成流程 Steps 1-11
- ✅ AuthorIntent + TasteModel 基础注入([SYSTEM] 区简化版)
- ✅ Imagination 基础检索注入(embedding top-3,无调度精确匹配)
- ✅ 内核3 内置反平庸规则注入(TasteModel 冷启动兜底)
- ✅ 基础 Prompt 三区([SYSTEM]/[CONTEXT]/[INSTRUCTION])
- ✅ 简化 VoiceProfile 注入(仅 speech_patterns + ooc_red_flags)
- ✅ 初稿生成 + 1 轮简化自反思(仅检查 hook_present + OOC flag + beat_coverage)
- ✅ SegmentSplitter + SegmentIndexer(批量向量化 + pgvector)
- ✅ 基础 WritingQA(字数 + 钩子)
- ✅ FeedbackProcessor 基础版(4 种 operation:rewrite_segment/adjust_tone/cut_verbosity/fix_ooc)
- ✅ 人机协同动作:Continue + Rewrite(其余 4 个推后)
- ✅ OptionSet 生成基础版(2 个方案,章级触发,无差异度校验)

**MVP 排除**:
- ❌ OptionSet 段落级触发
- ❌ OptionSet 差异度自动校验 + 重生成
- ❌ DraftReviser 内部修订(MVP 直接传 reflection 给实现3)
- ❌ SwitchPOVAction / ToneShiftAction / ExpandAction / CondenseAction
- ❌ Imagination 调度精确匹配(scheduled_for)
- ❌ 动态 token 预算贪心裁剪(MVP 用固定截断)
- ❌ 钩子类型细分检测(MVP 只检测"有无明显悬念")
- ❌ 流式生成输出(MVP 同步等待全文)
- ❌ PreferenceSignal 自动记录(MVP 手动触发)

### 12.2 增强版

新增:
- 完整 WritingReflector(全部检查维度) + DraftReviser(最多 2 轮内部修订)
- 完整 TasteModel 注入(positive_exemplars few-shot + 完整 negative_list)
- Imagination 调度精确匹配 + 状态更新
- OptionSet 差异度校验 + 重生成
- Expand / Condense / ToneShift 动作
- 动态 token 预算裁剪(贪心填充)
- PreferenceSignal 自动记录
- `force_append_hook` 强制钩子修复

### 12.3 完整版

新增:
- SwitchPOVAction(多视角叙事支持)
- 流式生成 → 前端实时展示(工程2)
- 多模型路由:DraftGenerator 用旗舰模型,WritingReflector 用中档快模型(工程3)
- OptionSet 段落级触发(作者在编辑器中选段触发)
- Prompt caching 支持(工程3)
- 风格连续性监测:每 10 章计算 Segment embedding 分布偏移(工程6)
- FeedbackNote 全部 operation 类型支持(12 种)
- VoiceProfile 版本感知切换(角色弧光转变前后使用不同版本)

## §14 开放问题

### OQ-W-01: OptionSet 最优触发策略

**问题**:当前用 `is_key_chapter` 布尔值触发 OptionSet。实际上"关键度"是连续值,低关键度章节是否也应该偶发给 2 个方案?触发频率与作者疲劳/参与感的平衡点在哪?

**待验证**:在真实使用中统计作者对 OptionSet 的选择参与率和跳过率,校准触发阈值。

### OQ-W-02: TasteModel 冷启动的过渡策略

**问题**:新作品的前 1-5 章 TasteModel 几乎为空(无 positive_exemplars,negative_list 仅有内置规则)。内核3 内置规则作兜底够不够?是否需要在作品创建时引导作者快速输入 2-3 个品味样本?

**待设计**:与内核2 协商"品味激活"流程。

### OQ-W-03: 自反思循环的边际收益

**问题**:第 2 轮修订相对第 1 轮是否有显著质量提升?边际 token 成本与质量提升的比值。

**待验证**:对同批章节做 0/1/2 轮修订盲测对比(人评 + WritingQA 自动分),确定是否默认开启 2 轮。

### OQ-W-04: VoiceProfile 版本感知

**问题**:角色发生重大弧光转变后(CharState.change_type=personality),WritingEngine 应注入哪个版本的 VoiceProfile?旧版?新版?混合?转变章节的窗口如何处理?

**待协商**:与门槛2 协商 CharState→VoiceProfile 版本切换的接口。

### OQ-W-05: 流式生成与自反思的 UX 冲突

**问题**:完整版目标是将初稿流式输出给前端,但若自反思要求修订,前端已显示的内容需要回收。"diff 覆盖"还是"版本切换"范式哪个体验更好?

**待协商**:与工程2(交互)、实现3(编排)协商"流式初稿 + 异步修订通知"的 UX 方案。

### OQ-W-06: 定向重写的靶区精度

**问题**:FeedbackNote.target_ids 是 Segment 粒度。若作者指的是跨两个 Segment 的某个"场景片段",当前设计如何处理?是否需要引入"场景"粒度的 target_type?

**待设计**:与内核1 协商 FeedbackNote.target_type = "scene" 的定义与 Segment 范围的推断逻辑。

### OQ-W-07: Imagination 消耗与未消耗的处理

**问题**:某些 Imagination 碎片被检索并注入了 Prompt,但由于 token 裁剪或 AI 处理,正文中并未体现。此时 status 是否应该改为 used?还是保持 scheduled 等待下次?

**待设计**:与内核1 协商 Imagination 消耗确认机制(是否需要人工确认"这条想象已被体现"?)。

### OQ-W-08: 百万字后段的去冗精度

**问题**:"近 5 章已交代信息禁止列表"无法覆盖"50 章前埋下、此刻需要重申以唤醒读者记忆"的信息。如何区分"不该重复的啰嗦"与"需要有意重申的长程记忆刷新"?

**待设计**:与实现4 协商"可重申信息标记"机制(距上次出现 > N 章且与本章相关则允许简短重提)。
