## Q1 Hermes 0.17.0 → 上游增量 —— 查到,证据充分

**基线**:`hermes --version` → v0.17.0 (2026.6.19) · upstream 9259d1e5;安装方式 git checkout + 专属 venv(`~/.hermes/hermes-agent`,更新=git pull);上游 https://github.com/NousResearch/hermes-agent 。
**变更面**:`hermes update --check` 实测 **2150 commits behind origin/main**(记忆中的 267/504 已严重过时);期间上游发布 **v0.18.0(2026-07-01)**。以下结论来自 HEAD vs origin/main 的只读 git diff/grep(比 release notes 可靠):

- **①elicitation 批量待批:未查到**。elicit 相关 131 处命中两版逐行同位;2150 条 commit message 零命中。唯一 approval 面变化:`approval_session_key = run_id`(per-run 审批隔离,安全收紧,非批量确认)。
- **②更细粒度事件钩子:查到,新增 2 个**——`pre_verify`(改码收尾前可续推,配 max_verify_nudges)与 `subagent_start`(观测用)。均面向 coding,对写作工序价值边际。
- **③script-injection 新注入点:未查到**。cron.py(--script 定义处)零 diff;main 反而在 hosted console 禁用 cron --script。

**五个 breaking 关注面(HERMES_UPGRADE_EVAL.md 清单)逐项:全部无变化**——/v1/responses tools 协议(端点+请求指纹键一致)、config 键(compression/skills.external_dirs/approvals.mode/API_SERVER_PORT 均未改名)、ctx.elicit 签名、cron --script 语义。
**会咬人的行为变化 3 项**:非流式 stale 检测默认 300s→90s(scribe3 hermes_complete 非流式 timeout 600s,升级须验);restart_drain_timeout 60→0(gateway restart 立即打断在途 agent,写长章期间重启有风险);moa toolset 移除(实查 scribe3 profile 无 moa 引用,无影响)。
**对 scribe3 直接受益项(实锤)**:后台 subagent fan-out;/goal 完成契约;/learn 工序转 skill;`fix(agent): repair empty-name tool_calls sanitizer to prevent Responses 400`(正是 :8643 Responses+MCP 链路);compressor/MCP reload/EventBridge 一批稳定性修复;cron 凭证外传封堵。

## Q2 DEFINE EVENT 物化聚合 —— 查到:非稳定路径,官方自己劝退

官方 Real-time best practices 明说聚合场景该用 `DEFINE TABLE … AS SELECT` 视图而非 EVENT。EVENT 坑史:#4470(同事务联动失效)、#7310(UNIQUE 索引改变 EVENT 内 UPDATE 结果,2026-05 仍新鲜)、#5801(事件内错误静默)、#6413(3.0.0-alpha 破坏 INFO);聚合视图自身也有 #2825(median/stddev 增量更新报错)、#4371。本仓一手经验同向:migration 017 两个 ASYNC EVENT 已是 write-only 幽灵记录(P2-15)。
**落点**:书级 scorecard(任务7)沿用 062 模式(应用层计算+独立缓存表+LIVE 推表名),不迁 DB 侧。

## Q3 LIVE SELECT 断线重连/背压 —— 查到

- 重连:JS SDK managed live queries 自动重启,unmanaged 不会;**断线期间变更不重放**(无 resume token;官方无 replay 承诺——重连后全量重取是通行做法)。
- 背压:#5068(慢消费者拖死全进程 LIVE)→ PR #5383 官方答案=每 WS 100 条缓冲/通知通道 15000/**投递失败直接丢弃**。即尽力而为可丢通知,慢面板会静默漏事件,必须重取兜底。LIVE 仅单节点、排序 best-effort。
- 多面板多表开销:未查到系统性 benchmark(如实标注)。**scribe3 现行架构已是社区稳态**(后端单点订阅、SSE 只推表名、前端重取);扩面板时保持"后端单点订阅、前端多路复用",勿让每面板各开 LIVE。

## Q4 多类向量 HNSW 隔离 —— 部分查到,判据够用:**分表分索引**

- SurrealDB HNSW 本就 per-table per-field,DIMENSION/DIST 定死在索引上;
- **无 pre-filtered HNSW**:`WHERE kind=… AND <|K|>` 是 ANN 后过滤,召回不足是通病(Supabase/pgvector 文档+filtered-ANN 综述 arXiv:2509.07789);SurrealDB 的 KNN×WHERE 组合还有故障史(#6949 远程连接 KNN 返回全表、#6995 OR/NOT 组合报错已修)——能不组合就不组合;
- 本仓已是分表先例:proposition.embedding(003)/chapter.embedding(016)各表各索引。
**落点(任务8)**:lesson 独立表+专属 HNSW 索引,与 semantic_recall 同构;蓝图"查不到就影子库 A/B"的备选**可以省**——判据已足。
- 顺带只读发现:store.py:763 注释称 HNSW 但操作符写 `<|K,COSINE|>`(距离名形式),按文档索引路由形式是 `<|K,EF|>`,传距离名可能走 brute force——lesson 放量前用 EXPLAIN 验一次(记入遗留风险)。

## Q5 delta 草单工序:skill/script-injection vs prompt 内嵌 —— 本地实证:**prompt 内嵌胜出**

- 机制匹配:草单是"对话回合内必发生"工序;cron --script 是定时触发对不上;skill 在 :8643 路径是模型自选加载,必走工序交模型自觉=纪律必失守(POV 漂移教训同构);instructions 内嵌是唯一确定性生效通道。
- 单一真相源+可测:app.py 一处追加,pytest 可断言;SKILL.md 无测试护栏且与 skill_manage 自补丁并存会双真相源漂移。
- 同链维护:任务6 的 deltas 注入 brief 本就在 app.py 组装链。
折衷:SKILL.md 同步一小节工序摘要,注明"权威在 app.py"。

## 升级裁决(Hermes 升级协议第 2 步)——最终:本 goal 内不升级,维持 0.17.0(台账 D-014)

**调研员初判**为"可升非急升(判据勉强达标)";**最终裁决收紧为不升级**,理由按协议判据字面:
1. 协议判据是"存在**本方案任务**直接受益的特性"——北极星 13 任务所需的底座能力(elicitation 待批/HNSW 向量/LIVE SELECT/cron/script-injection/Responses tools 协议)在 0.17.0→main 增量中**零变化**(A.3 三问命中仅"新钩子"半项且面向 coding 场景);升级对本 goal 零加速。subagent fan-out//goal 契约//learn 是通用平台收益,不属判据内"直接受益"。
2. 运维风险不对称:hermes-agent 是单一 git checkout+共享 venv,8643 网关是生产写作活服务;无人值守窗口内做 2150 commits 升级+依赖重装,回滚半径大于收益。
3. 择机升级的完整迁移清单已备(下节),留给作者选窗执行;届时任一回归回滚 v0.17.0 tag。
