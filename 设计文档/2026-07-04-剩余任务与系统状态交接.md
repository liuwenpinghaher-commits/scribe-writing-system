## 四、DB 事件记录与恢复方法（重要）

**事件**（2026-07-04）：:8001 SurrealDB 进程约 12:54 掉线（残留 LOCK 记录旧 PID=79281），导致 :3321 除 /health 外端点全 500。**非代码问题、非数据污染**，纯 DB 进程掉线。数据完好持久化，零丢失。已重启恢复。

**若 :8001 再掉线，恢复命令**：
```bash
# 1. 确认无残留进程占用 + 删残留 LOCK（LOCK 内容是旧 PID，进程已死才删）
lsof ~/.scribe2-surreal/data.db/LOCK   # 无输出=可删
rm -f ~/.scribe2-surreal/data.db/LOCK
# 2. 重启 :8001（指向 scribe3 真实生产库）
nohup ~/.surrealdb/surreal start --no-banner --bind 127.0.0.1:8001 \
  --user root --pass root "surrealkv:~/.scribe2-surreal/data.db" \
  > /tmp/scribe3_surreal_8001.log 2>&1 &
# 3. 重启 :3321（store.py 无自动重连，必须重启重连新 :8001）
cd "<repo-root>"
kill $(lsof -ti TCP:3321) 2>/dev/null
nohup scribe3/.venv/bin/python -m scribe3.app > /tmp/scribe3_app_3321.log 2>&1 &
# 4. 验证
curl -s http://127.0.0.1:3321/works | python3 -m json.tool   # 应返 4 本书
```

**红线提醒**：`~/.scribe2-surreal/data.db` 是 scribe3 生产书稿（含纸命等），**绝不可删**。目录名的 "scribe2" 是历史遗留，勿被误导。真机实验用临时 work，用后删；改真 prose 先 checkpoint。
