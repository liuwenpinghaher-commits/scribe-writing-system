## 0. 问题陈述（作者真实处境）

### 0.1 作者现在看到什么

```text
设定库侧栏
  └─ 待确认设定  [595]
       · 高门          第8章 · faction · faction
       · 原本是替高门   第8章 · faction · faction
       · [✓] [×]
```

| 缺失 | 后果 |
|------|------|
| **无详情** | 不知道 before/after、证据句、与现有 Codex 是否冲突 |
| **无分类** | 人物/规则/势力/噪声混成一条河，无法按类型审 |
| **无置信度/来源** | 标记可信 vs 启发式乱切 一视同仁 |
| **无正文跳转** | 不能点到第 N 章看上下文 |
| **无编辑后批** | 只能全有/全无，不能改名合并再批 |
| **无批量策略** | 595 条只能一条条点；「全部忽略」太危险且无预览 |
| **入口弱** | 嵌在设定目录树里，无独立工作台、无旅程设定债入口 |

**结论：** 后端「反填到候选」已发生；**审阅 UX 未完成**，作者无法完成「确认」。

### 0.2 成功定义（改进后作者能做什么）

```text
作者打开「设定收件箱」
  → 按 类型 / 章 / 风险 / 来源 看清队列
  → 点开一条，看到：主张 · 证据 · 现状对比 · 影响章 · 建议动作
  → 可 批准 / 拒绝 / 合并到已有 / 改写后批准 / 批量按规则处理
  → 批准后 Codex 立即可见；设定债下降
  → 噪声（过召回 faction）可一键降噪，不污染正典
```

## 1. 北极星与铁律

### 1.1 北极星

**待确认设定是「正典变更的审批台」，不是侧栏提示条。**  
每一条决策必须 **可理解、可对照正文、可撤销审计、可按类型批处理**。

### 1.2 铁律（继承 v6.2）

| # | 铁律 |
|---|------|
| F1 | L1 正典 **禁止** 静默写；仅 `approved_item_ids` / 收件箱显式批准 |
| F2 | 批准前必须展示 **可理解 diff**（before → after 或「新建」） |
| F3 | 全类型同一收件箱；分类是视图，不是多套队列 |
| F4 | 启发式过召回 **默认降权**，不得与标记/LLM 高置信同权展示 |
| F5 | 批量操作须二次确认；高风险（world_rule / intent）禁止无预览全批 |
| F6 | 旅程可见 **设定债**；收件箱与债数字同源 |

## 3. 审阅详情卡（解决「没有详情」）

每一条候选打开后，详情卡 **必须** 包含下列区块（缺数据则显式「—」而非藏字段）。

### 3.1 详情字段规格

| 区块 | 字段 | 说明 |
|------|------|------|
| **主张摘要** | module · op · layer · risk · confidence | 人话标题，如「新建势力 · 高门」/「角色·恐惧 变更」 |
| **对象** | target · field | oid/裸名；字段中文名映射（fear→恐惧） |
| **变更对比** | before · after | 并排 Diff；新建时 before=「（无）」 |
| **证据** | evidence · seq · source · extractor | 引文 + 章号；source 徽章：定稿/讨论/ingest/标记/启发式/LLM |
| **影响** | impact.chapters · inject_surfaces | 「将影响第 3、5 章 brief」；空则写「尚无章索引命中」 |
| **冲突/消歧** | conflict · disambiguation | 与已有 Codex 同名建议合并；红线冲突高亮 |
| **预览写后** | 只读 Codex 预览 | 批准后大致长什么样（patch 字段预览） |
| **操作** | 批准 · 拒绝 · 合并到… · 编辑后批准 · 打开正文 | 见 §5 |

### 3.2 人话标题模板

```text
{op中文} · {module中文}「{显示名}」
  op: add→新建  patch→修改  plant→埋设  …
  module: character→角色  world_rule→世界规则  faction→势力  …
例：修改 · 角色「沈拾灯」· 恐惧
    新建 · 势力「高门代还」
    埋设 · 伏笔「合灯夜烧掉伪契…」
```

### 3.3 正文证据预览

- 有 `seq`：拉 `GET /chapter?seq=`，在正文中 **高亮 evidence 子串**（找不到则展示附近 200 字 + 警告「证据句未在正文定位」）
- 无 `seq`（讨论）：展示讨论原文片段（若 pack 带 text 引用）
- 按钮 **「跳到第 N 章写作台」**（深链 work+seq）

## 4. 分类与筛选（解决「没有分类」）

### 4.1 主维度：类型 Tab（必做）

```text
全部 | 角色 | 势力 | 物件 | 术语 | 规则 | 关系 | 伏笔 | 母题 | 事实/知识 | 其他
```

- 角标 = 该 module pending 数（与 `GET /canon/debt` by_module 同源）
- 「全部」默认；记忆上次 Tab（localStorage per work）

### 4.2 次维度：工具条筛选（必做）

| 筛选项 | 取值 |
|--------|------|
| 来源 | 定稿 prose_finalize / 讨论 discussion / ingest / 全部 |
| 抽取器 | 标记 marker / LLM / 启发式 heuristic / hybrid |
| 风险 | high / med / low |
| 置信度 | ≥0.8 / 0.5–0.8 / <0.5（启发式默认可标 <0.5） |
| 章 | 全部 / 第 N 章 / 无章（讨论） |
| 状态 | pending（默认）/ 最近已批 / 最近已拒（审计用，只读） |
| 质量 | **建议优先**（高置信或标记）/ **疑似噪声**（启发式 faction 短名等） |

### 4.3 分组视图（推荐）

在列表模式切换：

| 视图 | 分组键 |
|------|--------|
| 按类型 | module |
| 按章 | seq |
| 按变更包 | change_pack_id（同一次定稿/讨论） |
| 按目标对象 | target（同一角色多字段合在一组） |

**同一 target 多字段** 应可「展开组 → 逐字段批」或「整组批准」。

### 4.4 噪声桶（必做 · 针对 595 条现状）

启发式过召回（如 `原本是替高门`、`是会`）不得与真设定同列抢注意力：

```text
默认列表 = 建议优先（confidence≥阈值 OR extractor∈{marker,llm} OR risk=high 真变更）
次级折叠 = 疑似噪声（heuristic 且 module=faction 且 名称过短/像短语）
一键：「忽略本页全部噪声」→ status=rejected，reason=noise_heuristic
```

服务端规则见 §7.2。

## 5. 决策动作模型（如何「确认」）

### 5.1 单条动作

| 动作 | 行为 | 闸 |
|------|------|-----|
| **批准** | apply_item → Surreal；status=approved | L1 必有人点 |
| **拒绝** | status=rejected；不写库 | — |
| **编辑后批准** | 弹表单改 target/field/after → 再 apply | 校验 codex_schema |
| **合并到已有** | 选 Codex 已有实体 → op=patch 到该 id | 消歧 |
| **拆分/改 module** | 纠错：误判 faction→term 等 | 服务端改写后批 |
| **打开正文** | 跳章 | 只读 |
| **稍后** | 保持 pending；可打标签 `needs_second_look` | — |

### 5.2 批量动作

| 动作 | 约束 |
|------|------|
| 批准当前筛选结果 | 仅 `建议优先`；high+world_rule/intent **排除**，须单条 |
| 拒绝当前筛选结果 | 二次确认数字 |
| 忽略全部噪声桶 | 仅 noise 标记；可撤销（5 分钟内 undo 列表） |
| 按包批准 | 选 change_pack_id，展示包摘要后批 |

### 5.3 决策后反馈

- Toast：`已写入角色「沈拾灯」·恐惧`  
- 可选：Codex 目录闪一下该条目  
- 债数字即时 −1  
- 失败：展示 apply error（字段校验/Surreal），条目标红，不偷偷消失

## 7. 后端与数据（支撑详情/分类）

### 7.1 API 增强

| 端点 | 增强 |
|------|------|
| `GET /canon/candidates` | 已有 status/module/seq；**补**：`source` `extractor` `risk` `min_confidence` `noise_only` `pack_id` `limit` `cursor`；返回 `facets`（各 module 计数） |
| `GET /canon/candidates/{id}` | **新增** 单条详情：完整 before/after/impact + 可选 `chapter_excerpt` |
| `POST /canon/candidates/{id}/decide` | 已有 approve/reject；**补**：`edit` 体（改 after/target/module 后批）；`merge_into` |
| `POST /canon/candidates/batch-decide` | **新增** `{ ids[], decision, reason? }` 事务或 best-effort+报告 |
| `GET /canon/debt` | 已有；**补**：`by_source` `noise_count` `suggested_priority_count` |
| `POST /canon/candidates/mark-noise-rules` | 可选：按规则批量标 noise 再拒 |

### 7.2 噪声识别（服务端权威）

```text
noise_heuristic 当且仅当：
  extractor ∈ {heuristic, hybrid} 且 非 marker
  且 module=faction 且 (
       名称长度 < 2
    OR 名称匹配 短语垃圾：/^(是|会|的|了|在)/ 
    OR 名称含「替高门」「原本是」等连接残片
    OR confidence < 0.45
  )
标记/LLM 结果默认 never auto-noise。
```

写入字段：`risk` 可保留；另加 `flags: ["noise_heuristic"]`（migration 107 或 SCHEMALESS 旁路 json）。

### 7.3 详情 enrichment

`GET /canon/candidates/{id}` 服务端组装：

```json
{
  "item": { "...candidate row..." },
  "labels": { "module": "势力", "op": "新建", "field": null },
  "diff": { "before": null, "after": { "name": "高门代还" }, "kind": "add" },
  "codex_match": { "exists": false, "similar": [{"id":"…","name":"高门代还","score":0.9}] },
  "chapter_excerpt": { "seq": 8, "snippet": "…", "highlight": [12, 20] },
  "impact": { "chapters": [8], "inject_surfaces": ["chapter_brief", "…"] }
}
```

### 7.4 抽取质量（源头减债 · 与 UI 并行）

| 项 | 动作 |
|----|------|
| 启发式 faction | 收紧正则；禁止从短语切势力；白名单「…门/帮」须 2–6 字且非语法残片 |
| 定稿默认 | `use_llm=true` 时以 LLM 为主、启发式为辅且标 confidence |
| 去重 | 同 module+target+field+after 哈希，24h 内不重复 pending |
| 已在 Codex | op=add 且已存在 → 自动改 patch 或合并建议，不堆重复 add |

**源头减债 + 收件箱降噪** 双管齐下；只做 UI 不够。

## 11. 现状对照与优先级理由

| 现状 | 本方案 |
|------|--------|
| 侧栏一行 target | 工作台 + 详情 Diff |
| 无分类 | 类型 Tab + 筛选 + 分组 |
| 595 条启发式洪泛 | 噪声桶 + 源头收紧 |
| 只有 ✓/✗ | 编辑/合并/批量/跳转正文 |
| 与旅程脱节 | 债入口 + 定稿弹层 |

**为何不「只加 tooltip」：** 不能解决分类与批量；作者仍无法在噪声中找到真变更。  
**为何不「自动全批」：** 违反 L1 铁律，且当前噪声会污染 Codex。
