# 伏笔 · 母题「本章视角」章感知设计

> 左栏「伏笔」「素材·母题」两面板从全书平铺升级为**按当前章锚定**:点开第 N 章,一眼看到"这章要收/要埋/仍悬着哪些伏笔""这章触及了哪些母题",与已是章内视角的 帧/演绎/校验 对齐。全书数据不丢,只是相关的浮上来、其余折叠。

**日期**:2026-07-02 · **分支**:feat/audit3-fixes(接续)· **范围**:前端 PromisesPanel/MotifsPanel + 后端母题实例抽取(ingest)

---

## 一、背景与问题

左栏 6 面板当前分两类作用域:帧/演绎/校验 是**章内**(随 seq 变),伏笔/素材/项目树 是**全书**(不随章过滤)。伏笔本质是时间性的——写到第 N 章时作者要的是"此刻还欠哪些账",全书平铺把最相关的埋没了,且与其它章内面板不一致。母题同理:作者想知道"这章触及了哪些母题",但后端母题表(`name/theme/echoes/unfolding`)**无章号联结**。

## 二、A · 伏笔「本章视角」(纯前端)

`PromisesPanel` 接收 `seq`,复用 `promisesLedger()` 已返回的每条 `setup_chapter / payoff_chapter / overdue / kind`,按当前章分桶。默认「本章视角」:

| 桶 | 判定 | 呈现 |
|---|---|---|
| **本章收** | `payoff_chapter === seq` | 置顶,ok 色 |
| **本章埋** | `setup_chapter === seq` | 置顶 |
| **截至本章仍悬** | `setup_chapter ≤ seq` 且未收(open)且(`payoff_chapter` 空 或 `> seq`) | `overdue` 者红字(text-danger)置该桶顶 |
| **障眼法** | `kind === 'red_herring'` | fore 色 Tag,上下文参考 |
| **已了结 / 与本章无关** | 其余(含 `setup_chapter > seq` 未来才埋的、已收非本章的) | 折叠(details 收起),可展开看全书 |

- 无「本章/全书」模式切换(避免隐藏状态);全书内容在「已了结/无关」桶里折叠可展开。
- 空桶不渲染标题。每条仍显 `埋 第N → 收 第M`,点击跳 setup 章(复用 T2-D 的 onJumpChapter)。
- **改动仅 `PromisesPanel` 展示层**;不动后端、不动 ledger 数据、不动 `LeftDock` 的 seq 传递(seq 已可得)。

## 三、B · 母题「本章触及」(ingest LLM 抽取)

### 3.1 数据模型
新表 `motif_instance`:
```
motif_instance: { motif_id: string, chapter: int, evidence: string, ingest_seq: int }
```
SCHEMAFULL,新增 migration `050_motif_instance.surql`(当前最新 049,下一序号)DEFINE 表与字段(镜像现有 SCHEMAFULL 表写法,`IF NOT EXISTS` 幂等)。

### 3.2 抽取(ingest)
- `build_knowledge_extract_prompt(prose, ...)` 增一段:把**本书已有母题名单**(`list_motifs()` 的 name)注入 prompt,要求 LLM 判断本章触及了其中哪些,每条产出 `{ "motif": "<母题名>", "evidence": "<本章一句引文>" }`,放进 delta 的 `motif` 数组。**只在已有母题里选,不发明新母题。**
- `apply_delta(store, delta, seq)` 增 `for it in delta.get("motif") or []` 循环:
  - `resolve` `it["motif"]`(名)→ 已有 `motif_id`(按 name 匹配 `list_motifs()`;匹配不到**跳过**,不自动建母题——与 `_resolve_char` 匹配不到跳过同范式)。
  - 写 `motif_instance(motif_id, chapter=seq, evidence=it.get("evidence",""), ingest_seq=seq)`。
- **章级幂等**:`apply_delta` 开头已 `purge_ingest(seq)`;`purge_ingest` 增删本章 `motif_instance`(`DELETE motif_instance WHERE ingest_seq=$seq`),重复 ingest 不残留。

### 3.3 端点
- `GET /motifs` **不变**(全书,MotifsPanel 折叠区仍用它)。
- 新增 `GET /motif-instances?chapter=N&work=..` → 返回本章触及:`[{ motif_id, name, evidence }]`(join motif 表取 name,便于前端直接显示)。单一职责,不改 `/motifs` 语义。
- `api.js` 增 `motifInstances(ch)`。

### 3.4 前端
`MotifsPanel` 接 `seq`,并行拉 `/motifs`(全书)+ `/motif-instances?chapter=seq`(本章):
- **本章触及**分组置顶:命中的母题高亮(带 `evidence` 引文,小字或 hover)。
- 其余全书母题折叠(details),与伏笔「已了结/无关」同构。
- 空(本章无触及)→ 「暂无触及——写/反哺本章后自动检测」(信息性空态,不崩)。

### 3.5 回填
motif_instance 只在 ingest 时写,故**只对已 ingest 的章生效**。已有章用 **T2-C 已加的「反哺设定库」入口** re-ingest 即填充。设计不做批量回填脚本(YAGNI);文档注明"老章反哺一次即有"。

## 四、错误与边界

- LLM 未抽到 motif / `parse_failed` → 本章 motif_instance 为空 → 前端降级空态「暂无触及,可反哺检测」,不崩。
- `resolve` 不到的母题名跳过(fail-safe,不建母题、不报错)。
- `motif_instance` 随 `purge_ingest(seq)` 幂等清除。
- 伏笔分桶对 `setup_chapter`/`payoff_chapter` 为 null 的条目安全归入「仍悬」或「无关」(空值不进"本章收/埋")。
- 前端 `/motif-instances` 拉取失败 → 只显全书折叠区 + 空的本章触及(区分空与失败,不静默当"无触及")。

## 五、测试

4. `/motif-instances` 端点返回 join 后的 name+evidence。

5. 伏笔面板 5 桶按当前章分层、超期红字置顶、跳章仍工作、折叠可展开。

## 六、验收标准

1. 点开第 N 章,伏笔面板顶部即为"本章收/本章埋/仍悬(超期红字)",全书其余折叠;母题面板顶部为"本章触及(带引文)"。
2. 反哺(ingest)一章后,该章母题触及被抽取落库、面板显示;重复反哺不产生重复实例。
3. 伏笔纯前端零后端改动;母题后端 pytest 绿、迁移幂等、resolve 兜底不崩。
4. 两面板与帧/演绎/校验 的「本章视角」一致;全书数据不丢(折叠可达)。
5. build 绿、真机零 console 报错。

## 七、实施顺序(交 writing-plans 细化)

1. 后端母题:migration(motif_instance)+ store 读写 + purge 幂等 → pytest。
2. 后端抽取:extract prompt 加母题段 + apply_delta 加 motif 循环 + resolve → pytest。
3. 后端端点:`/motif-instances` + api.js → pytest。
4. 前端母题:MotifsPanel 章感知(本章触及置顶+evidence+全书折叠)。
5. 前端伏笔:PromisesPanel 本章视角分桶(纯前端)。
6. 真机验收:两面板本章视角 + 反哺检测母题 + 零报错。
