# 写作台前端全量审查改造方案

> 5 路只读审查(中区五阶段 / 正文编辑器 / 左栏6面板 / 右栏主编存档 / 外壳设计系统)归纳。目标:信息显示的**统一性 · 完善性 · 完整性 · UI 展示完美性 · 交互最优**。分三批,每批真机验证。

**日期**:2026-07-02 · **分支**:feat/audit3-fixes · **范围**:scribe3/web/src 全量 + 少量后端端点(QC/ledger 补字段)

---

## 一、诊断(根因)

设计系统底子好(语义色 token 1200+ 一致引用、硬编码色≈0、正文区防丢稿/乐观更新扎实)。债集中在三处系统性问题:

1. **原语有却没被一致复用** → `ui.jsx` 的 SectionTitle/Empty/Skeleton/Btn 只有少数文件用:4 套标题、5 种空态、3 种 padding、148 个手搓 `<button>`、14 种任意字号(含 4 种半像素)。
2. **错误态/防丢稿兜底不齐** → 多处 `.catch(()=>{})` 静默吞错;5 个丢稿/覆盖点;全站仅 1 个根 ErrorBoundary。
3. **后端能力没全暴露** → 伏笔 ledger、QC 检测器、进度字数、ingest 反哺、草稿 proposal 落地动线都缺。

## 三、执行方式

- subagent-driven-development:逐任务派实现 subagent,前端 build + Playwright 真机验证,每批末做一次跨任务复核。
- 每批独立提交、真机零 console 报错为验收线;批间可停下等用户反馈。
- 不改后端行为除非补 QC/ledger 返回字段(T2.1/T2.2),那两处走 pytest。

## 四、验收标准

1. 防丢稿:草稿/正文任意阶段切章、保存失败均有反馈且不静默丢(批一)。
2. 崩溃隔离:图表视图强制抛错只坏单栏,书稿区不白屏(批一)。
3. 完整性:伏笔 overdue/障眼法、QC 全检测器、进度字数、演绎进度、草稿落地动线全部可见可用(批一+批二)。
4. 一致性:字号收敛到 token scale、按钮/空态/弹层/Toast 走统一原语,深色模式品牌色对比正确(批三)。
5. 每批 build 绿 + 真机零报错。
