# 编排 UiTarget 与讨论→落库闭环 · 最优方案

> **日期**：2026-08-05  
> **状态**：最优方案（取代「点状止血」作为下一阶段唯一目标架构）  
> **定位**：在 `2026-08-05-讨论驱动能力编排-全系统改进方案`（A–D 已部分落地）之上，补齐 **可寻址性、讨论产物、跟焦策略、全域同构** 四根支柱  
> **原则**：作者只聊/批/选；系统负责舞台与提案；**禁止**半截 node、禁止幽灵 leaf、禁止口头=落库  

---

## 0. 为何现有补丁不是最优

| 已做（止血） | 缺口（导致「还能再炸」） |
|--------------|--------------------------|
| 角色无专名 → `codex_category` | 势力/物件/术语/规则/母题/命题/伏笔仍可幽灵 selection |
| CodexDetail 拒 `/characters/null` | 防线在 UI 末端，契约层仍可发出坏 target |
| 规则抽名（沈砚/顾声） | 无会话实体表，讨论产物不持久、不可提案 |
| WriteProposal 卡已挂 | **讨论轮次不自动沉淀提案**；模型空转 completed 仍常见 |
| resolve + ui_events | 默认硬抢栏 3 selection，打断作者当前章/大纲 |

**最优不是「多写几个 if」**，而是：

1. **可寻址代数类型** 作为唯一 UI 目标契约  
2. **会话草稿实体（Session Draft）** 承接讨论产物  
3. **讨论→提案→批准→可寻址 leaf** 硬状态机  
4. **跟焦策略分层**（soft / hard / none）  
5. **Catalog 全域同构**（一种规则覆盖所有 CODEX_LEAF + 伏笔/母题）  

---

## 1. 一句话目标

> 任意能力域上：讨论只产生 **草稿与提案**；栏 3 只打开 **可寻址对象或合法入口**；批准后焦点落到 **真实 leaf**。  
> 不存在「角色「」/ faction / null」这类半截选中。

---

## 2. 核心模型

### 2.1 `UiTarget`（取代半截 `node: {type}`）

```ts
// 代数类型：四选一，禁止第五种「半 leaf」
type UiTarget =
  | { kind: "none" }
  | { kind: "stage"; entry: EntryKey; phase?: Phase; panel?: string; right_tab?: string }
  | { kind: "category"; entry: EntryKey; category: CodexCategory | "promise" | "motif" | ... }
  | { kind: "create"; entry: EntryKey; object_type: ObjectType; draft_id?: string; seed?: object }
  | { kind: "leaf"; entry: EntryKey; object_type: ObjectType; id: string; label: string; phase?: Phase }
```

**硬不变量（Invariants）**

| # | 不变量 | 违反后果 |
|---|--------|----------|
| I1 | `kind=leaf` 的 `id` 必须通过 **AddressabilityProbe**（存在或本会话 draft 可解析） | 禁止发 selection leaf |
| I2 | catalog 模板不得直接当 selection；只提供 **默认 stage/category** | 消灭 `{type:character}` 幽灵 |
| I3 | 前端 `DetailPane` / `CodexDetail` **拒绝** 非 leaf 的 CODEX_LEAF 请求 | 双保险，测试锁死 |
| I4 | 口头同意永不改变 Addressability | 仍须审批 |

**AddressabilityProbe**

```text
resolve_leaf(work, object_type, id) →
  | exists_in_store(id)     → Addressable
  | session_draft(id)       → AddressableDraft（栏3 显示「草稿·待写入」卡，非 GET 404）
  | else                    → Unaddressable → 降级 category 或 create
```

### 2.2 `SessionEntity`（讨论产物，非正典）

```json
{
  "draft_id": "draft:char:gusheng",
  "object_type": "character",
  "label": "顾声",
  "aliases": ["主角", "他"],
  "fields": { "occupation": "夜班代驾", "ghost": "哥哥消失六年", ... },
  "source_turn_ids": ["..."],
  "status": "drafting | proposed | approved | discarded",
  "work": "book_xxx"
}
```

- 存 **按 work 隔离** 的会话草稿表（settings 或 Surreal `session_draft`，**非** codex 正典表）  
- 主编回复中出现的可抽取实体 → upsert draft（可规则 + 可选 LLM 结构化，**先规则后增强**）  
- **批准 WriteProposal 成功后**：draft → 正典 id，UiTarget 升为 `leaf`  

这直接解决「聊了顾声半天库是空的、栏 3 却想打开顾声」。

### 2.3 `WorkPackage` 升级（在现有 package 上加字段，不推倒）

```json
{
  "id": "wp_...",
  "domain": "codex.character",
  "intent": "discuss | draft | write | review",
  "required_outcome": "read_only_advice | write_proposal | prose_proposal",
  "entities": ["draft:char:gusheng"],
  "ui_target": { "kind": "category", "category": "character", "entry": "codex" },
  "focus_policy": "soft",
  "tool_allowlist": [...],
  "status": "discussing | awaiting_proposal | awaiting_approval | applied | abandoned"
}
```

- `intent=discuss`：永不 `use_world_write_run`，永不 incomplete 空谈失败  
- `intent=write`：必须工具 + 提案；空谈 → incomplete + **自动生成提案草稿按钮**  
- 从消息与会话草稿 **推断 intent**（突变词 / force / 用户点「生成写入提案」）

### 2.4 `FocusPolicy`（跟焦策略，最优体验关键）

| policy | 行为 | 何时用 |
|--------|------|--------|
| `none` | 只改 right_tab=chief，不改栏 2/3 | 纯闲聊、作者正在写正文 |
| `soft` | open-capability + 轻提示条「相关：角色·顾声草稿」；**不** setSel 抢栏 3 | 默认讨论 |
| `hard` | setSel 到 category/leaf/create | 用户点「打开设定」、旅程 continue、批准后跟焦 |

**最优默认：`soft`。** 硬抢 selection 是本次「找不到入口」的体验放大器（前缀污染 + 错误栏 3）。

## 3. 端到端状态机（最优主路径）

```text
                    ┌──────────────┐
         消息 ──►   │  resolve     │──► WorkPackage + UiTarget + FocusPolicy
                    └──────┬───────┘
                           │
              soft: 舞台提示 / hard: 合法入口
                           │
                    ┌──────▼───────┐
                    │  对话通道     │  discuss → chat；write → Run（白名单）
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        抽取 Session    工具写提案    空谈+write intent
        Entity 草稿     WriteProposal  → incomplete
              │            │            │
              └────► 提案卡（作者语义）◄─┘
                           │
                      人 批 准
                           │
              commit_if_approved → 正典 id
                           │
              UiTarget=leaf(id) + FocusPolicy=hard
                           │
                      栏3 真详情
```

**关键差异（相对现状）**

| 现状 | 最优 |
|------|------|
| 聊完 = 气泡文字 | 聊完 = draft + 可一键提案 |
| 跟焦 = 半截 node | 跟焦 = 仅 Addressable |
| 空转 Run completed | write intent 无写工具 → 强制 incomplete **并** 预填提案 ops |
| 仅角色特殊处理 | Catalog 声明 `fallback_target` 全域一致 |

## 4. Catalog 最优形态

每条 domain **必须**声明：

```json
{
  "domain": "codex.character",
  "object_type": "character",
  "fallback_target": { "kind": "category", "category": "character", "entry": "codex" },
  "create_target": { "kind": "create", "object_type": "character", "entry": "codex" },
  "match_keywords": [...],
  "write_tools": ["s3_add_character", "s3_patch_character", ...],
  "read_tools": [...],
  "required_outcome_default": "read_only_advice",
  "write_outcome": "write_proposal",
  "focus_policy_default": "soft"
}
```

**解析算法（唯一）**

```text
1. match domain
2. extract entity ref / attach session draft
3. if write intent → required_outcome = write_outcome else default
4. ui_target =
     if addressable(leaf) → leaf
     elif has draft → create|leaf(draft)  // 草稿详情卡
     else fallback_target
5. never emit selection unless target.kind ∈ {category, create, leaf}
```

势力/物件/术语/世界规则/母题/命题/伏笔 **同一算法**，禁止再为 character 单开例外树。

## 5. 前端最优消费（单一总线）

### 5.1 废弃「半事件拼盘当真理」

保留事件适配层，但 **唯一真理是 `ui_target`**：

```text
applyUiTarget(target, policy):
  policy=none  → 仅 right_tab
  policy=soft  → open-capability + Toast/条「相关舞台」；可选 setFocus(origin:orchestration) 不 setSel
  policy=hard  → setSel 映射：
       category → codex_category | promise_view | ...
       create   → codex_new
       leaf     → 真实 leaf node {type, ref: localId, label}
```

### 5.2 栏 3 详情

| target | 栏 3 |
|--------|------|
| category | 目录/列表（已有 Container） |
| create / draft | **DraftInspector**：展示会话字段 +「生成写入提案」主按钮 |
| leaf 正典 | 现有 CodexDetail GET |
| leaf 不可寻址 | **禁止渲染**；降级 DraftInspector 或 category |

`/characters/null` 在类型层不可达（I1+I3）。

### 5.3 主编气泡

每轮 assistant 可附：

- `orch_chip`：当前包 domain + intent + draft 名  
- `WriteProposalCard`：write intent 或用户点「根据讨论生成提案」  
- `remedy`：incomplete 时的可点 suggested_prompt / 一键生成提案  

---

## 6. 抽取与提案（讨论闭环最优解）

### 6.1 抽取管线（两级）

1. **L1 规则**（必做）：专名模式、「草案：X」「名叫 X」、工具结果里的 id  
2. **L2 结构化**（增强，可选）：回合结束对 assistant 输出跑轻量 schema 抽取 → 合并进 SessionEntity（失败不阻断）

### 6.2 提案生成（必做，最优体验核心）

触发：

- 用户点「根据以上讨论生成写入提案」  
- write intent 且 evaluate incomplete  
- 旅程 continue 且域要求 write  

输入：active WorkPackage + SessionEntity.fields + 近窗对话  
输出：`WriteProposal.ops[]`（如 `s3_add_character` args 从 draft 填满）  
人批 → 现有 `commit_if_approved` 路径  

**禁止**自动 execute=true 默认落库。

## 7. API 契约（最优形态）

| 端点 | 职责 |
|------|------|
| `POST /orchestration/resolve` | 返回 package + **ui_target** + focus_policy + ui_events（由 target 派生，兼容旧客户端） |
| `GET /orchestration/drafts` | 列会话草稿 |
| `POST /orchestration/drafts/upsert` | 抽取/手动补全 |
| `POST /orchestration/proposal/from-discussion` | 讨论→WriteProposal（主路径） |
| `POST /orchestration/evaluate-turn` | 不变语义 + 可附 `suggested_proposal_id` |
| `POST /orchestration/proposal/apply` | 批准后返回 **ui_target leaf**（Addressable） |

兼容期：旧 `ui_directive.node` 由 `ui_target` **投影**生成，禁止反向。

## 8. 爆炸半径与迁移（最优交付纪律）

### 8.1 爆炸半径表

| 组件 | 变化 | 风险 | 缓解 |
|------|------|------|------|
| resolve 输出 | 增 ui_target / focus_policy | 中 | 兼容投影 ui_directive |
| 默认 soft 跟焦 | 不再默认抢栏 3 | 中（体感变化） | hard 用于 continue/批准/显式打开 |
| 全域 fallback category | faction 等不再幽灵 404 | 低 | 单测表驱动全域 |
| SessionEntity | 新存储 | 中 | work 隔离；可清；非正典 |
| from-discussion 提案 | 新主路径 | 中 | 与 Hermes 卡并存；双显策略文档化 |
| CodexDetail | 只收 leaf | 低 | ghost 测 + 契约测 |

### 8.2 分阶段落地（最优完整，非「最省」）

| 阶段 | 内容 | 完成定义 |
|------|------|----------|
| **O1 契约** | UiTarget + AddressabilityProbe + Catalog fallback 全域；前端单一 applyUiTarget；禁止幽灵 leaf 测试矩阵 | 全域弱意图消息 0 次 CODEX_LEAF 假 selection；0 次 /x/null |
| **O2 草稿** | SessionEntity 存取 + 规则抽取 + DraftInspector | 「顾声」讨论后 drafts 可见；栏 3 草稿卡非 404 |
| **O3 提案闭环** | from-discussion + incomplete 一键提案 + 批准后 leaf hard 跟焦 | 口头讨论 → 一键提案 → 批 → 库中有顾声且栏 3 打开顾声 |
| **O4 策略打磨** | 默认 soft、正文编辑中 none、旅程 hard；前缀话术只在 soft 用短 chip 不污染 user 消息 | 用户不再看到「角色「」」污染；写正文不被乱切栏 |
| **O5 增强** | L2 抽取、多实体包、批量提案 | 质量指标：写意图空转率下降 |

**不接受**只做 O1 角色特例作为终态；O1 必须全域。

### 8.3 验证矩阵（最优验收）

| 用例 | 期望 |
|------|------|
| 「我们先讨论主角」 | ui_target=category(character)，policy=soft，无 GET leaf |
| 「讨论势力」 | category(faction)，非 id=faction leaf |
| 「埋一个承诺…」 | stage+panel promise 或 category；无假 promise id GET |
| 讨论产出顾声草案 | draft 存在；DraftInspector |
| 「生成写入提案」 | WriteProposal 含 s3_add_character 填全字段 |
| 批准后 | leaf(顾声) hard 跟焦；GET 200 |
| 写正文时 resolve 讨论 | policy=none 或 soft，不切走章编辑器 |
| 回归 | director / experience / finalize 绿 |
