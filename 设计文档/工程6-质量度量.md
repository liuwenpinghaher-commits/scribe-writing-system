## § 2 · 设计目标与百万字挑战

### 2.1 设计目标

| 目标 | 可测量描述 | 证据级别 |
|---|---|---|
| **"对"/"好"双轨** | 门槛轨(M 系列)与价值轨(Q 系列)明确分离,报告界面清晰区分两类指标 | 【设计决策】 |
| **"好"由人评定义** | H 系列人评与 TasteModel 锚定的个性化标准一致,不使用固化的"通用文学优秀"标准 | 【设计决策】 |
| **机器-人评校准** | 每卷完成后运行校准;M 系列与 H 系列相关系数 \|r\| ≥ 0.4 为合格 | 【设计决策,需验证】 |
| **百万字覆盖** | 500 章场景下评估系统不成为瓶颈:LITE 模式单章 < 50ms(纯 SQL);FULL 模式异步执行 | 【设计决策】 |
| **反哺有效性** | 建议注入后,下一章 Q 系列均值相对前章提升;可通过 A/B 实验量化 | 【设计决策,需验证】 |
| **TasteModel 个性化可见** | 同一章,对不同 TasteModel 可产出不同的 Q 系列价值评分,差异可在报告中说明 | 【设计决策】 |

### 2.2 百万字的核心挑战

**挑战 A:无现成百万字崩坏率曲线**

学术论文中"一致性错误随长度线性累积"假设已被证伪【已核实 arXiv 2505.12572】。真实曲线形态未知——可能是阶跃式崩坏(在某个结构节点后突然恶化),也可能是平台期。**本系统须自建曲线:边写边采集,边积累边校准,不引用外部排行。**

**挑战 B:"好"难量化**

G1–G6(张力/情感真实/人物/新鲜/主题/文字质感)是主观美学判断【已核实 arXiv 2310.00785 BooookScore 发现"连贯但平淡"的质量维度无单一最优解】。任何单一机器指标都是代理量,不可避免存在与人感知的偏差。**解决方案:以人评为地基,机器指标为高频更新的代理,定期校准。**

**挑战 C:"好"因人而异**

玄幻修仙的"好"与纯文学的"好"截然不同【稳定知识:编辑学共识】。使用通用文学标准会导致对网文作者的过度惩罚,或反之。**解决方案:Q 系列指标的评估参数从 TasteModel 动态取,不硬编码。**

**挑战 D:成本与覆盖的矛盾**

500 章全量 FULL 评估(含 LLM 调用)成本过高。**解决方案:分层评估——LITE(纯 SQL)全覆盖,FULL(含 LLM)按结构节点+低分章抽样,人评(外部)约 10% 章。**

**挑战 E:指标漂移**

前期校准好的 M7 权重在百万字规模下可能失效(因为作品风格演进、TasteModel 更新)。**解决方案:每卷结束强制触发权重重新校准,并标注权重的"有效区间"(本卷 vs 全书)。**

## § 3 · 详细设计

### 3.1 指标体系全景

**核心原则**:门槛指标描述"有没有问题"(越低越好,接近 0 是目标),价值指标描述"有多好"(越高越好,由人评的 TasteModel 定义上限)。两类指标性质不同,不应混为一个综合分数。

```
QualityReport
│
├── 门槛轨(Correctness Track) ── "写得对" ── 消费内门槛层输出
│   ├── M1  Scribe-BooookScore 连贯性得分         [0,1] ↑好
│   ├── M2  ConStory 19 类错误命中(五大类明细)    count ↓好
│   ├── M3  伏笔回收率                             [0,1] ↑好
│   └── M4  时间线冲突数                           count ↓好
│
├── 价值轨(Quality Track) ── "写得好" ── 消费内核3输出 + TasteModel 校准
│   ├── Q1  反 AI 腔密度                           density ↓好
│   ├── Q2  意外性评分(CritiqueAgent 子维度)        [0,5] ↑好
│   ├── Q3  情感命中评分(intent_resonance)          [0,5] ↑好
│   ├── Q4  文字质感综合分(8 维 rubric 均值)         [0,5] ↑好
│   ├── Q5  网文钩子覆盖/强度                       [0,3] ↑好
│   ├── Q6  爽点密度                               /千字 ↑好
│   └── Q7  追读预测分(代理)                        [0,1] ↑好
│
└── 人评轨(Human Eval Track) ── 校准地基 ── 低频高质量
    ├── H1  文字质感(TasteModel 锚定)               [1,5] ↑好
    ├── H2  情感/爽感(TasteModel 锚定)              [1,5] ↑好
    └── H3  人物感染力                              [1,5] ↑好
```

> **双轨分离的报告原则**:门槛轨不及格时警示(消费门槛 1);价值轨的"好"由 TasteModel 和 H 系列定义,没有外部标准。报告 UI 中两轨分栏展示,永远不合并为一个综合数字(避免"高连贯性分掩盖低质感"的误导)。

### 3.2 门槛轨指标

#### 3.2.1 M1 · Scribe-BooookScore 连贯性得分

**理论来源**【已核实 arXiv 2310.00785,ICLR 2024 oral】:
BooookScore 定义:
> BooookScore = 不含任一已识别连贯错误的句子数 / 总句子数

**Scribe 适配**:以章为单位;消费门槛1 已产出的 `ConsistencyFlag`,避免重复 LLM 调用;对门槛1 未覆盖的叙事流畅性问题,FULL 模式追加一次 LLM 连贯性扫描。

**公式**:

```
设:
  S_total(c)   = 章 c 的总句子数
  S_flagged(c) = 被 ConsistencyFlag 覆盖的句子数
               + LLM 连贯性扫描新增的不连贯句子数(FULL 模式)

M1(c) = 1 − S_flagged(c) / S_total(c)   ∈ [0, 1]
```

**计算伪代码**:

```python
def compute_m1_booookscore(
    chapter_id: UUID,
    mode: EvaluationMode = EvaluationMode.LITE,
) -> float:
    segments = db.query(Segment).filter(
        Segment.chapter_id == chapter_id,
        Segment.deleted_at.is_(None)
    ).order_by(Segment.seq).all()

    full_text = " ".join(s.text for s in segments)
    sentences = split_into_sentences(full_text)
    S_total = len(sentences)
    if S_total == 0:
        return 1.0

    # 消费门槛1 的 ConsistencyFlag(00 §4.3)
    flags = db.query(ConsistencyFlag).filter(
        ConsistencyFlag.chapter_id == chapter_id,
        ConsistencyFlag.status.in_(["open", "confirmed"])
    ).all()

    flagged_indices: set[int] = set()
    for flag in flags:
        indices = flag.evidence_refs.get("sentence_indices", [])
        flagged_indices.update(indices)

    # FULL 模式:追加 LLM 连贯性扫描
    if mode == EvaluationMode.FULL:
        llm_new_flags = await llm_coherence_scan(sentences, chapter_id, existing_flags=flags)
        flagged_indices.update(llm_new_flags)

    return round(1.0 - len(flagged_indices) / S_total, 4)
```

**LLM 连贯性扫描 Prompt 骨架(FULL 模式)**:

```
[SYSTEM]
你是专业的长篇小说编辑。逐句审查以下章节文本,识别影响叙事连贯性的句子。
高精确率优于高召回——只报告确实存在的问题,不要误报。

[USER]
## 已知问题(已由一致性模块标记,请跳过这些句子索引)
${existing_flag_sentence_indices}

## 章节文本(编号句子)
${numbered_sentences}

## 输出(严格 JSON)
{
  "incoherent_sentence_indices": [整数列表],
  "reasons": {"句子索引": "一句话说明为何不连贯"}
}
若无新问题: {"incoherent_sentence_indices": [], "reasons": {}}
```

#### 3.2.2 M2 · ConStory 19 类错误命中数

**理论来源**【已核实 arXiv 2603.05890】:ConStory 定义五大类 19 子类一致性错误(见 00 §5)。

**数据来源**:直接消费门槛1 产出的 `ConsistencyFlag.error_class`,纯 SQL 聚合,不重复 LLM 调用。

**公式**:

```
F(c, cls) = 章 c 中 error_class=cls、status ≠ 'dismissed' 的 ConsistencyFlag 数量

M2_detail(c) = {
  "时间线与情节逻辑": sum F(c, TIMELINE_*),   # 6 子类
  "人物塑造":         sum F(c, CHAR_*),       # 4 子类
  "世界观与设定":     sum F(c, WORLD_*),      # 3 子类
  "事实与细节":       sum F(c, FACT_*),       # 3 子类
  "叙事与风格":       sum F(c, NARRATIVE_*),  # 3 子类
}

M2_total(c) = sum(M2_detail(c).values())      # 越低越好,理想为 0
M2_weighted(c) = Σ weight(flag.severity)      # critical=3, major=2, minor=1
```

**计算伪代码**:

```python
CATEGORY_PREFIX_MAP = {
    "时间线与情节逻辑": (
        "TIMELINE_SEQUENCE", "TIMELINE_CAUSALITY", "TIMELINE_DUPLICATE",
        "TIMELINE_PARALLEL", "TIMELINE_LOOP", "TIMELINE_IMPOSSIBLE"
    ),
    "人物塑造":         ("CHAR_OOC", "CHAR_ABILITY", "CHAR_RELATION", "CHAR_MOTIVATION"),
    "世界观与设定":     ("WORLD_RULE", "WORLD_GEOGRAPHY", "WORLD_FACTION"),
    "事实与细节":       ("FACT_ITEM_STATE", "FACT_APPEARANCE", "FACT_NAMING"),
    "叙事与风格":       ("NARRATIVE_POV", "NARRATIVE_STYLE", "NARRATIVE_INFO"),
}

SEVERITY_WEIGHT = {"critical": 3, "major": 2, "minor": 1}

def compute_m2_constory(chapter_id: UUID) -> dict:
    flags = db.query(ConsistencyFlag).filter(
        ConsistencyFlag.chapter_id == chapter_id,
        ConsistencyFlag.status != "dismissed"
    ).all()

    result = {cat: 0 for cat in CATEGORY_PREFIX_MAP}
    weighted = 0
    for flag in flags:
        for cat, subtypes in CATEGORY_PREFIX_MAP.items():
            if flag.error_class in subtypes:
                result[cat] += 1
                break
        weighted += SEVERITY_WEIGHT.get(flag.severity, 1)

    result["total"]    = sum(result[cat] for cat in CATEGORY_PREFIX_MAP)
    result["weighted"] = weighted
    return result
```

#### 3.2.3 M3 · 伏笔回收率

**理论来源**【已核实 arXiv 2601.07033 CFPG】:F-T-P 状态机伏笔追踪检测率 69.8%。

消费门槛1 维护的 `Foreshadow` 表(00 §4.3)。

**公式**:

```
截止章 c 的章序号 seq(c):

F_planted(≤c)   = {f | f.foreshadow_chapter.seq ≤ seq(c)}
F_paid(≤c)      = {f | f.payoff_chapter.seq ≤ seq(c) AND f.state = 'paid'}
F_abandoned(≤c) = {f | f.state = 'abandoned' AND f.foreshadow_chapter.seq ≤ seq(c)}

M3(c) = |F_paid(≤c)| / max(|F_planted(≤c)| − |F_abandoned(≤c)|, 1)  ∈ [0, 1]
```

**分级报警阈值**【设计决策,需在实际作品上校准】:

| M3 范围 | 等级 | 行动 |
|---|---|---|
| ≥ 0.75 | 正常 | 无 |
| 0.50–0.75 | 警告 | 建议在下一卷安排回收情节 |
| < 0.50 | 危险 | 在 PlanningAgent prompt 注入"伏笔积压专项回收"约束 |

#### 3.2.4 M4 · 时间线冲突数

M4 是 M2_detail["时间线与情节逻辑"] 的直接引用,单独列出原因:时间线冲突是百万字最高频的崩坏信号,需独立监控趋势【稳定知识:多篇长文生成研究均优先对抗时间线问题,见 arXiv 2508.03137, 2503.23512】。

**公式**:

```
M4(c) = M2_detail(c)["时间线与情节逻辑"]    越低越好,理想为 0
```

**全书时间线冲突曲线构建**:

```python
def compute_timeline_conflict_curve(work_id: UUID) -> list[dict]:
    chapters = (
        db.query(Chapter).join(Volume)
        .filter(Volume.work_id == work_id, Chapter.status.in_(["reviewing", "done"]))
        .order_by(Chapter.seq).all()

    return [
        {
            "chapter_seq": ch.seq,
            "chapter_id":  str(ch.id),
            "m4_timeline": compute_m2_constory(ch.id).get("时间线与情节逻辑", 0),
        }
        for ch in chapters
    ]
```

### 3.3 价值轨指标

价值轨的核心设计原则:

1. **机器指标是代理,不是裁判**:Q 系列指标从内核3 的产出(SlopReport / CritiqueReviseResult)派生,可高频更新,但其对"好"的判断必须定期对照人评(H 系列)校准。
2. **"好"由 TasteModel 锚定**:Q 系列指标的阈值和权重不是固定常数,而是从 `TasteModel.anti_slop_sensitivity`、`TasteModel.learned_preferences` 等字段动态取。同一章,TasteModel 不同的两位作者,得到的 Q 系列分数可以不同。
3. **必须与 H 系列对应**:每个 Q 指标都有对应的 H 指标(或子项)作为校准锚。Q 与 H 脱钩时触发校准任务。

#### 3.3.1 Q1 · 反 AI 腔密度

**数据来源**:消费内核3 的 `SlopReport`(00 §4.3 消费链,`SlopReport.slop_density`)。

**公式**:

```
Q1(c) = SlopReport.slop_density(c)
      = total_hits / (chapter_word_count / 1000)
      单位: 命中数 / 千字   越低越好

个性化调整:
  Q1_personalized(c) = Σ(hit.confidence × sensitivity_weight(hit.rule_id)) / (word_count / 1000)

  sensitivity_weight(rule_id) = TasteModel.learned_preferences["anti_slop_sensitivity"][rule_category]
  — 作者对某类 AI 腔敏感度高时,该类命中权重提升,体现"这个作者更在意这一点"
```

**阈值参考**【设计决策,须用自有语料和人评校准】:

| Q1 raw | 等级 | 含义 |
|---|---|---|
| < 1.0 / 千字 | 优秀 | AI 腔稀少 |
| 1.0–2.0 | 可接受 | 有 AI 痕迹但不突出 |
| 2.0–4.0 | 警告 | AI 感明显 |
| > 4.0 | 严重 | 需重写 |

**与 H 系列的校准关系**:Q1 应与 H1(文字质感)负相关。若两者 Pearson |r| < 0.30,说明 slop_density 未能反映作者实际感受到的"AI 腔",需检查 TasteModel.anti_slop_sensitivity 权重是否准确。

#### 3.3.2 Q2 · 意外性评分

**数据来源**:消费内核3 `CritiqueReviseResult.final_critique` 中的 `emotional_tension` 和 `subtext_whitespace` 两个维度——它们合并反映"是否让读者猜不到下一步"这一意外性维度(内核3 §3.3)。

意外性是 G4(新鲜/猜不到)的直接度量。它是 LLM 的结构性弱点(next-token 趋均值)【已核实 arXiv 2310.00785】,也是最难用机器准确量化的维度。

**公式**:

```python
def compute_q2_surprise_score(
    critique_result: CritiqueReviseResult | None,
    taste_model: TasteModel,
) -> float | None:
    """
    Q2 由两个 rubric 子项合并计算。
    若本章没有经过内核3 评改(LITE 档),则返回 None(报告中标注"未评估")。
    """
    if critique_result is None:
        return None

    dims = critique_result.final_critique.dimensions
    tension_score     = dims.get("emotional_tension",  {}).get("score", None)
    subtext_score     = dims.get("subtext_whitespace",  {}).get("score", None)

    if tension_score is None and subtext_score is None:
        return None

    # 加权平均(两维度权重可由 TasteModel 调整:偏好张力的作者给 tension 更高权重)
    prefs = taste_model.learned_preferences
    twist_freq = prefs.get("题材与内容倾向", {}).get("twist_frequency", {}).get("value", 0.5)

    w_tension = 0.5 + twist_freq * 0.3        # 高反转偏好 → 张力权重高
    w_subtext = 1.0 - w_tension

    scores = []
    weights = []
    if tension_score is not None:
        scores.append(tension_score);  weights.append(w_tension)
    if subtext_score is not None:
        scores.append(subtext_score);  weights.append(w_subtext)

    return round(sum(s * w for s, w in zip(scores, weights)) / sum(weights), 2)
```

**重要诚实声明**【设计决策】:Q2 仅在 PREMIUM 或 STANDARD 质量档(内核3 运行了评改环)的章节上有值。LITE 档章节 Q2=None。在 50 章人评积累之前,Q2 的可信度低——应在报告中明确标注"机器代理,需人评校准"。

#### 3.3.3 Q3 · 情感命中评分(北极星共鸣)

**数据来源**:直接消费内核3 `CritiqueReviseResult.final_critique.dimensions["intent_resonance"]`。

`intent_resonance` 是 8 维 rubric 中专门对照 `AuthorIntent.reader_feeling` 判断的维度(内核3 §3.5.2)——"本章是否有至少一个具体时刻令读者感受到作者意图中的核心感受"。这是 G2(情感真实)和 G5(主题)的联合代理指标。

**公式**:

```python
def compute_q3_intent_resonance(
    critique_result: CritiqueReviseResult | None,
) -> float | None:
    if critique_result is None:
        return None
    score = critique_result.final_critique.dimensions.get(
        "intent_resonance", {}
    ).get("score", None)
    return score  # ∈ [0, 5],5 = 强烈共鸣,0 = 完全感受不到
```

**Q3 的特殊性**:它是本指标体系中唯一直接对照 `AuthorIntent`(北极星)的机器指标。对同一段文字,CritiqueAgent 依据不同的 `AuthorIntent.reader_feeling` 会给出不同的 Q3 分——体现了个性化的另一个维度。

#### 3.3.4 Q4 · 文字质感综合分

**数据来源**:消费内核3 `CritiqueReviseResult.final_critique` 的 8 维 rubric 中除 `emotional_tension`、`subtext_whitespace`、`intent_resonance` 之外的 5 个维度:
`show_not_tell` / `sensory_detail` / `dialogue_quality` / `imagery_rhythm` / `scene_blocking`

**公式**:

```python
CRAFT_DIMS = [
    "show_not_tell",
    "sensory_detail",
    "dialogue_quality",
    "imagery_rhythm",
    "scene_blocking",
]

def compute_q4_craft_score(
    critique_result: CritiqueReviseResult | None,
    taste_model: TasteModel,
) -> float | None:
    if critique_result is None:
        return None

    dims = critique_result.final_critique.dimensions
    prefs = taste_model.learned_preferences

    # 权重从 TasteModel 取:作者更强调 show_not_tell 则其权重高
    show_tell_pref   = prefs.get("文风维度", {}).get("show_tell_target", {})
    dialogue_pref    = prefs.get("文风维度", {}).get("dialogue_style", {})
    imagery_pref     = prefs.get("文风维度", {}).get("imagery_density", {})

    dim_weights = {
        "show_not_tell":   0.25 + max(show_tell_pref.get("value", 0.5) - 0.5, 0) * 0.4,
        "sensory_detail":  0.20,
        "dialogue_quality": 0.20 + max(dialogue_pref.get("confidence", 0) - 0.4, 0) * 0.3,
        "imagery_rhythm":   0.15 + max(imagery_pref.get("confidence", 0) - 0.4, 0) * 0.2,
        "scene_blocking":   0.20,
    }

    total_weight = sum(dim_weights.values())
    weighted_sum = 0.0
    valid_dims   = 0

    for dim in CRAFT_DIMS:
        score = dims.get(dim, {}).get("score", None)
        if score is not None:
            weighted_sum += score * dim_weights[dim]
            valid_dims   += 1

    if valid_dims == 0:
        return None

    # 归一化:不要求所有维度都有评估结果
    effective_weight = sum(
        dim_weights[d] for d in CRAFT_DIMS
        if dims.get(d, {}).get("score") is not None
    )

    return round(weighted_sum / effective_weight, 2) if effective_weight > 0 else None
```

**个性化说明**:`show_not_tell` 对于 `TasteModel.learned_preferences.show_tell_target` 高的作者,权重会被放大;对不强调此维度的作者(如轻小说作者),权重降回基准。这体现了"这个作者的好文字是什么样的"。

#### 3.3.5 Q5 · 网文钩子覆盖与强度

**数据来源**:消费 `Chapter.hook_strength`(由内核3 或 ExtractAgent 在章生成后写入)。

`hook_strength` 取值:0=无钩子 / 1=弱钩子 / 2=中钩子 / 3=强钩子

**公式**:

```
Q5_score(c)        = c.hook_strength / 3          ∈ {0, 0.33, 0.67, 1.0}
Q5_coverage(C)     = |{c ∈ C | c.hook_strength ≥ 1}| / |C|
Q5_strong_rate(C)  = |{c ∈ C | c.hook_strength ≥ 2}| / |C|

目标参考值 [设计决策]: Q5_coverage ≥ 0.90; Q5_strong_rate ≥ 0.60
```

**Q5 与追读率的关系**【稳定知识:中文网文行业共识,见调研文档 §2.3】:章尾钩子是网文追读率最直接的代理指标。Q5 与 H2(情感/爽感)相关性预期较强,是 Q 系列中与 H 系列相关性最可靠的指标之一。

#### 3.3.6 Q6 · 爽点密度

**数据来源**:消费 `Chapter.outline.payoff_beats`(jsonb 数组,由规划层或 ExtractAgent 写入)。`payoff_beats` 类型枚举:upgrade / face_slap / obtain / reversal / reveal / bond / release。

**公式**:

```python
def compute_q6_payoff_density(scope_chapters: list[Chapter]) -> float:
    """
    爽点密度 = 爽点数 / 千字
    """
    total_payoffs = sum(
        len((ch.outline or {}).get("payoff_beats", []))
        for ch in scope_chapters
    )
    total_words = sum(ch.word_count or 0 for ch in scope_chapters)
    if total_words == 0:
        return 0.0
    return round(total_payoffs / total_words * 1000, 4)
```

**类型分布分析(完整版)**:除总密度外,还统计各类 payoff 类型占比。规划 Agent 可据此判断"是否过度依赖某一类爽点导致读者疲劳"。

**参考基线**【设计决策,无现成已验证外部数据,必须用自有读者反馈校准】:

| 作品类型 | 参考 Q6 | 来源 |
|---|---|---|
| 爽文 / 系统流 | ≥ 2.0 / 千字 | 内部估算,待验证 |
| 玄幻 / 都市 | 1.0–2.0 / 千字 | 内部估算,待验证 |
| 文学向 / 慢热 | 0.3–1.0 / 千字 | 内部估算,待验证 |

> ⚠️ 以上参考值为初始设计估算,**必须在积累 ≥ 3 部不同类型作品的人评数据后校准。** 在校准前,报告中标注"基线待验证"。

#### 3.3.7 Q7 · 追读预测分(代理合成)

Q7 是代理指标,基于 Q5/Q6/M2 等可观测值合成,不是真实追读率。

**公式**:

```python
def compute_q7_read_through_pred(
    q5_hook_score: float,
    q6_density:    float,
    m2_total:      int,
    h2_pleasure:   float | None,   # 仅抽样章有值
    weights:       Q7Weights,
    target_density: float = 1.5,   # 按作品 genre 取值
) -> float:
    """
    Q7 ∈ [0, 1]
    初始权重需人评校准;权重每卷更新一次。
    """
    m2_penalty      = min(m2_total / 10.0, 1.0)
    q6_normalized   = min(q6_density / target_density, 1.0)

    base = (
        weights.w_hook  * q5_hook_score
      + weights.w_payoff * q6_normalized
      + weights.w_err   * (1.0 - m2_penalty)
    )

    if h2_pleasure is not None:
        # 有人评时直接纳入(最可靠的信号)
        combined = base * (1 - weights.w_human) + (h2_pleasure / 5.0) * weights.w_human
    else:
        # 无人评时,用历史章的 H2 均值插值
        h2_interp = get_volume_h2_average(work_id=...) / 5.0
        combined  = base * 0.90 + h2_interp * 0.10

    return round(min(combined, 1.0), 4)

@dataclass
class Q7Weights:
    w_hook:  float = 0.35   # 初始,需校准
    w_payoff: float = 0.30
    w_err:   float = 0.20
    w_human: float = 0.15
    version: int   = 0      # 每次校准后递增
    calibrated_at: datetime | None = None
```

**权重校准机制**:每卷结束后,用本卷 H2 分数对 Q7 运行最小二乘拟合,更新 `Q7Weights` 并持久化。校准时要求人评样本 ≥ 4 章。

```python
def calibrate_q7_weights(
    human_eval_records: list[HumanEvalRecord],
    machine_scores:     list[dict],
    current_weights:    Q7Weights,
) -> Q7Weights:
    import numpy as np

    if len(human_eval_records) < 4:
        return current_weights  # 样本不足,维持原权重

    X = np.array([
        [s["q5_hook_score"], s["q6_normalized"], 1.0 - s["m2_penalty"]]
        for s in machine_scores
    ])
    y = np.array([r.h2_pleasure / 5.0 for r in human_eval_records])

    try:
        coeffs, _, _, _ = np.linalg.lstsq(X, y, rcond=None)
        w1, w2, w3 = [max(0.05, c) for c in coeffs]  # 强制非负
        w4  = 0.15  # H2 直接权重固定
        total = w1 + w2 + w3 + w4
        new_weights = Q7Weights(
            w_hook=w1/total, w_payoff=w2/total,
            w_err=w3/total,  w_human=w4/total,
            version=current_weights.version + 1,
            calibrated_at=datetime.utcnow(),
        )
        return new_weights
    except np.linalg.LinAlgError:
        return current_weights
```

### 3.4 人评轨指标(H 系列)

#### 3.4.1 设计哲学:人评是地基

H 系列不是 Q 系列的"补充",而是它的**校准地基**。机器永远无法完全替代人对"好"的判断,尤其是:
- 情感被击中的那一刻(G2)
- 人物真的"活着"的感觉(G3)
- 文字读来有质感(G6)

这三者恰好对应 H1/H2/H3。H 系列的稀缺和成本是真实代价——这是系统设计必须接受的,而不是用机器指标规避的。

#### 3.4.2 H 系列定义

**个性化说明**:H 系列的量表锚点不是通用文学标准,而是由 `TasteModel.get_eval_anchor()` 提供的个性化参照。同一量表,不同 TasteModel 的作者,5 分的含义略有不同。评分人在评分前会看到从 TasteModel 导出的参照描述。

| 维度 | 标识 | 量表 | 通用定义 | TasteModel 个性化锚点示例 |
|---|---|---|---|---|
| **文字质感** | H1 | 1–5 | 文字是否有独特节奏、意象、克制感,读来有质感 | "对这位作者:节奏舒缓 + 高意象密度 + show not tell ≥ 70% 为 4 分" |
| **情感/爽感** | H2 | 1–5 | 读完本章是否有被击中感(文学向=情感共鸣;网文向=即时爽感) | "对这位作者:章末有未解决张力 + 角色行动来自欲望 ≥ 4 分" |
| **人物感染力** | H3 | 1–5 | 本章角色是否有内在一致的欲望/矛盾,读来立体可信 | "对这位作者:无'说明性'台词,角色选择源于性格为 4 分" |

**量表锚点(H2 完整示例)**:

| 分值 | 通用描述 | 网文向个性化描述 |
|---|---|---|
| 1 | 完全无感染力 | 全章无爽点,情节平淡或令人烦躁 |
| 2 | 偶有一点意思 | 有一处满足但整体提不起劲 |
| 3 | 有明确的满足感 | 有 1–2 个清晰爽点,值得继续读 |
| 4 | 明显感染力 | 章末有强钩子,读完立即想看下一章 |
| 5 | 强烈被击中 | 章节高潮/核心爆发点,难以放下 |

#### 3.4.3 TasteModel 个性化注入到评分任务

```python
def generate_eval_task(
    chapter_id: UUID,
    taste_model: TasteModel,
    evaluator_id: str,

    """
    生成包含 TasteModel 个性化锚点的评分任务。
    评分人看到的不是通用标准,而是针对这位作者的参照。
    """
    anchor = taste_model_service.get_eval_anchor(taste_model)

    return HumanEvalTask(
        chapter_id    = chapter_id,
        evaluator_id  = evaluator_id,
        h1_anchor_desc= anchor.h1_description,   # "对您而言，5分意味着：..."
        h2_anchor_desc= anchor.h2_description,
        h3_anchor_desc= anchor.h3_description,

            e["exemplar_id"] for e in taste_model.positive_exemplars[:2]

    )
```

#### 3.4.4 H 系列回流到 TasteModel

H 系列分数被内核2 消费,生成 `PreferenceSignal`(类型 `rating`)并更新 TasteModel。这是"度量绑定好"的核心回路——作者的评分行为直接影响"好"的下一次定义。

```
作者对章 c 提交 H 评分
      │
      ▼
HumanEvalRecord 写入(本模块持久化)
      │
      ▼
内核2 SignalCollector 消费
  signal = {
    "eval_type": "h1_quality" | "h2_pleasure" | "h3_character",
    "score": <H1/H2/H3 值>,
    "baseline_score": <该作品近期 H 系列均值>,
    "chapter_style_tags": { ... },
    "inferred_preferences": [ ... ]
  }
  polarity = sign(score - baseline_score)
  weight   = sigmoid(|score - baseline_score| × 2) × 0.50
      │
      ▼
TasteModel 增量更新(内核2 §3.4.1)
```

#### 3.4.5 抽样策略

人评资源稀缺,需要有效抽样。每卷抽取 `max(2, round(卷内章数 × 0.10))` 章,约 10%。

**抽样维度权重**:

| 维度 | 优先级 | 说明 |
|---|---|---|
| **结构节点章** | 必选 | StructureBeat = climax/resolution/midpoint/first |
| **低机器分章** | 高(诊断用) | M1 < 0.80 或 M2_total ≥ 3 |
| **高 Q6 爽点章** | 中(校准 H2) | Q6 密度最高的前 20% |
| **Q4 异常章** | 中(校准 H1) | Q4 异常低(< 2.0)或异常高(> 4.5) |
| **随机章** | 低(填充配额) | 确保随机覆盖 |

```python
def sample_chapters_for_human_eval(
    volume_id:     UUID,
    sample_ratio:  float = 0.10,
) -> list[UUID]:
    chapters  = get_volume_chapters_done(volume_id)
    n_sample  = max(2, round(len(chapters) * sample_ratio))
    selected  = set()

    # 1. 必选:结构节点章
    for c in chapters:
        if has_structure_beat(c, ["climax", "resolution", "midpoint", "first"]):
            selected.add(c.id)
            if len(selected) >= 2:
                break

    # 2. 低机器分章(诊断用)
    reports = get_chapter_reports_for_volume(volume_id)
    low_score = [r for r in reports if r.m1_booookscore < 0.80 or r.m2_constory.get("total", 0) >= 3]
    for r in sorted(low_score, key=lambda x: x.m1_booookscore)[:2]:
        selected.add(r.chapter_id)

    # 3. 高 Q6 章(校准 H2)
    high_q6 = sorted(reports, key=lambda r: -(r.q6_payoff_density or 0))
    for r in high_q6[:max(1, n_sample // 4)]:
        selected.add(r.chapter_id)

    # 4. Q4 异常章(校准 H1)
    q4_anomaly = [
        r for r in reports
        if r.q4_craft_score is not None and (r.q4_craft_score < 2.0 or r.q4_craft_score > 4.5)
    ]
    for r in q4_anomaly[:1]:
        selected.add(r.chapter_id)

    # 5. 随机补充
    remaining = [c for c in chapters if c.id not in selected]
    import random; random.shuffle(remaining)
    for c in remaining[:max(0, n_sample - len(selected))]:
        selected.add(c.id)

    return list(selected)
```

### 3.5 个性化评分机制:TasteModel 如何改变 Q/H 分数

这是本文档最重要的设计区分点。

```
场景:同一章节文本 T,两位作者 A、B 的 TasteModel 不同

作者 A 的 TasteModel:
  - anti_slop_sensitivity["E_FORCED_ELEVATION"] = 0.90  (高度敏感总结升华)
  - learned_preferences.show_tell_target.value = 0.80   (强调 show not tell)
  - learned_preferences.emotional_tone.dominant = "压抑克制"

作者 B 的 TasteModel:
  - anti_slop_sensitivity["E_FORCED_ELEVATION"] = 0.20  (不在意总结升华)
  - learned_preferences.show_tell_target.value = 0.40   (接受 tell)
  - learned_preferences.emotional_tone.dominant = "爆发热烈"

对同一文本 T:
  T 有 3 处 E_FORCED_ELEVATION 命中,show_tell_ratio = 0.45,情绪爆发密集

  Q1_personalized(A) = high      (3 处 ×0.90 权重 → 明显 AI 腔)
  Q1_personalized(B) = low       (3 处 ×0.20 权重 → 基本可接受)

  Q4(A) = 2.1 / 5                (show_not_tell 权重高,0.45 达不到 0.80 目标 → 低分)
  Q4(B) = 3.7 / 5                (show_not_tell 权重低;情绪爆发与 B 的偏好对齐 → 较高)

  H1 评分表述(A): "4分意味着 show≥70%、无总结升华……"
  H1 评分表述(B): "4分意味着情绪张力强烈、有感染力……"
```

**实现方式**:Q1/Q4 在计算时从 `TasteModel` 取权重参数(见 §3.3.1、§3.3.4);H 系列评分任务由 `generate_eval_task()` 注入个性化锚点(§3.4.3)。

#### 3.6.5 双轨评级规则

**门槛评级**【设计决策,需人评校准后调整分界】:

```python
def compute_correctness_grade(
    m1: float, m2_total: int, m3: float, m4: int,
) -> str:
    if m1 >= 0.90 and m2_total == 0 and m4 == 0:
        return "A"
    elif m1 >= 0.80 and m2_total <= 2 and m4 <= 1:
        return "B"
    elif m1 >= 0.65 and m2_total <= 5:
        return "C"
    elif m1 >= 0.50 or m2_total <= 10:

    else:

```

**价值评级**【设计决策,须由人评数据反复校准】:

```python
def compute_quality_grade(
    q1_personalized: float | None,
    q4_craft:        float | None,
    q5_hook_score:   float,
    q7_pred:         float | None,
    h1:              int | None,     # 若有人评,优先用
    h2:              int | None,
) -> str:
    """
    价值评级优先用人评(H),无人评时降级为代理估算,并在报告中标注。
    """
    # 若有足够人评,用 H 系列直接定级
    if h1 is not None and h2 is not None:
        avg_h = (h1 + h2) / 2.0
        if avg_h >= 4.5:   return "A"
        elif avg_h >= 3.5: return "B"
        elif avg_h >= 2.5: return "C"
        elif avg_h >= 1.5: return "D"
        else:              return "F"

    # 无人评:使用机器代理,但评级上限设为 B(代理不可高于 B)
    score = 0.0
    weight_sum = 0.0

    if q4_craft is not None:
        score += q4_craft / 5.0 * 0.40;  weight_sum += 0.40
    if q1_personalized is not None:
        score += max(0, 1.0 - q1_personalized / 3.0) * 0.25;  weight_sum += 0.25
    score += q5_hook_score * 0.20;  weight_sum += 0.20
    if q7_pred is not None:
        score += q7_pred * 0.15;    weight_sum += 0.15

    if weight_sum == 0:
        return "?"   # 无足够数据

    normalized = score / weight_sum
    if normalized >= 0.80:   return "B"   # 机器代理上限为 B
    elif normalized >= 0.60: return "C"
    elif normalized >= 0.40: return "D"
    else:                    return "F"
```

### 3.7 百万字崩坏率自建曲线

#### 3.7.1 定义与设计依据

**无现成数据**【已核实 arXiv 2505.12572,调研文档 §1.1】:百万字长文生成质量随章节序号的真实曲线形态未知。"一致性错误线性累积"假设已被证伪——实际可能是阶跃式崩坏或非线性。

**本系统自建两条崩坏曲线**:
- **门槛崩坏率(Correctness Collapse)**:基于 M1/M2/M4
- **价值崩坏率(Quality Collapse)**:基于 Q1/Q4(有 Q 系列数据的章节才有值)

两条曲线独立追踪,因为门槛崩坏和质量崩坏可能在不同章节序号上出现,缓解策略也不同。

#### 3.7.2 崩坏分公式

**门槛崩坏分**:

```python
def compute_correctness_collapse_score(
    m1: float,
    m2_total: int,
    m4: int,
    alpha: float = 0.50,   # M1(连贯性)权重
    beta:  float = 0.30,   # M2(一致性)权重
    gamma: float = 0.20,   # M4(时间线)权重
    m2_max: int = 10,
    m4_max: int = 5,
) -> float:
    """
    门槛崩坏分 ∈ [0, 1];越高越接近"崩坏"。
    初始权重为设计决策,须用实际作品数据迭代校准。
    """
    return (
        alpha * (1.0 - m1)
      + beta  * min(m2_total / m2_max, 1.0)
      + gamma * min(m4 / m4_max, 1.0)
    )
```

**价值崩坏分**:

```python
def compute_quality_collapse_score(
    q1_personalized: float | None,
    q4_craft:        float | None,
    q1_max:   float = 4.0,   # 认为 >4/千字 为严重 AI 腔
    q4_floor: float = 2.0,   # 认为 <2 为文字质感崩坏
) -> float | None:
    """
    价值崩坏分:仅在有内核3 评改结果(Q 系列有值)时计算。
    ∈ [0, 1];越高质量越差。
    """
    if q1_personalized is None and q4_craft is None:
        return None   # LITE 档章节无法计算

    scores = []
    if q1_personalized is not None:
        scores.append(min(q1_personalized / q1_max, 1.0))      # 密度归一化
    if q4_craft is not None:
        scores.append(max(0.0, (q4_floor - q4_craft) / q4_floor))  # 低于地板分

    return round(sum(scores) / len(scores), 4) if scores else None
```

#### 3.7.3 崩坏曲线构建

```python
def compute_collapse_curves(work_id: UUID) -> dict:
    """
    返回全书两条崩坏曲线。
    curves["correctness"]: 每章都有值(仅需 M 系列)
    curves["quality"]:     仅有 Q 系列评估的章才有值
    """
    reports = (
        db.query(ChapterQualityReport).join(Chapter).join(Volume)
        .filter(Volume.work_id == work_id, ChapterQualityReport.deleted_at.is_(None))
        .order_by(Chapter.seq)
        .all()
    )

    correctness_curve = []
    quality_curve     = []

    for r in reports:
        seq = get_chapter_seq(r.chapter_id)

        cc = compute_correctness_collapse_score(
            r.m1_booookscore,
            r.m2_constory.get("total", 0),
            r.m4_timeline_conflicts,
        )
        correctness_curve.append({
            "chapter_seq":   seq,
            "chapter_id":    str(r.chapter_id),
            "collapse_score": round(cc, 4),
            "m1": r.m1_booookscore,
            "m2": r.m2_constory.get("total", 0),
            "m4": r.m4_timeline_conflicts,
        })

        qc = compute_quality_collapse_score(
            r.q1_slop_density_personalized,
            r.q4_craft_score,
        )
        if qc is not None:
            quality_curve.append({
                "chapter_seq":   seq,
                "chapter_id":    str(r.chapter_id),
                "collapse_score": qc,
                "q1": r.q1_slop_density_personalized,
                "q4": r.q4_craft_score,
            })

    return {"correctness": correctness_curve, "quality": quality_curve}
```

#### 3.7.4 崩坏趋势告警

```python
def check_collapse_trend_alerts(
    correctness_curve: list[dict],
    quality_curve:     list[dict],
) -> list[str]:
    alerts = []

    # ── 门槛崩坏告警 ─────────────────────────────────────────
    if len(correctness_curve) >= 10:
        recent = correctness_curve[-10:]
        early  = correctness_curve[:10]
        avg_r  = sum(p["collapse_score"] for p in recent) / len(recent)
        avg_e  = sum(p["collapse_score"] for p in early)  / len(early)
        if avg_r > avg_e * 1.5:
            alerts.append(
                f"[门槛崩坏] 近10章连贯/一致性崩坏分均值 {avg_r:.3f}"
                f" 较前期 {avg_e:.3f} 上升 {(avg_r/avg_e-1)*100:.0f}%"
            )

    # 连续 3 章门槛崩坏分 > 0.4
    for i in range(2, len(correctness_curve)):
        if all(correctness_curve[j]["collapse_score"] > 0.4 for j in [i-2, i-1, i]):
            alerts.append(
                f"[门槛高危] 连续 3 章(seq "
                f"{correctness_curve[i-2]['chapter_seq']}–"
                f"{correctness_curve[i]['chapter_seq']}"
                f")崩坏分 > 0.4,建议人工审查"
            )
            break

    # ── 价值崩坏告警 ─────────────────────────────────────────
    if len(quality_curve) >= 8:
        recent_q = quality_curve[-8:]
        early_q  = quality_curve[:8]
        avg_rq   = sum(p["collapse_score"] for p in recent_q) / len(recent_q)
        avg_eq   = sum(p["collapse_score"] for p in early_q)  / len(early_q)
        if avg_rq > avg_eq * 1.6:
            alerts.append(
                f"[价值崩坏] AI腔密度/文字质感在近期明显恶化"
                f"(崩坏分均值 {avg_rq:.3f} vs 前期 {avg_eq:.3f})"
                f" — 建议检查 TasteModel 注入是否生效"
            )

    return alerts
```

#### 3.7.5 曲线的自建性质与使用限制

**重要声明**:

```
本系统的崩坏率曲线是完全自建的,具有以下限制:

1. 前 50 章缺乏统计意义:曲线的所有趋势判断在 < 50 章时仅供参考
   → 报告中标注"数据积累中(N/50章)"

2. 曲线形态因作品类型不同:玄幻修仙与纯文学的"正常崩坏分区间"不同
   → 建议积累 ≥ 3 部同类型作品后,建立类型专属基线

3. 权重是初始设计决策,不是研究结论:α=0.50/β=0.30/γ=0.20 须通过
   人评相关性分析迭代调整
   → 每部作品完成后,计算崩坏分与 H 系列均值的相关系数,指导下一版权重

4. 不与任何外部"模型错误密度排行"比较:本曲线只与同一作品的历史数据比较
```

#### 3.9.2 章级评估详细流程

```
输入: chapter_id, mode, taste_model(当前版本)

1. 检查缓存
   └─ mode=CACHE 且报告存在且 chapter.updated_at < report.generated_at → 返回缓存

2. 并行计算门槛轨(纯 SQL,无 LLM)
   ├─ M1: 汇聚 ConsistencyFlag → 计算;FULL 模式追加 LLM 连贯性扫描(异步)
   ├─ M2: ConsistencyFlag 按五大类统计
   ├─ M3: Foreshadow 表查询(全书累积)
   ├─ M4: M2["时间线与情节逻辑"]
   └─ 门槛评级: compute_correctness_grade(M1, M2, M3, M4)

3. 消费内核3 产出(若有)
   ├─ 取 SlopReport(chapter_id) → Q1 raw + Q1_personalized
   └─ 取 CritiqueReviseResult(chapter_id) → Q2/Q3/Q4 各 rubric 子项

4. 计算价值轨
   ├─ Q1: slop_density + personalized(from TasteModel)
   ├─ Q2: surprise_score(from CritiqueResult)
   ├─ Q3: intent_resonance(from CritiqueResult)
   ├─ Q4: craft_score(from CritiqueResult, TasteModel weighted)
   ├─ Q5: hook_strength(from Chapter)
   ├─ Q6: payoff_density(from Chapter.outline)
   └─ Q7: compute_q7(Q5, Q6, M2, h2_interp, Q7Weights)

5. 汇聚人评(若已提交)
   └─ HumanEvalRecord.filter(chapter_id=chapter_id)

6. 价值评级
   └─ compute_quality_grade(Q1_p, Q4, Q5, Q7, H1, H2)

7. 生成建议
   ├─ generate_correctness_suggestions(M1, M2_detail, M3, M4, M5)
   └─ generate_quality_suggestions(Q1_p, Q2, Q3, Q4, Q6, taste_model)

8. 构造并持久化 ChapterQualityReport
9. 返回
```

#### 3.9.3 触发时机

```
标准写章时序(实现3 编排引擎):
  章大纲(实现1) → assembleContext(实现4) → WritingAgent(实现2) →
  门槛1(一致性) + 门槛2(伏笔) + 内核3(反平庸) →
  人审/回流(工程4) → status="done" →
  evaluate(chapter, LITE)  ← 此处自动触发(同步,纯 SQL)

  可选(抽样章): evaluate(chapter, FULL)  ← 异步,含 LLM

卷级触发: 卷内所有章 done → evaluate(volume)
全书触发: 每 50 章 OR 人工 → evaluate(work)
人评触发: 卷完成后 → sample_for_human_eval() → 通知评分人
```

## § 6 · 失败模式与缓解

### 6.1 门槛崩坏场景

| 失败模式 | 触发条件 | 缓解策略 |
|---|---|---|
| **M1 断崖** | 单章 M1 < 0.60 或连续 5 章 < 0.75 | 触发 FULL 模式 + 人工审查警告;阻止下一章继续生成直到修复 |
| **M2 爆炸** | M2_total 单章 ≥ 5 | 标记章为 reviewing;在 WritingAgent prompt 中激活全量一致性约束 |
| **M3 伏笔黑洞** | M3 < 0.30 且章序 > 100 | 在规划 prompt 强制插入"伏笔回收专章"约束;向作者推送积压清单 |
| **时间线崩溃** | M4 连续 3 章 ≥ 3 | 规划层调用 TimelineEvent 全量检索,生成时序核查清单注入 prompt |

### 6.2 价值崩坏场景

| 失败模式 | 触发条件 | 缓解策略 |
|---|---|---|
| **Q1 AI 腔失控** | Q1_personalized 均值连续 5 章 > 3.0 | 检查 TasteModel 注入是否生效;检查内核3 AntiSlop 阈值是否配置正确 |
| **Q3 北极星漂移** | Q3 均值连续 5 章 < 2.0 | 加强 AuthorIntent 注入权重;触发内核1 "意图重确认"交互 |
| **Q2/Q4 长期不提升** | PREMIUM 档多轮评改后仍不改善 | 触发内核3 VariationEngine 强制风格变奏;或升级 critique 模型 |
| **Q 系列与 H 系列严重背离** | \|r(Q4, H1)\| < 0.20 | 记录校准异常;强制触发下一卷额外人评样本(20%);审查 TasteModel 个性化锚点 |

### 6.3 百万字特有失败模式

| 失败模式 | 说明 | 缓解 |
|---|---|---|
| **指标历史过多导致查询慢** | 500 章 × 报告行 | 趋势曲线预聚合(每 50 章生成分段摘要);为 ChapterQualityReport 建 work_id + chapter_seq 复合索引 |
| **LLM 扫描成本失控** | FULL 全量 500 章 ≈ 200 万 token | 严格限制 FULL 仅用于抽样章(约 50 章);LITE 做日常全覆盖 |
| **人评积压** | 卷尾触发但评分人无暇 | 72 小时窗口;超时用历史 H 均值插值;标记 "missing" |
| **崩坏基线缺失** | 前 10 章无对比基准 | 前 10 章数据仅存储,不产出趋势判断;明确标注 "数据积累中" |
| **Q 系列覆盖不足** | LITE 档章节无 Q2/Q3/Q4 | 报告中标注 "q_series_available=False";价值评级上限 B,标注 "代理估算" |

### 6.4 指标固有局限

- **M1** 依赖门槛1 的 ConsistencyFlag 质量:门槛1 漏报 → M1 虚高。缓解:定期 FULL 模式补充 LLM 扫描
- **Q7** 是代理指标,非真实追读率。缓解:报告中永远标注"预测分",不对外声称"追读率 X%"
- **Q6** 依赖 payoff_beats 正确标注:漏标 → Q6 偏低但正文实际有爽点。缓解:ExtractAgent 后处理补充 payoff_beats 抽取;若召回率 < 60% 改用 LLM 全章扫描
- **H 系列** 校准来自作者自评:单人视角偏差。缓解:支持 beta_reader 多人评分;区分 eval_source 统计

## § 9 · 反模式(严禁行为)

### 9.1 严禁引用外部"模型错误密度排行"

> **铁律**:禁止引用任何"GPT-X 的错误密度为 Y/万字"或类似模型排行榜作为系统选型依据或质量基准。

原因【已核实,调研文档 §1.1,投票 0-3 剔除】:此类排行在自有语料跑通之前无效;不同语料、不同检测工具、不同评判标准会产生完全不同的排名。引用此类数据只能产生误导性的"质量感"。

> 唯一有效的比较基准:同一个作品、同一套指标体系在不同章节/阶段的纵向对比。

### 9.2 严禁混并"对"与"好"为单一综合分

门槛轨和价值轨的得分不应被合并成一个 `overall_score`。原因:
- 一章可能"对"但"平"(M1=0.95, Q4=2.0)——没有 AI 腔但毫无质感
- 另一章可能"有缺陷"但"精彩"(M1=0.78, Q4=4.2)——有几处瑕疵但情感震撼

合并后两者得分相近,报告失去区分能力。**报告界面始终双轨分栏展示**。

### 9.3 严禁以机器指标替代人评

Q 系列是代理量。在任何公开声明中:
- 不说"本系统文学质量达到 X 分"
- 不说"AI 腔被消除"
- 只说"Q1 个性化密度降低至 X/千字(自建基线),需人评校准"

人评(H 系列)是唯一的"真值锚",哪怕样本很少。

### 9.4 严禁固化"通用文学标准"

任何"这样写是好的"的陈述都必须来源于 TasteModel,而不是系统的硬编码判断。不同作者的 Q4/H1 阈值可以不同。若系统某处硬编码"show_not_tell ≥ 0.7 = 好",且没有被 TasteModel 覆盖和可配置,则该处为设计缺陷。

## § 10 · 开放问题

1. **M1 与 H1 的真实相关性**:积累 50 章人评后检验 \|r(M1, H1)\|。若 < 0.30,需重新设计 LLM 连贯性扫描 Prompt 或重新思考 M1 的定义。

2. **Q4(文字质感综合分)的稳定性**:内核3 的 CritiqueAgent 对同一文本的评分稳定性如何?连续两次调用的结果方差有多大?若方差过大,Q4 不可信。需要在 MVP 期做稳定性测试(多次重跑同一章)。

3. **Q7 非线性问题**:Q7 使用线性加权,但追读率与各代理指标的真实关系可能是非线性的(如钩子强度有阈值效应:弱钩子效果差不多,中/强钩子效果有断层)。若积累 100+ 章人评后线性模型 R² < 0.3,考虑换 GBDT 或分段线性。

4. **崩坏曲线的收敛性**:自建崩坏曲线需要多少章才有统计意义?理论上 ≥ 50 章。在此之前所有趋势判断应标注"数据积累中"。建议在第 20 章、50 章、100 章分别回顾一次曲线形态是否稳定。

5. **payoff_beats 的自动抽取可靠性**:Q6 依赖 payoff_beats 正确标注。需评估 ExtractAgent(或规划 Agent)在不同类型作品上的召回率。目标 ≥ 70%;若低于此,Q6 需改用 LLM 直接全章扫描。

6. **人评个性化锚点的有效性**:TasteModel 生成的 H 系列个性化评分描述(§3.4.3)是否真的提升了评分一致性?建议在积累多次人评后,比较"有锚点"与"无锚点"条件下同一作者对同一章的评分方差。若无差异,锚点设计无效,需重新考虑。

7. **多人评分的聚合策略**:若同一章有多位 beta_reader 评分(H 值分布有方差),应使用均值、中位数还是加权(作者评分权重更高)?当前设计默认均值,未处理离群值。

8. **百万字报告存储规模**:500 章 × 双轨报告 ≈ 500 行;崩坏率曲线两条各 500 点 JSONB。当 > 300 章时,建议将 m1_trend/q1_trend 等 JSONB 数组拆出独立表 ChapterMetricHistory,避免单行 WorkQualityReport 过大。

9. **Q 系列评估与内核3 质量档的协调**:Q2/Q3/Q4 依赖内核3 的 CritiqueReviseResult。若内核3 出于成本控制只对 20% 章节运行完整评改,则 Q 系列大量缺失。工程层需对此场景有明确的降级方案(报告中标注 q_series_available=False,且价值评级上限 B)。

10. **TasteModel 版本对历史报告的影响**:TasteModel 更新后(version+1),历史章节的 Q1_personalized / Q4 会变化。报告中的 taste_model_version 字段保存了生成时的版本,但不会自动重算历史报告。需要明确策略:是否允许"用新 TasteModel 重算历史 Q 系列"作为可选操作。
