# 对话驱动写入 · 禁止表单直填（产品铁律）

> **日期**：2026-07-22  
> **状态**：已采纳，待分批落地  
> **废止/修正**：`scribe3/AGENTIC_BOUNDARY_DECISION.md` 中「作者经前端 REST 直编世界状态」作为**作者主路径**的表述；REST 直写降级为 **dev/emergency 后门**，默认 UI 不可达。  
> **目标心智**：真人只做三件事——**说**（和主编讨论）· **批**（批准/拒绝写入提案）· **选**（正文提案接受/弃用/再议）。**不填业务表单。**

---

## 1. 产品铁律

| # | 铁律 |
|---|------|
| L1 | 凡需作者在表单里填写**作品语义数据**（设定/北极星/大纲/节拍/演绎/伏笔/关系/卷章元数据/synopsis 等）= **缺陷**，必须改成对话驱动 |
| L2 | 落库唯一作者可见路径：`讨论 → 结构化提案 → 人批一次 → 写入` |
| L3 | 设定库 / 大纲 / 看板 = **只读检视 + 跳转对话**，不是编辑器 |
| L4 | 正文：只认「提案卡接受」；禁止把「表单式正文编辑」当主路径（局部润色可保留选区→让主编改） |
| L5 | 验收时出现「只能手填才能完成意图」→ **P0/P1 停写修**，不得当 workaround |

### 允许保留的「非业务表单」（白名单）

仅系统/工程配置，不算创作语义：

- 作品库：新建书名（可改为对话「开一本书叫…」二期）
- 设置：API Key、网关、主题、权限
- 审批卡片上的 **批准/拒绝**（决策控件，非填字段）
- 搜索框（查询，非写语义）

除此以外，**全部表单直写 = 待灭缺陷**。

## 2. 与旧决策的关系

旧 R3 决策（甲）：

- agentic 只读  
- **作者 REST 直编**（全权）  
- MCP 写需 elicitation  

**问题**：甲把「表单直填」合法化了，与内核1「人只想象+意见」冲突，也与本次产品方向冲突。

**新决策（乙·作者面）**：

```
作者面主路径:
  自然语言意图
    → 主编 (Hermes Run / write-tools)
    → 批量结构化 WriteProposal（字段级 diff）
    → 单一审批 UI（可展开每条变更）
    → commit_if_approved / _execute_write
    → 只读面板刷新

作者面禁止:
  CodexDetail 失焦保存、CodexNew 多字段表单、
  ChapterMetaPane 手改、NorthStar 手改 intent、
  卡片墙手改 synopsis、节拍/演绎 textarea 直存…
```

后端 REST 可暂留供测试与迁移；**前端创作 UI 默认卸载写入口**。

## 3. 目标交互（作者看到什么）

### 3.1 讨论 → 提案包（核心）

作者：

> 「主角沈砚：候潮匠，Ghost 是…，和季棠是盟友，从第 2 章起。再把书的北极星定为…」

主编：

1. 只读工具核实现状  
2. 生成 **WriteProposal**（可多对象）：

```json
{
  "summary": "登记角色沈砚、关系、更新北极星",
  "ops": [
    {"tool": "s3_add_character", "args": {...}, "label": "新建角色·沈砚"},
    {"tool": "s3_set_char_anchors", "args": {...}, "label": "弧光锚"},
    {"tool": "s3_add_character_relation", "args": {...}, "label": "沈砚→季棠·盟友"},
    {"tool": "s3_set_intent", "args": {...}, "label": "北极星"}
  ]
}
```

3. UI 展示提案卡：每条可读中文 + 展开 JSON；底部 **全部批准 / 全部拒绝 / 逐条剔掉**  
4. 批准后原子或尽最大努力写入；失败条目标红可重试  
5. 成功后自动打开只读设定页「刚写入的对象」

### 3.2 正文仍走提案卡

不变：`/chat/write` → proposal → 接受。  
意见改稿：选区/整章 → 主编再提案。

### 3.3 看板/设定页的新行为

点击「编辑」或空字段 **不再出 input**，改为：

```
[让主编补全] → 预填一条对话
「请根据本书上下文，为角色季棠补全外貌与弧光锚，并提交写入提案供我批准。」
```

空状态文案统一：

> 与主编讨论后批准写入；此处只读。

## 5. 工具面缺口（MCP 须补齐才能灭表单）

现有 `WRITE_GATED` 已覆盖角色/事实/事件/伏笔/规则/势力/物件/术语/关系/声线等，**缺**或需确认：

| 能力 | 建议工具 | 优先级 |
|------|----------|--------|
| 书级北极星 | `s3_set_intent` | P0 |
| 建卷/改卷 | `s3_add_volume` / `s3_patch_volume` | P0 |
| 建章/章元数据 | `s3_add_chapter` / `s3_patch_chapter_meta` | P0 |
| synopsis / beats / scene_truth / deductions | `s3_patch_chapter_plan` | P0 |
| 弧光锚 | `s3_set_char_anchors`（若无则补） | P0 |
| 母题 CRUD | `s3_add_motif` / `s3_patch_motif` | P1 |
| 素材 | `s3_add_material` | P1 |
| 批量提案 | `s3_propose_writes`（可选：服务端聚合） | P0 UX |

写工具一律：`commit_if_approved` + 前端 **统一 WriteProposal 卡**（Hermes approval 与 MCP elicit 体验对齐）。

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 每改一个字段都审批，烦 | **批量提案**一次批多 op；「信任本线程」可选（后置） |
| 模型填错字段 | 提案卡可读 diff；拒绝后自然语言纠正再提案 |
| 无网关时完全不能写 | 设置页显式「紧急直写模式」（默认关，写审计日志） |
| 测试依赖 REST 直写 | 测试用 header / dev flag，不进作者 UI |
| 旧书数据 | 只读展示不受影响；改则走对话 |
