# 遗留风险处置方案(以系统最佳效果为目标)

> 输入:《总验收报告》第四节 12 条遗留。排序准绳:**对"写出乱世铜炉级长篇"的边际收益**,不是工程洁癖。
> 核心判断:12 条里真正影响写作质量与可靠性的是 3 件事——**修复环的语义覆盖缺口(#1)、检测器校准回路(#7/#11)、真实丢稿场景(#3)**;其余是卫生项或择机项。另有 1 项 12 条之外的高杠杆追加(时间线检测器第一刀,来自 ConStory 对照结论)。

## 批次一 · 安全网与语义补全(最高杠杆,约 1 天,建议立即执行)

### 1-A. S1 判据接线 + 三重防误杀(遗留 #1,本方案的主菜)

**为什么第一**:现在 blocking 四判据只有三条活着(泄密/退化/AI 味 heavy)——全是"文本统计+结构查询"能抓的。而长篇真正致命的语义级硬伤(知情者整段交底、双高潮、解说倾泻、声音崩)恰在 LLM 纪律判的地盘,S1 不接线,修复环对这类硬伤只能干看着出 advisory。这是修复环覆盖面的最后一块缺口。

**接线设计**:
1. `/post-check` 的 discipline 段(LLM 纪律判)输出走既有 `normalize_findings`(方案B任务18,已在库未接线)统一成 FindingsSchema,severity 进 `issues[].meta.severity` —— triage 判据④即刻激活,零改 loop。
2. **防误杀三件套**(蓝图第六章"误报重写毁好稿"是明列风险,LLM 判假阳性≠确定性检测):
   - **降档默认**:单次纪律判给出的 S1 一律降为 S2(advisory);
   - **共振升格**:仅当"LLM 判 S1 且 确定性信号同向命中"(如判知识泄露且 find_god_view/find_leaks 亦中,判解说倾泻且 oversaturation 亦中)才保留 S1 → 进 blocking;共振表≤5 条硬编码,可审计;
   - **强制观察**:被 S1 触发回炉的章自动优先进盲评池A(journal 已有 verdict 留痕,免费)——检测器错杀由人裁,数据回流校准共振表。
3. 熔断阈值:上线后前 10 个真实章,若 S1 触发回炉率 >30% → 自动把共振升格也降为 advisory 并在面板告警"S1 门槛待人工复核"(宁可漏,不可磨)。
4. 测试:构造共振 S1 → blocking;单判 S1 → advisory;熔断路径。真机:loop-qa 构造"知情者整段交底"章走一次回炉。

### 1-B. 防真实丢稿(遗留 #3 的高频半边)

loop/选择环是数分钟长请求,你等不及手改正文是必然发生的场景:
- 后端:`POST /save-chapter` 入口查 `_loop_inflight`,同章在途 → 409"本章生成在途,完成后再存(你的编辑不会丢,请先复制)";
- 前端:`s3-live` 广播已有,WriteLayout 监听在途状态显示只读横幅"生成在途"。
(settle 与 PATCH 登记的 CAS **不做**——窗口毫秒级、单用户形态、代价是全链加版本号,收益不成比例;维持台账记录。)

### 1-C. 五个顺手小项(合计 <1 小时)

- **#12** `build_regen_constraints` 头部加一句:"以下约束优先级高于本轮用户指令与大纲中与之冲突的部分;若根本冲突,宁可留疑而不违规"(一行,治大纲与检测器打架)。
- **#2** loop 端点复用选择环的 `.result.json` 模式,每次 loop 把 rounds(含 blocking 明细)落 journal 旁——审计与池A的"为什么"单文件可查。

## 批次二 · 校准回路与效率(约半天,批次一验证后执行)

### 2-A. 盲评池A 扩 needs_human 观察模式(遗留 #11 的升级)

现状池A只收"回炉且过审"章,而 **needs_human 章才是检测器假阳性的富矿**(三稿全被拦,拦得对吗?)。扩池A2:journal 含 needs_human 的章,样本=版本库三稿并排+一问"这三稿真的都不行吗?有可用稿即说明检测器过严,引原文"。key 记 blocking 原因分布。这一条与 1-A 的强制观察合流,构成**检测器校准的完整人工回路**——系统长期效果的关键,因为检测器阈值的天花板不在代码在标定。

### 2-B. 短文本置信度警示(遗留 #7 止血半边)

<500 可见字的稿,ai_grade 密度类 Gate 置信度低(P2 真机:400 字三候选全灭)。止血:post-check 响应对短文本加 `short_text_low_confidence: true`,triage 对**仅由密度类 Gate 构成的 heavy**在短文本上降为 advisory+标注。阈值曲线的正式标定(批次三)要等真实短章数据,不拍脑袋。

### 2-C. 增量蒸馏(遗留 #6 的可行半边)

`distill_marker` 已存消息数——改为只喂**上次标记之后的新增对话**(教训天然是增量的,软去重兜住重复),长会话的蒸馏 prompt 从 3 万字级降到增量级。judge 的轮内裁剪**不做**(需预知终轮,复杂度>收益,量控账已可见)。

### 2-D. 两个性能卫生项

- **#4** 一次性 EXPLAIN 实验:`<|K,COSINE|>` vs `<|K,EF|>` 对拍 plan 与召回一致性;确认 brute force 则改 4 处查询(行为敏感,须对拍后换)。
- **#5** `north_star_book` 改窄字段查询(SELECT 不拉 prose/embedding),面板在几百章时不卡。

## 批次三 · 择机项(有窗口才做,不阻塞写作)

- **#9 Hermes 升级演练**:迁移清单已在《底座对表结论》。触发条件二选一:①你有半天不写作的空窗;②scribe3 下一个功能真的需要上游新能力(subagent fan-out 等)。按协议 3-5 步:backup→非生产 profile 演练→钉死 restart_drain_timeout/stale_timeout 两处默认变化→doctor+三条 e2e+全量 pytest→金丝雀一章。任一回归即回滚 v0.17.0。
- **#7 后半**:密度阈值按短文本标定(需 2-B 攒的真实数据)。
- **#8 后半 + 追加项(12 条之外,ConStory 对照的明确结论)**:检测器扩展第一刀——**结构化时间标记检测**(更次之外扩日期/季节/月相,单调比对)+ **事件三元组同时性查询**(event 已有 story_time/location/participants,同刻双地=纯结构查询,近乎免费)。这是当前确定性检测最大裸奔区(Timeline 大类 6 子类仅 2 窄点),论文自证时间维是长篇错误重灾区——**若只追加一件事提升系统效果,是这件**。

## 明确不做(及理由)

1. settle/PATCH 的 CAS 并发控制——毫秒级窗口、单用户、全链版本号代价大。
2. judge 轮内裁剪——需预知最终轮,复杂度>省下的 LLM 调用。
3. 池A暂空的"催熟"——等第一个真实"回炉后过审"章自然出现,不为凑数据造章。
4. 短文本密度阈值的立即改动——无标定数据前动检测器核心口径=拍脑袋,先警示后标定。

## 验收与守则

- 每批完成:全量 pytest 绿 + 相应真机证据(1-A 要一次语义硬伤真机回炉;2-A 要一次含 needs_human 章的盲评包导出)+ 沿用对抗审查(批次一因动 triage 判据,**必须**过一轮独立审查)。
- 宪法不动:S1 是严重档不是分数,共振升格是收紧不是放宽;所有新阈值(共振表/熔断 30%/短文本 500 字)进台账并在面板/响应标注"自定口径"。
- 预计总工时:批次一 ≈1 天、批次二 ≈0.5 天、批次三择机;全部走既定 DoD(TDD/全量/审查/真机)。
