# GOAL: 写作方案强制闭环 · 门槛满配 · 内核反平庸注入

**代号：** `scribe3-authoring-closure`（亦称 northstar-v3-enforcement）  
**一句话：** 把「充分使用 Scribe 写出好小说」从可选最佳实践，变成**默认强制的单章/卷闭环**；抬升结构与限知**下限**到生产可辩护；**不宣称**系统自动保证文学**上限**。

---

## 0. 北极星语境与继承关系

### 0.1 作者终局语境

最终目标仍是：让作者能写出**乱世铜炉级**长篇。本 goal **不**承诺「系统自动写出好小说」，只承诺：

- 默认路径下**坏稿可拦、世界可审计、伏笔可追踪、回写默认发生**；
- 作者在抬高的下限之上做裁决与文学终审。

### 0.2 继承（extends）

| 上游 | 关系 |
|------|------|
| `2026-07-05-北极星goal全文.md` / 精简版 | **宪法与三环（修复/选择/沉淀）**全部继承；已落地能力不重造 |
| `2026-07-04-北极星-KR-Loop结合scribe3设计方案.md` | 实施细节事实源之一 |
| 2026-08 能力审查结论 | 增量范围的依据：强制化 / 生成注入 / 覆盖与度量缺口 |

**已具备（验收时勾选「继承」、勿重复造轮）：** 限知 `project_frame`、写门控 `WRITE_GATED`/`commit_if_approved`、伏笔 plant/advance/超期、双层 QC、`_enqueue_ingest`、loop 三分流（若代码已合入则锁回归测试）。

**本 goal 增量（必须新建或补齐验收）：**

1. **强制化**——默认写路径门闩，旁路显式危险；  
2. **生成时注入**——兑现内核3「默认目标函数」的**最小生产集**；  
3. **覆盖与度量**——ConStory 确定性补检、scorecard/面板、选择环、母题卷复盘、ingest 失败可观测。

### 0.3 禁止的 goal 措辞

验收报告、进度、对外说明中**禁止**：

- 「完美解决一切」  
- 「确保输出高质量小说」  
- 「系统已自动写出好小说」  

允许：「下限生产级」「默认闭环」「可审计」「坏稿可回炉」「作者终裁上限」。

## 3. 宪法条款（任何调研与实现不可推翻）

### 3.1 继承自北极星

1. **不造总分**；rubric / fulfillment **永不进入 blocking**。  
2. **advisory 永不自动重写**（保护作者声音）。  
3. **蒸馏升格永不自动生效**（必须待批）。  
4. **regenerate 复用完整 chat_write / 等价组装链**（禁止缩水 prompt 复跑）。  
5. **停机 / blocking 判据只挂确定性项**（及已文档化的共振白名单；禁止裸 LLM 分）。  
6. **生产作品数据只读**；真机验证仅 `work=loop-qa`（或本 goal 专用测试 work，须记台账命名）。  
7. schema/底座变更前 **surreal export 备份成功**才继续；禁破坏性删库。

### 3.2 本 goal 新增

8. **默认写章路径 = 强制闭环**（post-check → triage → 必要时回炉 → 人/pass 后落库 → ingest）。「快速草稿 / 危险旁路」必须**显式开关**且 UI/API 标危险；默认配置下不可静默绕过。  
9. **不得宣称系统确保好小说**；验收与产品文案仅限「下限 + 可审计 + 可回炉 + 作者终裁」。  
10. **ingest 失败必须可观测、可重试、不可静默当成功**（API + UI 角标/面板至少一处）。  
11. **检测降级不得假绿 pass**（`degraded_stages` / `leaks_degraded` 时最高 advisory）。

## 4. 完成定义（Done）= 门 A + 门 B + 门 C

### 门 A · 方案闭环默认生效（产品）

在**不打开危险草稿**的默认配置下，作者走 UI 或主编主路径写一章：

| # | 行为 |
|---|------|
| A1 | 必经 post-check（或文档声明的等价检测链） |
| A2 | blocking → 自动回炉 ≤2 轮，或 `needs_human`；**禁止一键 final** |
| A3 | pass 或人批后才落 final prose |
| A4 | 自动 enqueue ingest；成功/失败状态清晰 |
| A5 | 校验面或交付卡可见：知识帧摘要 / 伏笔 / QC 摘要至少两类 |

**证据：** loop-qa journal + curl/截图；旁路开关有自动化测试。

### 门 B · 审查缺口关闭到生产可辩护（工程）

下列每条均有 **代码 + 测试 + loop-qa 证据**（详见 §5 KR）：

| 缺口 | 完成标准 |
|------|----------|
| 绕过 loop 乱存 | 默认禁止无检 final；或 final 强制 post-check |
| 生成时反平庸 | 组装链注入：北极星 intent + 本章代价/purpose + open promises top-N + anti-slop/craft 约束（可配置关闭仅测试用） |
| 母题闭环 | 可登记；brief/plan 可引用；卷级「未回响」可查询告警 |
| 隐性伏笔 | 不要求全自动发现；须有「候选待批 plant」或作者确认 plant 流程 |
| ConStory | 对照表更新；确定性可检类较基线 **+≥3** 且进 post-check 或 health |
| 体检 | health：因果 + 伏笔超期 + **至少一项**风格/声音漂移 proxy 或 ingest 失败积压 |
| lesson | 挂 ingest 成功路径；brief「上章复盘」；升格 craft 待批 |
| 目的合同 | 章 purpose + deltas；fulfillment **仅 advisory**；carried 滚章 |
| 选择环 | 关键章 3 候选 + 确定性过滤 + 人终选 + 理由入 lesson |
| 度量 | 书级 scorecard 四维只自比、无总分；面板可读（SSE 优先） |

### 门 C · 诚实边界（文档 + 文案）

- 总验收报告专节：**系统不保证的文学维度清单**  
- 作者大白话**七步用法**（对齐单章闭环）  
- 全文禁止 §0.3 禁用措辞

## 5. 关键结果 KR

### KR1 · 默认路径不可绕过（包 0）

- [ ] 关闭草稿模式时，final/定稿入口 **100%** 触发 post-check  
- [ ] 种泄密词构造 blocking：回炉 ≤2 后新稿无该泄密；仍 blocking → `needs_human` 且 **不进 final**  
- [ ] 构造 advisory：**零自动改写**  
- [ ] 干净章 pass → ingest 成功且至少 1 条知识变化可查  

### KR2 · 生成时注入（包 1）

- [ ] chat_write / 渲染组装链可证明注入段存在（单测断言 prompt 片段）  
- [ ] 注入内容至少含：intent 北极星摘要、open_promises（top-N≤5）、anti-slop/craft 约束；有 purpose 时含 deltas  
- [ ] 真机开/关注入各一章，journal 可对比  

### KR3 · 回写与账本诚实（包 0–1）

- [ ] ingest 失败可观测 + 可重试 API/工具  
- [ ] 解析失败不错误 purge（回归锁）  
- [ ] 构造「章 N 目击 → 章 N+1 帧含新知」样例通过  

### KR4 · 伏笔 + 母题产品闭环（包 1–2）

- [ ] plant → advance → payoff/overdue 全路径 UI 或 MCP + 测试  
- [ ] 卷复盘：超期数、长期未 advance 数、母题未回响数可查询  
- [ ] loop-qa：≥8 promise + ≥3 motif 跑通  

### KR5 · 一致性覆盖提升（包 2）

- [ ] 更新 ConStory 对照表；确定性可检类 **+≥3**  
- [ ] 新检测器：假阳用例 + 降级路径测试；进入 post-check 和/或 health  
- [ ] 书级矛盾密度仅自比；文档声明不可对标外部 CED  

### KR6 · 作者体验与选择（包 2）

- [ ] 章级 scorecard 三分栏真数据（constraints / advisory_scores / fulfillment）  
- [ ] 书级四维无总分  
- [ ] 选择环真机 1 次：3 策略可区分 + 过滤生效 + 终选理由入 lesson  
- [ ] 前端 `npm run build` + 关键路径冒烟  

### KR7 · 回归与安全

- [ ] `cd scribe3 && python -m pytest` 基线只增不减  
- [ ] 假绿防护测试（降级不得 pass）  
- [ ] 生产只读与备份协议遵守；端口约定与 CURRENT 一致（API/前端以 README 为准）

## 7. 每任务 Definition of Done

1. **TDD**：先失败测试后实现；降级路径必测（检测器挂 → `degraded_stages` 如实，不假绿）。  
2. **`cd scribe3 && python -m pytest` 全绿**；涉前端 **`npm run build`**（禁止仅用 `tsc --noEmit` 当验收）。  
3. **规格自查**：对照本文 KR / 任务表列「要求 vs 实现」；偏离记台账。  
4. **对抗审查**：每包结束后独立找茬（丢数 / 假绿 / 绕过门闩 / 违宪 / migration 无回滚）；修完才过包门。  
5. **真机证据**：loop-qa curl/journal/截图贴进度文档。  
6. **commit 前缀**：`feat(closure):` / `fix(gate):` / `feat(inject):` / `feat(scorecard):` / `feat(motif):` / `docs(closure):` 等；一文一事。
