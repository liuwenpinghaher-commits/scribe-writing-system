# 主编主动化改造方案——Initiative 反转:作者只出想法,主编驱动全流程

> 目标一句话:**作者=创意总监(想法/意见/终选),主编=执行主编(规划→写→检→修→交付→反哺全流程主动驱动)**。
> 输入:PulseBar 前置分析(本文档吸收)+ 全网调研六路(文末来源)+ scribe3 现状(北极星三环/工艺引擎/检测器栈全量在线)。
> 宪法继承不放宽:终选留人、蒸馏升格待批、advisory 永不自动重写、停机判据只挂确定性项——本方案把它们升格为「授权矩阵」的锚点,而不是绕开。

## 一、调研锚定(为什么这样设计)

1. **现有工具的共同局限=executor 模型**:响应命令,不主动参与探索性协作(CHI 2026 proactive AI;CoFI 框架把"主动性时机"列为协作第一轴)。Sudowrite/NovelCrafter 至 2026 仍是"作者点一下、AI 做一步",没有自主推进的章生命周期——这正是差异化空间。
2. **学界多 agent 写作管线已收敛**:Agents' Room(ICLR'25)=planning agents+writing agents+orchestrator+共享 scratchpad,人评全维碾压端到端;StoryWriter(2025)=outline/planning/writing 三 agent。**scribe3 的对应件全部已建**(大纲/节拍/演绎=planning,chat_write+loop=writing,简报=scratchpad,北极星三环=质量闭环)——缺的只是 **orchestrator 的"驱动器"**:现在每步靠作者点按钮。
3. **主动时机的 HCI 结论**(CHI 2025 proactive programming support / ProMemAssist / 中断成本建模):打断要落在**自然断点**(子任务边界),不打断专注中的主任务;主动行为必须**解释为什么**;主动帮助有"威胁感"反噬风险→需可静音、可否决。
4. **监督会衰减**(confirmation frequency 建模研究):会话越长,人工检查越稀疏→**检查点必须制度化**(状态机停靠),不能靠作者自觉;HITL→HOTL 的升级应由**放行数据驱动**(连续高通过率的步骤才降级为自动)。

## 二、总架构:感知 → 决策 → 执行 → 汇报

```
┌─ 感知层 ─────────────────────────────────────────────┐
│ /chapter-pulse 聚合(伏笔/弧光/关系/张力/因果/质量)   │ ← 全部复用既有信号,零新检测器
│ + 书级 pulse(北极星四维趋势)                         │
└──────────────┬───────────────────────────────────────┘
┌─ 决策层 ─────▼───────────────────────────────────────┐
│ Chapter Pilot(章生命周期状态机)+ 授权矩阵(三档)     │ ← 本方案唯一的"新引擎"
│ + 主动开口时机引擎(进章/落稿/对话注入/卡文)          │
└──────────────┬───────────────────────────────────────┘
┌─ 执行层 ─────▼───────────────────────────────────────┐
│ 全部既有能力:大纲/节拍生成·演绎三投影·loop 回炉·      │ ← 零新造,纯编排调用
│ 选择环·全量体检·dedup·ingest·蒸馏·简报组装            │
└──────────────┬───────────────────────────────────────┘
┌─ 汇报层 ─────▼───────────────────────────────────────┐
│ 决策收件箱(等作者的事,一处集中)+ 工作日志(主编做了   │
│ 什么/为什么/依据哪条信号)+ 交付卡                     │
└──────────────────────────────────────────────────────┘
```

## 三、核心机制

### 3.1 Chapter Pilot——章生命周期状态机(新模块 `pilot.py`)

```
idle → outline_proposed → beats_ready → deduced → drafting(loop) → checked → delivered → finalized
        [propose]           [auto]      [auto]      [auto≤2轮]      [auto]    [propose]   [approve]
```

- 每个状态迁移=调用一个**既有函数**(生成大纲=chat_write(phase=plan)、演绎=deduce 生成链、草稿=run_chapter_loop、体检=post_check、交付=留版+交付卡)。
- 迁移完成后按**授权矩阵**决定:自动推进,还是停靠等作者。
- 停靠点=调研说的"自然断点":章与章之间、阶段与阶段之间——绝不在作者正打字时弹任何东西。
- 失败路径如实停靠:loop needs_human / 体检 decision 级 → 进决策收件箱,不硬闯。

### 3.2 授权矩阵(三档,可按书配置,宪法锚硬编码)

| 档 | 语义 | 默认覆盖 | 依据 |
|---|---|---|---|
| **auto**(human-on-the-loop) | 做完记日志,可事后追认 | 节拍细化、演绎三投影、loop 回炉(≤2轮)、全量体检、dedup、ingest、蒸馏、简报组装 | 可逆、已有质量闭环兜底 |
| **propose**(轻确认) | 产出进决策收件箱,作者可改/放行;**连写模式**下自动放行 | 大纲提案、章稿交付(交付≠定稿) | 品味决策但可逆 |
| **approve**(hard HITL,宪法锚) | 永远等人,任何模式不放行 | 终选定稿、蒸馏升格、伏笔弃置/红鲱鱼、设定圣经变更 | 不可逆或本体级 |

- **连写模式**:作者显式说"连写到第 N 章"才进入;期间 propose 级自动放行、approve 级照停;每章交付卡照发(事后可追认/回滚到版本库任一稿)。**不做超时自动放行**——沉默≠同意,写作是品味活。
- **自治升级数据环**(P2):某 propose 步骤连续 5 章零修改放行 → 主编**建议**降为 auto("这步你从没改过,要不要我以后直接过?"),切换权永远在作者。

### 3.3 想法收件箱(Idea Inbox)——作者唯一的输入负担

作者随时丢一句话("下一章让哑姑第一次开口,在井边"/"老范太懦弱了,加点脾气"),主编负责**路由**:
- 涉未来章 → 改该章大纲提案/写进 steer;
- 涉人物长期设定 → 提案改 arc_plan/性格锚(approve 级,因为动设定圣经);
- 涉已写章 → 提案定向修订(span 级,修订纪律已有);
- 模糊 → 主编先复述理解再问一句(只问一句)。

### 3.4 主动开口时机引擎(吸收 PulseBar 前置方案)

- **时机 A|进章**:有 decision 级才开口,一条(伏笔超期三选一/弧光跳变…)。
- **时机 B|落稿后**:体检有 nudge+ → 摘要+"要我修吗"(接既有"让主编修这章")。
- **时机 C|对话注入**:pulse 摘要进**讨论模式** instructions(现在只有写作模式有简报)——聊大纲时主编自然带出"这章按计划该埋第二根刺"。
- **时机 D|卡文**(并 M9):检测"久未落字/删多写少"→ 问一句"卡住了?情节卡/语言卡/心态卡,聊聊?"(纯话术,零表)。
- **防烦协议**:每章每维度最多主动开口一次;nudge 只在 PulseBar 变黄不说话;维度可静音;每次主动行为必须自带一句"因为…"(调研:解释性消解威胁感)。

### 3.5 汇报层

- **决策收件箱**:所有等作者的事项一处集中(propose 停靠+approve 待批+decision 级 pulse),右栏新 tab,有徽章计数——替代"散落七个面板找待办"。
- **工作日志(Captain's Log)**:主编每个 auto 动作一行:`[第10章] 演绎已生成 3 投影(依据:涉及角色 3 人)`——复用 pipeline_journal 底座,前端可折叠查看。透明度是 on-the-loop 的前提。
- **交付卡**:章稿交付的标准形态=正文+体检摘要+本章兑现/新埋伏笔+"我拿不准的 N 处"(主编主动暴露低置信段,调研:置信度校准)。

## 四、典型流(作者只出想法)

> 作者(Inbox):"第10章:哑姑第一次开口说话,在井边,别煽情。"
> 主编:大纲提案 →(作者放行/连写模式自动)→ 节拍→演绎三投影→loop 草稿(回炉1次,泄露拦截自动修)→体检绿→**交付卡**:"1980 字,QC 干净,『赎骨钱』伏笔本章兑现;第三段哑姑开口的那句我写了两版,拿不准哪版更冷,标在文中。"
> 作者:挑一版,改两个字,终选(approve)。
> 主编(auto):ingest→蒸馏→relation_touch 更新→发下一章大纲提案。循环。

## 五、实现映射(几乎全是接线)

| 件 | 落点 | 量 |
|---|---|---|
| /chapter-pulse 聚合 | app.py 新端点,复用 brief/tension/北极星/QC 产出 | 0.5d |
| PulseBar+弹层(含压力级 sparkline/关系冷热) | web 新组件,挂 NorthStarBar 位 | 0.5d |
| 时机 C 讨论注入 | ChiefDock instructions 拼 pulse 摘要(一处) | 0.1d |
| Chapter Pilot 状态机+授权矩阵 | 新 pilot.py+/pilot/* 端点;状态落 chapter 字段;宪法锚硬编码 | 1.5d |
| 想法收件箱+路由 | 后端 idea 表+主编路由 prompt;前端 ChiefDock 输入框升级(本就是对话框,加"收到→路由结果"回执) | 1d |
| 决策收件箱+交付卡+工作日志 | 右栏新 tab;journal 扩展 | 1d |
| 时机 A/B/D+防烦协议 | ChiefDock 开场白注入+localStorage 静音 | 0.5d |
| 连写模式 | pilot 队列循环(BackgroundTasks 链或 Hermes cron 二选一,倾向后端自链,cron 留给夜间体检) | 0.5d |

**分期**:P0=感知+汇报+时机(1.5d,立刻可感知"主编活了");P1=Pilot+授权矩阵+Inbox+连写(3d,达成"一句想法→一章交付");P2=自治升级数据环+多章连写节律+盲评池联动(观察后)。
**验收**:①loop-qa 真机:一句想法→交付卡,中途零人工;②《纸命》第5章用此流程写作并达标(4.3+);③防烦:全流程主编主动开口≤4 次/章。

## 六、风险与不做

- **不做**:全自动定稿(宪法)、超时视为同意、每轮对话都插提醒、并行多章同写(先单章链稳)。
- **风险①主动性反噬**(调研实证:proactive 可被感知为威胁/打扰):对策=解释性("因为…")+静音+连写模式显式 opt-in。
- **风险②监督衰减**:连写越久作者越不看交付卡 → 对策=交付卡强制含"拿不准的 N 处"(把注意力引到刀刃)+每卷末强制一次盲评包节律。
- **风险③成本**:连写=连续 loop,LLM 日帽(SCRIBE3_DAILY_CALL_CAP)已接线为硬保险丝;pilot 每章记 token 账进日志。
- **回滚**:pilot.py+端点独立,REMOVE 即净退;所有自动产物走版本库,任意稿可恢复。
