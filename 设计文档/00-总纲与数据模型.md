## 1. 系统的第一性定义:一个协作回路

Scribe 不是"AI 写小说的系统",也不是"写作软件"。它是**一个把作者的稀缺输入(想象 + 意见)无损放大成一本好小说的回路**:

```
        ┌──────────────────────────── 人(你)──────────────────────────┐
        │  ① 想象:出创意、指方向、"我想要…"                              │
        │  ③ 提意见:判断、反馈、"不对/更狠/选B"(从不亲手写正文)          │
        └───────────────┬───────────────────────────▲──────────────────┘
                        │ 想象/意图/意见                │ 选项 + 成稿 + 依据
                        ▼                              │
   ┌───────────────────────────── AI(全程主笔)──────────────────────────┐
   │  ② 实现一切:想象→大纲→卷→章→正文;关键处产出多方案;按意见重做         │
   └───────────────────────────────┬─────────────────────────────────────┘
                                    │
   ┌────────────────────────────────┴─────────────────────────────────────┐
   │  系统的三件事(回路得以成立的保障):                                      │
   │   A. 捕获并放大「想象 / 意图 / 品味」——保证 AI 写的是"你的书"            │
   │   B. 默认对抗「趋均值/AI 腔」——保证不滑向平庸(无人手在 prose 上兜底)    │
   │   C. 维持「连贯/一致/伏笔」——门槛,后台隐形运转,不打扰创作               │
   └────────────────────────────────────────────────────────────────────────┘
```

**一切设计服从这张图。** 评判任何模块只有一个标准:它是否让这个回路更快、更准、更"好"。

## 2.5 运行底座决策:基于 Hermes Agent,少写代码、多复用(详见 [工程8](工程8-HermesAgent复用方案.md))

经联网深度调研确认:**Hermes Agent(Nous Research,开源 MIT,Python)原生提供了主编所需的绝大部分能力**——编排主循环、工具自注册、SKILL.md 技能(含自主创建)、MCP 客户端/服务端、`delegate_task` 子 Agent(并行/可指定模型)、Cron 定时、8 种可插拔记忆后端、Docker/microVM 沙箱、6 类接入端(含 OpenAI 兼容 API、桌面端、消息平台)。且 Nous 官方有 **autonovel** 小说写作 pipeline 可直接参考。

**架构方针:Scribe 不自建 Agent 框架,而是把领域逻辑实现为 Hermes Agent 之上的"技能(SKILL.md)+ 轻量插件 + MCP 工具",最大化复用、最小化自写代码。** 自建的只有真正的业务层(稿件版本、设定/伏笔的专属 schema、小说专用编辑器面板、多本书/作品库逻辑)。**账号/鉴权由你自建,系统不做账号体系**,只消费一个 `owner_id` 边界。各模块文档的"详细设计"在落地时优先映射到 Hermes 原语(工具/技能/插件/delegate/cron/memory provider)。

**两项进一步复用(经核实,详见 [工程8 核实更新](工程8-HermesAgent复用方案.md)):**
- **存储/向量**:MVP 用 **SQLite + sqlite-vec**(复用 Hermes `qmd` 技能),**不起 PostgreSQL/pgvector**;规模化(>~50万向量/多租户)再迁,实现4 接口不变。§4.5 技术基线据此为"SQLite 优先"。
- **Chat UI**:**复用现成**(Hermes Desktop / Open WebUI 一键 / LobeChat 插件),只自建小说专用面板。

## 2.6 模块化与文件大小公约(避免巨型文件)

1. **一职一文件**:一个工具一个 `tools/*.py`;一个技能一个 `SKILL.md` 文件夹;一个插件一个目录。借 Hermes 的自注册/插件模型天然保持小文件。
2. **源码软上限 ~400 行 / 硬上限 ~600 行**:超过即拆分(按职责,不按行数硬切)。前端组件同理,避免巨型组件。
3. **设计文档软上限 ~900 行**:超过拆分(如 API 已拆出 [工程5b](工程5b-主编与协作API.md))。
4. **数据/Schema 与逻辑分离**;**Prompt 模板独立成文件**(便于版本化与 eval,见 [工程10](工程10-可观测日志与评测.md))。

## 2.7 多本书 / 作品库模型(不是只写一本)

系统是**一个作者的作品库**,不是单本书工具。账号/鉴权你自建(系统只消费 `owner_id`);系统负责"一个作者拥有多本书"的建模与体验。

**作用域规则(谁按书隔离、谁跨书共享):**

| 范围 | 实体 | 说明 |
|---|---|---|
| **按书隔离(work_id 必填)** | Volume/Chapter/Segment、AuthorIntent、设定圣经(Character/SettingItem/EntityRelation/CharState/TimelineEvent)、Foreshadow、ConsistencyFlag、Snapshot、MemoryEntry、DiscussionThread、ProactiveInsight、本书的 Imagination/OptionSet/FeedbackNote | 每本书的稿件/设定/一致性/记忆完全隔离,**绝不串味** |
| **跨书共享(owner 级,work_id 可空)** | TasteModel(你的文风品味)、StyleExemplar、Material(素材库)、AgentMemory(semantic/meta:关于"你"的稳定知识)、AgentSkill | 你的品味、素材、主编对你的理解跨所有书积累——**越写越懂你** |
| **双层** | TasteModel | owner 级"底色" + 每本书特化(work_id);按书注入时合并 |

**主编的跨书意识**:主编知道你所有的书,可跨书参照("你在《X》里这样处理过背叛")、跨书迁移品味;但**生成某本书时严格只用该书的设定/记忆**(防串味),跨书仅在品味/素材/经验层共享。

**落地映射(对齐 [工程8](工程8-HermesAgent复用方案.md))**:每本书 ≈ 一个 Hermes Profile(隔离配置/记忆/技能)+ owner 级共享层;或单进程 + work_id 全程过滤。**作品库视图、切书、跨书搜索是前端([工程2](工程2-交互与编辑器.md))一等功能。**

## 3. 设计原则(任何文档违背即为错)

源自哲学文档,逐条是硬约束:

1. **AI 主笔,人只想象 + 提意见。** 人从不亲手写 prose。任何要求"人来写/人来填正文"的设计都错。
2. **想象是 AI 一切文字的源头,必须被一等公民地捕获。** 不是 `theme` 一个字段——见内核1 的 Imagination/AuthorIntent。
3. **关键处给选项,人做判断。** 情节走向、人物抉择、关键场景写法 → 2–4 个有差异的方案 + 各自代价,人选。AI 绝不替人拍板"什么是好"。
4. **提意见 → AI 重做,是主交互。** 自然语言批评直接驱动重写;低摩擦;人永不动 prose。
5. **默认对抗趋均值。** 反平庸是生成的默认目标函数,不是事后检查(因为无人手兜底)。
6. **一切可解释、可回流成"作者品味模型"。** 每段生成说得清依据;人的每次选择/意见/打分都喂回偏好模型。系统越用越懂"你的书"——这是护城河。
7. **度量绑定"好"而非只绑"对"。** 见工程6。
8. **门槛隐形,内核显形。** 见 §2 注。
9. **ponytail:先验证子机制再递归组合。** MVP 用 Postgres+pgvector,Neo4j/独立向量库/微服务设量化阈值才迁。
10. **百万字约束贯穿。** 无经验证的百万字端到端最佳实践;组合方案属【设计决策】,须配自建度量(工程6)边放大字数边验证。
11. **全功能交付,不做 MVP 阉割。** 每个模块按完整设计实现;[工程7 路线图](工程7-工程化与路线图.md) 按**依赖顺序**分批落地,但不裁剪功能。各文档"MVP vs 完整版"小节一律改读为"**先交付 vs 后交付的依赖顺序**",而非功能取舍。

## 4. 规范数据模型(唯一真理源)

所有文档用以下实体名与字段名,可细化不可改名。**粗体为本次重构新增的"内核"实体**——它们承载人的想象与品味,是旧设计完全没有的。

### 4.1 内核实体(心脏)

```
Imagination    (想象碎片): id, work_id→Work, raw_text, 
                          type(scene_wish/character_impulse/plot_what_if/
                          world_idea/theme_seed/mood/twist),
                          structured(jsonb), status(captured/structured/scheduled/used),
                          scheduled_for(chapter/volume nullable), embedding, created_at
AuthorIntent   (北极星)  : id, work_id→Work(1:1), 
                          reader_feeling(要让读者感受什么),
                          core_emotional_arc, why_write, central_promise,
                          do_not_betray(jsonb=红线/绝不背叛的东西), updated_at
OptionSet      (多方案)  : id, work_id→Work, decision_point(jsonb=在哪做决定),
                          options(jsonb=2-4个变体:文本/差异/代价),
                          chosen_option_id, choose_rationale, created_at
FeedbackNote   (意见)    : id, work_id→Work, target_type(segment/chapter/option/
                          setting/outline), target_id, nl_critique(自然语言批评),
                          parsed_directive(jsonb=结构化指令), 
                          resulted_snapshot_id→Snapshot, created_at
PreferenceSignal(偏好信号): id, owner_id, work_id→Work(nullable=跨作品),
                          source(option_choice/feedback/rating/revision_diff/exemplar),
                          signal(jsonb), polarity(+/-), weight, created_at
TasteModel     (品味模型) : id, owner_id, work_id→Work(nullable),
                          positive_exemplars(jsonb), negative_list(jsonb=AI腔黑名单/反例),
                          learned_preferences(jsonb), version, updated_at
```

### 4.2 作品与正文

```
Work          : id, title, premise, genre, structure_type, created_at, updated_at
                (北极星见 AuthorIntent;不再用单字段 theme_anchor)
Volume        : id, work_id→Work, seq, title, arc_goal, structure_beats(jsonb), status
Chapter       : id, volume_id→Volume, seq, title, outline(jsonb), beat_targets(jsonb),
                hook_text, hook_strength, word_count, status(draft/reviewing/done)
Segment       : id, chapter_id→Chapter, seq, text, embedding, created_by(ai/human)
```

### 4.3 设定 · 连贯(门槛层)

```
Character     : id, work_id, name, traits(jsonb), motivation, voice_profile(jsonb), relations(jsonb)
CharState     : id, character_id→Character, chapter_id→Chapter, state_desc, change_type
SettingItem   : id, work_id, type(rule/item/place/faction/term), name, content(jsonb),
                first_chapter_id→Chapter, embedding
EntityRelation: id, work_id, src_entity, dst_entity, relation,
                valid_from_chapter→Chapter, valid_to_chapter(nullable)
TimelineEvent : id, work_id, chapter_id→Chapter, abs_time, rel_order, description,
                entity_refs(jsonb), embedding
Foreshadow    : id, work_id, summary, foreshadow_chapter_id, trigger_chapter_id,
                payoff_chapter_id, state(planted/triggered/paid/abandoned), payload(jsonb)
ConsistencyFlag: id, chapter_id→Chapter, error_class(枚举见 §5), severity, detail,
                evidence_refs(jsonb), status(open/confirmed/dismissed/fixed)
```

### 4.4 记忆 · 版本 · 素材 · 文风

```
MemoryEntry   : id, work_id, scope(chapter/volume/global), summary_text,
                source_chapter_range, embedding, updated_at

# 主编智能体相关(内核0,详见该文档 §4)
DiscussionThread: id, work_id, trigger(imagination/feedback/option/proactive), topic,
                messages(jsonb: role=human/editor, text, evidence_refs, concern_type),
                resolution(jsonb), status(open/resolved/overridden), created_at
ProactiveInsight: id, work_id, kind(foreshadow_overdue/arc_drift/intent_deviation/
                opportunity/consistency/process), summary, evidence_refs(jsonb),
                confidence, severity, suggested_action, status, created_at
AgentMemory   : id, owner_id, work_id(nullable), namespace(working/session/episodic/
                semantic/meta), key, value(jsonb), confidence, embedding, updated_at
AgentSkill    : id, owner_id, name, spec(jsonb), status(proposed/approved/active/retired),
                created_by(editor/human), approved_by_human(bool)
Snapshot      : id, chapter_id→Chapter, content, created_by(ai/human),
                parent_id→Snapshot(nullable), branch_label, created_at
Material      : id, owner_id, work_id(nullable), type(inspiration/reference/research/
                snippet/name/place_idea/image/quote/worldbuilding/style_sample),
                title, content(jsonb), source, tags(jsonb), embedding, status, created_at
MaterialRef   : id, material_id→Material, used_in, target_id, ref_type, relevance, created_at
StyleExemplar : id, owner_id, work_id(nullable), label, sample_text,
                style_descriptors(jsonb), embedding, scope(work/character/global)
```

**ID** = uuid v7。**软删除** 重要实体带 `deleted_at`。**审计** 一律记 `created_by`。

## 7. 文档写作公约

每篇文档含固定小节:① 在回路中的位置与职责 ② 设计目标与百万字挑战 ③ 详细设计(算法/状态机/ASCII 图/伪代码/Prompt 骨架) ④ 数据契约(引用 §4,可细化) ⑤ 对外接口 ⑥ 失败模式与缓解 ⑦ MVP vs 完整版 ⑧ 证据与引用(分级:【已核实】带 arXiv /【稳定知识】/【需复核】/【设计决策】) ⑨ 开放问题。

中文撰写;代码/字段/标识符英文;实体名严格用 §4;一致性错误类型用 §5;凡涉及"人写正文"即为违规(AI 主笔)。
