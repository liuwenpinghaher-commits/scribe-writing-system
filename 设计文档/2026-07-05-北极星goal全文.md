## 自主决策协议(替代人工停机,全程不停不问)

**决策优先级**:方案宪法条款 > 全网调研证据 > 方案文档实现细节 > 仓库既有先例 > 保守可逆默认。
**决策台账**:`设计文档/2026-07-05-北极星实施决策台账.md`,每个自主决策一条:问题/候选项/调研证据(带链接)/选择/理由/回滚方式。作者事后翻账替代事中审批。
**全网调研义务**:五个组件动工前各做定向调研(≤1小时/次,搜工程实践与 prior art):loop 编排、目的合同、复盘蒸馏、QD 档案、选择环;另加两次底座调研(见下两协议)。

### Hermes 升级协议(允许升级,按此流程)
1. **评估**:通读 0.17.0→上游 267 commits 的 changelog/diff,列出对本方案有用的特性(elicitation 批量待批/事件钩子/script-injection 增强等)与全部 breaking changes(重点:Responses 工具来自 config 的格式是否变更)。
2. **决策判据**:存在本方案任务直接受益的特性,且 breaking changes 有明确迁移路径 → 升级;仅"版本新"不构成理由。
3. **隔离验证**:固定当前版本可回装(记录安装方式与版本号);在隔离参数环境起升级后的 Hermes,跑全量 pytest + MCP 工具 roundtrip(s3_ 工具逐个调通)+ elicitation 写待批 roundtrip + config 迁移核对。
4. **金丝雀**:loop-qa 测试作品真机写一章走完整链(写→检测→ingest)。
5. **裁决**:全绿→正式采纳并记台账;任一回归→回滚到 0.17.0,把回归证据记台账,继续用旧版实施(升级失败不阻塞 goal)。

### Schema 设计协议(自由设计最优方案,按此流程)
1. **自由设计**:目的合同 deltas、lesson 表、chat_message、scorecard 缓存等新结构,**不强制沿用 scene_truth 章表字段先例**——按查询模式/基数/演进空间选最优(独立表/章表字段/图边均可),必要时查 SurrealDB 3.x 建模社区实践,选择理由记台账。
2. **允许改已有 schema**(不限于只增),但任何触及已有表的 migration 必须走**影子库演练**:`surreal export` 备份 → 另起临时端口导入副本 → 副本上跑 migration → 行数比对+抽样字段核验+全量 pytest 指向副本 → 全过才对真库执行。
3. **可回滚**:每个 migration 配 down-migration 或书面回滚步骤(含数据恢复路径),记台账;演练失败的方案直接弃用换设计,不硬闯。

**绝对规则(纯安全项,与最优性零冲突,无例外)**:
1. 生产作品数据(纸命等)只读;所有真机验证在专用测试作品 work=`loop-qa` 上做(种入 3-5 章测试数据)。
2. 任何 schema/底座变更前 `surreal export` 备份到 scratchpad,备份成功才继续;`~/.scribe2-surreal/data.db` 本体永不直接删改。
3. 端口不漂移(前端3311/后端3321/DB8001);禁破坏性命令;不 push;不动与任务无关的已改文件。
4. **方案宪法条款(设计本身,任何调研都不能推翻)**:不造总分;rubric/fulfillment 永不进 blocking;advisory 永不自动重写;蒸馏升格永不自动生效(机制必须是待批);regenerate 复用完整 chat_write 组装链;停机判据只挂确定性项。

## 任务清单(13 项全做,严格按序,一任务一 commit)

### 第一批 P0
1. **chat_message 会话落库**:schema 按设计协议自定;`POST /chat/write` 每轮追加(work/chapter/stage/role/text/ts)。
2. **causal_directives 进 brief**:三选一指令,措辞照 `promise_directives` 先例;top-N=5 硬上限;`no_event_data` 整段不渲染。
3. **章级 scorecard**:`GET /north-star/chapter/{seq}`,constraints/advisory_scores/fulfillment 三分栏(fulfillment 本批空);挂 `_compute_chapter_caches`;缓存表入 `_LIVE_TABLES`。
4. **loop 编排层**:`POST /loop/chapter`(或 scribe3/loop.py)。blocking→regenerate≤2轮/advisory→待批清单/pass→ingest;每轮落 PipelineJournal;旧稿留版本;2 轮仍 blocking→状态置 `needs_human` 标记后绕行,继续后续任务。

**P0 自动验收门**(全过才进第二批;不过则修复重验,最多 3 轮修复,仍不过记台账降级绕行):
- 全量 pytest 绿(基线只增不减);
- loop-qa 真机跑 `POST /loop/chapter` ≥3 章:构造 blocking(种泄密词)验证自动回炉≤2轮且新稿无泄密、构造 advisory 验证只出清单不重写、干净章验证直通 ingest;journal 完整记录三路径;
- curl 章级 scorecard 返回真实数据;chat_message 表有本轮对话。

### 第二批 P1
5. **底座对表调研(升格为决策任务)**:附录 A.3 五问逐条查证 + 执行 Hermes 升级协议第1-2步得出升级与否的裁决;若裁决升级,走协议 3-5 步完成后再做任务 6-9(让后续任务吃到新特性);产出 `设计文档/2026-07-05-底座对表结论.md`,每问"查到/未查到+出处"。
6. **章节目的合同 MVP**:purpose_text+deltas(schema 自定);主编对话侧列草单走 elicitation 待批机制;deltas 注入 brief;认知类 delta 对 project_frame 写前预演;`/post-check` 增 fulfillment 段(结构类查库/认知类针对性判定只进 advisory);未达成置 carried 滚下章,连续 2 章未达成→面板告警;空 delta 章照常可写。
7. **书级 scorecard**:四维(张弛/回收率/矛盾密度[标注仅自比趋势]/达成率),不合成总分。
8. **章后复盘蒸馏+lesson 反哺**:挂 ingest 成功路径事件驱动;只提取决策理由/用户纠偏/坑三类;lesson 带 embedding 走 HNSW 召回(与情绪模式向量的隔离方案按任务5结论定,查不到社区经验则影子库上 A/B 两种设计各跑测试选优);反哺 brief"上章复盘要点"段+升格 craft_rule 候选走待批;lesson 严禁复述世界状态;带合并去重+过期。
9. **QD 多样性档案**:句长CV/对话占比/POV策略章级记录+分布单调告警,进书级面板。

**P1 自动验收门**:pytest 全绿;loop-qa 真机完整链:登记含 3 条 delta 的目的合同(1 条构造为帧外不可实现,验证预演报错)→写章→fulfillment 验收(构造 1 条未达成,验证滚入下章 brief)→ingest 后 lesson 表有蒸馏记录且下一章 brief 出现复盘要点段。

### 第三批 P2
10. **北极星面板前端**:双级 scorecard 三分栏,`/live` SSE 推送不轮询;`npm run build` 通过 + Playwright(pw.mjs 先例)截图验证真实数据渲染。

12. **ConStory 19 类覆盖面对照**:调研分类体系,逐类标注现有检测器覆盖(确定性可检/需LLM/不可检/缺口),产出对照文档。
13. **秘密审计制度**:制度文档+抽样工具(被自动 regenerate 章与随机章导出盲评包的脚本/端点)。

**P2 自动验收门**:pytest+build 全绿;loop-qa 真机跑选择环一次,3 候选 journal 留痕;面板截图存档。
