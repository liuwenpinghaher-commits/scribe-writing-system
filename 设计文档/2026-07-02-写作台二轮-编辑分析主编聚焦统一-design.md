# 写作台二轮设计:编辑 · 分析 · 主编聚焦统一

> 用户一轮实机走查暴露的一组交织问题,收敛为一份整体设计:前置阶段(大纲/节拍/演绎/草稿)编辑体验拉齐正文、主编讨论↔中区闭环、通用选中→主编聚焦、分析面板信息架构、一批视觉 bug。分阶段实施,每阶段真机验证。

**日期**:2026-07-02 · **分支**:feat/audit3-fixes(接续 PR#2)· **范围**:scribe3/web 前端为主 + 少量后端(草稿轻量分析端点)

**已定决策**(brainstorming):① 前置阶段用 tiptap WYSIWYG(同正文);② 节拍保留"有序条目"结构、每条升级;③ 草稿跑轻量分析(不 ingest);④ 全部问题合入本设计;⑤ 主编支持"通用选中聚焦"。

---

## 一、背景与根因

写作台已有两套断层:
- **编辑体验断层**:正文用 tiptap 富文本(`editor/ProseEditor.jsx`:StarterKit + BubbleMenu + 护栏)+ 健壮保存(`WriteLayout.jsx` 的 `dirtyRef` 切章前 flush + beforeunload);前置 4 阶段(大纲/节拍/演绎/草稿)是简易 `<textarea>` + 失焦存,脆弱且非富文本。**演绎生成后切换丢内容**、**多角色投影互相覆盖**就是这套脆弱保存的直接后果。
- **聚焦/信息架构断层**:主编(`ChiefDock.jsx` 的 `ctx`)只认"视图级"(在看哪个横切视图)和"项目树节点级"两种 `sel`;横切视图(图谱/时间线/仪表盘)内部选中是局部 state,不回抛,主编聚焦不到具体条目。伏笔等面板点击只跳章、不出中区详情。

## 二、块一:前置阶段编辑器拉齐正文

### 2.1 共享富文本编辑器
抽 `editor/RichEditor.jsx`(从 `ProseEditor` 提炼可复用内核:tiptap `useEditor` + StarterKit + Placeholder + CharacterCount;去掉正文专属的护栏装饰/场景断)。props:`value`(markdown 字符串)、`onChange(md)`、`onBlur`、`placeholder`。输出/输入以 **markdown** 序列化(用 tiptap 的 markdown 序列化或 StarterKit + 简单转换;`react-markdown` 已在依赖,渲染侧可复用)。
- **大纲**:单个 RichEditor(synopsis)。
- **演绎**:场景真相 / 每个角色投影各一个 RichEditor(五层小标题用 markdown H3)。
- **草稿**:单个 RichEditor(draft)。
- **节拍**:保留有序条目列表;每条 `beat.text` 用一个精简 RichEditor(或单行富文本),条目级上下移/删除/新增保留;支持"让主编生成/追加条目"。

### 2.2 统一健壮保存(根治丢内容)
所有前置阶段编辑器改用正文同款保存范式:
- 组件持 `dirtyRef`(实时值,脱离 state 闭包):`{ key, value, dirty }`,`key` = `${seq}|${selected/字段}`。
- **切换前 flush**:切章 / 切阶段 / 切演绎选中项(truth↔角色)/ 卸载前,若 dirty 则先 `await persist(旧 key 的值)` 再加载新目标(用闭包捕获旧 key/值,不读可能已变的 state)。
- **beforeunload 兜底**:有未保存改动时浏览器原生提示。
- 保存失败 → danger toast + 保留 dirty(可重试),不静默。
- **演绎多角色覆盖修复**:保存单个角色投影时不再用可能过期的 `meta.deductions` 算 `others` 覆盖整数组;改为**先读取最新 deductions 再合并**(或后端加"单条 upsert deduction"端点,前端只发被改的那条)。本设计采用**前端读最新再合并**(persist 前 `api.chapter(seq)` 取最新 deductions,或维护本地权威 ref 随每次成功保存更新),避免竞态覆盖。

**验收**:演绎生成场景真相/角色投影后,切选中项/切章/切阶段来回,内容不丢;连续生成多个角色,互不覆盖(后端 `curl /chapter` 核对 deductions 全在)。

## 三、块二:主编讨论↔中区闭环统一

批一已为**草稿**做过"主编生成→ChiefSlotContext 跨栏→中区 DraftTab 一键填入"。本块把该模式**推广到大纲/节拍/演绎**:
- ChiefSlotContext 增通用 `stageProposal` 通道 `{ phase, seq, target, content, ts }`(target 用于区分演绎的 truth/某角色、节拍的追加条目)。
- 各前置阶段主编 `chatWrite`(带 `phase`)生成完 → 发布 `stageProposal`。
- 中区对应编辑器接住 → 顶部提示条「主编生成了内容 · 填入 / 追加」→ 落进 RichEditor(置 dirty,走块一的健壮保存)。
- 中区各阶段「生成」入口统一(演绎已有;大纲/节拍/草稿补一致的生成动作,或明确"生成在右栏主编"并保持落地闭环)。

**验收**:每个前置阶段都能"右栏主编生成→中区一键落地",无"生成了停在气泡里不知道怎么用"。

## 四、块三:通用选中→主编聚焦(universal selection bus)

### 4.1 选中总线
新增 `selectionContext.jsx`:`SelectionProvider`(由 App/BinderLayout 顶层提供)持 `focus = { type, id, label, payload } | null` + `setFocus`。`type` ∈ chapter/scene/character/faction/item/term/world_rule/promise/motif/event/frame_fact/deduction/view。
- **任何视图选中即发**:项目树节点、图谱节点(AtlasView 点节点)、时间线事件(TimelineView 的 `setSelected` 改为同时 `setFocus`)、仪表盘条目、左栏伏笔/母题/帧行、演绎项——统一 `setFocus(规范对象)`。
- 兼容现有 `sel`:`sel` 逐步并入或映射到 `focus`(过渡期二者同步,最终以 `focus` 为单一源)。

### 4.2 主编消费
`ChiefDock` 的 `ctx` 改从 `focus` 构建:据 `type` 生成聚焦话术(prefix/suggests),并可携带 `payload` 给后端联查。选中一条即主编聚焦它、话术随之变。

### 4.3 中区详情联动(可选增强)
`focus` 为可详情化类型(promise/character/motif…)时,中区可复用 `CodexDetail` 展示完整详情——解决"伏笔点击不出中区详情"。此为增强,分析面板块(块四)细化。

**验收**:图谱点节点 / 时间线点事件 / 伏笔点行 → 主编标题与话术立即聚焦到该条;选设定类条目→中区可出详情。

## 五、块四:信息架构重构 + 分析面板 + 草稿分析

### 5.1 真素材库(Materials Library)——新增顶级能力
收集**非正典**写作材料(研究资料/参考片段/灵感剪藏/待用桥段/笔记),与设定库(codex=故事正典)严格分开:**素材不进知识图谱、不被 ingest、不参与限知/伏笔/QC/时间线**。
- **数据模型**:新表 `material`(SCHEMAFULL + migration `051_material.surql`):`{ id, title, body(markdown), kind: research|reference|snippet|inspiration|note, tags(JSON数组字符串), source, created_at, updated_at }`。每书独立(work 隔离)。轻类型 + 自由 tag,不做复杂文件夹树(YAGNI)。
- **端点**:`GET /materials`(可选 `?kind=`)、`POST /materials`、`PATCH /materials/{id}`、`DELETE /materials/{id}`(镜像 motif/promise CRUD)。`api.js` 加对应方法。
- **交互**:项目树新增**第三个顶级根「素材库」**(与「手稿」「设定库」并列):materials_root → 按 kind 分类 → 素材条目。详情/编辑复用 `CodexDetail`/`CodexNew` 模式(标题 + 富文本正文 + kind + tags + source),不新造 UI。素材库支持按标题/正文/tag 搜。
- **素材→写作桥**:素材详情有「插入到草稿/正文」把片段插进当前写作;选中素材经块三选中总线 → 主编可引用讨论。
- **明确不参与**:素材不出现在 帧/演绎/伏笔/QC/时间线(非正典)。

### 5.2 命名正位 + 母题归位
- 左栏「素材·母题」tab → 正名「**母题**」(它就是设定库的母题面板),消除"素材"名不副实。
- 母题在导航/详情里明确归属**设定库(codex)**,不再挂"素材"名。真「素材库」是 5.1 的新顶级支。

### 5.3 大纲层级 + 可发现性 + 单一真相源
- 确立「**书级大纲(总览)→ 章级大纲(细写)**」层级:点**手稿根**默认即全书大纲视图(ContainerOutline 提为手稿根默认视图,显眼可发现)。
- **synopsis 单一真相源**:书级大纲点某章 = **导航进该章的大纲阶段**(而非就地另一套编辑),消除"就地改 vs 章级改"两个割裂编辑面。(inline 快速编辑可保留为辅,但明确标注"即章级大纲、处处同步"。)
- **视角(focalizer)露出**:大纲/章卡显示 focalizer + 一句说明它管限知(点开可看该章限知帧),让"视角有什么用"可见。
- **北极星提为书级常驻**:作品意图/纲领(`/intent`,现仅挂在 WriteLayout 正文内)提到应用级(AppRail)或写作台各阶段可见,从大纲阶段起就能看到/编辑"这本书往哪写",不再正文专属。
- **显示修复**:大纲表/卡片 synopsis 换行/截断/列宽逐条核查修正(ContainerOutline 渲染层)。

### 5.4 分析面板 IA + 草稿轻量分析
- **伏笔(PromisesPanel)**:窄栏默认只重点展开"本章相关"(本章收/埋/超期/仍悬),"障眼法/已了结/无关"强折叠;点伏笔行→经块三 `focus` 驱动中区 `CodexDetail` 详情(埋/收/线索/编辑),不再只跳章。
- **草稿轻量分析**:草稿阶段对**草稿文本**跑确定性检测(复用 `critique` 的 quality_flags/复读/排比/情感直说 + 限知泄露预览),**不跑 LLM ingest**、不写 proposition/knows/台账。新增端点 `POST /draft-check`(入草稿文本,返回确定性检测结果),草稿阶段展示。
- **面板一致性**:标题/空态/间距沿用批三 ui 原语。

**验收**:项目树三支(手稿/设定库/素材库);素材库可增删改查搜、能插进写作、且不污染分析;母题正名归设定库;点手稿根即全书大纲、点章进章级大纲(synopsis 一处改处处同步);草稿阶段能看确定性质检;伏笔面板不拥挤、点击出中区详情。

## 八、非目标(YAGNI)

- 不把节拍改成自由富文本文档(保留条目结构)。
- 草稿不跑 LLM ingest(只确定性检测)。
- 不重写正文编辑器(仅提炼共享内核复用)。
- markdown 采用 tiptap 序列化,不引入独立 markdown 源码编辑模式。
