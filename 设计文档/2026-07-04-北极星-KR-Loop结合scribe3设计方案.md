## 一句话结论

用户构想的骨架(北极星定方向、与主编探讨章节目的、节拍/大纲当章级合同、loop 驱动演绎→草稿→正文)全部保留,但把"KR=可验证分数、达标即收敛"这个管理学内核替换为"控制论 setpoint(违规数维持在零)+ 确定性检测器分流回炉 + 北极星度量算子只做面板不做总分";同时把用户构想里真正可救的 KR 内核——**"目的分解出的不是分数,是本章承诺改变的世界状态清单(delta)"**——落成第四块拼图(章节目的合同,验"做没做"而非"好不好")。scribe3 现有架构离这个形态差四块拼图:检测结果自动回炉、因果欠账进下一章 brief、北极星双级 scorecard、章节目的合同;四块合起来是**修复环**(守下限),其外再补**选择环**(关键章 N 候选人终选,攻上限)与**沉淀环**(会话落库+章后复盘,品味复利)——全部是增量接线,不推倒任何现有结构。**本方案的诚实定位:这不是一台"写出好小说"的机器,是一台"不让好小说被写坏、并让作者品味花在刀刃上"的机器;上限始终由终选的人决定。**

## 四条最重要决策

1. **KR 换 setpoint,不设可最大化的总分。** loop 的收敛判据只挂确定性检测器(限知泄露=0、退化=0、blocking issues=0、伏笔超期=0),LLM rubric 分降级为软性参考——因为 LLM 评审机会校正后 κ 仅 0.376-0.511、创意写作人机一致 ICC=0.43(文档2 B4),拿它当 KR 收口必被 Goodhart;而数学上不存在完全不可利用的代理指标(arXiv:2209.13085,文档2 B2),所以北极星算子输出"约束偏离面板"而非加权总分。
2. **回炉自动化按 severity 三分流,硬上限 2 轮,判据全部来自外部确定性信号。** blocking(退化/泄露/ai_grade heavy)→自动 regenerate;advisory→rewrite 建议清单待人批;pass→ingest 反哺。绝不让生成模型依据自己的 rubric 自评分数决定重写——"无外部反馈的自我修正反而更差"(arXiv:2310.01798)与自发 reward hacking(arXiv:2407.04549)在文档2 B1 均有实证。而"反馈信号能称得上外部和客观",前提是本体这个**不由生成模型说了算的真相层**——本体在本方案里的定岗不是引擎也不只是账本,是让 setpoint 可判定的**度量基准**(限知违规靠 KnowledgeEdge/project_frame 才可判定、伏笔超期靠 promise 账本才可判定;文本统计类检测器是唯一不依赖本体的少数派)。
3. **setpoint 只查"没写坏",章节目的合同补上"写到了"。** 负向门禁(违规=0)之外,新增正向验收:与主编探讨出的章节目的翻译成一组**本体状态增量(delta)**——认知增量(读者/角色谁得知什么)、承诺增量(伏笔埋/触/收)、事实增量、关系热度增量——写前登记进合同并对 project_frame 做可实现性预演,写后逐条验收达成率,未达成滚入下一章。可验证的不是"好不好",是"做没做"——这是用户 OKR 直觉里可救内核的严格形态,不触碰"主观质量可验证"这个被证伪的假设(详见 §3-④)。
4. **与计划 B 的分工在 v2 简化为:计划 B 已全部合入,直接消费。** 合同层字段(字数预算/压力级/chapter_role/反转字段)、FindingsSchema/fix_action、heat 状态机、PipelineJournal 均已在库;本设计新增的接通件(loop 编排层、causal_directives、双级 scorecard、目的合同、会话落库+复盘)**无一被计划 B 阻塞,全部可立即动工**。

## 第一章 · 对用户构想的正面裁定

用户原始构想:**以北极星「写出最好的小说」为 O,以节拍/大纲为 KR,用 loop 逻辑生成 演绎→草稿→正文。**

### 1.1 保留什么

| 构想成分 | 裁定 | 依据 |
|---|---|---|
| **北极星作为方向** | **保留**,且系统已有落点:`intent` 单例(reader_feeling/emotional_arc/red_lines,`scribe3/store.py:1640-1663`)每次写作注入 prompt(`scribe3/app.py:1247-1248`)。缺的不是北极星本身,是它的**度量算子**(见 §3-③) | 文档1 结语:"北极星现在是贴在墙上的标语,不是 loop 里可以被查询、被度量的目标函数"——问题在算子缺失,不在方向错误 |
| **节拍/大纲作为章级合同** | **保留并强化**。这不是 KR(一次分解、达标收口),而是 DOME 式后向依赖的分层大纲:粗纲→细纲逐章展开、可回溯修订。计划 B 任务 10/11/13b 已把合同字段补齐入库(字数预算、压力级、chapter_role、reversal_type/setup_clues,均已合入);§3-④ 再加一层:章节目的与 delta 条款,让合同从"怎么写"扩到"为什么写、写成什么算数" | 文档2 B3:DOME(arXiv:2412.13575)分层大纲+结构化记忆使冲突率从 Re3 的 0.77 降到 0.56,是被量化验证的路线;文档2 替代框架表:"节拍/大纲状态应设计成可回溯修订的状态机,而非完成即不可变的 KR 清单式里程碑" |
| **loop 驱动 演绎→草稿→正文** | **保留**。scribe3 现有形态(SurrealDB 状态层+逐章生成+四阶段 大纲/节拍/草稿/正文)本质上已是 Reflexion 式增量循环,方向被文档2 判定正确;缺的是环路闭合(检测→回炉自动化,见 §3-①) | 文档2 B1:"Self-Refine 式全局重写与长篇现实冲突;Reflexion 式增量局部生成-评审与'新章基于历史累积状态生成'高度同构……scribe3 现有架构在方向上吻合,不必推翻重来" |

### 1.2 替换什么

| 构想成分 | 替换为 | 为什么 |
|---|---|---|
| **KR="可验证子目标,达标即收敛"** | **控制论 setpoint:一组硬约束维持在容许区间(违规数=0),循环目标是纠偏回区间,不是爬升某个分数** | ① 文档2 B2:OKR 式分解在 AI agent 领域仅 1 篇字面先例(OKR-Agent, arXiv:2311.16542)且不涉创作;其方法论祖先(HTN/层级RL/OKR)共享的"存在可验证子目标"假设被 Writing-Zero(arXiv:2506.00103)与 Beyond Correctness(arXiv:2510.14616,去掉客观信号后写作偏好 reward model 准确率崩到 52.7%≈随机)明确证伪。② 文档1 问题四给出同构的系统内证据:scribe3 里唯一真正生效的引擎级机制是 `project_frame` 限知投影——一个**约束**("帧外事实物理进不了 prompt"),而所有"目标分数"类结构(张力评分、rubric)全部沦为事后账本。本系统自己的历史已经证明:硬约束能落地成引擎,分数落不了。 |
| **"最好的小说"作为可收口的 O** | **O 操作化为"质量宪法"= setpoint 约束集 + rubric 软参考 + 双级度量面板;整体文学质量的最终裁决保留给人** | 文档2 B4:当前不存在已验证的、可信赖到能替代人类的"整体文学质量"自动化实时信号(κ 虚高 33.8-41.2 个百分点,arXiv:2606.19544;人机 ICC=0.43,arXiv:2411.02316);唯一扎实可自动化的是确定性检测器类信号(ConStory-Checker F1=0.678,是人类专家召回的 3.2 倍,arXiv:2603.05890)——恰是 scribe3 已有路线 |
| **单一收敛方向的打磨** | **quality-diversity 保底:多样性是一等目标,不是副产品** | 文档2 B2:Kenneth Stanley 目标悖论/novelty search/MAP-Elites/open-endedness(arXiv:2406.04268)构成"专门以创作为战场"的成体系反证,证据密度显著强于支持 OKR 的一方;文档2 B1 并警示评审压力诱导趋同(arXiv:2509.05396) |

**一句话裁定(v2 精化)**:用户构想的三个词里,"北极星"和"loop"是对的,"KR"这个词只借错了一半——借错的是"子目标可验证、达标可收口"这条隐含假设(在创作任务上被 2025-2026 年多篇独立论文证伪,文档2 裁定章);**没借错的是"先与主编探讨出章节目的、再共同分解怎么达到"这条派生链**——它是人类编辑部的章纲会工作流,最难的两步(目的好不好、最终收不收)留给了人,不需要被证伪的那条假设。它的可落地形态:目的分解出的不是分数,是"本章承诺改变的世界状态清单"(delta),而"状态变化发生没发生"是可验证的(§3-④)。换成"setpoint 守负向 + delta 合同验正向"之后,loop 照转,而且转得更稳。

| ③ 基于分解写节拍/大纲 | ✅ 四阶段 tab+计划B合同字段,已建成 | 现状保留 |

**三环总览(v2 新增,Loop 层的完整定位)**:上图的每章循环是**修复环**——它保证"没有一章烂",这是机器的比较优势(缺陷累积是长篇的主导失败模式,人在五十万字后靠脑子记账必然出错)。修复环之外还有两个环(第四章详述):**选择环**(关键章 N 个策略多样候选→本体确定性过滤→rubric 批次粗排→人终选,攻上限)与**沉淀环**(会话落库→章后复盘→lesson 反哺 craft 规则/声音库/brief,品味复利)。三环的分工:修复环管"合格",选择环管"出彩",沉淀环管"越来越像作者的书"。判断整套架构的标准只有一条:**作者的品味是全系统最稀缺的资源,架构要把它的每次消耗放在最高杠杆点(终选与目的探讨,而非查账),且绝不浪费它产生的信号(纠偏与选择理由必须沉淀)。**

架构要点:

1. **O 层不出现"总分"。** 北极星算子输出的是约束偏离面板(哪条 setpoint 被违反、偏离多少),LLM rubric 只在面板上以"软参考"栏位展示。理由见第六章 Goodhart 条。
2. **合同层与 KR 的本质区别是可回溯修订。** 节拍写完不冻结:书级 scorecard 发现张弛单调(计划 B 任务 11 的 `find_tension_monotony`,已合入)时,修订的对象是**后续章的合同**,不是判"KR 未达成"。这正是 DOME 后向依赖的语义(文档2 B3)。
3. **Loop 层区分硬引擎与软引擎**(文档1 问题四的量级区分):`project_frame` 是生成前物理裁剪(硬),brief 指令是文案提示(软),检测分流是生成后闸门(硬)。本方案新增的四块拼图落在两条边上:①②③在"生成后闸门→下一次生成输入"这条断开的边上,④在"目的探讨→合同"这条从未存在过的边上。
4. **本体在三层架构里的正式定岗(v2 新增,吸收溯源审计结论)**:本体不当作者(提议情节——因果合法是几乎空的过滤器,戏剧价值函数不存在,做不到),不当法官(评判好坏——做不到),当**海关**(project_frame 生成前物理拦截越权信息,唯一硬引擎,现状保留)+ **公证处**(Fact/KnowledgeEdge/promise 账本让"违规"可判定,是 setpoint 反馈信号能称"外部且客观"的前提——没有这个真相层,检测就退化成拿 LLM 读散文评散文,掉回被证伪的自评陷阱)+ **档案馆**(跨章结构化状态,DOME 证据:结构化记忆使冲突率 0.77→0.56,去掉暴涨到 4.52)。§3-④ 给它加第四个岗位:**合同登记处与验收员**——登记每章承诺的世界状态变化,预演其可实现性,验收其是否兑现。这是本体在不越出能力边界前提下的最高岗位;数据方向也由此翻转了一半:delta 是写前登记的一手承诺,不再只是写后逆向抽取的二手笔录。

**成本**:中。章表两字段+迁移、brief 注入段、预演函数(复用 project_frame)、验收段(结构类查库+认知类判定 prompt)约 150-250 行+测试;主编对话侧加"列 delta 草单"指令段。

**风险与防护**:
- **纪律成本是最大风险**:每章多一道"目的→delta 待批"工序,跳过则本章退化回现状(不崩,环断)。防护:工序嵌在主编对话里自然完成;delta 为空的章照常可写(渐进采纳,不设硬门槛)。
- **delta 表达力边界(诚实声明)**:冰山条款只覆盖认知/事实/承诺/关系这类**可陈述状态**;情绪基调、潜文本、文字质感不可表达——不硬塞,这部分继续走 craft 规则与人审。验收"发生了"不等于验收"动人了",后者是选择环与人的领地。
- **认知类验收半确定**:见上,只进 advisory。防止有人日后把达成率做成门禁——达成率是给人看的仪表,不是给机器用的闸门。

## 第四章 · 三环架构:修复环之外的两个环(v2 新增)

**定位声明**:第三章四块拼图合起来是**修复环**——一台"不让好小说被写坏"的机器。评审讨论确认了它的边界:质量不是缺陷的补集,修复环只有下压力没有上拉力,把人抽走它会精确收敛到"无缺陷的平庸"(一致、干净、可读、无记忆点——这是架构的数学性质,不是实现缺陷)。攻上限的自动化路径已被证伪(总分爬坡=Goodhart),**但"选择"和"沉淀"两种形态的上拉力是证据支持的**,构成另外两个环。

### §4-① 选择环:关键章 N 候选 → 本体过滤 → 批次粗排 → 人终选

**为什么选择而不是优化**:拿 rubric 分当目标迭代打磨被证伪(评分升质量停,arXiv:2407.04549);但在 N 个**已完成**的候选里排序,噪声可被批次聚合压制——TensorZero 证据(文档2 B1):单次评分相关性可低至 0.08,批次聚合达 0.75-0.96。**rubric 不配当法官,够格当初筛员。**同时多样性靠构造保证而非事后补救(Stanley/QD 脉络的可操作化):生成候选时强制策略多样。

**机制**:
1. **触发**:仅关键章(转折/开局/卷尾/反转章——合同里 `chapter_role`+`reversal_type` 现成可判),过渡章单候选走修复环。N 倍生成成本只花在刀刃上。
2. **多样化生成**:同一章级合同出 3 个候选,强制不同策略——不同切入点/节奏形状/信息释放顺序(QD 行为空间从"防退化监控"升级为"生成时分配器";特征轴复用 P2 多样性档案的句长CV/对话占比/POV策略)。
3. **确定性过滤(本体当过滤器)**:每个候选过 find_leaks/因果断裂/伏笔触达/delta 达成/反讽面变化量——全是本体**算得出**的量;违规者杀掉,合格者标注特征差异。这也是"戏剧目的层"将来复活的现实形态:**不是本体提议情节,是 LLM 出候选、本体打分过滤**——与全架构哲学(LLM 生成、确定性层否决)同构。
4. **批次粗排**:rubric 对候选做排序参考(只排序不门禁,分数不落收敛判据)。
5. **人终选,强制留一句理由**——理由是沉淀环(§4-②)最贵的输入。

**排期**:P2(等修复环真机跑通后)。**风险**:N 倍成本失控→只开关键章+每卷限额;候选同质(多样性约束失效)→特征轴距离低于阈值时判"伪多样"重生成。

### §4-② 沉淀环:会话落库 + 章后复盘蒸馏 + 反哺(品味复利)

**现状核实(v2,2026-07-04 复核)**:
- 后端 SurrealDB **无任何 chat 表**(57 个 migration 零命中);`/chat/write` 每请求无状态。
- 前端 `web/src/useChatPersist.js` 把对话按章存 localStorage:上限 60 条(长讨论静默截断)、换浏览器/清缓存即丢、**系统自己读不到**——brief 组装、检测器、主编下次对话都查不到上章聊了什么。对系统而言,讨论从未发生过。
- ingest 只回收**散文里的世界状态**(事件/知识边/promise touch);对话里的**决策与纠偏**(为什么否了第一版开头、POV 为什么换乙、哪个建议被骂回去)零回收。这是全系统品味密度最高的信号,现归宿是浏览器缓存第 61 条之外。
- 根因是可考古的设计哲学:**交付物中心主义**(对话=操纵杆,真相进库靠 ingest 散文)。对了一半——对话的大部分内容确实该扔;**但扔错了最贵的那一小撮:决策和纠偏**。

**改动落点(三级,成本递增)**:
1. **会话落库(P0,最便宜,先做)**:`chat_message` 表(work/chapter/stage/role/text/ts),`POST /chat/write` 每轮追加写。零智能处理也值回票价:"当初为什么这么定"可回看,目的推导链不再蒸发(§3-④ 的原材料),与 PipelineJournal 同一种诚实留痕哲学——对话不该是全系统唯一不留痕的环节。
2. **章后复盘蒸馏(P1)**:一章过审/ingest 后触发一次 LLM pass,对本章会话**只提取三类**:做过的决策及理由(POV/反转位置/节奏取舍)、**用户对 AI 的纠偏**(最值钱)、踩过的坑。产出结构化 lesson 记录(非摘要全文),挂章。**(v2 底座对表补注)**触发方式定死:挂 ingest 成功路径内,事件驱动;**不走 Hermes cron**——cron 那套(6h 体检先例)适合定时巡检,不适合章粒度事件。
3. **反哺三条边(P1-P2)**:lesson → ①下一章 brief"上章复盘要点"段(软指令);②跨章反复出现的偏好升格为 craft_rule **候选,走 elicitation 待批**;③风格类结论进声音库。选择环的终选理由同入 lesson 流。**(v2 底座对表补注)**lesson 的召回**复用已跑通的 HNSW 向量检索**(情绪模式库同款,SurrealDB 现成能力,v1 漏用):写某类场景时按语义召回"类似场景的历史教训"进 brief,而非全量注入——这同时构成 lesson 膨胀防护的一半(另一半是合并去重+过期);建库时注意与情绪模式向量的索引隔离(附录 A 问题4)。

**两条铁律(防退化)**:
- **蒸馏产物升格必须待批,不能自动生效**——LLM 总结自己参与的对话再自动改写自己的规则,是自评自改(arXiv:2310.01798)的变体;lesson 入库可自动,升格为注入 prompt 的规则必须过人的手(复用"写待批"既有哲学)。
- **严格分家:世界状态归本体(ingest 管),工作方法归复盘(lesson 管)**——lesson 严禁复述"戊丢了信物"类事实(重复存必漂移),只存"这类场景该怎么写/不该怎么写";且带合并去重+过期机制,防 lesson 无节制累加把 brief 变成稀释硬指令的噪声(系统在 critique 注入上吃过 prompt 噪声堆积的亏)。

### 三环关系与系统定位(一段话)

修复环保证**没有一章烂**(机器的活:缺陷累积是长篇主导失败模式,机器比人守得住百万字的账);选择环让**关键章出彩**(LLM 供多样性、本体做过滤、人做裁决);沉淀环让**书越来越像作者的书**(品味复利:每次纠偏与终选只花一次,永久生效)。三环全部建成,系统的上限仍由终选的人决定——这不是架构的缺陷,是创作这件事的定义;架构能做到的极限,是让那个人的每一分品味都花在刀刃上,且花过一次就不必再花第二次。

**你的系统离「用 loop 逻辑朝北极星迭代」差四块拼图和两个环,依赖已全部解除,按这个顺序补:**

**第二批(P1):补上"写到了"和"记住了"。** ⑤章节目的合同——你原来管它叫 KR,名字借错了,但你要的东西是对的:与主编探讨出目的→分解成本章承诺改变的世界状态清单(谁得知什么/伏笔动没动/事实与关系怎么变)→写前对限知帧预演可实现性→写后逐条验收、未达成滚入下章。可验证的不是"好不好",是"做没做"——这是 setpoint 之外的正向验收,补齐"零违规但没写到点上"的盲区。⑥书级 scorecard 四维(含达成率)。⑦章后复盘蒸馏:一章过审后从会话里只提取决策/纠偏/坑,待批后反哺 craft 规则与声音库——品味花过一次,不再花第二次。⑧QD 多样性档案(从 P2 提前:同质化是承认了严重性却给了最弱防护的风险)。

**第三批(P2,跑通修复环之后):攻上限。** 关键章选择环——同一合同出 3 个策略多样候选,本体做确定性过滤(这也是戏剧目的层将来复活的唯一现实形态:LLM 提议、本体否决,不是反过来),rubric 只排序不门禁,你终选并留一句理由。

**同样重要的是想清楚不补什么**:不给北极星造总分(κ 0.38-0.51,拿它收口就是 Goodhart 的开始);不做"因果层提议下一步情节"的引擎(因果合法是几乎空的过滤器,"该发生什么"需要不存在的戏剧价值函数——四十年符号叙事规划的前车之鉴:因果自洽、戏剧性死亡);不推翻节拍/大纲——它们是你系统里最健康的章级合同,计划 B 已把字数预算、压力级、反转字段这些条款全部补齐入库。

**最后把定位说透**:你的直觉里,"北极星+合同+loop"是对的,"先与主编探讨目的、再一块分解"也是对的——整套构想里唯一借错的是"KR 达标收口"这四个字,而它的可救内核(目的分解为可验收的状态变化)就是第四块拼图。修复环保证没有一章烂,选择环让关键章出彩,沉淀环让书越来越像你的书;三环全部建成,这台机器仍然不是一台"写出好小说"的机器,而是一台**"不让好小说被写坏、并让你的每一分品味都花在刀刃上"**的机器——上限永远由做终选的那个人决定,这不是架构的缺陷,是创作的定义。面板全绿只证明机器没失职;书好不好,最终要过的是不进 loop 的盲评和读者——那条"秘密审计指标"看似最不起眼,其实是整套设计里唯一能回答"这一切有没有意义"的部件。
