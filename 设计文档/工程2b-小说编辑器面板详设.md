## 1. 作品库 / 切书

### 1.1 目的

多本书是一等功能(00 §2.7)。作品库是进入编辑器前的「选书门厅」，也是在写作中途「切书」的统一入口。主编品味(TasteModel)跨书共享；设定、章节、一致性全部按 work_id 严格隔离。

### 1.3 核心交互

| 动作 | 触发 | 行为 |
|---|---|---|
| 打开作品 | 点击「打开」或双击卡片 | 加载 WorkspaceStore,进入编辑器,恢复上次打开章节 |
| 切书(从编辑器内) | `⌘⇧O` 或左上角作品名下拉 | 在当前作品自动保存后，弹出迷你作品选择器（见 §1.4），不跳出编辑器全屏 |
| 跨书搜索 | `⌘K` 在作品库页 | 同时搜索所有作品的章节标题 + 想象 raw_text + 设定名(各有类型标签区分) |
| 新建作品 | 点击「新建作品」卡片 | 弹出新建向导(见 §1.5) |

### 1.4 切书迷你选择器(编辑器内快速切换)

```

│  ────────────────────────────────────────────────  │
│  ▶ 凡人修仙传 2.0           (当前)                  │

│    深海                      §02 - 3天前打开         │
│  ────────────────────────────────────────────────  │
```

- 切书时当前章节草稿自动落盘(`localStorage` + 后端 PATCH /chapters/:id)
- 切入新书后恢复该书上次 `activeChapterId`
- 主编品味（TasteModel, owner级）立即可用；该书设定/章节从对应 work_id 加载

### 1.9 百万字性能

- 作品库页最多展示 50 本书，超出分页；卡片数据来自轻量汇总查询，不加载 Segment
- 跨书搜索走后端 FTS，不在前端持有多书全文；结果截断至 20 条/类型

### 1.10 好用性细节

- 作品卡片悬停显示「主编品味积累：已学习 N 次偏好」，强化「越写越懂你」的产品感知
- 卡片上「主编札记 N 条新」角标：让作者在切书前就知道哪本书有待查看的洞察
- `⌘⇧O` 切书而不是「退出当前书再进作品库」——保持键盘流，不打断心智状态

### 2.5 拖拽重排

- 拖拽时显示目标位置的横线指示符(2px 高亮线)
- 跨卷拖拽时，前端预计算受影响的 Foreshadow 时序
- 检测到伏笔冲突 → 弹出警告对话框后方可继续(见工程2 §3.10.5)
- 拖拽到卷标题上 → 移入该卷末尾
- 拖拽不可跨书

**状态机**：

```
IDLE
  │ mousedown + drag > 5px
  ▼
DRAGGING
  (实时显示: 拖影 + 目标指示线 + 受影响伏笔预计算)
  │
  ├─ mouseup on valid target
  │    ▼
  │  COMMITTING → PATCH /api/chapters/:id/reorder → 树刷新 → IDLE
  │
  ├─ 检测到伏笔冲突
  │    ▼
  │  CONFLICT_DIALOG → 用户确认 → COMMITTING
  │                  → 用户取消 → IDLE(拖影消失)
  │
  └─ Esc / mouseup on invalid target → IDLE
```

### 2.6 虚拟滚动实现要点

```typescript
// 扁平化树节点 → TanStack Virtual
interface FlatTreeNode {
  id: string;
  type: 'volume' | 'chapter' | 'setting_group' | 'setting_item';
  depth: 0 | 1 | 2;
  parentId: string | null;
  label: string;
  seq: number;
  status: 'done' | 'reviewing' | 'draft' | 'generating' | 'planned';
  flagCount: number;
  foreshadowCount: number;
  hasOptionSet: boolean;
  isExpanded: boolean;
  isActive: boolean;
}

const ITEM_HEIGHT = 32;  // px，所有节点等高，避免 estimateSize 抖动

const virtualizer = useVirtualizer({
  count: flatNodes.length,
  getScrollElement: () => scrollRef.current,
  estimateSize: () => ITEM_HEIGHT,
  overscan: 5,            // 视口外各预渲染 5 个
});

// 性能边界: 500章 + 200设定 = 700节点 → 实际 DOM ≤ 50
// 节点 > 1000 时禁用 CSS 折叠动画: transition: none
```

### 2.8 空/加载/错误态

**空状态(新书无章节)**:

```
┌──────────────────────────────┐
│   还没有任何章节              │
│   [AI 生成第一卷大纲]         │
│   [手动创建第一章]            │
└──────────────────────────────┘
```

**加载中**：骨架线占位，宽度随机 60-90% 避免视觉跳动

**错误态**：`⚠ 无法加载大纲 [重试]`，右键菜单仍可用于已缓存节点

## 3. 正文编辑器(Tiptap)

### 3.1 目的

编辑器是正文的主舞台，也是 AI 草稿、diff、批注、引用解释的汇聚点。设计原则：**AI 生成内容与人工操作物理隔离（草稿区）**，让作者可以在 AI 生成的 30-120 秒内继续工作。

## 4. 想象捕获

### 4.1 目的

### 5.3 差异矩阵的防同质化机制

生成 OptionSet 时，后端要求每对方案在「情感走向/人物代价/情节后果」三维度中至少有一个**显著差异**。前端渲染时：

- 若某维度各方案内容相近(后端标注 `similar=true`)，高亮显示警告「⚠ 方案差异可能不足，建议重新生成」
- 不满意次数 ≥ 3 时，显示：「告诉我您偏好什么方向 →」打开 FeedbackNote 输入框(`target_type='option'`)

### 5.4 选择 → 回流 → 触发续写的前端时序

```
  │    2. 大纲树 🎯 角标消除
  │    3. 中央区过渡动画(300ms slide) → 切回正文编辑区
  │    4. 触发续写: POST /api/chapters/:id/actions/continue
```

### 8.4 状态流转

```typescript
type InsightStatus = 'new' | 'acked' | 'acted' | 'dismissed';

// new    → 角标计数；面板展示
// acked  → 角标 -1；折叠到「已知晓」区
// acted  → 有关联操作(如已创建 FeedbackNote / 已规划章节)；标注「已处理」
// dismissed → 不再显示，记录为潜在误报数据

// PATCH /api/proactive-insights/:id { status: 'acked' | 'acted' | 'dismissed' }
```

### 8.5 「这是故意的」训练机制

作者点击「这是故意的低谷，跳过」时：
- `status → dismissed`
- 同时写入一条 `PreferenceSignal`：`{ source: 'proactive_dismiss', kind: 'arc_drift', signal: '作者明确: 此低谷是故意为之' }`
- 连续 3 次相同 kind 被标记「故意」→ 主编在该 kind 检测时增加「询问是否故意」前置步骤

### 8.6 不打断设计清单

- 不弹框
- 不播放声音
- 不在生成进行中更新角标(等待生成完成后批量更新)
- 不在写作活跃期(最近 3 分钟内有键盘输入)触发新条目显示
- HIGH 级别最多也只更新右栏角标为红色，不改变中央编辑区

**伏笔裁决**：

```
ARIA 要求(重点):
```

## 13. 好用性自检：作者真实一天动线走查

以下走查一次完整的写作动线，逐步检验每个面板的顺手程度。

---

**早上开工: 开库 → 选书 → 看主编札记**

1. 打开 Scribe → 作品库页面 ✓
   - 卡片上「主编札记 3 条新」角标一眼可见
   - 点「打开」或双击进入上次所在章节 §14 ✓
   
2. 主编对话区右栏可见最新消息：「您上次在 §14 留下了一个未决 OptionSet」✓
   - 右栏底部「主编札记 ●3」角标红色，提示有待查内容 ✓
   
3. 展开主编札记(`⌘⇧L`后点「主编札记」)
   - 高优先级 F-02 超期一眼看到；点「规划回收」→ 打开大纲树，在 §52 右键「规划伏笔回收」✓
   - 全程不离开工作区，不弹框打断 ✓

**续写一章: 看大纲 → 生成正文 → 看方案**

4. 大纲树 §15 节点，右键「AI 续写正文」
   - 草稿区出现，流式输出；主编辑区不被遮挡，可以同时批注 §14 ✓
   
5. 写到关键决策点 → SSE 推送 `optionset.created` → 大纲树 §15 出现 🎯 角标
   - 点角标 → 中央区切换为 OptionSet 三卡布局 ✓
   - 差异矩阵一行一行显示情感/代价/后果，不需要阅读全文节选就能做判断 ✓
   
6. 选方案 C(⌘↵)，写几个字选择理由，自动续写 ✓

**提意见重做: 选中段落 → 说意见 → 看 diff → 接受**

7. 悬停 §15 段落2，工具栏出现，点「✏ 提意见」
   - 内联输入框在段落下方展开，视线不离文字 ✓
   - 点快捷模板「不像角色」→ 自动填入 ✓
   
8. 提交意见 → 置信度高 → 右下角 Toast 通知重做中 ✓
   - 30 秒内 diff 预览出现，side-by-side 双栏对比 ✓
   - 接受(⌘↵)✓

**查一处设定冲突 → 定稿**

9. 右栏门槛区「⚠ 连贯性 1 个 open」角标
   - 展开连贯侧栏：HIGH 级 OOC 问题，带证据两条跳转 ✓
   - 点「✓ 确认真错」→ FeedbackNote 自动打开(target_type=segment) ✓
   - 提意见重做，接受 diff ✓
   
10. 编辑器底部点「✓ 标记完成」(⌘⇧D)→ 大纲树 §15 变为绿色 ✓

---

**结论**:整条动线顺手。主要体现在：
- **不跳页面**：大纲、编辑、意见、门槛、想象都在同一工作区完成
- **角标引导**：「3 条新主编札记」「⚠1」「🎯」让作者知道「先看什么」，不需要扫描每个面板
- **主动不打断**：门槛和主编札记均以角标+折叠呈现，写作时心流未被打断
- **决策有质量**：OptionSet 差异矩阵让选择有依据；FeedbackNote 快捷模板降低了说意见的摩擦
- **AI 贡献透明**：diff 预览保证作者始终知道 AI 改了什么，声音不被悄悄替换
