# 主编主动化实施计划(方案→任务分解→门禁→验收,D-030 起记账)

> 蓝本:《2026-07-05-主编主动化改造方案.md》。本计划把方案拆成 11+2 个可验收任务,每个任务带 TDD 测试清单、真机证据要求、已知坑预防条款。
> "完美实现"的操作性定义(可证伪):①方案六件套(pulse/Pilot/授权矩阵/Inbox/收件箱/日志)全部真机在线;②三条金标验收全过(见 §六);③全量 pytest 绿+前端 build 绿+Playwright 冒烟绿;④宪法四锚零放宽(测试钉死);⑤主编每章主动开口≤4 次(防烦协议可审计);⑥台账逐任务记录,失败如实。

## 〇、铁律(全程有效,违反即停)

1. **生产作品只读**:纸命/铜炉等真书零写入;一切真机验证只在 loop-qa(及新建 pilot-qa 书)。
2. **schema 变更前备份**:`surreal export` 到 scratchpad;`~/.scribe2-surreal/data.db` 本体永不直接删改;端口不漂移(3311/3321/8001/8643)。
3. **宪法四锚**(硬编码+测试钉死,任何模式不放行):终选定稿、蒸馏升格、伏笔弃置/红鲱鱼、设定圣经变更 = approve 级;advisory 永不自动重写;停机判据只挂确定性项。
4. **测试跑法**:仓库根 `scribe3/.venv/bin/python -m pytest scribe3/tests`;门级全量运行期间冻结 scribe3/*.py;前端真检查= `npm run build`,交互验收= Playwright(build 绿≠运行时活,TDZ 教训)。
5. **每个前端任务的 DoD 必含 pw 冒烟项**(本轮 22 断头的根因=pytest 对前端最后一厘米失明,永不再犯)。
6. 不 push;不动无关文件;台账《北极星实施决策台账》D-030 起每任务一条(含自定口径与回滚)。

## 一、P0 期:感知+汇报+时机("主编活了",预算 1.5-2 天)

### T1 `/chapter-pulse` 聚合端点(后端,0.5d)
- **改动**:新 `scribe3/pulse.py`(纯函数组装,可单测)+ app.py `GET /chapter-pulse?seq=`。六维条目 `{dimension: promise|arc|relation|tension|causal|quality, severity: info|nudge|decision, message, action: {kind, payload}|null}`。
- **信号源映射**(全复用,零新检测器):promise←brief.promise_directives(reminders→info/directives→nudge/decisions→decision);arc←arc_directive+lie_belief 跳变 hint(D-029 已做);relation←brief 关系冷热;tension←tension_deterministic(rubric 不进 pulse,按需手跑);causal←causal_debt;quality←chapter qc 缓存计数+ingest_status(failed→nudge)。
- **TDD**(tests/test_pulse.py):`test_pulse_six_dimensions_shape`、`test_overdue_promise_maps_to_decision`、`test_refresh_exhausted_maps_to_decision`、`test_clean_chapter_all_info`、`test_dimension_failsoft_isolated`(单维抛错→该维 degraded 条目,其余五维照常——fail-soft 逐维隔离)、`test_ingest_failed_surfaces_in_quality`。
- **坑防**:B-3 同型(组装空内容)→ 每维条目 message 非空断言;北极星宪法(不造总分)→ pulse 无任何聚合分数,只有分维 severity。

### T2 PulseBar 前端(0.5d)
- **改动**:web 新 `PulseBar.jsx`(六点+弹层),挂 WriteLayout 顶栏 NorthStarBar 旁;弹层含:该维条目列表、`跟主编聊这个`(复用 chiefIntent 预填)、`去处理`(跳伏笔详情/北极星面板);tension 弹层内嵌压力级 1-5 sparkline(数据=章级 meta 压力级序列,纯 SVG 折线);relation 弹层列最近互动对+冷了几章。
- **DoD-pw**:六点渲染/decision 变红/弹层开合/「聊这个」预填右栏输入框/sparkline 出线;零 console error。
- **坑防**:TDZ——组件定义序自查+pw 必跑;s3-live chapter 变更→pulse 重拉(防 stale)。

### T3 时机 C:讨论模式注入 pulse 摘要(0.1d)
- **改动**:讨论链路(/chat/stream agentic instructions 组装处)拼入 pulse 摘要段(≤400 字:decision 全量+nudge 计数)。写作模式已有简报,不重复注入。
- **TDD**:`test_discussion_instructions_contain_pulse`(有超期伏笔→讨论 prompt 含该条;B-3 防:断言具体文本而非标题)、`test_write_mode_not_double_injected`。

### T4 决策收件箱 v1(0.5d)
- **改动**:`GET /inbox?work=` 聚合已有等人事项:needs_human 章(journal 扫描,复用 blind-pack 判定)/蒸馏升格候选(待批表)/pulse decision 级;前端右栏新 tab「收件箱」+Rail badge 计数;每项带跳转动作。
- **TDD**:`test_inbox_aggregates_three_sources`、`test_inbox_empty_book`;**DoD-pw**:badge 计数/列表渲染/跳转。

### T5 时机 A/B/D + 防烦协议(0.5d)
- **改动**:前端 ChiefDock:进章时拉 pulse,若有 decision 且本章该维未开过口→dock 顶部主编开场白一条(带"因为…"+「聊」「静音此维」);落稿后(save 响应含 nudge+)→摘要条+「要我修吗」;卡文探测=前端计时(正文聚焦 N 分钟零输入或删>增)→一条 M9 三处方话术。静音=localStorage `s3.pulse.mute.{dim}`;开口记账=localStorage `s3.spoke.{work}.{seq}.{dim}`。
- **DoD-pw**:造超期伏笔→进章开场白恰一条;再进不重复;静音后不出;**开口计数≤4/章审计脚本**。
- **坑防**:主动性反噬(调研)→开场白必含依据短语;绝不在输入框聚焦时弹。

**P0 门**:全量 pytest 绿+build 绿+pw 五连绿;真机(loop-qa):手造超期伏笔→pulse decision→进章开场白→点「聊这个」→主编讨论回复中引用该伏笔(时机C 实证);**对抗审查一轮**(动了讨论 prompt 组装与 ChiefDock);台账 D-030~031。

## 二、P1 期:Pilot+授权矩阵+Inbox+连写("一句想法→一章交付",预算 3-3.5 天)

### T6 Pilot 状态机核心(1d)
- **改动**:新 `scribe3/pilot.py`:`STATES`(idle/outline_proposed/beats_ready/deduced/drafting/checked/delivered/finalized)、`AUTHZ`(默认矩阵+book 级覆盖配置,**宪法锚字典硬编码不可覆盖**)、`step(store, seq, actor)` 纯函数式推进(读状态→执行→写状态→返回 {state, gate, artifacts})。状态落 `chapter.pilot_state`+`pilot_log`(journal 复用,stage=`pilot_ch{n}_{state}`)。端点:`POST /pilot/step`、`GET /pilot/status`、`POST /pilot/approve|revise`(propose 停靠处理)。
- **并发**:进入执行态时登记 `_loop_inflight`(与 save/dedup/loop 互斥体系共用);pilot step 自身同章互斥。
- **TDD**(tests/test_pilot.py):`test_full_transition_path_stub`(stub 执行器,idle→finalized 全链)、`test_constitution_gates_never_auto`(连写模式下 finalized 前仍停;**参数化四锚**)、`test_propose_gate_waits_and_approve_advances`、`test_needs_human_parks_with_reason`、`test_crash_recovery_resumes_from_db_state`(重建 store 后 status 正确)、`test_pilot_respects_loop_inflight`(409)、`test_authz_override_cannot_touch_anchors`(book 配置试图把终选改 auto→拒)。
- **坑防**:状态卡死→每状态带 `updated_at`,status 端点对 stale(>30min 执行态)报 `stalled` 并可 `POST /pilot/reset-step`(回上一停靠点,不丢版本库任何稿)。

### T7 执行器接线(1d)
- **改动**:pilot 执行表:outline←chat_write(phase=plan) 复用组装链;beats←同;deduce←演绎生成链(scene_truth 注入已修);drafting←`run_chapter_loop`(journal/result.json 原样);checked←post_check 全量;delivered←留版(label=「pilot交付·第N稿」)+交付卡数据落 pilot_log。**全部经既有函数,禁止新写生成逻辑**(北极星宪法:regenerate 复用完整组装链,同理)。
- **TDD**:`test_executor_calls_existing_chain`(monkeypatch 计数断言调的是 chat_write 组装/run_chapter_loop 本尊)、`test_draft_failure_parks_not_crashes`、`test_delivered_leaves_version_with_label`。
- **真机**:loop-qa 单章 idle→delivered 逐 step 手动推进全绿。

### T8 想法收件箱+路由(1d)
- **改动**:迁移 069 `idea` 表 {text, status: pending|routed|done, route_kind, target_seq, created_at};`POST /ideas`;路由=LLM 判(prompt 输出 {kind: outline|steer|setting|revise|unclear, target_seq, proposal}),产物按 kind:outline→该章大纲提案(propose 级进收件箱);steer→写入该章 pilot steer 字段;setting→**approve 级**提案(动圣经);revise→span 修订提案;unclear→主编回一句澄清问题(只一句)。前端:ChiefDock 输入框加「💡 记想法」发送模式(或 `#想法 ` 前缀),回执显示路由结果。
- **TDD**:`test_idea_route_four_kinds`(stub LLM)、`test_setting_idea_always_approve`(宪法)、`test_unclear_asks_one_question`、`test_idea_roundtrip_persist`。
- **DoD-pw**:发一句想法→回执含路由去向。

### T9 交付卡+工作日志(0.5d)
- **改动**:交付卡数据=delivered 时组装 {字数, 体检摘要, 本章伏笔埋/收, 低置信段}——低置信段来源:交付前主编自审 prompt("列出你拿不准的≤3 处,引原文短语"),存 pilot_log;前端交付卡组件(收件箱内渲染,含「终选定稿(approve)」「让主编再修」「查看两版」动作)。工作日志:前端左栏「日志」折叠面板,渲染 pilot_log 时间线(每行=动作+因为)。
- **TDD**:`test_delivery_card_fields`、`test_low_confidence_max3`;**DoD-pw**:交付卡渲染+终选按钮走既有 finalize 链。

### T10 连写模式(0.5d)
- **改动**:`POST /pilot/run {until_seq}`:后端 BackgroundTasks 自链(step 循环:propose 级自动放行、approve 级硬停靠、needs_human 停靠、日帽 RuntimeError 停靠并如实记因);每章交付卡照发;`POST /pilot/pause` 随时叫停(下一 step 边界生效,不打断在途 loop)。
- **TDD**:`test_run_until_stops_at_constitution`(到 finalized 前停)、`test_run_pauses_on_needs_human`、`test_run_respects_daily_cap`(monkeypatch 帽→停靠+原因)、`test_pause_at_step_boundary`。
- **坑防**:oversight 衰减→连写中每章交付卡必含低置信段;运行状态进 /pilot/status(前端 PulseBar 加「连写中 第N章」徽标)。

### T11 收件箱 v2:propose 停靠+放行/修改闭环(0.5d)
- **改动**:收件箱渲染 pilot 停靠项(大纲提案可就地编辑后 approve;交付卡见 T9);全部动作走 /pilot/approve|revise。
- **DoD-pw**:大纲提案→就地改一句→放行→pilot 推进到下一态。

**P1 门**:全量绿+build+pw 全套;**金标真机①**:pilot-qa 新书(或 loop-qa 新章段)一句想法(`POST /ideas`)→路由→连写模式→交付卡,中途零人工(除最终 approve);**金标真机②**:全程主编主动开口≤4 次/章(journal 审计);**独立对抗审查(必须)**——本期动了写作主链编排+新增自动写库路径,审查面:状态机死锁/宪法锚旁路/并发互踩/连写失控(预算/停靠)/交付卡真实性(低置信段是否如实);台账 D-032~035。

## 六、总验收(金标三条,全过=本方案"完美实现")

1. **一句想法→一章交付**:pilot-qa 真机,`POST /ideas {"text":"第2章:哑姑在井边第一次开口,别煽情"}` → 连写 → 交付卡(含低置信段)→ 人工终选。中途零人工干预,全程日志可审计。
2. **主动性可感且不烦**:同章旅程中 PulseBar 状态实时变化;主编主动开口≤4 次且每次带"因为…";静音生效。pw 脚本+人工核录屏各一遍。
3. **《纸命》第 5 章作者首用**(作者参与项,不阻塞收官):用 Inbox+连写写一章,ai_grade 评分 ≥4.3(乱世铜炉级门槛),流程主观顺手度由作者裁决。

收官交付:总验收报告(含三金标证据/偏离/遗留)+台账 D-030 起全记录+memory 更新。
