## 1. 在回路中的位置与职责

### 1.1 一句话定位

本文定义 **Scribe 协作回路的界面层**:人的两件事(想象 + 意见)如何以最低摩擦进入系统;AI 的三类输出(选项、成稿、依据)如何以最清晰的方式呈回作者。工程2 不执行 AI 逻辑——它是回路的"手"和"眼",把内核1 定义的四件套交互(想象捕获 / 北极星 / OptionSet 选择 / FeedbackNote 反馈)落成真实可用的界面。

### 1.2 界面的第一性问题

旧设计犯的错:把"功能完备"当成界面目标,结果是一堆面板堆叠——一致性检测、伏笔追踪、设定圣经、AI 操作都平等地摆在屏幕上抢夺注意力。

正确的问题是:**界面在任何时刻的视觉重心应该是什么?**

答案由分工决定:人只做两件事,界面就只为这两件事设计视觉重心。

```
界面的视觉层次:

  第一层(前景,随时可及):
    - 想象快速捕获入口(⌘I,全局浮层)
    - 北极星常驻条(顶部,始终可见)
    - OptionSet 选择卡(生成后,正文区占主视图)
    - FeedbackNote 输入(选中段落后内联触发)

  第二层(中景,工作区):
    - 正文区(成稿 + Segment 批注点)
    - 大纲树(左栏导航)
    - 重做 diff 预览(生成完成后覆盖正文区)

  第三层(后台,按需查阅):
    - 连贯性 / 一致性侧栏(角标计数,折叠)
    - 伏笔侧栏(角标计数,折叠)
    - 设定圣经侧栏(按需查阅)
    - 可解释面板(每段折叠展开)
```

**铁律**:门槛层(连贯/伏笔/一致性)是安静的角标和折叠侧栏,**绝不主动打断写作**。内核层(想象/北极星/OptionSet/FeedbackNote)才是界面的主角。

### 1.3 与其他层的职责边界

| 层 | 文档 | 本文的接口关系 |
|---|---|---|
| 内核1 | 内核1-作者协作回路 | 本文实现内核1 §5.2 定义的 REST/SSE 接口,呈现四件套交互 |
| 实现层 | 实现2-写作生成 | 通过 SSE 接收生成进度和成稿,展示流式输出和 diff |
| 实现层 | 实现3-编排引擎 | 通过 SSE 接收任务状态,前端状态机对应 |
| 门槛层 | 门槛1-连贯性保障 | 读取 ConsistencyFlag,展示角标,提供裁决交互 |
| 门槛层 | 门槛2-设定圣经 | 读取 SettingItem/Character,在设定侧栏展示 |
| 工程层 | 工程4-版本与回流 | 读取 Snapshot 版本链,展示 diff,触发接受/拒绝 |
| 工程层 | 工程5-API | 所有接口调用均通过工程5 定义的端点 |

**本文不负责**:AI 生成逻辑、一致性检测算法、版本快照存储、LLM 调用。

## 2. 设计目标与百万字挑战

### 2.1 设计目标

| # | 目标 | 可度量指标 |
|---|---|---|
| U-1 | 想象捕获低摩擦 | 从"有想法"到"已捕获"≤ 3 步,≤ 10 秒 |
| U-2 | 北极星始终可见 | 任意页面滚动位置均可看到北极星摘要条 |
| U-3 | OptionSet 决策清晰 | 差异矩阵一屏展示完毕,不需要横向滚动 |
| U-4 | FeedbackNote 端到端 | 从选中段落到重做草稿出现 ≤ 90s;确认步骤 ≤ 2 次点击 |
| U-5 | 门槛不打扰 | 一致性/伏笔提示响应时间 ≤ 500ms;不阻断任何写作动作 |
| U-6 | 百万字流畅 | 500 章大纲树虚拟滚动帧率 ≥ 60fps;单章编辑器内存 < 50MB |
| U-7 | 可解释可信任 | 每段可一键展开"引用了哪些想象/设定/记忆/伏笔" |

### 2.2 百万字下的具体挑战

**挑战 I:OptionSet 在百章后的决策疲劳**
写到第 200 章时,作者已做过 50+ 次方案选择。如果每次 OptionSet 都长得一样,作者会产生"走流程"心态而不是真正思考。
→ 解法:OptionSet 卡片的视觉权重随"与北极星的偏差幅度"动态调整;与历史高相似方案相比时,自动标注"与 §87 的选择类似"。

**挑战 II:FeedbackNote 链式积累**
500 章 × 平均 3 轮 = 1500 条 FeedbackNote。历史查看面板不能全量渲染。
→ 解法:历史分页(limit=20);虚拟列表;按 target_id 过滤只看当前段落的历史链。

**挑战 III:SSE 流式更新与编辑器并发**
AI 生成一章 30-120 秒,作者不能干等。需要能在 §14 生成时去批注 §13。
→ 解法:草稿暂存区与编辑器主文档隔离;生成完成后通知徽章;不中断主编辑器。

**挑战 IV:大纲树 500+ 节点**
500 章 + 设定圣经入口 = 700+ 树节点,全量 DOM 渲染帧率崩坏。
→ 解法:tanstack-virtual 虚拟滚动;折叠未激活卷;树节点扁平化后只渲染视口 ±5 个。

**挑战 V:北极星偏离检测的误报率**
偏离检测每章运行一次,如果误报率高,作者会无视所有提示。
→ 解法:软偏离只在右下角显示 5 秒 Toast;硬红线违反才在北极星常驻条显示红点;作者一键"标记误报"回流阈值。

**关键布局决策**:

1. **北极星常驻条**置于顶部,横贯全宽——任何章节、任何滚动位置都可见。这是唯一一个"不需要点击就能看到"的全局上下文。

2. **右栏分区**:上半部是"主动输入区"(想象库、意见历史),下半部是"门槛区"(连贯/伏笔/设定),门槛区默认折叠。视觉重心在上。

3. **OptionSet 生成时**:中央正文区整体切换为 OptionSet 选择卡布局,不是弹框——决策是主工作,不是插曲。

4. **FeedbackNote 触发**:不是独立面板,是选中段落后在正文内联弹出输入框——保持作者视线在文字上。

### 3.3 北极星常驻条

#### 3.3.1 设计原则

北极星(AuthorIntent)是 AI 每次执行取舍的最高裁判。界面上,它必须始终可见——不需要用户主动查看,因为"忘记北极星"正是长篇写作中最危险的事。

常驻条不是"设置入口",是**活的上下文**——偏离状态实时显示在上面。

#### 3.3.2 常驻条 ASCII 详图(正常对齐态)

```

```

### 3.4 OptionSet 选择卡

#### 3.4.1 设计原则

OptionSet 出现时是主事件——不是弹框插曲,而是正文区的主内容切换。作者的任务在这个时刻就是做判断,所以整个中央区交给它。

### 3.8 门槛后台呈现:连贯/伏笔角标 + 折叠侧栏

#### 3.8.1 铁律:门槛隐形

00 §3 第8条:门槛隐形,内核显形。连贯性/伏笔/一致性是"写得对"的 table stakes——它们存在、它们工作,但它们**绝不打断作者的创作流**。

前端实现这一原则的具体约定:

| 门槛信息 | 前端呈现方式 | 绝不做的事 |
|---|---|---|
| 一致性 Flag | 大纲树章节节点角标 ⚠N | 不自动弹框,不中断输入 |
| 伏笔超期 | 大纲树章节节点角标 🧵N;右栏折叠区 | 不播放声音,不强制点击 |
| 设定冲突 | 设定圣经侧栏相关项 ⚠ 图标 | 不全屏提示 |
| ConsistencyFlag(new) | 右栏"门槛"区角标更新 | 不中断 SSE 生成 |

## 6. 失败模式与缓解

### 6.1 SSE 连接中断

```
场景: AI 生成中网络断开
缓解:
  1. EventSource.onerror → 自动重连(指数退避: 2s/4s/8s,最多3次)
  2. 重连携带 lastEventId,后端从断点续流
  3. 3 次失败 → 转 ERROR 状态,保留已生成草稿供参考
  4. Toast 提示"连接中断,已保存 847 字草稿"

// 实现:
source.onerror = () => {
  if (retryCount++ < 3) {
    setTimeout(() => reconnect(), 2 ** retryCount * 1000);
  } else {
    setTaskError(taskId, 'NETWORK_ERROR');
  }
};
```

### 6.2 编辑器数据丢失

```
场景: 未保存就关闭页面
缓解:
  1. Tiptap 内容每 5 秒自动存 localStorage(key: draft-${chapterId})
  2. beforeunload 事件同步保存一次
  3. 重新打开时,若 localStorage 比数据库新 → 提示"恢复未保存草稿?"
  4. 本地草稿超过 7 天自动清除
```

### 6.3 OptionSet 方案差异不足

```
场景: 三个方案本质相同,作者全都不满意
缓解:
  1. 每张卡片显示差异矩阵(情感/代价/后果三行),帮助作者快速识别差异程度
  2. [我都不满意,重新生成] → 重新生成,同时将"三方案均不满意"记录为 PreferenceSignal
  3. 第3次不满意时提示:"是否想告诉我您偏好什么方向?"
     → 打开 FeedbackNote 输入框,target_type="option"
```

### 6.4 北极星偏离检测误报疲劳

```
场景: 偏离检测误报率高,作者开始无视所有提示
缓解:
  1. 软偏离只以 Toast 形式出现,5 秒消失,从不阻断操作
  2. 一键"标记误报"回流,动态提高阈值
  3. 若某类红线连续 3 次被标记为误报,建议"您是否要细化这条红线的描述?"
  4. 可在北极星设置中关闭"软偏离提示"(hard 红线无法关闭)
```

### 6.5 大纲树拖拽伏笔冲突

```
场景: 拖动章节导致伏笔 F/T/P 时序关系错乱
缓解:
  1. 拖拽前检:前端预计算受影响伏笔
  2. 发现冲突 → 弹出警告对话框,列出受影响伏笔
  3. 用户确认后 → 执行拖拽 + 触发后端伏笔重排扫描
  4. 完成后伏笔侧栏刷新
```

### 6.6 百万字下大纲树卡顿

```
场景: 500+ 章节全部展开,滚动帧率 < 30fps
缓解:
  1. tanstack-virtual 虚拟滚动:只渲染视口 ±5 节点
  2. 默认只展开活跃章节所在卷,其余折叠
  3. 搜索模式:直接展示搜索结果列表(跳过树渲染)
  4. 节点 > 1000 时,禁用所有折叠动画(CSS transition: none)
```

### 6.7 FeedbackNote 解析误解导致错误改写

```
场景: AI 误解意见,改写方向完全错误
缓解:
  1. parse_confidence < 0.7 强制确认对话
  2. diff 预览时作者看到的是完整 side-by-side 对比,不是仅看新版
  3. 拒绝接受重做版 → 原版保持不变,可重新提意见
  4. 链式反馈深度 > 3 时提示"是否需要检查北极星或调整品味偏好?"
```

## 8. 证据与引用

**【稳定知识】想象捕获入口的"低摩擦"原则**
HCI 研究中"创意捕获工具"的核心结论:摩擦越低,捕获率越高,创意遗失越少。≤3步/≤10秒是经验上限。参考快速记录工具(Drafts, Bear 等)的产品设计惯例。【稳定知识,无需 arXiv】

**【已核实】大纲树虚拟滚动支持 500+ 节点**
tanstack-virtual 已在生产环境验证可处理 10k+ 节点的虚拟列表,500 章场景远低于其性能边界。结合 ProseMirror 的按需加载,单章编辑器内存 < 50MB 是可达目标。【工程实践,设计决策】

**【已核实】百万字禁止一次性加载全书进编辑器**
BooookScore(arXiv 2310.00785)测试的长文生成场景上下文约束就说明 LLM 需分章处理;同理前端编辑器在 10 万字以上必须分章加载,否则 ProseMirror 内存与渲染性能均崩溃。【工程推论,已核实】

**【设计决策】OptionSet 占据中央区而非弹框**
方案选择是主工作,不是插曲——把它做成弹框意味着作者的注意力还留在"正文"上,做成中央区主内容意味着它是当前任务。这是产品优先级的界面化表达。【设计决策】

**【设计决策】软偏离只显示 Toast,硬红线才显示 banner**
来自 00 §3 第8条「门槛隐形,内核显形」的直接推论:偏离检测是门槛层机制(保证"对"),不应喧宾夺主。只有确定性高(硬红线)才值得强打断。【设计决策】

**【设计决策】FeedbackNote 在正文内联触发而非独立面板**
"提意见"是作者在读正文时产生的即时反应——如果要跳转到独立面板才能提意见,这个反应窗口就消失了。内联触发保留了"看到就说"的自然性。【稳定知识,UI交互原则】

**【稳定知识】diff 预览是接受AI修改前的必要安全感**
用户研究显示,在接受 AI 生成内容前看到具体的改动范围,显著提高用户对 AI 输出的信任度和采纳率。diff 展示不是可选功能,是"让作者保持控制感"的必要设计。【稳定知识】

**【设计决策】门槛层折叠于右栏下区,内核层(想象库/意见历史)置于右栏上区**
视觉重心的物理位置对认知优先级有直接影响(眼动研究)。把门槛信息放在折叠区下部,强化了"它们重要但不紧急"的心理预期。【设计决策,稳定知识引申】

## 9. 开放问题

**O-1:OptionSet 在中央区的过渡动画**
正文区切换为 OptionSet 视图时,过渡动画如何设计?立即切换可能造成"迷失感";渐进动画需要约 300ms。具体动效方案需 Phase 2 的用户测试反馈。

**O-2:想象捕获浮层的快捷模板**
浮层中是否需要提供"快捷输入模板"(如"我想要一场…""如果…的话")?这可能降低捕获质量(模板引导比自由输入更平庸),也可能提高捕获频率(降低空白焦虑)。需 A/B 测试确定。

**O-3:FeedbackNote 快捷模板的边界**
目前设计了[太长][节奏慢][不像角色]等快捷模板。模板数量和覆盖范围如何平衡"降低摩擦"和"过度简化意见表达"?建议 Phase 2 分析真实意见的分布,根据实际高频批评调整。

**O-4:移动端/iPad 的布局适配**
三栏布局在 iPad 上是否需要专门的"审阅模式"(只有正文和 FeedbackNote 入口)?还是折叠左栏的响应式方案就够用?需要用户测试。

**O-5:北极星常驻条的高度与文字截断**
reader_feeling 可能很长(100+ 字)。常驻条固定高度两行时,超长内容必须截断——但截断位置可能切断关键语义。目前方案是"展开/收起"切换,需测试不同长度的体验。

**O-6:OptionSet 历史的价值呈现**
作者在第200次做选择时,是否应该展示"您上次在类似情境中选了什么"?这可以帮助作者保持一致性,也可能让作者陷入"历史依赖",丧失新鲜感。Phase 2 评估。

**O-7:百万字下意见历史的可视化**
1500 条 FeedbackNote 历史是重要的创作记录——但怎么让作者从中发现规律("我总是在意人物塑造问题")而不只是看线性历史?可能需要一个"意见统计/品味分析"子界面,属 Phase 4 特性。

## 与主编(内核0)的对齐增补

界面是 [内核0-主编智能体](内核0-主编智能体.md) 的脸。两处新增:

1. **主编对话区(主交互)**:除三栏外,主编是常驻对话体——你说话、它回话/提议/发起讨论。`DiscussionThread` 渲染为对话气泡里的"责编批注卡"(硬冲突红/软建议黄,带证据跳转、备选按钮、一键"按我说的"覆盖);内嵌的 OptionSet 以选项卡呈现。
2. **主编札记(主动引擎,对齐 内核0 §3.5)**:`ProactiveInsight` 以**安静的"主编札记"面板**呈现(角标计数,不弹窗不打断),按 severity 排序、可跳转证据、可 ack/acted/dismissed。这与门槛侧栏(连贯/伏笔)同属"后台低打扰"区。
3. 接口见 [工程5b-主编与协作API](工程5b-主编与协作API.md)(discussion-threads / proactive-insights)。
