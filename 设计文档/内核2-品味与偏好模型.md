## § 1. 在回路中的位置与职责

### 1.1 系统回路定位

Scribe 的协作回路由三件事支撑(见 00 §1):A. 捕获并放大想象与品味;B. 默认对抗趋均值;C. 维持连贯一致。品味与偏好模型是 **A 的第二支柱、B 的核心依据**。

```
        ┌─────────────────────────────────── 人(你)────────────────────────────────────┐
        │  ① 想象  →  内核1 捕获                                                        │
        │  ③ 意见  →  本模块持续学习 ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ←            │
        └─────────────────────────────────────────────────────────────────────────────┘
                                                           ↑ 回流
   ┌──────────── AI 全程主笔 ──────────────────────────────────────────────────────────┐
   │  实现1(规划)  ← 品味约束注入 ←──────────────────── TasteModel                     │
   │  实现2(写作)  ← 品味约束注入 ←──────────────────── TasteModel                     │
   │  内核3(反平庸) ← "好"的判断标准 ←──────────────── TasteModel                      │
   │  工程6(度量)  ← "好"的评估锚点 ←──────────────── TasteModel                      │
   └──────────────────────────────────────────────────────────────────────────────────┘
```

**一句话职责**:持续从作者行为(选、说、改、评、收藏)中提炼"这个作者认为什么是好"——形成结构化的 `TasteModel`,并将它注入每一次 AI 生成,使系统"越用越懂你的书"。

### 1.2 与其他模块的分工边界

| 模块 | 关系 | 边界说明 |
|---|---|---|
| **内核1-作者协作回路** | 上游来源 | 内核1 采集 `FeedbackNote`、选择的 `OptionSet.chosen_option_id`、打分;本模块消费并结构化为 `PreferenceSignal` |
| **内核3-反平庸与文学质量** | 消费 `TasteModel` | 内核3 的"好"的判断标准由 `TasteModel.learned_preferences` 提供;负面清单 `negative_list` 驱动 AntiSlop |
| **实现1-分层规划** | 消费注入 | 在大纲生成阶段注入作者的题材倾向、结构偏好、雷区清单 |
| **实现2-写作生成** | 消费注入 | 在 Prompt 组装时注入文风偏好、`StyleExemplar` few-shot、负面清单约束 |
| **工程6-质量度量** | 双向 | `TasteModel` 提供"好"的个性化定义;工程6 的人评分数(H1/H2/H3)回流成 `PreferenceSignal` |
| **门槛1-连贯性保障** | 独立不交叉 | 门槛1 管"写得对";本模块管"写得好";两者不竞争 |

## § 2. 设计目标与百万字挑战

### 2.1 设计目标

| 目标 | 可测量描述 | 证据级别 |
|---|---|---|
| **信号有效性** | 作者产生 ≥ 10 个高置信度 `PreferenceSignal` 后,AI 生成文本的人评 H1 较基线提升 ≥ 0.4 分(1–5 量表) | 【设计决策,需实验验证】 |
| **冷启动可用** | 新作者、零信号时,系统仍能以 `TasteModel` 默认值 + `StyleExemplar` 上传完成合格生成 | 【设计决策】 |
| **注入感知率** | 在 Prompt 中注入 `TasteModel` 约束后,LLM 对约束的遵从率(人工抽评)≥ 70% | 【设计决策,需实验验证】 |
| **漂移可控** | 百万字作品中,偏好模型对早期偏好的"过拟合衰减"通过滑动窗口权重策略控制在可接受范围 | 【设计决策】 |
| **可解释性** | 作者可在 UI 上查看"系统认为你偏好X的理由",每条偏好均有来源 Signal ID 可追溯 | 【设计决策】 |
| **跨作品迁移** | 新作品创建时,可选择从作者全局 `TasteModel`(work_id=NULL)继承偏好作为起点 | 【设计决策】 |

### 2.2 百万字下的核心挑战

**挑战 A:长期偏好漂移(Taste Drift)**

百万字创作跨越数月甚至数年。作者自身的审美会演进——第一个月觉得"意象密集"好,第六个月开始偏好"克制留白"。固化的 `TasteModel` 会越来越不匹配作者的当前审美,反而成为束缚。

**设计应对**:偏好更新使用指数衰减权重——越近的 Signal 权重越高;同时保留历史版本链(`version` 字段),支持作者显式回滚。

**挑战 B:信号规模与噪声**

百万字作品可能累积数千个 `PreferenceSignal`。其中大量是弱信号或噪声(例如作者因疲劳随机点了选项 A,并非真实偏好)。直接平均会产生"均值偏好",失去个性。

**设计应对**:信号分级(polarity 权重 × 来源可信度系数),弱信号不直接写入模型;批量信号用贝叶斯更新而非简单平均。

**挑战 C:冲突信号处理**

同一维度可能出现正负冲突信号——作者昨天说"节奏要快",今天又说"不要太急"。简单覆盖会导致模型振荡。

**设计应对**:冲突信号触发"偏好澄清"机制:在下次人机交互时以低摩擦方式呈现冲突并确认,结果作为高权重 Signal 写入。

**挑战 D:避免过拟合到早期偏好**

作者在第一章花了大量时间调整风格,产生了密集的强信号。后续生成一直被这批早期信号主导,锁死了风格空间。

**设计应对**:早期信号权重随时间衰减(时间衰减因子),并用滑动窗口(最近 N 章的信号)作为主要驱动,全局积累信号作为"底色"而非"命令"。

**挑战 E:"好"的标准因流派而异**

玄幻修仙的"好"与纯文学的"好"标准截然不同。`TasteModel` 不能有硬编码的"文学性"优越感。

**设计应对**:`TasteModel.learned_preferences` 使用流派相对化设计——所有偏好描述符均以作者自身的信号为基准,不与"客观文学标准"绑定;`StyleExemplar` 由作者自己提供,而非系统预设。

### 3.2 PreferenceSignal — 信号采集

#### 3.2.1 信号来源分类与结构化方式

`PreferenceSignal` 是 `TasteModel` 的原料。每一条信号对应作者一次可观测的偏好表达行为。

```
PreferenceSignal (00 §4.1):
  id          : uuid v7
  owner_id    : str              — 作者 ID
  work_id     : UUID | NULL      — NULL = 跨作品全局信号
  source      : enum             — 信号来源类型(见下表)
  signal      : jsonb            — 结构化信号内容(因 source 不同而异)
  polarity    : +1 | -1          — 正信号(更多/更好) vs 负信号(更少/删除)
  weight      : float [0,1]      — 信号强度(由来源类型×置信度计算)
  created_at  : timestamptz
```

**五类来源的详细结构化方式**:

---

**来源 1:`option_choice` — 从多方案选择中学品味**

当作者在 `OptionSet` 中选择了某个方案时,触发此类信号。

```jsonb
-- signal 字段示例
{
  "option_set_id": "<uuid>",
  "chosen_option_id": "<uuid>",
  "rejected_option_ids": ["<uuid>", "<uuid>"],
  "decision_point": "chapter_43_climax_scene_approach",
  "chosen_descriptors": {
    "intensity": "restrained",       — 作者选了克制版
    "pov_distance": "close",         — 近景视角
    "resolution_speed": "slow"       — 慢节奏展开
  },
  "rejected_descriptors": [
    {"intensity": "explosive", "resolution_speed": "fast"},
    {"intensity": "melodramatic", "pov_distance": "distant"}
  ],
  "inferred_preferences": [
    {"dimension": "emotional_tone", "direction": "restrained", "confidence": 0.75},
    {"dimension": "pov_distance", "direction": "close", "confidence": 0.70}
  ]
}
```

权重计算:
```
weight = 0.6                         — option_choice 基础可信度(作者主动选择,中等可信)
       × confidence_of_inference     — 推断置信度(来自 OptionDescriptorDiff 分析)
```

之所以不给满分:作者选择受疲劳、情绪、当前情节约束的干扰,不一定完全代表美学偏好。

---

**来源 2:`feedback` — 从自然语言意见中提炼偏好**

作者提交 `FeedbackNote.nl_critique` 时,触发此类信号。解析器提取其中的风格信号。

```
[解析 Prompt 骨架]

[SYSTEM]
你是写作系统的偏好信号提取器。
从作者对 AI 生成文本的自然语言意见中,提取可结构化的文风偏好信号。
仅提取风格维度的偏好信号;忽略情节内容类批评。

[INPUT]
作者意见原文: "{nl_critique}"
意见目标对象: {target_type}/{target_id}
目标对象的上下文摘要(100字): "{target_context}"

[OUTPUT — 严格 JSON]
{
  "has_style_signal": true/false,
  "signals": [
    {
      "dimension": "<维度标识,见 DIMENSIONS 枚举>",
      "direction": "increase" | "decrease" | "maintain" | "avoid",
      "intensity": "strong" | "moderate" | "weak",
      "confidence": 0.0-1.0,
      "evidence_quote": "<支持此判断的意见原文片段>",
      "polarity": 1 | -1
    }
  ],
  "negative_patterns": [
    {
      "description": "<作者明确不想要的写法描述>",
      "example_quote": "<意见中的反例引用或null>"
    }
  ],
  "ambiguous": false/true,             — 信号模糊时设为 true
  "conflict_with_hint": "<若与已知偏好冲突,在此说明>"
}

-- DIMENSIONS 枚举(扁平化维度列表):
rhythm_tempo | sentence_length | imagery_density | show_tell_ratio
pov_distance | emotional_tone  | dialogue_style  | sensory_channels
genre_flavor  | plot_density   | character_depth | twist_frequency
theme_weight  | pacing_control | description_vs_action
```

权重计算:
```
weight = base_weight[intensity] × confidence
base_weight = {"strong": 0.85, "moderate": 0.60, "weak": 0.35}
```

示例:

| 作者意见原文 | 提取信号 | polarity | weight |
|---|---|---|---|
| "这段太平了,没有张力" | `emotional_tone → increase_tension` | +1 | 0.72 |
| "AI 腔太重,感觉在凑字" | `anti_slop → avoid_inflation` | -1 | 0.85 |
| "节奏还可以,继续" | `rhythm_tempo → maintain` | +1 | 0.35 |
| "人物对话太假,说话像机器人" | → `negative_list` 新增 `dialogue_robotic_pattern` | -1 | 0.80 |
| "意象很好,我喜欢这种写法" | `imagery_density → high, maintain` | +1 | 0.75 |

---

**来源 3:`rating` — 从打分/评估中学偏好**

作者对章节或段落打分(H1/H2/H3,见工程6),或在 UI 上点击"喜欢"/"不喜欢"按钮。

```jsonb
-- signal 字段示例(H2 人物感染力评分)
{
  "eval_type": "h2_pleasure",
  "score": 4.5,             — 本次打分
  "baseline_score": 3.1,    — 该作品近期均值(用于判断正负偏差)
  "target_type": "chapter",
  "target_id": "<uuid>",
  "chapter_style_tags": {   — 本章的文风标签(由内核3/实现2记录)
    "rhythm": "急促",
    "imagery_density": "低",
    "show_tell_ratio": "0.8"
  },
  "inferred_preferences": [
    {
      "dimension": "rhythm_tempo",
      "direction": "fast",
      "confidence": 0.55    — 打分推断置信度较低,因为章节得分受多因素影响
    }
  ]
}
```

权重计算:
```
score_deviation = score - baseline_score
weight = sigmoid(|score_deviation| × 2) × 0.50    — rating 置信度上限 0.5
                                                    — 因为高分的原因多元,不一定纯文风
polarity = sign(score_deviation)                   — 高于均值→正信号,低于均值→负信号
```

**明确标记("喜欢此段"/"不喜欢此段")** 是 rating 的强化形式:

```jsonb
{
  "eval_type": "explicit_like",     — 作者点击了"喜欢此段"
  "segment_id": "<uuid>",
  "segment_style_tags": { ... },
  "weight_override": 0.80           — 明确标记强制权重 0.8,不做推断折减
}
```

**来源 4:`revision_diff` — 从人工修订中学偏好**

作者对 AI 生成文本做了手工修改(Snapshot.created_by="human"),系统对比 diff 提取风格变化方向。

```
[diff 分析流程]

输入: original_text (AI生成), revised_text (人工修订后)
步骤:
  1. difflib.unified_diff 提取增删段落对
  2. 对每对 (removed, added):
     a. 跳过纯情节类改动(人名/地名/事件替换,无风格信息)
     b. 提取可比较的风格特征:
        - 句长统计(average_chars_per_sentence)
        - 情感词密度(emotional_word_density)
        - 感官词频(sensory_word_count)
        - 对话比例(dialogue_ratio)
        - 意象类词频(imagery_word_count)
        - 动作词比例(action_verb_ratio)
     c. 计算 removed_features vs added_features 的方向差
     d. 差值超过阈值(默认 15%)才产生信号

输出信号示例:
  removed 句长均值: 28字  → added 句长均值: 14字
  → dimension: sentence_length, direction: shorten, confidence: 0.65

  removed 情感词密度: 0.12 → added 情感词密度: 0.03
  → dimension: show_tell_ratio, direction: more_show, confidence: 0.70

  removed 意象词频: 2/千字 → added 意象词频: 8/千字
  → dimension: imagery_density, direction: increase, confidence: 0.75
```

权重计算:
```
weight = 0.65 × confidence    — revision_diff 可信度较高(明确的行为证据)
                               — 但不到满分:作者有时改的是情节,不是文风
```

`revision_diff` 信号同时写入 `negative_list`:被删除的 AI 腔片段作为 `negative_pattern` 样本:

```jsonb
-- 负面模式提取示例
{
  "pattern_type": "sample_segment",
  "description": "作者删除的典型 AI 腔片段",
  "example_text": "他终于明白了,生命的意义在于…(被删的升华句)",
  "inferred_slop_category": "E_FORCED_ELEVATION",
  "severity": "high",
  "source": "revision_diff"
}
```

**来源 5:`exemplar` — 从收藏/上传范本中学偏好**

作者上传 `StyleExemplar`(收藏的好段落、偏好的参考文本),或显式标记某段 AI 生成为"好范例"。

```
[StyleExemplar → PreferenceSignal 转化流程]

输入: StyleExemplar { sample_text, style_descriptors, label, scope }
步骤:
  1. 提取 style_descriptors 中的每个维度值
  2. 对比 TasteModel.learned_preferences 中的当前偏好值
  3. 差异超过阈值的维度产生正信号(朝范本方向移动)

输出信号示例:
  StyleExemplar.style_descriptors.rhythm = "急促"
  TasteModel.learned_preferences.rhythm_tempo = {"舒缓": 0.7, "急促": 0.3}
  → dimension: rhythm_tempo, direction: increase_fast, confidence: 0.85

信号权重:
  weight = 0.90    — exemplar 是最强信号(作者主动提供的正面样本)
```

`exemplar` 同时直接写入 `TasteModel.positive_exemplars`——不只是信号,也是库存。

#### 3.2.2 信号过滤与质量控制

```python
SIGNAL_QUALITY_RULES = [
    # 规则 1: 弱信号丢弃
    {"rule": "weight < 0.30", "action": "discard",
     "reason": "过弱信号引入噪声大于价值"},

    # 规则 2: 冷启动期(信号数 < 5)保守模式
    {"rule": "model.signal_count < 5", "action": "buffer_only",
     "reason": "冷启动期不更新模型,仅积累"},

    # 规则 3: 同一章节连续相反信号(作者可能在实验)
    {"rule": "same_chapter_conflicting_polarity",
     "action": "flag_for_clarification",
     "reason": "作者可能在探索风格,非稳定偏好"},

    # 规则 4: 偏好维度跳变过大(单次变化 > 0.4)
    {"rule": "delta > 0.40", "action": "dampen_to_0.20",
     "reason": "防止单次异常信号过度扰动模型"},

    # 规则 5: 非风格类 feedback 误判为风格信号
    {"rule": "confidence < 0.45 AND source == 'feedback'",
     "action": "discard",
     "reason": "NL 解析置信度过低,情节批评误分类为风格信号"},
]
```

### 3.3 TasteModel — 品味模型结构

`TasteModel` 是 `PreferenceSignal` 的聚合体,是系统"懂你"的核心数据结构。

```
TasteModel (00 §4.1 扩展定义):
  id                  : uuid v7
  owner_id            : str
  work_id             : UUID | NULL         — NULL = 用户级跨作品模型
  positive_exemplars  : jsonb               — 正例库
  negative_list       : jsonb               — 负面清单(AI腔黑名单/反例)
  learned_preferences : jsonb               — 习得偏好(详见 §3.3.1)
  version             : int                 — 每次更新递增
  updated_at          : timestamptz
  signal_count        : int                 — 产生此版本的累积信号数
  reliability_score   : float [0,1]         — 模型可靠度(信号数越多越高)
  deleted_at          : timestamptz         — 软删除
```

#### 3.3.1 learned_preferences — 习得偏好的内部结构

```jsonb
{
  "文风维度": {
    "rhythm_tempo": {
      "distribution": {"急促": 0.30, "舒缓": 0.55, "跳跃": 0.10, "压迫": 0.05},
      "dominant": "舒缓",
      "confidence": 0.72,
      "signal_basis": 24             — 产生此分布的信号数量
    },
    "sentence_length": {
      "distribution": {"极短": 0.10, "短句为主": 0.25, "长短交替": 0.55, "长句为主": 0.10},
      "dominant": "长短交替",
      "confidence": 0.68,
      "signal_basis": 18
    },
    "imagery_density": {
```

### 3.4 学习机制

#### 3.4.1 增量更新算法

```python
def update_taste_model(
    model: TasteModel,
    new_signals: List[PreferenceSignal],
    current_chapter_seq: int,
    total_chapters_done: int,
) -> TasteModel:
    """
    增量更新品味模型。
    使用带时间衰减的指数移动平均(EMA),而非简单平均。
    """

    # 时间衰减因子:越早期的信号权重越低
    # 公式:decay = exp(-(current_chapter - signal_chapter) / decay_horizon)
    DECAY_HORIZON = 50.0     # 每隔50章,历史信号权重衰减到 e^-1 ≈ 0.37

    # 学习率:控制单次信号对模型的扰动幅度
    # 随着信号积累,学习率递减(防止后期单一噪声信号翻盘)
    base_lr = 0.20
    stability_factor = min(1.0, model.signal_count / 50.0)
    effective_lr = base_lr * (1.0 - 0.5 * stability_factor)   # 信号多时最低降到 0.10

    for signal in new_signals:
        # 时间衰减
        signal_chapter = get_chapter_seq_for_signal(signal)
        time_decay = math.exp(-(current_chapter_seq - signal_chapter) / DECAY_HORIZON)
        effective_weight = signal.weight * time_decay

        # 跳过弱信号
        if effective_weight < 0.30:
            continue

        # 按维度更新 learned_preferences
        for pref_signal in signal.signal.get("inferred_preferences", []):
            dim = pref_signal["dimension"]
            direction = pref_signal["direction"]
            confidence = pref_signal["confidence"]
            delta = effective_lr * effective_weight * confidence * signal.polarity

            _apply_preference_delta(model, dim, direction, delta)

        # 更新 anti_slop_sensitivity
        for neg_pattern in signal.signal.get("negative_patterns", []):
            slop_cat = neg_pattern.get("inferred_slop_category")
            if slop_cat:
                current_sens = model.learned_preferences["anti_slop_sensitivity"].get(slop_cat, 0.5)
                new_sens = min(1.0, current_sens + effective_lr * 0.5)
                model.learned_preferences["anti_slop_sensitivity"][slop_cat] = new_sens

    model.version += 1
    model.signal_count += len(new_signals)
    model.updated_at = datetime.utcnow()
    model.reliability_score = _compute_reliability(model.signal_count)
    return model


def _compute_reliability(signal_count: int) -> float:
    """
    可靠度曲线:
    0 信号 → 0.0(冷启动,完全不可靠)
    10 信号 → 0.45
    30 信号 → 0.75
    60 信号 → 0.90
    100+ 信号 → 0.95+(趋近但不满)
    """
    return 1.0 - math.exp(-signal_count / 40.0)
```

#### 3.4.2 冷启动机制

新作者首次使用,或新作品创建时,`TasteModel.signal_count = 0`,`reliability_score = 0.0`。此时模型不可信,注入层使用降级策略。

**冷启动三阶段**:

```
阶段 0: 零信号 (signal_count = 0)
├── TasteModel 内容: 系统默认值(全维度均等分布,anti_slop_sensitivity 使用通用规则库)
├── 跨作品继承: 若作者有全局 TasteModel(work_id=NULL)且 reliability > 0.5,继承它作为起点
├── 用户上传: 强烈引导作者上传 1-3 个 StyleExemplar(最快建立偏好锚点的方式)
└── 注入策略: 仅注入 StyleExemplar few-shot + 通用 anti_slop 约束,不注入 learned_preferences

阶段 1: 信号积累期 (1 ≤ signal_count ≤ 10)
├── TasteModel 内容: 部分维度开始有倾向,但置信度低
├── 写入条件: 有信号写入,但模型更新保守(学习率减半)
├── 注入策略: 注入 StyleExemplar + 置信度 > 0.5 的维度偏好 + anti_slop
└── 冷启动问题提示: UI 上可见"品味模型还在学习中,上传更多范本或提供更多意见可加速"

阶段 2: 初步可用期 (11 ≤ signal_count ≤ 30)
├── TasteModel 内容: 主要维度有明确倾向,reliability ≈ 0.5-0.75
├── 注入策略: 全量注入(含 learned_preferences),但注入文本中标注置信度
└── 护城河初现: 用户开始感受到"AI 写的越来越符合我的口味"

阶段 3: 成熟期 (signal_count > 30)
├── TasteModel 内容: 大多数维度高置信度,模型稳定
├── 注入策略: 全量注入,注重时间衰减防止早期偏好过度主导
└── 护城河深化: 作者离开此系统将损失"一本书"的偏好积累
```

#### 3.4.3 冲突信号处理

当收到与现有模型显著冲突的信号时(同一维度方向相反,且双方 weight × confidence 均 > 0.5):

```
冲突信号处理流程:

检测:
  新信号 dimension=X, direction=increase, weight=0.70
  现有偏好 dimension=X, dominant=decrease, confidence=0.65
  冲突检测: polarity_conflict(new_signal, existing_preference) → True

处理策略(按冲突来源分):
  
  策略 A: 同一章节的正反冲突 → 标记"作者在探索",双方均缓冲,不写入模型
    reason: 作者可能在实验两种写法,不代表稳定偏好
    action: buffer_both; emit ConflictFlag { chapter_id, dimension, signals: [...] }

  策略 B: 跨章节的渐进漂移 → 允许模型更新(偏好自然演进)
    condition: 冲突信号 created_at > 旧信号 created_at + 30天 AND signal_count > 20
    action: 使用时间衰减 EMA 正常更新(近期信号优先,旧偏好自然衰退)

  策略 C: 剧烈冲突(单次跳变 > 0.4) → 触发偏好澄清
    condition: |delta| > 0.4 AND 非渐进漂移
    action:
      1. 将冲突写入 ConflictQueue
      2. 在下次人机交互时(比如写下一章之前),以低摩擦方式呈现:
         "你对[维度X]的偏好发出了矛盾信号:之前倾向[旧方向],最近倾向[新方向]。
          这次生成用哪个?"  [用旧偏好] [用新偏好] [都试试]
      3. 作者确认结果作为 weight=0.90 的高权重信号写入
```

```python
def resolve_preference(
    user_model: TasteModel,     # work_id=NULL
    work_model: TasteModel,     # 当前作品
    dimension: str,
) -> ResolvedPreference:
    """
    当两层模型对同一维度有不同偏好时,按以下规则融合。
    """
    user_pref = user_model.learned_preferences.get(dimension)
    work_pref = work_model.learned_preferences.get(dimension)

    # 作品级信号足够多时,以作品级为主
    if work_model.reliability_score >= 0.6:
        primary = work_pref
        blend_ratio = 0.85    # 85% 作品级 + 15% 用户级
    # 作品级信号少时,融合用户级偏好补充
    elif work_model.reliability_score >= 0.3:
        blend_ratio = 0.60    # 60% 作品级 + 40% 用户级
    # 冷启动:完全依赖用户级
    else:
        blend_ratio = 0.0     # 0% 作品级 + 100% 用户级

    return blend_preference(work_pref, user_pref, blend_ratio)
```

**蒸馏机制**:作品完成(状态变为 `done`)后,将该作品 `TasteModel` 中置信度 ≥ 0.7 的维度偏好蒸馏上移到用户级模型。蒸馏权重 = 0.30(新作品偏好不过度覆盖全局积累)。

### 3.6 版本化与历史管理

```
TasteModel 版本链:

version_1 ─→ version_2 ─→ version_3 ─→ ... ─→ version_N (current)
   ↑               ↑
 created          delta: {
 (冷启动)          signals_applied: [...],
                   dimensions_changed: [...],
                   reason: "20章后增量更新"
                 }

存储策略:
  - 当前版本:完整 JSONB 存储
  - 历史版本:存储 diff(变化的维度及 delta 值),不存全量(节省空间)
  - 保留最近 10 个版本,更早版本压缩为"季度快照"

回滚操作:
  - 作者可在 UI 上回滚到任意历史版本(软删除当前,恢复历史)
  - 回滚后产生新版本(回滚也是一个版本记录,source="user_rollback")
  - 回滚版本的 reliability_score 维持(不因回滚而清零信号计数)
```

```python
def inject_to_planning(
    model: TasteModel,
    planning_context: PlanningContext,   # 来自实现1
) -> TastePlanningConstraints:
    """
    将品味模型转化为规划阶段的约束。
    由实现1(分层规划)在生成大纲/卷结构时调用。
    """
    prefs = model.learned_preferences
    veto_list = prefs.get("hard_veto", [])

    constraints = TastePlanningConstraints()

    # ① 题材倾向约束
    genre_tags = prefs.get("题材与内容倾向", {}).get("genre_flavor_tags", [])
    if genre_tags:
        top_genres = [t["tag"] for t in sorted(genre_tags, key=lambda x: -x["weight"])[:3]]
        constraints.genre_guidance = (
            f"此作者的题材倾向为:{', '.join(top_genres)}。"
            f"大纲设计中的情节走向、矛盾类型、氛围应向这些方向靠拢。"
        )

    # ② 人物深度偏好
    char_depth = prefs.get("题材与内容倾向", {}).get("character_depth", {})
    if char_depth.get("confidence", 0) > 0.5:
        val = char_depth["value"]
        if val > 0.7:
            constraints.character_guidance = (
                "此作者高度重视人物心理深度。在大纲中为核心角色设计内在矛盾和心理弧线。"
            )

    # ③ 雷区清单(硬约束)
    veto_descriptions = [v["description"] for v in veto_list if v["weight"] >= 0.85]
    if veto_descriptions:
        constraints.hard_vetoes = veto_descriptions
        constraints.veto_prompt_fragment = (
            "【作者雷区 — 规划层硬约束】\n"
            "以下内容是本作者的绝对雷区,大纲和情节设计中不得出现:\n"
            + "\n".join(f"- {v}" for v in veto_descriptions)
        )

    # ④ 节奏偏好
    pacing = prefs.get("节奏与结构偏好", {})
    slow_ratio = pacing.get("pacing_control", {}).get("slow_chapters_ratio", 0.3)
    constraints.pacing_guidance = (
        f"此作者接受约 {slow_ratio:.0%} 的慢节奏过渡章节。"
        f"不必每章都是高密度情节,适当安排呼吸章。"
    )

    # ⑤ 可靠度门槛:信号不足时不注入
    constraints.reliability = model.reliability_score
    if model.reliability_score < 0.30:
        constraints.planning_taste_prompt = "（品味模型信号不足,本次规划使用通用约束）"
    else:
        constraints.planning_taste_prompt = _assemble_planning_prompt(constraints)

    return constraints


def _assemble_planning_prompt(c: TastePlanningConstraints) -> str:
    sections = ["【作者品味约束 — 规划层注入】"]
    if c.genre_guidance:
        sections.append(c.genre_guidance)
    if c.character_guidance:
        sections.append(c.character_guidance)
    if c.pacing_guidance:
        sections.append(c.pacing_guidance)
    if c.veto_prompt_fragment:
        sections.append(c.veto_prompt_fragment)
    return "\n\n".join(sections)
```

```python
def inject_to_writing(
    model: TasteModel,
    writing_context: WritingContext,    # 来自实现2
    scene_type: str,
    token_budget: int = 1200,
) -> TasteWritingInjection:
    """
    将品味模型转化为写作 Prompt 注入块。
    由实现2(写作生成)在组装 Prompt 时调用。
    token_budget: 分配给品味注入的 token 上限。
    """
    prefs = model.learned_preferences
    injection = TasteWritingInjection()

    # ① StyleExemplar few-shot 选取(正例库)
    exemplars = _select_exemplars_from_positive_library(
        model.positive_exemplars,
        scene_type=scene_type,
        token_budget=int(token_budget * 0.55),   # 55% token 给 exemplar
    )
    injection.exemplar_block = _format_exemplars_for_prompt(exemplars)

    # ② 文风描述符(高置信度维度才注入)
    style_lines = []
    CONFIDENCE_THRESHOLD = 0.50

    style_dims = prefs.get("文风维度", {})
    for dim_name, dim_data in style_dims.items():
        conf = dim_data.get("confidence", 0)
        if conf < CONFIDENCE_THRESHOLD:
            continue
        dominant = dim_data.get("dominant") or dim_data.get("value")
        if dominant is not None:
            style_lines.append(f"- {dim_name}偏好: {dominant} (置信度{conf:.0%})")

    injection.style_descriptor_block = (
        "【作者文风偏好(从行为中学到)】\n" + "\n".join(style_lines)
        if style_lines else ""
    )

    # ③ 负面清单
    active_negatives = [p for p in model.negative_list if p.get("active")]
    high_negatives = [p for p in active_negatives if p["severity"] == "high"]
    med_negatives = [p for p in active_negatives if p["severity"] == "medium"]

    neg_lines = []
    for p in high_negatives[:5]:    # 高危限5条
        neg_lines.append(f"⚠️ 必须避免: {p['description']}")
        if p.get("example_text"):
            neg_lines.append(f"   反例: 「{p['example_text'][:40]}」")
    for p in med_negatives[:3]:     # 中危限3条
        neg_lines.append(f"• 尽量避免: {p['description']}")

    injection.negative_list_block = (
        "【作者个性化禁忌】\n" + "\n".join(neg_lines)
        if neg_lines else ""
    )

    # ④ 个性化反 AI 腔敏感度
    anti_slop = prefs.get("anti_slop_sensitivity", {})
    high_sens = {k: v for k, v in anti_slop.items() if v >= 0.75}
    if high_sens:
        slop_lines = [f"- {k}(敏感度{v:.0%})" for k, v in
                      sorted(high_sens.items(), key=lambda x: -x[1])[:4]]
        injection.anti_slop_focus_block = (
            "【此作者高敏感的 AI 腔类型,重点回避】\n" + "\n".join(slop_lines)
        )

    # ⑤ 可靠度降级
    if model.reliability_score < 0.30:
        injection.reliability_note = "（作者偏好信号尚少,上方约束为粗略估计,请综合上下文判断）"

    injection.total_token_estimate = _estimate_tokens(injection)
    return injection


def _select_exemplars_from_positive_library(
    positive_exemplars: List[dict],
    scene_type: str,
    token_budget: int,
) -> List[dict]:
    """
    从正例库中选取与当前场景最匹配的 exemplar。
    匹配逻辑:
    1. 场景类型过滤(style_descriptors 中的 genre_flavor/sensory_profile 标签)
    2. 按 weight × (1 / (1 + usage_count × 0.05)) 排序(多用减权)
    3. 按 token_budget 截断
    """
    candidates = []
    for entry in positive_exemplars:
        ex = db.get(StyleExemplar, entry["exemplar_id"])
        if not ex:
            continue
        relevance = _scene_relevance(ex, scene_type)
        adjusted_weight = entry["weight"] * (1.0 / (1.0 + entry.get("usage_count", 0) * 0.05))
        candidates.append((adjusted_weight * relevance, ex, entry))

    candidates.sort(key=lambda x: -x[0])

    selected = []
    used_tokens = 0
    for _, ex, entry in candidates:
        t = count_tokens(_format_single_exemplar(ex))
        if used_tokens + t > token_budget:
            break
        selected.append(ex)
        used_tokens += t
        # 使用后递增计数(写回 positive_exemplars)
        entry["usage_count"] = entry.get("usage_count", 0) + 1

    return selected
```

```python
def get_critique_standard(
    model: TasteModel,
    chapter: Chapter,
) -> TasteCritiqueStandard:
    """
    提供内核3(反平庸与文学质量)评改时使用的个性化评判标准。
    内核3的 LiteraryCritiqueAgent 使用此标准来定义"好"。
    """
    prefs = model.learned_preferences
    standard = TasteCritiqueStandard()

    # ① rubric 阈值个性化
    # 不同作者对不同维度的容忍度不同
    default_thresholds = {
        "show_not_tell": 3,
        "dialogue_quality": 3,
        "imagery_rhythm": 3,
        "emotional_tension": 3,
        "subtext_whitespace": 3,
        "sensory_detail": 3,
        "scene_blocking": 3,
        "character_presence": 3,
    }
    # 根据偏好调整阈值
    show_tell = prefs.get("文风维度", {}).get("show_tell_target", {})
    if show_tell.get("value", 0.5) > 0.7 and show_tell.get("confidence", 0) > 0.6:
        default_thresholds["show_not_tell"] = 4    # 此作者强调 show,提高阈值

    dialogue_style = prefs.get("文风维度", {}).get("dialogue_style", {})
    if dialogue_style.get("dominant") == "潜台词丰富" and dialogue_style.get("confidence", 0) > 0.6:
        default_thresholds["subtext_whitespace"] = 4
        default_thresholds["dialogue_quality"] = 4

    standard.rubric_thresholds = default_thresholds

    # ② 正例锚点(内核3评改时的参照系)
    # 提供正例库中最典型的 3 个 exemplar 作为"好"的范本参照
    standard.positive_exemplar_ids = [
        e["exemplar_id"] for e in sorted(
            model.positive_exemplars,
            key=lambda x: -x["weight"]
        )[:3]
    ]

    # ③ 负面模式清单(内核3的 AntiSlop 权重调整)
    standard.anti_slop_weights = prefs.get("anti_slop_sensitivity", {})

    # ④ 人格化的"好"的标准描述(注入 CritiqueAgent Prompt)
    standard.taste_description = _compose_taste_description(model, prefs)

    return standard


def _compose_taste_description(model: TasteModel, prefs: dict) -> str:
    """
    生成一段自然语言描述,说明"对这个作者而言什么是好文字"。
    """
    lines = ["【对这位作者而言,'好'的标准】"]

    if model.reliability_score < 0.3:
        lines.append("（品味模型信号尚少,以下标准为初步估计）")

    style_dims = prefs.get("文风维度", {})
    emotional = style_dims.get("emotional_tone", {})
    if emotional.get("confidence", 0) > 0.5:
        lines.append(f"- 情感表达方式:偏好"{emotional.get('dominant')}"风格")

    show_tell = style_dims.get("show_tell_target", {})
    if show_tell.get("confidence", 0) > 0.5:
        val = show_tell.get("value", 0.5)
        lines.append(f"- 此作者强调 Show not Tell(目标{val:.0%} Show),评改时重视感官化表达")

    dialogue = style_dims.get("dialogue_style", {})
    if dialogue.get("confidence", 0) > 0.5:
        lines.append(f"- 对话偏好:"{dialogue.get('dominant')}",对话质量评改标准相应提高")

    hard_vetoes = prefs.get("雷区清单(hard_veto)", [])
    if hard_vetoes:
        lines.append("- 以下是此作者的创作雷区,评改时若发现须优先指出:")
        for v in hard_vetoes[:3]:
            lines.append(f"  · {v['description']}")

    return "\n".join(lines)
```

```python
def get_eval_anchor(

    由工程6在采集 H1/H2/H3 评分时调用,注入评分引导 Prompt。

    if eval_type == "h1_readability":
        anchor_desc = "对这位作者,'可读性好'意味着:"
        anchor_items = []
        show_tell = prefs.get("文风维度", {}).get("show_tell_target", {})
        if show_tell.get("value", 0) > 0.65:
            anchor_items.append("情感通过行为/细节展示而非直说")
        emotional = prefs.get("文风维度", {}).get("emotional_tone", {})
        if emotional.get("dominant") == "压抑克制":
            anchor_items.append("语言克制,不堆砌辞藻")
        if not anchor_items:
            anchor_items.append("文字流畅,读起来自然")

    elif eval_type == "h2_pleasure":
        anchor_desc = "对这位作者,'阅读愉悦感'来自:"
        genre_tags = prefs.get("题材与内容倾向", {}).get("genre_flavor_tags", [])
        anchor_items = [t["tag"] for t in genre_tags[:2]] if genre_tags else ["情节驱动","人物魅力"]

    elif eval_type == "h3_character":
        anchor_desc = "对这位作者,'人物塑造好'意味着:"
        char_depth = prefs.get("题材与内容倾向", {}).get("character_depth", {})
        anchor_items = (
            ["人物有独特心理逻辑","行为源于内在矛盾"]
            if char_depth.get("value", 0) > 0.7
            else ["人物行为可信","有记忆点"]
        )

    return EvalAnchor(
        eval_type=eval_type,
        anchor_description=anchor_desc,
        anchor_items=anchor_items,
        reliability=model.reliability_score,
    )
```

### 4.6 与 StyleExemplar 和 Character.voice_profile 的关系

```
   │
   ├── positive_exemplars ──→ 引用 StyleExemplar.id
```

```python
    positive_exemplar_ids:  List[UUID] = field(default_factory=list)

    taste_description:      str = ""
    reliability:            float = 0.0

@dataclass
class EvalAnchor:
    eval_type:          str
    anchor_description: str
    anchor_items:       List[str]
    reliability:        float

@dataclass
class PreferenceExplanation:
    dimension:    str
    conclusion:   str
    evidence:     List[dict]
    confidence:   float
    signal_count: int = 0
```

## § 6. 失败模式与缓解

### 6.1 NL 意见误解析为错误风格信号

**风险**:作者的自然语言意见针对的是情节("这段情节太慢了"),被误解析为文风信号("rhythm_tempo→fast"),污染 TasteModel。

**缓解**:
- 解析 Prompt 明确要求"仅提取风格维度的信号,忽略情节类批评",并在输出中要求 `confidence` 字段
- 低置信度信号(< 0.45)自动丢弃,不写入模型
- 每轮信号写入后记录 `source="feedback"`,UI 上可见,作者可逐条删除误判信号
- 定期(每 20 章)展示信号摘要给作者确认,作者可批量撤销

### 6.2 冷启动期生成质量差

**风险**:新用户前 10 章几乎没有信号,`TasteModel` 空洞,注入块等同于无效,生成不"对味"。

**缓解**:
- 强引导上传 StyleExemplar:在首次创作界面以高优先级提示"上传 1-2 段你喜欢的文字片段,帮助系统快速理解你的文风"
- 继承全局 TasteModel:若作者有其他作品的已有偏好(work_id=NULL 全局模型),自动继承作为起点
- 首章双方案策略:强制为首章生成两种不同文风方向的版本供选择,作者的选择产生首批 `option_choice` 信号
- 注入层的降级策略:冷启动期注入文案中明确告知模型"作者偏好尚不明确,请采取中性偏保守风格"

### 6.3 偏好模型过拟合早期偏好

**风险**:前 20 章作者密集调整风格,产生大量早期信号。后期生成一直被早期信号主导,风格锁死。

**缓解**:
- 时间衰减机制:早期信号权重随时间衰减(DECAY_HORIZON=50章),不会永久主导
- 滑动窗口主驱动:最近 50 章的信号作为"主驱动",全局积累信号作为"底色"(权重占比上限 30%)
- 可回滚:作者如发现风格锁死,可通过 UI 回滚模型到任意历史版本,或重置特定维度

### 6.4 冲突信号导致模型振荡

**风险**:作者在某个阶段反复给出相反的节奏信号,导致模型在两个方向间振荡,注入指令自相矛盾。

**缓解**:
- 冲突检测即触发缓冲:相反信号不立即写入,双方均缓冲 5 章观察
- 偏好澄清对话:在下次写章前以低摩擦方式呈现冲突,作者一次选择产生高权重信号定调
- 振荡阻尼:连续 3 次以上冲突信号后,自动降低该维度的学习率(阻尼系数 0.5),防止持续振荡

### 6.5 TasteModel 被滥用为"风格强制器"

**风险**:偏好模型积累了某种强信号后,AI 生成变得千篇一律,完全锁定在一种风格里,失去意外感和变奏。

**缓解**:
- 注入权重上限:任何单一维度的偏好注入权重不超过 0.85(留 15% 的"余白"给 AI 的自然变奏)
- VariationEngine 协作:内核3 的 VariationEngine 可覆盖 TasteModel 的部分约束来制造风格变奏,这是系统设计的一部分
- 偏好描述语言:注入 Prompt 使用"倾向"而非"必须"的语言("此作者偏好舒缓节奏"而非"你必须使用舒缓节奏")

### 6.6 正例库同质化

**风险**:作者反复上传相似风格的范本,正例库内部高度相似,丧失多样性,注入效果退化为单一风格强化。

**缓解**:
- 入库相似度检查:新 exemplar 与已有库中任意一条 embedding 余弦相似度 > 0.85 时拒绝入库,提示作者"已有相似范本"
- 库容量上限 + 多样性淘汰:超过 20 条时,优先淘汰 embedding 距离最近的配对中权重较低的一条
- 多样性评分展示:UI 上展示"正例库多样性评分",鼓励作者上传不同场景类型的范本

### 6.7 百万字下的信号规模性能问题

**风险**:百万字作品可能累积数千甚至上万条 `PreferenceSignal`,模型更新和查询性能下降。

**缓解**:
- 批处理更新:信号不实时写入模型,而是每累积 **20 条**或**每5章完成后**批量更新一次
- 信号压缩:更新后,将权重 < 0.30 的历史信号标记为 `compressed=True`,不再参与未来迭代(但保留用于解释)
- 分页查询:可解释性查询只取 top-10 强信号,不全量扫描
- 异步更新:模型更新完全异步,不阻塞写作生成流程

## § 7. MVP vs 完整版

### 7.1 MVP 阶段(最小可验证版本)

**目标**:验证"品味信号采集 + 基础注入"是否让作者感受到"AI 越来越懂我"。

**包含**:
- `PreferenceSignal` 表 + 基础信号采集(仅 `option_choice` 和 `exemplar` 两类来源)
- `TasteModel` 基础结构(仅 `positive_exemplars` 和 `negative_list`,无 `learned_preferences`)
- 冷启动:强引导上传 StyleExemplar
- 注入层:仅 `inject_to_writing()`(exemplar few-shot + 简单负面清单)
- 双层架构:仅作品级,无用户全局模型
- 可解释性:无(MVP 阶段先验证效果,再做解释界面)

**不包含**:
- `feedback`/`rating`/`revision_diff` 信号解析
- `learned_preferences` 增量学习
- 冲突信号处理
- 注入到规划层
- 全局 TasteModel 蒸馏
- 版本化/回滚

**MVP 成功指标**:
- 作者上传 2+ StyleExemplar 后,主观评价"AI 写的感觉更像我的风格"(问卷 1-5 分 ≥ 3.5)
- 负面清单中的 Anti-Slop 规则命中率在使用 5 章后下降 ≥ 20%

### 7.2 增强版阶段

**新增**:
- `feedback` 信号解析(NL 意见提取风格信号)
- `rating` 信号处理(H1/H2/H3 回流)
- `learned_preferences` 基础版(仅 `show_tell_target` + `rhythm_tempo` + `emotional_tone` 三个维度)
- 注入到规划层(`inject_to_planning()`,仅雷区清单和题材倾向)
- 初步可解释性界面

### 7.3 完整版阶段

**新增**:
- `revision_diff` 信号分析
- `learned_preferences` 全维度(所有文风、节奏、题材、雷区维度)
- 冲突信号检测 + 偏好澄清机制
- 双层架构(用户全局 TasteModel + 作品级)
- 版本化 + 回滚
- 正例库同质化守卫
- 完整 `inject_to_planning()` + `get_critique_standard()` + `get_eval_anchor()`
- 时间衰减 EMA + 滑动窗口

## § 9. 开放问题

> 标注:【需实验验证】= 需自建度量实测;【需设计决策】= 需团队讨论;【理论未知】= 目前无已知答案

### 9.1 信号有效性

**Q1**【需实验验证】`option_choice` 信号的"偏好推断"准确率是多少?作者选方案B的原因很多(情节更好、风格更好、仅因为更短),如何隔离风格维度的信号?若无法隔离,`option_choice` 的权重是否应该更低(降到 0.4 甚至更低)?

**Q2**【需实验验证】`revision_diff` 信号分析对"情节改动"和"风格改动"的分类准确率?若作者修改了一段话是因为情节错误而非风格偏好,误分类为风格信号会造成多大污染?

**Q3**【需实验验证】累积多少条信号后,作者才能主观感受到"AI 开始懂我"?预期是 10-30 条,但需要用户研究验证。

### 9.2 学习机制参数

**Q4**【需实验验证】`DECAY_HORIZON=50` 是否合适?如果作者在 10 章内密集调整风格后趋于稳定,50章的衰减可能太慢(早期信号仍然过度主导);如果作者风格本来就慢慢演进,50章可能太快(合理的长期偏好被衰减掉)。

**Q5**【需设计决策】学习率是否应该按维度独立设置?例如"雷区"维度应该学习率很高(作者明确的红线应快速固化),而"节奏偏好"维度应该学习率较低(节奏可以随章节类型变化)?

**Q6**【需设计决策】`reliability_score` 的公式 `1 - exp(-n/40)` 意味着需要约 120 条信号才能达到 0.95 的可靠度。对于只写 5 万字短篇的作者,这个门槛是否过高?是否需要按作品规模自适应?

### 9.3 注入效果

**Q7**【需实验验证】当 `TasteModel` 信号充足时,注入到 Prompt 的文风约束,LLM 的实际遵从率是多少?特别是 Prompt 总长度很长时(> 50K token 上下文),早期注入的 TasteModel 片段是否会被模型"遗忘"?

**Q8**【需设计决策】品味注入应该在 Prompt 的 SYSTEM 区还是 USER 区末尾重申?SYSTEM 区权重通常更高,但 USER 区末尾更近;两者的遵从率差异需要实验测量。

**Q9**【需实验验证】`inject_to_planning()` 的品味约束对最终正文质量的影响有多大?如果规划层注入了题材倾向约束,但写作层没有额外约束,品味传导是否仍然有效?

### 9.4 双层架构

**Q10**【需设计决策】蒸馏机制:从作品级到全局级,蒸馏权重 0.30 是否合理?如果作者写了一部与自己整体风格完全不同的实验性作品,蒸馏会污染全局偏好——是否需要让作者手动确认"是否蒸馏此作品的偏好到全局"?

**Q11**【需设计决策】不同体裁作品的偏好是否应该标记体裁标签、只在相同体裁的新作品中继承?例如:玄幻作品积累的偏好不应该被继承到纯文学作品的冷启动期。

### 9.5 可解释性与信任

**Q12**【需实验验证】可解释性界面的实际使用率?如果作者从不查看"为什么系统认为你偏好X",这个功能的投入产出是否合理?可能需要在 MVP 后用行为数据评估。

**Q13**【理论未知】作者看到"你偏好X"的解释后,如果觉得不准确,会不会因为看到了解释而开始主动迎合系统的分析(确认偏差),而不是真实表达自己的偏好?这是人机交互中的"自我实现预言"风险,目前无已知应对方案。

### 9.6 护城河的实际形成

**Q14**【理论未知】品味护城河的真实深度——在一部 50 万字作品后,作者迁移到其他工具的"损失"有多大?如果其他工具也能快速采集偏好(例如通过上传已有作品分析),护城河能持续多久?这个问题需要在产品完成后通过用户留存数据回答。

```
    └─→ [内核2] inject_to_planning() → TastePlanningConstraints
            └─→ 注入规划 Prompt

[实现2] 生成正文(写作 Prompt 组装)
    └─→ [内核2] inject_to_writing() → TasteWritingInjection
            └─→ 注入写作 Prompt [SYSTEM 区]

[内核3] 触发评改环
    └─→ [内核2] get_critique_standard() → TasteCritiqueStandard

[工程6] 采集人评分数 H1/H2/H3
    ├─→ [内核2] ingest_signal(source="rating") → PreferenceSignal
    └─→ [内核2] get_eval_anchor() → EvalAnchor (个性化评分引导)

[工程4] 人工修订完成(Snapshot created_by="human")
    └─→ [内核2] ingest_signal(source="revision_diff") → PreferenceSignal
```
