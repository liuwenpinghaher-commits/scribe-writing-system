# 写作经验差距 · 完善改进方案

> **代号：** `scribe3-experience-pressure`（经验压力层）  
> **日期：** 2026-08-05  
> **对照基准：**  
> - 系统真源：`docs/CURRENT_ARCHITECTURE.md` + `scribe3/` 代码 + 强制闭环结案（`2026-08-04-写作方案强制闭环-*`）  
> - 经验真源：责编/作者实作（多轮修订、Scene–Sequel、人物可信、续写连续、真人读感）  
> - **不是** Scrivener/Atticus 功能对标  
> **一句话：** 在已抬高的技术下限之上，补齐「整本重见 · 戏的动能 · 人物可信 · 续写身体感 · 读感入口」——**只做责编式压力与问诊，不做文学总分、不自动改声口。**

## 1. 经验与全网实践依据（制定前的「真摸清」）

### 1.1 修订顺序（不可反）

业界/责编共识：先发展编辑（结构·人物·节奏），再行级，再文稿/校对。  
**本方案所有「压力」按此分层**；禁止在结构未稳时用 AI 腔检测冒充发展编辑。

### 1.2 Scene–Sequel（Dwight Swain）

- **Scene：** Goal → Conflict → Disaster（半灾难即可）  
- **Sequel：** Reaction → Dilemma → Decision → 接下场 Goal  
经验核心：只有动作没有消化 → 事件多、人不真。  
**系统应对：** 诊断链是否断裂；**永不**因缺 sequel 直接 blocking 落库（除非作者选择「严格戏格」模式）。

### 1.3 发展编辑问的是问题，不是分数

典型问诊：开篇承诺是否兑现、中段是否空、人物目标是否清晰、选择是否可信、结局是否赚来。  
**系统应对：** `RevisionLetter`（编辑信）= 结构化问题 + 系统证据链接 + 作者勾选/作答；**无加权总分**。

### 1.4 伏笔经验双轨

- **契约轨：** 已登记 plant/payoff（你已强）  
- **发现轨：** 二稿重读才发现的种子（你弱）  
**系统应对：** 建议登记，人批入正典。

### 1.5 声口与感动

逐句拧紧、辨认「像不像这本书」——属作者资产。  
**系统应对：** 最多声口锚偏离提醒 + 强制慢读抽样；**禁止**文学自动改写与总分。

### 1.6 与强制闭环的关系

| 闭环（已结案） | 本方案 |
|----------------|--------|
| 章级技术下限、定稿门闩、ingest 诚实 | **不回退、不平行第二总 goal 抢门闩** |
| blocking = 确定性硬伤 | 经验压力默认 **advisory / decision**；仅「作者开启严格戏格」时部分可升 S1 白名单 |
| 禁止确保好小说 | 全文遵守；验收措辞同宪法 |

## 2. 完成定义（Done）

**完成 = 经验压力层五门全过：**

| 门 | 含义 |
|----|------|
| **门 E1 · 全书 re-vision** | 可对任意 work 生成「编辑信」：开篇承诺、中段、弧线、未回收契约、意图对照；作者可勾选处理状态；证据可点回章/伏笔/scorecard |
| **门 E2 · 场景动能** | 章/场景可登记或推断 Scene–Sequel 六元组；诊断断链；进 brief/pulse/post-check advisory |
| **门 E3 · 人物可信 + 种子发现** | 关键选择质疑清单 + 疑似种子建议入台账（待批） |
| **门 E4 · 续写连续 + 修订模式** | 续写仪式（近章重读证明 + 状态快照）；修订模式切换改变检测/注入权重（非关停门闩） |
| **门 E5 · 读感入口 + 留白压力** | 外部问题单/批注汇入；可删段建议；字数目标与质量压力解耦说明 |

**结案结语（固定）：**  
「系统在技术下限之外，增加责编式经验压力；整本重见与戏的真假仍由作者完成。」

## 3. 总体架构：经验压力层（Experience Pressure Layer）

```text
                    ┌─────────────────────────┐
                    │  作者勾选 / 作答 / 终裁   │
                    └───────────▲─────────────┘
                                │ 只提问、列证据、记决定
        ┌───────────────────────┴───────────────────────┐
        │         Experience Pressure（本方案）            │
        │  re-vision letter │ scene grid │ choice audit   │
        │  seed miner │ continue rite │ feedback import   │
        └───────────────────────┬───────────────────────┘
                                │ 只读聚合 + 少量登记写
        ┌───────────────────────┴───────────────────────┐
        │  已有：brief / pulse / scorecard / north_star    │
        │       purpose / promises / arcs / finalize_gate  │
        │       deductions / scene_truth / lessons         │
        └─────────────────────────────────────────────────┘
```

**设计铁律：**

1. **问诊优先于检测**——先问题清单，再可选确定性规则。  
2. **证据链接已有表**——不新建平行「文学分」库。  
3. **写路径单源扩展**——注入/简报/脉冲挂接，不新开第三套 prompt 组装。  
4. **人答才算处理**——报告项 `open|acknowledged|waived|fixed`；机器不自动 fixed。  
5. **严格模式 opt-in**——默认经验压力 = advisory/decision，不拦定稿。

## 4. 分期（严格按序）

### 包 E0 · 地基：修订模式 + 数据契约 + 问诊骨架（2–3 周量级）

**目标：** 所有后续包共用的类型与 API；零文学保证措辞。

| ID | 任务 | 做法 | 验收 |
|----|------|------|------|
| E0-1 | `RevisionMode` | `structure \| scene \| line \| proof \| full`；存 work 或 session 偏好；影响 pulse 权重与 post-check 展示排序，**不关闭 finalize_gate** | 单测：mode 切换只改 advisory 排序/展示 |
| E0-2 | `RevisionLetter` 模型 | 纯结构：`items[{id,kind,severity,question,evidence[],status,author_note}]`；kind∈ 下表 | roundtrip 序列化 + store 读写 |
| E0-3 | `GET/POST /revision/letter` | GET 现算或缓存；POST 更新 item status/note | 真机 work=loop-qa 或测试 work |
| E0-4 | 宪法夹具 | 禁总分字段；禁 letter 进 blocking | 单测 assert |

**Letter kind 初始集（E1 填满）：**  
`opening_promise` · `middle_sag` · `character_arc` · `theme_or_intent` · `unpaid_promise` · `info_control` · `pacing` · `custom`

**E0 交付物：** schema/migration（若落库）· API · 空报告可生成 · 进度表。

---

### 包 E1 · 全书 re-vision 问诊（核心）

**目标：** 责编式「整本重见」——问题 + 系统证据，作者勾选。

| ID | 任务 | 数据来源（已有） | 问诊逻辑（最佳实践 → 规则） |
|----|------|------------------|---------------------------|
| E1-1 | 开篇承诺 | intent + 第1–2章 prose/synopsis 摘要 | 「读者开篇被承诺了什么？结局/最新章是否仍在还？」作者填承诺句；系统只提示未读完/无 intent |
| E1-2 | 中段空转 | chapters_lite 压力级 + tension monotony + 字数分布 | 连续低压/同 role 过长 → 提问「中段是否只是赶路？」 |
| E1-3 | 弧线 | arc anchors / arc_plan / pulse arc_dim | 计划章已过但锚点未更新 → 「弧是否停滞？」 |
| E1-4 | 契约未还 | open_promises overdue + volume_signals | 直接链到超期列表（已有）升为 letter 项 |
| E1-5 | 意图对照 | intent.red_lines / reader_feeling vs 抽样章 | LLM **可选**辅助起草问题，**输出仅 advisory 问题文本**；失败则只用模板问题 |
| E1-6 | 前端「全书问诊」页 | 列表 + 证据跳转 + 勾选状态 | 无雷达总分图 |

**验收：**

- 对 ≥5 章样本书生成 letter，含 ≥4 类 kind 的可构造项  
- 作者把一项标 `waived` 后不消失、可审计  
- 文档写明：letter **不**进入 finalize blocking  

**非目标：** 自动重排章节、自动重写中段。

---

### 包 E2 · 场景动能（Scene–Sequel）

**目标：** 把 Swain 六元组变成章/场景可诊断结构。

| ID | 任务 | 做法 |
|----|------|------|
| E2-1 | 数据：`scene_grid` | 挂 chapter 或 beat：`{goal, conflict, disaster, reaction, dilemma, decision, source:author\|inferred\|empty}` |
| E2-2 | 登记 | MCP `s3_patch_scene_grid`（待批）+ UI 推演台旁简易六格；允许空 |
| E2-3 | 诊断 `diagnose_scene_grid` | 纯函数：缺 goal/conflict；有 disaster 无 reaction；有 decision 无新 goal 链；**连续三场无 sequel 字段** → advisory |
| E2-4 | 接线 | brief 段「本场动能」；pulse 维 `scene`；post-check 可选 `type=scene_kinetics` advisory |
| E2-5 | 与 purpose 分工 | purpose = 世界状态 delta；scene_grid = 戏的心理因果；文档与 UI 双栏，禁止混写一个 JSON |

**严格戏格（opt-in）：**  
`work.flags.strict_scene_grid=true` 时，实质正文存稿若本场 grid 全空 → **craft/finalize 旁路不可**，409 提示补 grid 或关严格模式。默认 false。

**验收：**

- 构造「有灾难无反应」样本 → 诊断命中  
- 默认模式不 409；严格模式 409  
- 单测纯函数不启 Surreal  

**非目标：** 自动从 prose 完美抽取六元组当真理（推断仅 source=inferred，人可改）。

---

### 包 E3 · 人物可信 + 种子发现

| ID | 任务 | 做法 |
|----|------|------|
| E3-1 | `choice_audit` | 输入：章内「关键选择」标记（作者点选句段或登记）+ 角色 lie/want/fear/anchors |
| E3-2 | 质疑模板 | 固定问句：「该选择与已建立的恐惧/欲望是否张力合理？若叛变，前文是否赚够？」系统只填证据摘录（角色卡字段 + 近章 synopsis） |
| E3-3 | 种子矿工 `seed_miner` | 确定性启发：专名反复出现、物件二次出现、对话未答之问；输出 `suggested_promise` 草稿 |
| E3-4 | 升格路径 | 建议 → 人确认 → 走现有 promise 登记/MCP 待批；**禁止**自动 plant |
| E3-5 | letter 挂接 | 未处理建议进入 re-vision letter kind=`latent_seed` |

**验收：**

- 种子建议不写正典直至批准  
- 选择审计无「像/不像」模型分，只有问题+证据  

---

### 包 E4 · 续写仪式 + 状态快照

| ID | 任务 | 做法 |
|----|------|------|
| E4-1 | `continue_snapshot` | 每章存稿成功后写：焦点者、未回收 top-N 伏笔、开环、关系冷线、伤/状态（若有 char_state）、近章末段 hash |
| E4-2 | 续写门（软） | 打开写作台 / 首次 chat/write 本章：若距上次写 >N 天或跨章，弹出「续写仪式」：展示 snapshot + 要求确认「已重读近文」checkbox |
| E4-3 | 硬模式 opt-in | `require_reread=true` 时未确认则禁止 generate（可存草稿） |
| E4-4 | 注入 | 确认后把 snapshot 摘要并入 assemble 的 continue 块（单源 write_assemble） |

**验收：**

- 中断续写可构造：未确认时硬模式拒写  
- snapshot 字段来自已有表，不靠 LLM 幻觉状态  

---

### 包 E5 · 读感入口 + 留白压力

| ID | 任务 | 做法 |
|----|------|------|
| E5-1 | `FeedbackImport` | 粘贴/上传批注（Markdown：章号+引用+问题）；解析为 FeedbackNote 列表 |
| E5-2 | 标准问题单 | 模板：困倦点、恨谁、猜到结局吗、哪段假、哪段快——作者发给 beta 后回收 |
| E5-3 | 汇入 letter | 外部反馈 → letter items kind=`external_read` |
| E5-4 | 可删段建议 | 复用 cross_repetition / 功能重复启发式；列表「删了信息量是否仍在」；**不自动删** |
| E5-5 | 字数目标解耦 | UI 文案：日更字数 ≠ 本章质量；pulse 在「仅冲字数」时加 nudge「是否该留白」 |

**验收：**

- 一份样例 beta 粘贴可解析出 ≥3 条  
- 可删建议零自动写回

## 10. 决策台账（预置）

### D-E01 · 经验压力默认不进 blocking  
与强制闭环宪法一致；严格戏格 opt-in。

### D-E02 · purpose ≠ scene_grid  
世界状态合同 vs 戏的心理因果；双轨。

### D-E03 · 种子只建议不自动 plant  
防止污染正典。

### D-E04 · 外部读感不模型化  
导入真人批注；不用 LLM 冒充 beta 完成「读感闭环」。

### D-E05 · 不与「导出/排版」绑死本 goal  
交付导出属工作台缺口，可另 goal；本方案专注**经验压力**。

## 11. 非目标（写清以免膨胀）

- 保证文学神作、情感击中、畅销  
- 自动发现全部隐性伏笔  
- ConStory 19 类全覆盖

## 12. 成功标准（作者侧体感）

作者应能说：

1. 「整本写完后，系统像责编一样逼我回答中段/弧线/承诺问题。」  
2. 「每场戏我能看见目标–代价–消化有没有断。」  
3. 「停很久再写，系统逼我接上状态而不是只灌设定。」  
4. 「别人说的意见能进同一套问诊单，而不是散落聊天记录。」  
5. 「它仍然不会替我说这本书好不好。」
