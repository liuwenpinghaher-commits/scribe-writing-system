## §2 · 验证方法论

### 2.1 四类检验手段总览

| 手段 | 编号 | 性质 | 成本 | 适用层 |
|---|---|---|---|---|
| **确定性断言** | T1 | 确定性,零 LLM 成本 | 低 | 数据契约、API 行为、状态机流转 |
| **度量阈值** | T2 | 确定性计算,阈值比对 | 低-中 | M/Q 系列指标,来自工程6 |
| **LLM-as-judge** | T3 | 概率性,需防偏差 | 中-高 | 内容质量、意图共鸣、反平庸 |
| **人评** | T4 | 高质量,低频 | 高 | 最终校准地基;H 系列 |

四类手段按层叠使用——T1 先行过滤,T2 持续监控,T3 深度评估,T4 最终校准。**任何单一手段单独使用都不充分。**

### 2.2 T1 · 确定性断言

**设计原则**:对有明确 pass/fail 语义的行为使用确定性断言,不引入 LLM 判断——LLM 的概率性会降低硬性契约的可靠性。

**适用断言类型**:

```python
# 类型 A:数据契约断言 —— 实体存在且字段符合 schema
assert chapter.id is not None             # uuid v7 格式
assert chapter.status in ("draft","reviewing","done")
assert len(options) in range(2, 5)        # OptionSet 必须 2–4 个方案
assert author_intent.do_not_betray != {}  # 北极星红线非空

# 类型 B:状态机流转断言 —— 伏笔状态机合法跃迁
# planted → triggered/paid/abandoned 是合法的;
# paid → planted 是非法的(回退禁止)
assert foreshadow.state != "planted" or prev_state in ("planted",)

# 类型 C:隔离边界断言 —— 多本书防串味
assert all(e.work_id == current_work_id for e in char_states)
assert all(m.work_id == current_work_id for m in memory_entries)

# 类型 D:操作不变式断言 —— AI 绝不替人直接提交正文
# 所有 Segment.created_by == "ai";人的操作只在 FeedbackNote/OptionSet 上
assert segment.created_by == "ai"

# 类型 E:API 结构断言 —— 响应结构与 schema 吻合
response_body = call_api("POST /chapters/{id}/write")
validate_against_openapi_schema(response_body, "ChapterWriteResponse")
```

**harness 集成**:T1 断言全部以 pytest 单元/集成测试形式组织,并纳入 CI 阻塞门(工程10 §5.1)。失败即阻断——不允许"断言失败但继续跑"的情形。

### 2.3 T2 · 度量阈值

#### 2.3.1 门槛轨阈值(Correctness Track)

| 指标 | 标识 | 验收通过阈值 | 来源 | 校准状态 |
|---|---|---|---|---|

| ConStory 加权错误数 | M2_weighted | 单卷总计 ≤ 30;单章 critical ≤ 1 | 工程6 §3.2.2 | 【设计决策须校准】 |

```python
# 门槛阈值验收检查伪代码
def assert_correctness_thresholds(work_report: WorkQualityReport):
    assert work_report.m1_global_avg >= 0.82, \
        f"M1 全书均值 {work_report.m1_global_avg:.3f} < 0.82"
    assert work_report.m1_trend[-1]["m1"] >= 0.65 or \
        all(r["m1"] >= 0.65 for r in work_report.m1_trend), \
        "存在 M1 < 0.65 的章节"
    assert work_report.m3_global >= 0.75, \
        f"全书伏笔回收率 {work_report.m3_global:.2f} < 0.75"
    # 检查时间线连续崩坏
    m4_series = [r["m4_timeline"] for r in work_report.m4_trend]
    consecutive = max(
        sum(1 for _ in g) for k, g in groupby(m4_series, key=lambda x: x >= 1) if k
    )
    assert consecutive < 3, f"连续 {consecutive} 章时间线冲突 ≥ 1"
```

### 2.4 T3 · LLM-as-judge

#### 2.4.1 judge 框架

LLM-as-judge 覆盖工程10 §4.2 无法用确定性规则检验的维度。判断内容包括:意图共鸣、反平庸表现、Agent 轨迹计划质量、多方案差异度、意见→重做闭环效果。

**架构原则**:沿用工程10 §4.2 的 DAG 设计——硬规则层先行,通过后才进 LLM 软评分层。

```
输入文本/轨迹
    │
    ▼
硬规则层(T1 确定性断言)
    │ 通过
    ▼
LLM-as-judge 软评分层
    │
    ├─ rubric 评分(逐条标准,显式可操作)
    ├─ 防偏差:换模型 judge(生成≠评分)
    └─ 高风险样本 → 人工审查队列(T4)
```

#### 2.4.2 验收用 rubric

**rubric 设计原则**:每条标准必须写**具体可操作的判断准则**,避免"标准模糊导致分数方差大"偏差(工程10 §4.2)。

**rubric A:反平庸与文学质量**

```yaml
rubric_antiaverage:
  description: "判断生成章节是否有效对抗 AI 平庸化"
  dimensions:
    - id: no_formulaic_opening
      instruction: |
        章节开头100字内是否避免了以下公式化模式:
        "她深深地感受到…""他不禁感叹…""此刻的XXX心中百感交集"
        类似的"情感总结句"启动。直接以具体动作/感官细节/对话启动得1分,
        以总结性情感句启动得0分。
      scale: [0, 1]
    - id: show_not_tell_ratio
      instruction: |
        随机抽取章节中5处情感表达。每处判断:是通过具体可见的行动/细节/
        对话暗示(show),还是通过"他感到悲伤"类直接陈述(tell)。
        show比例 ≥ 0.6 得满分,每低0.1扣0.2分。
      scale: [0, 1]
    - id: surprise_moment
      instruction: |
        章节中是否有至少一处令人"猜不到但事后觉得理所当然"的情节转折、
        人物行动或对话内容?如果有,得1分;如果全章情节发展完全可预测,得0分。
      scale: [0, 1]
    - id: character_voice_consistency
      instruction: |
        主视角角色的行动和对话是否符合其已建立的性格/动机?
        是否存在"为了推进情节而让角色做奇怪事"的感觉?
        完全一致=1分,有1处明显违和=0.5分,多处违和=0分。
      scale: [0, 1]
  pass_threshold: 总分 ≥ 2.8 / 4.0  # 【设计决策须校准】
```

**rubric B:意图共鸣(北极星对照)**

```yaml
rubric_intent_resonance:
  description: "判断章节是否让读者感受到 AuthorIntent.reader_feeling 中声明的核心感受"
  preamble: |
    本书的北极星(AuthorIntent):
    reader_feeling = "${author_intent.reader_feeling}"
    core_emotional_arc = "${author_intent.core_emotional_arc}"
    do_not_betray = "${author_intent.do_not_betray}"
  dimensions:
    - id: resonance_moment
      instruction: |
        章节中是否至少有一个具体场景/台词/细节,让读者真实感受到
        reader_feeling 中声明的核心感受?需要给出具体引文。
        有且引文可信=1分;勉强算数=0.5分;完全感受不到=0分。
      scale: [0, 1]
    - id: no_betray
      instruction: |
        章节内容是否触碰了 do_not_betray 红线中的任何一条?
        未触碰=1分;擦边=0.5分;明确触碰=0分(此项为硬否决项)。
      scale: [0, 1]
  pass_threshold: 总分 ≥ 1.5 / 2.0  # 其中 no_betray 不得低于 0.5
```

**rubric C:多方案差异度**

```yaml
rubric_option_diversity:
  description: "判断 OptionSet 中的 2–4 个方案是否有实质差异"
  dimensions:
    - id: structural_difference
      instruction: |
        比较各方案的情节走向、人物行动结果。是否存在至少一对方案,
        其选择会导致后续章节走向显著不同(不只是写法不同)?
        是=1分;差异仅在风格/写法层面=0.5分;实质相同=0分。
      scale: [0, 1]
    - id: cost_tradeoff_explicit
      instruction: |
        每个方案是否明确说明了其"代价"或"风险"?
        所有方案都有明确代价说明=1分;一半有=0.5分;基本没有=0分。
      scale: [0, 1]
  pass_threshold: 总分 ≥ 1.5 / 2.0
```

**rubric D:意见→重做闭环**

```yaml
rubric_feedback_loop:
  description: "判断 AI 的重做是否真正响应了人的自然语言意见"
  preamble: |
    原意见(FeedbackNote.nl_critique): "${feedback_note}"
    原版本片段(before): "${original_segment}"
    重做版本片段(after): "${revised_segment}"
  dimensions:
    - id: directive_addressed
      instruction: |
        逐条解析意见中的核心指令。重做版本是否对每条核心指令都有
        可见的文本响应(不只是重新生成一遍)?
        全部响应=1分;部分响应=0.5分;基本没改=0分。
      scale: [0, 1]
    - id: no_regression
      instruction: |
        重做版本是否保留了原版本中人没有批评的优点?
        即:有没有"改了A但丢了B,而B原本是好的"的情况?
        无回退=1分;轻微回退=0.5分;明显回退=0分。
      scale: [0, 1]
  pass_threshold: 总分 ≥ 1.5 / 2.0
```

#### 2.4.3 防偏差策略(对齐工程10 §4.2)

| 偏差类型 | 具体缓解措施 |
|---|---|
| **自我偏好** | judge 模型与生成模型**必须不同**。若生成用 claude-opus,judge 用 claude-sonnet 或 gemini-pro-1.5;验收集中交叉对比两个 judge 模型结论 |
| **位置偏好** | 多方案 rubric 中随机化方案顺序;对同一 OptionSet 运行两次 judge(顺序互换),取均值 |
| **冗长偏好** | rubric 中显式加入"简洁"惩罚项;对超过目标字数 20% 的章节,长度项主动扣分 |
| **标准模糊** | rubric 每条标准均写具体可操作判断准则(见上文设计);每条标准包含具体示例或引文要求 |
| **与人评交叉** | 验收集中至少 15% 的 LLM judge 样本同时做 T4 人评,计算 Pearson |r|;|r| < 0.40 时该 rubric 标记为"校准不足",不得用于硬门判定 |

### 2.5 T4 · 人评

#### 2.5.1 黄金集构建

**黄金集(Gold Set)**用于两个目的:①校准 LLM-as-judge;②建立可信的 H 系列基准。

构建规则:
- 规模:验收阶段最少 **30 章**;其中涵盖至少 3 种结构节点类型(climax/midpoint/resolution)
- 来源:①作者本人(TasteModel 持有者)的 H1/H2/H3 评分;②2 名 beta 读者独立评分
- 一致性要求:3 名评分者的 H2 均值之间,两两 Pearson |r| ≥ 0.55【设计决策须校准】;否则重新校准评分锚点
- 格式:每章有自由文本注释(至少 2 句);不允许只给分数不写理由

```python
@dataclass
class GoldChapter:
    chapter_id: UUID
    work_id:    UUID
    # 三名评分者各自的 H1/H2/H3
    evaluations: list[HumanEvalRecord]
    gold_h1: float  # 三者均值
    gold_h2: float
    gold_h3: float
    inter_rater_r: float   # 评分者间 Pearson r(H2)
    free_texts: list[str]
    is_calibration_pass: bool  # inter_rater_r >= 0.55
```

#### 2.5.2 抽样策略(验收阶段)

验收阶段的人评抽样比例高于日常运营,目的是建立足够置信度的基准:

| 阶段 | 样本比例 | 优先级规则 |
|---|---|---|
| **验收(本文)** | ≥ 30% 章节 | 必选所有结构节点章 + 低 Q4 章 + 随机补充 |
| **上线后日常** | 约 10% / 卷 | 沿用工程6 §3.4.5 策略 |
| **品味模型校准触发** | 额外 +5% | 每卷结束,当 Q/H 相关系数 |r| < 0.40 时触发 |

#### 2.5.3 人评与 LLM judge 交叉校准

```python
def validate_judge_calibration(
    gold_set: list[GoldChapter],
    judge_scores: dict[UUID, float],  # chapter_id → LLM judge 总分
) -> dict:
    """
    计算 LLM judge 分数与人评 gold_h2 的 Pearson r。
    r < 0.40 → rubric 标记"校准不足",该 rubric 不得用于硬门判定。
    """
    h2_values     = [g.gold_h2 for g in gold_set if g.chapter_id in judge_scores]
    judge_values  = [judge_scores[g.chapter_id] for g in gold_set if g.chapter_id in judge_scores]
    r, p_value    = pearsonr(h2_values, judge_values)
    calibrated    = abs(r) >= 0.40
    return {
        "pearson_r": r,
        "p_value":   p_value,
        "n_samples": len(h2_values),
        "calibrated": calibrated,  # False 时该 rubric 降为软门
        "recommendation": "合格" if calibrated else "须重新校准 rubric 描述或锚点"
    }
```

### 2.6 通过标准分级:硬门 vs 软门

**原则**:硬门失败 → 系统不得上线;软门失败 → 记录、告警、限期整改,但不阻断上线。

#### 硬门(Hard Gate)— 任一失败即阻断上线

| 硬门编号 | 检验内容 | 手段 | 阈值 |
|---|---|---|---|
| HG-01 | 所有 T1 确定性断言通过率 | T1 | 100% |
| HG-02 | AI 绝不替人写正文(Segment.created_by == "ai") | T1 | 100% |
| HG-03 | 多本书数据不串味(work_id 隔离) | T1 | 100% |
| HG-04 | M1 全书均值 ≥ 0.80(宽松版,上线前) | T2 | ≥ 0.80 |
| HG-05 | 伏笔回收率 M3 ≥ 0.65(上线前可放宽) | T2 | ≥ 0.65 |
| HG-06 | 策略违规检测零容忍 | T3 硬规则层 | 0 violations |
| HG-07 | 工具选择正确率 ≥ 0.85(golden trace) | T3+T1 | ≥ 0.85 |
| HG-08 | 多章任务完整完成率 ≥ 0.95 | T1 | ≥ 0.95 |
| HG-09 | 人评 H2 均值 ≥ 2.5 /5 (≥ 30 章黄金集) | T4 | ≥ 2.5 |
| HG-10 | 意见→重做闭环:FeedbackLoop rubric ≥ 1.2/2.0 | T3 | ≥ 1.2/2.0 |

#### 软门(Soft Gate)— 失败记录告警,限期 2 周整改

| 软门编号 | 检验内容 | 手段 | 阈值 |
|---|---|---|---|
| SG-01 | M1 全书均值 ≥ 0.82(完整目标) | T2 | ≥ 0.82 |
| SG-02 | Q1 卷均值 < 2.0 /千字 | T2 | < 2.0 |
| SG-03 | Q4 有值章均值 ≥ 2.8 | T2 | ≥ 2.8 |
| SG-04 | Q5 钩子覆盖率 ≥ 0.90 | T2 | ≥ 0.90 |

### 2.7 真实复杂测试语料要求

验收测试语料必须满足以下**复杂度要求**,不接受人工简化的"toy case":

| 维度 | 最低要求 | 理由 |
|---|---|---|
| **题材** | 具有多线叙事或多视角的题材;不接受单线单主角无支线 | 测试设定圣经与记忆检索的跨线管理能力 |
| **北极星** | AuthorIntent 有非空 `do_not_betray`(≥ 2 条红线) | 验证意图贯穿的完整性 |
| **伏笔密度** | 每5章至少埋1条伏笔,须有跨卷回收的伏笔 | 测试伏笔状态机 + 跨上下文记忆检索 |
| **设定复杂度** | ≥ 3 个主要角色,各有独立 voice_profile;≥ 1 个世界观规则 | 测试设定圣经注入 + 角色声音一致性 |
| **反馈密度** | 每卷至少 3 次真实自然语言意见驱动重做 | 测试意见→重做闭环 |
| **多方案覆盖** | 每卷至少 2 个决策点给出 OptionSet,人做选择 | 测试多方案生成与人机协作 |
| **文字量** | 场景1 须达到 ≥ 5万字真实输出;场景3 须达到 ≥ 30万字 | 验证百万字续航能力 |

| HG-04(M1 < 0.80)失败 | 门槛1 一致性检测召回率不足;或 Prompt 引入了长跨度矛盾 | 检查 ConsistencyFlag 的漏检 case;加强门槛1 扫描 |

| HG-09(H2 < 2.5)失败 | 内核3 反平庸效果不足;或 TasteModel 冷启动偏差 | 检查 Q1/Q4 是否也低;增加 StyleExemplar 正例;加强反平庸 prompt |
| SG-09(|r| < 0.35)失败 | rubric 标准模糊;或 judge 模型与生成模型相同 | 修订 rubric 具体判断准则;更换 judge 模型 |
| 断点续跑失败(场景3) | SQLite WAL 未正确配置;或 Segment 写入不是事务性的 | 检查 WAL 模式配置;检查写入 Segment 的事务边界 |
| 多本书串味(HG-03)失败 | work_id 过滤条件缺失;或 AgentMemory 跨书查询无隔离 | 审查所有涉及 work_id 的查询语句;AgentMemory 查询加 work_id 过滤 |

## §7 · 开放问题

1. **黄金集冷启动**:验收需 ≥ 60 章人评,但系统刚建成时无法预先积累——建议验收分两阶段:Phase 1(≥ 30 章)做初步验收放行内测,Phase 2(≥ 60 章)做正式生产验收。

2. **崩坏率曲线基准**:场景3 的 M2 ≤ 240、M4 ≤ 60 等阈值是工程估算,无已验证外部对照。**这些值在首部完整百万字作品完成前都是可疑的**,须在完成后立即修订。

3. **多 judge 模型可用性**:T3 防偏差要求用与生成模型不同的 judge 模型(如 gemini-pro-1.5),其 API 可用性和定价需在验收执行前确认【需复核】。

4. **断点续跑中断类型覆盖**:场景3 仅测试了 `kill -9` 注入。其他中断类型(网络超时、OOM、API 限流中断)的恢复行为需要独立测试用例覆盖。

5. **TasteModel 冷启动评分漂移**:前几章无人评时,H 系列缺失,rubric 锚点由 TasteModel 默认值提供——此时 LLM judge 与人评的 |r| 可能显著低于 0.40,是否允许用默认值作为临时锚点待确认。
