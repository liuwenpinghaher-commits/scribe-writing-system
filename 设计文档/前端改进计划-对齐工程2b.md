# 前端改进计划 · 对齐工程2b、达到"好用"

> 现状:`scribe/web-app/`(React+TS+Vite+Tiptap)是**方向正确但深度严重不足的薄客户端**;能打开,但与 [工程2b](工程2b-小说编辑器面板详设.md) 的规划差距很大,**离"好用"还差关键闭环**。
> 本文是逐面板差距→分阶段改进的完整计划。验收标准 = 工程2b 的"**一天写作动线**"8 步全部走顺。

---

## 0. 诊断:为什么"不好用"(根因)

现状失败不在"少了几个按钮",而在**几条主交互闭环断裂 + 几个架构地基缺失**:

| 根因 | 后果(用户实感) |
|---|---|
| **意见→重做没有 diff 预览**(重写直接覆盖) | 作者**看不到 AI 改了什么**,无法判断接受与否——最致命卡点 |
| **OptionSet 在右栏迷你列表、无差异矩阵** | 关键决策**不知道选哪个、区别是什么**,"AI 不拍板"形同虚设 |
| **只有整章意见,无段落级 + 无批注** | 视线被迫离开正文,违反"视线始终在文字上" |
| **无卷(Volume)层级,章节平铺** | 百万字导航失效 |
| **正文无 SegmentNode/AI·人标记/引用展开** | AI 贡献不透明、不可追溯——产品核心卖点没落地 |
| **设定/门槛侧栏只读,看到问题无法处理** | "看得到、动不了",比没有更挫败 |
| **北极星非 sticky、无偏离提示** | 写着写着就忘了"这本书要干什么" |
| **AI 操作全走 `chat()` 拼字符串指令** | 不可控、无草稿区、无流式、无 diff —— 上面多条都因此实现不了 |

> **结论:必须先补"架构地基",主交互闭环才修得动;否则只是给薄客户端贴按钮。**

## 一天动线现状(8 步只有 1 步通)

| 步 | 动作 | 现状 | 卡点 |
|---|---|---|---|
| 1 | 开库看角标 | 卡片无角标 | 进书前不知哪本有待办 |
| 2 | 回到上次章节 | ✅ URL 深链已做 | — |
| 3 | 看札记→规划伏笔 | 有札记,但无证据跳转/规划操作 | 看到动不了 |
| 4 | 大纲树右键→AI续写 | 无卷/无右键,只能点进章再点按钮 | 节奏断 |
| 5 | OptionSet 三卡决策 | 右栏迷你卡,无差异矩阵 | 决策体验缺失 |
| 6 | 提意见→看 diff→接受 | 整章重写直接覆盖,无 diff | **最致命:看不到改了啥** |
| 7 | 查冲突→提意见重做 | flag 只读,无操作 | 看到动不了 |
| 8 | 标记完成 | 编辑器内无此操作 | 流程断 |

**改进目标:这 8 步全部走顺 = "好用"达标线。**

## 改进计划(分 5 阶段;每阶段含 后端依赖 / 前端 / 验收)

> 标注:🟦前端 🟩后端 ⭐"好用"关键

### 阶段 P0 · 架构地基(解锁后续一切;⭐⭐⭐)

没有这层,P1 的主交互修不动。

| 项 | 内容 | 端 |
|---|---|---|
| P0-1 **卷 Volume 层级** | 后端已有 volumes 表,但 API/前端未用:补 `GET/POST /works/{id}/volumes`、章归属 volume_id;前端大纲树两级 | 🟩🟦 |
| P0-2 **SegmentNode + 引用** | 正文按段落存(已有 segments 表),每段带 `segment_id/created_by/citation_ids`;Tiptap 自定义 SegmentNode 扩展;写作时回填"引用了哪些设定/想象/伏笔" | 🟩🟦⭐ |
| P0-3 **结构化 AI 动作 API**(取代 chat 拼指令) | `POST /chapters/{id}/actions/{continue\|rewrite\|expand…}` → 返回**草稿(不直接覆盖)** + 改动说明;rewrite 接 FeedbackNote;**这是 diff 预览/草稿区/可取消的前提** | 🟩⭐ |
| P0-4 **SSE 实时推送** | `GET /works/{id}/events`(SSE):optionset.created / imagination.structured / insight.new / 写作流式 token;前端替代 `rev+bump` 轮询 | 🟩🟦 |
| P0-5 **PreferenceSignal 回流前端化** | 选方案/接受重写/"这是故意的"/对话覆盖 → 显式写偏好(已有 record_preference,前端补调用点) | 🟦 |
| P0-6 **WorkSummary 汇总端点** | `GET /works` 返回 word_count/progress/new_insight_count/pending_optionset_count/last_chapter(消除 N+1,喂作品库角标) | 🟩 |
| P0-7 **偏离检测 + hard/soft 红线** | AuthorIntent.do_not_betray 支持 hard/soft;`POST /chapters/{id}/intent-check` 返回对齐/软偏离/硬违反(喂北极星条 + 对话硬冲突卡) | 🟩 |

**验收**:草稿/diff/卷/段落引用/实时事件 这些"管道"通了(单测 + curl)。

### 阶段 P1 · 主交互闭环(修致命卡点;⭐⭐⭐)

| 面板 | 改进 | 验收(动线步) |
|---|---|---|
| **意见→重做(面板6)** | 段落悬停工具栏[提意见/引用];意见**段落内联展开**+快捷模板[太长/太直白/更狠/AI腔];rewrite 走 P0-3 出草稿→**side-by-side diff 预览**+"改动说明"→[接受 ⌘↵/保持原版 Esc/再改];链式>3 提示查北极星 | 步6 通 ⭐ |
| **OptionSet(面板5)** | 就绪时**中央区切换为多卡**;每卡 差异矩阵(情感走向/人物代价/情节后果)+北极星契合★+正文节选展开+红线警告;选择理由→回流品味;选后过渡回正文并触发续写;快捷键 1-4/E/↵/Esc | 步5 通 ⭐ |
| **正文编辑器(面板3)** | SegmentNode 渲染;AI 草稿淡蓝/人工淡绿 mark;段落元信息行(创建者/引用 N 项 ▸ 展开);章头 钩子★+字数/目标;diff clean/unified/sidebyside;⌘S/⌘⇧D(标记完成) | 步6/8 通 |
| **大纲树(面板2)** | 卷→章两级;节点角标 ⚠N/🧵N/🎯;右键菜单(AI续写/生成大纲/提意见/标记/版本/删除);虚拟滚动(行高32,从第1章启用);↑↓/↵/Space/F2 | 步4 通 |

### 阶段 P2 · 导航与输入(零摩擦;⭐⭐)

| 面板 | 改进 |
|---|---|
| **作品库(面板1)** | 卡片显字数/进度条/📝札记/◆方案角标(用 P0-6);`⌘⇧O` 切书浮层(选→存档→恢复上次章);新建作品向导(名称/体裁/北极星/起步);跨书搜索 |
| **想象捕获(面板4)** | `⌘I` 全局浮层(自动聚焦/类型标签/排期/⌘↵);正文内 `//` 内联(吃掉 // 字符);想象库面板(右栏,状态筛选/推荐排期);SSE 结构化刷新 |
| **北极星条(面板11)** | 改为 **sticky 顶部条**(任意滚动可见);4 态边框(未设定橙/对齐绿/软偏离琥珀+Toast/硬违反红+banner,用 P0-7);hard/soft 红线分级;"AI 帮我提炼";⌘⇧P 编辑 |

### 阶段 P3 · 主编与门槛"可操作"(看得到也动得了;⭐⭐)

| 面板 | 改进 |
|---|---|
| **主编对话(面板7)** | 按 concern_type 分层渲染:HardConflictCard(红,证据跳转+提意见重做+一键覆盖+标记误报)/SoftSuggestionCard(琥珀)/InlineOptionSetCard;对话识别想象意图→"存为想象";⌘⇧A 抽屉;消息持久化 |
| **主编札记(面板8)** | kind 图标分类;**证据跳转**到章节段落;操作[规划回收/这是故意的(→回流偏好)/标记误报];严重度筛选;写作活跃期不打扰 |
| **门槛侧栏(面板10)** | 折叠角标入口(⚠/🧵/📌);连贯每条**证据跳转**+裁决(确认真错→开 FeedbackNote/标记误报→提阈值/AI修复→diff);伏笔(本章状态+全书超期)+规划回收+编辑器高亮 ⌘⇧H |
| **设定圣经(面板9)** | 分类 tab+计数;角色卡(性格/声音/关系/CharState 时间线);**行内编辑**;改设定→**影响分析**(受影响章节+冲突)→标记复查批量建 flag;关系图谱(后置) |

### 阶段 P4 · 体验打磨(从"能用"到"好用极致")

- **专注/全屏写作模式** `⌘⇧F`(隐左右栏、680px 居中、18px/1.8);北极星缩为色条。
- **命令面板** `⌘K`(跨书/章/设定 搜索 + 全局跳转)。
- **防丢稿**:localStorage 5s 自动存 + `beforeunload` + 本地草稿恢复提示;(Y.js 多 tab 防冲突,后置)。
- **键盘体系全套**(各面板快捷键 + 取消 AI `⌘.`)。
- **深/浅色切换** + `prefers-color-scheme`;**iPad 竖屏底部 Tab Bar**;**章节拖拽重排**(跨卷伏笔冲突警告);**分支版本 UI**(切换/合并)。

## 横切:每阶段都要过的 UX 质量门(ui-ux-pro-max)

- **无障碍**:全控件键盘可达 + `:focus-visible`;icon-only 按钮带 `aria-label`;状态用色+图标/文字双编码;对比 ≥4.5:1。
- **反馈**:异步按钮防重入+spinner(已有 Btn);错误就近+可重试(已有 State);toast `aria-live`/3-5s(已有)。
- **加载**:>1s 用骨架屏而非纯 spinner(待补)。
- **动效**:150-300ms、transform/opacity、`prefers-reduced-motion`(已有基础)。
- **导航**:深链(已有);back 恢复状态;焦点随路由移到主区。
- **性能**:列表虚拟化(已有初步)、SSE 替代轮询(P0-4)、按路由 code-split(bundle 656KB 偏大)。

## 依赖与建议顺序

```
P0 地基(卷 / SegmentNode / 结构化动作API / SSE / 偏好回流 / 汇总端点 / 偏离检测)
   └─▶ P1 主交互闭环(意见diff / OptionSet中央 / 编辑器 / 大纲树)   ← 做完这步,"一天动线"基本走通 = 好用达标线
        └─▶ P2 导航与输入(作品库 / 想象浮层 / 北极星sticky)
             └─▶ P3 主编与门槛可操作(对话卡 / 札记 / 门槛 / 设定圣经)
                  └─▶ P4 打磨(专注模式 / 命令面板 / 防丢稿 / 主题 / 拖拽 / 分支)
```

**最小"好用"里程碑 = P0 + P1**:把第 6 步(意见→diff→接受)和第 5 步(OptionSet 决策)这两条致命闭环修通,产品就从"能打开"跨到"真能用来写"。

## 工作量粗估(数量级,非承诺)

| 阶段 | 前端 | 后端 | 说明 |
|---|---|---|---|
| P0 地基 | 中 | **大** | 后端要加卷/段落引用/结构化动作/SSE/偏离检测/汇总 —— 是大头 |
| P1 主交互 | **大** | 中 | Tiptap 自定义扩展 + 中央区 OptionSet + diff 流 |
| P2 导航输入 | 中 | 小 | 浮层/向导/sticky/快捷键 |
| P3 可操作侧栏 | 大 | 中 | 影响分析/证据跳转/对话卡 |
| P4 打磨 | 中 | 小 | 体验细节,可持续迭代 |

诚实提示:**这是数周量级的前端+后端协同工程**,不是一轮能全做完;但 **P0+P1 做完即可达到"好用达标线"**,建议先打这两阶段。
