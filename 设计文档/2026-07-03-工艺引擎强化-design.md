# 工艺引擎强化设计:从"软提醒"到"可执行的叙事工艺机制"

> A线设计文档。基于四方向全网调研(叙事张力/伏笔理论、角色弧光/情感曲线、场景工艺/节奏/POV、AI 小说系统学界+业界实践,共 50+ 来源)+ 对 scribe3 现有代码的客观锚定,给出工艺引擎强化的整体方案。
>
> **日期**:2026-07-03 · **分支**:后续新分支或续 feat/audit3-fixes · **范围**:scribe3 后端为主(store/ingest/craft/app/critique)+ 少量前端露出

---

## 一、诊断:四个已证实的缺口(代码锚点)

| # | 缺口 | 代码证据 |
|---|------|----------|
| ① | **弧光白抽**:char_state 每章 ingest 抽取,但唯一消费方是 timeline 弧光泳道(`store.py:1699`);写作 prompt(`_editor_system`/`_editor_write_system`,app.py:911/1016)完全不注入;前端角色详情也不露出 | `add_char_state` 16 个调用方全在 ingest/timeline 侧 |
| ② | **张力零机制**:全库只有 `dramatic_irony`(knowledge.py)一个反讽近似,无 stakes/urgency/钩子/开环任何机制 | — |
| ③ | **伏笔纯软提醒**:promise 表只有 `text/setup_chapter/payoff_chapter/status(open/closed)/kind/clues`;`_overdue_flag`(store.py:154)只报超期;`_editor_system` 注入"开着的承诺线·勿忘"一行(app.py:951)。何时收/收哪条/收前要做什么,系统不知道 | schema + 注入点均已核 |
| ④ | **设定软注入摆设**:facts 全知/限知帧一次性截 28 条注入(app.py:932/941),codex 全塞;没有"本章相关性"过滤,没有注入清单回显,作者不知道哪些设定实际生效 | `_facts`/`_codex_block` |

调研结论对这条路线的总背书:**张力/伏笔兑现/长程一致性都不会从模型参数里涌现,必须在生成流程里显式编码**——[100-Endings 论文](https://arxiv.org/html/2604.09854v1)(LLM 系统性过早消解不确定性,显式结构约束把晚期张力从 0.139 提到 0.339)、[Codified Foreshadowing](https://arxiv.org/pdf/2601.07033)(显式因果链+验证器把伏笔兑现率从 ~40% 提到 80%+)、[DOC](https://arxiv.org/abs/2212.10077)("抽了就注回"本身带来连贯性 +22.5pt)。

## 二、总架构:一进一出两个枢纽

所有机制收敛为两个共用枢纽,避免十几个机制各自为政:

```
┌─────────────────────────────────────────────────────┐
│ 章前组装器 assemble_chapter_brief(st, seq, focalizer) │  ← 新模块 scribe3/brief.py
│  产出「本章创作简报」结构化块,注入 _editor_write_system │
│  · 弧光指令(M3)   · 伏笔窗口指令(M1)                  │
│  · 张力目标+开环账本(M2) · 关系子矩阵(M4)             │
│  · 场景卡硬约束(M5) · 相关设定包+注入清单(M6)          │
│  · 待激活角色心跳(M3附)                               │
└─────────────────────────────────────────────────────┘
                    ↓ 写作(chat/write)
┌─────────────────────────────────────────────────────┐
│ 章后检测环(critique.quality_flags 同管线扩容)          │
│  · 兑现验证器(M1) · 张力检查清单(M2)                  │
│  · 弧光跳变(M3)  · 节拍贴合度(M5)                     │
│  · filter words/PD曲线(M7) · 事实效度区间矛盾(M7)      │
│  检测产出 → span 级定向修订指令(M8),不做整章 self-critique │
└─────────────────────────────────────────────────────┘
```

原则:**规划期编码(前馈)重于生成后补救(反馈)**;检测器输出必须是"过/不过 + 具体修复指令",不是分数。ingest 继续做反哺,但每个抽取物必须有≥1个消费出口(消灭"白抽")。

## 三、模块设计

### M1 伏笔生命周期状态机(治缺口③,P0)

理论:Sanderson promises/progress/payoff([2025 讲义](https://www.brandonsanderson.com/blogs/blog/brandon-sandersons-2025-guide-to-plot-lecture-2));三次法则+salience 衰减;MICE FILO 嵌套([Writing Excuses 16.40](https://writingexcuses.com/16-40-nesting-threads-in-the-m-i-c-e-quotient/));Zeigarnik 开环预算。

**Schema 扩展**(migration,promise 表加字段,旧数据默认值兼容):
- `tier`: book | arc | chapter(默认 chapter)
- `payoff_window`: `[min_ch, max_ch]`(按 tier 默认:章级 setup+1~+3、卷级 +5~+15、书级 = 至 climax 章;可改)
- `refresh_count` / `last_refresh_at`(章号)
- `promise_type`: tone | story | character | structural(可选,先不强制)
- 派生量 `salience`(不存库,查询时算):随 `max_chapter - max(setup, last_refresh)` 衰减

**状态机**:`open(planted) → refreshed → armed(进窗且 salience 达标) → paid / expired / abandoned`(status 字段扩枚举;`closed` 兼容映射为 paid)。

**升级式干预**(替代纯软提醒,核心):
1. 进窗 → 现有软提醒(保留);
2. 过窗 50% → 该 promise 的"刷新或兑现"指令**自动写进章前简报**(M0 组装器),并在 beats 阶段生成草案条目(人可删);
3. 过窗 100% → 阻塞级警告 + 三选一决策推到作者面前:立即兑现 / 显式展期(记 reason)/ 降级 abandoned。何时收仍归人,但决策点由系统推送。
4. **兑现前置门槛**:salience 低(近 K 章未刷新)时先产出刷新节拍——"三次法则"机器化;已刷新 ≥3 次仍未兑现 → "过度提示,读者已猜到"提醒。

**FILO 检查**:收 arc 级线时列出其窗口内未收的 chapter 级线;book 级线中途关闭且剩余篇幅多 → 警告"主线程提前闭合"。

**兑现验证器**(章后):声称 paid 的 promise,LLM 盲验"兑现事件是否在正文出现且与埋设语义一致"(Codified Foreshadowing 的验证器思路)。

**ingest 联动**:抽取段新增"本章触及了哪些 open promise(引文)"→ 自动更新 `last_refresh_at/refresh_count`(与母题章感知 motif_instance 同构,复用其管线形态)。

### M2 张力机制(治缺口②,P0 清单 + P1 检测器)

理论:三因子模型 stakes×uncertainty×urgency;Maass micro-tension;MDQ 戏剧问题层级;麦基价值转折;yes-but/no-and 结果语法;网文钩子类型学与"1 强 2 缓";Sternberg 悬念/好奇/惊讶三通道;希区柯克炸弹理论;[Dramatis](https://cdn.aaai.org/ojs/8836/8836-13-12364-1-2-20201228.pdf) 出路收窄;100-Endings 结局分歧度。

**2a. 章级张力检查清单**(P0,接 critique 管线,每项"过/不过+修复指令"):
1. 本章戏剧问题存在且章末被"回答并升级"(scene_question 状态机);
2. 场景结局全部为 yes-but / no-and,climax 前无裸 yes(泄气检测);
3. 至少一场发生价值极性反转(与 M5 场景卡联动);
4. 章末钩子存在,`hook_type + hook_strength` 标注,近 3 章强度序列非全强/全缓;
5. micro-tension 抽查:每 ~500 字窗口内是否有 POV 情绪对立/念头交战,标记"荒漠段"(与既有 telling 检测器同族,LLM rubric);
6. 进展路标:本章至少一条 open promise 产生 signpost 级进展(与 M1 `last_refresh_at` 联动)——**"忘了推"比"忘了收"更早报警**;
7. 信息差资产盘点:限知引擎输出"读者知/角色不知"面,irony 面长期为空 → 提示主动制造读者知情点(炸弹理论进攻性用法——这是 scribe3 限知引擎独有的红利,业界无人有此基座)。

**2b. 张力预算(前馈)**:书级持目标张力曲线(模板:厚中间层+中后段峰值,对抗 LLM"转折提前+晚期塌方"通病);章前简报注入本章张力档位(1-5)+ 开环账本(open promise 按 tier 加权计数,book×3/arc×2/chapter×1,超上限拦截新坑:"先收一条再开")。

**2c. 张力检测器**(P1,由廉价到贵):三因子 LLM rubric 打分(短板即诊断);出路收窄(列主角出路+成功率,max 过高 → "堵退路");结局分歧度简化版(章末采样 N=10 个续写预测,分歧率即张力值,重点盯 80% 进度后)。

### M3 弧光引擎(治缺口①,P0)

理论:K.M. Weiland [Lie→Truth 状态机](https://www.helpingwritersbecomeauthors.com/write-character-arcs/)(ghost/lie/truth/want/need + positive/flat/negative 三型)+ 15 拍绑定结构位置;DOC"抽了就注回"。

**静态锚**(character/codex 侧加字段,建卷时 LLM 辅助生成、作者定稿):`ghost`(一句创伤事件)、`lie`(一句可证伪错误信念)、`truth`(对偶)、`want`(外在目标)、`need`(内在需要)、`arc_type`(positive/flat/disillusionment/fall/corruption)、`private_agenda`(配角必填:与主线相交的独立日程)。

**arc_plan 里程碑表**(每主要角色,~8-15 行):`{beat_name, target_chapter, lie_belief_target(0-100), trigger_event}`。

**动态标量**:char_state 加 `lie_belief`(0-100)——ingest 时 LLM 更新,把弧光进度从散文压成可监控数字。

**章前注入**(组装器,三行指令而非全文,防淹没):
```
【角色弧光·柳怀玉】弧型:disillusionment | Lie:"官法大过阴律"
当前:lie_belief=62(上章位移+8,因目睹判牍改命)
本章节拍:二幕下半(midpoint 已过) → 指令:62→68 缓升;她应第一次
主动用 Lie 的逻辑做一个小决定但自我辩解为权宜。禁止:顿悟、明说信念。
```

**弧光跳变检测器**(章后):ingest 反抽 lie_belief 与里程碑目标比对,单章位移 >15 报"顿悟来得太便宜"。

**出场心跳**(零新表):从 char_state 推导每个角色最后活跃章,主要配角 gap>3 → 章前简报"待激活名单"(附 private_agenda)。

**前端露出**:角色详情页显示 静态锚 + lie_belief 曲线 + char_state 历史(可编辑回写——RecurrentGPT 的"记忆必须可被作者看和改")。

### M4 关系动态矩阵(新挖掘,P1)

理论:[Prom Week 社交物理](http://www.ben-samuel.com/wp-content/uploads/2015/09/FDG-2011-Prom-Week-Social-Physics-as-Gameplay.pdf)(有向不对称数值网络);关系弧 2×2 四型 + Token/Breakup 里程碑。

**新表 `relation_state`**:`{chapter, from_char, to_char, trust, affection, debt, awe(各-100~100), tags[], delta_reason}`。三纪律:
1. **ingest 只出增量**且必须有本章事件背书("A→B trust −30,因:撞见 B 私通仇家"),无背书拒收——防幻觉漂移、可审计;
2. **不对称是特性**:`debt`(亏欠/恩义)轴对中文叙事尤其提张力;
3. **注入只给子矩阵**:本章出场角色两两对 + 每对最近 2 条 delta_reason + 关系弧下一里程碑("你俩计划 ch30 决裂,本章应埋第二根刺")。

**检测器**:某对关系连续 4 章零增量 → 线死了;trust 单章摆幅 >50 → 翻脸没铺垫。

### M5 场景卡 schema 升级(新挖掘,P1——节拍层的结构化)

理论:Swain scene/sequel(goal-conflict-disaster / reaction-dilemma-decision);Bickham 三型灾难;McKee/Story Grid value shift("没有不含转折的场景");网文章纲模组(冲突-高潮-钩子)。

节拍(beats)条目从纯文本升级为可选结构字段(向后兼容,纯文本仍可用):
- `type`: scene | sequel;scene 必填 `goal/conflict/disaster_type(no|yes_but|no_and_furthermore)`;sequel 必填 `reaction/dilemma/decision`
- `value_at_stake` + `polarity_start/end`(志怪题材预置价值轴词表:安全/危险、信任/背叛、真相/蒙蔽、人/非人…)
- `turning_point`(期望与结果裂开的那一刻,一句话)
- `hook_type + hook_strength`(章末条目)
- `tempo`: fast | slow;`mode`: scene | summary(重要事件禁 summary 一笔带过)
- `pd_range`(心理距离变焦计划,见 M7)

**规划时校验**:polarity 无变化 → nonevent;decision→下场 goal 断链;连续同型灾难 → 单调;章纲缺"冲突源/高潮点/章尾钩子"任一 → 警告(网文模组)。
**章后贴合度**:LLM 盲抽"这场什么价值朝哪翻转了",与卡比对——抽不出 = 正文没写出转折(DOC 事后贴合度的廉价版);逐节拍问"是否兑现",输出未兑现列表。

### M6 注入器改造:三态注入 + 预算 + 可见性(治缺口④,P0)

理论:业界收敛的标准答案(NovelCrafter Codex / NovelAI Lorebook / Sudowrite Saliency):**少量 always + 提及触发(别名匹配+关系一跳)+ 检索兜底,受 token 预算约束,并向作者展示注入了什么**。纯全塞与纯向量检索都是被淘汰形态。

- 设定条目(facts/codex/素材)加 `injection_mode`: always | detected | never(默认 detected)+ `aliases[]` + `priority`;
- 章前组装器对本章节拍/演绎文本跑**别名匹配 → 命中实体 + 关系图一跳扩展** → 组成本章设定包;
- 显式 **token 预算分配**(设定 X / 旧章事实 Y / 声音库 Z / 简报 W),超预算按 priority 裁,不无序堆叠;
- **注入清单回显**:`/chapter-brief` 端点返回本章实际注入了哪些条目,前端在写作页可看("本章生效设定")——治"软注入摆设、不回显效果"的另一半:看得见才可调。
- 与 UI二轮块四-a 的素材库(material 表)天然衔接:素材默认 `never`(非正典不注入),但可手动升为 detected 供文风参考。

### M7 检测器扩容(P1,多数近零成本)

1. **中文 filter words 检测器**(最廉价):词表"看到/看见/听到/听见/闻到/感到/感觉/觉得/意识到/察觉/注意到/发现/知道/心想/暗忖/似乎/想起"——POV 段每千字密度超阈值报警 + "删壳直写"示例;同表兼检"他想:"引导语密度(推自由间接体)。白名单:对话内、"发现"作情节动词。
2. **PD 心理距离刻度**:渲染 prompt 注入 Gardner 5 档中文刻度定义 + 本场变焦计划(与 focalizer 锚叠加:"谁的头"已有,补"进头多深");章后逐段 LLM 打 PD 分出曲线,全平 → 单调,突跳 → 变焦断裂。**这是限知引擎缺的最后一块**。
3. **MRU 倒序检测**:反应槽位"感受→反射→行动"倒序抽查(先答话再写心跳 = 假)。
4. **事实时间效度区间**([FACTTRACK](https://arxiv.org/abs/2407.16347)):fact 加 `valid_from_ch/valid_to_ch/superseded_by`;跨章矛盾检测从"整体比对"改为"新事实 vs 同主语同谓词的活跃事实"窄比对——消灭"断臂后来治好了"式误报,同时对齐 [FlawedFictions](https://arxiv.org/abs/2504.11900) 结论:LLM 通读找矛盾不可靠,必须结构化窄比对。
5. **情感曲线**(P2):书级 target_valence 序列(六形状之一)+ 章后实测 valence 比对;`beat_mode`(scene/sequel:上章大灾难,本章前 1/3 必须给反应/两难,不许直接开打)。

### M8 修订纪律(流程约束,P0 即可生效)

自我修正文献 + scribe3 自己的"critique 噪声坑"经验一致:**禁止开放式整章 self-critique 原地重写**(同质化/越改越差)。有效形态:
1. 检测器(含现有复读/telling/矛盾 + 本设计新增)输出 **span → 只重写 span**(定向修订指令);
2. 高潮章 **3 候选生成 + 检测器打分 rerank**(Re3;新增 draft_candidate 概念可后置到 P2);
3. LLM critique 集中在**大纲/节拍层**多轮迭代,正文层只做表达增强(CRITICS)。

### M9 卡文诊断(小件,P2)

网文方法论:情节卡(回查主线目标与对手/升级冲突/切配角视角写关联剧情)、语言卡、心态卡三类处方,做成主编的一个诊断话术工具(纯 prompt,零表)。

## 四、分期与优先级

**第一期(P0)——"白抽变消费 + 软提醒变状态机"**,全部围绕已有数据资产,增量改造:
1. `scribe3/brief.py` 章前组装器 + `/chapter-brief` 端点(基础设施,M1/M2/M3/M6 的载体);
2. M3 弧光:静态锚字段 + lie_belief + arc_plan 表 + 章前三行指令 + 出场心跳 + 前端角色详情露出;
3. M1 伏笔:schema 扩展 + 状态机 + 升级式干预 + ingest 触及联动(复用 motif_instance 管线形态);
4. M6 注入器:injection_mode/aliases/预算/注入清单回显;
5. M2a 张力检查清单 7 项(接 critique 管线)+ M8 修订纪律(prompt/流程层)。

**第二期(P1)**:M5 场景卡 schema + 双向校验;M2c 张力检测器(三因子/出路收窄);M7 检测器扩容(filter words、PD、MRU、FACTTRACK 效度区间);M4 关系矩阵。

**第三期(P2)**:结局分歧度曲线可视化;情感曲线目标/实测;3 候选 rerank;分层记忆压缩+往事检索(千万字扩展件);M9 卡文诊断。

依据:P0 三项分别有论文级收益背书(DOC +22.5pt 连贯性;Codified Foreshadowing 兑现率翻倍;业界注入形态收敛),且都是对既有表/管线的增量;P1 引入新校验面;P2 是差异化亮点与扩展件。

## 五、非目标(YAGNI)

- 不训练/微调任何模型,不做 FUDGE 式解码控制器(用事后贴合度检测器替代);
- 不搬 Prom Week 5000 条规则,只搬数据结构;
- 不做纯向量检索的设定注入(别名匹配+关系一跳为主);
- 情感词典/LIWC 类纯统计曲线暂不引入(LLM 打分够用,4 章体量);
- 不改五阶段工作流本身,所有机制挂在既有阶段与 critique 管线上。

## 六、验收方式

- 每模块:pytest(表/端点/检测器规则)+ 真机(章前简报在写作页可见、检测环出具体修复指令);
- 全局验收:用《纸命》写第 5 章走完整环——章前简报含弧光指令+伏笔窗口+张力档位+注入清单;章后检测环 7 项清单出报告;对比无简报盲写版本的成文质量(乱世铜炉级 rubric 打分)。
