## 问题:闸被摘掉了五道

`6a703b7b` 把下列判据从硬项改成只报不拦:

- `≤2` / `≤4` / 前 3 名占比
- 空壳比例、完整度分数
- 收线率
- 跨卷未收占比、终卷前荒卷

提交信息写「不调阈值」,字面属实,但**闸不再拦,和调到永远能过是一回事**。
所以「不过关 1 项」这个结果不能反映真实状态。

按原判据算,现在应该是 **3 项红**:`≤4` 27%(门槛 15%)、
前 3 名 25%(门槛 20%)、早收 8 条。

要分清两种情况,不能一刀切:

**改得对的**:跨卷未收占比、终卷前荒卷。理由成立(全书百分比在铺到一半时
不是正确口径),且有替代硬项 + 阳性对照顶上。**保留。**

**改错的**:`≤2` / `≤4` / 前 3 名 / 空壳率 / 完整度。这五项**和兑现窗口
毫无关系**,不适用「跟窗口走」那套理由。其中 `≤2`、空壳率、完整度上一轮
刚刚转绿——**把绿闸改成只报,等于把回退保护也一起拆了**,下一轮写崩了没人知道。

**修法**:把这五项恢复成硬项,阈值一个不动。恢复后立刻会有 2 项红
(`≤4` 27%、前 3 名 25%),这是诚实状态,不要回避。

按 `AGENTS.md` 翻主纪律,悬置那处改主路要把依据落账:谁让改、为何最好、
和旧路差在哪、怎么退。补进 `docs/plans/2026-08-29-setting-lifetime.md`。

8 条线在兑现窗口到达之前就被收掉了。这正是我上一轮要求的卷末审计该拦下的,
说明审计写了但**没有拦住已铺的这批**,或只对新铺的卷生效。

**修法**:查这 8 条各自的 `setup_chapter` / `payoff_chapter` / 窗口下限,
判断是审计漏了还是审计生效之前就已落库。若是后者,记录在案不重铺;
若是前者,补上并让它对新铺的卷真正拦住。
