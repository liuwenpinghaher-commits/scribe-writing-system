# 回到第一性:这 160 章里没有一个字是小说

## 零、先承认偏差

作者问「你是不是被历史干扰了」。是。

从第 40 章那次审查开始,我连续九轮做的是同一件事:查判据对不对、查数字动没动、
查数据有没有污染。这些都必要,但它们衡量的是**账本的质量**,不是**小说的质量**。

一个可以立刻验证的事实:

```
章数 160｜has_prose 为真 0/160｜has_draft 0｜beats 0
梗概长度 中位 115 字｜命题 850 条｜实体 109 个
```

**这 160 章没有一句正文。** 我们造出来的是一份索引良好、内部自洽、
无矛盾、长尾够厚的**大纲**。它不是小说,也还没有任何证据表明它能变成小说。

九轮里我从没问过一句:照这份账写出来的字,人愿不愿意读下去。

## 一、第一性:一本好小说需要什么

| 要素 | 系统现状 | 判定 |
|---|---|---|
| 读者想翻下一页 | 从未测过 | **未知** |
| 句子好 | 从未产出 | **未知** |
| 人物让人在意 | 有四槽 duty 字段,无正文体现 | **未知** |
| 情节自洽不塌 | 850 命题、全库无矛盾、红线不破 | **已解决** |
| 长线埋收有节奏 | tier 三档窗口、无早收无逾期 | **已解决** |
| 世界有厚度 | `≤2` 0%、`≤4` 27%、109 实体 | **基本解决** |
| 信息差经营 | `hides`/`knows`/`must_not_know` | **机制已解决** |

**右侧四个「已解决」全是可机器判定的项;三个「未知」全是要人读才知道的项。**
九轮把能机器判的都推到了绿灯,一个要人读的都没碰。

这就是为什么账记得住、设定文还是不能用——**因为从来没有把账变成戏。**

## 二、第一件事:一章正文的试金石(在做任何新功能之前)

在写下一行功能代码之前,先回答那个从未问过的问题。

**做法**:挑三章——一章开头(第 1–20 卷内)、一章中段(第 80 章附近)、
一章刚铺的(第 155 章附近)——用现有账(梗概 + 命题 + 知情 + 待收线 + 写厚卡)
铺成正文,走已有的 `ScenePaper` / `ChapterStudio` 路径,不新建管线。

**验收不是数字,是人读。** 读完回答四问:

1. 读到第三段还想读吗?
2. 这一章的信息差立住了吗(该瞒的瞒住、该露的露出)?
3. 人物说的话像这个人说的,还是像系统说明?
4. 账里那些漂亮的机制(死光票、体温扣算、场核坐标),在正文里是**戏**
   还是**名词堆**?

**这一步的结论决定后面所有优先级。** 三种可能的结果:

- **能读**:账本这条路成立,后续按第三节把它显性化、可视化,继续铺。
- **像说明书**:问题在「账 → 戏」这一跳,后续全部资源投这一跳,
  UI 和数据层都往后排。
- **账本身没戏**:命题都对但没有一条能生成冲突,那说明前九轮优化的
  是错的东西,要回到卷纲重立。

**在拿到这个结论之前,下面第三节以后的所有事都不要开工。**
这是我这九轮最该早点说、却一直没说的一句话。

---

以下是拿到结论之后的方案。按作者点名的四块组织。

## 三、显性化与 UI

现有前端已相当完整(`ScenePaper`、`ChapterStudio`、`WriteChat`、`DeduceTree`、
`Corkboard`、`Outliner`、`PulseBar`、`NorthStarPanel`、`MaterialNetwork`、
`EntityTruthPanel` 等),**缺的不是写作台,是三个「看账」的视图**。

### U1 全书因果树(作者点名)

现状:事件因果链在库里,画在章内 `causal_complete`、脉搏「因果」维、章前简报;
**没有「点事件看全书因果树」的 UI**。时间线因果弧按 SESSION 标记推迟。

**要做**:一个以事件为节点的全书视图。点任一事件,向上展开它的
`causal_in`(为什么会发生),向下展开它引出的后果,跨章。
复用 `DeduceTree` 的渲染,不新建图组件。

**配套约束(已定,写进 UI 提示)**:落事件必须带 `causal_in`;
只有切场景才允许写独立根理由;不填脉搏就一直欠着。
跨章边现在硬拒——**这一条开不开另议**,UI 先按「硬拒」画,把被拒的边
显示成灰色待议,不要偷偷放开。

### U2 读者截至第 N 章看见什么(作者点名,也是我上一份评估里的 G3)

现状:伏笔账本齐(埋 / 线索 / 触及 / 兑现 / 弃置 / 障眼法、三档窗口、
超期 ≥3 硬闸),但只有角色视角,**没有读者视角切片**。

**要做**:一条章号滑杆,拖到第 N 章,显示读者此刻掌握的信息。
关键规则:**线索与兑现要对读者隐藏**——读者看见的是「井底有个东西」,
不是「这是青铜匣,第 20 章会打开」。

**明确不做第三套 ledger。** 这是对现有伏笔账的一个**读取切片**,
按 `setup_chapter` / `last_refresh_at` / `payoff_chapter` 与 N 的关系过滤。

### U3 账与戏的对照视图(我加的一条,承接第二节)

第二节那三章正文读完之后,需要一个常设视图:左边这一章的账
(命题 / 待收线 / 谁知道什么 / 写厚名单),右边正文,中间标出
**哪条账在正文里真的变成了戏、哪条只是被提了一句**。

理由:这正是九轮下来唯一没有任何工具支持、只能靠人肉抽样的判断,
而它恰恰是「设定文能不能用」的唯一真判据。做成视图之后,
每铺一卷抽样读的动作就从「我手写脚本捞数据」变成「打开看」。

### U4 揭示深度(承接上一份评估的 G1)

`knows` 现在是布尔,表达不了「甲看见匣角但不理解」。
加深度档(察觉 / 能命名 / 懂含义),`must_know` / `must_not_know` 的 key
带深度。这一项同时服务 U2:读者切片的「看见什么」本身就需要深度。

规则形态(不设量化闸):声明「只许到察觉」的,卷末不得已经「能命名」。
带阳性对照。

## 四、数据层

作者已点名四项,按风险排序:

### D1 同槽两条开区间必须关旧(最高优先,已咬过一次)

现状靠调用方显式传 `supersede_open`。**本项目已经因此吃过亏**:
写厚差额重跑时模型换词重写,两条同槽开区间并存,被一致性扫描打成
`value_conflict`,当时误判为「模型注水」。

**要做**:`add_fact` 层默认关旧,而不是靠调用方记得传参。
需要并存的场景显式声明,反过来。

### D2 批准时刻(第三时态)

现在只齐两轴:世界 `valid_from/to`、知情 `knows.since/until`。
缺批准时刻。**晚到事实应按故事时投影**——第 100 章批准的一条设定,
如果它描述的是第 20 章的世界,应当按故事时第 20 章生效,而不是第 100 章。

**要做**:补第三轴。这一项不挡当前主线,但一旦开始回改早期章节就必须有。

### D3 `tx` 审计实装

审计设计过,未实装。补上。

### D4 顺序

D1 立刻做(已造成过实际损害);D3 次之;D2 在需要回改早期章节之前做完即可。

## 五、检索 / 记忆

作者已定调:**RRF 已有(库内 `search::rrf` + `MemoryRetriever` 四通道),
不必引 HyperMem。** 按此执行。

### R1 命题 `hybrid_recall` 挂进写作 assemble(唯一的实缺)

现在写作 assemble 没用上命题级 hybrid_recall。这是现成能力没接线,
性价比最高。接上之后,写正文时能按语义捞到相关命题,而不只是靠
章级提示词里那几个固定块。**这一项直接服务第二节的「账 → 戏」。**

### R2 一书一检索合同

多书场景下检索边界要按书隔离,避免串味。

### R3 TiMem 式 L1→L5

**只进 fabric,正典压制,旗可关。** 按作者定调执行——它是分层记忆的
辅助通道,不许成为第二真相,正典永远压过它,且要能一键关掉。
优先级最低,前面几项没做完不要碰。

## 六、决策账本(低于事件因果)

现状 `pipeline_trace` 只留约 7 天。

若要回答「上次同类设定为什么被拒」:**把审批结果落成可查节点 + 先例检索。**
不装 Semantica。

优先级:低于事件因果链。等 U1 做完再说。

## 七、明确不做

作者已列,原样保留:

- 换 Surreal
- Graphiti / HyperMem / TiMem / Semantica 当第二真相
- 用 LLM 抽边当正典

我再补三条,理由是本项目的实证:

- **不加逐章调度器层**(见 `2026-08-29-SCHEDULER-REVIEW.md`):七成已实现,
  逐章调用成本乘十,且「每章 1–3 动作」是量化闸,与规矩冲突。
- **不设量化闸**。需要判定就写规则,一条一条有唯一正确答案、能指到具体对象。
- **不加没有阳性对照的机制**。八轮里没有阳性对照的判据,四次被证明是坏的。

## 八、执行顺序与验收

```
第 0 步  三章正文试金石(人读四问)         ← 不做完不许往下
   ↓
第 1 步  D1 add_fact 默认关旧              ← 已造成过损害,单独先修
   ↓
第 2 步  R1 hybrid_recall 挂进 assemble    ← 现成能力接线,直接服务第 0 步结论
   ↓
第 3 步  U3 账与戏对照视图 + U2 读者切片   ← 把唯一靠人肉的判断变成工具
   ↓
第 4 步  U4 揭示深度 + U1 全书因果树
   ↓
第 5 步  D3 tx 审计 → D2 第三时态 → R2 一书一合同
   ↓
第 6 步  决策账本先例检索 → R3 TiMem(只进 fabric)
```

每一步的验收都要包含:

- 规则形态的硬项(不许用比例)
- 阳性对照(它坏掉时会怎样被发现)
- **人读一次**——第 0 步之后,每一步都要回答「这让书更好读了吗」,
  答不上来就说明这一步不该做

## 九、给我自己的一条纪律

九轮里我每次都从「上一轮的红项清单」开始。这让我把一份大纲优化得很好,
却始终没发现它不是小说。

**今后每一轮的第一句话必须是:这一步让书更好读了吗。**
答不上来的,再绿也不算完成。
