# 「章节信息调度器」提案评估

结论:**方向对,但七成已经实现了**;真缺口是三处,都比提案说的小;
提案照搬会引入四个问题,其中一个和作者定的规矩直接冲突。

## 一、已经实现的部分(提案当成缺失的)

章级提示词(`expand_wanjie_chapters.py:585-700`)现在已经包含:

| 提案要的 | 现状 |
|---|---|
| 卷级契约输入 | 「这一卷的契约(必须兑现,会被逐条核对)」 |
| 动作池 | 「还欠着的线(从库里查的,不是我编的)」 |
| 角色知识状态 | 「柳岸青此刻知道什么(从库里查的)」 |
| 埋/推进/收三类动作 | `plant` / `learns` / `payoff` 三个结构化字段 |
| reveal 分档 | `tier`: `chapter` / `arc` / `book`,窗口 `(1,3)/(5,15)/(1,None)` |
| 不许提前收大伏笔 | 「未到期和 book 未点名的不许收,写了也不落库」(persist 层硬拦) |
| 信息不对称 | 「谁不在场就不许知道」;`hides` 至少一处 |
| 禁止列表 | 红线块;「后面几卷预留的实体现在别用」 |
| 事后核对 | 写厚差额、长线仍 open、早收/逾期,均带阳性对照 |

提案里的「井底匣角 → 听说 → 打开」这个阶梯,对应的就是
`tier=book` + `payoff_min/payoff_max` 窗口。**机制在,不用新建。**

## 二、真正缺的三处

### G1 揭示深度只有二值(最有价值的一处)

现在知情是布尔:知道 / 不知道。提案举的例子——「甲看见匣角但不理解」、
「乙听说有匣但没见过」——**表达不了**。

这是三处里最值得做的,而且不需要新层:在 `knows` 边上加深度
(察觉 / 能命名 / 懂含义),`must_know` / `must_not_know` 的 key 顺势带深度。
好处是「不许知道」能写成「只许到察觉,不许到能命名」,
比现在的一刀切精确得多,且**每条有唯一正确答案,是规则不是比例**。

### G2 欠账池是平铺的,没有排序

「还欠着的线」是一张平表,模型自己挑。`promise_window_state` 已经算出
`inactive / pre_window / in_window / over_half / overdue` 和 `salience_gap`,
**但这些状态没进提示词**。

修法不是加调度器,是**把已有的状态标进那张表并排序**:逾期的排最前、
标「必须处理」;`over_half` 次之;`pre_window` 标「不许收」。
零新增机制,只是把已经算出来的东西给模型看。

### G3 没有「读者截至第 N 章看见什么」

作者自己点名的缺口。现在只有角色视角的知情,没有读者视角的切片。
这是一个读取视图,**不是第三套 ledger**,别按 ledger 建。

## 三、提案的四个问题

### H1 「每章 1–3 个结构动作」与规矩冲突

这是量化闸。作者定的规矩是**不设量化闸,用规则解决**。
规则形态应当是「本章的 `plant` 至少一条接到已有账上」「不许收未到窗口的线」
——这两条**已经在了**。再加一个数量上限是走回头路。

### H2 前提与实测不符

提案的立论是「模型只能在旧元素上加细节,越写越像原地打转」。
实测(160 章)不支持:每 10 章新实体 6–7 个、`≤2` 命题占比 0%、
`≤4` 从 62% 降到 27%、前 3 名集中度 36% 降到 25%。
**原地打转在 40 章时是真的,现在已经不是主要矛盾了。**
按一个已经缓解的症状去加一整层,收益对不上。

### H3 逐章规划会把成本乘以十

现在是一次调用铺 10 章。改成逐章排程,LLM 调用数 ×10。
160 章已经跑了多轮、每轮数小时。这笔账提案没算。

### H4 没有阳性对照

提案里的 Planner / Recall / Thread 三个 agent,都没有说怎么验证它们真的起作用。
本项目八轮下来,**凡是没有阳性对照的判据或机制,四次被证明是坏的**
(拼接串子串、无标签解析、悬置显示与判定不一致、空壳判据背旧数据的锅)。
新增任何一层,必须同时给出「它坏掉时会怎样被发现」。

另:提案建议引 Recall/Thread agent,而作者自己的笔记已写明
「RRF 已有(库内 `search::rrf` + `MemoryRetriever` 四通道),不必引 HyperMem」。
检索这一侧不缺东西,缺的是把 `hybrid_recall` 挂进写作 assemble。

## 四、最优做法:不加层,补三处 + 清一处旧账

按性价比排序:

1. **G2 排序欠账池**(最便宜):把 `promise_window_state` 已有的状态标进
   「还欠着的线」并排序。改一个提示词块,零新机制。
2. **G1 揭示深度**(最有价值):`knows` 边加深度档,`must_know` /
   `must_not_know` 的 key 带深度。配规则:声明「只许到察觉」的,
   卷末不得已经「能命名」。带阳性对照。
3. **G3 读者切片**:读取视图,不建 ledger。
4. **清旧账**:作者笔记里「同槽两条开区间必须关旧(现在靠显式
   `supersede`)」——**这一条已经在本项目咬过一次**:差额重跑时模型换词重写,
   两条同槽开区间并存,被扫成 `value_conflict`。应当在 `add_fact` 层默认
   关旧,而不是靠调用方记得传 `supersede_open`。

暂不做:批准时刻(第三时态)、决策账本先例检索、TiMem L1→L5。
这三项都不挡当前主线,且都会引入新层。

## 五、若仍要做调度器,最小可行形态

不新建 agent,不逐章调用。在**现有批次调用之前**加一步纯计算(不调 LLM):
按 `promise_window_state` 把本批 10 章的欠账池排序、分配到章号区间,
作为提示词里的一个「本批各章建议处理的线」块。

这样成本增加为零,且可审计:铺完之后核对每条被建议的线是否真被处理,
不达标走已有的差额重跑那条路。**先做这个,验证有效再谈加层。**
