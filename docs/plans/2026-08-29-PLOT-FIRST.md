## 一、实测:剧情层面的真问题

不看文笔,只看剧情结构。对第 11–160 章共 150 章的梗概做统计:

```
焦点(focalizer)      柳岸青 150/150 = 100%
柳岸青做主语          149/150 =  99%
「付 N 度」交易       126/150 =  84%
「折成 / 登记成」      65/150 =  43%
「N 息」时限           53/150 =  35%
```

抽六章并排读(12 / 45 / 88 / 120 / 152 / 158),形状完全一致:

> 某吏 / 某房把 X 登记或折成 Y → 柳岸青付零点几度买几息 →
> 半成、失败或被锁

- 第 12 章:付零点五度,交易接口只差一步没合上
- 第 45 章:付零点七度挡住吞名
- 第 88 章:付零点五度买断白牌七息,白牌挡秤**失败**
- 第 120 章:付腕内零点五度买验锁三息,交差**被锁**
- 第 152 章:付掌心零点四度自补半枚缺口
- 第 158 章:付锚体零点三度让合法炉只熔冷票

**150 章一个视角、一套动作、一种结局(半成)。** 这就是「设定文不能用」的
真正原因,和文笔无关,和账本自洽也无关。

## 二、为什么九轮判据一个都没发现

不是判据写错了,是**判据全都测不到剧情**,其中两条还在反向奖励这个毛病:

| 判据 | 面对 150 章同一模板时 | 为什么 |
|---|---|---|
| 全库无矛盾 | 绿 | 重复恰恰最自洽 |
| 每卷新鲜度 ≥5 | 绿 | 新造「报名字吏 / 观测权吏 / 炉心使」就算新鲜,**奖励造新名词** |
| 实体厚度 | 绿 | 给新名词挂命题就算写厚,**奖励继续摊大** |
| 无早收 / 无逾期 | 绿 | 埋收节奏正常,与情节是否重复无关 |
| 空壳率 / 完整度 | 绿 | 角色卡填满,与他在剧情里做什么无关 |

**新鲜度和厚度这两条,实际效果是鼓励横向摊名词,而不是纵向推剧情。**
这一点必须写进账,是这九轮最大的一条教训。

## 三、缺的那一层:草稿

现库每章只有中位 115 字的梗概,`beats` 字段 **160 章全空**,
`has_draft` 全 0。

作者要的「草稿」正是这一层:比 115 字梗概厚,但不是正文。
**它才是剧情的载体**——梗概只能写「谁办成什么」,草稿要能写出
「谁想要什么、被谁挡住、用什么手段、付了什么、局面因此变成什么」。

**但在填 `beats` 之前必须先修第一节那四个毛病,否则等于把同一个模板
放大十倍写 160 遍。**

## 四、剧情规则(规则形态,不设量化闸)

按作者定的规矩:一条一条有唯一正确答案、能指到具体对象。
这些规则进卷契约与章级提示词,铺完走已有的差额重跑那条路审计。

### P1 视角不得独占

**规则**:每一卷至少有一章由非主角视角承担,且该章的核心动作由该视角人物
自己做出,不是旁观主角。

现状 150/150 全是柳岸青。系统里 `focalizer` 字段现成,兰因、沈烛、赫斯、
牧场主、温贩婆都有四槽 duty,**有人物没有戏**。

### P2 手段不得单一

**规则**:同一卷内,不允许所有章的核心动作都属于同一类。
动作类型至少要分出「买 / 换 / 骗 / 抢 / 拖 / 揭发 / 结盟 / 背叛」这一层,
落成字段,每章标注。

现状 84% 是「付温买时间」。柳岸青有 850 条命题的世界可用,却只会付钱。

### P3 每卷必须有一次决定性输赢

**规则**:每卷至少一章的结局不是「半成」,而是明确的成或败,
且该结果在后续章节里被引用为前提。

现状全是「只差一步没合上 / 挡住 / 失败 / 被锁」,永远悬在半空,
读者拿不到任何一次落地。

### P4 关系必须变化

**规则**:每卷结束时,至少一对人物之间的关系状态与卷初不同
(结盟 → 反目、隐瞒 → 摊牌、上下级 → 对等),并落成命题。

现状写厚都在给机构和地点挂机制,**人物之间的账几乎不动**。

### P5 代价必须升级

**规则**:同一类代价的量级不得长期持平。柳岸青付的温度从卷一到卷八
一直是零点三到零点七度,八卷下来主角没有真正失去过什么。

这一条要小心不要写成量化闸:**规则是「卷末必须有一项不可逆的失去」**,
指到具体对象(失去某人、某处、某种能力、某个身份),不判数值。

## 五、UI:让重复一眼可见

作者问「能显性展示吗」。现在不能——这四个毛病我是写脚本统计才看出来的,
UI 里没有任何地方会暴露它。前端有 `ScenePaper` / `ChapterStudio` /
`DeduceTree` / `Corkboard` / `PulseBar` 一整套写作台,但没有一个视图回答
「这本书是不是在原地打转」。

### V1 剧情节奏板(最高优先)

一行一章,横向铺开全书。每章显示四个格子:**视角 / 动作类型 / 输赢 / 关系变化**。
重复会直接呈现为一整片同色。这是把第一节那张统计表变成常设视图。

复用 `Corkboard` 的栅格,不新建组件。

### V2 读者截至第 N 章看见什么(作者点名)

章号滑杆,拖到 N 显示读者此刻掌握的信息。线索与兑现对读者隐藏。
是对现有伏笔账的读取切片,**不建第三套 ledger**。

服务剧情的用法:拖动滑杆能看出「读者在第 80 章知道的,和第 40 章相比
多了什么」——如果多的全是新名词、没有新的**局面**,就是打转。

### V3 全书因果树(作者点名)

点事件看 `causal_in` 上溯与后果下展,跨章。复用 `DeduceTree`。
落事件带 `causal_in`;切场景才写独立根理由;不填脉搏一直欠。
跨章边现在硬拒,**开不开另议**,UI 先按硬拒画、被拒的边显示成灰色待议。

服务剧情的用法:如果全书因果树是 150 棵各自独立的小树、没有长链,
那就证明每章的事没有后果,与第一节的观察互相印证。

## 八、执行顺序

```
第 1 步  V1 剧情节奏板              ← 已接 Corkboard「按剧情」
第 2 步  P1 视角 + P2 手段          ← 已进契约/提示/落库/卷末断言（2026-08-29）
第 3 步  只重铺一卷(20 章)验规则    ← 卷八《盲按录》141-160 已重铺；1-140 未动
第 4 步  P3 输赢 + P4 关系 + P5 失去
第 5 步  填 beats 草稿层            ← 规则立住之后才填，否则放大重复
第 6 步  V2 读者切片 + V3 因果树
第 7 步  D1 → R1 → 其余数据层与检索
```

每一步验收都要:规则形态硬项、阳性对照、**并回答「这一步让剧情更有肉了吗」**。
