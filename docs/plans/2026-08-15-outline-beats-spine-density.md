# 大纲 / 节拍应变「干线索」：剧情密度方案

| 项 | 值 |
|----|-----|
| **日期** | 2026-08-15 |
| **状态** | Draft · 方案（本轮不改宣称 / GATE-B / 地板数字） |
| **对象** | `generate-stage` 的 outline / beats 合同；注入帽；四仪抽取 |
| **不改** | `GATE_SAVE_MODE`、宣称公式、WCG；第 6 章定稿整章重写 |

> **一句话：** 剧情密度是大纲和节拍定的。这两层现在被问成「能看见的场面」，又被 500/2000 地板逼成小散文，再整段灌进草稿/定稿。正文慢，是上游把「线索」写成了「正文预演」。

---

## 1. 客观结论：是的，要从这两层下手

| 层 | 它该决定什么 | 它不该决定什么 |
|----|----------------|----------------|
| 大纲 | 本章必发生的因果：谁、对谁、做了什么、为何必须、不能说、章末把柄 | 烟怎么走、锅怎么磕、指腹什么温度 |
| 节拍 | 3 次不可撤回的台阶（事件→翻转）+ 一句水下 | 每拍重新从巷子/烟囱进场 |
| 演绎 | 限知差、误读、没察觉 | 再写一遍街景 |
| 排演/定稿 | 把台阶写成可感的场面 | 发明新的主台阶 |

第 6 章实证（改造前卷宗）：

- 大纲 2375 字。「日子」是灰狸磨铜、婆子擦钱的巡礼；「必须发生」是整场拨铜；「章末未决」是整场咳。槽名还泄漏过「为什么非发生不可」。
- 节拍 3 拍、每拍 1100–1400。进场常 300–670 字烟与巷；事件/翻转也是连贯散文。
- 定稿组装把大纲+节拍整段注入（`outline` 工件约 6000 字，`INJECT_CAP.synopsis=2500` / `beat=1200`）。模型被要求「据此展开，勿另起炉灶」——上游有多少巡礼，下游就复写多少。
- 四仪从这些肥段落里抽：欲望空、挡=呼吸、付被截断。戏的合同也是场面渣。

所以：**不是正文单独爱写细节，是大纲/节拍已经把节奏写成「慢镜头说明书」。** 只改定稿 extra，治不了下一章。

---

## 2. 根因：合同自相矛盾

现网 `stage_generate.py` 的提问：

```text
大纲·日子：村里/场上正在过什么（具体，能看见）
节拍·进场：谁在哪，空气里有什么
每拍 ≥500 · 合计 ≥2000 · 大纲 ≥500
```

同时纪律写的是：「字数 = 信息覆盖，不是文学分」。

两套指令叠在一起，模型的理性选择是：**用可看见的感官填满 500 字。**  
「日子」和「进场」被点名为空气与场面，感官比「账勾了 / 门没开」更好凑字。

再叠加：

1. **地板数字 > 干线索所需。** 一章真正的情节骨架大约 200–400 字就够。500×3+500 的闸逼出 4–6 倍注水。闸的本意是防口号（80 字「查明真相」），副作用是把线索层写成小正文。
2. **加厚句**（「还差 N 字，接着写新场面」）在大纲/节拍不够厚时继续堆场面，不堆因果。
3. **注入几乎全给。** 刚过闸的肥稿整段进模型，定稿无法「只看见台阶」。
4. **四仪抽取吃进场/事件长句**，肥稿污染合同，下游更按场面写。

`stage_skips_craft_engine` 已经不给大纲/节拍灌「身体先行」——产品知道这两层不该像正文。但 **ASK 和地板仍按正文在要字。**

---

## 3. 原则（不降地板数字的前提下）

**Ice1/Ice2 的 500/2000 本版不改数字**（避免和 rev.4 地板吵）。改的是 **这 500 字必须是情节信息，不是感官覆盖。**

干线索的验收（人读 / 可机检）：

| 层 | 必须有 | 禁止 |
|----|--------|------|
| 日子 | 时空一句（何时何地、正在过什么日子） | 超过 80 字的巡礼 |
| 必须发生 | 谁对谁做了什么 + 当场结果 | 重复进场气氛 |
| 因→果 | 2–4 条因果，每条含动作 | 「为什么非发生不可」槽名；心情句 |
| 不能说 | 限知/禁令条目 | 场面 |
| 章末未决 | 一个未完成动作或把柄 | 再写 400 字收束散文 |
| 进场 | ≤1 句时空定位 | 空气、烟、青苔独立成段 |
| 事件 | 本拍唯一必须发生的动作 | 风景 |
| 翻转 | 相对上拍的升级/反转 | 同一动作换词重写 |
| 出场 | 留下的物件/话/账 | 走位描写 |
| 水下 | 一句作者知道、正文不写的 | 全知剧透长段 |

500 字从哪来：三条因果展开成「动作—阻力—后果—不能说—把柄」，每条写清主语宾语，不写感官。信息密度高也可以到 500，而不是靠烟。

---

## 4. 最优改造（分刀）

### P0 改提问（`_OUTLINE_ASK` / `_BEATS_ASK`）

大纲改成：

```text
写本章因果提纲，不是场面预演，不是读者正文。
日子：一句时空（≤80字）。
必须发生：谁对谁做了什么、当场结果（动作句，禁风景）。
因→果：2–4条「因A所以必须B」，每条有动作，禁止槽名当标题。
不能说：条目列表。
章末未决：下一章必须接的一个动作或把柄（一句）。
全文≥500字，全部用于情节信息；禁止气味/街景/重复微动作凑字。
```

节拍改成：

```text
≥3拍，每拍一次不可撤回的台阶。
进场：一句时空（≤40字）。
事件：本拍必须发生的那一下（本章戏的主体）。
翻转：相对上拍新的阻力或反转。
出场：留下的物件/话。
水下：一句作者知情。
每拍≥500、合计≥2000：字数用在事件+翻转的情节信息上；
进场+水下合计不得超过该拍 1/4。禁止每拍重写烟/锅/巷。
```

加厚续写句（outline/beats 专用）：「还差 N 字，补未写清的因果/台阶，禁止新开街景。」

### P1 机检（不降地板）

在 `parse_outline_payload` / `parse_beats_payload` 或 persist 前加软硬闸：

- 日子 / 进场超过预算 → 记缺陷；硬闸可先 warning，一章后改 422。
- 事件+翻转占该拍不足一半 → 薄（情节薄，不是字数薄）。
- 大纲/节拍命中注水词表过密（烟、青苔、檐口、指腹…且无新动作）→ 薄，强制重写。

与现有锁眼扫描并列，不进宣称。

### P2 注入

- 大纲注入优先五槽的「必须发生 / 因→果 / 章末未决」，日子只留首句。
- 节拍注入优先事件+翻转；进场裁到一句。
- `INJECT_CAP` 可保持数字，但 clip 按槽，不按整篇散文。

否则 ASK 改瘦了，旧肥稿仍 1200 字/拍灌进第 7 章。

### P3 四仪

只从「必须发生 / 事件 / 翻转」抽要/挡/翻；禁止从日子、进场抽。已有槽名泄漏规则保留。

### P4 本书

- **不**重写第 6 章定稿。
- 第 7 章起走新 ASK。
- 若第 6 章还要当下游燃料：点批或 `persist=true` **只重跑大纲+节拍**（已厚但情节瘦），用新合同把肥稿换成干线索；演绎/草稿/定稿不动。

---

## 5. 明确不做

- 不把 Ice1/Ice2 数字改成 80/200 来「变干」（那是口号回潮，且动 rev.4 地板）。
- 不把演绎 5000、草稿 10000 一并砍掉（那是下一刀；本方案只治密度源头）。
- 不靠作者 extra 长期人工压节奏（extra 可作过渡，合同必须改）。

---

## 6. 验收

新开一章（或第 7 章）只跑 outline+beats：

1. 日子 ≤80；每拍进场 ≤40；事件+翻转 ≥ 该拍一半。
2. 人读能用条目复述本章 3 个台阶，不需要读烟。
3. 注入工件里日子/进场是短句，不是巡礼。
4. 四仪短句动词，不场面倾倒。
5. 定稿另验：主台阶仍在，不再用空锅/烟开三次场。

---

## 7. 执行顺序

```text
1. 改 _OUTLINE_ASK / _BEATS_ASK + outline/beats 加厚句
2. 解析侧情节密度 warning（先软）
3. 注入按槽裁
4. 四仪抽取收口
5. 第 7 章 OpSeq 从大纲走；第 6 章定稿锁定
```

*完。先改合同提问，再改注入；不要先动正文。*
