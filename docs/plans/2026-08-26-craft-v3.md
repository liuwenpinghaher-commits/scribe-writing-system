## 触发本次修正的事实

任务 A 产出第一篇样章《夜班差三百》（当代职场，便利店夜班盘点差三百）。作者评审结论：

1. 比喻还是太多。
2. 表现不生活化，说话不像真人说话。
3. 矛盾点没有吸引力。
4. **味道和之前已删掉的样本差不多——之前「炼铜」是对账，这次还是对账。**

第 4 条是致命的，且已查到机制。

## 诊断一 · 母题坍缩（本次核心发现）

**数据：**

| | 章卡总数 | 含「账」的卡 | 占比 |
|---|---|---|---|
| 乱世铜炉 | 214 | 135 | **63%** |
| 诡秘之主 | 1394 | 197 | **14%** |

「账」是**铜炉的题材母题**，不是小说写法的通则。两本差四倍以上。

**机制链条：**

1. 21 段拆解模板里固定有一段「钱与人情」→ 每章都被要求回答钱的事。
2. 铜炉本身 63% 的卡真的在讲账 → few-shot 与「可搬走的一条作法」里，账的密度极高。
3. `scribe3/playbook/structural.py` 把 `bill_holder` 设成**必填**：

   ```
   duty_holder_empty  "bill_holder 不能空：这笔账此刻在谁手里"
   duty_bill_shame    "不要换气换丢人。账要换持有人或换地"
   ```

4. 于是系统写任何题材，**第一件事是先造一笔账**，否则过不了闸。
5. 结果：《腕账》是账，「炼铜」是对账，便利店还是对账。

**关键澄清**：样章号称绕开了硬编码闸，仍然写成对账。说明**病根不在闸，在语料的母题分布从未做过区分**。拆文包把铜炉的题材特征和通用写法混在一起交给系统了。

**这也反证了接《诡秘之主》的价值**：单本永远看不出 63% 是异常，两本一比立刻暴露。

## 诊断二 · 清单化写作（前三条反馈的共同根源）

当前生成顺序：

```
拿到 21 格作法清单 → 造一个能装下这些格子的场景 → 逐格填
```

样章的每一格都填得工整：要有账就设计盘点，要物件承重就塞压缩机/口香糖/皮筋，要回不去就让她签字，要代价就砍掉末班车，要翻就从能交班变成不能交班。

**格子填满 ≠ 有人想看。**

三条反馈对应到这个根源：

| 反馈 | 机制 |
|---|---|
| 比喻太多 | 每格填完都想「点一下题」，比喻成了**代替观察的捷径** |
| 说话不像人 | **每句台词都在推进情节**；真人说话有废话、跑题、答非所问、被打断、说错再改 |
| 矛盾没吸引力 | 「盘点」是**流程**不是**事件**；读者不知道主角是谁、怕失去什么，唯一赌注是末班地铁 |

## 被推翻的底层假设

v1/v2 的主干是：**会拆 → 有尺子 → 会写。**

样章给出反例：**尺子本身会变成模板。**

修正后的原则（v3 主干）：

> **拆解产物只能当「写完之后的检查表」，不能当「写之前的填空提纲」。**

顺序一旦反过来，产出必然是「符合全部字段但没人想看」。

## 任务

严格按 A→B→C→D→E 顺序。每完成一项更新「进度」段。

### A · 母题分层（纯机械，零 LLM 成本，最先做）

**目的**：把「铜炉的题材特征」和「两本共同的写法」分开。这是母题坍缩的直接解药，且不烧一个 token。

做什么：

1. 写 `scribe3/eval/motif_split.py`。逐段统计两本章卡的用词与结构特征。
2. 产出 `docs/worlds/两本对照/母题分层.md`，分三档：
   - **通则**（两本占比都高，差距 < 15 个百分点）→ 允许进写作提示
   - **单本母题**（一本高一本低，差距 ≥ 15 个百分点）→ **禁止**进写作提示，只能作为「这本书怎么处理它自己的母题」的例子
   - **不确定**（样本太少）→ 暂不使用
3. 「账」按现有数据（63% vs 14%）必然落进**单本母题**，作为该分层正确性的第一个验收点。
4. 建 `scribe3/eval/motif_blacklist.json`：写作提示与生成结果里禁止出现的母题清单。首批至少含：账、盘点、清算、对账、欠款、差钱。

验收：

- `母题分层.md` 落盘，三档都有条目
- 「账」在单本母题档
- 零 LLM 调用

---

### B · 反转生成顺序（解决清单化）

**目的**：不再让系统「造一个能装下清单的场景」。

做什么：

1. **处境由外部给定，系统不许自己想。** 建 `scribe3/eval/premises.json`，至少 12 条，每条包含：
   - 题材（避开古代武侠/江湖、维多利亚/神秘学）
   - 一个具体的人（有职业、有年龄、有一件在乎的事）
   - **一件今天躲不掉的事**（必须是事件，不是流程；「盘点」「对账」「例会」这类流程一律不合格）
   - 这个人怕失去什么
   - 处境**不得**触发母题黑名单
2. 写作时脚本**随机抽一条**，不许挑。
3. **写作提示里不给 21 段清单。** 只给：这个人、这件事、以及 A 步分出来的**通则**（且不超过 5 条）。
4. 写完**之后**才用 21 段检查表逐项对照，产出自评页——检查表是事后的尺，不是事前的模具。

验收：

- `premises.json` ≥ 12 条，每条都是事件不是流程
- 生成脚本随机抽取，有日志可查抽到哪条
- 提示词里不含 21 段清单（可机械检查）

---

### C · 文风机械闸（解决比喻与对话）

**目的**：作者提的「比喻太多」「说话不像人」都可机械测。测不了的部分交给作者。

做什么：写 `scribe3/eval/prose_check.py`，对样章跑以下检查，**只报告不自动修改**：

| 指标 | 阈值 | 依据 |
|---|---|---|
| 明喻密度 | 每千字「像 / 如同 / 仿佛 / 好似」≤ **1** | 样章 2000 字里 5 个 |
| 对话冗余率 | 至少 **30%** 的对白回合不推进情节 | 样章接近 0，每句都是供词 |
| 答非所问 / 打断 | 全篇至少 **2** 处 | 样章 0 处 |
| 开篇事件 | 前 300 字内出现一个不可逆动作，不是流程描写 | 样章开篇是盘点流程 |
| 结尾总结句 | 最后 150 字**不得**出现「不是……而是……」式点题 | 样章末段自己讲了主题 |
| 母题黑名单 | 核心冲突不得命中 A 步黑名单 | 样章核心冲突是对账 |

验收：

- 脚本能对《夜班差三百》跑出报告，且上述六项**全部标红**（这是脚本正确的证明）
- 新样章至少通过其中五项

---

### D · 再产样章，一次三篇不同题材

**目的**：一篇看不出是不是又坍缩了，三篇不同题材一比就知道。

做什么：

1. 从 `premises.json` 随机抽 **3** 条不同题材，各写一场约 2000 字。
2. 每篇跑 `prose_check.py`，报告附在文末。
3. 三篇一起交给作者读。

验收（**作者是唯一验收人**）：

- 三篇的核心冲突**互不相同**，且都不是账/盘点
- 作者读前 300 字愿意读下去
- 成本 ≤ 6 次调用，且**不走 tonglu 的 hermes 通道**

红线：样章不作任何闸的证据，不进 Surreal，不上现网，不 overlay 已删的书。

## token 纪律

- A、C 两步**零 LLM 调用**（纯脚本统计）。
- B、D 加起来 ≤ 6 次调用。
- 默认**不走 tonglu 的 hermes 通道**。`complete_fn` 是注入参数，换通道是小改动。

- **新增：母题黑名单命中 = 本篇作废**，重抽处境重写，不许辩解「这个题材天然要算账」。
- 禁止：为过闸写书；改尺子刷分；调阈值当改进；留出章或探针章进 few-shot；重拆两本；通读全文；本机 Surreal；全量 pytest；npm ci；把情节灌进 Surreal。
- 两本全文 gitignored，**禁止入库**。
- commit 只含本轮路径。不要重演 `f5891c53`（1394 个拆文文件和 eval 代码装进同一个提交）。

**不作停机条件**：字数、QC、十维、现网点验绿、「填满了 21 格」。
