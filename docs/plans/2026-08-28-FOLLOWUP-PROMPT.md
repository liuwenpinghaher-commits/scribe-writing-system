## 任务一：悬置闸显示的量和把关的量不是同一个

现在的输出是自相矛盾的——判据名说「不得为 0」，显示的数就是 0，却判通过：

```
悬置（跨卷未收）0/256 = 0%
✓ 悬置率不得为 0（全收完 = 把话说完）　跨卷未收 0
```

根因在 `scribe3/tools/verify_scale.py`：

```python
rep.check(not su["all_closed"] and su["n"] > 0, "悬置率不得为 0（...）",
          f"跨卷未收 {su['cross_open']}")
```

`suspense_rate` 里 `all_closed` 的定义是「cross_open 为 0 **且**所有线都收了」。
现库 18 条开着，`not all_closed` 为真，于是过。**显示 `cross_open`，把关 `all_closed`。**
这正是方案书第六节警告过的「推导用一个口径、验收用另一个口径」，只不过这次写进了代码。

### 先看清楚现库到底什么样（我算过了，别重算错）

| | 条数 | 占比 |
|---|---|---|
| 埋在本卷、本卷内就收 | 96 | 38% |
| **跨卷才收（后置揭示）** | **142** | **55%** |
| 至今未收 | 18 | 7%（**全部埋在卷 10**） |

跨卷线的跨度分布：跨 1 卷 102 条、跨 2 卷 31 条、**跨 3 卷以上只有 9 条**。

**注意别把结论说过头**（我第一遍就说过头了）：书里的线**是会活过卷界的，而且很多**。
不能说「全收完 = 把话说完」。真正的毛病是两条：
**卷 1-9 埋的线到卷末一条不剩**，以及**后置揭示的跨度很浅**（长弧只有 9 条）。
对完本的 200 章书这算正常，**对千万字连载是硬伤**——这本书的目标是后者。

### 要改成什么

作者已定口径，两条都要满足才算过：

1. **跨卷未收 ÷ 总线数 ≥ 15%**
2. **终卷之前的每一卷，都至少有一条埋在本卷、跨过本卷卷界仍未收的线**

现库基线：第 1 条 0/256 = 0% → 红；第 2 条卷 1-9 全是 0 条 → 红。

`suspense_rate` 要返回按卷的明细（哪几卷是 0），报告里要能看见是哪几卷不合格，
不能只给一个总比例。**阈值 15% 是作者定的连载口径，不是 StoryScope 推出来的数**，
注释里要写清楚这一点，别伪装成有实测依据。

### 顺带提一条建议（做不做你判断，要说明理由）

上面那两条管的是「有没有线悬着」，管不到「悬多久」。现库 142 条跨卷线里 102 条只跨 1 卷，
**长弧稀缺才是连载的真问题**。建议再加一个只报不拦的观测项：跨 ≥3 卷的线占比
（现库 9/256 = 4%）。**先别设成门**——没有依据说多少才对，设了就是拍脑袋。

## 任务二：设定当障碍闸是装饰性的

```python
rep.check(not (ob["n_rules"] >= 1 and ob["triggered"] == 0),
          "设定当障碍：至少有一条规矩被命题引用", f"{ob['triggered']}/{ob['n_rules']}")
```

只要有**一条**规则被引用就过。StoryScope 的原始发现是**比例差**
（设定不当障碍：人 11.1% vs 模型 3-4%），到这里退化成「至少一条」；
再配上 `_rule_needles` 的 2 字实词匹配，实际上永远绿。
而且 `with_cost` 算出来是 6，**根本没进闸**——「有代价」才是障碍的定义，
没代价的规则被引用多少次都只是装饰。

改成比例门。现库 6 条规则、6 条有代价、5 条被引用（83%）。
**门槛定多少你来定，但必须给出依据并写进注释**，不许挑一个正好让现库通过的数。
如果找不到依据，就诚实地只报不拦，别放一个假门在那儿。

`_rule_needles` 那套 2 字匹配我抽样读过原文了——「场核」「光子」「五维」「穿越」
命中的都是真讲那条规则的命题，不是碰巧撞字。**匹配这层不用改。**

## 任务三：新判据一个阳性对照都没有

方法论第三条写着「返回 0 的检查必须有阳性对照」。现在只有一致性扫描做了（0 → 1），
**新加的深度／厚度／空间／障碍／悬置一项都没做**——而悬置返回的就是 0。
两道假闸能活到交付，根因就在这儿。

给每一项新判据补阳性对照：往内存结构里塞一条已知缺陷，确认判据抓得出来，再撤掉。
**不要往 `wanjie_scale` 里写**，这些判据都是纯函数（`setting_depth.py` 只吃公开结构），
在单测里构造假数据就够，不用碰真库。

## 任务四：对照库上那条「卷末该知道的都知道了」不该算红

`wanjie_scale` 的 70 条知情终态**带 key 的是 0 条**，全部退回模糊匹配，
而这条路的误报率上一轮实测是 11 条里 8 条假。所以十项红里有一项在这个库上
其实是**无法判定**，记成不过关会污染对照。（`wanjie_v2` 是 61 条全带 key，不受影响。）

改法：契约不带 key 时，这一项报「无法判定（契约无 key）」，
既不算通过也不算失败，单独列出来。**不要偷偷跳过**，要在报告里显示。
