# 设定线：从配额仪表盘回到寿命账

> 2026-08-29。接 `setting-scale` → ROOTCAUSE → DEPTH → WALL → PADDING → STALE → SUSPENSE。
> **本文件是现行方案。** 不铺 141+、不调已绿门槛、不新增百分比闸。

**Goal：** 让章级生成跟每条线、每个实体自己的寿命走；验收查有没有违约，不再用全书占比指挥写作。

**Architecture：** 伏笔已有 `tier` / `payoff_min` / `payoff_max` / `promise_window_state`；实体已有自己的命题。铺章 persist 目前无视窗口，改用「到期必收、未到期不许收」；写厚改成「用已有命题推出本卷处境」，不再用 ≥3 条新 attribute + 差额重跑。`verify_scale` 硬项只留逻辑违约，占比全部只报。

**Tech Stack：** `scribe3` · Surreal 3.x · `wanjie_v2`（`wanjie_scale` 只读）

---

## 0. 一句话

剩下四项红不是四个病，是**同一台机器的四个读数**：用配额交差去产账，再用 StoryScope 式百分比去判账。配额产不出仪表盘要的分布，于是两周里一直在加规则、加闸、加重跑。真正缺的不是更严的闸，是生成已经不听自己写过的寿命。

## 3. 核心问题

### 3.1 仪表盘和产线在抢方向盘

`verify_scale` 把关的是**全书占比**。`expand_wanjie_chapters` 产线用的是**本批配额**：

- 每卷点名一批实体，各交 `THICKEN_FACTS_MIN = 3` 条新 attribute，不够整批重跑
- 每批前 3 名命题不得超过 25%
- 提示词写死「每三到四章要有一条 `payoff`」
- 长线保护是开铺时从开口里抽最老的 `max(2, n_open//4)` 条

配额是为了让某个百分比动一下。百分比动了，书的形状没变。

### 3.2 四项红在数学上就过不了——不是还没铺够

**`≤4` 对不上 15%。** 非主角最多被点名 2 卷，每卷下限 3 条新 attribute。一次点名停在 3–4，两次停在 6，仍挤在 ≤4 附近。87 个「有 20 章跑道」的实体、每卷约 11 个名额，大部分人一辈子只被点一次。这台机器**造不出**「85% 实体 >4 条命题」。继续铺 141–200，形状不变。

**前 3 名对不上 20%。** 第 140 章把关分母 680 条，柳岸青 91 + 沈烛 49 + 兰因 44 = 27%。这是情节主体。`setting-scale` 自己废过关键词占比：人写种子里主角词 50–70%，没区分度。前 3 名是同一类指标。

**跨卷未收对不上 15%。** `required_holdovers` 只保护约 2–3 条。153 条线里保护 3 条，上限就是 2%。闸要 15%，产线最多交 2%。卷 7 已经 3/3 open，闸仍然红——**闸和机制从第一天就不是同一件事。** 这就是假闸那一课：显示一个口径、把关另一个。

**荒卷。** 提示词逼每 3–4 章收一条；抽签只护最老的几条。不是最老的开口，模型照收。不是「模型不听话」，是提示词在下收线任务。

### 3.3 库里其实已经有寿命，铺章不用

伏笔落库时已经写了窗口（`store/promises.py` + `core_preamble._TIER_WINDOW`）：

| tier | 窗口 | 含义 |
|------|------|------|
| `chapter` | 埋后 1–3 章 | 本卷内该收 |
| `arc` | 埋后 5–15 章 | 跨批、可能跨卷 |
| `book` | 埋后 1 章起、无上限 | 可一直挂 |

`promise_window_state` 已能算 `pre_window` / `in_window` / `overdue`。`volume_signals.overdue_promises_in_range`、cron `check_overdue_promises` 都在。章级提示甚至会标「已过期，必须收」。

persist **不看窗口**：到期的可以不收，未到期的只要不在 holdover 名单就可以收。默认 `tier="chapter"`。`book` 的 `payoff_min` 是埋后第 1 章，所以「全书挂着」的线从下一章起就可以被「每三到四章收一条」收掉。

写厚同理。R1 已经证明短文要吃这个实体自己的命题。WALL 却改成「本卷再立 3 个新 attribute」。模型没有新机制就换词，PADDING 再加「只认新 attribute」。病在**不问旧账的后果**，药却是**再要三条新键**。

### 3.4 两周里反复出现的失败模式

1. 红项 → 加提示词配额 → 数字微动 → 注水或假绿 → 再加一条 persist 规则。
2. 新闸没有阳性对照（悬置显示 `cross_open`、把关 `all_closed`；障碍「至少一条」永绿）。
3. StoryScope 故事级取值搬进书内当门槛。15% 写成「连载口径」，产线从未按 15% 产。
4. 抽样原文才是真验收。占比绿过假，原文红过真。

用户原话：**不要设量化闸，填规则去解决。**

## 4. 三条路

**A. 继续配额。** 把下限提到 5，holdover 提到 `n//2`，继续铺。  
否决：数学上仍难满足三道占比；重跑会再注水；直接违反「不要量化闸」。

**B. 只把四项红改成只报不拦。** 验收诚实了，产线仍默认收线、仍交差三条新键。书的形状不变。  
否决：治标。障碍那条「只报不拦」是因为找不到依据；这里依据在寿命窗口上。

**C. 寿命驱动（推荐）。** 生成听每条线、每个实体自己的账；验收查违约。占比只报，给人看趋势，不指挥写作、不退非零。

## 5. 最优方案

原则：**对象有寿命，生成跟寿命走，验收查违约。** 违约是 0/1，带阳性对照。不是 15%、20%、三条。

### 5.1 伏笔：到期必收，未到期不许收

落点：`expand_wanjie_chapters.py` 的提示词 + `persist`。**不改** `_TIER_WINDOW`（全书产品语义，扩万界铺章不配改全局）。

生成：

- 删掉「每三到四章要有一条 payoff」。
- 「本卷该收的线」= 当前章落在 `[payoff_min, payoff_max]` 的开口（`in_window` / `overdue`）。
- 「本卷不许收的线」= `pre_window`，以及 `tier=book` 且尚未被本卷 `pays` 点名的。不再用 `pick_holdovers` 抽最老 N 条来冒充长线。
- 埋线必须带 `tier`。缺省不许再静默成 `chapter`。模型选「本卷收 / 数章后收 / 挂到很后」，分别对应 chapter / arc / book。

persist：

- `advance_promise` 之前问 `promise_window_state`。`pre_window` → 跳过（与现 holdover 跳过同路，不新开旁路）。
- `overdue` 本批必须出现在某章 `payoff` 里；没有则批次失败重试（复用现成批次失败）。
- `tier=book`：本卷默认不可收，除非本卷契约 `pays` 点了这条。
- `pick_holdovers` / `required_holdovers` / 卷末 `holdover_deficit` 对声明名单的审计，改成对窗口的审计：本卷结束时，`pre_window` 和未点名的 book 线必须仍 open；`overdue` 必须已收或改判。S1 那条路保留，换输入。

验收硬项（替换 `CROSS_OPEN_MIN` 和「终卷前每卷 ≥1」）：

- **早收**：`payoff_chapter < payoff_min`（或 book 线被非 `pays` 收掉）→ 红。阳性：插一条 `pre_window` 收掉，必须 0→1。
- **逾期**：`status=open` 且 `state=overdue` → 红。阳性：插一条已过 `payoff_max` 仍 open，必须 0→1。
- 跨卷未收占比、荒卷名单、跨 ≥3 卷：**只报**，退出码不看它们。

卷 1–20 旧流水线：继续挂账，不重铺，不拿它打红新闸。

### 5.2 写厚：用旧账推出本卷处境，不是再立三条新键

保留（P1 是对的）：开铺前按长尾重排 `thickens`；提示词写「这一卷它做什么」。

停掉：`THICKEN_FACTS_MIN = 3` 当差额重跑；「至少 3 条新 attribute」作过关；为了 `≤4` / 前 3 名加码。

改成：

- 每个被点名的实体，本卷必须**被用到**：至少一条故事命题接到该实体已有账上。新 attribute 可以有，但不是分数。
- 差额审计从「新 attribute 条数」改成「本卷是否有该 oid 的命题」。没有 → 带着「这个实体本卷还没办事」重跑。有一条真办事就过。这是 0/1，不是 ≥3。
- 同键仍 `supersede_open=True`（PADDING 防注水，留着）。
- **每卷抽 3 个点名实体贴原文**——这条不省。

`≤2` / `≤4` / 前 3 名：verify_scale **只报**。`≤2` 仍是气味（出场 20 章了还没账），给人决定下一卷点谁，不退非零。批内 1/4 可留作提示软提醒，**persist 不再因前 3 名占比抛错**。

### 5.3 角色卡：名单，不是 0.3

空壳真问题是「这个人没有欲望」，R1 已修好上下文。此刻 40 人里 2 个薄。

硬红仅当**本卷 thickens 点到的角色**写厚后仍缺四槽。全书比例只报。`DUTY_FIELD_MIN=25` 不动。

### 5.4 verify_scale 硬 / 软

**硬（退非零），每项内存阳性 0→1：**

1. 已铺连续、章梗概过短
2. 野前缀、悬挂实体
3. 全库无矛盾（unfolded）
4. 红线 / `must_not_know`
5. 契约 `introduces` 未在本卷首次出场
6. 契约 `pays` 声明要收的没收
7. 早收、逾期（5.1）
8. 本卷点名写厚的实体 0 条本卷命题（5.2）
9. 本卷点名角色写厚后仍空壳（5.3）

**软（打印、不进 `rep.failed`）：** `≤2` `≤4` 前 3、跨卷未收占比、荒卷、跨 ≥3 卷、障碍、空间无从属、`char_issue_ratio`、`completeness_score`。

显示和把关必须同一口径。软项标题不许打钩。

不改：`setting_audit` 四类扫描、隐瞒键含 from（已做，待提交）。

## 6. 明确不做

- 不把 `LE4` / `TOP3` / `CROSS_OPEN_MIN` / `CHAR_ISSUE_RATIO_MAX` 调到现库能过
- 不新增任何全书百分比闸
- 不重铺 1–20；本方案落地并在 121–140 复验硬项之前不铺 141+
- 不改 `wanjie_scale`、不改 `_TIER_WINDOW` 全局数字
- 不把监控项写进提示词；不为过线改一致性扫描
- 不把「再铺一卷数字会好」当成方案

## 7. 落地顺序（一轮一事，批准后才动代码）

1. 提交隐瞒键那两份未提交文件。
2. 单测先红：persist 跳过 `pre_window`；`overdue` 本批不收则失败；点名实体本卷 0 条命题则失败，有 1 条即过。
3. 改 persist + 提示词。删「每三到四章一条 payoff」、删批内 1/4 抛错、`pick_holdovers` 退出主路。
4. 改 `verify_scale` 硬/软切分 + 早收/逾期阳性对照。
5. 只在已铺的 121–140 上复验（不重铺），如实报早收/逾期/点名是否被用到。旧窗口不可信则挂账。
6. 作者看过硬项和抽样，再只铺 141–160。验收看硬项 + 3 个实体原文，不看占比是否过线。

**文件：** `expand_wanjie_chapters.py`、`verify_scale.py`、`test_expand_persist.py`、`test_verify_scale.py`。`setting_depth.py` 不改常数数值；verify 不再用它们 `rep.check`。

## 8. 怎样算做对了

不是 `verify_scale` 退出码 0。是：

- 新铺的一卷里，`pre_window` / 未点名 book 线没有被收掉
- `overdue` 要么收了，要么报告点名改判，不默默挂着
- 点名写厚的实体，原文能读到「它本卷办了什么」，不是换词三条
- 占比四项仍红也允许；它们不再有权叫停
- 无矛盾仍绿，阳性仍 0→1
