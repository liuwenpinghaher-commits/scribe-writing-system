# SurrealDB 3.2.4 升级后优化方案（详细）

> **状态**：方案；**M0–M3 已落地，M4 部分**（2026-08-08）  
> - M0：compose 超时、护栏、smoke/backup、runbook  
> - M1：seed + 热路径基线 + EXPLAIN（KnnScan/FullText）；索引暂缓  
> - M2：capture→vector/retrieve_full 闭环  
> - M3：`tokenize_for_fts` 修 BM25「铜炉」空命中 + FTS 探针全绿  
> - M4：清洁 export + **两阶段恢复**演练绿  
> - 续：大负载（80 章/120 命题）复测；**109 chapter.seq / 110 prop.valid_from 索引**已落地，chapter 查询改 **IndexScan**  
> 详见 `docs/ops/surrealdb-3.2.4-m1-baseline.md`、`docs/ops/surrealdb-3.2.4-m3-m4.md`  
> **范围**：仅 **SurrealDB 3.2.4 底座** 可开启的工程与产品优化；**不**含 Hermes 语音/产品新 UI 大改。  
> **前提**（2026-08-08 demo 已落地）：  
> - 服务端：`surrealdb/surrealdb:v3.2.4`，`surrealkv`  
> - 应用：SurQL 已对齐 3.x（`type::record` / `FULLTEXT ANALYZER` / `type::is_string`）  
> - Python SDK：**仍 pin `surrealdb==2.0.0`**（与 3.2.4 实测可用）  
> - demo **已清空**，一书一库从空库起  
> - **记忆**：`memory_fabric_v1` 默认开；正典 + `memory_item` 在 Surreal；**非** Hermes memory；**不接 Spectron**

**架构铁律（优化不得违背）**

1. SurrealDB = 世界正典唯一真相源（一书一 `db=<slug>`）。  
2. `memory_fabric` = 过程/经验记忆，**不得**替代正典。  
3. 不引入第二真相库（Spectron / 外挂 GBrain 等）作为剧情记忆。  
4. 验证默认 = 打 **已部署 demo** 冒烟，不为验收再起平行全量栈。  
5. Grok 运行机禁止重活；构建/装依赖/长测在 demo 或 CI。

## 0. 目标与非目标

### 0.1 目标

| # | 目标 | 度量（验收） |
|---|------|----------------|
| G1 | 3.2.4 运行面稳定、可观测、可回滚 pin | 镜像钉死；慢查询/错误可查；健康检查绿 |
| G2 | 检索（全文 + 向量 + 混合）在 3.x 上正确且可调 | 探针 + 真实素材/记忆集上有序召回 |
| G3 | 热路径查询有索引与预算，延迟可控 | 章节列表/codex/回忆 p95 有基线与上限 |
| G4 | Schema 更严、脏数据更早失败 | ASSERT/TYPE 覆盖关键路径；写失败可解释 |
| G5 | 过程记忆端到端可证明「写得进、取得回」 | capture → `memory_item`>0 → prefetch 命中 |
| G6 | 迁移与代码无 2.x 回流 | CI 护栏禁止 `type::thing` / `SEARCH ANALYZER` |

### 0.2 非目标（本方案不做）

- 接入 **Spectron / Surreal 商业 agent-memory 服务** 作为书记忆。  
- 把剧情记忆迁入 **Hermes memory**。  
- 立刻升级 **Python SDK 3.0 alpha** 到生产（单列预备项，不绑本方案主线）。  
- 全量重写 MCP/前端；大改写作产品交互。  
- 为「再验一次」在 Grok 机起 Surreal + 全量 pytest。

## 2. 优化地图（总览）

```text
P0  运行面与正确性护栏     → 先稳住，再谈快
P1  索引与热路径查询       → 延迟/吞吐
P2  检索质量（FTS+向量+混合）→ 记忆/素材/命题好用
P3  过程记忆闭环可观测     → 证明 agent 记忆在 Surreal
P4  Schema 硬化与写路径    → 数据质量
P5  备份/运维/容量         → 可恢复
P6  （预备）SDK 3 正式版   → 不阻塞 P0–P5
```

优先级原则：**正确 > 可观测 > 热路径延迟 > 检索质量调参 > 硬化 > SDK 大改**。

### P1 — 索引与热路径查询（建议第 1–2 周）

#### P1.1 热路径清单（先量再改）

| 路径 | 典型 SurQL/访问 | 风险 |
|------|-----------------|------|
| 章节列表 | `chapter` 按 seq/状态 | 书长后全表 |
| Codex 列表 | character/faction/item/… | 过滤+排序 |
| 命题时间门 | `valid_from`/`valid_to` 后过滤 | 与 KNN 组合 |
| 记忆检索 | FTS + HNSW + graph 一跳 | 多通道 fan-out |
| 素材召回 | tokens FULLTEXT | analyzer 质量 |
| Ingest 状态 | ingest_seq 索引已有 | 保持 |
| `_migration` / work 注册 | 启动路径 | 已较轻 |

**动作**：在 demo 灌入 **合成负载**（脚本批量章节/角色/命题/memory_item，可删可重建），对上述路径记：

- 次数、p50/p95 延迟（应用层 `time.perf_counter` 或 access log）  
- 是否出现 transaction conflict 重试尖峰  

**不做**：无基线就加一堆索引。

#### P1.2 索引策略（原则）

1. **只为已证明的慢查询加索引**；每条新索引 = 新 migration `109+`。  
2. 优先：等值/范围过滤字段（`work`、`status`、`valid_from`、`thread_id`、`seq`）。  
3. 已有 HNSW/FULLTEXT **先验证 3.2 上 EXPLAIN/行为**，再谈调 EF/BM25。  
4. 避免「全字段索引」；写放大对 ingest/capture 敏感。  

**候选（待基线后裁定，非全部必做）**

| 候选 | 表 | 字段方向 | 触发条件 |
|------|-----|----------|----------|
| C1 | `chapter` | `seq` / `archived` 组合 | 列表 p95 > 门槛 |
| C2 | `proposition` | `valid_from`（时间门） | 语义召回后过滤砍半以上 |
| C3 | `memory_item` | `work,status,kind` 已有则复测 | fabric 检索超时 |
| C4 | `chat_message` | `thread_id, turn` | 长线程拉史慢 |
| C5 | `knows` | `since_chapter` 相关 | 图投影变慢 |

每条索引 PR 必须含：EXPLAIN 或前后 p95、回滚（REMOVE INDEX）说明。

#### P1.3 HNSW 正确性复核（3.2 必做）

代码已记录 2.x 坑：`<|K,COSINE|>` 可能退化为暴力扫，`<|K,EF|>` 才走索引。

| 步骤 | 动作 | 验收 |
|------|------|------|
| 1 | 在 3.2.4 上对 `semantic_recall` / `memory_vector` 跑 EXPLAIN（demo） | 确认 KnnScan/HNSW，非 TableScan |
| 2 | 若不兼容，改 SurQL 为 3.2 文档推荐的 KNN 语法 | 单测或探针脚本绿 |
| 3 | EF 策略：`max(40,k)` 可配置化（env） | 延迟 vs 召回可调 |

#### P1.4 查询预算（应用层）

| 项 | 建议 |
|----|------|
| `k` 上限 | 记忆/语义召回 k 硬顶（如 20），防 prompt 爆炸 |
| 通道超时 | bm25/vector/graph 单通道超时后降级，**fail-soft 仅检索通道**（正典通道策略保持现有） |
| 事务 | 保持「多语句拼 BEGIN/COMMIT」；避免超大 transaction |
| 冲突重试 | `semantic_index` 已有重试；扩展到其它高冲突 UPSERT 时统一工具函数 |

### P2 — 检索质量：FULLTEXT + 向量 + 混合（建议第 2–3 周）

依赖 P1 基线与正确 HNSW。

#### P2.1 全文（FULLTEXT ANALYZER）

现状：jieba 预分词写 `tokens` + Surreal blank/BM25（material / memory_item）。

| 步骤 | 动作 | 验收 |
|------|------|------|
| 1 | 固定中文探针集（10–30 条素材/记忆 + 查询） | 脚本可重复 |
| 2 | 对比：仅 jieba+BM25 vs 调 analyzer FILTERS | 人工相关性打分表 |
| 3 | 确认 3.2 `search::score` / `@1@` 语法与高亮需求 | 与 `test_material_bm25_probe` 对齐 3.x |
| 4 | 文档化「只索引 tokens、正文另存」约定 | 避免误建全文在未分词 prose 上 |

**不做**：上线未评估的中文 n-gram 全表扫。

#### P2.2 向量

| 步骤 | 动作 | 验收 |
|------|------|------|
| 1 | 统一 embedding 模型与维度（现 capabilities：`BAAI/bge-small-zh-v1.5` / HNSW 512） | 维度与 migration 一致 |
| 2 | 保证 ingest/capture **写库后必写 embedding**（失败可重试队列） | 无「有文无向量」比例统计 |
| 3 | 限知：继续 **KNN 后过滤** chapter 门（避免 KNN×WHERE 坑） | 与现 `semantic_recall` 一致 |

#### P2.3 混合检索（RRF）调参

`MemoryRetriever` 已多通道 + 权重设置（`memory.weight_*` / half_life）。

| 步骤 | 动作 | 验收 |
|------|------|------|
| 1 | 暴露/文档化设置项默认值 | 运维可知 |
| 2 | 用同一探针集扫 weight 网格（小范围） | 选定默认，写入 settings |
| 3 | ContextInspector 展示「本回合命中通道」 | 已有能力则只验收可见性 |

#### P2.4 正典 vs 经验 边界不变量测试

| 用例 | 期望 |
|------|------|
| 仅正典有、无 memory_item | 写作仍能拿到 canonical 事实 |
| 仅 memory_item 有冲突经验 | 不得覆盖正典；pending 可升级 |
| fabric 关 | `/memory/*` 403；写作行为符合现定义 |

### P3 — 过程记忆闭环（建议与 P2 并行，第 2 周）

**目标**：清库后也能在 15 分钟内证明「agent 记忆在 Surreal」。

#### P3.1 端到端剧本

1. 登录 demo，作品 `main` 或新建。  
2. `POST /memory/capture-turn`（或完整写作路径）写入 1–N 条经验。  
3. `SELECT count() FROM memory_item` > 0。  
4. `POST /memory/prefetch` 对相关 query 返回非空候选。  
5. （可选）产生 pending-claim → resolve 入正典。  

**验收**：checklist 脚本 + 人工点一次 ContextInspector。

#### P3.2 可观测性

| 信号 | 落地 |
|------|------|
| capture 成功/失败计数 | 日志字段 `event=memory_capture` |
| 每通道耗时 | prefetch 日志或 trace |
| 空检索原因 | 无数据 / 门控 / 超时 可区分 |
| 管理/诊断 API | 只读：`count by kind/status`（若缺则加 **只读** 管理接口，勿开 REST 世界写） |

#### P3.3 质量规则（小步）

- capture 去重：同 thread 近重复文本不灌爆库。  
- 置信度/状态机保持现有；**不**为「多记」而降低正典门槛。

### P4 — Schema 硬化与写路径（建议第 3–4 周）

空库窗口适合 **渐进 SCHEMA 变严**，避免历史脏数据迁移。

#### P4.1 原则

1. 新字段默认 **有 TYPE + 合理 DEFAULT**。  
2. 枚举类（如 `importance`）保持 ASSERT；错误信息对用户/主编可读。  
3. 大批 `SCHEMALESS` 表按 **读写频率** 分批收紧，不一次全库 SCHEMAFULL。  
4. 任何硬化 migration 必须 **幂等** + 空库可重放。  

#### P4.2 候选硬化顺序

1. `character` / `proposition` / `event` / `knows`（叙事核心）  
2. `memory_item` / `material`（检索核心）  
3. `chapter` meta  
4. 其余 codex 表  

#### P4.3 写路径

- 保持：世界写 MCP 审批门；`EMERGENCY_REST_WRITE` 默认关。  
- 优化：高频幂等 UPSERT 统一冲突重试；减少「半成功 migration」类问题（已有 `_query_all_checked`）。  
- 批量 ingest：评估 chunk 大小，避免单事务过大。

## 4. 明确不做（再次冻结）

| 项 | 原因 |
|----|------|
| Spectron 作为书记忆 | 第二真相源；与现架构与历史 SDD 冲突 |
| Hermes memory 存剧情 | SOUL 纪律禁止；限知/审计失效 |
| DEFINE API 替代 FastAPI | 无收益、双栈路由 |
| Grok 机全量 pytest + 本机 Surreal | 资源规则 |
| 无基线乱加索引 | 写放大与维护成本 |
