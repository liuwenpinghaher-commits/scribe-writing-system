## 三条更正

**一、野前缀不是模型写的。** 六条命题全在第 1 章，id 是 `fact:moon-regulator`
这种手写形式，不是模型产的 `fact:c{章}-{序}`。出处是
`scripts/humanrun_wanjie_seed.py` 第 290-296 行，硬编码 `loc:` / `world:` / `hist:`
且绕过 `canon_oid`。**11-40 章那 178 条命题，野前缀是 0。**
去收紧章级提示词是白做。

**二、「写厚跑了、只覆盖 5 个」是错的，真实是几乎全军覆没。**
种子脚本手写了动机的角色正好 4 个（柳岸青、沈烛、兰因、赫斯），
就是那 5 个「非空壳」里的 4 个。**模型真正写成的只有牧场主一个，还是半个**
（`deep_need` 仍为 None）。之前有人夸「兰因的 deep_need 写得好」——
那是人手写的种子，不是模型产出。**这条错我也犯过，别再引用那个说法。**

**三、悬置 23% 通过是假象。** 那 10 条线开着是因为书停在第 40 章、没有后文去收。
`跨≥3卷 23%` 更离谱：它拿终卷（第 10 卷）算跨度，卷 2 埋的线自动算成跨 8 卷。
**这两个数在半本书上没有意义，不能当达标。**

## 根因清单（按价值排序）

### R1　写厚不吃这个实体在书里已经发生的事 ← 最要命

实测复现（81 秒，`code=llm_thin`）：短文写出来了而且不难看，但抽不出
「她要什么 / 她让人付出什么」，于是整条判失败、**一个字都不落库**。

查下去发现，喂给短文的「设定圣经」里关于温贩婆只有一行：

```
〔角色〕
- 温贩婆
```

**只有名字。** 而库里明明有她四条命题：

```
第13章 亲情价：温贩婆把柳母余温写进价单，用亲情可抵诱导柳岸青接受体温交易。
第19章 亲情：温贩婆把体温价单写成亲情可被交易的入口，拒绝把活人样本登记却仍标价余温。
第19章 隐瞒·瞒抵押条款：对role:柳母瞒：瞒抵押条款
第24章 价单：温贩婆把柳母余温价单交给温税吏和余温押店，体温价单成为可接手的金融化账目。
```

**这四条就是答案**——她要把余温金融化，她让人付亲情和抵押条款。
模型只拿到一个名字，只能凭空编；编出来的白描自然过不了 `portrait_grounded`。

短文提示词本身**问得是对的**（`build_portrait_prompt`：「他要什么，他会让人付出什么」），
`duty_fields_ready` 也只要四个字段里凑齐两个。**坏的是上下文，不是提示词，也不是阈值。**

**改**：`_bible_for` 给 portrait 类实体补上该实体自己的命题
（按 `entity_id` 取，含 `隐瞒·` 那些），按章号排序，给个条数上限。
这是全套修复里唯一能直接把 `char_issue_ratio` 打下来的一条。

### R2　写厚失败即全丢，抽取步骤零重试

`thicken_codex_portrait` 里抽取失败就 `return {"ok": False, "code": "llm_thin"}`，
**短文那段好材料一起扔掉**，重跑要从头再来（每个 81 秒）。
而同一个文件里非 portrait 那条路（`codex_generate.py:853` 附近）
有 4 轮带 slot 提示的重试。**两条路待遇不一样，portrait 这条一轮都没有。**

**改**：抽取失败时，(a) 至少把短文本身存下来，别丢；
(b) 照 853 那段的样子补重试，重试时把缺哪个字段直接point给模型。

### R3　契约按卷发，批次按 10 章跑，中间没有按批分配

卷 2 点名 11 个，**首次出现全部落在第 21-26 章**：

```
盲眼邮差 21｜锈月台 22｜漏声商会 22｜冷票巷 22｜折光贩子 23｜壳外哨所 23
温税吏 24｜夜潮仓 24｜余温押店 24｜耳后针 25｜裂口灯 26
```

21-30 章引入 11 个，**31-40 章引入 0 个**。卷级新鲜度 7.0 仍然达标，
所以闸没红，但后半整整十章没长任何新东西。

这还是「契约是地板」那个机制：**模型只做被点名的，点名的能早做就早做。**
卷级点名可以全塞进前半批，判据看卷级就发现不了。

**改**：把引入按批分配。可选两条路，说明你选哪条：
契约给每个 `introduces` 带一个章号区间提示；
或者章级提示词按「本批该引入几个」现算（剩余点名数 ÷ 剩余批数）。
另外加一个**按批**的新鲜度观测项（先只报不拦），否则这类问题永远看不见。

### R5　验收不知道这本书铺到哪

`verify_scale` 把没铺的卷 3-10 当失败报：`引入缺 11 / 新鲜度 0 / 该知道缺 2 /
收线差 1`，**11 项红里有 4 项是这个**。悬置和跨卷跨度也拿终卷当分母，

### R6　写厚在每批之后对整卷重跑

`run_batch` 每铺完一批就对**整卷**的点名实体跑一次写厚。
20 章的卷、batch=10 → 同样 ~22 个实体跑两遍，每个约 81 秒。

**改**：写厚挪到整卷铺完之后跑一次；或者只对本批新出现的实体跑。

### R7　设定圣经里母题块重复两遍

`【母题·该回声 must_echo】` 和 `【贯穿母题·可主动编织】` 内容完全相同，

### R8　嵌入缓存落在会被清空的临时目录

缓存在 `/var/folders/.../T/fastembed_cache`，macOS 会清理临时目录，
所以隔一阵就要重下 54.6MB，网络一抖当次就失败。
`scribe3/embed.py:24` 支持 `SCRIBE3_FASTEMBED_CACHE`，只是没设。

**改**：指到固定目录（比如 `~/.cache/scribe3/fastembed`），
在 README 或跑批脚本里写死。**注意这不是写厚失败的根因**（根因是 R1），
但它会让长跑随机断。
