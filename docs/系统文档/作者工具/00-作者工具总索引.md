# 作者工具设计文档 · 总索引(主题五:把"算好的连续性"变成可用工艺视图 + 一个统一导航容器框架)

> 承接 `docs/系统文档/00-总览与架构.md` 的**全局改进路线图 · 主题五**。系统把世界建模(限知知识图/双时态/事件因果/弧光/伏笔)做到了专业写作软件之上——**但很多算好的东西既没接回生成,也没给作者用**。本目录把主题五的 **5 个作者工具(01–05)** 每个详成一份独立设计+实现文档(现状代码实证 / 深挖全网竞品工艺 / 完整设计 / 实现任务分解 / 验收 / 分期),并新增 **1 个导航容器框架(06 混合 Binder 项目树)** 把这 5 个工具**统一装进同一个壳**。
>
> 日期 2026-06-28。只读分析,文档不改代码。

## 一句话:5 个工具 + 1 个导航容器框架(06)

> **绝大多数所需数据已经在库里算好了,缺的只是「聚合端点 + 前端视图」——后端改动小、对作者价值大。** 唯一需要新建表的是「进度统计」(因为 chapter 是覆盖式 UPSERT、不留每日码字时间戳)。
>
> **共性升级(重要)**:01–05 **不是 5 个各自独立的新全屏视图**,而是**插进 06「混合 Binder 项目树」这一个统一导航容器框架**的零件——
> - **06 混合 Binder 项目树 = 导航容器框架**:左侧一棵统一**项目树**(📖 手稿支 卷→章→场景 + 📚 素材支 角色/势力/物件/术语/规则/伏笔/母题)常驻 + 中间栏按选中节点路由**详情/卡片墙/大纲表**;而图谱/时间线/伏笔台账/仪表盘这类**横切聚合视图**不挂树上,走**顶栏一排 tab**。已锁定**决策 B**:写作台左栏并入项目树,中间栏 = 对话 + 正文 + 护栏(含本章结构面板)。
> - **01 大纲/卷章树** = Binder 的**【手稿支】**(不是独立视图);其 `volume` 表 / chapter 字段 / `/outline` 数据设计仍有效,被 06 的 `/project-tree` 复用,点章 → 中间栏写作台。
> - **02 时间线 / 03 伏笔台账 / 04 进度** = **【横切视图】**,入口顶栏 tab。
> - **05 护栏** = **中间栏写作台内**(伴随当前章)。
> - **母题、伏笔有二象性**:既当**素材支分类容器**(点容器=列表、点单条=详情卡),又在**横切区保留全局视图**(母题列表 / 伏笔台账)——同源数据、两种视角。

## 迁移编号说明(重要)

各文档草案里独立提到的迁移号(如 `043_outline` / `043_daily_progress` / clue 的 `043`)只是**示意"下一个迁移"**。真实实现时按当时仓库实际最大号(现已到 `042`)**顺序分配、避免撞号**——三者若同期落地,应是 `043/044/045`。设计文档里的号不要照抄。06 混合 Binder **不新建迁移**(无 tree/node 表,纯只读投影),不占号。

## 跨工具实现顺序建议(据 Binder 框架调整)

> **框架视角**:01–05 都是装进 06 混合 Binder 的零件,实现顺序因此分两条线——「**横切工具**(02/03/04/05,旧 Rail 下零改即可见效)」与「**Binder 框架本体**(06 的项目树骨架,承载手稿支 01 与素材支)」。**06 的 MVP(项目树骨架 + `GET /project-tree`)是 01 的承载**:01 不再是"独立的第 5 个全屏视图",而是 06 手稿支的落地——卷章树 = 手稿支、卡片墙 = 容器节点的 DetailPane。

**按"价值÷成本"的工具内排序(横切优先,仍然有效)**:

1. **先做 [03 伏笔台账]**:零 schema 改动、纯聚合端点 + 三栏 UI,数据全在,**最快见效**;且 overdue 已单源,直接复用。
2. **再做 [05 护栏定位到句]**:后端"白送类"offset 一行即可,前端已有 `pmPosToProseOffset` 半套基建,MVP 性价比高,直接提升日常写作体验。
3. **再做 [02 时间线视图]**:零 schema、聚合端点 + 纯 CSS 横轴(不引依赖);注意用**不带限知时间门**的全量读画关系全史(Timeline≠Atlas 快照)。
4. **再做 [04 进度统计]**:需建 `daily_progress` 表 + save 单点记账,改动稍大但独立;先替换硬编码 100000 目标即有感。
5. **[01 大纲/卷章树]不再单列为"最后做的第 5 视图"**:它的卷章树/卡片墙**随 06 的手稿支一起落地**——一旦先上 Binder 框架,01 自然内含(手稿支即卷章树、容器节点 DetailPane 即卡片墙)。其新表(`volume`)+ 4 字段 + 拖拽(`@dnd-kit`)仍是 01 的成本,但承载它的"第 5 个独立视图"被 06 的项目树取代。

**推荐路径(把 Binder 框架纳进来)**:

- **① 先做零改的横切工具(03/05)**:在**旧 AppRail Rail 下**直接加视图/改返回结构,数据全在、不依赖 Binder,**最快见效**(对应上面的 1→2)。
- **② 再上 06 Binder MVP**:落 `GET /project-tree` + 左侧常驻 ProjectTree + DetailPane 路由,**把 01 手稿支并进来**(点章 → 写作台中间栏,接 `seq`;同步下线 WriteLayout 自带的 `renderOutline`,大纲不再两处重复)。此步即把 01 内含落地,左侧统一为一根项目树。
- **③ 02/04 收进横切**:时间线/进度做成 `view:timeline`/`view:progress` 横切 mode,与 atlas/insight 一起从旧 Rail **收编为顶栏 tab**;AppRail 降级为横切入口(决策 B / 06 §4.4),不清空。

> 关键纪律(贯穿 5 篇 + 06):**重排/排序一律走 `sort_order` 或叙事位,绝不动 `chapter.seq`**——seq 是故事时间轴,被限知全链路(facts_at/events.story_chapter/promise.setup_chapter)引用,动它=动全书时间轴。这与系统已有的"故事时间 vs 叙事顺序"分离哲学一致([02] 还指出本体尚未真正把两轴分离,是完整版才补的能力)。

## 与生成回路的关系

这 5 个工具(连同装它们的 06 框架)是**作者工具**(看/管),与主题一~四的**生成改进**(写得更好/限知保真/质控/人在环路)互补:
- 作者工具把"系统算好的连续性"可视化 → 作者能发现问题、做决策;06 的统一项目树让这些工具不再是割裂的全屏视图,而是同一棵树 + 同一中间栏里随手可达;
- 生成改进把"决策与约束"喂回主编 → 写得更好。
两者闭环:如 [03 伏笔台账]的超期告警 ↔ 主题一的伏笔回收提醒;[02 时间线]的事件 ↔ 主题二的限知帧;[05 护栏]的句级问题(在 06 的中心栏写作台内)↔ 主题三的"让主编改这处"。
