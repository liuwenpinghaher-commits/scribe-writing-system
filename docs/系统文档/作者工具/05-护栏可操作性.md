## 0. 核心判断(已核实)

护栏现状的根本缺口:**后端 QC / leak 返回的是"问题文本/短语",但不带它在正文里的字符位置(offset)**。所以前端只能列出"复读:某短语",作者知道有问题、却找不到在哪一句。

本篇的核心改造在后端:**每条 QC / leak 问题都要返回 `range:[start,end]`(在 prose 字符串中的字符 offset)**。前端拿到 range,才能用 TipTap/ProseMirror decoration 给那一段加波浪线、点击滚动定位、并把那一句单独交给主编改写。

幸运的是,**前端的 offset ↔ ProseMirror 位置对齐已经解决了**:`ProseEditor.jsx` 里的 `pmPosToProseOffset(doc, pmPos)`(`scribe3/web/src/editor/ProseEditor.jsx:40`)和 `toText(editor)`(:29)已经把"PM 文档位置"与"prose 字符串偏移"用同一口径互转(顶层块以 `\n\n` 相连、`sceneBreak` 序列化为 `* * *`)。本篇要做的是它的逆向:**prose offset → PM 位置**,口径完全照抄,见 §3.2.4。

## 1. 现状与缺口

### 1.1 护栏现在展示什么

护栏有两条触发路径,都只显示**计数 + 短语文本**,无定位:

**① 边写边查(顶栏护栏芯片)** — `WriteLayout.jsx:99-109` 防抖 3s 调 `api.checkProse` → `POST /check`,结果进 `guard` state。芯片(`WriteLayout.jsx:229-282`)显:
- 限知泄露词:`guard.leaks.map(l => l.marker).join('、')` —— 只列破绽词文本(如"镇煞钉")。
- 五类 QC:`复读 3 排比 2 升华 1 AI腔 1 过饱和 1` —— 只列每类**计数**。

**② 生成后体检** — `WriteLayout.jsx:123-135` 调 `api.postCheck` → `POST /post-check`,进 `postCheckResult`,在右栏「校验」cap(`renderVerify`,:404-472)显 QC/泄露/纪律三排,底部一个「让主编修这章」按钮(`sendPostCheckToChief`,:137-160)——把所有问题汇成一段 `seedQuote` 整章重交主编。**颗粒度=整章**。

**结论**:作者看到的永远是"有 N 处问题",但:
- 点不进正文——没有任何 issue 能跳到它对应的那一句。
- 改起来粗——只能整章重交,不能"就改这一句"。

### 1.2 各 QC / leak 函数的返回结构(逐类列:带不带 offset)

后端确定性 QC 全在 `scribe3/critique.py`,leak 在 `scribe3/verify.py`。逐类核实:

| 类别 | 函数(file:line) | 当前返回 | 带位置? | 算 offset 的依据 |
|---|---|---|---|---|
| 复读(章内) | `find_repetitions` `critique.py:15` | `[{phrase, count}]` | ❌ | phrase 是去空白 n-gram,可 `prose.indexOf(phrase)` 反查(但去空白会错位,见 §3.1.4) |
| 跨章复读 | `find_cross_chapter_repetitions` `critique.py:47` | `[{phrase, prior_chapters}]` | ❌ | 同上;另有 `cross_repetition_sentences`(:106)已落到**句**粒度,返回 `[{sentence, phrases}]` |
| 结构(排比/短断句) | `find_structural_repeats` `critique.py:159` | `[{phrase, count, kind}]` | ❌ | phrase 是描述性文本(如"诤…(排比开头)"),**非原文子串**,须改为吐"命中的句列表 + 各句 offset" |
| 升华(purple) | `find_purple_prose` `critique.py:189` | `[{phrase, kind}]` | ⚠️ 半 | phrase = `句.strip()[:30]`,是**原文句的前 30 字**,可 `prose.find(句全文)` 但被截断;须改为吐整句 + offset |
| AI 腔 | `find_ai_tics` `critique.py:205` | `[{kind:em_dash,count}]` 或 `[{kind:not_a_but_b, phrase}]` | ⚠️ 半 | `not_a_but_b` 有 `re.finditer`,**m.start()/m.end() 就是 offset**(白送);`em_dash` 是全章计数,无单点位置(可给每个 `——` 的 offset 列表) |
| 过饱和 | `find_oversaturation` `critique.py:224` | `[{kind, count, per_k}]` | ❌ | 纯密度统计,无逐处位置;须改为 `str.count` → `finditer` 收集每个命中词的 offset |
| 限知泄露 | `find_leaks` `verify.py:29` | `[Leak(fact_id, marker, subject)]`(`m in prose` 命中即收) | ❌ | `m in prose` 改 `prose.find(m)` / `finditer(re.escape(m))` 即得 offset(白送) |
| 纪律(LLM) | `discipline_truncate` `critique.py:285` | `{violations:[...], cut_after, changed}` | ⚠️ 句 | `cut_after` 是"复发前最后一句的原文逐字",`prose.find(cut_after)` 可定位(:291 已这么做) |
| 设定校验 | `validate_setting` `store.py:1358` | `[{type, severity, entity, description, evidence}]` | ❌ | `evidence` 是命中的原文片段(物名/limitation/情感词),`prose.find(evidence)` 可定位 |

**汇总——哪些 QC 需补 offset**:
- **几乎全部都要补**。其中 `find_ai_tics`(not_a_but_b)、`find_leaks`、`validate_setting`、`discipline` 是**白送**(已有 finditer 或原文 evidence,加一行 `.start()` / `.find()` 即可);
- `find_repetitions` / `find_cross_chapter` / `find_oversaturation` 要把"去空白 n-gram / 密度统计"改成"在原文上 finditer 收 offset"(去空白错位是坑,见 §3.1.4);
- `find_structural_repeats` 最重——它的 `phrase` 是描述文本不是原文,要顺带吐出命中句的原文 + offset。

### 1.3 为何点不到正文句(技术根因)

1. **后端无 offset**:如上,返回结构里没有 `range`。
2. **前端无 decoration 层**:`ProseEditor.jsx` 当前只挂 `StarterKit / Placeholder / CharacterCount / Focus / SceneBreak`,**没有任何 decoration 扩展**,无法给任意 range 上色。
3. **issue 与正文无双向链路**:护栏 popover / `renderVerify` 的每条都是纯文本 `<span>`,无 `onClick`、无 range 数据可传给编辑器。

**提炼出的通用交互范式(本设计直接采用)**:
- **分类着色下划线**:每类一种颜色的波浪线,**侧栏面板复用同一套色**。本仓映射(自定语义,不抄具体产品):复读=琥珀、穿帮=红、AI腔=灰、升华=紫、过饱和=橙。

- **面板 ↔ 正文双向联动**:点面板卡 → 滚动到该句 + 高亮闪;点正文下划线 → 弹卡。**两边共享同一份 issue 列表 + 同一套 range**,点哪边都能反查另一边。

### 2.2 TipTap / ProseMirror Decoration 实现机制(技术要点)

核心不变量(官方 guide,`https://prosemirror.net/docs/guide/`):**decoration 是纯渲染层,绝不改文档**。官方推荐模式:*"put the set in your plugin's state, map it forward through changes, and only change it when you need to."* 三类 decoration:**inline**(给范围加样式/属性,即波浪线)、**widget**(在某点插非文档 DOM,如 ⚠ 图标)、**node**(给单节点 DOM 加属性)。

落到本仓 TipTap v3(`@tiptap/react ^3.27`,ProseMirror 内核),一条 issue → 一段波浪线的标准链路:

```
后端 issue {type, message, text, range:[s,e]}  (prose 字符串 offset)
        │  前端拿到 issues 列表
        ▼
proseRangeToPm(doc, s, e)   ← §3.2.4,逆 pmPosToProseOffset
        │  得到 PM 位置 [pmFrom, pmTo]
        ▼
Decoration.inline(pmFrom, pmTo, { class: 'guard-uline guard-<type>',
                                  'data-issue-id': id })
        │  收进 DecorationSet
        ▼
GuardDecoration 扩展.addProseMirrorPlugins() → plugin.props.decorations(state)
        │  返回 DecorationSet → 视图渲染波浪线(纯 CSS,不进文档)
        ▼
issues 变化时:editor.view.dispatch(tr.setMeta(key, {issues}))
        │  plugin.apply 重建 DecorationSet
```

**官方参考实现 = ProseMirror lint 示例** `https://prosemirror.net/examples/lint/`——直接可移植到 TipTap:它用 `Decoration.inline(prob.from, prob.to, {class:"problem"})` 画线 + `Decoration.widget` 放图标,`handleClick` 里命中图标则 `tr.setSelection(TextSelection.create(doc, prob.from, prob.to)).scrollIntoView()`。本设计照此结构。

**已验证 API 签名(firsthand,prosemirror.net/docs/ref)**:
```
Decoration.inline(from, to, attrs, spec?) → Decoration      // 范围 + attrs(如 {class})
Decoration.widget(pos, toDOM, spec?)      → Decoration      // 单点 + DOM 构造器
DecorationSet.create(doc, decorations[])  → DecorationSet   // 不可变,每个方法返回新集合
set.map(mapping, doc, opts?)              → DecorationSet   // 随文档变化重定位
set.add(doc, decorations[]) / set.remove(decorations[]) / set.find(start?, end?, pred?)
EditorProps.decorations(state) → DecorationSource           // 插件把存的 set 交给视图
EditorProps.handleClick(view, pos, event) → boolean         // ★pos 已是解析好的文档位置(白送)
EditorView.coordsAtPos(pos) / domAtPos(pos)                 // 悬浮卡定位
tr.scrollIntoView() → Transaction                            // 滚动选区进视野
```

**五个技术要点**:
1. **不污染文档**:decoration 只影响**渲染**,`editor.getText()` / `toText()` 拿到的正文不含任何标记,落库 prose 干净。
2. **随编辑映射**:`apply(tr, set)` 里**先 `set = set.map(tr.mapping, tr.doc)`,再吸收 `tr.getMeta` 的新 issue**(map-then-mutate,官方 upload 示例同序)。作者插字/删字时已有下划线跟着移,不漂、不闪。
3. **点击 / 滚动**:`handleClick(view, pos, event)` 的 `pos` 是**已解析的文档位置(白送)**——读 `event.target` 的 `data-issue-id` 反查 issue → 弹卡;反向"点面板卡"→ 在该 range 上 `setSelection(...).scrollIntoView()` + 临时加 `guard-flash` decoration 闪一下。
4. **TipTap 接入**:扩展 `addProseMirrorPlugins()` 返回 `[Plugin]`;PM 包**必须从 `@tiptap/pm/state` / `@tiptap/pm/view` 导入**(re-export,避免双实例 bug),不要单独装 `prosemirror-state`。
5. **offset↔位置对齐(唯一坑)**:字符串下标 **不是** PM 位置——PM 位置按 token 计(每进出一个非叶节点 +1),每跨一个段落边界 offset 与 position 差 +2。见 §3.2.4 / §3.3,务必与 `toText` 同口径。

## 3. 设计

### 3.1 后端:让每条问题带 `range`

#### 3.1.1 统一 issue 形状

所有 QC/leak/纪律/设定校验,前端消费时统一成:

```jsonc
{
  "type": "repetition",          // 类别:repetition|cross_rep|structural|purple|ai_tics|oversaturation|leak|discipline|setting
  "message": "跨段复读:这措辞出现 3 次",  // 人读说明
  "text": "他知道回不去了",        // 命中的原文片段(用于前端兜底 indexOf + 校验)
  "range": [128, 135],           // ★ 在 prose 字符串里的 [start,end) 字符 offset;无法定位时为 null
  "meta": { "count": 3 }          // 类别附加(count/severity/fact_id/prior_chapters…)
}
```

> `range` 用**含空白的原始 prose 的字符 offset**(Python `str` 的码点下标)。前端 `toText(editor)` 产出的 prose 与后端 `req.prose` 是同一串(POST body 原样),所以 offset 同源。

#### 3.1.2 新增定位辅助(`critique.py`)

加一个纯函数,在**原始(含空白)文本**上按"去空白后的子串"找回原文 range——解决去空白 n-gram 的错位:

```python
def locate_phrase(text: str, phrase: str, max_hits: int = 20) -> list[tuple[int, int]]:
    """在原始 text 里定位"去空白后等于 phrase"的所有片段,返回含空白原文的 [start,end)。
    phrase 来自 find_repetitions 等(已去空白);text 含空白/换行。
    做法:把 text 折成"去空白字符序列 + 各字符的原始下标映射",在去空白序列上 str.find,
    再用映射把命中区间还原回原始 text 的 [start, end)。"""
    stripped_chars = []
    orig_idx = []          # stripped_chars[i] 在原始 text 的下标
    for i, ch in enumerate(text):
        if not ch.isspace():
            stripped_chars.append(ch)
            orig_idx.append(i)
    stripped = "".join(stripped_chars)
    out, start = [], 0
    while len(out) < max_hits:
        j = stripped.find(phrase, start)
        if j < 0:
            break
        s = orig_idx[j]
        e = orig_idx[j + len(phrase) - 1] + 1      # 闭区间末字符 +1 → 半开
        out.append((s, e))
        start = j + 1
    return out
```

每个 finder 升级为**同时**返回旧结构(向后兼容计数)+ 一个 `spans` 字段。给一个 `quality_flags` 的 offset 版聚合器,前端走它:

```python
def quality_issues(text: str, extra_patterns=None) -> list[dict]:
    """五类 QC 的"带 offset"展开形式(与 quality_flags 并存;后者仍供计数仪表盘)。"""
    issues = []
    # 复读
    for r in find_repetitions(text):
        for (s, e) in locate_phrase(text, r["phrase"]):
            issues.append({"type": "repetition", "text": text[s:e], "range": [s, e],
                           "message": f"复读:此措辞出现 {r['count']} 次", "meta": {"count": r["count"]}})
    # AI 腔 not_a_but_b(白送:finditer 有 offset)
    for m in _NOT_A_BUT_B.finditer(text or ""):
        issues.append({"type": "ai_tics", "text": m.group(0), "range": [m.start(), m.end()],
                       "message": "AI腔:「不是A——是B」伪深刻句式", "meta": {"kind": "not_a_but_b"}})
    # em_dash:逐个破折号给点(range 长度 2),仅当全章超阈值才报
    if _em_dash_over_threshold(text):
        for m in re.finditer("——", text or ""):
            issues.append({"type": "ai_tics", "text": "——", "range": [m.start(), m.end()],
                           "message": "AI腔:破折号过密", "meta": {"kind": "em_dash"}})
    # 升华:find_purple 改吐整句,locate 整句 offset
    for s_obj in _purple_sentences_with_offset(text, extra_patterns):
        issues.append({"type": "purple", **s_obj, "message": "升华/抒情:替读者下结论"})
    # 结构 / 过饱和 同理(见 3.1.3)
    ...
    return issues
```

#### 3.1.3 逐类改造要点

- **复读 `find_repetitions`**:phrase 去空白 → 用 `locate_phrase` 在原文找全部出现位置(可能多处,每处一个 issue,或只标第 1 处,产品取舍见 §6)。
- **跨章复读**:复用已有的 `cross_repetition_sentences`(已落到句),对每个 `sentence` 直接 `text.find(sentence_clean)`——但句子带空白,稳妥用 `locate_phrase(text, re.sub(r"\s+","",sentence))`。
- **结构 `find_structural_repeats`**:它的 `phrase` 是描述文本。改造:`anaphora` 类——把命中"同 3 字开头"的那些**句**找出来,逐句给 offset;`short` 类——把那些单字/极短断句逐个给 offset。
- **升华 `find_purple_prose`**:当前 `phrase = st[:30]`(截断)。改造:遍历句时记录该句在原文的 offset(用 `re.split` 的同时累加长度,或 `locate_phrase(text, 句去空白)`),`text` 给整句、`range` 给整句区间。
- **AI 腔 `find_ai_tics`**:`not_a_but_b` 白送 `m.start()/m.end()`;`em_dash` 是密度判定,过阈值后给每个 `——` 的 offset。
- **过饱和 `find_oversaturation`**:当前是 `str.count` 密度。改造:超阈值的类别,用 `re.finditer`(解释词 / 情感词 / 比喻词)收集每个命中的 offset,逐处给 issue。
- **限知泄露 `find_leaks`(`verify.py`)**:`m in prose` → `for mm in re.finditer(re.escape(m), prose): ...`,`Leak` 加 `range` 字段(或 app 层 `[lk.range for ...]`)。**白送**。
- **纪律 `discipline_truncate`**:`cut_after` 已能 `text.find`(:291),把那一句的 `[idx, idx+len(cut_after))` 作为 range 回传。
- **设定校验 `validate_setting`(`store.py`)**:每条 hint 的 `evidence` 是原文片段,加 `prose.find(evidence)` 得 range。

#### 3.1.4 去空白错位坑(必读)

`find_repetitions` 等的 phrase 是 `re.sub(r"\s+","",text)` 后的 n-gram。直接在含换行/空格的原文 `prose.indexOf(phrase)` 会**找不到**(原文里两字之间可能有换行)。因此必须走 `locate_phrase`(去空白序列 + 原始下标映射)。这是后端唯一的算法坑;务必带单测(§4)。

#### 3.2.4 prose offset → PM 位置(`proseRangeToPm`,对齐策略)

**这是唯一的对齐难点**。`ProseEditor.jsx:40` 已有正向 `pmPosToProseOffset`(PM→offset),口径:顶层块以 `\n\n` 连接,`sceneBreak` 序列化 `* * *`,段落内文本始于 `nodeStart+1`。逆向**照抄同一口径**:

```js
// 逆 pmPosToProseOffset:prose 字符 offset → PM 位置。口径必须与 toText 完全一致。
function proseOffsetToPm(doc, target) {
  let acc = 0          // 已走过的 prose 字符数(含块间 \n\n)
  let pmPos = 0        // 对应 PM 位置(每块前)
  let result = null
  doc.forEach((node) => {
    if (result !== null) { pmPos += node.nodeSize; return }
    const serialized = node.type.name === 'sceneBreak' ? '* * *' : node.textContent
    const len = serialized.length
    if (target <= acc + len) {
      if (node.type.name === 'sceneBreak') {
        result = pmPos                        // atom 块:落到块起
      } else {
        const inBlock = Math.max(0, target - acc)   // 块内偏移
        result = pmPos + 1 + inBlock           // +1 跳过段落开标记
      }
    } else {
      acc += len + 2                           // 块尾 + \n\n
      pmPos += node.nodeSize
    }
  })
  return result === null ? pmPos : result
}

function proseRangeToPm(doc, from, to) {
  const pmFrom = proseOffsetToPm(doc, from)
  const pmTo = proseOffsetToPm(doc, to)
  if (pmFrom == null || pmTo == null || pmTo <= pmFrom) return null
  return { pmFrom, pmTo }
}
```

**对齐兜底(双保险)**:`range` 跨段落(含 `\n\n`)时 inline decoration 也能正确切到多块(ProseMirror 自动按块拆)。但若后端 offset 与前端文档因极端编辑漂移失配,用 `it.text` 做**校验**:若 `doc.textBetween(pmFrom, pmTo)` 去空白 ≠ `it.text` 去空白,则**退回纯文本 indexOf**(在 `toText(editor)` 上 `indexOf(it.text)` 重新算 offset 再转 PM),仍失败则丢弃该 decoration(不画错位置的线)。这条 fallback 保证"宁可不标,不标错"。

- 后端任务 1–5:`locate_phrase` + `quality_issues` + `find_leaks` range + `/check`·`/post-check` 吐 `issues`。**白送类优先**(leak / not_a_but_b / discipline / setting),复读/过饱和次之。
- 前端:`proseOffsetToPm` + `focusIssue`(只做**点面板 → 滚动定位 + 临时 flash 高亮**,先不画常驻波浪线)。
- 价值:作者点一下就跳到出问题的句——"找不到在哪"立刻解决。

### 进阶(decoration 波浪线 + 分类着色)

- `GuardDecoration` 常驻 inline decoration + 六类 CSS 着色 + `set.map` 不漂。
- 点下划线弹悬浮卡(类别 + message)。
- `it.text` 校验兜底(宁可不标不标错)。

### 完整(句级「让主编改这处」闭环 + 忽略持久化)

- 悬浮卡 / 面板「让主编改这处」→ `discussSel` 定向 seed → 候选 → `applyProposal` 句级替换。
- `expandToSentence` 把短语 range 扩到整句给主编上下文。
- 「忽略」持久化:穿帮词一键判定(确认穿帮→改 / 确认无碍→加 `motif_terms` 白名单 or per-issue dismiss 存 localStorage / 后端),消除复发误报。
- 可选:把"忽略/接受"率回流,调 QC 阈值(降噪)。
