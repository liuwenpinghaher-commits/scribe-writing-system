## 0 · 一句话定位与本文产出

scribe3 现在能写出标杆级长篇,但作者**看不见自己写的长篇的骨架**:章节是一列扁平按钮,没有「卷」、没有每章梗概、不能拖拽重排、场景只能靠正文里的 `* * *` 推断。这是「作者基本盘」里被专业写作软件打磨了十几年、而 scribe3 完全空缺的一块。

本文交付:**OutlineView**——一个新的顶层视图,把 `卷 → 章 → 场景` 三层结构做成「卷章树(Binder)+ 卡片墙(Corkboard)+ 大纲表(Outliner)」三视图联动,支持拖拽重排、每章 synopsis 编辑、字数/QC/视角/伏笔角标与色彩编码,点卡片跳回写作台对应章。

本文包含:现状代码实证(§1)、竞品工艺提炼(§2)、数据模型迁移草案(§3.1)、后端端点 JSON 契约(§3.2–3.3)、前端组件树与 ASCII 布局(§3.5)、可直接执行的任务分解(§4)、验收清单(§5)、MVP→完整的分期(§6)。

## 1 · 现状与缺口(代码实证)

### 1.1 现有「章导航」是什么

写作台 `WriteLayout.jsx` 里章导航有两处,都是**扁平 seq**,无层级:

1. **顶栏步进器**(`WriteLayout.jsx:206–211`):`◂ 第 N 章 ▸` 两个按钮 + 中间「第 {chapter} 章」文字。`setChapter((c) => Math.max(1, c-1))` / `setChapter((c) => c+1)`,纯数字加减,不校验该章是否存在。

2. **左轨「素材→大纲」列表**(`WriteLayout.jsx:357–366`):
   ```jsx
   <SectionTitle icon={BookText} right={`${chapters.length} 章`}>章节</SectionTitle>
   {chapters.map((c) => (
     <button key={c.seq} onClick={() => setChapter(c.seq)} className={...c.seq === chapter ? 选中 : ...}>
       {chapterLabel(c.seq, c.title || '')}
     </button>
   ))}
   ```
   数据来自 `api.chapters()`(`WriteLayout.jsx:117`),即 `GET /chapters` → `store.list_chapters()`,**只返回 `seq` 和 `title`**(`store.py:818`)。一列纯文本按钮,点了 `setChapter(c.seq)`。无梗概、无字数、无拖拽、无卷分组。

App 顶层视图只有 4 个(`AppRail.jsx:3`):`write / codex / atlas / insight`。**没有 outline 视图**。视图切换在 `App.jsx:39–43` 用 `if/else` 硬编码渲染。

### 1.2 数据已有什么(章一级)

`chapter` 表(`migrations/004_manuscript.surql` + `016/022`,SCHEMAFULL):

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `seq` | int | 004 | 章序号(= 故事时间轴章号,**也是主键** `chapter:$seq`) |
| `title` | string DEFAULT '' | 004 | 章标题 |
| `focalizer` | option\<string\> | 004 | 视角角色(限知护栏的输入) |
| `prose` | string DEFAULT '' | 004 | 章正文 |
| `updated` | datetime VALUE time::now() | 004 | 最后更新 |
| `embedding` | option\<array\<float\>\> | 016 | 章向量(512 维) |
| `qc_word_count` | option\<int\> | 022 | 字数缓存 |
| `qc_issues` | option\<int\> | 022 | QC 问题数缓存 |
| `qc_causal` | option\<int\> | 022 | 因果问题数缓存 |
| `qc_at` | option\<datetime\> | 022 | QC 时间 |

`chapter_version`(032,命名存档点):`seq / prose / label / kind / qc / created_at`——和大纲无关,本文不动。

关键写入路径 `store.save_chapter`(`store.py:777`):`UPSERT chapter:$seq SET seq,title,focalizer,prose,embedding,qc_word_count`——**主键是 `chapter:$seq`**,这是后面「重排为什么需要独立 sort_order」的根因(见 §3.1)。

### 1.3 缺什么(逐项确认,据实写)

逐字段核对 migrations 001–042 与 `store.py`、`app.py`,**确认结论**:

| 缺口 | 是否已有 | 实证 |
|---|---|---|
| **卷(volume)层级** | ❌ 完全没有 | 全仓 grep 无 `volume` 表 / 字段;`chapter` 表无 volume 字段 |
| **每章 synopsis(梗概)** | ❌ 没有 | `chapter` 表无 synopsis 字段;`list_chapters` 只回 `seq,title` |
| **sort_order(独立于 seq 的排序)** | ❌ 没有 | 排序全靠 `ORDER BY seq`(`store.py:819`);主键即 `chapter:$seq` |
| **重排端点** | ❌ 没有 | `app.py` 无 `/chapters/reorder`、无 `PATCH /chapters/{seq}`;只有 `GET /chapters`(1225)、`GET /chapter`(1230)、`POST /save-chapter`(1287) |
| **聚合大纲端点** | ❌ 没有 | 无 `GET /outline`;前端拿不到「卷→章→场景树 + 每章梗概/字数/QC/视角」一把 |
| **场景(scene)层级** | ⚠️ 只能推断 | 正文里有 `* * *` SceneBreak 节点(`editor/SceneBreak.js`),解析为 `<hr data-scene-break>`;无独立 scene 表、无 scene 元数据 |
| **卡片视图 / 拖拽** | ❌ 没有 | 无 corkboard;`@dnd-kit` 未在 `web/package.json` 依赖中 |
| **色彩编码** | ❌ 没有 | 无 label/status/color 字段 |

> **核心判断(给决策)**:`chapter` 表**需要加字段**(`synopsis`、`sort_order`、可选 `label`/`status`),并**需要新建 `volume` 表**(独立表,不内联到 chapter)。重排**必须引入 `sort_order`**,不能改 `seq`——因为 `seq` 既是主键(`chapter:$seq`)又是故事时间轴章号(被限知 `_at(chapter)`、`facts_at`、`events.story_chapter`、`promise.setup_chapter` 等全链路引用),动 `seq` = 动全书时间轴,代价灾难性。详见 §3.1。

## 2 · 工艺与竞品参考(全网素材,带出处)

深挖了 Scrivener / Plottr / Ulysses 的大纲/卡片/结构工具,提炼「一个好的大纲工具该有什么」。

### 2.1 五条带出处的关键工艺

1. **Scrivener 三视图联动(Binder + Corkboard + Outliner)**:同一份文档,三种视角随时切——Binder 是左侧卷/章/场景的层级树;Corkboard 把每个文档显示成一张索引卡,卡正面是 synopsis;Outliner 是带可定制列(status / word count / synopsis / label)的表格。三者共享同一数据,在任一处拖拽重排都同步到另两处。([Literature & Latte — Integrating Binder, Corkboard, Outliner](https://www.literatureandlatte.com/blog/integrating-scriveners-binder-corkboard-and-outliner)、[ProWritingAid — Scrivener Outliner & Corkboard](https://prowritingaid.com/art/1555/using-scrivener-s-novel-outlining-tools.aspx))

2. **索引卡 = synopsis + 拖拽重排**:点卡片正文区即可直接键入/修订该文档的 synopsis;拖动卡片到目标位置即重排,Corkboard / Binder / Outliner 三处顺序同步;Grid 模式整齐排列、Freeform 模式可任意摆放。([Literature & Latte — Organize with the Corkboard](https://www.literatureandlatte.com/blog/organize-your-scrivener-project-with-the-corkboard)、[How to Use Scrivener's Freeform Corkboard](https://www.literatureandlatte.com/blog/how-to-use-scriveners-freeform-corkboard))

3. **色彩编码 = Label + Status,可任意语义**:用 Label 给章节上色(`View > Corkboard Options > Arrange by Label` 还能按 Label 把卡片排成色带泳道);用 Status 跟踪修订进度。颜色含义由作者自定(POV、进度、情节线、节奏)。([Literature & Latte — 5 Tips for Using Labels](https://www.literatureandlatte.com/blog/5-tips-for-using-labels-in-scrivener)、[Scrivener Overview](https://www.literatureandlatte.com/scrivener/overview))

4. **Plottr 场景卡 = 章 × 情节线网格,卡片携带元数据**:Timeline 的行是 Chapters、列是 Plotlines,每个交点是一张 Scene Card(像贴在墙上的便利贴),可拖拽换章/换情节线;卡片可链接 Characters / Places / Tags,据此过滤时间线。卡片在**场景级**记录 POV、角色目标、冲突等自定义属性(Custom Attributes)。([Plottr Docs — Scene Cards](https://docs.plottr.com/article/57-timeline-scene-cards)、[Plottr Features](https://plottr.com/features/))

5. **Plottr 色彩 = 情节线色 / POV 色 / 自定义状态色,Outline 与 Timeline 双视图**:Outline 侧栏的颜色映射该章场景卡所属的情节线色;切到 Card view 可逐卡设色——绿=「已写」、红=「待改」,或按主题/节奏/冲突类型上色;同一份数据可在结构化 Outline 与可视 Timeline 间切换。([Plottr Docs — Outline Overview](https://docs.plottr.com/article/68-outline-overview)、[Plottr — Outline Books](https://plottr.com/outline-books/))

补充对照:**Ulysses 没有 corkboard / 索引卡 / 时间线**,只能用 keywords + filters 把场景按角色/地点/状态聚合——这反向印证了「卷章树 + 卡片墙」正是 Scrivener/Plottr 区别于轻量笔记类工具的核心竞争力。([Reedsy — Ulysses Review](https://reedsy.com/studio/resources/ulysses-writing-app-review)、[Laterpress — Writing Software Compared](https://www.laterpress.com/comparisons/writing-software-compared/))

中文网文工具(橙瓜码字 / 番茄作家助手)同样以「卷 + 章 + 大纲助手」为标配结构骨架,PC/手机端同步查看,印证「卷」是中文长篇的必需层级(网文动辄数百章,无卷无法管理)。([橙瓜码字](https://www.chenggua.com/)、[番茄作家助手](https://www.32r.com/app/122865.html))

### 2.2 提炼:一个好的大纲工具该有什么

| 能力 | 含义 | scribe3 对应设计 |
|---|---|---|
| **三视图同源** | 树 / 卡片墙 / 大纲表共享一份数据,随时切 | OutlineView 内 Tab 切换,共用同一份 `GET /outline` 结果 |
| **层级** | 卷 → 章 →(场景),长篇必需 | 新建 `volume` 表 + `chapter.volume` 链接;场景从 `* * *` 推断(MVP) |
| **卡片携带信息** | 卡正面 synopsis,角标 字数/状态/POV/标签 | 卡片显 synopsis + 字数 + QC 角标 + POV 角标 + 伏笔点 |
| **拖拽重排** | 拖卡片即重排,顺序立即同步 | `@dnd-kit/sortable`,落定调 `POST /chapters/reorder`(改 `sort_order` 不改 `seq`) |
| **色彩编码** | 颜色自定义语义(进度/POV/情节线) | `chapter.label` 枚举上色 + POV 自动色(按 focalizer 取色) |
| **就地编辑梗概** | 点卡片即写 synopsis | 卡片 inline textarea → `PATCH /chapters/{seq}` |
| **跳转** | 点卡片直达写作台对应章 | 点卡片 → `setView('write')` + 跨视图传 seq |

## 3 · 设计

### 3.1 数据模型(迁移草案)

#### 决策:加字段 + 建表,且重排用 `sort_order` 不动 `seq`

- **`chapter` 加 4 个字段**:`synopsis`(梗概)、`volume`(链接卷)、`sort_order`(排序权重)、`label`(色彩编码枚举,可选)。
- **新建 `volume` 表**:卷是一等结构对象,有自己的标题/序号/简介/颜色,且一卷含多章——内联到 chapter 无法表达卷自身属性,故独立建表。
- **`sort_order` 是重排的落点**:`seq` 是主键 + 故事时间轴,被限知全链路引用,**绝不能因为「把第 5 章拖到第 3 章前面」就去改它**。展示顺序由 `sort_order` 决定(初始 = `seq`);重排只改 `sort_order`。这样「叙述呈现顺序」与「故事时间轴章号」解耦——这正符合 scribe3 已有的 discourse(叙述层)vs story(故事层)分离哲学(见 `01-本体与数据模型.md`:章是 discourse 对象)。
  - 写作台仍按 `seq` 定位章(`api.chapter(seq)` 不变);OutlineView 按 `sort_order` 展示。MVP 阶段二者一致,重排功能上线后才可能分叉。

#### 迁移 043(草案)

```sql
-- scribe3/migrations/043_outline.surql · 作者工具:大纲/卷章树
-- 卷(volume):一等结构对象。一卷含多章(chapter.volume 反向链接)。
DEFINE TABLE IF NOT EXISTS volume SCHEMAFULL;
DEFINE FIELD IF NOT EXISTS seq     ON volume TYPE int;              -- 卷序(第几卷)
DEFINE FIELD IF NOT EXISTS title   ON volume TYPE string DEFAULT '';
DEFINE FIELD IF NOT EXISTS summary ON volume TYPE string DEFAULT ''; -- 卷简介
DEFINE FIELD IF NOT EXISTS color   ON volume TYPE option<string>;   -- 卷色带(可选)
DEFINE FIELD IF NOT EXISTS updated ON volume TYPE datetime VALUE time::now();
DEFINE INDEX IF NOT EXISTS idx_volume_seq ON volume FIELDS seq UNIQUE;

-- chapter 增列:梗概 / 卷链接 / 排序权重 / 色彩标签
DEFINE FIELD IF NOT EXISTS synopsis   ON chapter TYPE string DEFAULT '';
DEFINE FIELD IF NOT EXISTS volume     ON chapter TYPE option<record<volume>>;
DEFINE FIELD IF NOT EXISTS sort_order ON chapter TYPE option<int>;   -- NONE=回退按 seq 排
DEFINE FIELD IF NOT EXISTS label      ON chapter TYPE option<string>
  ASSERT $value = NONE OR $value IN ['draft','revise','done','idea','beat'];

-- 回填:已有章 sort_order 初始化为 seq(让旧数据有稳定展示序)
UPDATE chapter SET sort_order = seq WHERE sort_order = NONE;
```

> 注意:迁移由 `scribe3/migrate.py` 顺序执行 `migrations/*.surql`。`DEFINE FIELD IF NOT EXISTS` 对 SCHEMAFULL 表是加列、幂等。回填用 `UPDATE … WHERE sort_order = NONE` 保证幂等重跑安全。

#### 场景层级(scene)——MVP 不建表

场景从正文 `* * *` SceneBreak **推断**,不落库:`chapter.prose` 按 `editor/SceneBreak.js` 的同款正则(`/^\s*(?:\*\s?\*\s?\*|---)\s*$/m`)切段,段数 = 场景数,每段首句/前 N 字 = 场景标题。理由:已有 SceneBreak 节点,零迁移即可出「场景层级」;显式 scene 卡(带 POV/地点/冲突等元数据)留到「完整」分期再评估建 `scene` 表(见 §6)。

### 3.2 后端端点

#### `GET /outline` — 聚合卷 → 章 → 场景树

一次拿全 OutlineView 渲染所需数据,不回正文全文(只回梗概与统计,省带宽)。

**响应**:
```json
{
  "volumes": [
    { "id": "1", "seq": 1, "title": "第一卷 · 镇煞", "summary": "焦三入清潭派…", "color": "#5b8c6e" }
  ],
  "chapters": [
    {
      "seq": 3,
      "sort_order": 3,
      "title": "炼真",
      "synopsis": "焦三在地窖炼成镇煞钉,代价是右手灼伤。",
      "focalizer": "焦三",
      "volume": "1",
      "label": "done",
      "word_count": 3120,
      "qc_issues": 0,
      "qc_causal": 1,
      "promise_open": 2,
      "scene_count": 3,
      "scenes": [
        { "idx": 0, "title": "地窖前的犹豫", "char_count": 980 },
        { "idx": 1, "title": "炼钉", "char_count": 1340 },
        { "idx": 2, "title": "灼伤与代价", "char_count": 800 }
      ]
    }
  ],
  "unassigned_chapters": [5, 6]
}
```
- `chapters` 按 `sort_order` 升序(回退 `seq`)。
- `volume` 字段是卷裸 id;`unassigned_chapters` 是 `volume = NONE` 的章 seq(渲染成「未分卷」分组)。
- `promise_open`:该章 `setup_chapter == seq` 且未回收的伏笔数(可选,MVP 可省)。
- `scenes`:由 `prose` 按 SceneBreak 切段得到(后端切,前端只渲染)。MVP 可只回 `scene_count`,`scenes[]` 留到「完整」期。

**store 方法草案**(`store.py`):
```python
def outline(self) -> dict:
    """聚合大纲:卷 + 章(梗概/字数/QC/视角/卷/标签 + 场景切分),不回正文全文。"""
    vols = self._query(
        "SELECT meta::id(id) AS id, seq, title, summary, color "
        "FROM volume ORDER BY seq")
    rows = self._query(
        "SELECT seq, sort_order, title, synopsis, focalizer, "
        "meta::id(volume) AS volume, label, qc_word_count AS word_count, "
        "qc_issues, qc_causal, prose "
        "FROM chapter ORDER BY (sort_order ?? seq)")
    chapters = []
    for r in rows:
        scenes = _split_scenes(r.pop("prose", ""))   # 按 * * * 切段
        chapters.append({**r, "scene_count": len(scenes),
                         "scenes": [{"idx": i, "title": s["title"],
                                     "char_count": s["chars"]} for i, s in enumerate(scenes)]})
    unassigned = [c["seq"] for c in chapters if not c.get("volume")]
    return {"volumes": vols, "chapters": chapters, "unassigned_chapters": unassigned}
```
`_split_scenes` 是模块级纯函数(便于单测):正则切段 → 每段 `{title: 前24字首句, chars: 去空白字数}`。

#### `POST /chapters/reorder` — 拖拽重排

**请求**:作者拖完一次,提交「这一卷(或未分卷区)内的章顺序」。
```json
{ "volume": "1", "order": [3, 1, 2, 4] }
```
- `volume`:目标卷裸 id;`null` = 未分卷区。
- `order`:该卷内章 `seq` 的新顺序(全量,非增量)。

**语义**:把 `order[i]` 章的 `sort_order` 设为「卷基址 + i」,并把这些章的 `volume` 设为请求里的 `volume`(支持「拖到别的卷」)。`seq` 不动。卷基址 = 卷 seq × 1000(留间隔,跨卷有序)。

**响应**:`{ "status": "reordered", "volume": "1", "count": 4 }`

**store 方法草案**:
```python
def reorder_chapters(self, volume_id: str | None, order: list[int]) -> int:
    base = 0
    if volume_id:
        v = self._query("SELECT seq FROM type::record('volume',$v)", {"v": volume_id})
        base = (v[0]["seq"] if v else 0) * 1000
    for i, seq in enumerate(order):
        self._execute_write(
            "UPDATE type::record('chapter',$seq) SET sort_order=$o, volume=$vol",
            {"seq": seq, "o": base + i,
             "vol": f"volume:{volume_id}" if volume_id else None})
    return len(order)
```

#### `PATCH /chapters/{seq}` — 改梗概 / 卷 / 标签(不碰正文)

**请求**(任意字段子集):
```json
{ "synopsis": "焦三炼成镇煞钉,右手灼伤。", "volume": "1", "label": "done", "title": "炼真" }
```
**响应**:`{ "status": "updated", "seq": 3 }`

**store 方法草案**:`UPSERT chapter:$seq SET` 只 set 传入的字段(白名单 `synopsis/volume/label/title`),**不碰 `prose/embedding/qc_*`**——和 `save_chapter`(写正文 + 重算向量/字数)是两条独立写路径,避免改梗概触发昂贵的 embedding 重算。

#### 卷的增删改(配套)

`POST /volumes`(建卷 `{seq,title,summary,color}`)、`PATCH /volumes/{id}`、`DELETE /volumes/{id}`(删卷时把该卷章的 `volume` 置 NONE,不删章)。常规 CRUD,参照 `app.py` 已有 `/characters`、`/factions` 模式。

### 3.3 前端 OutlineView

#### 接入点

#### 卡片(ChapterCard)显示什么

| 元素 | 数据源 | 视觉 |
|---|---|---|
| 顶部色条 | `label` 色 或 POV 自动色 | 4px 高色带 |
| 章号 + 标题 | `seq` + `title` | `chapterLabel(seq,title)`(复用 `chapterLabel.js`) |
| 梗概 | `synopsis` | 2–3 行省略;空则占位「+ 写梗概」,点击展开 textarea inline 编辑 → `patchChapter` |
| 字数 | `word_count` | `1.2k` |
| POV 角标 | `focalizer` | 小圆 + 角色名/首字 |
| QC 角标 | `qc_issues`/`qc_causal` | `0` → ✓ 绿;`>0` → ⚠N 橙(复用 `verifyIssues.js` 配色 token) |
| 伏笔点 | `promise_open` | ⚑N(可选) |
| 状态 | `label` | ◆ + 文案(draft/revise/done…) |

#### 色彩编码(编什么)

两套可切换语义(下拉选):
- **按状态**(默认):`label` 枚举 → 色 token:`idea`=灰 / `draft`=蓝 / `revise`=橙(`--color-fore`) / `done`=绿(`--color-ok`) / `beat`=紫。对齐 Plottr「绿=已写、红=待改」工艺。
- **按 POV**:`focalizer` 哈希到一组稳定色(同一角色恒定一色),一眼看出视角分布与跳视角。对齐 Plottr「按 POV 上色」。

复用全站语义色 token(`--color-brand/fore/irony/secret/ok/danger`,见 06 文档 §1.1),不引入新调色板。

#### 拖拽重排交互

- `@dnd-kit/sortable`,`VolumeLane` 是 `SortableContext`,卡片是 sortable item。
- 拖动时本地乐观重排(`arrayMove`);松手 `onDragEnd` 算出该卷新 `order`,调 `api.reorderChapters(volumeId, order)`;失败回滚 + Toast。
- 跨卷拖拽:卡片落到另一卷 lane → `order` 提交时带新 `volume`,后端 `reorder_chapters` 一并改 `volume`。
- **守卫提示**:因为 `sort_order` ≠ `seq`,首次重排弹一次性说明「重排只改阅读顺序,章号(故事时间轴)不变」——避免作者误以为动了限知时间轴。

## 6 · 分期

- T1–T2、T5(只读部分):迁移 + `GET /outline` + OutlineView 卷章树 + 卡片墙(显梗概/字数/POV/QC + 点卡跳章)。
