> 这是 scribe3「限知长篇小说写作台」的系统文档总入口。本系列把整个系统拆成 6 个子系统,每篇文档都做三件事:**① 读代码摸清现状并解释 ② 全网搜真实写作工艺定"最优" ③ 对照差距给详细改进方案**。本篇是总览:整体架构 + 系统哲学 + 6 篇索引 + 把 6 篇的改进汇成一张**全局优先级路线图**。

## 一、一句话定位

> **scribe3 是一台「按视角投影知识帧 → 只把帧喂给生成 → 事后确定性兜底校验」的限知长篇小说引擎,交互形态是「用户 chat 引导、主编(LLM)主笔」。**

它和普通"AI 写作工具"的根本区别:不是"提示模型别写穿帮",而是**物理隔离**——渲染前按焦点角色投影出"他此刻知道什么"的知识帧,帧外的事在数据上就进不了 prompt。这套限知能力是它的命根子与最大卖点。

判断任何字段/设计是否合理,先过三连(贯穿全系列):
1. 它服务于"投影某 knower 在某 chapter 的知识帧"吗?(限知)
2. 它带"故事时间轴(章号)"吗?系统所有读路径都是 `_at(chapter)`。
3. 私密内容若明文存在某字段、又走任何全读路径,它就是错模。

### 2.2 数据流(一章的生命周期)
```
用户 chat 引导
  → 主编(Hermes,可自调 s3_工具查库)
  → 后端组装写作 prompt:_editor_write_system + 限知帧 _frame_block + 前情 _recap_block
     + 当前章末段 _current_tail_block + 声音锚 _voice_anchor_block + 弧光 _arc_state_block
     + 母题 _motif_block + craft 引擎 build_craft_block + 防复读 _avoid_directive + 末尾强化
  → 模型出 ⟦PROPOSAL⟧ 围栏正文(忘写则兜底包成 chapter 提案,流式渲染)
  → 前端草稿卡 接受 → /save-chapter(落库 + 后台 ingest)
  → ingest 反向抽知识:命题/knows/reader_knows(自动)/char_state 弧光(自动)/声音演变 flag
     (语义去重防重复真相 · ingest_seq 幂等)
  → 下一章:_frame_block / _recap_block 物理反映上一章新知 → 主编"看得见、记得住"
  → /post-check 生成后体检:五类 QC + 限知穿帮 + discipline 语义判官 + 设定矛盾 → 一键让主编修
```

### 2.4 系统哲学(五条贯穿设计)
1. **限知 = 物理隔离**:门控唯一来源是 KnowledgeEdge,不是 secret(secret 只是 verify 元数据)。
2. **双时态**:命题/知识/关系都有"故事时间"区间,事实会失效(supersede/forget/evolve),限知推演能撤销不只叠加。
3. **写读单点 + 创作写待批**:所有世界状态写经 `_execute_write` 单点;创作类写经 elicitation fail-closed 待批(manuscript/ingest 例外)。
4. **质量两层**:生成时 prompt 预防(防复读/声音/craft 指令)+ 生成后确定性扫描兜底(系统自承"prompt 治不了已生成文本,扫描+定向删才拦得住")。
5. **craft 引擎层**:8 引擎(身体先行/温度/闲笔/比喻/潜台词/感官/浸泡/留白)+ 题材正则 + 母题 + 北极星意图,把"怎么写得好"注入生成。

## 四、全局改进总纲(对比"最优"的差距 → 优先级路线图)

> 把 6 篇各自的 top 改进汇成一张跨子系统路线图。**贯穿性结论:生成的 prose 质量不是瓶颈(真机两次都出乱世铜炉级散文),瓶颈在"规划/保真/质控/工具"——系统把世界建模做到了专业写作软件之上,但很多算好的东西没接回生成、也没给作者用。**

### 主题一 · 让主编写得更好(规划与生成)——最高杠杆
| 改进 | 现状→最优差距 | 优先级 | 出处 |
|---|---|---|---|
| **场景级规划 `_scene_block`** | 主编现"听一句话即兴出整章";最优是先定 goal-conflict-disaster 场景卡。命中"AI 最弱在 plotting" | **P0** | [03](03-写作主链路.md) |
| **弧光 want-vs-need 接线 `_motivation_block`** | `surface_goal/deep_need/internal_conflict/fear` 字段已在但**从不进 prompt**;加一个块零建表激活 Weiland 框架 | **P0** | [05](05-声音弧光与craft引擎.md) |
| **对白潜台词支架 + `find_on_the_nose`** | craft 只有一段文字引导、零校验;最优是场景级潜台词支架(各角色明面想要/绝不肯认)+ 去 on-the-nose | **P0** | [05](05-声音弧光与craft引擎.md) |

## 五、最该先做的 5 件(最高杠杆 P0)

> 若只做 5 件,这 5 件对"写出乱世铜炉级长篇"杠杆最大:

1. **场景级规划 `_scene_block`**([03](03-写作主链路.md))—— plotting 是 AI 最弱项,单章质量天花板最大杠杆。
2. **弧光 want-vs-need `_motivation_block`**([05](05-声音弧光与craft引擎.md))—— 字段全有、零建表,激活"想要vs需要"立刻让人物有内在驱动。
3. **过滤词/show-don't-tell 检测**([04](04-质量管线.md))—— 自编头号刀,纯函数高 ROI,直接压"告知体"。
4. **大纲/卷章树 OutlineView**([06](06-前端与交互.md))—— 长篇 10 万字结构现在全靠脑记,这是作者工具最大空缺。
5. **讨论→定稿衔接**([03](03-写作主链路.md))—— "用户 chat 引导"的引导现在喂不进写作,人在环路的环要先闭上。
