## 0. 一页摘要

| 维度 | 现状 |
|---|---|
| **核心范式** | 渲染前按 focalizer 投影知识帧,**只把帧喂生成;帧外的事物理上进不了 prompt** |
| **唯一门控** | `KnowledgeEdge`(谁/哪章/经何途径/知道某命题)。`secret` 只是 verify 元数据,不是门控 |
| **三极视角** | `world`(全知真相,一致性裁判)/ 角色帧(`role:xxx`,有边才知道)/ `reader`(读者已知,反讽的一极) |
| **反讽** | `dramatic_irony = reader帧 − focalizer帧`,集合差集,**可计算**,非人脑事后判断 |
| **写作注入** | `_frame_block` 把焦点者此刻确知的事实确定性拼进续写 prompt(本会话从「靠模型自觉」升级为「物理注入」) |
| **兜底** | `find_leaks` 事后扫描散文里有没有泄露帧外私密(第二道 pass,判官,不是主防线) |
| **最大优势** | **物理隔离**——绝大多数写作软件做不到,它们只能在 prompt 里写「请别写角色不知道的事」 |
| **最大短板** | POV 切换无场景级管理(一场一视角纪律未编码)、误信(`polarity`)读端就绪写端缺位、反讽点作者侧不可视化主动运用、私密只有「全有/全无」两档 |

**三个最重要改进**(详见 §7):
1. **POV 场景级纪律引擎**——把「一场一视角」从口头约定变成可校验的结构约束(场景登记 focalizer + 切换只在场景/章边界 + 头脑跳跃检测)。
2. **反讽点的作者驾驶舱**——`dramatic_irony` 现在只「能查」,不「主动用」;要把反讽点表面化进写作 prompt 与编辑面板,让作者「明知故纵」地经营悬念。
3. **私密分级 + 误信生产路径**——把 secret 从「完全保密/完全透露」两档升级为「保密/半透露(有泄露痕迹)/已揭示」三态,并补上 `polarity=False` 的写入口,让「假情报/被误导」成为可表达的剧情。

## 1. 限知是什么、为何是命根子

### 1.1 定义

**限知(limited knowledge)** = 在任一时刻,叙事只能呈现**视角人物(focalizer / 焦点者)此刻确实知道的东西**。他不知道的事——别人的密谋、墓室深处的机关、读者已经看穿的真相——既写不进他的所见,也写不进他的所想。

`knowledge.py` 的模块 docstring 把范式说死(逐字):

> 限知渲染 = 渲染前按 focalizer 投影出他的知识帧,只把帧喂生成。
> 帧里没有的事,**物理上进不了 prompt**。判官只兜底,不是主防线。

### 1.2 两条路线:「提示模型别写」 vs 「物理隔离」

这是理解本系统价值的关键对比。

| | 路线 A:提示模型别写 | 路线 B:物理隔离(本系统) |
|---|---|---|
| 做法 | 把全部世界设定喂给模型,附一句「请只写角色 X 知道的事」 | 渲染前先算出角色 X 的知识帧,**只把帧喂进 prompt**,帧外内容根本不出现在上下文里 |
| 失败模式 | 模型一旦「脑补」或注意力涣散,就会泄露它本不该知道的设定(因为那些设定就在它眼前) | 模型想泄露也无从泄露——它从未见过帧外内容 |
| 类比 | 给嫌疑人看了全部卷宗,叮嘱他「别提第 7 页」 | 第 7 页根本没放进卷宗袋 |
| 业内现状 | 绝大多数写作软件/RAG 续写工具的做法 | **本系统的核心差异化**(详见 §6 工艺对照) |

> **一句话**:路线 A 是「信息在场 + 自律」,路线 B 是「信息屏障」。本系统选 B,这是它相对市面写作工具的结构性优势——也正因如此,任何「全读路径吐明文私密」的洞,都是对命根子的直接破坏(故 §5 本会话集中堵这类洞)。

**举例(乱世铜炉式)**:老乌头守着祖坟,知道墓室第三道砖墙后藏着前朝的镇煞钉。
- 焦点者 = 胡不为(年轻后生,只听过传言)时:`project_frame(胡不为, 第5章)` 里**根本没有**「墓室藏镇煞钉」这条命题——因为胡不为没有对应的 `KnowledgeEdge`。于是写胡不为视角的第 5 章,模型上下文里压根看不到这个秘密,**想剧透也剧透不了**。
- 焦点者 = 老乌头时:他的帧里有这条命题(`secret=True`),`_frame_block` 注入时会把 value 屏蔽成「此处有私密」——焦点者「心里有数」但叙述不直白吐出明文,留给读者悬念。
- 同时若读者已经从前文某章看到了这枚镇煞钉(`reader_knows`),而胡不为还蒙在鼓里 → `dramatic_irony(胡不为, 第5章)` 就会**算出**这条反讽点:读者揪心地看着胡不为往墓室里闯。

## 2. 三层机制(逐层拆解 + 源码)

限知由三层叠成:**① 知识边(唯一门控)→ ② 帧投影(把真相裁成「他知道的子集」)→ ③ secret 元数据 + 全读路径打码(防私密明文外泄)**。

### 2.1 第一层:`KnowledgeEdge`——唯一门控

一条 `KnowledgeEdge` 回答:**谁、从哪章起、经何途径、知道哪条命题、信不信、几成把握、到哪章遗忘。** 这是一条显式的、可错的、**非闭包**的信念库(belief base)边。

`scribe3/ontology.py:43`(逐字):

```python
@dataclass
class KnowledgeEdge:
    """knower 知道 proposition(=Fact.id)。无隐式闭包:不自动知道逻辑后果。"""
    knower_id: str                  # role:焦三 / reader / world
    proposition_id: str
    polarity: bool = True           # False=误信(切片暂不用)
    certainty: float = 1.0
    since_chapter: int = 0
    until_chapter: int | None = None
    acquired_via: str = "given"     # saw / told / inferred / given
```

**关键设计点**:
- **唯一门控来源是边,不是 secret**。一条事实是否进某人的帧,只看他有没有指向该命题的、有效的 `KnowledgeEdge`。`secret` 标志不参与投影决策(见 §2.3)。
- **非闭包**:知道 A、知道「A→B」,不自动知道 B。要让角色「推断出 B」,必须显式新建一条 `acquired_via="inferred"` 的边。这避免了「上帝视角的逻辑推理」污染限知。
- **`acquired_via` 途径**:`saw`(目击)/ `told`(被告知)/ `inferred`(推断)/ `given`(设定初值);ingest 另用 `learned`(从定稿抽取的客观新知)、`narrated`(叙述揭示给读者)。

**SurrealDB schema**(`migrations/001_ontology.surql`,逐字):

```surql
DEFINE TABLE IF NOT EXISTS knows TYPE RELATION FROM character TO proposition SCHEMAFULL;
DEFINE FIELD IF NOT EXISTS since_chapter ON knows TYPE int;
DEFINE FIELD IF NOT EXISTS until_chapter ON knows TYPE option<int>;
DEFINE FIELD IF NOT EXISTS polarity      ON knows TYPE bool DEFAULT true;       -- false=误信
DEFINE FIELD IF NOT EXISTS acquired_via  ON knows TYPE string DEFAULT 'given';  -- saw/told/inferred/given
```

补充字段:`certainty`(`036_knows_certainty.surql`,float DEFAULT 1.0)、`ingest_seq`(`012`,供幂等 purge)。

**`reader` 是特殊 knower,走单独表**(`002_reader_frame.surql`):读者不是角色,不走 `character->knows` 边(类型安全),而写 `reader_knows` 表;读者已知**随章单调累积、不遗忘**(只有 `since_chapter`,无 `until`/`polarity`)。

```surql
DEFINE TABLE IF NOT EXISTS reader_knows SCHEMAFULL;
DEFINE FIELD IF NOT EXISTS proposition   ON reader_knows TYPE string;   -- proposition oid
DEFINE FIELD IF NOT EXISTS since_chapter ON reader_knows TYPE int;
```

`store.add_knowledge`(`store.py:279`)据 `knower_id == "reader"` 分流到两张表;`load_knowledge`(`store.py:979`)再把两表拼回统一的 `list[KnowledgeEdge]`(reader 边统一造成 `polarity=True`、`until=None`),供投影使用。

### 2.2 第二层:`project_frame`——帧投影

投影 = `facts_at(chapter)`(双时态投影出本章有效的真相) ∩ 「该 knower 知道的命题 id 集合」。

`scribe3/knowledge.py:24`(逐字):

```python
def project_frame(world: World, knower_id: str, chapter: int, edges=None) -> KnowledgeFrame:
    facts_now = world.facts_at(chapter)
    if knower_id == "world":
        return KnowledgeFrame("world", chapter, list(facts_now))
    if edges is None:
        edges = world.load_knowledge() if hasattr(world, "load_knowledge") else world.knowledge
    known_ids = {
        k.proposition_id for k in edges
        if k.knower_id == knower_id and k.polarity
        and k.since_chapter <= chapter
        and (k.until_chapter is None or k.until_chapter > chapter)
    }
    return KnowledgeFrame(knower_id, chapter,
                          [f for f in facts_now if f.id in known_ids])
```

**逐句解释**:
- `facts_now = world.facts_at(chapter)`——先拿到「第 N 章这个世界客观上为真的事实」(双时态:`valid_from <= ch < valid_to`,见下)。
- `knower == "world"`——全知视角(一致性裁判用),直接返回全部真相,不过滤。
- `known_ids` 过滤四个条件叠加:
  - `k.knower_id == knower_id`——是这个人的边;
  - `k.polarity`——**信念为真**(误信边 polarity=False 被排除,见 §2.4);
  - `k.since_chapter <= chapter`——这章之前(含)已经知道;
  - `k.until_chapter is None or k.until_chapter > chapter`——**还没遗忘**(遗忘机制,见 §2.4)。
- 最后从 `facts_now` 里取 id 命中的事实,组成 `KnowledgeFrame`。

返回结构(`knowledge.py:13`):

```python
@dataclass
class KnowledgeFrame:
    """某 knower 截至某章【知道】的事实集。renderer 只能看见这些。"""
    knower_id: str
    chapter: int
    facts: list[Fact]
    def knows(self, fact_id: str) -> bool:
        return any(f.id == fact_id for f in self.facts)
```

`edges` 参数是去 N+1 优化:`dramatic_irony` 一次 `load_knowledge()` 后把 edges 传进两次投影,避免重复全扫。

**双时态投影 `facts_at`**(`store.py:475`,逐字):

```python
def facts_at(self, chapter: int) -> list[Fact]:
    rows = self._query(
        "SELECT meta::id(id) AS local, entity_id, attribute, value, "
        "valid_from, valid_to, secret, leak_markers FROM proposition "
        "WHERE valid_from <= $ch AND (valid_to = NONE OR valid_to > $ch)", {"ch": chapter})
    return [Fact(f"fact:{r['local']}", r.get("entity_id") or "", r["attribute"], r["value"],
                 r["valid_from"], r.get("valid_to"), r.get("secret", False),
                 r.get("leak_markers", [])) for r in rows]
```

按**故事时间(valid time)**查 `valid_from <= ch < valid_to`(`valid_to=null` 表示惯性持续至今)。这让限知带上故事时间轴:第 3 章投影时,看不到第 8 章才发生的事(未来),也看不到第 2 章已被推翻的旧事实(若 `valid_to` 已置)。

> **注意**:`facts_at` 自己**不做 secret 过滤**——它原样返回带 `secret` 标志的全部事实。屏蔽是上层(`_facts`/`_frame_block`/MCP `_mask_value`)的职责。这是「数据层 vs 边界层」的清晰分工。

### 2.3 第三层:`secret` / `leak_markers`——verify 元数据 + 全读路径打码

**`secret` 不是门控,是元数据**。再强调一次审计的硬约束:

> 限知门控的唯一来源 = `KnowledgeEdge`,不是 `secret`。`secret` 只是 verify 元数据。

`secret` 的真正作用有二:
1. **给 `find_leaks` 判官用**——「这条事实是私密的,如果焦点者不知道却出现在他视角的散文里,就是泄露」。
2. **触发全读路径打码**——任何会把事实 value 吐到「非限知出口」的路径,遇到 `secret=True` 都要把 value 换成占位符,只保留「此处有私密」的标志。

**全读路径打码的三个落点**:

① REST 命题层 `_facts`(`app.py:101`,逐字):

```python
def _facts(fs, reveal_secret: bool = False):
    def _item(f):
        d = {"id": f.id, "entity": f.entity_id, "attribute": f.attribute, "is_secret": f.secret}
        if f.secret and not reveal_secret:
            d["value"] = None   # 私密 value 屏蔽,前端只知"此处有私密"
        else:
            d["value"] = f.value
        return d
    return [_item(f) for f in fs]
```

② REST 实体层 `_mask_field`(`app.py:113`)——把 `character.backstory` / `faction.private_operation` 在 `*_secret=True` 且未解锁时换成 `"🔒 私密"`:

```python
def _mask_field(row: dict, field: str, secret_field: str, reveal: bool) -> dict:
    if row.get(secret_field) and not reveal:
        row = {**row, field: "🔒 私密"}
    return row
```

③ MCP 召回层 `_mask_value`(`mcp.py:95`,逐字)——**默认 `reveal_secret=False`**:

```python
_SECRET_MASK = "🔒 私密"
def _mask_value(value: str, is_secret: bool, reveal_secret: bool) -> str | None:
    if is_secret and not reveal_secret:
        return _SECRET_MASK
    return value
```

所有召回类 MCP 工具(`s3_semantic_recall` / `s3_hybrid_recall` / `s3_graph_recall` / `s3_dramatic_irony`)都带 `reveal_secret: bool = False`,docstring 统一警告(逐字):

> reveal_secret=True 解锁明文——**仅供主编全知联查**,其输出严禁进入限知章续写 prompt。

> **两套占位符,同一意图**:REST `_facts` 用 `None`(给前端判定),实体层与 MCP 用字符串 `"🔒 私密"`(给人/agent 读)。两处都保留 `is_secret` 标志——「读者只知道此处有私密,看不到内容」。

## 3. 戏剧反讽:可计算的反讽点

戏剧反讽(dramatic irony)= **读者知道、而视角角色不知道**。在本系统里这不是写作时拍脑袋判断,而是一条可执行的集合差查询。

`scribe3/knowledge.py:43`(逐字):

```python
def dramatic_irony(world, focalizer: str, chapter: int) -> list[Fact]:
    """戏剧反讽点 = KNOWS(reader,F) ∧ ¬KNOWS(focalizer,F)。
    返回读者已知、而视角角色尚不知的事实(可计算查询,非人脑事后判断)。"""
    edges = world.load_knowledge() if hasattr(world, "load_knowledge") else world.knowledge
    reader = project_frame(world, "reader", chapter, edges=edges)
    foc_ids = {f.id for f in project_frame(world, focalizer, chapter, edges=edges).facts}
    return [f for f in reader.facts if f.id not in foc_ids]
```

**逻辑**:投影读者帧、投影焦点者帧,返回「读者帧里有、焦点者帧里没有」的事实——即 `reader帧 − focalizer帧` 的集合差。

`reader_knows`(读者已知)由 ingest **自动回写**(见 §4.3),所以反讽极不再依赖手动维护。`witnesses_of`(`knowledge.py:52`)负责另一条因果:事件发生时谁在场谁就获知(「看见即知道」),为角色帧自动长出新知。

```python
def witnesses_of(event: Event) -> set[str]:
    """在场者 = 事件的全部参与者(切片:participants 的 entity 值;含 WITNESS 角色槽)。"""
    return {v for v in event.participants.values() if v}
```

**反讽举例(乱世铜炉式)**:第 4 章一场夜戏里,读者透过一个旁观视角看到老乌头偷偷往胡不为的行囊里塞了一枚往生钱(`reader_knows` 自动记下)。第 5 章焦点者切回胡不为,他对此一无所知(没有对应 `KnowledgeEdge`)。此时 `dramatic_irony(胡不为, 5)` 会算出「行囊里有往生钱」这条反讽点——作者据此可以写胡不为浑然不觉地把行囊甩上肩,而读者心头一紧。

> **现状局限**(详见 §7-改进2):反讽点目前**只能被查询**(`/irony` 端点、`s3_dramatic_irony` 工具),系统**不主动把它推到写作 prompt 或编辑面板**,作者得自己想起来去查。这是反讽工艺没有兑现的一环。

## 4. 写作回路里的限知:从「靠模型自觉」到「物理注入」

### 4.1 `_frame_block`——限知帧物理注入续写 prompt(本会话核心修复)

本会话之前,焦点者的限知靠「主编 agent 自己去调 `s3_project_frame` 工具 + 提示它别越界」——典型的**路线 A(靠模型自觉)**。本会话新增 `_frame_block`,把焦点者帧**确定性地拼进续写 instructions**,转为**路线 B(物理注入)**。

`scribe3/app.py:1026`(逐字):

```python
def _frame_block(st, focalizer: str, chapter: int) -> str:
    """限知帧注入块:将 focalizer 截至本章确知的事实喂进 prompt(私密 value 屏蔽)。
    物理隔断:帧外的事情物理上进不了这段 prompt,生成时无从写他不知道的内容。"""
    if not focalizer:
        return ""
    try:
        from scribe3.knowledge import project_frame
        frame = project_frame(st, focalizer, chapter)
        masked = _facts(frame.facts, reveal_secret=False)   # secret value → None
        # 仅保留 value 不为 None 的条目(secret=True 且未解锁的被屏蔽掉)
        visible = [f for f in masked if f.get("value") is not None]
        if not visible:
            return ""
        lines = [
            f"- {f.get('entity') or ''}|{f.get('attribute', '')}|{f.get('value', '')}"
            for f in visible[:40]
        ]
        return (
            f"\n\n## 本章焦点者【此刻确知】的事实(限知硬边界)\n"
            f"以下是 {focalizer} 截至第 {chapter} 章所知的全部。"
            "**只能据这些写他的所见所想,严禁写他不知道的事**:\n"
            + "\n".join(lines)
        )
    except Exception:
        return ""
```

**双重屏障**:
1. **帧外不进**:`project_frame` 已经把焦点者不知道的命题排除——prompt 里根本看不见。
2. **帧内私密也打码**:即便焦点者帧里有一条 `secret=True` 命题(他「心里有数」),`_facts(reveal_secret=False)` 把 value 置 None,`visible` 过滤掉,**明文也不进 prompt**——避免叙述直白吐出他知道的秘密,留住悬念。

**注入点**:`chat_write`(`app.py:1098`)与 `chat_write_post` 按固定顺序拼 instructions:`_voice_anchor_block → _arc_state_block → _motif_block → _frame_block → _recap_block → _current_tail_block`,且开头据 `focalizer` 有无切换「跟随限知视角」vs「作者全知」指令。

### 4.2 `/frame` 与 `/irony` 端点

旧状态:`reader_knows` 写侧只有手动 `s3_record_knowledge` + seed_demo,真机近乎空表,**戏剧反讽大概率恒空**(审计主题 E)。本会话在 ingest 的 `apply_delta`(`ingest.py:54`)里加了自动钩子——**叙述揭示即读者已知**。

learned 分支(`ingest.py:80`,只对新建命题写 reader 边,逐字):

### 4.4 `find_leaks`——事后兜底(第二道 pass)

## 6. 全网搜索:专业限知/反讽写作工艺

> 检索词(英文+中文):`limited third person POV discipline`、`dramatic irony technique fiction`、`unreliable narrator`、`POV discipline novel`、`信息差 悬念 写作`、`读者视角 角色视角 错位`。提炼 5 条权威要点。

**要点 1 · 视角即过滤器(Le Guin 的经典定义)。** 厄休拉·勒古恩对限知的定义:「只有视角人物所**知道、感受、感知、思考、猜测、希望、记得**的东西才能被讲述;读者只能从视角人物观察到的他人行为去**推断**他人的所思所感。」——这正是 `project_frame` 的语义:帧外的他人内心,叙述无权直接进入。([Reedsy](https://reedsy.com/blog/guide/point-of-view/third-person-pov/))

**要点 2 · 一场一视角(POV 纪律的硬规矩)。** 第三人称限知的根本纪律是**每个场景只用一个视角**;视角切换必须落在**场景或章的边界**;在同一场景内跳进另一个角色的脑子叫「**头脑跳跃 head-hopping**」,被绝大多数写作老师明令反对。([Advanced Fiction Writing](https://www.advancedfictionwriting.com/blog/2016/05/23/rules-mixing-viewpoints/)、[Now Novel](https://nownovel.com/third-person-limited-examples/))

**要点 3 · 叙述者即过滤器,「不知道的写不出来」。** 「叙述者作为故事的过滤器——**叙述者不知道、未经历的,就无法呈现给读者**。」不可靠叙述者更进一步:可以「障眼法」地藏线索、把读者引向错误方向。——这与本系统「帧外物理进不了 prompt」同构。([Writers Write](https://www.writerswrite.co.za/nine-types-of-unreliable-narrator/)、[Jericho Writers](https://jerichowriters.com/the-unreliable-narrator/))

**要点 4 · 戏剧反讽 = 读者知道、角色不知道,用来制造悬念。** 「戏剧反讽是观众知道、而作品中角色不知道某事的技法……这个**信息落差**制造张力与悬念,观众揪心地等着角色何时、如何得知真相。」经典例:《罗密欧与朱丽叶》观众知道朱丽叶没死、罗密欧不知道。——本系统 `dramatic_irony` 把这个「落差」变成可计算查询。([MasterClass](https://www.masterclass.com/articles/writing-101-what-is-dramatic-irony-literary-device-definition-examples-and-tips-for-employing-dramatic-irony-in-writing)、[The Novelry](https://www.thenovelry.com/blog/dramatic-irony))

**要点 5 · 信息差的三种类型(中文工艺,悬念引擎)。** 悬念来自「**已知与未知的信息反差**」,信息不对称有三类:**角色之间、角色与读者之间、作者与读者之间**。其中「读者作为上帝视角能预见、而主角茫然不知」即戏剧反讽;关键不只在让读者提前知道,更在**经营读者对「角色得知后如何应对、应对结果如何」的关切**。([知乎·悬念的写法](https://zhuanlan.zhihu.com/p/376183931)、[澎湃·信息差异与叙述张力](https://www.thepaper.cn/newsDetail_forward_22684389))

**提炼成可对照的工艺清单**:
- (a) 视角即过滤器,只写视角人物所知所感,他人内心只能旁观推断;
- (b) 一场一视角,切换只在场景/章边界,禁头脑跳跃;
- (c) 叙述者不知道的写不出来(本系统的物理隔离正是这条的工程化);
- (d) 反讽 = 主动经营读者已知/角色未知的落差,且经营「角色得知后的应对」;
- (e) 信息差分三类(角色间/角色-读者/作者-读者),要分别管理。

## 7. 差距与改进方案(逐条:现状→工艺要求→改法→优先级)

> **总判断**:本系统的**物理隔离**(§1.2 路线 B)是绝大多数写作软件没有的结构性优势,已经做对了工艺要点 (a)(c)。差距集中在「**视角的场景级管理**」「**反讽的主动经营**」「**信息差的精细分级**」三处——即工艺要点 (b)(d)(e) 尚未充分编码。

### 改进 1 · POV 场景级纪律引擎(对应工艺要点 b)· 优先级 P1

- **现状**:`focalizer` 是**章级**参数(`chat_write(focalizer, chapter)`),`save_chapter` 也只存章级 focalizer。系统**没有「场景」这一粒度**,也没有任何机制保证「一场一视角」「切换只在边界」。一章里若主编自己在两个角色脑袋间跳来跳去(head-hopping),系统**完全不会察觉**——`find_leaks` 只查 secret 泄露,不查视角越界。
- **工艺要求**(要点 2):每场景单一视角;切换落在场景/章边界;禁头脑跳跃。
- **具体改法**:
  1. **场景登记**:在 chapter 下引入 `scene` 粒度(或至少「分节标记 + 每节 focalizer」),`save_chapter` 时记录每节的 focalizer 与字符区间。最小实现:解析散文里的分隔符(空行/`* * *`)分节,前端让作者给每节指定 focalizer。
  2. **`_frame_block` 跟随当前节 focalizer**:续写到第 k 节时注入的是**该节** focalizer 的帧,而非全章统一帧——让物理隔离精确到场景。
  3. **头脑跳跃检测器**:新增 `verify.find_head_hops(prose, scene_focalizers)`——在单一 focalizer 的节里,检测对**其他角色内心动词**(「他心想/她暗忖/X 觉得/X 知道」)的直接陈述,命中即报「疑似头脑跳跃」。作为 `find_leaks` 的姊妹判官接进 `/check` 与存稿后扫描。
  4. **切换合法性校验**:focalizer 变更只允许发生在节边界;节内变更直接报错。
- **杠杆**:这是把「限知」从「知道什么」扩展到「谁在看」的维度,直接决定长篇的视角秩序;也是当前**唯一完全没有结构支撑**的核心工艺。

### 改进 2 · 反讽点的作者驾驶舱(对应工艺要点 d)· 优先级 P1

- **现状**:`dramatic_irony` 能算,但**只能被动查询**(`/irony` 端点 / `s3_dramatic_irony` 工具)。写作 prompt **不注入**反讽点,编辑面板**不主动呈现**,作者得自己想起来去查。工艺要点 4/5 强调反讽要「主动经营」,系统目前停在「能查不会用」。
- **工艺要求**(要点 4、5d):主动经营读者已知/角色未知的落差,并经营「角色得知后的应对」。
- **具体改法**:
  1. **反讽块注入续写 prompt**:新增 `_irony_block(st, focalizer, chapter)`,与 `_frame_block` 同级注入——「**读者已经知道、但 {focalizer} 此刻不知道**的事(可用于制造戏剧反讽:让他在无知中行动,读者揪心)」。注意:这里**只告诉模型「读者知道 X」**,不让焦点者「知道」X(否则破坏限知)——给作者一个「明知故纵」的开关。
  2. **反讽驾驶舱(前端)**:在写作视图侧栏常驻 `/irony` 结果,每条反讽点标「读者从第几章起知道」「焦点者预计第几章得知(若已规划)」,让作者一眼看到「现在有几颗雷埋着」。
  3. **反讽兑现追踪**:复用 promise/payoff 机制,把「反讽点」登记为一种「待引爆的信息差」,到期未引爆(焦点者迟迟没得知、读者悬念悬太久)给提醒,呼应工艺要点「经营角色得知后的应对」。
- **杠杆**:把系统**已经算得出**的反讽能力,从「数据库里躺着」变成「写作时的主动武器」——投入小、对「写出乱世铜炉级悬念」收益大。

### 改进 3 · 私密分级 + 误信生产路径(对应工艺要点 e)· 优先级 P1/P2

- **现状**:① 私密只有**两档**——`secret=True`(完全屏蔽 → `🔒 私密`)或 `False`(完全明文)。没有「半透露」——比如「读者察觉到不对劲,但还没拼出全貌」。② 误信 `polarity=False` **读端就绪、写端缺位**(§5):投影会排除误信边,但没有任何路径写得出一条假情报边,「角色被误导/听信谣言」这一信息差类型**做不出来**。
- **工艺要求**(要点 5e):信息差分三类(角色间/角色-读者/作者-读者),要分别精细管理;不可靠叙述者要能「藏线索、引向错误方向」。
- **具体改法**:
  1. **私密三态化**:把 `secret: bool` 升级为 `secrecy: enum{open, hinted, sealed}`——
     - `sealed`(=今 `secret=True`):全屏蔽;
     - `hinted`(半透露):value 屏蔽,但允许其 `leak_markers` 作为「线索」出现在散文里(对应「藏线索」)。`_frame_block`/`_mask_value` 对 hinted 输出「此处有未明说的端倪:{leak_markers}」而非完全锁死;
     - `open`(=今 `secret=False`):明文。
     向后兼容:`hinted` 缺省按 `sealed` 处理。
  2. **误信写入口**:补 `store.add_misbelief(knower, proposition_id, since_chapter)`(写 `polarity=False` 边)+ REST `/knowledge/misbelieve` + MCP `s3_record_misbelief`(经 elicitation 待批)。这样「角色 A 听信了一条假情报」可被表达:他的帧里有这条命题但 polarity=False,`project_frame` 排除真相、可另投影一个「他以为为真」的错觉帧供写他的误判行动。
  3. **错觉帧投影(进阶)**:新增 `project_belief_frame(focalizer, chapter)`——返回「焦点者**以为**为真的世界」(含 polarity=False 的命题当真处理),与 `project_frame`(他**确知**的真相)区分。写「被骗的角色照着假情报行动」时注入错觉帧。这是不可靠叙述/误信工艺的工程化终点。
- **杠杆**:补全三类信息差里「角色被误导」这一类,以及私密的「半透露」灰度——这是「悬疑/权谋」题材(乱世铜炉式)真正吃重的能力。改进 3 的 (1)(2) 是 P1,(3) 错觉帧是 P2(依赖 (2))。

### 改进 4 · 限知帧的信息量与裁剪(对应工艺要点 a)· 优先级 P2

- **现状**:`_frame_block` 取 `visible[:40]` 条,格式 `主体|属性|值`——**无优先级排序的硬截断**。第 40 章焦点者可能确知几百条事实,前 40 条是哪些全凭 `facts_at` 的返回顺序(近似按命题创建序),**本章最相关的事实可能被截在 40 条之外**。且格式扁平,模型拿到一堆 `A|B|C` 难分主次。
- **工艺要求**(要点 1):限知不是「把他知道的全倒出来」,而是「**此刻此景他会注意到、对他有意义**的东西」(Le Guin:「染上只有他会观察到、对他有意义的色彩」)。
- **具体改法**:
  1. **相关性排序再截断**:用本章 query/场景上下文对焦点者帧做一次语义排序(复用 `semantic_recall` 的向量能力,但**限定在焦点者帧内**),取 top-K 而非创建序前 40。
  2. **新近性加权**:`since_chapter` 越接近当前章的知识越靠前(刚得知的事更鲜活、更可能进入当下意识)。
  3. **分层呈现**:把帧分「核心(本章直接相关)/ 背景(久远设定)」两层注入,让模型分清主次。
- **杠杆**:中等。长篇后期帧膨胀时尤其重要,否则限知帧从「精确的当下意识」退化成「一锅设定乱炖」。

### 改进 5 · `certainty` 接入投影与叙述语气(对应工艺要点 a)· 优先级 P3

- **现状**:`certainty` 持久化就绪,但 `project_frame` 不读它——「确信」和「半信半疑」在帧里一视同仁。Le Guin 的定义里「**猜测、希望**」与「知道」是分层的。
- **改法**:`project_frame` 增可选 `min_certainty` 阈值;`_frame_block` 对低 certainty 的条目标注「(他并不确定)」,引导叙述用「也许/像是/他猜」之类的不确定语气。优先级 P3(锦上添花)。

### 改进汇总优先级表

| 改进 | 工艺要点 | 优先级 | 一句话 |
|---|---|---|---|
| 1 POV 场景级纪律引擎 | b 一场一视角 | **P1** | 唯一完全没结构支撑的核心工艺;补场景粒度 + 头脑跳跃检测 |
| 2 反讽点作者驾驶舱 | d 主动经营反讽 | **P1** | 已能算的反讽从「躺着」变「主动武器」;投入小收益大 |
| 3 私密分级 + 误信写入口 | e 信息差三类 | **P1**/P2 | 补「半透露」灰度 + 「角色被误导」这一类信息差 |
| 4 帧的信息量与裁剪 | a 此刻有意义的 | P2 | 相关性排序替代硬截断,防长篇后期帧膨胀 |
| 5 certainty 接入语气 | a 猜测/希望分层 | P3 | 「半信半疑」用不确定语气叙述 |

```
    secret/leak_markers 随 Fact 透传(store 层不打码)

[3] project_frame 投影 (knowledge.py:24)
    facts_at(chapter) ∩ load_knowledge() 里 (knower==focalizer ∧ polarity ∧ since≤ch<until) 的命题
    → KnowledgeFrame(focalizer, chapter, facts)
    反讽极:dramatic_irony (knowledge.py:43) = reader帧 − focalizer帧

[4] _frame_block 注入 prompt (app.py:1026)
    project_frame → _facts(reveal_secret=False) 打掉 secret value
    → 过滤 value!=None → 格式化 "- 主体|属性|值" ×≤40
    → "## 本章焦点者【此刻确知】的事实(限知硬边界)" 块
    注入点:chat_write (app.py:1098) / chat_write_post
    (主防线:帧外的事物理上进不了这段 prompt)

[5] find_leaks 兜底 (verify.py)
    project_frame → frame;遍历 facts_at(chapter):
    secret 且 ¬frame.knows(f.id) 的命题,其 leak_markers/value 出现在散文里 = Leak
    入口:/save-chapter、/check、MCP s3_find_leaks
    (第二道 POV 修订 pass,判官,不是主防线)
```

**一句话总纲**:`KnowledgeEdge` 是唯一门控,`project_frame` 把真相裁成「他知道的子集」,`_frame_block` 把这个子集物理注入 prompt(帧外进不来、帧内私密打码),`find_leaks` 事后兜底。`secret` 自始至终只是元数据,不参与门控决策。
