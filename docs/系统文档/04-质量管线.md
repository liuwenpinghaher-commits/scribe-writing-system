# scribe3 写作质量管线(Writing Quality Pipeline)

> 本文档说明 scribe3 如何把"一段刚生成的中文小说正文"判定为合格或不合格,以及不合格时如何兜底修复。
> 读代码摸现状 → 对照专业自我修改工艺 → 给出差距与改进。日期 2026-06-28。
>
> 涉及文件:
> 后端 `scribe3/critique.py`(纯函数确定性 QC + LLM 判官 prompt/parse)、`scribe3/verify.py`(限知泄露 find_leaks)、`scribe3/store.py`(check_ooc / validate_setting / motif_terms / recent_proses)、`scribe3/soak.py`(浸泡)、`scribe3/craft.py`(写作引擎层)、`scribe3/app.py`(`/quality` `/check` `/post-check` `/dedup-chapter` `/discipline` `_avoid_directive`)。
> 前端 `scribe3/web/src/views/InsightView.jsx`(质量仪表盘)、`scribe3/web/src/WriteLayout.jsx`(护栏芯片 + 生成后体检 + "让主编修这章")。

## 0. 大纲

1. 质量哲学:为什么是"生成时预防 + 生成后扫描兜底"两层,而非"靠 prompt 让模型自律"
2. 五类确定性 QC 详解(repetition / structural / purple / ai_tics / oversaturation)+ 对照表 + 检测示例
3. 跨章复读专项:`distinctive_phrases` → `_avoid_directive`(生成时防)+ `find_cross_chapter_repetitions` / `rewrite_cross_repetitions`(生成后治)
4. 语义判官 `discipline`:确定性正则抓不到的语义病(双高潮/声音崩/解说倾泻/知识泄露),fail-open
5. 限知穿帮 `find_leaks` + `leak_markers`;OOC `check_ooc`(弱);设定矛盾 `validate_setting`
6. 生成后体检闭环:`/post-check` 串五类 + leaks + discipline + setting;前端"立即体检 / 让主编修这章";`/quality` 全量计数
7. 本会话修复记录
8. 全网工艺综述(专业自我修改清单 / show-don't-tell / 去 AI 腔)
9. 差距与改进方案(逐条:现状→工艺→改法→优先级)

## 1. 质量哲学:两层防线

系统的核心信念写在 `critique.py` 文件头与多处 docstring 里,一句话:

> **"prompt 规则治不了已生成文本,确定性扫描 + 定向删才拦得住。"**

这句话是整条质量管线的设计公理。展开为两层:

| 层 | 时机 | 手段 | 代表实现 | 性质 |
|---|---|---|---|---|
| **L1 生成时预防(防患)** | 写 prompt 时 | 把"别犯的错"喂进 instructions | `_avoid_directive`(防跨章复读)、`craft.build_craft_block`(8 条写作引擎)、`_voice_anchor_block`(声音锚)、`soak`(浸泡进角色)、`_frame_block`(限知帧) | 概率性。模型可能照做,也可能忘 |
| **L2 生成后扫描(兜底)** | 拿到正文后 | 确定性扫描 + 定向删/改 | `quality_flags`(五类)、`find_leaks`、`discipline_truncate`、`validate_setting`、`rewrite_cross_repetitions` | 确定性(正则)或半确定(LLM 判官)。**可度量、可拦截** |

**为什么不能只靠 L1?** 因为 prompt 是"请你不要……"式的软约束:一次生成里塞进上百条禁用词,模型记不住、也会在长程生成中漂移。系统的实测教训(见 `_avoid_directive` docstring):10 章里共 **106 处跨章逐字搬运**,而逐章 QC 一处也查不到——单遍长程生成会自然复用自己偏爱的措辞,这是结构性病,光靠"提醒它别重复"无效。

**为什么 L2 是可靠层?** 因为它是事后对**已生成文本**的确定性度量。`find_repetitions` 一定能数出复读;`find_leaks` 一定能扫出帧外破绽词;不依赖模型"这次有没有自律"。代价是它只在文本已经写出来之后才发力,所以需要"扫描 → 定向删/改/重生"的闭环把问题清掉。

**L1 与 L2 的协同**(关键):L2 的扫描产物会反哺成 L1 的预防物料。最典型的是 `distinctive_phrases`——它从已写章里抽出"独特措辞短语",`_avoid_directive` 把这些喂进下一章的系统指令,让模型在**生成时**就避开。这就是把"重复"从"事后逐章删"升级成"跨章可度量、可在源头预防"的闭环。

## 2. 五类确定性 QC 详解

入口是 `critique.quality_flags(text, extra_patterns)`,聚合五个纯函数,返回 `{repetition, structural, purple, ai_tics, oversaturation}`,每项是命中列表。这五类全部是**纯函数**(无 DB、无网络),所以快、可离线单测、可在编辑器停笔时实时跑(前端"护栏芯片")。

### 五类 QC 对照表

| 类别 | 函数 | 病象 | 怎么算(阈值) | 触发示例 |
|---|---|---|---|---|
| **repetition** | `find_repetitions` | 单章内逐字复读(同一长串反复出现) | 去空白后,长度 ≥8 字、出现 ≥3 次的子串;去重叠保留最长代表;取前 10 | "他握紧了腰间的刀"在一章里出现 4 次 |
| **structural** | `find_structural_repeats` | 排比开头 + 单字/极短断句滥用 | 同 3 字开头 ≥4 句 = 排比;长度 1–2 字的含中文断句 >4 个 = 短句滥用 | 连续 5 句以"他知道"开头;"风。雨。血。火。刀。"五个单字句 |
| **purple** | `find_purple_prose` | 升华句/抒情主题直陈/替读者下结论 | 命中"紫色种子正则"(`LUANSHI_PURPLE_SEEDS`)+ 题材注入 `extra_patterns` | "从那一刻起,他知道再也回不去了";"原来从一开始就没得选" |
| **ai_tics** | `find_ai_tics` | 破折号泛滥 + "不是 A——是 B"伪深刻 | 破折号密度 >2/千字 = em_dash;命中 `不是.{1,15}——是` = not_a_but_b | 全章 12 个"——";"那不是恐惧——是认命" |
| **oversaturation** | `find_oversaturation` | 过度解释 / 情绪命名 / 比喻过密(缺留白) | 每千字:解释词 >3、情绪标签 >5、比喻 >6 | "这意味着""也就是说"密集;"愤怒""绝望"直接命名情绪;"仿佛/如同/像……一样"刷屏 |

> 注:这五类的 `len()` 之和就是仪表盘里某章的 `qc_issues`(确定性 QC 问题数)。

### 逐类解释 + 算法细节

**① repetition(单章内逐字复读)** — `find_repetitions(text, n=8, min_count=3, top=10)`
去掉所有空白后,对每个长度 8 的滑动窗口计数(`Counter`),保留出现 ≥3 次的;排除纯标点串(`_PUNCT_ONLY`);再做"去重叠"——长串优先,被它包含的短串丢弃,只留最长代表(避免相邻 n-gram 刷屏)。这是单遍长程生成最典型的偷懒:同一动作句反复打。

**② structural(句式结构病)** — `find_structural_repeats`
字面 n-gram 查不到结构病,所以单独算。两路:
- 排比开头:取每句前 3 字做 `Counter`,同开头 ≥`min_anaphora`(默认 4)句即报 `anaphora`。
- 单字/极短断句:长度 1–2 且含中文的句子 >`max_short`(默认 4)即报 `short`。短句本身不是病,**滥用**才是(AI 爱用"风。雨。刀。"制造廉价节奏感)。

**③ purple(紫色文风/升华句)** — `find_purple_prose`
冷笔大忌是"替读者下结论、硬塞命运隐喻"。用一组题材正则种子 `LUANSHI_PURPLE_SEEDS` 逐句扫,例如:
```python
r"原来[^。！？\n]{0,30}(就|早就|从一开始|没的选|没得选)",   # "原来从一开始就没得选"
r"从[^,，。\n]{1,18}那一刻起",                              # "从他转身那一刻起"
r"(有些|有的)[^。！？\n,，]{0,14}(就再也|再也)[^。！？\n]{0,14}",  # "有些人再也回不来了"
```
通用正则跨题材;题材专属升华句经 `extra_patterns`(来自本书 `craft_rule.purple_regex`)叠加注入。

**④ ai_tics(AI 腔硬检)** — `find_ai_tics`
两个全网公认的 LLM 指纹:
- `em_dash`:破折号"——"密度 >2/千字。破折号本身无罪,但 LLM 在该用逗号/句号/重组句子的地方滥用它(见第 8 节 The Ringer / Rolling Stone 的讨论)。
- `not_a_but_b`:正则 `不是.{1,15}——是`,对应英文臭名昭著的 "It's not X, it's Y"——**模仿洞察的形状,却不含洞察**(见第 8 节 Ruben Hassid)。

**⑤ oversaturation(过度饱和/缺留白)** — `find_oversaturation`
留白引擎(`craft.ENGINES["restraint"]`)的确定性兜底。按每千字密度算三个指标,超保守阈值即报(宁可漏不滥杀):
- `explain`(>3/千字):解释词表 `这意味着/也就是说/换句话说/正是因为/说明了/其实是/无非是/不过是/正因如此`——把读者能自己推的话说破。
- `emo_label`(>5/千字):情绪标签表 `愤怒/悲伤/恐惧/绝望/痛苦/欣喜…`——直接命名情绪,违反 craft 的"身体先行,叙述者不命名情感"。
- `simile`(>6/千字):明确比喻词 `仿佛/如同/宛如/好似/犹如` + 精确模式 `像[^,。]{1,10}(一样|般|似的|似地)`(避开"好像/图像"的误命中)。比喻过密即装饰泛滥。

## 3. 跨章复读专项(L2 扫描 ⇄ L1 预防的闭环)

逐章 `find_repetitions` 只看单章内部,**完全查不到跨章逐字搬运**(模型在第 N 章复用第 3 章用过的句子)。这是单遍长程生成的命门,系统为它建了完整闭环:

```
                  ┌─────────────────── L1 生成时预防 ───────────────────┐
 已写章正文 ──► distinctive_phrases(抽独特短语) ──► _avoid_directive(拼成"严禁逐字复用"硬约束注入系统指令)
                                                                          │
                                                                          ▼ 模型据此避开
                                                                      新章正文
                  ┌─────────────────── L2 生成后兜底 ───────────────────┐
 新章 + 前文 ──► find_cross_chapter_repetitions(逐字 ≥8 比对,揪出漏网) ──► rewrite_cross_repetitions(逐句定向 LLM 改写,/dedup-chapter)
```

关键设计点:

- **母题白名单**(`_is_allowed` + `store.motif_terms()`):乱世铜炉式母题(奈何谷/镇煞钉/大元炼真经/三百六十…)本应跨章复现,**不算懒惰复读**。这些词进白名单,既不进 avoid 清单(否则逼模型回避母题、伤质感),也不计入跨章复读指标。让指标只反映"动作句/句式的偷懒重打"。
- **`_avoid_directive`**(app.py):取前 `lookback` 章(注释提到调到 8 以覆盖全书前文)的独特短语,拼成 `【防跨章复读·硬约束】前文已用过下列 ≥8 字措辞……本章严禁逐字复用——同一个意思换感官/换喻体/换节奏另写`,贴到 instructions 末尾。
- **`rewrite_cross_repetitions`**(critique.py):确定性定位含跨章复读的句子 → 逐句调 `complete_fn` 定向改写(保意/保限知/保语气,只换措辞)→ 字符串替换回原文。比"prompt 预防"可靠:不依赖模型记住上百条禁用词,只精准改犯规句。`/dedup-chapter` 是其 REST 入口,**幂等**(无复读则不调 LLM 原样返回),实测最严重章 30→8(↓73%)。

## 4. 语义判官 discipline(确定性盲区)

正则只能抓**字面**病。语义级违规——双高潮、声音崩、解说倾泻、知识泄露——正则抓不到,交给 LLM 判官。实现在 `critique.build_discipline_prompt` / `parse_discipline` / `discipline_truncate`,REST 入口 `/discipline`,并接进 `/post-check`。

判官判四类违规(`build_discipline_prompt`):

| 违规 | 含义 |
|---|---|
| `double_climax` | 出现第二场打斗/救援/开挂,或偷跑了本不属于本章的后续剧情、凭空发明新登场角色 |
| `voice_collapse` | terse 角色(声细如蚊/半截就断)崩成大段流畅独白、系统结算音、或与主角同温 |
| `exposition_dump` | 大段身世/前史/规则的集中倾泻(本该零星渗出) |
| `knowledge_leak` | 某角色说出/表现出知晓【其视角不可能知道】的他人私密(prompt 里带各角色"截至本章已知"清单作判定依据) |

判定流程(`discipline_truncate`):
1. LLM 返回一行 JSON:`{"ok": bool, "violations": [...], "cut_after": "复发前最后一句的原文逐字"}`。
2. 若违规且 `cut_after` 命中正文:**复发点靠后**(截掉后仍留 ≥40% 正文)则截到复发点;**复发太早**(截掉后不足 40%)则只标记不砍(整章交回重生)。

**fail-open(关键且是改进点)**:`parse_discipline` 解析失败时返回 `{"ok": True}`——**默认放行**。理由是判官是兜底,不该因为一次 LLM 抽风或 JSON 截断就阻断交付。代价见第 9 节:静默放行无任何告警,运维看不见"判官今天有多少次没判成"。`/post-check` 里 discipline 抛异常时会置 `degraded=True` 回传,算是部分弥补,但 parse 层 fail-open 本身静默。

## 5. 保真三件套:限知泄露 / OOC / 设定矛盾

### 5.1 限知泄露 find_leaks + leak_markers(强)

`verify.find_leaks(prose, world, focalizer, chapter)` 是第二道 POV 修订 pass。限知渲染已在生成前结构性防住泄露,这是事后兜底:

```python
frame = project_frame(world, focalizer, chapter)      # focalizer 此刻的知识帧
for f in world.facts_at(chapter):
    if not f.secret or frame.knows(f.id):  continue    # 非私密 / focalizer 知道的 → 跳过
    for m in (f.leak_markers or [f.value]):            # 破绽词:命中即泄露
        if m and m in prose:
            leaks.append(Leak(f.id, m, f.entity_id)); break
```

`leak_markers` 是每条私密命题预先标注的"破绽词"列表(没有就退化用 `f.value` 本身)。例如某角色的私密身份"前朝余孽",破绽词可能是 `["龙纹玉牌","旧主","复国"]`——focalizer 不该知道这身份,正文里冒出任一词即穿帮。这是**确定性、可靠**的一层。

### 5.2 OOC check_ooc(弱)

`store.check_ooc(character_id, dialogue)` 对照角色 `voice_profile.ooc_signals` 扫描对话。但实现是**硬编码关键词分支**:
```python
if "长句" in desc:      # 连续 >3 句 >25 字 → 报
elif "感叹号" in desc:  # ！ >2 次 → 报
elif "情感词"/"我爱你"… in desc:  # 命中 ["很高兴","我爱你","感谢","很开心","太好了"] → 报
```
问题:它只认 voice_profile 里描述文本**字面包含**"长句/感叹号/情感词"这几个锚词,且情感词表是写死的 5 个。换个角色、换种声音病就完全失灵。`validate_setting` 内部又通过"含角色名的句子拼成 dialogue"调它一次,粒度也粗。**这是公认最该改的弱项**(见第 9 节)。

### 5.3 设定矛盾 validate_setting

`store.validate_setting(chapter, prose)` 比对正文与设定圣经,产出冲突线索,覆盖三类:
1. **物件状态矛盾**:`symbolic_state` 为 `lost/destroyed` 的物品仍在正文出现使用 → `item_state_inconsistency`(high)。
2. **OOC**:对每个有 voice_profile 的角色,取含其名的句子调 `check_ooc` → `personality_ooc`(继承上面的弱)。
3. **世界规则违反**:遍历 `list_world_rules` 的 `limitations`,关键词前 4 字出现在正文即报(很粗,易误报/漏报)。

## 6. 生成后体检闭环(本会话新加)

### 6.1 REST 端点矩阵

| 端点 | 落库 | 内容 | 用途 |
|---|---|---|---|
| `GET /quality` | 否 | 全书每章:字数 + 五类 QC 分项(`qc_breakdown`)+ `qc_issues` 合计 + 因果违规 + 伏笔状态 | 仪表盘 InsightView |
| `POST /check` | 否 | 五类 QC + leaks(轻检查,停笔静默刷新) | WriteLayout 护栏芯片 |
| `POST /post-check` | 否 | 五类 QC(`qc_breakdown`+total)+ leaks + **discipline 判官** + **validate_setting** | "立即体检"全量 |
| `POST /dedup-chapter` | **是** | 跨章复读定向改写并存回 | "去复读"治层 |
| `GET /discipline` | 否 | 单章语义判官 | 单独跑判官 |
| `POST /save-chapter` | 是 | 存章 + 软校验(五类 + 跨章复读 + leaks),回写走独立 `/ingest` | 存章 |

`/post-check`(app.py:1371)是体检主入口,串四件:① 五类确定性 QC;② 限知泄露(有 focalizer 才跑);③ LLM 语义纪律判(fail-open,异常置 `degraded=True`);④ 设定校验(fail-soft)。返回 `{quality:{…,total}, leaks, discipline, degraded, setting}`,**不落库**。

### 6.2 前端闭环(WriteLayout.jsx)

- **护栏芯片**(line 228+):编辑器停笔时调 `/check`,实时显示"复读 N / 排比 N / 升华 N / AI腔 N / 过饱和 N"+ 限知泄露;有泄露 danger、有 QC warn、干净 ok。
- **生成后体检(全量)**(line 412+):"立即体检"按钮调 `/post-check`,展示五类 total + leaks + discipline.violations。
- **诊断 → 治疗(半自动)**:"让主编修这章"按钮(line 463)把体检结果拼成一段 `seedQuote`:
  ```
  本章体检发现:
  复读 3 处 / AI腔 2 处 / 过饱和 1 处
  限知泄露 2 处:龙纹玉牌、复国
  纪律违规:exposition_dump
  请据此修订本章。
  ```
  注入 WriteChat,**由人点击、主编据此重写**。这是当前"诊断→治疗"闭环的形态:诊断自动、治疗触发是人工一键、实际改写是主编(LLM)。

### 6.3 仪表盘 InsightView.jsx

读 `/quality`,展示规模/伏笔/超期/质检问题四个 Metric + 各章字数面积图 + 各章 QC+因果堆叠柱 + "弱章诊断"列表(按 `qc_issues+causal` 排序取前 8)。**只读诊断,无治疗入口**——治疗在 WriteLayout。

## 8. 全网工艺综述(专业自我修改的事实基线)

检索英文 + 中文权威来源,提炼五条与本系统直接对照的工艺要点:

### 要点 1:过滤词(filter words)是 show-don't-tell 的头号敌人
专业自编清单的第一刀就是删过滤词:`saw / heard / felt / knew / noticed / realized / thought / looked`(中文对应:看见/听见/感到/知道/注意到/意识到/觉得)。它们在角色与体验之间插一道滤镜,把"经历"降级成"被告知"。规则:能删就删,除非角色的感知本身不可靠才保留。这正是 show-don't-tell 的可操作化——**不是抽象口号,而是一张可正则扫描的词表**。(Reedsy / Jericho Writers / writersinthestormblog)

### 要点 2:副词与"to be"弱动词
搜 `ly`(中文:"地"+程度副词),把 "walked quickly" 换成 "sprinted/darted/shuffled" 这种强动词。弱动词+副词 = 偷懒信号。同时清理 `that/just/even/seem/very/really`(中文冗词:就/只是/甚至/似乎/非常/真的)与 "to be" 被动结构。(book-editing.com / AutoCrit / The Writer)

### 要点 3:紫色文风 = 修饰语无目的堆叠 + 叹号/最高级当拐杖
形容词/副词必须服务于具体,否则是把弱句撑起来的拐杖。"Kill your darlings":你最得意的华丽句往往最该砍——它打断故事流。做法:把 darlings 剪进单独文件而非直接删,降低心理阻力。(Reedsy kill-your-darlings / Writer's Helping Writers)

### 要点 4:AI 腔有可枚举的指纹
- "It's not X, it's Y"("不是 A,是 B"):模仿洞察的形状却无洞察,维基编辑常据此判 AI。(Ruben Hassid)
- 破折号(em dash)异常高频:某些模型在该用逗号/句号/重组的地方滥用——但破折号本身**不是**可靠的单一判据,需结合密度。(The Ringer / Rolling Stone)
- 中文专项:去 AI 腔要拆掉"过度承接、工程师腔、小红书腔、翻译腔、无源权威铺垫";翻译腔判据是"译文生硬、不协调"。开源 skill `shuorenhua`(说人话)总结为:保事实、分场景、清单式"建议删除"。(huxiu / 维基百科:翻译腔 / GitHub shuorenhua)

### 要点 5:节奏 = 句长变化
句长是节奏最基本的杠杆。句长全一致 → 大脑识别出模式 → 走神。短句出拳(冲击/紧迫),长句铺陈(氛围/沉思),中句是主力。技法:长复句后接一记短句,"像判决一样落地"。分析法:画"节奏图"——把一章句长/段落张弛画成曲线,标注动作/对话/描写。**句长方差是可量化指标。**(Novela / River / Fiveable)

## 9. 差距与改进方案

总评:**"确定性扫描 + LLM 语义判官"是正确架构**——它兑现了"prompt 治不了已生成文本"的公理,且已把 show-don't-tell 的一部分(情绪命名、比喻过密、升华句、AI 腔指纹)落成了可扫描指标,这一步已领先多数 AI 写作工具。差距在覆盖面、闭环自动化与可观测性。

下表每条:现状 → 工艺(第 8 节出处)→ 具体改法 → 优先级。

### 改进 1 ★ 过滤词 / show-don't-tell 专门检测(P0,最高)
- **现状**:五类 QC 间接覆盖了 show-don't-tell 的两个侧面(`oversaturation` 的 emo_label 抓情绪命名、simile 抓比喻过密),但**没有过滤词检测**——而过滤词是专业清单的头号刀(要点 1)。
- **工艺**:`saw/heard/felt/knew/noticed/realized/thought`,中文"看见/听见/感到/知道/注意到/意识到/觉得"——在体验前插滤镜,把 show 降级成 tell。
- **改法**:`critique.py` 新增 `find_filter_words(text, per_k=4.0)`,词表 `["看见","看到","听见","听到","感到","感觉到","注意到","意识到","觉得","知道","发现自己","他想"]`,按每千字密度报(留白:对话/不可靠叙述者可放宽)。聚合进 `quality_flags` 作第六类 `filter_words`;前端护栏芯片加"滤镜 N";`/quality` `qc_breakdown` 同步。配套定向改写器(类比 `rewrite_cross_repetitions`):命中句调 LLM"删过滤词、直写体验"。
- **优先级:P0**——单一最高 ROI,纯函数、可单测、直接提升沉浸感,且是全网公认第一刀。

### 改进 2 ★ check_ooc 并入 discipline 判官(P0)
- **现状**:`check_ooc` 是硬编码关键词分支(只认"长句/感叹号/情感词"三锚 + 写死 5 个情感词),换角色就失灵;`validate_setting` 还以"含角色名句子"粗粒度喂它。审计已列为 W2#4。
- **工艺**:声音一致性是语义判断,不是字面匹配——正则抓不到"这句话不像这个角色"。
- **改法**:把 OOC 判定从字面规则迁到 `discipline` 判官:`build_discipline_prompt` 已有 `voice_collapse` 维度,扩展为"对照各角色 voice_profile.style_summary 判断本章对白是否走音",把 voice_profile 摘要喂进 prompt。保留 `check_ooc` 作纯函数快筛(停笔实时),但**权威判定走判官**;`validate_setting` 的 OOC 分支改为可选/降级。
- **优先级:P0**——现有实现近乎无效,且判官框架已就位,边际成本低。

### 改进 3 ★ 判官 fail-open 静默 → 可观测告警(P1)
- **现状**:`parse_discipline` / `parse_knowledge_delta` / `parse_voice_profile_from_fold` 解析失败全部 fail-open/fail-soft 且仅 `_log.warning`,运维无聚合指标。`/post-check` 的 `degraded` 只覆盖 discipline 抛异常、不覆盖 parse 静默放行。
- **工艺**:兜底层必须可观测——否则"判官今天放行了多少没判成的章"无人知晓,质量闸名存实亡。
- **改法**:(a) `parse_discipline` 在 fail-open 时多回一个 `parse_failed: True` 字段;`discipline_truncate` 透传;`/post-check` 把它并进 `degraded`/新增 `judge_degraded` 计数回前端。(b) 前端"立即体检"在 `degraded` 时显示"判官未判成(已放行,建议复检)"黄条,而非伪绿。(c) 可选:judge 失败计数进 `/quality` 聚合。
- **优先级:P1**——不改判定逻辑,只补可观测性,防"假绿"。

### 改进 4 副词 / 冗词 / 陈词检测(P1)
- **现状**:无副词、无冗词("就/只是/甚至/似乎/非常/真的")、无陈词滥调检测。
- **工艺**:要点 2 + 要点 3——搜"ly"/"地"、清 filler words、cliché finder。
- **改法**:`critique.py` 新增 `find_weak_words(text)`:① 冗词表密度;② "形容词/程度副词 + 地"模式(`[一-鿿]{1,3}地(?=[一-鿿])`)密度;③ 陈词短语表(可 per-work 配 `craft_rule.cliche_phrases`,如"心如刀绞/不寒而栗/不由自主")。报为新类或并进 oversaturation 的"装饰"维度。**保守阈值,宁漏不滥**(与 oversaturation 同哲学)。
- **优先级:P1**——成熟工艺、纯函数,但需 per-work 陈词表才不误杀,故次于过滤词。

### 改进 5 节奏 / 句长变化分析(P2)
- **现状**:`structural` 只抓"排比开头"和"极短断句滥用"两个极端,**没有句长方差/节奏曲线**。
- **工艺**:要点 5——句长方差是可量化指标;句长全一致→读者走神。
- **改法**:新增 `analyze_rhythm(text)` 返回 `{mean_len, std_len, max_run_same_band}`(把句子按短/中/长分档,检测"连续 N 句同档"=节奏呆板)。InsightView 加一张"各章句长方差"折线,低方差章标黄。这是诊断指标(供主编参考),不一定自动治。
- **优先级:P2**——锦上添花,且"低方差=差"在某些克制段落是特意为之,需谨慎,先做可视化不做硬闸。

### 改进 6 诊断 → 治疗闭环自动化(P2)
- **现状**:`/post-check` 诊断自动,但治疗是"人点'让主编修这章'→注入 seedQuote→主编重写";跨章复读有 `/dedup-chapter` 全自动治,其余类无定向治疗器。
- **工艺**:专业修订是"扫描清单→逐项定向修",非整章重写(整章重写易引入新问题)。
- **改法**:按类配定向改写器,复用 `rewrite_cross_repetitions` 范式:purple 句→"删升华、留冷笔"、ai_tics 句→"拆破折号/重写不是A是B"、filter_words 句→"删滤镜直写"。`/post-check` 可选 `auto_fix=true` 串这些定向器(类比 dedup 的幂等)。仪表盘 InsightView 弱章行加"一键修"直达。
- **优先级:P2**——价值高但工程量大,依赖改进 1/4 先把检测器铺齐。

### 改进优先级汇总

| 优先级 | 改进 | 一句话 |
|---|---|---|
| **P0** | 1 过滤词/show-don't-tell 检测 | 补上专业清单第一刀,纯函数高 ROI |
| **P0** | 2 check_ooc 并入 discipline | 现实现近无效,判官框架已就位 |
| **P1** | 3 判官 fail-open 可观测 | 防"假绿",只补告警不改逻辑 |
| **P1** | 4 副词/冗词/陈词检测 | 成熟工艺,需 per-work 陈词表 |
| **P2** | 5 节奏/句长方差分析 | 先可视化、不做硬闸 |
| **P2** | 6 诊断→治疗自动化 | 按类配定向改写器,依赖 1/4 |
