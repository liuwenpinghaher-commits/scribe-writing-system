# 06 · 前端架构与交互体验

> 本文是 scribe3 写作台前端的现状解剖 + 对照专业写作软件 UX 经验的差距分析 + 详细改进方案。
> 代码基准:`scribe3/web/src/`。日期:2026-06-27。
> 阅读顺序建议:先看 §1 架构总览建立心智模型,再按 §2–§5 逐视图深入,最后看 §7 差距与改进(全文的"产出")。

---

## 0 · 一句话定位

scribe3 前端是一个**"对话驱动 + 护栏托底"的长篇写作工作台**。它和市面写作软件最大的不同:不是"作者一个字一个字敲、软件只管排版统计",而是**作者提思路 → 主编(LLM)主笔出草稿卡 → 作者接受/弃用/再议 → 正文落库 → 后台限知/质检护栏实时体检**。这套交互是真正的创新点;它的短板,恰恰在那些专业写作软件打磨了十几年的"作者基本盘"——大纲树、卡片、专注、进度、版本对比。这篇文档把两者都讲清楚。

## 1 · 前端架构

### 1.1 技术栈

| 层 | 选型 | 用途 |
|---|---|---|
| 框架 | **React 18** + **Vite 6** | SPA、HMR、`strictPort` 锁 3311(见 MEMORY) |
| 样式 | **Tailwind CSS 4**（`@tailwindcss/vite`)+ CSS 变量主题 | 原子类 + 一套语义色 token(`--color-brand` 黛绿 / `--color-fore` 伏笔橙 / `--color-irony` 反讽蓝 / `--color-secret` 私密紫),深浅双主题切换 |
| 正文编辑 | **TipTap 3**（ProseMirror)+ StarterKit / Placeholder / CharacterCount / Focus | 富文本编辑、字数统计、专注高亮、自定义 `SceneBreak` 场景分隔节点 |
| 关系图谱 | **@xyflow/react 12** + **elkjs 0.11** | 节点-边渲染 + ELK force 自动布局 |
| 图表 | **recharts 3** | 仪表盘字数/质检折线柱状 |
| 命令面板 | **cmdk 1** | ⌘K 跳视图/切书 |
| Markdown | **react-markdown** + **remark-gfm** | 主编对话气泡渲染 |
| 图标 | **lucide-react** | 全站统一线性图标 |
| 工具 | clsx / tailwind-merge（`cn()`)| className 合并 |
| 测试 | **vitest** + @testing-library/react + jsdom | 单测(applyProposal / rewriteButtons / chapterLabel / api 等) |

设计语言是"纸感 + 黛绿":浅色底 `#f6f5f2`、正文衬线(Source Serif 4 / Noto Serif SC / 宋体),管理界面用 Inter / Noto Sans SC。全站 `focus-visible` 环、`prefers-reduced-motion` 降级、`::selection` 黛绿——基础可达性与质感到位。

### 1.2 顶层编排（App.jsx）

```
App
├─ AppRail（顶栏 h-12:字标 SCRIBE3 · 作品切换 · 视图 tab · 主题切换)
├─ body（按 cur/view 切换)
│   ├─ 无当前作品 → Library（作品库)
│   ├─ view='write'   → WriteLayout（写作台,默认)
│   ├─ view='codex'   → CodexView（设定库)
│   ├─ view='atlas'   → AtlasView（图谱)
│   └─ view='insight' → InsightView（仪表盘)
└─ CommandPalette（⌘K 命令面板,全局)
```

- 状态极简:`works`(书列表)、`cur`(当前书 `{slug,title}`)、`view`(当前视图)、`theme`、`cmdOpen`。无 Redux/Zustand,纯 `useState` + props 下传。
- **一书一库**:`cur` 变化时 `api.setWork(cur.slug)`,后续所有请求自动带 `?work=slug`。
- 切书用 `key={cur.slug}` 强制 remount 各视图,杜绝跨书状态串味。
- 主题持久化到 `localStorage('s3-theme')`,`<html>` 上 toggle `.dark`。

### 1.3 Shell + Rail 工作区框架（shell.jsx）

三个"工作台型"视图(写作台 / 设定库 / 图谱外)共用 `Shell`:

```
[左轨 Rail w-12][左面板 可拖宽][中区 自适应 min-480px][右面板 可拖宽][右轨 Rail w-12]
```

- **Rail / RailBtn**:窄竖条,每个 cap 一个图标按钮;`hover` 出 tooltip,可挂 `badge`(红点计数,如校验问题数)。点已激活的 cap 再点 = 收起面板。
- **面板可拖拽改宽**:`Resizer` 鼠标拖动,宽度 clamp 190–620px,经 `useNumPref` 持久化到 localStorage(`s3.lw`/`s3.rw`)。
- **cap.bare**:对话面板用 `bare` 跳过默认 padding,自己管滚动。
- 中区 `flex-1 min-w-[480px]`,左右面板 `shrink-0`,保证正文区永远优先。

这是从 scribe2 `WorkspaceShell` 继承的成熟骨架,响应式与持久化都已考虑。

### 1.4 api.js — 统一调用层

- `BASE = VITE_API_BASE ?? http://127.0.0.1:3321`(开发回退,生产注入)。
- `WORK` 模块级变量 + `ww(p)` 给每个 path 拼 `?work=`,**多书隔离的唯一收口**。
- `handle(res)`:非 2xx 抛带 `status`/`body` 的 Error(history 有一坑修复:works 写操作曾绕过 handle 致 HTTP 错误"静默假成功",见 commit `7b23681`)。
- CRUD 辅助:`j/post/patch/del/put`。
- **SSE / 流式消费**:三套
  - `chatStream`:`EventSource` GET,主编速答 / agentic 联查(设定库右栏用)。
  - `chatWrite`:**`fetch` + ReadableStream 手动逐行解析**(POST,因为要带 `images`/`msg` body)。这是写作台主链路。解析 `data:` 行后按 `delta`/`tool`/`proposal_start`/`proposal_chunk`/`proposal`/`done`/`error` 分派回调,返回 `AbortController` 可取消。
  - `live`:`EventSource`,数据变更广播(预留)。

> 设计要点:`chatWrite` 把"提案"拆成 `proposal_start`(给个空壳卡)→ 多个 `proposal_chunk`(逐字流入卡)→ `proposal`(最终定形)三阶段,前端据此实现**草稿卡边生成边渲染**(commit `f01287a`),避免长草稿生成期间中区空白。

## 2 · 写作台 WriteLayout（核心)

写作台是整个产品的主战场,也是代码量最大的单文件(`WriteLayout.jsx` ~620 行)。

### 2.1 三区布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ AppRail：SCRIBE3 · 《书名》▾ · [写作台][设定库][图谱][仪表盘] · ☾    │  ← 应用顶栏
├──────────────────────────────────────────────────────────────────────┤
│ NorthStarBar：⊕ 北极星  读者感受·情感弧·红线  ……………………… ▾   │  ← 作品意图常驻条
├──────────────────────────────────────────────────────────────────────┤
│ topbarMid：◂ 第 N 章 ▸ │ 本章视角[作者全知▾] │ 🛡护栏 · 1234字 · 存▾ · 存为正文 │
├────────┬───────────────────────────────────────────────┬──────────────┤
│ 左轨   │  ┌─────────── DraftCard（主编草稿卡)──────────┐ │   右面板      │
│ ▫素材  │  │ ✦ 主编提议·整章改写         弃用 / 接受    │ │  ┌─主编对话─┐ │
│ ▫帧/意图│  │ （流式逐字写入的草稿正文……)              │ │  │ 气泡列表  │ │
│ ▫存档  │  └────────────────────────────────────────────┘ │  │ 工具芯片  │ │
│        │  ┌──────── ProseEditor（TipTap 正文)─────────┐ │  │ 建议按钮  │ │
│ 左面板 │  │ 正文段落…（选中浮 BubbleMenu:粗斜删/复制/  │ │  │ ───────  │ │
│ (大纲/ │  │ 改这段)…  ＊ ＊ ＊ 场景分隔…              │ │  │ 输入框+📎 │ │
│ 结构/  │  │                              1234 字       │ │  └──────────┘ │
│ 母题/  │  └────────────────────────────────────────────┘ │  右轨        │
│ 检索)  │                                                 │ ▫对话 ▫校验  │
│        │                                                 │ ▫演绎        │
└────────┴───────────────────────────────────────────────┴──────────────┘
```

中区 = **草稿卡 + 正文编辑器**纵向叠放,最大宽 48rem 居中(阅读舒适列宽)。左右是可折叠/拖宽的辅助面板,每侧顶部一根 Rail 切 cap。

**左轨三 cap**:
- `素材`:再分段(Segmented)——大纲(章列表跳转)/ 结构(本章事件+事实)/ 母题(参照不透支)/ 检索(向量召回设定)。
- `帧/意图`(FramePanel):限知视角下显示该角色"此刻已知事实"+ 戏剧反讽(读者知他不知)+ 北极星意图编辑。
- `存档`(VersionPanel):本章存档点列表 + 回看 + 恢复。

**右轨三 cap**:
- `对话`(WriteChat):主编对话主链路。
- `校验`(badge=问题数):再分段——校验(限知泄露/QC/因果/生成后全量体检+一键修)/ 伏笔(超期红)/ 在场(角色→设为视角)。
- `演绎`(DeducePanel):渲染某角色限知草稿,作素材交给主编。

**窄屏(<1100px)**进入瞬间自动收起右栏一次(`narrowRef` 保证不与用户手动重开"较劲")。

### 2.2 主链路:对话 → 草稿卡 → 编辑 → 落库

完整交互流(这是产品的灵魂):

```
1. 作者在右栏 WriteChat 提思路（"本章这样展开：…"/"把选中这段写得更冷"/"续写一段")
2. WriteChat → api.chatWrite(POST /chat/write，SSE 流)
   ├─ onDelta   → 主编对话气泡逐字显示思路前言（react-markdown 渲染）
   ├─ onTool    → 气泡上方挂工具芯片（mcp_scribe3_* 去前缀显示，表明主编联查了知识图谱）
   ├─ onProposalStart → 中区出现空草稿卡（DraftCard）+ "书写中…" loader
   ├─ onProposalChunk → 草稿正文逐字流入卡（proposalStreaming=true）
   └─ onProposal → 草稿定形：
        · scope='chapter'/'append' → 单张接受/弃用卡
        · scope='selection'        → 推入 candidates[]，多候选横排卡
3. 作者在 DraftCard 上操作：
   ├─ 接受 → applyProposal(prose, proposal, lastSel) 把草稿并入正文 → persist 落库
   ├─ 弃用 → 清空，原文不动
   └─ 多候选 → 逐张"用此版"
4. 落库 persist → POST /save-chapter → 返回 qc/leaks → 触发 tick 刷新护栏/统计
5. "存为正文" → persist + checkpoint(kind='final') 打定稿存档点
```

**草稿卡 DraftCard** 三种形态:
- 单提案(chapter/selection/append):标题"主编提议·整章改写/改这段/续写",`streaming` 时显"书写中…"loader 且接受按钮禁用,正文 `whitespace-pre-wrap` 渲染。
- 多候选(`candidates.length >= 1`):横排可滚的候选卡,各带"用此版"。**注意 `>= 1` 不是 `> 1`**——这是 history 修过的坑(单 selection 候选曾走多候选分支解引用 `proposal` 致崩溃,commit `9999bbb`)。
- 接受逻辑 `applyProposal`(`editor/applyProposal.js`)按 scope 把草稿拼回 prose;若 `lastSel` 标的原文已漂移(`drifted`),弹 toast"请重新选中"并放弃——防止盲目覆盖。

### 2.3 ProseEditor（TipTap 正文)

- **纯文本 ↔ HTML 互转**:段落以 `\n\n` 分隔;`* * *`/`***` 行 → 自定义 `SceneBreak` 原子节点(渲染为"＊ ＊ ＊")。`toText`/`toHTML` 严格同口径,保证落库是干净纯文本。
- **PM 位置 ↔ prose 偏移换算**(`pmPosToProseOffset`):选区改写要把 TipTap 的 ProseMirror 坐标精确折算到 prose 字符串偏移,才能让"改这段"的 `{text,from,to}` 三者自洽。这是选区改写不漂移的关键算法。
- **BubbleMenu**:选中文字浮出——加粗/斜体/删除线/复制/**改这段**(✦,触发 `onDiscuss` 把选区喂给对话)+ 实时"选中 N 字"。
- **专注模式**(`focusMode`):CSS `.focus-mode .tiptap-prose p { opacity:.3 }`,当前聚焦段 `opacity:1`——**句段聚焦式的轻量无干扰**(借鉴 Ulysses/iA Writer)。
- **防丢草稿**:`onUpdate` 防抖 1s 把正文写 `localStorage('s3-draft-{ch}')`;载章时若本地草稿比落库内容新且非空,顶部弹"发现未保存草稿 · 恢复/丢弃"。
- 阅读字体可切黑体/衬线(`serif` 持久化)。
- 外部 `value` 变化(切章/草稿灌入)与内部编辑解耦(`lastEmit` 防回灌循环)。

### 2.4 护栏(guard)体系

护栏是 scribe3 区别于通用写作软件的第二个创新点——**确定性质检 + 限知穿帮校验,边写边体检**:

- **顶栏护栏芯片**(Chip):tone 按严重度——`danger`(限知泄露)>`warn`(QC>0)>`ok`(干净)>`faint`(关闭)。点开 popover 显:限知泄露词、五类 QC(复读/排比/升华/AI腔/过饱和)计数、开关 toggle。
- **触发**:正文停笔 3s 后防抖跑 `api.checkProse(chapter, prose, focalizer)`,软校验不挡接受。
- **限知穿帮**:仅 focalizer(限知视角)模式下,`leaks` = 写了焦点角色不该知道的私密。作者视角(全知)无此约束。
- **右栏"校验"cap** 的 `renderVerify`:限知/QC/因果三行 + **生成后全量体检**("立即体检"→ `POST /post-check` 跑全 5 类 QC + `find_leaks` + `discipline_truncate`)→ **"让主编修这章"** 一键把体检结论塞进 `seedQuote` 喂回主编。这是"发现问题→定向重写"的闭环(commit `cf3b7ab`)。

### 2.5 选区改写 & 改写按钮库

- BubbleMenu"改这段" → `discussSel({text,from,to})` → 记 `lastSel` + 灌 `seedQuote`("把这段改一下,给我 2-3 个候选:「…」")→ 切到对话。
- 选区存在时,正文上方浮出**改写按钮条**:用户自存的常用指令(如"压缩、去形容词"),点一下即灌入"按『…』改"的 seedQuote。按钮库 `loadButtons/addButton` 持久化(`lib/rewriteButtons.js`),按 work 隔离。

### 2.6 北极星条 NorthStarBar

顶部常驻"作品意图"(读者感受 / 情感弧 / 红线),点开可编辑,`PUT /intent` 落库。它会被后端拼进主编 prompt 当**写作纲领**,保证主编不跑题。FramePanel 也复刻了一份编辑入口。

## 3 · 设定库 CodexView

最复杂的 CRUD 视图(`CodexView.jsx` ~790 行),用 Shell 框架:左轨 11 分类、中区列表/详情、右栏主编+检查。

### 3.1 分类(11 tab)

概览 / 角色 / 设定·命题 / 世界规则 / 势力 / 物品 / 术语 / 伏笔 / 母题 / 弧光 / 关系。

- **概览**:`setting-completeness` 完整度分(0–100)+ 9 类计数卡 + 缺失维度 + 角色问题诊断。
- **角色**:卡片网格(名/重要度/目标/前史/性格标签/弱点)→ 点入 `DetailView`。
- **通用条目**(命题/规则/势力/物品/术语/伏笔/母题):表格视图,点行入详情。
- **弧光**:`TimelineCard` 时间线(各角色质变点)。
- **关系**:`character_relation` 关系列表(源—关系—目标—建立章)。

### 3.2 详情编辑 DetailView

- **失焦自动保存的内联 Field 组件**:点即编辑,blur 提交,ESC 取消,空值显"+ 添加X"。type 涵盖 text/textarea/select/number/tags/abilities/array_csv。这是很顺手的 inline-edit 模式(类 Notion)。

## 7 · 差距与改进（对照专业写作软件 UX）

### 7.0 先说创新点(不要丢)

对照 Scrivener / Ulysses / 番茄/橙瓜码字,scribe3 有两条**它们都没有**的护城河:

1. **对话驱动主笔**:主编(LLM)按知识图谱限知约束出草稿卡,作者只做"提思路 + 接受/弃用 + 选区再议"。专业软件全是"作者主笔、软件辅助",scribe3 是"作者导演、AI 主笔"——交互范式不同。
2. **护栏体系**:确定性 QC(复读/排比/升华/AI 腔/过饱和)+ 限知穿帮校验 + 因果/伏笔超期,**边写边体检**。这是任何通用写作软件都没有的"质量地基"。

改进的原则是:**守住这两点,把"作者基本盘"补齐到专业软件水准**。

### 7.1 专业写作软件 UX 经验(研究提炼·七项基线 + 中文网文增量)

| # | 经验 | 来源/代表 | 解决的痛点 |
|---|---|---|---|
| E1 | **三视图联动:Binder(卷/章/场景树)+ Corkboard(卡片)+ Outliner(大纲表)** 同一份数据三种视角随时切 | Scrivener | 长篇结构看不见、改结构靠记忆 |
| E2 | **卡片式大纲"养书"**:每章/场景一张 index card 写 synopsis,拖拽重排即重排章节 | Scrivener corkboard | 先搭骨架再填肉,推翻重来成本低 |
| E3 | **分屏对照**:左设定/前章、右正文,边查边写 | Scrivener split / Ulysses | 写时频繁跳查打断心流 |
| E4 | **版本快照"时光机"**:任意时刻打 snapshot,逐版 diff、一键回滚 | Scrivener snapshots | 大改怕丢、想对比删改前后 |
| E5 | **无干扰/专注写作模式**:全屏沉浸 + 句/段聚焦(打字机模式)+ 可选背景音/打字音 | Ulysses / iA Writer / 码字软件 | 界面元素分心、进不去状态 |
| E6 | **进度可视化 + 目标**:字数目标进度条、每日 target、**写作连胜 streak / 码字日历打卡** | Scrivener project targets / Ulysses goals / 番茄·橙瓜 | 长篇看不到尽头、动力衰减 |
| E7 | **章节快速导航 + 多端同步** | 全部 | 翻章慢、换设备续写 |
| E8(中文增量) | **网文工具盘**:锁定逼更/日更目标、取名器、敏感词扫、稿费看板、防丢自动备份 | 橙瓜码字 / 番茄作家 | 网文连载节奏与商业化诉求 |

### 7.2 逐条差距与改进

下面每条:**现状 → 经验 → 具体改法(到组件/视图)→ 优先级**。优先级 P0(命门,直接挡作者基本流程)> P1(高杠杆)> P2(锦上添花)。

---

#### 改进 1 · 大纲/卷章树 + 卡片视图(最大空缺)【P0】 ✅ 已实现(见 §0.5;混合 Binder + volume 044,`9f01a47`)

- **现状**:章导航只是左轨"素材→大纲"里一列扁平按钮(`renderOutline`),无"卷",无场景层级,无 synopsis,不能拖拽重排。结构完全靠作者脑记。
- **经验(E1/E2)**:Scrivener 的 Binder + Corkboard 是长篇写作的"中枢"——树看层级,卡片看梗概并拖拽重排。
- **改法**:
  1. 新增独立视图 **OutlineView**(AppRail 加第 5 tab"大纲",图标 `LayoutList`),或在写作台左轨升级"大纲"cap。
  2. **卷章树**:`Volume → Chapter → Scene` 三层树。后端需补 `volume` 维度与 `scene` 切分(可先用正文里的 `* * *` SceneBreak 推断场景边界,已有节点!)。树支持拖拽改序 → 调 `seq` 重排。
  3. **卡片视图**:每章一张卡,正面是 synopsis(新增 `chapter.synopsis` 字段 + 设定库式 inline-edit),角标显字数/QC/视角/伏笔状态。用 CSS grid 或现成 `@dnd-kit` 做拖拽重排。
  4. 卡片点击 = 跳写作台对应章;空卡 = "+ 新章"。
- **杠杆**:这是把 scribe3 从"单章编辑器"升级为"能掌控长篇结构的工作台"的关键一步,直接影响 10 万字能否写下去。
- **前向指针**:本条已升级为**混合 Binder 导航重构**——独立 OutlineView 收编进左侧统一项目树(手稿支 + 素材支),详见 [作者工具/06-混合Binder项目树.md](作者工具/06-混合Binder项目树.md)(决策 B:写作台左栏并入项目树)。本条"独立 OutlineView 第 5 tab"的表述以 Binder 框架为准。

---

#### 改进 2 · 专注写作模式升级【P1】

- **现状**:`focusMode` 只做了段落 dimming(`.focus-mode p{opacity:.3}`),且入口藏在"存▾"下拉里,藏得很深;不全屏、无打字机滚动、无背景音。
- **经验(E5)**:专注是把"敲字者"送进心流的核心仪式——全屏隐藏所有 chrome、当前行居中(打字机模式)、可选氛围音。
- **改法**:
  1. 在 `WriteLayout` 顶栏给专注模式一个**显式快捷入口**(图标按钮 + 快捷键如 `⌘.`),不要埋下拉。
  2. **真·全屏沉浸**:进入后隐藏 AppRail / NorthStarBar / 左右 Rail 与面板,只留居中正文 + 极简退出条;ESC 退出。
  3. **打字机模式**:当前行滚到视口中线(TipTap 可监听 selection 调 `scrollIntoView({block:'center'})`)。
  4. (P2)氛围音/键音开关(`<audio loop>`),借鉴码字软件。
  5. 专注下仍保留防丢草稿与字数 HUD(角落淡显)。
- **组件**:扩 `ProseEditor` + 在 `WriteLayout` 加 `focusMode` 全屏容器层。

---

#### 改进 3 · 进度与码字统计 + 目标【P1】 ✅ 已实现(见 §0.5;daily_progress 043 + `/progress` + streak/热力图,`d34bfbe`)

- **现状**:只有静态"X 字 · 约 Y% · 目标 10 万字"(书卡 + 仪表盘),**无每日字数、无连胜、无日历打卡、无 session 统计**。写长篇看不到节奏与势头。
- **经验(E6/E8)**:project targets / writing streak / 码字日历是长篇与网文连载的核心动力机制。
- **改法**:
  1. 后端记 **每日码字事件**(每次 save 落 `{date, work, delta_words}`,或从 checkpoint 推断)。
  2. **InsightView 增"码字进度"区**:日字数柱状 + 累计曲线 + 连胜天数(streak) + GitHub 式打卡热力图(可用 recharts 或自绘 grid)。
  3. **可设目标**:作品级总目标(已有 10 万常量,改成可编辑)+ 每日字数目标;写作台顶栏/书卡进度条按真实目标算,达标给正反馈(toast/微动效)。
  4. **本 session 计数**:写作台 HUD 显"本次 +N 字 / 用时 M 分"。
- **组件**:`InsightView` 新区 + 书卡/顶栏进度条接真目标 + 后端 daily-words 端点。

#### 改进 4 · 章节导航增强【P1】

- **现状**:写作台靠 `◂ 第 N 章 ▸` 步进 + 左轨大纲列表点跳。无键盘翻章、无"跳到第 N 章"、无章间未保存提醒、无相邻章预览。
- **经验(E7)**:快速章节导航是长篇的高频操作。
- **改法**:
  1. 章号区做成**可点下拉/可输入跳转**(点"第 N 章"出章列表浮层,带标题/字数,支持搜),复用 CommandPalette 思路。
  2. 键盘:`⌘[` / `⌘]` 翻章(避开浏览器占用键)。
  3. 切章前若 `saved===false` 弹"有未保存改动"确认(现在 `setChapter` 直接覆盖,靠 localStorage 草稿兜底,但体验上应有提示)。
  4. ⌘K 命令面板增"跳到第 N 章"。
- **组件**:`WriteLayout.topbarMid` 章号控件 + 全局快捷键。

#### 改进 5 · 版本对比 UI(diff 时光机)【P1】

- **现状**:VersionPanel 能列存档点、回看全文、整体恢复,但**无 diff 视图**——看不出这版相对当前改了哪几句,只能整文替换。
- **经验(E4)**:Scrivener snapshots 的价值一半在 "compare"——逐行高亮增删。
- **改法**:
  1. VersionPanel 回看弹层加 **"对比当前"** 按钮 → 左右分栏或行内 diff(增绿删红)。前端可用轻量 diff 库(如 `diff-match-patch`)对 prose 做段/句级 diff。
  2. 支持**部分恢复**:diff 视图里选某段"采用旧版",而非整文回滚。
  3. 存档点列表显时间戳 + 字数变化(+N/−M),已有 qc 摘要可保留。
- **组件**:升级 `VersionPanel`,新增 `DiffView` 子组件。

#### 改进 6 · proposal 多候选 / 选区改写体验打磨【P1】

- **现状**:多候选横排卡可用,但——候选间无 diff 对照、不能"融合两版"、接受后无撤销;选区改写靠 `lastSel` 漂移检测(原文一动就作废,体验"白改一场");草稿卡接受是**直接落库**,误接受难回退(只能靠存档点)。
- **经验**:AI 写作工具(类 Sudowrite/Lex)的候选体验讲究"对照 + 可逆 + 微调"。
- **改法**:
  1. 多候选卡支持**与当前文 diff 高亮**,让作者看清每版改了什么。
  2. 接受草稿后给 **"撤销接受"** toast(N 秒内可回退),而非只靠存档点。
  3. 选区漂移时,不直接作废而是**尝试模糊重定位**(按选区文本 indexOf 重找),找不到再提示。
  4. 改写按钮库支持编辑/删除/排序(现在只能加)。
  5. 草稿卡正文超长时折叠"展开全文"(现已 `max-h-42vh` 滚动,可加锚点)。
- **组件**:`DraftCard` + `applyProposal` + `WriteLayout` 撤销栈。

#### 改进 7 · 护栏的可操作性【P1】 ✅ 已实现(见 §0.5;字符 offset + 波浪线 decoration + 句级修,`a93b9a6`/`5f0f756`)

- **现状**:护栏报"复读 3 / 排比 2 / 限知泄露:某词",但**不定位到正文具体位置**——作者知道有问题却找不到在哪句。"让主编修这章"是整章重交,颗粒度粗。
- **经验**:好的 lint UX 是"点问题 → 跳到出问题的那一处 + 给修复建议"(类编辑器 Problems 面板)。
- **改法**:
  1. 后端 QC/leak 结果带 **字符 offset / 句子定位**;前端在 ProseEditor 里用 TipTap decoration 给问题句**波浪下划线**(复读黄、泄露红、AI 腔灰)。
  2. 护栏 popover / 校验 cap 的每条问题**可点 → 编辑器滚动并高亮**该句。
  3. 单句级"让主编改这一处",而非整章重写(复用选区改写链路)。
  4. 泄露词给"这词该不该出现"的一键判定(确认是穿帮→改;确认无碍→加白名单)。
- **组件**:`ProseEditor`(decoration 层)+ 护栏 popover + `renderVerify`。

#### 改进 8 · 分屏对照【P2】

- **现状**:左面板能显前章事件/事实/帧,但不能并排显**前一章正文全文**或另一章对照;写第 N 章想看第 N-1 章结尾要切章。
- **经验(E3)**:分屏(setting | prose,或 prev chapter | current)是减少跳查、保持心流的利器。
- **改法**:写作台中区支持**纵向/横向分屏**——一栏当前章可编辑,另一栏只读显前一章尾段 / 设定卡 / 演绎草稿。`Shell` 已有可拖宽面板基础,可在中区内再嵌一个只读 prose pane,数据复用 `recent_proses`。
- **组件**:`WriteLayout.center` 增分屏布局开关。

#### 改进 9 · 多端同步与移动端【P2】

- **现状**:纯桌面 SPA,localStorage 本地态(主题/面板宽/草稿/改写按钮),换设备不带走;响应式仅做到"窄屏收右栏",无真正移动端布局。
- **经验(E7)**:Ulysses/番茄等的"随时随地续写"靠云同步 + 移动端。
- **改法**:
  1. 把 localStorage 偏好(草稿、按钮库、面板宽、北极星草稿)**上云**到 work,实现跨端续写(后端已是一书一库,加用户偏好表即可)。
  2. 移动端:至少做**只读阅读 + 主编对话**的窄屏布局(写作台三区在手机上塌成单列 tab 切换)。
  3. (远期)PWA 离线缓存。
- **杠杆**:相对前 8 条偏远期,长篇创作主要发生在桌面,故 P2。

#### 改进 10 · 中文网文增量盘【P2,按定位取舍】

- **现状**:无取名器、无敏感词扫、无日更锁定/逼更、无稿费看板。
- **经验(E8)**:橙瓜/番茄的网文工具盘。
- **改法**(若产品定位含网文连载):取名器(可接主编生成 + 设定库去重)、敏感词扫(确定性,接进护栏第 6 类)、日更目标锁定(接改进 3)。**若定位是"纯文学/严肃长篇",这条可不做**——避免堆功能稀释护栏与对话两条主线。

### 7.3 改进优先级汇总

| 优先级 | 改进 | 一句话理由 |
|---|---|---|
| **P0** | 1 大纲/卷章树+卡片视图 | 没有它,10 万字长篇结构失控;最大空缺 |
