# Scribe3 全系统全维审查总报告

**审查时间:** 2026-07-08  
**审查范围:** Wave A 全局骨架、Wave B 写作主链路、Wave C 知识与素材、Wave D 工艺与横切视图、Wave E 横切风险与生产化。  
**审查定位:** 这不是普通代码 review，也不是功能点清单验收。本报告按业务完善性、逻辑闭环性、架构合理性、UI 交互友好性、数据可信性、创作质量、失败恢复和工程可维护性审查每个能力是否能被产品承诺。

## 总判断

Scribe3 当前整体成熟度是 **M2 可用，但未到 M3 稳定闭环**。

它已经不是“只有 demo”的状态：手稿、设定库、素材库、主编、限知、图谱、时间线、仪表盘、伏笔/母题、校验、Pilot 等都有真实后端和大量测试支撑。真正的问题不是底座缺失，而是 **产品闭环不均匀**：有些能力后端很强但 UI 不可达，有些 UI 已经出现但详情/错误态是占位，有些数据会写入但用户不知道写入影响，有些失败被吞成空态。

本轮没有发现 P0 级“立即数据灾难或 secret 明文泄露”的证据；但发现多项 P1 会让用户觉得“功能丢了、功能假了、数据不可信”。最高优先级不是再换皮，而是把入口、目录、详情、右栏、API、store 和 prompt 串成可解释闭环。

## 闭环断点地图

| 断点类型 | 典型问题 | 影响 |
|---|---|---|
| 入口断点 | 未选章时演绎/伏笔/母题/检索/校验消失 | 用户以为能力被删或只能章内使用 |
| 目录断点 | `DirectoryPane`/`EntryRail` 有实现但真实壳仍走旧 `active.render()` | 新二栏架构无法被生产验证 |
| 详情断点 | `CapabilityDetailPanes` 多数是占位 | 搜索/QC/伏笔/母题接新详情会降级 |
| prompt 断点 | 正文右栏 `WriteChat` 未传 `phase='final'` | 后端 final prompt 和演绎块不进入真实写作入口 |
| 数据生命周期断点 | 角色/fact 硬删直接 ok，素材删除不清引用 | 图谱、搜索、限知、素材引用可能出现孤儿或误导 |
| 失败态断点 | 实时护栏、搜索、仪表盘、progress、卷操作失败不可见 | 用户把失败误判为空、没问题或已保存 |
| 性能断点 | 素材列表/素材网络全量拉取渲染 | 素材量增长后 UI/网络图风险上升 |
| 测试边界断点 | e2e 有只读和写真实作品两类，但命令分层不清 | 回归可能污染用户作品 |

## 三批修复路线

### 第一批：可信性止血

目标是先保证用户不会被错误状态误导，也不会因为查看/删除/导入而产生不可解释数据变化。

- 正文右栏传 `phase='final'`，补 prompt 内容断言。
- `DeduceTree` 自动写入改成“建议同步”按钮，带预览和撤销。
- 角色/fact 删除补 404 和 impact dry-run；material 删除补引用/relates 处理。
- 素材导入 commit 返回失败条目和可重试上下文。
- 搜索、仪表盘、progress、护栏、卷操作失败态从空态/console 改为可见错误和重试。

### 第二批：产品闭环补全

目标是让每个能力能从入口到沉淀再回流，不再只是一段面板或 API。

- 左栏常驻显示手稿、设定库、素材库、演绎、伏笔、母题、搜索、校验；未选章时进入全书态，选章后进入章态。
- 真正接入 `EntryRail + DirectoryPane + DetailPane`，保留旧真实面板能力，不用静态占位替换。
- 搜索升级为分类结果：设定、章节、素材、伏笔、母题、事件，并可跳三栏详情。
- 章工作台显示本章素材引用账本、QC issue 台账、张力检查结果台账。
- 横切视图节点/事件/弱章可跳回具体对象。

### 第三批：架构生产化

目标是把能长期扩展的边界固化下来。

- 建对象 lifecycle 层：impact、archive、delete、restore、cascade/refuse。
- 拆 `studioDocks.jsx` 大文件，按能力拆目录、详情、右栏上下文、状态 hook。
- 素材列表和素材网络加分页、虚拟化、`limit/focus/hop/truncated`。
- MCP 多书联查做 per-work profile/cache。
- e2e 分 `readonly`、`writes-with-snapshot`、`destructive-manual` 三档。

## 正式验收标准

后续修复不能只说“build 绿”。每个功能要按下面标准验收：

1. 业务目标明确：知道它服务作者哪一步。
2. 入口稳定：顶栏/左栏/二栏/三栏/右栏归属不混乱。
3. 目录常驻：二栏不被详情替换，选中态可解释。
4. 详情真实：三栏不是占位文案，能读写真实对象或展示真实视图。
5. 数据可信：成功、失败、部分成功、降级、删除影响都有表达。
6. 写作回流：结果能进入正文、主编、素材、校验、图谱、时间线或仪表盘。
7. 浏览器可证：至少一条成功路径和一条失败/空态路径有真实浏览器证据。
8. 回归分级：只读、写入带恢复、破坏性手工三类分开。
