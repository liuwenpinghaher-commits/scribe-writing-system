## 摘要

**好消息(架构级不变量成立)**:门控/登记/单写点/ingest 幂等/fail-soft 记账齐全;**REST 读端点私密屏蔽全部正确**——新增的 `/project-tree`(素材支只投影身份+secret布尔角标,backstory/private_operation 不进树)、`/timeline`、`/outline`、`/ledger`、`/post-check` 都不泄露私密;overdue/字数单源、限知时间门(`_all_relations` 仅 timeline 用、不可达限知)无误用;作者工具新表(volume/daily_progress/clues/narrative_position)与世界状态/限知/ingest 隔离干净,双轴回退、clues 增删、record link NONE 防护均健康。

## 一、跨段最严重(🔴 ×3,优先修)

### 🔴 #1 限知物理隔离在写作主链路被击穿,密文明文泄露(R3+R6 独立确认)
**现象**:`/chat/write`(GET app.py:1219 / POST :1308)的 instructions 基座是 `_editor_write_system → _editor_system`(app.py:879),它**无条件**把 `facts_at(99999)[:28]` 全部事实注入系统提示,**含 secret 的 value 明文**,仅附"(私密/伏线)"标记(app.py:805)。而 `_frame_block`(app.py:1142,屏蔽帧外私密、自称"帧外的事物理上进不了 prompt")在同一字符串里**晚于**基座追加(app.py:1229/1318)。
**为何最高危**:设了 focalizer 的限知章,模型**物理上仍持有焦点者帧外的全部私密原文**,`_frame_block` 的屏蔽形同虚设,限知叙事的命根子(物理隔离)失效;伏笔/反转密文随时可能被写穿。`find_leaks` 只是事后兜底,不是物理隔断,且无任何测试守这条属性。
**已点名未修**:`docs/audits/2026-06-28-写作主链路分析与改进.md` line 20 第3条已指出"focalizer 模式应以 `_frame_block` 限知帧为准、非全知截断",本轮确认仍原状。
**改进**:`_editor_system` 接 focalizer 参数;focalizer 非空时设定块改用 `project_frame(focalizer,ch)` + `_facts(reveal_secret=False)` 屏蔽,或移除全知设定块只靠 `_frame_block`;仅作者视角(focalizer 空)才注入全知含私密。**并加测试守"焦点者章 prompt 不含帧外 secret value"。**

### 🔴 #2 切章丢未保存正文(真实数据丢失,R5)
**现象**:写作台改了正文未保存 → 点项目树另一章 → 当前章编辑静默丢失,无提示。
**证据**:`WriteLayout.jsx:135-142` chapter-load effect 依赖 `[chapter,tick]`,`api.chapter(chapter).then(ch=>setProse(ch?.prose||''))` **无条件覆盖** prose;`onChange` 仅 `setSaved(false)`;`DetailPane.jsx:46` 用 `key={work}` 而非 `key={seq}` 故切章不重挂载、走覆盖式 effect;全仓无 `!saved` 切章拦截 / `beforeunload`。
**改进**:切章前 `!saved` 则 confirm 或自动 `persist`;加 beforeunload 兜底。

### 🔴 #3 daily_progress delta 可为负,污染进度真源(R1)
**现象**:`_record_daily_progress`(store.py:1096-1111)`delta = 全书新总字数 − prev_total`,无 `max(0,…)`。作者把已有章**改短**时 new_total<prev_total → `words_written` 被倒扣甚至变负。
**为何**:daily_progress 是 streak/热力图/趋势的唯一真源(app.py:794);负 delta 让 `_compute_streaks` 达标判定(store.py:179)误判、streak 断裂。
**改进**:delta 落库前 `max(0, delta)`,缩写日记 0 不倒扣。
