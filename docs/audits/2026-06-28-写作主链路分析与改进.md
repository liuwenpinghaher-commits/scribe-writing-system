# scribe3 写作主链路(主编主笔+chat引导)全链路分析与改进

> 目标:让"用户 chat 引导、主编主笔"能写出堪比《乱世铜炉》的长篇。本文是全链路分析(3 并行 agent W1对话生成/W2质量管线/W3反馈闭环 + 2 次真机写作探针)+ 分批改进计划。日期 2026-06-28。

## 真机探针实测(2 次)
- 两次明确写作请求(focalizer=胡不为 / 作者全知=老乌头)均产出**乱世铜炉级散文**(古白话筋骨、世界密度侧笔、冷笔素描、拉到了"镇煞钉/潼关/往生钱"世界设定)。**生成质量不是瓶颈**。
- 但两次都 **proposal=0、无 ⟦PROPOSAL⟧ 围栏、无"处理思路前言"** → 主编忽略围栏指令 → 正文以聊天 delta 流出,前端无法渲染为可接受草稿卡。**交付环系统性破损。**

## 根因
ingest 的**写端**(落 knows/reader_knows)自动且扎实;但**反哺读端**(把图谱内容确定性拼回下一章 prompt)、**质量闸**、**proposal 交付**三者要么外包给模型自觉、要么离线、要么脆弱。生成 prose 够好,但**保真/记忆/质控/交付**四环漏。

## 改进计划(4 批,按对"写出乱世铜炉级"的杠杆排序)

### 批 G1 — 写作回路保真+记忆(限知命门 + 主编不失忆)
**Files:** `scribe3/app.py`、`scribe3/tests/test_app.py`
1. **`_frame_block(st, focalizer, chapter)`**:focalizer 模式下,把 `project_frame(st, focalizer, chapter).facts`(经 `_facts` 屏蔽私密)确定性注入 instructions——"本章焦点者**此刻确知**的事实(只能写这些,别写帧外私密)"。不依赖模型自调工具。与 voice/arc 块同级,注入 chat_write GET+POST。
2. **`_recap_block(st, chapter)`**:注入"前情"——`recent_proses(chapter, k=1)` 的尾段(末~300字)+ `events_at(chapter-1)` 的事件摘要,作"上一章发生了什么,接着往下写"。与 avoid-directive 语义区分(那是"别逐字抄措辞")。
3. **focalizer 模式优先帧、非全知截断**:`_editor_system` 当前注入 `facts_at(99999)[:28]` 全知设定。focalizer 模式下应以 `_frame_block` 的限知帧为准(全知设定仅作者视角用)。
**TDD**:种 focalizer 知道的命题 + 帧外私密命题 → `_frame_block` 含前者不含后者;`_recap_block` 含上一章尾段。

### 批 G2 — proposal 交付健壮
**Files:** `scribe3/proposal.py`、`scribe3/app.py`、`scribe3/web/src/WriteChat.jsx`、`scribe3/web/src/DraftCard.jsx`、tests
1. **围栏兜底(后端)**:`_stream_write`/`ProposalParser` 收尾时,若**整轮无任何 proposal 围栏**、但本轮是写作意图(由调用方传入 `expect_proposal` 标志,chat_write 据 msg 写作动词判定)且输出主体是长段散文 → 把整段兜底包成 `scope=chapter` proposal 吐出。让"模型忘了写围栏"不再导致正文掉聊天轨。
2. **单 selection 候选崩溃(前端)**:`DraftCard.jsx` 多候选分支 `candidates.length>1` → `>=1`,或单候选回退单卡;消除 `proposal===null` 解引用崩溃。
**TDD**:ProposalParser 喂无围栏长散文 + expect_proposal=True → 收尾吐 chapter proposal;前端 build 绿。

### 批 G3 — 质量闸接进生成回路 + 仪表盘全量
**Files:** `scribe3/app.py`、`scribe3/web/src/...`、tests
1. **生成后自动质量扫描**:save/accept 后(或新 `/post-check`)自动串 `quality_flags`(全 5 类)+ `find_leaks` + `discipline_truncate`,把结果回传前端;弱章给"让主编修这章"入口(触发 dedup/discipline/定向重写)。
2. **/quality 全量计数**:`qc_issues` 现漏算 `ai_tics`/`oversaturation`(app.py:616);`/check` 与 WriteLayout guard 同漏。全量纳入五类,InsightView 分类展示。
**TDD**:/quality 计数含 ai_tics+oversaturation;post-check 返回 leaks+discipline。

### 批 G4 — 弧光自动入账(边写边长出弧光)
**Files:** `scribe3/ingest.py`、`scribe3/critique.py`、`scribe3/store.py`、tests
- 扩展 ingest 抽取:LLM 抽取 delta 时同时抽 char_state(能力/关系/性格质变)→ `apply_delta` 调 `add_char_state`(经 ingest_seq 幂等)。让正文里角色成长自动变成下一章 `_arc_state_block` 约束。
**TDD**:喂一段含角色成长的正文 → ingest 后 `char_state_at` 含该质变。

- append 注入当前章末段上下文(W1#6)。
- check_ooc 改走 discipline 判官、validate_setting 接进 save(W2#4)。
- 声音 flag→profile 半自动消化(W3#4);voice_anchor 注入 open flags 提示。
- ingest learned 命题语义去重(W3#6);final checkpoint 触发 ingest(W3#7);对拍扩到知识边(W3#8)。
