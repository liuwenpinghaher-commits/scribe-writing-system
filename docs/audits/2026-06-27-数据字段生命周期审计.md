## 一、七大横切主题(爆炸半径模式)

这是比逐条 bug 更重要的层——**问题不是孤立的,而是七种反复出现的结构性模式**:

### 主题 1 · 雄心 schema、未接线的上层(死/孤儿字段 ~20 个)
schema 宣告了双时态、声音指纹、角色快照等能力,但**上层写或读路径从未接通**:
- `event.draft_version`/`tx_at`(事务时态轴,从不差异化/读)、`chapter.qc_at`/`qc_issues`/`qc_causal`(022 缓存,无写或同名碰撞)、`word_stats` 视图(023,全仓零引用)、`place` 027 四扩展字段(geography/...,无写无读)、`voice_profile` 4 字段(sentence_patterns/vocabulary_profile/internal_monologue_style/reference_lines)+ `version`+`last_updated_chapter`、`char_state.before_state`/`affects_voice`、`proposition.created`、`character.created`/`traits`/`motivation`。
- **半径**:让人误以为"已建模"(地点完整性、声音指纹、时点快照),实则功能名存实亡;设定完整度判定/快照查询恒空。

### 主题 2 · 半截子重命名,双写技术债(命名漂移)
重构加了新字段名,旧名没废,靠运行时双写/双读弥合:
- `event`:`etype`/`event_type`(015)、`valid_from`/`story_chapter`(018);`voice_evolution_flag`:`seq`/`trigger_chapter`(021);`proposition`:`entity`/`entity_id`(014);`character.aliases` 双定义(001 array vs 029 option)。
- **半径**:任何"只写其一/只读其一"的新代码会与现存读写错配。`max_chapter` 只查 `valid_from` 是已埋的雷(若将来只写 story_chapter 即算错扫描范围)。`graph_recall` 残留依赖 `etype`。

### 主题 3 · 消费方就绪、生产方缺席(写孤儿时间门)
读路径 + UI 都备好了,**写路径从未建** → 特性是死的:
- `character_relation.until_chapter`:`relations_at` 有失效门、CodexView 有"第N章结束"红字 UI,但**无任何写入** → 关系永不失效,敌变友/破裂无法表达。
- `char_state.after_state`:`char_state_at` 的能力/关系/性格快照**唯一**依赖它,但 `s3_add_char_state`/`POST /char-states` 都不写 → 时点快照恒空。
- **半径**:整块功能(关系演变、角色快照)对用户不可用,且 UI 分支永不触发,极具误导性。

### 主题 4 · 限知/私密屏蔽边界不一致(🔴 安全)
系统命根子是"限知物理隔离",但屏蔽只在一条路严格成立:
- ✅ REST `_facts`(`/facts /frame /irony /recall`)正确屏蔽 secret value。`/live` SSE 不带值。
- 🔴 **`GET /graph` 泄露**:`store.graph()` 对 secret fact 输出 `value[:18]` 进节点 label(store.py:754)。私密短句(如"攒钱给老娘治眼")整句上 wire。
- 🔴 **MCP 召回工具全线明文**:`s3_semantic_recall`/`s3_hybrid_recall`/`s3_graph_recall`/`s3_dramatic_irony`/`s3_project_frame` 原样返回 secret `value`,且 semantic/hybrid 召回**无 focalizer 概念**——主编 agent 可把私密原文带进上下文/续写 prompt。`s3_dramatic_irony` 按定义就吐"读者知、角色不知"的私密。
- 🔴 **graph_recall 双定义**:store.py:480 覆盖 451,生效版**丢了 secret 字段**,下游无从屏蔽。
- 🟠 **设定层私密无对等保护**:`character.backstory`(冰山私密前史)、`faction.private_operation`(暗线)经 `/entities`/`/factions` 明文下发。
- 🟠 **前端锁标记永不显示**:`_facts` 输出键 `is_secret`,前端读 `f.secret`(WriteLayout.jsx:322)→ 名字不符,Lock 图标永远不亮。
- **半径**:这是"信息屏障 vs 全知联查"两条路线冲突的具体落点——主编全知场景下设计如此,但限知章里若误用 MCP 私密 value 入正文,穿帮屏障失效。

### 主题 5 · 路由/方法遮蔽 + 设定 CRUD 语义全错
- 🔴 **路由重复定义**:`/world-rules`(app.py:317/448/497)、`/factions`(343/477/518)、`/setting-completeness`(361/539)各定义 2-3 次,FastAPI 只用**首个**;能接收完整字段(limitations/exceptions/established_chapter/known_members/first_mention_chapter)的后续 handler **全是死代码** → 这些字段经 REST **永远写不进去**。
- 🔴 **设定增删改全错**:`faction/world_rule/item/term` 的 `name` 无 UNIQUE,前端"编辑"走 `POST`(CREATE,CodexView.jsx:404-407)→ 每次编辑**新增重复行**;`delete WHERE name` 又**一次删光所有同名**。增改删语义皆错。
- **半径**:作者在设定库里编辑世界规则/势力/物品/术语,实际在不断造重复脏数据,删一次全没。

### 主题 6 · 静默失败(无回执)
- 🔴 **ingest 丢数据**:`parse_knowledge_delta` 失败(LLM 截断/未转义引号/`{.*}` 贪婪误匹配,critique.py:312)→ 返回空 delta,但 `apply_delta` **已先 `purge_ingest(seq)` 删本章旧产出再写空**(ingest.py:24)→ **一次解析失败=本章已有 ingest 知识被清空且不重建**,`applied:0` 与"本就无新知识"无法区分。`_bg_ingest`(app.py:952)异常仅 log,前端永远显示"回写中"无成败回执。
- 🟠 **api.js work 写操作**(createWork/renameWork/deleteWork,api.js:39/42/43)绕过 `handle`,**不查 res.ok** → HTTP 500 当成功 JSON 返回(静默假成功)。
- **半径**:角色"忘记"上章已知信息 → 后续限知帧 POV 一致性破口;用户不知道知识账本没更新。

### 主题 7 · per-work 工艺到不了用户路径
- 🔴 **craft_rule.pattern 在全部 HTTP QC 失效**:`quality_flags` 在 app.py:608/919/970/1024 四处**都不传 extra_patterns**,只有 MCP `s3_qc_chapter`(mcp.py:231)注入。作者在实时护栏(/check)、保存(/save-chapter)、仪表盘(/quality)看到的 purple 计数**只用通用正则**,本书 8 条乱世铜炉特化升华句 + 主编加的规则全部失效。
- 🟠 **声音指纹完全不进续写 prompt**:gen3/critique/scenario 零引用 `get_voice_profile`/`latest_voice_samples`;9 节指纹只在事后 `check_ooc` 用到 `ooc_signals` 一节。声音系统投入大、对生成零影响。
- **半径**:per-work 定制(升华正则、声音)只惠及走 MCP 的主编 agent,前端用户路径享受不到。
