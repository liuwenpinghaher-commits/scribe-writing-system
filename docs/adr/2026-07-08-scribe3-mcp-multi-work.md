# ADR: Scribe3 多书联查与 MCP 接入策略

日期: 2026-07-08

## 状态

Accepted

## 背景

Scribe3 当前运行模型仍以单一 `work` 为主要边界:前端通过 `api.setWork()` 和每个请求的 `work` 参数切换作品,后端按 `work` 选择对应存储。这个模型适合单书写作、单书设定库、单书素材库和单书四栏钻取,但不适合直接表达以下需求:

- 多书之间共享人物、素材、母题或世界观。
- 在一本书写作时召回另一书的素材或设定,并能解释来源。
- MCP 工具按不同作品暴露不同上下文、权限和检索边界。
- 同一浏览器会话中并行查看 A 书和 B 书时,左栏偏好、缓存和后台请求不能串书。

当前已完成的前置收敛:

- 左栏偏好已按 `s3.${work}.leftTab` 隔离。
- 四栏能力路由以 `entry -> directory -> detail -> chief context` 为主线。
- 搜索、校验、素材引用、横切视图跳转都已使用显式 `target_node` 或统一对象导航。

## 决策

采用 **per-work store cache first, per-work MCP profile deferred**。

短期先把每本书视为独立 store profile,在前端和后端明确缓存、偏好、请求、索引和 target node 的 `work` 边界。MCP 多书 profile 不在当前修复批次内直接实现,只定义契约和测试门槛,避免把未闭环的跨书权限和召回混进当前单书写作链。

## 方案比较

### 方案 A: 先做 per-work store cache

做法:

- 所有缓存 key、偏好 key、长连接事件和后台请求都携带当前 `work`。
- 搜索、校验、素材图谱、素材引用先在当前书内闭环。
- `target_node` 保持单书内可定位,后续扩展为 `{ work, id, type, ref }`。
- 后端 store 维持单书实例边界,只增加可测试的 per-work cache 策略。

优点:

- 与现有架构一致,风险低。
- 能先关掉串书、串偏好、串上下文这类可信性问题。
- MCP 接入前已有稳定契约和测试。

缺点:

- 不能立刻跨书联查。
- 需要后续迁移 `target_node` 结构,补 `work` 字段。

### 方案 B: 立即做 per-work MCP profile

做法:

- 每本书生成独立 MCP profile。
- 搜索和素材召回直接跨 profile 聚合。
- 前端允许在当前书中打开其他书 target。

优点:

- 更接近最终多书联查形态。
- 能一次性打通 MCP 使用场景。

缺点:

- 当前权限、来源标注、写入边界和 UI 回跳规则还不够完整。
- 容易把“读另一本书”和“写当前书”的上下文混淆。
- 若没有充分测试,会放大素材误召回、设定串书和主编建议串书风险。

## 选型理由

选择方案 A。

Scribe3 的核心可信性问题不是“能不能多查一本书”,而是“当前书内每个能力是否真实、可定位、可解释、不会串上下文”。本轮修复已经把左栏、二栏、三栏和右栏主编上下文拉回同一条钻取链,此时直接引入跨书 MCP 会让数据来源和写入边界重新变复杂。

因此 MCP 延后到当前单书闭环稳定之后,以 per-work profile 的形式接入。

## 迁移路径

1. 当前批次:
   - 保持 `work` 作为请求级边界。
   - 新增功能必须支持 work-scoped 偏好、缓存和错误态。
   - `target_node` 继续兼容旧形态,但新代码优先通过统一对象导航处理。

2. 下一批:
   - 将 `target_node` 标准化为 `{ work, id, type, ref, label, source }`。
   - 搜索、素材引用、校验 issue、横切视图跳转全部透传 `work`。
   - 后端聚合结果必须返回 `source_work` 和 `trust_level`。

3. MCP 准备批:
   - 为每个 work 生成只读 profile。
   - MCP 工具默认只读,写入工具必须显式声明目标 work。
   - UI 上跨书结果必须显示作品名和来源类型,点击后进入只读详情或显式切书。

4. MCP 正式批:
   - 开启跨书搜索和跨书素材召回。
   - 对写作链注入的跨书素材加入来源解释和引用账本。
   - 任何跨书写入必须先弹出目标作品确认。

## 风险控制

- 串书风险:所有缓存和偏好 key 必须包含 work。
- 写错书风险:保存、导入、删除、归档、主编写作必须传入捕获时刻的 work。
- 误召回风险:跨书结果不得直接混入当前书建议,必须标注来源并可展开解释。
- 权限风险:MCP profile 默认只读;写入工具拆分为单独能力并要求显式目标。
- UI 风险:跨书 target 不直接替换当前书目录,先显示来源,再由用户选择切书或只读查看。

## MCP 前置测试门槛

进入 MCP 实现前必须新增并通过以下测试:

- 后端:同一请求并发访问两个 work,结果不能互相污染。
- 后端:跨书搜索返回 `source_work`、`target_node.work` 和来源解释。
- 后端:写入接口缺少显式目标 work 时拒绝执行。
- 前端:切换 work 后左栏 active、二栏目录、三栏详情和右栏上下文不沿用旧书状态。
- 前端:跨书搜索结果显示作品名,点击不会隐式写入当前书。
- 浏览器:打开 A 书横切视图,再切 B 书,图谱/时间线/仪表盘不沿用 A 书数据。

## 当前代码收口

本轮只做稳定边界拆分:

- 能力详情、搜索、校验、素材工作台已进入独立 capability 目录或独立组件。
- 横切视图对象回跳统一收敛到 `targetNavigation`。
- 暂不继续拆 `studioDocks.jsx` 和大型视图文件;这类拆分应在行为测试覆盖更完整后单独执行。
