# 真人作者全功能验收测试方案 · v2

> **目标**：用**真正作者的心智与操作**验证 scribe3——能不能写出高质量小说；功能设计/交互是否合理；**所有功能是否既能用、又用得上**。  
> **基线**：`main`（合并后 `a7e730e` 起）；旧轮 `artifacts/e2e-20260718-book_d0bb19e9/` 仅作对照，本轮**新建隔离作品**。  
> **方法锚点**：认知走查（Nielsen Cognitive Walkthrough）+ 真人创作工作流（Story Bible / 多稿修订 / 看板决策）+ 缺口即研即改闭环。  
> **与改造融合**：与「禁表单直填」改造**同一条主线**执行，见 `docs/融合执行规程-真人验收×对话驱动改造.md`（禁止先手填验收再回头改）。  
> **证据分级**：UI 真机操作 > 只读 API 回读 > 单测；禁止「只调 API 造数据假装写过」。

## 0. 核心原则（与 v1 的差别）

| # | 原则 | 含义 |
|---|------|------|
| P1 | **作者心智优先** | 步骤按「真人会先干什么」排序，不按模块目录排序 |
| P2 | **功能必须上桌** | 全量功能矩阵每项至少完成 1 次**有写作后果**的任务 |
| P3 | **看板驱动决策** | 每写下一章前，强制用 1–2 个横切看板梳理逻辑（不是写完再看） |
| P4 | **返工是主场景** | 中途改设定/改总纲/回滚章节是验收主路径，不是边角 |
| P5 | **缺口即研即改** | 卡死或不完善 → 停笔 → 全网/竞品/设计文档对照 → 定最优方案 → 修 → 回归 → 再写 |
| P6 | **质量双轨** | 系统 QC/十维 + 人工文学判断；数字干净但读着假 = 不通过 |
| P7 | **证据可审计** | 每步：意图 / 点了哪 / 系统反应 / 落库回读 / 判定 / 截图编号 |
| P8 | **禁止业务表单直填** | 设定/北极星/大纲/节拍/演绎/伏笔等**一律**对话→提案→批准；出现手填 = P0/P1 缺陷（见 `设计文档/2026-07-22-对话驱动写入-禁表单直填-决策与改造方案.md`） |
| P9 | **批准/接受由代理点** | 浏览器「批准写入 / 接受提案」由执行代理 Playwright 点击完成；不得留给人类，不得 API 静默代替（见融合规程 §3.1） |

## 1. 运行制度：缺口即研即改（强制）

### 1.1 触发条件（任一即停）

- 真人 **2 分钟内找不到**下一步入口  
- 必须查代码/调 API 才能完成作者意图  
- 功能存在但**改完设定/大纲后正文与下游不同步**  
- 看板/校验给出信号，但**无法导航到可修复对象**  
- 作者真实会做的动作（改总纲、返工、对比版本）**系统无路径**  
- 文案误导（显示成功实际未存、显示干净实际缓存过期）

### 1.2 标准闭环（不可跳过）

```
STOP 记录缺陷（现象 / 意图 / 复现步骤 / 证据路径）
  → RESEARCH 全网 + 本仓设计文档 + 竞品（Scrivener/Twine/Novelcrafter 等）
  → DECIDE 最优方案（最小改动 + 作者心智 + 不破坏主路径）
  → FIX 实现 + 定向回归（单测/组件 + 真机同一路径）
  → RESUME 从断点继续；禁止「先写完再修」
```

### 1.3 研究时强制问的 4 个问题（Cognitive Walkthrough）

对每一个失败步骤回答：

1. **用户会不会想做这一步？**（目标是否可见）  
2. **用户能否注意到正确控件？**（入口是否可发现）  
3. **用户能否把控件与目标关联？**（文案/图标是否匹配心智）  
4. **执行后反馈是否让用户知道成功？**（落库/回读/状态）

参考：Nielsen Norman Group — Cognitive Walkthrough。

### 1.4 缺陷分级（决定是否阻断连写）

| 级 | 定义 | 处置 |
|----|------|------|
| **P0** | 主路径不可完成（建书/动稿/存稿/刷新丢数据） | 立即修，停写 |
| **P1** | 返工/总纲/看板决策路径断，或静默数据损坏 | 立即修，停写 |
| **P2** | 功能用得上但路径深/反馈差 | 记台账，本轮至少修 1 次再继续相关章 |
| **P3** | 文案/视觉/次要体验 | 记台账，不阻断 |

## 2. 系统能力地图（真人会「去哪看/改什么」）

> 先对齐产品现实：**有分层结构，但没有单一「总纲.md」文档型入口**——本轮必须验证「总纲心智」能否被现有能力覆盖；若不能，记为产品缺口并按 §1 闭环。

### 2.1 作者心智层 → 系统落点

| 作者心里的东西 | 系统落点（当前） | 真人验收时必须做的事 |
|----------------|------------------|----------------------|
| **书级总纲 / 为什么写** | 北极星 `NorthStarBar/Panel`（读者感受·情感弧·红线） | 建书后 10 分钟内写满；中途改一次红线，看后文是否受约束 |
| **全书结构总览** | 手稿根/卷 → **卡片墙 Corkboard / 大纲表 Outliner / 列表** | 用卡片墙写每章 synopsis；拖拽/排序；从墙跳进章 |
| **卷纲** | 卷节点 + 卷详情（排序等） | 建 ≥3 卷，填卷意图，排序可改 |
| **章纲 → 节拍 → 演绎 → 稿** | 章阶段 Tab：大纲 / 节拍 / 演绎 / 草稿 / 正文 | **每章至少完整走一轮阶段**（禁止跳过只灌正文） |
| **看台梳理逻辑** | 顶栏：**图谱 / 时间线 / 仪表盘**；另有概览/进度（视入口） | **每写下一章前强制看板仪式**（§4） |
| **设定圣经** | 入口轨·设定：角色/势力/物件/术语/规则/关系/命题… | 主角色深档 + 关系边 + 至少 1 条私密/限知 |
| **伏笔账本** | 工艺·伏笔（本章要收/新埋/超期/仍悬/已回收） | 埋→悬→收全生命周期；超期必须在看板上可见 |
| **母题** | 工艺·母题（本章/卷/书/不足/重复） | 登记 ≥1 母题，跨章触及 |
| **素材与参考** | 素材库 + 导入 + 网络；质量·参考作品 | 导入真实参考段落，写作时召回并**写进正文** |
| **限知/场景真相** | 演绎能力树 + 写作帧 | 至少 2 章不同 POV；故意测「读者知/角色不知」 |
| **改稿与返工** | 主编意见→提案；版本面板恢复；体检→修订种子 | §5 返工剧本全部跑一遍 |
| **质量看台** | QC、仪表盘质量区、十维评估/质量审阅 | 存稿后刷新；人工对照是否可信 |
| **搜索/校验** | 检查·搜索 / 校验 | 全局搜人设关键词；跑一次校验并处理结果 |

### 2.2 全量功能强制清单（F 矩阵）

每项状态只能是：`未测 | 能用 | 好用 | 用得上 | 摆设 | 缺口 | 已修`

**A. 作品与导航**  
作品库创建/切换 · 归档恢复 · 顶栏作品切换 · 主题深浅 · 命令面板/搜索（若有）

**B. 手稿结构**  
建卷 · 建章 · 章信息（标题/标签/归属） · 卷排序 · 卡片墙 synopsis · 大纲表 · 拖拽/重排 · 未分卷章 · 归档箱

**C. 北极星与意图**  
书级北极星读写 · 常驻条可见 · 偏离/红线相关提示（有则测） · 改意图后的生成差异

**D. 章阶段流水线**  
大纲讨论与落库 · 节拍拆分 · 演绎（场景真相/角色限知/冲突/可公开） · 草稿提案 · 正文接受 · 阶段切换后主编上下文是否切换

**E. 主编协作**  
讨论留痕（刷新仍在） · 动稿提案 · diff/接受/弃用/再议 · 审批 Run（世界状态变更类） · 停止 Run · 线程上下文绑定

**F. 设定库**  
角色全字段+弧光锚+能力+质变 · 关系 · 势力/地点/物件/术语/规则 · 命题/秘密/读者知 · 保存失焦/显式保存一致性

**G. 工艺**  
伏笔全生命周期 · 母题登记与本章触及 · 声音/弧光（有 UI 则测）

**H. 素材**  
手工素材 · 文件/粘贴导入 · 预览确认 · 检索召回 · 插稿 · 网络视图 · 反向溯源

**I. 横切看板**  
图谱 · 时间线 · 仪表盘（弱章/伏笔/质量缓存） · 概览/进度 · 从看板跳回章/对象

**J. 质量与参考**  
章 QC · 质量缓存刷新 · 十维/质量审阅 · 参考作品指纹/对照 · 因果/独立场景理由

**K. 版本与返工**  
存档点 · 回看 · 恢复到此版本 · 多稿对比（若有） · 本地暂存恢复横幅 · 改设定后下游一致性

**L. 检查**  
搜索 · 校验结果可执行（能点到问题处）

> **通过线**：A–L 无「未测」；「摆设」必须进保/砍/藏建议；「缺口」必须进缺陷台账 + 是否 P0/P1。

## 3. 测试人格与作品规格

### 3.1 三人格（分日或分半日）

| 人格 | 目标 | 重点 |
|------|------|------|
| **从零作者** | 一句话钩子 → 第 1 章成稿 | 可发现性、空状态、北极星、卡片墙 |
| **连载作者** | 10 章 / 约 3–5 万字可对外读草稿 | 看板仪式、阶段流水线、伏笔、质量 |
| **返工作者** | 在第 5–7 章后故意推翻设定 | 改圣经、回滚正文、版本、仪表盘告警 |

### 3.2 作品规格（推荐）

- 新书名：`《真人评测·YYYYMMDD》`（隔离 ID）  
- 结构：**3 卷 · 10 章**（短验可 5 章，但**返工剧本仍必须做**）  
- 类型建议：限知悬疑/志怪（逼出 POV、秘密、伏笔）  
- 字数：每章 **1500–3000** 即可（质量优先于注水）；深验可拉到 4000+  
- **禁止**使用旧验收书 `book_d0bb19e9` 作为主证据（可对照缺陷是否复发）

## 4. 主旅程：真作者日程（按时间，不是按模块）

### 阶段 0 · 环境与基线（≤ 30 min）

1. 确认 `git` 在目标 `main`，前后端为**当前 HEAD** 进程（防陈旧进程）  
2. 记录 `/health`、`/capabilities`、Hermes runtime、磁盘降级文案是否诚实  
3. 建目录：`artifacts/e2e-YYYYMMDD-<work_id>/`（模板见 §8）  
4. 打开旧缺陷台账，列「开测必回归」P1 清单  

**输出**：`00-runtime-baseline.md`

---

### 阶段 1 · 总纲与骨架（作者开书的前 1–2 小时）

> 真人不会一上来就写正文。必须先有「书要去哪」。

#### 1.1 建书与北极星（总纲 L0）

- UI 建书 → 进入工作台  
- 打开/填写 **北极星**：读者感受 · 情感弧 · 红线（≥3 条可检验红线）  
- 用主编对话：「把这本书的总纲收成一页：主题、核心冲突、结局承诺、不可写的东西」  
  - 若系统**无法把对话沉淀为可回看的书级总纲对象** → 记 **缺口：书级总纲载体**（对照 Scrivener Project Notes / Story Bible 惯例）→ 走 §1  

#### 1.2 卷章骨架（总纲 L1）

- 建 3 卷，写清每卷「读者离开本卷时应相信什么」  
- 卡片墙为 10 章各写 **1 句 synopsis + 计划 POV**  
- 大纲表扫一眼节奏（信息章/高潮章是否扎堆）  
- 拖拽或排序：故意调换两章，确认树/墙/写作台一致  

#### 1.3 骨架级看板仪式

- **时间线**：是否空？空是否可接受？有事件后是否反映计划？  
- **仪表盘**：是否显示「还没得检」而非假绿？  
- **图谱**：至少应在建完 2 角色后出现边  

**输出**：`02-step-journal` 中 STEP-1-xx；截图卡片墙全景  

**硬门**：没有可回看的书级意图（北极星或等价）+ 10 章 synopsis → 不得进入连写。

---

### 阶段 2 · 设定圣经最小完备（开写前）

按「下一章会用到」填充，禁止一次性填表地狱：

| 优先 | 内容 | 验收 |
|------|------|------|
| P0 | 主角 + 对手/关键配角 | 弧光锚 Ghost/Lie/Truth/Want/Need 可保存回读 |
| P0 | 1 条核心关系边 | 图谱可见 |
| P0 | 1 条世界规则（有代价） | 后文写作是否被约束 |
| P1 | 1 私密命题 + 读者知/角色知边界 | 限知演绎可引用 |
| P1 | 1–2 条计划伏笔（埋设章/回收窗） | 伏笔目录可见 |
| P2 | 素材：贴 1 段真实参考（口吻/资料） | 召回并进正文 |

**填写方式铁律（P8）**：

- 角色/关系/规则/伏笔/**只允许**：「请登记…」→ 审批提案 → 只读面板回读  
- 北极星/**只允许**对话设定后批准写入  
- **禁止**打开设定库逐字段失焦保存；若系统逼你手填 → **立即 STOP**，记 F-xx 缺陷并按改造方案修，不得用表单凑合继续  

**输出**：`01-feature-value-matrix` 中 F 设定行开始变绿  

---

### 阶段 3 · 单章黄金闭环（第 1 章，不跳阶段）

对第 1 章严格执行（**全对话，无业务表单**）：

```
大纲 tab → 主编讨论 3–5 句大纲 → 写入提案批准 → 只读回看
  → 节拍：对话拆拍 → 批准写入
  → 演绎：对话定场景真相/限知 → 批准写入
  → 草稿/正文 → 动稿提案 → 人工读 → 意见再写（至少 1 次）
  → 接受存稿 → QC → 人工评分卡
  → 版本：对话或决策控件打存档点「ch1-v1」（非填表）
```

**认知走查记录**每步四问（§1.3）。  

**硬门**：提案→接受→刷新后正文仍在；QC 与正文一致。

---

### 阶段 4 · 连写引擎（第 2–N 章）：「看板 → 决策 → 写」

> 这是 v2 的核心：**下一章不是拍脑袋写，而是看台驱动。**

#### 4.1 章前强制仪式（每章 10–20 min，写进 journal）

每开始第 N 章前，按顺序：

| 序 | 看台 | 作者要回答的问题 | 系统应提供 |
|----|------|------------------|----------|
| 1 | **卡片墙/大纲表** | 本章 synopsis 是否仍成立？前后章信息梯度？ | 可编辑 synopsis，跳转本章 |
| 2 | **伏笔工艺** | 本章要埋什么、必须收什么、有无超期？ | 本章要收/新埋/超期列表 |
| 3 | **仪表盘** | 哪章弱？质量缓存是否过期？ | 弱章跳转、刷新入口 |
| 4 | **时间线**（有事件后） | 时间是否打架？ | 事件落点 |
| 5 | **图谱** | 关系是否支持本章冲突？ | 跳到角色/关系 |
| 6 | **北极星** | 本章是否在情感弧正确位置？ | 常驻条可见 |

仪式输出写进模板：

```markdown
### 章前仪式 · 第 N 章
- 卡片墙结论：
- 伏笔决策（埋/收/拖）：
- 仪表盘警报：
- 设定是否要先改：
- 本章成功标准（3 条可检验）：
```

**若看台无法回答上述问题 → 记缺口/缺陷，§1 闭环后再写正文。**

#### 4.2 章内流程（可快可慢，但不可缺）

1. 阶段流水线（至少大纲+演绎+正文；节拍可在熟手章合并但需记录「为何跳过」）  
2. 动稿 → 提案 → **人工朗读式审**（限知、注水、OOC）  
3. 至少一次 Feedback：「更冷/信息晚给/删解释」→ 再提案  
4. 存稿 → QC → 质量评分卡  
5. 设定回写：本章新事实是否进圣经/事件/伏笔状态  

#### 4.3 章后简短复盘（5 min）

- 实际用到的功能列表  
- 本想用但找不到的  
- 绕开系统改用外部笔记的（严重信号）  

---

### 阶段 5 · 返工剧本（强制，写到第 5–7 章后插入）

> 真人后半程**一定**会改设定。不测返工 = 验收作废。

#### 剧本 R1 · 逻辑不成立，改设定

1. 选定一个已写入正文的设定（例：某能力无代价 / 某关系定性错误）  
2. 在设定库**改正**并保存  
3. 打开 **仪表盘/校验/图谱**，看是否提示正文可能过期  
4. 用主编：「第 X–Y 章因设定变更需要哪些返工」  
5. 对受影响章：提案修订或恢复旧版本再改  
6. **验收**：改后设定与正文一致；伏笔/关系边不残留旧语义  

**期望能力**（没有则记 P1 缺口并研究）：

- 设定变更 → 受影响章节列表  
- 或至少：搜索旧表述 + 版本恢复 + 批注修订路径清晰  

#### 剧本 R2 · 总纲/北极星改航

1. 修改北极星一条红线或情感弧终点  
2. 检查后续未写章的 synopsis 是否在卡片墙可批量调整  
3. 已写章是否出现偏离提示；用意见流改一章对齐新北极星  

#### 剧本 R3 · 结构调整

1. 两章对调或合并意图（卡片墙 + 目录）  
2. 确认 seq/卷归属/大纲 synopsis 不乱  
3. 时间线与伏笔回收窗是否需手工改，系统是否提示  

#### 剧本 R4 · 版本回滚

1. 对一章连续两稿，打存档点  
2. **恢复到此版本**，编辑器与库一致  
3. 多稿对比（有则用）做一次「选此稿」  

#### 剧本 R5 · 误写限知后修复

1. 故意（或真实翻车）写出焦点不可知信息  
2. 演绎/校验/找泄漏类能力是否抓住  
3. 修订后 QC/人工通过  

---

### 阶段 6 · 全功能扫尾日（专门「逛功能」）

连写结束后，用清单 §2.2 **逐项点名**：

- 每项一个**有写作后果**的任务（不能只打开看看）  
- 记：主动用 / 提示后用 / 被迫用 / 绕开 / 摆设  
- 质量·参考作品：绑定 1 个参考，看评估是否改变改稿决策  
- 导出/设置：能带走正文与关键元数据否  

**输出**：填满 `01-feature-value-matrix.md`

---

### 阶段 7 · 结案

1. 全文导出到 `manuscript/`  
2. 人工通读：主题是否兑现、伏笔是否空头、人物是否漂移  
3. 写 `09-author-verdict.md`（§9 五问 + 保改砍）  
4. 缺陷台账优先级排序；P0/P1 必须有修复结论或明确延期理由

## 5. 质量标准（文学 + 系统）

### 5.1 章级评分卡（每章必填）

| 维 | 1–5 | 说明 |
|----|-----|------|
| 可读性 | | 句子是否肉身、是否 AI 腔 |
| 人物声音 | | 是否可辨认说话的人 |
| 信息控制 | | 限知、披露节奏 |
| 情节推进 | | 本章是否改变人物处境 |
| 跨章衔接 | | 与前后章因果/情绪 |
| 系统辅助感 | | 没有系统是否写不出这章 |

另记：QC 五类计数、字数、POV、是否阶段跳过。

### 5.2 书级硬门

- 主路径 P0 为零  
- ≥70% 章人工综合分 ≥ 3.5  
- 伏笔：计划回收的在终局前关闭或显式「弃坑」记录  
- 返工剧本 R1–R4 全部执行并有结论  
- F 矩阵无「未测」  

### 5.3 书级软门

- 作者主观：是否愿意用它写下一本自己的书  
- 「绕开系统」次数 ≤ 3（高则交互失败）  
- 看板仪式是否真的改变了至少 3 次情节决策
