## 0. 一句话

在 demo 上**新建隔离书**，以 **写作导演（Director）五站** 为时间轴，以 **对话→提案→UI 批准** 为唯一写路径，真实连载写出约 **5 万字可接受正文**；过程中验证旅程「在哪 / 下一步 / 继续」全链路可用；**工艺卫生门闩 + 内容质量 + 人工读感** 双轨通过；无未关闭 P0/P1。

**5 万字是连载压力与规模目标，不是唯一 PASS 条件。**

## 3. 完成定义与 PASS 公式

### 3.1 完成定义（人话）

作者（或代理）能从空书开始，主要依靠：

1. 顶栏 **旅程** / 进度胶囊 / **继续**  
2. 主编 **聊天**  
3. **批准 / 接受** 真实点击  

走完五站，得到一本约 5 万字、辅信可审计、读感可接受的连载草稿，且导演进度与真实阶段一致。

### 3.2 PASS 公式（硬）

```text
旅程总 PASS
  ⇔ 导演线  ∧  工艺卫生线  ∧  质量线  ∧  规模线  ∧  缺陷线
```

| 线 | 条件 |
|----|------|
| **导演线** | 五站均有真实推进证据；胶囊与 `GET /workflow/snapshot` 在抽检点不与 pilot/章状态明显矛盾；「继续」在 ≥5 种不同 `pilot_state` 下可用且无 P0 失灵 |
| **工艺卫生线** | 书级 **GATE-A** 绿；每一「成稿章」**GATE-B ∧ C-Det 硬项** 绿（skip 规则遵循 craft-first v3） |
| **质量线** | 系统 ContentQuality / QC 无未处理阻断；**人工读感**无阻断项（假通顺、空戏、纯说明书体 = 不通过） |
| **规模线** | 正文累计字数 ∈ **[45000, 55000]**，分章可审计；**禁止**仅靠重复句/目录灌水 |
| **缺陷线** | 无未关闭 **P0/P1**；P2 有台账与是否结案说明 |

### 3.3 明确禁止

| 禁止 | 原因 |
|------|------|
| 仅因 `word_count≥50000` 宣布 PASS | craft-first v3 反面教训 |
| 业务表单 / REST 静默灌设定·大纲·正文冒充路径 | 测到假路径 |
| API `saveChapter` / 静默 approval 代替 UI 批准 | 融合规程 M7 |
| 用旧验收书当主证据 | 污染对照 |
| 试写 sandbox 计入旅程 PASS | 门闩作用域 |
| 在 Grok 运行机 `npm ci` / 起临时 Surreal 全量集成 | 主机资源规则 |

| 项 | 规格 |
|----|------|
| 隔离 | 全新作品，标题 `旅程五站·YYYYMMDD` |

| 会话策略 | 建议按卷 fork「卷 N 会话」；依赖已交付的父史边界 / 单飞创建 |

## 6. 导演契约（验收时对照）

`GET /api/workflow/snapshot?work=<slug>&seq=<n>`（P0 合成，真源 `scribe3/director.py`）。

### 6.1 五站 ID

| id | 标签 | 启发式就绪（代码 P0，验收时知悉局限） |
|----|------|----------------------------------------|
| `intent` | 立项 | 北极星读者感/情感弧/红线有内容 |
| `world` | 世界底座 | 角色数 ≥ 1（**偏松**；本方案站门闩更严） |
| `structure` | 结构 | 至少 1 章存在 |
| `serialize` | 连载推进 | 有章且前站满足后为 current |
| `ledger` | 账本健康 | P0 **不自动抢 current**；本方案仍要求人工完成账本站 |

### 6.2 每条 snapshot 必记字段

```text
work, journey.current_station, journey.stations[].status,
chapter_lane.seq, chapter_lane.pilot_state, chapter_lane.phase_hint,
next_step.id, next_step.title, blockers[], suggested_prompt
```

### 6.3 导演线抽检规则

| 时机 | 动作 |
|------|------|
| 每站结束 | 存一份 snapshot JSON 摘录 + 旅程页截图 |
| 每成稿章后 | 存 `pilot_state` / next_step 是否与刚完成动作一致 |
| 「继续」 | 记录：是否预填聊天、是否切到合理 phase/章；失败 = 缺陷 |

**已知 P0 局限（不因此免测，但缺陷分级时区分）：**

- `world_ok` 仅「≥1 角色」，本方案仍要求最小圣经  
- `ledger` 不自动 current  
- 无模型侧 director tool（P1 non-goal）

## 7. 主旅程：五站详细步骤

每站统一四件套：**入口 → 作者意图 → 系统应发生 → 站门闩**。  
入口优先级：`旅程页 / 胶囊 / 继续` → 失败再记缺陷并允许兜底导航（兜底次数计入体验债）。

---

### 站 0 · 基线（≤ 30 min）

| 步骤 | 动作 | 证据 |
|------|------|------|
| 0.1 | 确认 demo 可登录；`/api/health` `/api/ready` | `00-runtime-baseline.md` |
| 0.2 | `GET /workflow/snapshot`（任意已有书或新书后）可用 | JSON 摘录 |
| 0.3 | 顶栏「旅程」可打开，布局可交互 | 截图 |
| 0.4 | 创建证据目录与缺陷台账空表 | 目录 |
| 0.5 | 列出开测必回归旧 P1（若有） | `00-regression-checklist.md` |

**硬门：** 登录失败 / snapshot 500 / 旅程页白屏 → **停**，先修部署。

### 站 1 · `intent` 立项（0.5–1 日）

#### 入口

打开旅程 → 看 next_step → **继续**。

#### 作者意图（对话示例）

- 「新建一本书《旅程五站·日期》，类型限知志怪。」  
- 「北极星：读者应感到……情感弧是……红线：不写……、必须……、禁止……」  
- 「请把总纲收成可回看的书级意图。」

#### 系统应发生

- 作品创建成功并进入工作台  
- 北极星/意图可回读（对话沉淀 + 批准）  
- snapshot：`intent` 可 done，next 指向 world 或补意图  
- 「继续」预填合理 prompt  

#### 站门闩

- [ ] 书级意图可回看（读者感 **或** 情感弧 + **≥3 条可检验红线**）  
- [ ] 未依赖业务表单才能立项  
- [ ] 导演观察者记录 1 份 snapshot  

**输出：** `01-intent.md` + `screenshots/intent-*`

#### 开写前最小完备（硬）

| 优先 | 内容 | 回读验收 |
|------|------|----------|
| P0 | 主角 | 动机/欲望/需求或等价弧光锚可回读 |
| P0 | 对手或关键配角 | 同上 |
| P0 | 1 条核心关系边 | 图谱或关系列表可见 |
| P0 | 1 条世界规则（含代价） | 规则正文可回读 |
| P1 | 1 私密 / 限知边界 | 后文至少 1 章引用 |
| P1 | 1–2 条计划伏笔（埋章/收窗） | 伏笔目录可见 |

#### 路径

旅程继续 → 聊天补充 → **UI 批准写入** → 设定/图谱回读。

#### 站门闩

- [ ] 上表 P0 全满足

### 站 4 · `serialize` 连载推进（主工期 3–6 日）

#### 4.1 章循环 SOP（每章强制）

```text
S1  打开旅程 / 读胶囊 next_step.id 与 title
S2  点「继续」→ 确认聊天预填 / 舞台跟焦（记成功或缺陷）
S3  对话推进大纲 → UI 批准 → 回读大纲
S4  节拍 或 演绎/限知（关键章两者都做：第 1、3、5、7、9 章强制演绎或限知帧）
S5  草稿生成/修订 → 接受为正文
S6  跑章级 GATE-B + C-Det（或 craft_gate_cli / 等价）
S7  质量抽检（系统 QC 一次；人工读感对奇数章必做）
S8  看板仪式（每章至少 1 项：时间线 / 伏笔账本 / 图谱 / 仪表盘）
S9  写 chNN.md journal + 追加 director-trace
S10 累计字数更新；未达标则修订或规划下章字数
```

#### 4.2 检查点（字数 × 横切）

| 检查点 | 累计正文约 | 强制动作 |
|--------|------------|----------|
| CP1 第 2 章后 | ~1.0 万 | **X1 返工**：改 1 条规则或主角谎言，对话+批准，确认约束或告警 |
| CP2 第 5 章后 | ~2.5 万 | **X2 限知** 已发生；**X3 会话 fork** 续写 1 次 |
| CP3 第 8 章后 | ~4.0 万 | 旅程仍应在 serialize；抽检 3 章 pilot 与导演一致 |
| CP4 第 10 章后 | ~5.0 万 | 进入站 5；字数落在 ±10% |

#### 4.3 单章 journal 模板（`04-serialize/chNN.md`）

```markdown
# 第 N 章

- 日期 / 操作者：
- 标题 / POV：
- 目标字数 / 成稿字数：
- snapshot.next_step（开写前）：
- 「继续」结果：
- 大纲批准：是/否
- 节拍或演绎：
- 正文接受：是/否
- GATE-B / C-Det：
- 看板仪式做了什么：
- 缺陷 ID（若有）：
- 读感一句：
```

#### 站门闩

- [ ] ≥10 章接受为正文  
- [ ] 累计字数 ∈ [45000, 55000]  
- [ ] 每成稿章 journal 齐全  
- [ ] 「继续」成功样本 ≥5（不同 pilot_state）  
- [ ] X1–X3 完成  

**输出：** `04-serialize/ch01.md` … `ch10.md` + `08-wordcount-rollup.md`

## 9. 缺口即改（运行制度）

### 9.1 触发即停

- 2 分钟找不到下一步  
- 必须查代码/调 API 才能完成作者意图  
- 表单直填才是唯一活路  
- 导演与 pilot 严重矛盾且无法解释  
- 存稿后刷新丢失  

### 9.2 闭环

```text
STOP → 缺陷台账（现象/意图/步骤/证据）
  → RESEARCH（设计文档 + 代码真源）
  → DECIDE 最小修复
  → FIX + 定向测
  → 同路径回归
  → RESUME（禁止「先写完再修 P0/P1」）
```

### 9.3 缺陷分级

| 级 | 定义 | 处置 |
|----|------|------|
| **P0** | 主路径不可完成（建书/存稿/登录/旅程全挂/批准无效） | 立即修，停写 |
| **P1** | 返工/阶段/导演导航断，或静默数据损坏 | 立即修，停写 |
| **P2** | 能完成但路径深、反馈差 | 台账；相关章前至少处理 1 次 |
| **P3** | 文案/视觉 | 台账，不阻断 |
