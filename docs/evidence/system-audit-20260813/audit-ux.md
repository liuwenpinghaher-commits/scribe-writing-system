# 写作工具 UX 审计（只读）

- 仓库：`/home/admin/projects/scribe-writing-system`
- 北极星：**像在写字，不像填验收单。作者从打开书到改完一句应最短。**
- 范围：章工作台 / 正文台 / 契约门 / 双灯 / 选区改写 / 旅程与四栏
- 禁则：本稿不改代码、不加设置页；只记现状与更合理形态。

### F-U01 点第五章先进「大纲门」，第一次开写超过 4 次

- 角度：易用
- 严重度 **P1**（逐步点击 > 4）
- 现状：进书后栏 3 空态文案是「在左侧选择章节开始写作」。目录点章时 `chapterNodeFrom` **写死 `phase: 'outline'`**，`DetailPane` 原样传给 `ChapterStudio.initialPhase`。换章 effect 优先吃 `initialPhase`，**压过** 已持久化的正文阶段。新用户点第五章，先落到只读大纲页（主钮「让主编写入大纲」），不是稿纸。
- 不合理：打开书想写第五章，系统先把人送进「开写前材料」流水线。想自己落笔还要再点「正文」，空章还会亮「不建议开写」。
- 更合理：点章 = 打开稿纸（或上次停在哪就回哪）。大纲/节拍/真相是稿纸旁可展开的一张纸，不是进门闸。
- 不改的代价：每次换章都像重新办开工手续；作者学会「躲开系统」而不是「用系统写」。
- 证据：
  - `scribe3/web/src/layout/ManuscriptDirectory.jsx`：`phase: 'outline'`
  - `scribe3/web/src/DetailPane.jsx`：`initialPhase={node.phase}`
  - `scribe3/web/src/ChapterStudio.jsx`：`normalizePhase(initialPhase || readStoredPhase(...) || 'final')` —— `initialPhase` 有值时 **不读** 本地上次阶段
  - 同文件注释已写「不能让目录默认 outline 覆盖作者刚点开的正文」，实现与注释相反

**逐步点击（已登录、书已存在、第五章已建、从作品库点开该书）：**

| # | 作者动作 | 系统给什么 |
|---|----------|------------|
| 1 | 点开这本书 | 四栏壳；栏 3「请选手稿章节」；顶栏旅程/图谱/时间线/仪表盘 |
| 2 | 点栏 2「第 5 章」 | **大纲**只读空页 +「让主编写入大纲」+「聊聊怎么写」+ 五阶段页签 +「进度与准备」 |
| 3 | 点页签「正文」 | 稿纸终于出现；若契约缺项 → 黄条 **「不建议开写」** +「去补」 |
| 4 | 点「本次关闭」或无视横幅点进编辑器 | 才能打第一个字 |
| 5+ | 若想改一句 | 还要划选 →「改这段」→ 右栏发送 → 等整章 assemble → 接受候选 |

**结论：打开书到能改一句，最少 4 次导航 + 1 次划选发送，稳超 4。标 P1。**

若作者听从界面暗示走齐套：大纲主编写入 → 批准 → 节拍 → 批准 → 演绎 → 草稿/正文，是 **两位数点击**，验收单味。

### F-U02 主按钮是「让主编 / 过门 / 存为正文」，不是「写 / 改这句」

- 角度：易用
- 严重度 **P0**
- 现状：各阶段 `variant="primary"` 几乎全是合同动作：
  - 大纲：`让主编写入大纲`
  - 节拍：`让主编写入节拍`
  - 草稿：`采用为正文`
  - 正文顶栏：`存为正文`
  - 章节信息：`让主编写元数据`、`去补大纲/节拍/演绎`
  - 旅程胶囊：`继续`
  - 右栏写作槽：`发送`（空态建议第一条是「本章这样展开…主编写整章」）
- 不合理：稿纸上的「改这段」只是选区气泡里的小字，不是主路径。作者眼睛先被齐套、推进阶段、存档、终选吸走。
- 更合理：稿纸中央永远是「写下去 / 改这句」。主编是旁边的人，不是大门保安。保存是后台/⌘S，不是最大的蓝钮。
- 不改的代价：产品自我介绍成「工艺验收台」；新用户以为必须先过主编合同才能写。
- 证据：`ChapterStudio.jsx` OutlineTab/BeatsTab/DraftTab 的 `Btn variant="primary"`；`WriteLayout.jsx` 顶栏末钮「存为正文」；`WriteChat.jsx` `SUGGESTS[0]`「主编写整章」；`WorkflowCapsule.jsx`「继续」

### F-U03 双灯 + GATE 横幅制造假完成 / 假阻塞

- 角度：易用
- 严重度 **P1**
- 现状：同一章上叠多层「过没过」语言，口径互不相同：
  1. **契约软横幅**（正文顶）：「开写前材料 / 写完对照」+ **「不建议开写」**（可关本次会话）
  2. **章节信息清单**：`还不齐 · 不建议开写` / **`材料够了，可以开写`**
  3. **双灯芯片**（存稿后）：`可开写` / `材料未齐` + `可读：机判过关，请通读确认`
  4. Toast：「机判可读，请通读后点**「确认给读者」**」
  5. 切到正文 toast：「章前契约未齐……不建议开写；存实质正文仍可能被工艺门拦截」
  6. 探索模式条：「可以先存草稿；正式定稿前仍须补齐」
- 不合理：
  - **假完成**：「材料够了，可以开写」「机判过关」读起来像章写完了 / 可以连载。`readerReadyGate.js` 自己写了「不把 `lamps.reader.ok` 单独渲染成可连载」，但又用「可读：机判过关」这种准完成语。
  - **假按钮**：黄灯 toast 叫人点「确认给读者」，**正文台没有这个按钮**。只有芯片和「可宣称给读者」旁注。
  - **假阻塞**：「不建议开写」看起来像红灯，实际不拦聊天、不拦进编辑器；真拦在 **保存正式正文 / 定稿 stamp**。作者分不清哪盏灯是建议、哪盏会吞稿。
  - 存完稿还亮「可开写」——人已经在写了，灯还在说「你可以开始」。
- 更合理：写作中只保留一句人话：「这段还缺大纲/节拍，存正式稿时可能被拦」或「这句有 AI 腔」。绿灯留给作者自己点「这章给读者」；机判永远不说「过关」。
- 不改的代价：作者为了把灯变绿去填表；或以为绿了就能发；或找不到「确认给读者」而以为坏了。
- 证据：
  - `ChapterStudio.jsx` `ContractSoftBanner`：`不建议开写`
  - `ChapterMetaPane.jsx`：`材料够了，可以开写` / `还不齐 · 不建议开写`
  - `readerReadyGate.js`：`可读：机判过关，请通读确认`、`可开写`
  - `WriteLayout.jsx` persist toast：「请通读后点「确认给读者」」——全仓无对应按钮（仅 `mayClaimReadable` 文本）

### F-U04 「改这段」仍走整章 assemble

- 角度：易用
- 严重度 **P1**
- 现状：
  - 正文气泡「改这段」只把选区塞进种子：`把这段改一下,给我 2-3 个候选:「…」`，并记下 `lastSel` 偏移。
  - 发送仍走 `POST /chat/write` → **`_assemble_write_instructions` 整章信封**（身份+协议+文风+反平庸+续写快照+秘密守卫+大纲/卷纲/事件驱动/演绎/工艺…）。
  - 协议示例默认围栏是 **`⟦PROPOSAL scope=chapter⟧`**；多候选才写 `scope=selection`。
  - 前端：`scope !== 'selection'` 就当整章草稿卡；`applyProposal` 对 `scope=chapter` **整章替换**。
  - 草稿页「改这段」走 DiscussionDock 的同一 `chatWrite`；落地是整段填入/追加，除非锚点命中才替换选中段。
  - 编排目录 `prose.revise` 匹配「改这段」，`phase_hint: "draft"`，旅程/hard 跟焦时可能把人从正文拽到草稿。
- 不合理：作者改一句，系统编译整章圣经再让模型「动稿」。慢、贵、容易交整章。这不是改字，是开一次章级生产线。
- 更合理：选区改 = 只带前后各 N 句 + 本章大纲一句 + 限知一句；强制 `scope=selection`；接受后只替换选区。整章生成另开「写整章」。
- 不改的代价：改一句等整章；误接受会毁整章；作者不敢用「改这段」。
- 证据：
  - `ProseEditor.jsx` 气泡「改这段」→ `onDiscuss({ text, from, to, intent:'edit' })`
  - `WriteLayout.jsx` `discussSel` / `onProposal`（selection → 候选，否则整章卡）
  - `scribe3/api/routers/write.py` `chat_write_post`：无选区短路径，一律 assemble
  - `write_assemble_blocks.py` `_write_protocol_block` 默认示例 `scope=chapter`
  - `orchestration/catalog.py` `prose.revise` → `phase_hint: draft`

### F-U05 合同主栏与大纲 / 节拍 / 真相是三套表

- 角度：易用
- 严重度 **P1**
- 现状：同一份 `synopsis` / `beats` / `scene_truth` 至少三处出现：
  1. **五阶段页签**（大纲 / 节拍 / 演绎）：真编辑面（大纲只读+主编；节拍可手改 GCD；演绎整页）
  2. **章节信息（合同主栏）**：再摘要一遍 + 齐套红点 +「让主编写…」+「深编」跳回 1
  3. **写完对照 / 事件驱动 / SoftCards / StageBoard**：又一套只读对照与阶段推进
  另有左栏「演绎」能力、辅助面简报/关联/评分卡/经验复盘、脉搏条张力/因果。
- 不合理：作者要改「这章讲什么」，不知道该点页签、章节信息、还是让主编。三套表同步靠刷新，认知是「填三张验收单」。
- 更合理：**一份纸**。稿纸上方一行本章意图（大纲一句 + 3 拍折叠）。要深编再展开。章节信息不应再复制字段，只做「还缺什么」一句。
- 不改的代价：改一处漏两处；齐套灯与页签内容打架；新用户在页签和「章节信息」之间空转。
- 证据：`ChapterMetaPane.jsx` 清单 + 摘要区与 `OutlineTab`/`BeatsTab`/`DeduceStage` 字段同源；`ChapterSoftCards` 再叠 precheck/distill；`StageBoard` 与 ObjectFrame 五页签职责注释互相解释（「页签切面 / 这里推进」）——作者仍看到两套阶段。

### F-U06 旅程胶囊 / 四栏 / 系统图挤占主路径，该进高级

- 角度：易用
- 严重度 **P2**
- 现状：打开书默认四栏（入口轨 | 目录 | 详情 | 主编）。顶栏常驻：旅程、图谱、时间线、仪表盘、搜索、**旅程胶囊「继续」**。章头还有简报/关联、信息密度「简/标/全」、章节信息、归档。系统中心是活地图 + GATE 标签 + 模块目录。
- 不合理：写一句之前先理解「导演旅程、编排工作包、layoutMode reading/collaboration、阶段机」。胶囊 `继续` 会跳章、切 phase、预填主编、`orchestrateBeforeSend`——像项目管理，不像摊开稿纸。
- 更合理：主路径两栏（稿纸 + 主编）。目录可折叠且默认窄。旅程/图谱/系统图/驾驶舱/收件箱进「高级」或 ⌘K，不进第一眼。
- 不改的代价：注意力被「下一步任务」劫持；`继续` 把人带离正在改的那句。
- 证据：`AppRail.jsx` `VIEWS`；`WorkflowCapsule.jsx` `applyWorkflowContinue`；`FourPaneShell.jsx` 四栏 + 旅程换位；`system/SystemHub.jsx` 活地图首页

### F-U07 正文顶栏是验收仪表盘

- 角度：易用
- 严重度 **P1**
- 现状：进入「正文」后，稿纸上方仍叠：作品意图条、六维脉搏、本章记忆引用、视角下拉、护栏芯片、今日字数、**探索**、**危险草稿**、保存▾（存档点/全量体检/反哺设定库/专注/字体）、**存为正文**。缺项时再加契约黄条、探索黄条、双灯芯片、体检卡。
- 不合理：落笔区被「过检控件」压到折线以下。探索/危险草稿是给工艺门的逃生舱，却和保存并列在第一眼。
- 更合理：稿纸全宽。意图/脉搏/护栏折叠进一行状态或高级。保存用 ⌘S + 脏点。探索/危险草稿不进主栏。
- 不改的代价：作者写一段要先扫一遍灯板；「像填验收单」在视觉上坐实。
- 证据：`WriteLayout.jsx` `center`：`NorthStarBar` + `PulseBar` + `ChapterMemoryRefs` + `topbarMid`

### F-U08 大纲不能手写，空字段只能「让主编」

- 角度：易用
- 严重度 **P0**（相对北极星）
- 现状：大纲 `禁止 api.patchChapter` 叙事直写；空态主路径是「让主编写入大纲」或「聊聊怎么写」。种子强制点名 `s3_patch_chapter_plan`、GATE-B B1、**禁止用保存正文完成脚手架**。作者改大纲 = 对话 + 审批，不能在纸上改一句。
- 不合理：写书的人不能在「大纲」格里打字。这是合同系统，不是稿纸。
- 更合理：作者随时可在本章意图里写/改；主编是加速器。审批只用于会改别人章节或世界设定的动作。
- 不改的代价：第五章第一件事不是写，是「请主编提交提案供我批准」。
- 证据：`ChapterStudio.jsx` OutlineTab；`chiefSeed.js` `SCAFFOLD_FORBID_SAVE` / `seedChapterOutline`

### F-U09 五阶段时钟强迫「先齐套再写」

- 角度：易用
- 严重度 **P1**
- 现状：`PHASES` 固定 大纲→节拍→演绎→草稿→正文。切到草稿/正文会 toast 软门。`StageBoard` 推进可 `blocked`（材料未齐）。采用草稿为正文走 `saveChapter`，工艺前置失败会整段失败文案。
- 不合理：真人写作是搅在一起的：先写一段再补节拍。五页签把搅动拆成流水线。草稿和正文还是两套编辑器。
- 更合理：一个稿纸。草稿/正式只是保存语义。大纲三句钉在页眉，缺了提示，不换页。
- 不改的代价：作者为过阶段而填节拍；或永远停在草稿躲避正文护栏。
- 证据：`ChapterStudio.jsx` `PHASES` / `setPhaseP` / `DraftTab.adopt`；`StageBoard.jsx` `r.blocked`

### F-U10 「改这段」与「写整章」话术边界糊

- 角度：易用
- 严重度 **P2**
- 现状：气泡写「让主编改这段(出 2-3 候选)」。协议同时教模型整章围栏。空态建议第一条就是写整章。`sendPostCheckToChief`：「请据此修订本章」。体检主钮「让主编修这章」。
- 不合理：局部意图被整章话术淹没；模型按最大范围交稿。
- 更合理：改这句 / 续写一段 / 重写整章 三个互斥动作，按钮和协议各写死 scope。
- 不改的代价：F-U04 在产品语言层被鼓励。
- 证据：`WriteChat.jsx` SUGGESTS；`WriteLayout.jsx` `sendPostCheckToChief`；`_write_protocol_block`

## 最易用主路径草图（≤6 步，其余折叠）

1. **打开书** → 直接上一章稿纸（记住章+光标；不要先旅程、不要先大纲页）。
2. **打字**。不必先齐套。缺大纲只在页眉一行灰字：「本章还没写清要发生什么」。
3. **划一句 →「改这句」** → 右栏已预填，回车即出 2～3 个**只替换该句**的候选。
4. **点候选采用**。⌘S 默存；不叫「存为正文」。
5. **要让主编起整章**：页眉「让主编写这一章」（次要）。
6. **要给读者**：一个明确按钮「这章可以给读者了」（人签，不是机判绿）。

**折叠进「更多 / 高级」（默认不进第一眼）：**

- 五阶段页签、StageBoard、章节信息合同清单、SoftCards
- 旅程胶囊 / 旅程视图 / 图谱 / 时间线 / 仪表盘 / 系统活地图
- 双灯、GATE 文案、探索/危险草稿、全量体检、反哺设定库
- 选择环、Pilot 驾驶、收件箱、评分卡、经验复盘
- 四栏入口轨里的演绎/伏笔/母题/校验（写的时候用稿纸旁引用，而不是换入口）

## 七问逐条答

### 1. 新用户第一次写第五章要点几次？超过 4 次标 P1。

**要超过 4 次，标 P1。** 见 F-U01。

从打开书到能在第五章改一句：

1. 点开这本书  
2. 点目录「第 5 章」（落到**大纲**，不是稿纸）  
3. 点「正文」  
4. 关掉「不建议开写」或点进编辑器  
5. 划选 →「改这段」→ 发送  

只想自己打字也是 1–4；一用主编改句就是 5+。走齐套主钮则远超。

### 2. 主按钮是写/改这句，还是过门/让主编/材料齐套？

**是过门 / 让主编 / 材料齐套 / 存为正文。** 见 F-U02、F-U08。

「改这段」只活在选区气泡里，不是任何页面的 primary。章节信息、大纲、节拍的主 CTA 全是「让主编写…」和「去补」。旅程主 CTA 是「继续」。正文主 CTA 是「存为正文」。

### 3. 双灯、GATE 横幅是否制造假完成？

**是。** 见 F-U03。

- 「材料够了，可以开写」「机判过关」= 假完成语。  
- 「不建议开写」= 假红灯（软提示），真闸在存正式稿。  
- 「请点确认给读者」= **假按钮**（UI 不存在）。  
- 双灯「可开写」在已开写后仍亮 = 阶段语义错位。

### 4. 「改这段」是否仍整章 assemble？

**是。** 见 F-U04。

前端带了选区偏移和 selection 候选卡，但请求仍是章级 `_assemble_write_instructions`。协议默认教 `scope=chapter`。模型若交整章，接受即整章覆盖。编排还把「改这段」标成草稿阶段修订域。

### 5. 合同主栏与大纲/节拍/真相如何避免三套表？

**现状没避免，是三套。** 见 F-U05。

避免法（只建议，不实施）：

- **唯一真身** = 稿纸页眉的本章意图（大纲一段 + 节拍列表可展开 + 真相一句话）。  
- 五阶段页签降为「深编」或取消。  
- 章节信息不再复述字段，只留一句缺口 + 跳到页眉编辑。  
- SoftCards / 写完对照 / StageBoard 进高级。

### 6. 旅程胶囊 / 四栏 / 系统图哪些该进高级？

见 F-U06。应进高级：

| 现位置 | 建议 |
|--------|------|
| 顶栏旅程 / 图谱 / 时间线 / 仪表盘 | 高级或 ⌘K |
| 旅程胶囊「继续」 | 高级；主路径不要自动编导 |
| 栏 1 工艺+检查分组 | 写时收起，需要时打开 |
| 系统中心活地图 / GATE 标签 / 模块目录 | 仅调试/作者极客 |
| 右栏选择环 / Pilot / 收件箱 | 高级 |
| 章头密度切换、评分卡、经验复盘 | 已有 essential 隐藏后两项；密度控件本身也可藏 |

**主路径只留：稿纸 + 目录窄条 + 主编对话。**

### 7. 「最易用」主路径草图 ≤6 步，其余折叠。

见上文「最易用主路径草图」。六步：**开书即稿纸 → 打字 → 划句改 → 采用 →（可选）整章生成 → 人签给读者。** 齐套、双灯、旅程、四栏工艺、系统图全部折叠。
