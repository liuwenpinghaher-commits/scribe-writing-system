# 乱世铜炉 端到端真实业务测试方案

> 目标:通读原文→主编对话填充设定→推演10章→写10章×6000字→质量对比,全流程验证系统能力,达到乱世铜炉水准。
> 原则:分阶段执行,每阶段完成→验证→发现问题即时修复→验证通过→进入下一阶段。

---

## 阶段 0:原文通读与设定提取(基础数据准备)

### 0.1 通读范围
- 《乱世铜炉》引子~第十章(约10万字)
- 提取维度:角色/地点/势力/世界规则/物品/术语/事件/角色关系/伏笔/母题

## 阶段 1:主编对话验证设定(设定填充+一致性校验)

### 1.1 流程
1. 启动系统(后端:3321 + 前端:3311 + Hermes:8642/8643)
2. 在设定库右栏"主编"面板,逐项对话验证:
   - "帮我检查胡不为的角色设定是否完整"
   - "这个世界还缺什么规则?"
   - "蔺得岷和赵姑娘的关系对吗?"
3. 主编回复后,人工确认或修正
4. 使用 `s3_setting_completeness` MCP 工具检查完整度
5. 使用 `s3_validate_setting` 检查设定一致性

### 1.2 验证标准
- [ ] 主编能正确回答关于设定的问题
- [ ] `setting_completeness` 返回 ≥ 80分
- [ ] `validate_setting` 无 high severity 冲突
- [ ] `resolve_entities` 能正确识别正文中的实体

### 1.3 即时修复
- 发现主编回答错误 → 检查 `_editor_system` prompt 注入
- 发现设定不一致 → 修正数据库中的设定
- 发现工具调用失败 → 修复后端 API

## 阶段 2:推演台验证(10章事件设计+知识帧+伏笔)

### 2.1 流程
1. 在推演台(DeduceLayout)中,逐章设计:
   - 选择 focalizer
   - 设计本章事件(s3_add_event)
   - 查看知识帧(s3_project_frame)
   - 检查戏剧反讽(s3_dramatic_irony)
   - 检查伏笔状态(s3_list_promises)
2. 每章验证:
   - 限知渲染:帧外事实不进 prompt
   - 因果完整:s3_causal_complete 无违规
   - 伏笔追踪:open 伏笔有超期告警

## 阶段 3:10章写作(每章≥6000字)+ 质量对比

### 3.1 流程
1. 在写作台(WriteLayout)中,用主编对话驱动写作:
   - 对话:"写第1章,时闻盂视角,婚宴场景"
   - 主编生成正文(SSE 流式)
   - 保存→QC检查→纪律判官→泄露检测
2. 每章完成后:
   - 字数检查 ≥ 6000
   - QC:复读/排比/升华句
   - 限知泄露检测
   - ingest 回写知识账本
3. 10章全部完成后,与原文做深度质量对比

### 3.2 质量对比维度
| 维度 | 原文指标 | 生成指标 | 达标标准 |
|------|---------|---------|---------|
| 字数/章 | ~6000-8000 | ≥6000 | ≥6000 |
| 环境描写密度 | ~1.0‰ | ? | 差异 < 3‰ |
| 身体动作描写 | ~1.2‰ | ? | 差异 < 3‰ |
| 心理活动描写 | ~0.6‰ | ? | 差异 < 3‰ |
| 感官描写 | ~2.2‰ | ? | 差异 < 2‰ |
| 句长 | ~25字/句 | ? | 差异 < 20% |
| 限知泄露 | 0 | ? | 0 |
| QC违规 | 0 | ? | ≤ 2 |
| OOC违规 | 0 | ? | ≤ 1 |
| 因果断裂 | 0 | ? | 0 |

### 3.3 验证标准
- [ ] 10章全部生成,每章 ≥ 6000字
- [ ] 限知泄露 = 0
- [ ] QC违规 ≤ 2/章
- [ ] OOC违规 ≤ 1/章
- [ ] 因果断裂 = 0
- [ ] 风格对比:6个维度差异在可接受范围内
- [ ] 主观评价:生成文本可读性达到原文水准

### 3.4 即时修复
- 字数不足 → 调整 `max_tokens` 或 prompt 指令
- 限知泄露 → 检查 `project_frame` + `build_render_prompt`
- QC误报 → 调整阈值
- OOC → 检查 VoiceProfile ooc_signals
- 因果断裂 → 检查 `causal_complete`

## 风险与应对

| 风险 | 应对 |
|------|------|
| LLM 生成质量不达标 | 调整 prompt + soak + craft 规则 |
| 限知泄露 | 检查 project_frame 逻辑 |
| 设定不一致 | 用 validate_setting 检测 |
| 字数不足 | 调整 max_tokens + 分段生成 |
| 主编对话超时 | 检查 Hermes 网关连接 |
| 系统崩溃 | 检查后端日志,修复后继续 |
