# 偏好数据（作者判断的落账处）

这是这条循环里**唯一会累积**的东西。

四轮机械闸换来三轮套利：`≤1` 的明喻线让模型写出 0 个比喻，`≥30%` 的冗余线让它把句子切碎成四字，`≥15%` 的长句线让它造信息倾泻的独白，而 `prose_check` 里「无信息回合」的白名单至今写着 `你吃了|吃了没`——正是三篇样章共用、被作者判为「一个味道」的那句。

表面统计量指挥不了逐 token 的采样。而作者四轮的判断每次都命中。所以不再把规则编进代码，改成把判断记下来。

## 记什么

`prefs.jsonl`，一行一条，schema 见 [`scribe3/eval/prefs.py`](../../scribe3/eval/prefs.py)：

```json
{
  "id": "pref-0001",
  "round": "v5",
  "premise_id": "p01",
  "genre": "乡土",
  "chosen": "docs/craft-samples/v5/v5-p01-c2.md",
  "rejected": "docs/craft-samples/v5/v5-p01-c1.md",
  "notes": ["老金是公务员标本，不是活人", "结尾那句替读者把主题说了"],
  "author": "作者",
  "date": "2026-08-27"
}
```

`notes` 是最值钱的一栏，必须具体到能照着改。「一般」「不行」「凑合」这类会被 `validate_pref` 拒掉。

## 怎么用

1. `generate_candidates` 同一处境写 3 篇，互不知情（拒绝采样）。
2. 作者挑一篇，说清另一篇差在哪。
3. `append_pref` 落账。
4. `chosen_texts()` 把选中的稿子喂回 in-context 示范池——这是短期就能吃到的收益。
5. 攒够量之后做 SFT / DPO——这是唯一能真正改变分布的一步。

## 不做什么

- 不用 `prose_check` 替代作者判断。它已降级为只读监控，报告里没有过/红，也不进提示。
- 不把 `notes` 翻译成阈值。那就是第五轮坍缩。
