## 0. 为什么要改 6.2

| 6.2 做到的 | 6.2 留下的缺口（本版针对） |
|-----------|---------------------------|
| 旅程+主编路径纪律、正典全类型闭环、约 5 万字规模证明 | **规模偏重**，把「字数达标」抬到与「记忆是否真有用」同级，记忆变成附带现象 |
| `book_7b918ca0` 等工程/混路径证据 | 易用脚本串行 **冒充**「写完了」；**主编对话是否真记住、真续接**测得不够狠 |
| fabric / pending-claims / WCG 有 API 冒烟 | 缺 **作者侧可复述** 的记忆探针：埋锚 → 中后程只靠系统想起 → 正文可观测 |

**本版不否定 6.2**，只改验收重心与规模：

```text
6.2 成功 ≈ 聊着天 + 点批 → 能写完一本（约 5 万）可读好书 + 正典闭环
6.3 成功 ≈ 同上路径 → 写完一本约 2 万字的新书
         + 记忆系统在真实连载中「该起的作用」被证伪或证实
```

## 1. 北极星（三句）

1. **路径**：作者 **只开旅程 + 只和主编聊天 + 点批/放行/接受稿**，开 **一本新书**，写完约 **2 万字**（见 §6 规模带）。  
2. **主验**：记忆是否 **真的在跑、真的被用、真的改了后文质量**——不是接口 200，不是库里有条记录。  
3. **纪律**：继承 6.2 §1——**遇障 → 真路径最优修 → 同路径回归**；禁止捷径过关。

```text
成功 ≠ 库里有 2 万字
成功 ＝ 作者可复述「我只聊天和点批」
       ＋ 埋下的记忆锚在后文被系统主动用上
       ＋ 改过的设定/过程记忆在后续章可见
       ＋ 无静默失忆、无假空上下文、无脚本代写冒充 PASS
```

## 2. 强制路径（比 6.2 更硬的一条）

### 2.1 唯一合法作者路径

| 允许 | 禁止（体验 PASS 直接否） |
|------|--------------------------|
| 旅程看板看站位 / WCG / 停靠 | `v2_serial_pilot` / 任何串行灌章冒充作者 |
| **主编聊天** 表达全部创作意图 | 表单大批量改正典当主路径 |
| 点批：提案、大纲放行、advisory、终选、**待确认设定 / pending-claims** | EMERGENCY / safe_beats / prose_pure / 离线 prose 灌库 |
| 只读：Codex、目录、正文、记忆相关面板 | 验收时 `curl` 代聊（工程探针可记，**不算**作者路径） |

### 2.2 「chat 驱动」操作定义（可勾选）

下列 **全部** 须经主编对话发生（作者说人话 → 主编提案/执行 → 作者点批），不得靠脚本生成：

| 阶段 | 必须 chat 驱动的内容 |
|------|----------------------|
| 建书 | 「开一本新书…约 2 万字…主题…」 |
| 意图 / 红线 | 读者感受、禁忌、POV |
| 设定 | 角色/规则/物件/关系…直至 WCG 可绿 |
| 结构 | 卷章梗概（本版建议 **1 卷 4～5 章**，见 §6） |
| 每章 | 开写指令、放行大纲、改稿意见、终选 |
| **记忆探针** | §5 全部探针话术必须走主编线程，禁止后台 seed |

`00-author-path.md` 必须诚实：若任何一章大纲/正文主要靠脚本 → **主编线 FAIL**，不得总 PASS。

### 2.3 与工程工具的边界

| 工具 | 允许用途 | 能否当 PASS |
|------|----------|-------------|
| 旅程 + 主编 + 点批 | 写书 | **唯一**体验 PASS |
| WCG / 字数 / 记忆探针 **只读审计** | 证据 | 辅助 |
| `/memory/prefetch` 对照抽检 | 证实组装非空/含锚 | 辅助，须注明 |
| 串行 pilot / 灌库 | **禁止** 本验收 | 否 |

## 3. 记忆系统：应起什么作用（验收定义）

> 记忆不是「多一张表」，而是写长篇时 **跨话轮、跨章** 仍站在同一本书上。

### 3.1 三层记忆（本验收都要碰到）

| 层 | 落点（实现真相） | 作者可感 | 应起的作用 |
|----|------------------|----------|------------|
| **A. 正典记忆** | Surreal 人物/规则/命题/关系… + 全类型候选/人批 | Codex + 待确认设定 | 世界真相稳定；改设定必经批后再生效 |
| **B. 过程记忆 fabric** | `memory_fabric`：capture-turn / prefetch / flush / episodic… | 后文「主编还记得刚才说的」 | 讨论不丢；压缩后仍可召回；**不得空串假「无记忆」** |
| **C. 写作注入记忆** | recap / current_tail / 限知帧 / 检索进 brief | 正文接得上、不泄密 | 续写接气；限知不穿帮；相关事实进上下文 |

**明确不是本验收对象：** Hermes 自带 memory 当故事库（产品约定：故事在 Surreal，不靠 Hermes memory）。

### 3.2 「真正起到作用」的判据（四问）

每一层、每一探针都用这四问打分：

| 问 | PASS | FAIL 样例 |
|----|------|-----------|
| **存了吗？** | 对话/定稿后可观测落库或候选 | 聊完什么都不进、静默丢 |
| **召回了吗？** | 后文对话或写路径上下文里再次出现锚 | 只存在库里，后文像失忆 |
| **约束了吗？** | 矛盾被拦/被主编指出/限知不泄 | 后文自由打架，系统无反应 |
| **改了质量吗？** | 有锚章比无锚章更连贯（人评 + 清单） | 有记忆 API 绿但正文仍断层 |

四问全否 → 该层 **记忆线 FAIL**。  
API 绿但四问只有「存了」→ **PARTIAL**，不得总 PASS。

## 4. 完成定义（十线 · 2 万字 · 记忆主轴）

```text
总 PASS ⇔ 旅程 ∧ 主编 ∧ 设定 ∧ 正典闭环 ∧ 真路径
         ∧ 工艺 ∧ 质量 ∧ 规模 ∧ 缺陷 ∧ 【记忆】
```

| 线 | PASS 标准 |
|----|-----------|
| **旅程** | 站序可走通；live 状态可观测（不要求 6.2 的 tape≥5 硬指标，但须有旅程截图/日志） |
| **主编** | **全书主输入来自主编 chat**；见 §2.2 |
| **设定** | WCG 绿 **先于** 连载正文（本版 WCG 可按 4～5 章结构配置，见 §6） |
| **正典闭环** | 至少 1 次 **聊天改设定** + 至少 2 次 **定稿后候选/批** 路径证据（继承 6.2 §5，量级可缩） |
| **真路径** | EMERGENCY=0；无 safe_beats / prose_pure 冒充 |
| **工艺** | 接地失败走 STOP 同路径，禁止默认 skip |
| **质量** | 可读、限知不泄、无公式灌水；好书底线同 6.2 |
| **规模** | 合计 **[18000, 24000]** 去空白字（目标心中 **~2 万**） |
| **缺陷** | 无开放 P0/P1；路径诚实 |
| **记忆** | §5 **M0–M6 探针** 全执行；**至少 5/7 硬 PASS**，且 **M1、M3、M5 必须 PASS** |

**好书底线（继承）：** 限知不泄、动机不 OOC、非说明书体、章有压力/钩子。

## 5. 记忆探针协议（本版核心 · 强制）

> 探针 **嵌入** 同一旅程，不是测完再写书。  
> 每个探针：作者话术 → 期望系统行为 → 证据文件 → 人判 PASS/FAIL。

### 5.0 书内「记忆锚」设计（建书时就要定）

开书后 Phase A 必须在 `01-memory-anchors.md` 写下 **≥5 个可检索锚**，例如：

| 锚 ID | 类型 | 内容要求 | 首次植入站 |
|-------|------|----------|------------|
| A1 | 专名 | 独特人名/绰号（全书唯一串） | 设定 chat |
| A2 | 物件 | 独特道具 + 一处物理细节 | 设定 chat |
| A3 | 规则 | 世界硬规则（后文易违反的那种） | 设定 chat |
| A4 | 关系 | 两人之间的秘密/债务 | 设定 chat |
| A5 | 过程偏好 | 作者对文风/禁忌的一句话（应进过程记忆） | intent/chat |
| A6 | 中程变更 | 故意在第 2 章后 **改掉** A2 或 A3 的一个细节 | 中程 chat |
| A7 | 限知陷阱 | 仅角色 X 知道的秘密；POV 不是 X 时正文不得明文 | 设定+写章 |

### 5.1 探针表

#### M0 · fabric 存活（门槛，非充分）

| 项 | 要求 |
|----|------|
| 前置 | `GET /capabilities` → `memory_fabric_v1=true`（或产品默认开且 pending-claims 非「服务挂」） |
| 动作 | 登录后对 **本书** 拉一次 pending-claims / 任意 memory 相关 UI 可达 |
| PASS | 非 5xx；关 fabric 时 403 须诚实（本验收要求 **开**） |
| 证据 | `12-memory-m0-capabilities.json` |
| 失败 | 整验收 **记忆线 FAIL**，先修环境再写 |

#### M1 · 跨话轮过程记忆（必须 PASS）

| 项 | 要求 |
|----|------|
| 动作 | 在主编 chat **只说一次** A5（文风/禁忌）；**间隔 ≥3 轮无关闲聊或隔一章** 后，作者问：「我刚才对文风的要求是什么？不要猜，按你记得的说。」 |
| PASS | 主编回复 **命中 A5 关键信息**（允许 paraphrasing，不得张冠李戴） |
| FAIL | 否认说过 / 编造另一套 / 要求作者重复后才「记得」且无检索痕迹 |
| 证据 | 对话截图或 thread 导出 + `12-memory-m1-process.md` |
| 工程辅助（可选） | 同 thread 调 prefetch，context 是否含 A5 关键词 |

#### M2 · 正典锚写入与 Codex 可见

| 项 | 要求 |
|----|------|
| 动作 | chat 植入 A1–A4 → 待确认设定/变更包 **人批** → Codex 可见 |
| PASS | Codex 或 store-snapshot 回读含 A1–A4 |
| 证据 | `12-memory-m2-canon.json` + 截图 |

#### M3 · 跨章正典召回进正文（必须 PASS）

| 项 | 要求 |
|----|------|
| 动作 | 第 1 章或设定埋 A1/A2；**第 3 章起** 作者 **不再复述** 细节，只说「按已有设定续写，让读者感到那件东西还在」 |
| PASS | 定稿正文 **自然出现** A1 或 A2 的可识别信息（非作者本轮消息粘贴） |
| FAIL | 正文失忆；或靠作者本轮又把全文设定贴进聊天 |
| 证据 | `12-memory-m3-cross-chapter.md`（引正文句 + 锚对照） |

#### M4 · 中程变更传播（A6）

| 项 | 要求 |
|----|------|
| 动作 | 中程 chat：「把 A2/A3 改成…」→ ChangePack/候选 → **人批** → 再写下章 |
| PASS | 变更后章正文或主编 brief **用新值**；旧值不再当真相（除非刻意回忆） |
| FAIL | 批了但后文仍旧值；或未批就静默改了 L1 |
| 证据 | `12-memory-m4-mutation.md` + `11-canon-loop-chat` 一条 |

#### M5 · 限知 / 不泄密（必须 PASS）

| 项 | 要求 |
|----|------|
| 动作 | A7：非知情 POV 章；作者可试探「顺便写出秘密」 |
| PASS | 正文 **无** 秘密明文；或 check/leak 拦住并改稿后通过 |
| FAIL | 限知穿帮进定稿 |
| 证据 | `12-memory-m5-limited-knowledge.md` |

#### M6 · 定稿抽取 → 待批 → 下章可用

| 项 | 要求 |
|----|------|
| 动作 | 至少一章 finalize → PostFinalize/候选出现 **新** 主张 → 人批 → 下一章写作中被主编或正文用到 |
| PASS | 「存了 + 批了 + 后文用了」三连 |
| 证据 | `12-memory-m6-postfinalize-reuse.md` + `11-canon-loop-body` 一条 |

### 5.2 记忆线打分

| 结果 | 条件 |
|------|------|
| **记忆 PASS** | M1∧M3∧M5 全绿，且 M0–M6 中 ≥5 项 PASS |
| **记忆 PARTIAL** | 硬三项有绿但总数 <5，或仅 API 层绿 |
| **记忆 FAIL** | M1/M3/M5 任一项 FAIL，或 M0 环境挂 |

**总 PASS 要求记忆 PASS**（PARTIAL 不得总 PASS）。

### 5.3 质量侧「记忆是否有用」（人评，强制写进结案）

结案 `09-final-closure.md` 必须用 1 页回答：

1. 若关掉记忆（假设），这本书 **会坏在哪**？  
2. 哪一章因为「记得」而明显更好？引文。  
3. 哪一次失忆/错记浪费了作者时间？若无写「未观察到」。  
4. 过程记忆 vs 正典：哪一层本次更关键？

无此页 → 记忆线最多 PARTIAL。

## 6. 规模与结构（2 万字）

| 项 | 6.2 | **6.3** |
|----|-----|---------|
| 目标字数 | 45–55k | **18–24k**（心中 ~2 万） |
| 建议章数 | 10 章 | **4～5 章**（足够跨章记忆，不必灌水） |
| 卷结构 | 3 卷 10 章 | **1 卷 4～5 章** 即可 |
| WCG | 原 gate 全量 | **同脚本**；结构项按本书 synopsis 对齐（章数 4～5 时 gate 配置/参数以脚本实际为准，**禁止**为绿而假造 10 章空壳） |
| 单章 | 完整 pilot 链 | **同 6.2 章循环**（大纲→…→终选→PostFinalize），不得跳步 |

**禁止** 为凑 2 万字 pad 公式尾；宁 18k 诚实可读，不 24k 注水。

```text

S2  放行大纲
```

短稿：同链重写。全书 **>24k**：同链压缩，禁止离线灌删凑「好看数字」。

## 9. 分阶段执行（新书 · 强制顺序）

```text
Phase 0   环境锁：demo 健康；fabric 开；EMERGENCY=0
          记录 runtime；确认旧书 book_7b918ca0 / book_052a2adb 仅备查
Phase A   旅程建新书 + intent + 写下 01-memory-anchors.md（A1–A7）

Phase C   chat 结构批准

Phase C″  【M0+M1】fabric + 跨话轮过程记忆（写章前必须过 M1）
Phase D   连载 4～5 章，全程主编 chat；嵌入 M3/M5；中程 M4；每章 S0–S9
```

**硬门：**

- 未完成 **M1** 不得宣称「过程记忆可用」进入结案 PASS  
- 未完成 **M3** 不得宣称「跨章记忆可用」
