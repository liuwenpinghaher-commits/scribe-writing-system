### 2.4 真 chat 可执行路径（产品现实 · 6.3.2 强制）

> 产品现状：讨论区默认 **非 agentic**（`/chat/stream`）；设定落地走 **讨论原文 → ChangePack(LLM) → 待确认点批**；章循环可 pilot，但 **开写指令必须先 chat**。

| 步骤 | 作者可见动作（会话/UI） | 允许的自动化等价 | **禁止** |
|------|-------------------------|------------------|----------|
| 0 新建 | 作品库点「新建」 | `POST /works`（等同点新建） | 用旧书验收 |
| 1 开书意图 | 主编 chat 口述主题/2 万字/红线 | `GET /chat/stream` 落线程 | 无 chat 直接 set_intent |
| 2 设定 | chat 分多轮口述角色/物件/规则/关系 | 每轮后 `POST /canon/change-pack`（`use_llm=true`, `source=discussion`）+ **点批** candidates | 脚本手写 `s3_add_*` ops 批量 apply |
| 3 结构 | chat 口述卷章梗概 | 同上 ChangePack/点批；或 chat 后点批提案 | 无 chat 直接 add_chapter |
| 4 M1 | **同一线程** 植入 A5 → 闲聊 ≥3 轮 → 追问复述 | 仅 `/chat/stream` | 后台 seed 假记忆 |
| 5 连载 | chat「开始写第 N 章…」→ 大纲/稿点批/终选 | 开写 **后** 允许 pilot 步进 + approve（点批） | 无 chat 直接 pilot 灌五章 |
| 6 M3–M6 | 嵌在 chat/定稿后 | 只读审计 + 章后 post-finalize | 脚本伪造正文 |

**会话验收铁律（你可一眼拆穿）：**

1. `/api/chat/threads?work=` 有线程；消息数应 **远大于**「闲聊 5 条」。  
2. 消息内容须覆盖：开书、设定、结构、开写、记忆探针。  
3. 正典候选 `source=discussion` / change-pack 与 chat 原文可对上。  
4. `00-author-path.md` 写 **真 chat**；若仍是「批量 proposal/apply 拼 ops」→ **主编线 FAIL**。

**驱动脚本（6.3.2）：** `scripts/v632_true_chat_journey.py`（不得再用 `v63_memory_journey.py` 冒充主编线）。

## 3. 记忆系统：应起什么作用（验收定义）

> 记忆不是「多一张表」，而是写长篇时 **跨话轮、跨章** 仍站在同一本书上。

### 3.1 三层记忆（本验收都要碰到）

| 层 | 落点（实现真相） | 作者可感 | 应起的作用 |
|----|------------------|----------|------------|
| **A. 正典记忆** | Surreal 人物/规则/命题/关系… + 全类型候选/人批 | Codex + 待确认设定 | 世界真相稳定；改设定必经批后再生效 |
| **B. 过程记忆 fabric** | `memory_fabric`：capture-turn / prefetch / flush / episodic… | 后文「主编还记得刚才说的」 | 讨论不丢；压缩后仍可召回；**不得空串假「无记忆」** |
| **C. 写作注入记忆** | recap / current_tail / 限知帧 / 检索进 brief | 正文接得上、不泄密 | 续写接气；限知不穿帮；相关事实进上下文 |

**明确不是本验收对象：** Hermes 自带 memory 当故事库（产品约定：故事在 Surreal，不靠 Hermes memory）。

### 3.2 「真正起到作用」的判据（四问）

每一层、每一探针都用这四问打分：

| 问 | PASS | FAIL 样例 |
|----|------|-----------|
| **存了吗？** | 对话/定稿后可观测落库或候选 | 聊完什么都不进、静默丢 |
| **召回了吗？** | 后文对话或写路径上下文里再次出现锚 | 只存在库里，后文像失忆 |
| **约束了吗？** | 矛盾被拦/被主编指出/限知不泄 | 后文自由打架，系统无反应 |
| **改了质量吗？** | 有锚章比无锚章更连贯（人评 + 清单） | 有记忆 API 绿但正文仍断层 |

四问全否 → 该层 **记忆线 FAIL**。  
API 绿但四问只有「存了」→ **PARTIAL**，不得总 PASS。

## 4. 完成定义（十线 · 2 万字 · 记忆主轴）

```text
总 PASS ⇔ 旅程 ∧ 主编 ∧ 设定 ∧ 正典闭环 ∧ 真路径
         ∧ 工艺 ∧ 质量 ∧ 规模 ∧ 缺陷 ∧ 【记忆】
```

| 线 | PASS 标准 |
|----|-----------|
| **旅程** | 站序可走通；live 状态可观测（不要求 6.2 的 tape≥5 硬指标，但须有旅程截图/日志） |
| **主编** | **全书主输入来自主编 chat**；见 §2.2 |
| **设定** | WCG 绿 **先于** 连载正文（本版 WCG 可按 4～5 章结构配置，见 §6） |
| **正典闭环** | 至少 1 次 **聊天改设定** + 至少 2 次 **定稿后候选/批** 路径证据（继承 6.2 §5，量级可缩） |
| **真路径** | EMERGENCY=0；无 safe_beats / prose_pure 冒充 |
| **工艺** | 接地失败走 STOP 同路径，禁止默认 skip |
| **质量** | 可读、限知不泄、无公式灌水；好书底线同 6.2 |
| **规模** | 合计 **[18000, 24000]** 去空白字（目标心中 **~2 万**） |
| **缺陷** | 无开放 P0/P1；路径诚实 |
| **记忆** | §5 **M0–M6 探针** 全执行；**至少 5/7 硬 PASS**，且 **M1、M3、M5 必须 PASS** |

**好书底线（继承）：** 限知不泄、动机不 OOC、非说明书体、章有压力/钩子。

## 5. 记忆探针协议（本版核心 · 强制）

> 探针 **嵌入** 同一旅程，不是测完再写书。  
> 每个探针：作者话术 → 期望系统行为 → 证据文件 → 人判 PASS/FAIL。

### 5.0 书内「记忆锚」设计（建书时就要定）

开书后 Phase A 必须在 `01-memory-anchors.md` 写下 **≥5 个可检索锚**，例如：

| 锚 ID | 类型 | 内容要求 | 首次植入站 |
|-------|------|----------|------------|
| A1 | 专名 | 独特人名/绰号（全书唯一串） | 设定 chat |
| A2 | 物件 | 独特道具 + 一处物理细节 | 设定 chat |
| A3 | 规则 | 世界硬规则（后文易违反的那种） | 设定 chat |
| A4 | 关系 | 两人之间的秘密/债务 | 设定 chat |
| A5 | 过程偏好 | 作者对文风/禁忌的一句话（应进过程记忆） | intent/chat |
| A6 | 中程变更 | 故意在第 2 章后 **改掉** A2 或 A3 的一个细节 | 中程 chat |
| A7 | 限知陷阱 | 仅角色 X 知道的秘密；POV 不是 X 时正文不得明文 | 设定+写章 |

### 5.1 探针表

#### M0 · fabric 存活（门槛，非充分）

| 项 | 要求 |
|----|------|
| 前置 | `GET /capabilities` → `memory_fabric_v1=true`（或产品默认开且 pending-claims 非「服务挂」） |
| 动作 | 登录后对 **本书** 拉一次 pending-claims / 任意 memory 相关 UI 可达 |

| 证据 | `12-memory-m0-capabilities.json` |
| 失败 | 整验收 **记忆线 FAIL**，先修环境再写 |

|----|------|

### 5.2 记忆线打分

| 结果 | 条件 |
|------|------|
| **记忆 PASS** | M1∧M3∧M5 全绿，且 M0–M6 中 ≥5 项 PASS |
| **记忆 PARTIAL** | 硬三项有绿但总数 <5，或仅 API 层绿 |
| **记忆 FAIL** | M1/M3/M5 任一项 FAIL，或 M0 环境挂 |

**总 PASS 要求记忆 PASS**（PARTIAL 不得总 PASS）。

### 5.3 质量侧「记忆是否有用」（人评，强制写进结案）

结案 `09-final-closure.md` 必须用 1 页回答：

1. 若关掉记忆（假设），这本书 **会坏在哪**？  
2. 哪一章因为「记得」而明显更好？引文。  
3. 哪一次失忆/错记浪费了作者时间？若无写「未观察到」。  
4. 过程记忆 vs 正典：哪一层本次更关键？

无此页 → 记忆线最多 PARTIAL。

### 5.4 质量七维（D1–D7）· 6.3.1 强制对齐

> 权威细则：[`docs/plans/2026-08-09-memory-quality-rootcause-plan.md`](./plans/2026-08-09-memory-quality-rootcause-plan.md)。  
> **9.5 = 质量分**，不是 HTTP 200 / 文件存在。

| 维 | 本旅程硬门槛（自动化） | 质量 ≥9 仍须 |
