日期:2026-07-17。目标:全面审查 Hermes v0.18.2 剩余能力,凡对 scribe3 有真实正向作用的全量实现;凡无价值/有害的记录否决理由,防止日后重复调研。

## 一、真机审查记录(全部实测,非文档推断)

- `hermes status`:主模型 deepseek-v4-pro-260425(ark coding plan,custom endpoint);API keys 仅 ark 一枚有效;**fallback_providers 为空(主模型单点)**。
- `hermes auth list`:凭证池=ark key + copilot(gh token)。
- `hermes gateway list`:仅三个 api_server 网关(default/scribe3/scribe3_write),**无 telegram/discord 等消息平台**。
- `hermes fallback`:配置键 `fallback_providers: [{provider, model, base_url?}]`(主配置+每 profile 各一份);消费点=**agent loop**(conversation_loop/agent_init 调 get_fallback_chain)——三网关都驱动 agent loop,配置对 scribe3 全路径生效。`fallback add` 是交互式 → 自动化走 provision overlay。
- **兜底模型探针**(8-token 真调,只信 200):同一 ark coding key 下,`kimi-k2-thinking` ✅、`MiniMax-M2.5` ✅;`kimi-k2.5`/`glm-5`/`glm-4.7`/`qwen3-coder-plus`/`qwen3-max-2026-01-23`/`doubao-seed-code(-preview)`/`deepseek-v3-2-terminus` ✗(UnsupportedModel:不在 coding plan)。配置里 providers.custom.models 登记的 9 个模型**多数实际不可用**——登记≠可用,只信探针。
- `hermes doctor`:三 profile 网关健康;告警全是未配置的可选工具 key(与 scribe3 无关)。
- `hermes security audit`:OSV.dev 供应链扫描(hermes venv/插件依赖/固定 npx/uvx MCP)。**实跑即发现真漏洞**:starlette==1.0.1(PYSEC-2026-2281/248/249)、tornado==6.5.5(PYSEC-2026-3387/3388/3389,含 gzip bomb 与越界访问)——修复通道=升级 hermes(fixed in starlette 1.3.1 / tornado 6.5.6)。
- `hermes prompt-size`:离线报告 hermes 自身会话的固定 prompt 预算——测的是 hermes 面,不是 scribe3 组装的 prompt。
- cron 任务存储:`~/.hermes/cron/`;USER.md/SOUL/profiles config 均为文件资产。
