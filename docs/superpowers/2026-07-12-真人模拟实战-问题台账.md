## 问题

### S-001 · 主编纯讨论对开放式提问回"让我查查"就断流(可用性)
- **现象**:立项第一轮,作者开放式问主编"帮我想2-3个冷门行当",主编只回 36 字"让我先查查中国古代有哪些特别冷门的行当…"就结束(200 OK 无报错)。真人在 UI 看到主编答一句空话就没了。
- **诊断**:同一 msg 换成明确指令("直接凭学识、一次说完整、别说'让我查查'")→ 主编给出 2408 字完整高质量方案(过槽人/寒衣差/字枯)。两次 sysmsg 相同(书空,mat_hint 不注入,无工具承诺)。→ **根因=doubao 对开放式提问倾向回思考性开场白然后单轮 completion 结束;`chat_stream`(纯讨论,hermes_complete_stream 单遍无续接)的 sysmsg 缺"直接完整作答"约束**。非崩溃,是可用性:不该逼真人每次都写"别说让我查查"。
- **修复**:chat_stream 的 sysmsg 追加纯讨论作答引导(直接完整可操作、不要拖延开场、纯讨论无实时查询工具凭学识与设定作答)。只碰 chat_stream(讨论路径),_editor_system/写作/agentic 不动(零回归)。commit 待提交。
- **回归证据 ✅**:修复+重启后,重发【开放式】原问(不给任何"别说让我查查"引导)→ 主编直接给 1442 字完整方案(三行当含核心冲突/主角弧光),不再半截。单测 test_chat_stream_sysmsg_has_discussion_directive 绿。**闭环**。(改文件:app.py chat_stream +_DISCUSSION_DIRECTIVE、test_chat_message.py;顺带修一处 Edit 误把常量插进 @app.get 装饰器与 def 之间的语法错。)

### S-002 · 知情主角限知视角泄露核心悬念秘密(系统设计缺陷,已修)
- **现象**:第1章用沈砚(知情主角)限知视角写,主编把核心悬念秘密明写进正文——沈错(真名)×4、替兄顶罪×5、真名×1、后颈墓碑印×3。整本书的核心悬念(他是谁/他做过什么,本该第7章揭示)第1章就全抖光=严重剧透。
- **根因**:`project_frame(focalizer)` 只屏蔽【焦点者不知道】的帧外私密,但焦点者是知情主角时,他自己知道的秘密在帧内、且主角 backstory 也写了前史 → 写他视角就把该留到揭示章的秘密泄露给读者(知情 POV 倒灌)。`_write_protocol_block` 只说"不写他不知道的私密",无"他知道但读者未揭示的秘密也要藏"的约束。**统一记忆系统有 known_from(读者发现时间)概念,但写作 prompt 路径的 secret 命题没用它约束藏匿**。
- **修复**:新增 `_secret_guard_block(st,chapter)`——对本书 secret 命题的破绽词(leak_markers),即便视角人物知情,也硬约束本章藏匿、禁明写,注入写作 instructions(v1+旧两路)。默认所有 secret 藏,作者要揭示时写作指令覆盖。无 secret→空串(字节不变)。单测 test_secret_guard_block_hides_leak_markers 绿。
- **回归证据 ✅(v1 vs v2 决定性对比)**:同一第1章,修复前 v1=沈错×4/替兄顶罪×5/leaks2/复读2排比1紫词1;修复后 v2=**沈错/真名/替兄顶罪全0**、机械硬伤全0、leaks 2→1。核心悬念被系统层藏匿约束**完全挡住**。**闭环**。
- **顺带修 leak_markers 粒度**:"后颈"太通用(身体暗示"后颈发紧"是好写法却被当破绽词误判)→ 从 leak_markers 去掉,保留墓碑印/刺印等专属专名。第1章 v2 精化后只剩"墓碑印×1"(读者不知含义的悬念钩子,可接受)。**craft 印证:预防靠 prompt(_secret_guard_block)+检测靠 find_leaks,双层;leak_markers 要选"专属专名"不选通用词**。

### S-003 · 分幕长章暴露系统"治"层缺口:检测齐全但治只有跨章 dedup(系统缺陷,已修)
- **现象**:goal 要 10 章 5 万字=每章约 5000 字,但系统单次生成最佳粒度约 2000 字(此时硬伤 0)。为凑长章改分幕生成(每章 3 幕承接约 5700 字),章内自我复读/排比堆砌爆发:第 3 章首版机械硬伤 37(structural 排比×3、cross_repetition×5、duplicate_lines×2 等)。改进分幕 prompt(传本章已写全文+硬性避重清单)压到 10,但**压不到 0**(doubao 对避重清单遵守不完美,排比/对举句压不干净)。
- **根因**:系统 9 个检测器能查出全部问题,但"治"层只有 `/dedup-chapter` 一个、且只治**跨章逐字复读**(cross_repetition)。章内 repetition/duplicate_lines/排比无对应的治层——**检测与治严重不对称**。prompt 预防有天花板,长章必须靠"检测→治"闭环补齐。
- **修复**:新增章内治层,复用 `rewrite_cross_repetitions` 的"定位句子→定向改写→拼回"框架:
  - `critique.py`:`intra_repetition_sentences`(定位章内 repetition/duplicate_lines/排比问题句+改写 hint)、`rewrite_intra_chapter_issues`(逐句定向改写,改写器 sysmsg **强约束限知**——绝不点破未揭示悬念,S-002 延续;迭代至多 2 轮;幂等)。
  - `app.py`:`POST /polish-chapter` 端点,与 `/dedup-chapter` 三路对称(改写→落 final 版→排 ingest)+ 在途护栏。
  - 6 个单测绿(定位三类/假 LLM 消除复读/幂等/限知守护)。critique 全套 199 绿。
- **回归证据 ✅**:真机对第 3 章(章内硬伤 10)调 `/polish-chapter`:改写 17 句,**章内硬伤 10→0 全清零**,字数 7115→7245 基本不变,限知泄露 0。人读确认改写无突兀、声音/承接/限知俱佳。**闭环**。

### S-004 · 治层改写偶发混入英文占位词(改写质量,修复中)
- **现象**:第 3 章 polish 后人读发现正文第 107 行"或者是十二年前 **someone** 塞给他的"——doubao 改写单句时蹦出英文词 `someone`,被 `.replace` 拼回中文正文,破坏沉浸。
- **根因**:`rewrite_intra_chapter_issues`(及同源 `rewrite_cross_repetitions`)对 LLM 改写结果只校验"非空、≠原句、长度≥4",未校验**是否混入原句没有的 ASCII 字母/元叙述**。doubao 偶发英文占位词/拒答前缀。
- **修复**:改写结果加合法性校验 `_valid_rewrite`(引入原句没有的 ASCII 字母 → 弃用保留原句;含"改写/抱歉/无法/以下是"等元叙述 → 弃用),接入 `rewrite_intra_chapter_issues`。
- **回归证据 ✅**:第3章用加固链路重生,正文英文异物 **0 处**(re 全文扫描确认)。单测 test_rewrite_intra_rejects_english_garbage 绿。**闭环**。

### S-005 · 检测器盲区:近似段落重复漏检(QC 假绿,已修)
- **现象**:第 3 章 89/91 行两个自然段几乎一字不差("门缝里的光从棺盖移到灶台移到鞋尖+鞋面黑泥裂纹",仅换"蹭的→蹭上的""干结→干透""细碎→细密"几字),人读明显重复,但 **QC 报 0 机械硬伤**。
- **根因**:分幕拼接处幕 N+1 开头重写了幕 N 结尾的画面(近似非逐字)。`find_repetitions`(精确 8-gram)与 `find_duplicate_lines`(精确整句)都只认**逐字**重复,近似段落重复落在两者盲区之间。
- **修复**:新增 `find_near_duplicate_paragraphs`——切段后两两算 **difflib SequenceMatcher 字符级相似度**(阈值 0.7,对"大段逐字相同+局部改字"敏感,优于 n-gram Jaccard——6-gram 被局部改字破坏后 Jaccard 降到 0.4 抓不住);纳入章内治层 collector(近似重复段后段逐句改写)与 `_count`。
- **回归证据 ✅**:第3章重生 **near_dup 0**(89/91 类清除);对干净的第1/2章 **不误报**(near_dup 0)。单测 test_find_near_duplicate_paragraphs_catches_reworded 绿。**闭环**。

### S-006 · 治层健壮性加固(子代理审查驱动,已修)
- **背景**:章内治层(S-003)建成后派 code-review 子代理审查,发现 2 个 P1 + 一组同根 P2(都是"改写正文"这类高风险操作缺护栏)。
- **P1-1 限知二次门缺失**:`polish_chapter` 改写落库前没跑 `find_leaks`(系统已有、`/save-chapter`+`/check` 都用了),改写单句无全局 context 可能把原文刻意模糊的表述"具体化点破"未揭示悬念。**修**:落库前复跑 `find_leaks`,泄露增加则整体回退不落库(限知红线保险,fail-soft 异常也回退)。
- **P1-2 收敛回滚门缺失**:改写可能 after≥before(排比打散造出新排比、改写引入新复读)却仍落库+ingest 扩散更差版本。**修**:`rewrite_intra_chapter_issues` 末尾 `done==0 or after>=before` 则整体回退到原文。
- **P2 口径统一(collector 与检测器)**:①剥引号后在叙述层匹配(不误改台词)②切句正则含省略号 …(与 find_duplicate_lines 对齐,不漏定位)③duplicate/structural 分支也过 allow 母题白名单(不误改刻意复现的谶语)④`_count` 套 allow 与 targets 对齐⑤`_replace_whole_sentence` 句界锚定替换(防命中更早长句的同形尾部子串)。
- **回归证据 ✅**:4 条新单测(回滚门/英文异物/母题 allow/近似段)+ 原 6 条 = 10 绿;critique 全套 203 + app 章节 35 回归绿。第3章重生真机:限知泄露 0、无更差版本落库。**闭环**。
- **子代理确认安全的维度**(逐条有据):落库三路对称、双在途护栏齐全、幂等成立、收敛兜底完善、空文本三层防护。

### S-007 · assembler_v1 遗漏跨章避免禁令,flag 放量后跨章复读防线失效(系统缺陷,已修待真机验)
- **现象**:第4章分幕生成后 cross_repetition=25(复用第1/2章"巷口梆子声/摸后颈"等意象),叠加 rep10/dup7 共 46 机械硬伤;dedup 串行改写 25 句超 120s timeout → 治理整体 `timed out` 未执行 → 46 硬伤全留(mech_total=46 是治理前原始数字,非治理后)。
- **根因**:`_assemble_write_instructions_v1`(ContextAssembler v1 链,SCRIBE3_CONTEXT_ASSEMBLER_V1 开时走)第3999行用 envelope"替代旧 avoid/voice/arc/motif 散点拼装"。但 envelope 是【上下文信息聚合】(前文写了什么),给不出 `_avoid_directive` 的【确定性禁令】("前文用过这些 ≥8 字措辞,本章严禁逐字复用",料来自 distinctive_phrases)。**信息 ≠ 禁令**。旧链(flag 关)有 avoid(app.py:4122),v1 链把它当"信息散点"一起漏掉。→ **阶段0 放量开 assembler_v1 后,写作走 v1 链,跨章复读的确定性防线失效**;分幕长章跨度大,复用前文意象暴增。超时只是它的下游后果,不是根因。
- **影响面**:所有 assembler_v1 开的写作(非仅本小说)。统一记忆系统 flag 放量引入的**回归**——阶段0 放量金丝雀未覆盖"跨章复读防线"维度,漏网。印证 [[scribe3-unified-context-memory-done]] "flags 放量需谨慎"。
- **修复**:v1 链硬协议区补回 `_avoid_directive`(按本函数自己的分工原则第3979行"强制纪律逐条内嵌、不进 envelope",avoid 本就属每请求禁令、该内嵌)。回归钉 `test_v1_calls_avoid_directive`(spy 断言 v1 链调用 avoid)绿;v1 组装测试 3 绿。另把逐章脚本 dedup/polish timeout 增至 360/460s(治理超时兜底)。
- **待真机验**:第4章重生(avoid 生效)后 cross_repetition 应源头大降、治理不超时、达标。
- **连带观察**:v1 链相对旧链还少 `_voice_anchor_block`/`_arc_state_block`/`_motif_block`(声音锚/弧光/母题)——部分被 envelope 信息覆盖(补回有重复风险,v1 刻意消重),暂不动;若第4-10章出现声音崩/弧光漂再针对性处理。

### S-008 · 近似重复检测盲区②:句子级近似漏检(检测器边界,已修)
- **现象**:第10章结局两相邻句"他躺在自己的棺材里,手里的纸团硬邦邦的,是他此刻仅有的实在触感"vs"…是他还能攥住的唯一东西"(前半一字不差、后半改几字,各约 25 字),人读明显重复,但 near_dup(min_len=40 段落级)、duplicate_lines(精确整句)、find_repetitions(8gram)三检测器全漏。
- **根因**:S-005 的 near_dup 按段落级(≥40 字)切,句子级近似(25 字)落在其阈值外。
- **修复**:near_dup 默认 min_len 40→25(实证:抓到第10章 61/63 句级近似 sim=0.75;对干净的第1/2章零误报)。回归钉 test_find_near_duplicate_catches_sentence_level。重 polish 第10章清除(rewritten1,near_dup 1→0,无限知泄露)。**闭环**。
- **残留观察**:相似度 0.6~0.7 的主题性近似段(如第9章 9/73 行"案/架子同一天打的、崩刃、磨圆如棺头")仍在 0.7 阈值外漏检——降阈值会增误报,取舍上保留;这类多是"有主题功能但句式偷懒"的重复,记为可优化微瑕,不强清(避免无限调优)。

### S-009 · 引号配对瑕疵:检测有、治无(治层缺口,记录未修)
- **现象**:全本 7 处引号不配对(第3章2、第5/6/7/9/10各1),如第10章"该入槽了。那人开口"缺右引号——doubao 生成对话时的标点瑕疵。
- **诊断**:系统有 `find_unbalanced_quotes` 检测,但无对应治层(dedup 治跨章、polish 治章内复读/排比,都不治标点)。为 7 处引号建治层需判断"补哪个引号/是否自由间接引语",复杂且易误伤,成本不划算。
- **处置**:记为**已知微瑕**,不修——引号不进 mech_total、不影响叙事/限知/声音等核心质量。若后续系统化写作需要,可作独立治层任务(规则:检测左引号后到硬句界无右引号 → 补,但需 allow 自由间接引语豁免)。

## 验收结论(阶段3)

- **字数**:10 章共 **57179 字**(不含换行),超 5 万目标 ✓。分布:第1-2章 2084/2467(首章精炼),第3-10章 5805~7334。
- **机械硬伤**:第1/2/7章 mech=0;第3/4/5/8/9章 mech=1;第6/10章 mech=4。残留**全是功能性复现**——通用动作短语(他没抬头/瞥一眼)、对话标签(那人说)、人物指称(穿青布长衫的人)、母题钩子(方方正正/墓碑印),经 dedup 多轮(单轮覆盖不全)+polish 治理后改不动的顽固通用句;**非懒惰的意象/比喻/句式复读**,乱世铜炉标尺可容忍。
- **near_dup**:段落级+句子级全 0(S-005/S-008 修后);god_view 全 0;purple 仅第6章 1 处(有主题功能的"影子如墓碑"象征)。
- **限知曲线(核心)**:前 9 章 leaks=0(核心悬念"墓碑印=72个替死者""沈砚真名沈错""替兄顶罪"全程藏,只暗示不点破);第 10 章 leaks=1(结局引爆揭示墓碑印含义,叙事正确的揭示)。**完美的限知抛物线**。
- **人读对照乱世铜炉**(抽读第3/4/9/10章):冷笔克制、show 不 tell、感官细节密、沈砚寡言自苦声音立住;过槽反噬"记忆抽成"层层具象(忘名字/忘工具/底稿字自动模糊/数不到十二);方形母题贯穿(碑/砚/钱/印,记忆抽成后万物只剩几何轮廓);侧写高级(少年也被反噬传染失忆、王阿婆讲镜像替兄案、72鬼用挤压呼吸侧写)。**达乱世铜炉级**。
- **微瑕(诚实记录)**:引号 7 处(S-009)、第9章 9/73 主题性近似段、第6章 purple1;均不影响核心质量。
- **系统可用性产出**:全程发现并修复 S-001~S-008 共 8 类问题(1 类记录未修),其中 S-003(章内治层)、S-007(assembler_v1 漏 avoid 的 flag 放量回归)是有复用价值的系统能力补强;治层测试全绿、回归钉锁死、记忆持久化。
