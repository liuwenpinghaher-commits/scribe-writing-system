**环境**:仓库根 `<repo-root>`(引号)。后端 venv `scribe3/.venv/bin/pytest tests/...`;前端 `scribe3/web`(build/vitest)。分支 `feat/p1-clear-bugs`。每任务只 stage 本任务文件;不碰无关 .py。

## Task 1 — api.js work 写加 res.ok 检查(静默假成功)
**Files:** `scribe3/web/src/api.js`
**现状**:`createWork`/`renameWork`/`deleteWork`(api.js:39/42/43)裸 `fetch().then(r=>r.json())`,不查 res.ok → HTTP 500 当成功 JSON 返回。
**改**:三者改走 `handle`(同 `post`/`j` 的错误处理),或显式 `if(!res.ok) throw`。读 `handle`(api.js:8-15)复用之。
**验**:build + vitest 绿;(可加一个 vitest:mock fetch 返回 500 → reject)。提交。

## Task 2 — s3_record_knowledge 校验 proposition 为 fact: oid(悬挂边)
**Files:** `scribe3/mcp.py`、`scribe3/tests/test_mcp.py`
**现状**:`s3_record_knowledge`(mcp.py:482)把入参 proposition(可能是自然语言)直接当 oid → `add_knowledge` `_split` 后 RELATE 到畸形 proposition 记录。
**改**:若 proposition 不形如 `fact:xxx`(或库内不存在该命题),**拒绝并返回明确错误**(或在 docstring 强约束 + 运行时校验)。优先:校验存在性,不存在则不建边、回 error。
**TDD**:传裸文字 → 工具返回错误且不建悬挂边;传合法 `fact:` oid → 正常。红→绿。提交。

## Task 3 — embedding 写入补全(REST/ingest 命题进不了向量召回)
**Files:** `scribe3/store.py`(add_fact)、`scribe3/tests/test_store.py`
**现状**:仅 `s3_add_fact`(mcp.py)写后调 `semantic_index`;`store.add_fact`(被 REST `POST /facts` 和 ingest 调)**不建 embedding** → 这些命题 `semantic_recall`/`hybrid_recall` 召不到。
**改**:`store.add_fact` 写入后建 embedding(调 `embed`+`semantic_index`,同 mcp 路径)。**注意成本**:ingest 批量写 facts 会逐条 embed——可接受(章级量级),但若已有批量接口优先;否则逐条但加 try/except 不阻断主写。
**TDD**:`store.add_fact(Fact(...))` 后 `store.semantic_recall("该命题词")` 能召回到它(此前召不到)。红→绿。full test_store 回归。提交。
> 若 embed() 在测试环境不可用/太慢,改为:确保 add_fact 调用了索引路径(用 spy/mock 验证调用),而非真跑 embedding。实现者按测试基建择优,报告。

## Task 4 — world_rule.category 缺值不 400
**Files:** `scribe3/web/src/views/CodexView.jsx`(世界规则表单)
**现状**:`world_rule.category` SCHEMAFULL ASSERT in[6类];前端表单不强制选 → 漏值 CREATE 400。
**改**:CodexView 世界规则新增/编辑表单的 category 用 select(6 类枚举),默认选第一项,不允许空。
**验**:build + 截图:世界规则表单 category 是下拉、有默认值。提交。

## Task 5 — 更新过期 MCP docstring(误导 LLM)
**Files:** `scribe3/mcp.py`
**现状**:`s3_add_character_relation`(mcp.py:356)docstring 仍写英文5词关系表(029 已扩 26 词中文);`s3_add_faction`(mcp.py:393)docstring 未提 status 硬编码 active。
**改**:更新这两个(及扫一遍其它明显过期的)docstring,让 relation 词表、status 取值与当前 schema 一致。纯文档串改,不改逻辑。
**验**:build 无关(纯后端串);跑 test_mcp 绿。提交。

## Task 6 — 字数口径统一
**Files:** `scribe3/app.py`(/quality)或 `scribe3/store.py`
**现状**:`qc_word_count`(store 字符数)vs `/quality` `len(prose.split())`(app.py:611,中文≈段数)vs 前端去空白——三套。InsightView 与 Library 书卡字数对不上。
**改**:把 `/quality` 的逐章 `word_count` 改成与 store 一致的口径(`len("".join(prose.split()))` 字符数,同 store.py:664),让仪表盘与书卡一致。
**TDD**:`/quality` 某章 word_count == store 的 qc_word_count 口径。提交。
