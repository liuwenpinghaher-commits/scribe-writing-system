# scribe3 真人模拟实战:从零写出乱世铜炉级 10 章 5 万字

- **Goal**:完全模拟真人作者,从零开始只用系统正常流程,写出乱世铜炉质量的小说 10 章 / 5 万字;全程真正校验系统可用性,修复所有遇到的问题。
- **日期**:2026-07-12 起。**基线**:main 已合(44784b2),统一记忆系统 17 任务完成,flags 默认关。

## 铁律(goal 原文的操作化)

1. **不用超能力写作**:一切创作内容(大纲/节拍/草稿/正文/设定细化)必须由系统生成(Hermes→doubao 经系统链路)。我只扮演**作者**:输入意图与构思(真人也会打字的短文本)、做选择、审批待批项、给修改反馈、决定定稿。**我绝不直接把成段小说文本写进库。**
2. **和真人一样操作**:每一步走前端同款 REST 端点、按真实 UI 操作顺序(建书→设定→逐章五阶段→主编对话→审批→QC→定稿)。不用批量灌库脚本(fill_*.py 那种是超能力)。一次操作=一个真人动作。
3. **遇到问题当场修**:任何报错、卡点、体验断裂、质量缺陷 → 记入问题台账 → 当场根因修复(TDD)→ 回归 → 继续写。这是"校验可用性"的核心产出。
4. **质量标尺**:乱世铜炉级。用已验证的双重判据——①系统 QC 全绿(复读/结构/telling/限知泄露/god_view/紫词=0 硬伤);②人读对照工艺细则(纸命 4 章曾达 4.36-4.6)。critique 单次分数噪声 ±0.4,看趋势+人读,不对单次分过度反应。

## 阶段 2 · 逐章循环 ×10(核心,每章 0.5-1 天)

每章走完整真人流程:

1. **章前**:主编讨论本章意图(承接上章+本章目标);读简报/关联(新 UI 入口,顺便真实校验)。
2. **大纲**:章工作台大纲 tab,「帮我展开」按钮走主编生成→作者改定。
3. **节拍**:拆节拍(主编生成→作者调序/删改);安静章配安静 beats(拾骨记 gap 教训)。
4. **草稿→正文**:/chat/write 五环生成;作者以反馈迭代("这段声音崩了""砍掉第二个高潮");采用为正文。
5. **QC**:检测器全跑(复读/跨章/结构/telling/紫词/god_view/限知泄露)+ 纪律闸;硬伤=0 才过。
6. **定稿**:ingest 回写(知识账本/记忆反哺);伏笔台账推进;下章承接。
7. **每章记录**:字数、QC 计数、遇到的问题(系统 bug/体验断裂/质量缺陷)与修复 commit。

**已知深坑的预案**(来自拾骨记/纸命实战记忆):
- doubao 单遍长章 ~28-51% 处易复发(双高潮/声音崩/解说倾泻)→ 纪律闸+定向反馈重写,别硬灌全长。
- 长跑记忆漂移(身世/亲缘被压缩串改)→ 铁律事实进角色内核 verbatim 注入;每 2-3 章人查一次主线连贯。
- 知情倒灌 → 限知帧+知识边界是结构防线,QC knowledge_leak 兜底;发现即外科修那一句。

### synopsis 对齐修复(工具纪律,非系统缺陷)
