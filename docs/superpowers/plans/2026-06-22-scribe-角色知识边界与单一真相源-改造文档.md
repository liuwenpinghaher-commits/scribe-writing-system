# 角色知识边界与单一真相源 · 系统改造文档

> 版本 v1 · 2026-06-22 · scribe2(SurrealDB + Hermes 底座)
> 触发:生成稿里"刚追来的老道"说出了主角私密动机("够你老娘治三年眼")——POV 信息泄露。
> 结论:这不是单句 bug,是写作上下文**全知扁平、缺角色知识边界**的架构性缺口。本文给出工艺验证过的、零文笔代价的根治方案与落地步骤。

---

## 0. 问题与根因(已核实)

**现象:** 角色 A(老道,刚登场的外人)在对白里说出只有角色 B(焦三)/读者才知道的私密信息(老娘治眼及其花费)。

**根因(已用证据确认):** `build_writing_context` 把**每个角色的私密内核(wound/lie/want/need/fear)、动机、私密前史、伏笔**全部拍进**同一个共享 prompt** 喂主编。ch5 上下文里"老娘"出现 12 次、焦三的 want("给老娘治眼")明晃晃在场。系统**没有任何"哪个角色知道什么"的边界**——模型默认上下文里的都是公共信息,遂让任一角色说出任一被注入的信息。系统此前**只为伏笔**建了 `audience_knows`(读者 vs 角色,做戏剧反讽),**没有通用的角色知识模型**。

**为什么两层 QC 没拦住:** 确定性检测查复读/升华;纪律闸查双高潮/声音崩/解说倾泻——都不含"知识边界违规"维度(本次改造已补 `knowledge_leak` 判项,见 §6)。

---

## 1. 工艺依据(全网搜证,本方案不是发明,是把公认铁律工程化)

| 改造层 | 对应的写作工艺铁律 | 要点 |
|---|---|---|
| 角色知识边界 | **限知视角 / 不 head-hop**(Le Guin) | "只有视角角色知道/感知/想的才能写";跳进非焦点角色的脑子("head-hopping")是头号坑。老道泄露 = head-hopping。 |
| 单一真相源·轻量账本 | **Story Bible** | 职业作家用活的参考文档记角色/时间线/"谁知道什么"/伏笔线;**"能用的最小版本永远胜过华丽却被弃用的(functional minimum beats elaborate abandonment)"**——直接背书"轻量账本 > 重型模拟引擎"。 |
| 预设 canonical 前史 | **冰山理论**(Hemingway) | "know everything, show one eighth";作者事先 intimately 知道角色全部前史、只露 1/8。"阿萤前史前后打架"正是违反冰山(临时编、不自洽)。 |
| 不做全角色模拟 | **Plotter / Plantser**(非 Pantser 极端) | "角色自主接管"是 pantser 模式;有伏笔兑现/反讽/主题的结构性文学偏 plotter(自上而下设计)。全模拟产出"生活"而非"被设计的故事"。 |

**关键修正(贴合本书声音):** 乱世铜炉是**全知说书人**嗓音(有评点旁白)。知识边界应作用于**"角色的知识(他能说/能做什么)"**,而非**"叙述者的视角(它能告诉读者什么)"**。故注入策略取 **"标记私密"而非"扣留"**:全知叙述者仍可调取任何信息,但任一**角色**不得说出/表现出知晓他人私密底细。

## 2. 方案选型(为什么取"中道",不取"全模拟")

| 方案 | 治泄露 | 保文笔(统一声音) | 治连贯 | 成本/延迟 | 治"复发"(过度生成) | 建设量 |
|---|---|---|---|---|---|---|
| 多 agent 各写 prose | ✅ | ❌ 接缝碎裂 | 部分 | 很高 | ❌ | 大 |
| 意图 agent + 单叙述者 | ✅ | ✅ | ✅ | 高 | ❌ | 大 |
| 全 live 角色演绎(含台前幕后) | ✅ | ✅(若单叙述者) | ✅✅ | 极高 | 间接✅ | 很大 |
| **知识标记注入 + 增量账本 + 预设前史 + knowledge_leak 闸(本方案)** | ✅ 大部分 | ✅ | ✅ | 极低 | ❌(另由纪律闸管) | 小 |

**决策:取本方案。** 理由:
1. **对"乱世铜炉级文笔"这个目标,统一声音 > 知识边界的完美。** 全模拟用完美隔离换文笔碎裂,是亏的。
2. **全模拟不保证戏剧质量、不修文笔、不治复发**——它根治连贯与知识,却产出"生活"非"故事",还很贵。
3. 本方案把三条工艺铁律工程化,**零文笔代价、近零额外成本**,拿下泄露与连贯的大部分收益。
4. 全 live 演绎留作 **endgame** 或**特定不对称信息 set-piece**(一场骗局,各方知道的不一样且这是戏核)的可选工具——**非默认生成模式**。

## 3. 目标架构(四层,从便宜到贵,可独立增量上线)

```
        ┌─────────────────────────────────────────────┐
        │  L4 knowledge_leak 纪律闸(已建)              │  事后检测兜底
        ├─────────────────────────────────────────────┤
        │  L3 知识【标记】注入(build_writing_context) │  生成时:私密信息标"谁知道",
        │      POV角色全内核;他人内核标"他人不知"       │  全知叙述者可用、角色不得泄露
        ├─────────────────────────────────────────────┤
        │  L2 增量知识账本(单一真相源)                 │  定稿时记"本章谁新知道/做了什么"
        │      character_knowledge / 事件账本           │  → 注入按知识状态抽
        ├─────────────────────────────────────────────┤
        │  L1 预设 canonical 前史(冰山)                │  角色前史/timeline 预定义、不现编
        └─────────────────────────────────────────────┘
```

- **L1 预设前史(冰山):** 关键角色的前史/底细在写之前就定死(写进 kernel + 角色 timeline),"露 1/8、知 8/8"。根治"现编致前后不一"。
- **L2 增量知识账本(单一真相源):** 定稿(ingest)时额外记一笔结构化的"本章各角色**新知道了什么 / 做了什么 / 被谁看见**"。真相源是**已写定的章节**(非 live 模拟),近零额外成本。这是"story bible 的 functional minimum"。
- **L3 知识标记注入:** 注入时,POV 角色给完整内核;**其他角色的私密内核(wound/lie/want/need)打"⟨私密·他人不知⟩"标签**;并显式给出本章在场角色的"已知 / 未知"清单(从 L2 账本抽)。**标记不扣留**——保住全知说书嗓音。
- **L4 knowledge_leak 纪律闸(本次已建):** 判官扫描"某角色说出其视角不可能知道的他人私密信息"→ 定位穿帮点截断。事后硬闸,不依赖模型守规。

## 4. 数据模型(SurrealDB·SCHEMALESS,沿用现有约定)

新增 / 扩展:

```
character(扩展)
  + backstory: str            # L1 预设前史(冰山下的 7/8)
  + secrets: list[str]        # 该角色的私密底细(默认他人不知)
  + known_public: list[str]   # 公开可观察的(任何在场者可知)

knowledge_ledger(新表,L2;每章一条 delta)
  work, chapter:int
  learned: [{who, fact, from(谁/事件)}]   # 本章谁新知道了什么
  did:     [{who, action, seen_by:list}]   # 本章谁做了什么、被谁看见
  # 注:fact/action 为短句,真相源=已定稿章节,由 ingest 抽

character_knowledge(派生视图/可缓存,L3 用)
  work, character → known: set[fact]       # 截至某章该角色已知集合(account 累加)
```

> 与现有 `entity_beat / foreshadow.audience_knows / agent_memory` 不冲突:`audience_knows` 管"读者 vs 角色"(戏剧反讽),本账本管"角色 vs 角色"(知识边界),两者正交。

## 5. 逐文件改造点

### scribe2/domain.py
- `Character` 默认字段 + `backstory / secrets / known_public`(L1)。
- `record_knowledge_delta(work, chapter, learned, did)`:写 `knowledge_ledger`(L2)。
- `character_known(work, name, upto_chapter)`:累加账本得"截至该章某角色已知集合"(L3 取数)。
- `relevant_characters` 已有;新增**标记**:返回时附 `is_pov` 与 `secrets`。

### scribe2/writing.py · build_writing_context(L3,核心)
- 判定本章 **POV 角色**(默认主角/`relevant_characters` 首位,可由 beat/intent 指定)。
- 角色块改为**分级 + 标记**:
  - POV 角色:完整内核(伤/谎/欲/需/惧)。
  - 其他在场角色:公开可观察特征(声音/外貌/公开言行)正常给;其私密内核/动机**包"⟨私密·仅其本人知,他人不可说破⟩"**。
- 新增 **【本章知识边界】** 块:从 `character_known` 抽,列"焦三已知 X;老道只知 Y(不知 X/Z)"。
- CONSTRAINT_BLOCK 规则 9【知识边界】**已加**(预防)。

### scribe2/generate.py / app.py(ingest)
- 定稿建章记忆时(`ingest_chapter`),用一次 LLM(或确定性抽取)产出本章 `learned/did`,调 `record_knowledge_delta`(L2)。

### scribe2/critique.py · 纪律闸(L4,已建)
- `build_discipline_prompt` 已含 `knowledge_leak` 判项。**增强:** 把"本章各角色已知集合"喂给判官,判定更准(不只靠常识)。

### REST / MCP
- REST `GET/POST /works/{w}/knowledge-ledger`;`GET /character-known`。
- MCP `record_knowledge`(写)/`character_known`(读),更新 WRITE_TOOLS 守护。

## 7. 验证

1. **单测(确定性):** `character_known` 累加正确;标记注入含"⟨私密·他人不知⟩";边界块列出已知/未知;纪律闸 `knowledge_leak` 解析+截断(已有)。

3. **回归扫描:** 用新增 `knowledge_leak` 判项把 ch1-4 扫一遍,查残留同类轻微泄露并记录。
4. **文笔不退:** P2/P3 上线后,重跑一章对工艺标杆 8 细则 + 3 否决项,确认**声音/密度无回落**(中道的承诺=零文笔代价,必须验证)。

## 8. 非目标(明确不做,及理由)

- **不做"全 live 角色模拟生成 prose"**:文笔碎裂(乱世铜炉命门是统一声音);成本/延迟爆炸;不保证戏剧设计;不治复发。
- **不做"扣留式知识隔离"**:会损全知说书嗓音;改用"标记式"。
- **不把知识账本做成重型 wiki/规则引擎**:违反"functional minimum beats elaborate abandonment";只记 delta、按需累加。

---

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 模型无视注入标记仍泄露 | L4 纪律闸事后硬截(不依赖模型守规) |
| 账本本身漂移/不自洽 | 真相源=已定稿章节;delta 由 ingest 确定性抽,不让模型自由编 |
| 标记块挤占上下文、稀释文笔指令 | 标记从简(一行"⟨私密·他人不知⟩");边界块 cap 行数 |
| POV 角色判定错误 | 默认主角;允许 beat/intent 显式指定本章 POV |
| 与"双高潮/复发"纠缠 | 知识边界与复发正交;复发仍由纪律闸 double_climax 管,互不替代 |

## 10. 一句话

把"限知视角(不 head-hop)+ Story Bible + 冰山理论"三条公认写作铁律**工程化为四层**(预设前史 → 增量知识账本 → 知识标记注入 → knowledge_leak 纪律闸),**零文笔代价根治 POV 泄露与前史漂移**;全 live 角色模拟作为不对称信息 set-piece 的 endgame 可选,不作默认。
