## Task A2 — MCP 召回工具默认打码 secret value(现存最大限知敞口)
**Files:** `scribe3/store.py`(graph_recall)、`scribe3/mcp.py`(4 个召回工具)、`scribe3/tests/test_mcp.py`

**现状**:`s3_semantic_recall`/`s3_hybrid_recall`/`s3_graph_recall`/`s3_dramatic_irony` 原样返回 secret 命题的明文 `value`,只附 `is_secret` 标志却不打码;且 semantic/hybrid 连 focalizer 参数都没有。第一轮 P0 只修了 REST `_facts()` 和 `/graph`,MCP 侧仍是敞口——主编 agent 可把私密原文带进续写 prompt。

**改**:
1. 给这 4 个 MCP 工具各加参数 `reveal_secret: bool = False`。
2. 工具组装返回结果时,对 `f.secret`(或结果项 is_secret 为真)的项:`reveal_secret=False`(默认)→ 把 `value` 替换为 `"🔒 私密"`(与 store.graph 的占位一致);`reveal_secret=True` → 返回明文。
3. `store.graph_recall`(store.py:~495-506)若直接拼 value,同样接受一个 `reveal_secret` 形参并据此打码(被 s3_graph_recall 调用时透传)。
4. docstring 更新:说明默认屏蔽私密 value,`reveal_secret=True` 仅供主编确需核对私密时用,**严禁把解锁结果带入限知章续写**。

**TDD**(test_mcp.py):
```python
def test_recall_masks_secret_value_by_default(store):
    # 种一条 secret 命题
    from scribe3.ontology import Fact
    store.add_entity(...); store.add_fact(Fact("fact:s","role:x","秘密","主角是卧底", valid_from=1, secret=True))
    r = s3_semantic_recall("卧底", ...)            # 按工具真实签名调用
    item = [x for x in r if x.get("is_secret")][0]
    assert "卧底" not in str(item["value"]) and "🔒" in str(item["value"])   # 默认打码
    r2 = s3_semantic_recall("卧底", reveal_secret=True, ...)
    assert any("卧底" in str(x["value"]) for x in r2)                         # 显式解锁可见
```
对 4 个工具各补一条(或参数化)。红→绿 + full test_mcp.py + full tests/ 回归(不要 `| tail`)。

**真机抽验**:`s3_*` 经 MCP 网关不便直调,改 store/工具函数级断言即可。

**提交**:`git add scribe3/store.py scribe3/mcp.py scribe3/tests/test_mcp.py && git commit -m "fix(scribe3): MCP 召回默认打码 secret value(reveal_secret 显式解锁)——堵限知敞口(P0)"`

## Task A1 — 实体层私密 secret 模型(backstory / private_operation)
**Files:** `scribe3/migrations/035_entity_secret.surql`(新建)、`scribe3/store.py`、`scribe3/app.py`、`scribe3/mcp.py`、前端 `scribe3/web/src/views/CodexView.jsx`、`scribe3/tests/test_app.py`

**现状**:`character.backstory`(冰山私密前史)、`faction.private_operation`(势力暗线)经 `/entities`、`/factions` **明文输出,无 secret 标志、无门控**。实体表缺私密字段,与命题层 proposition.secret 不对等。

**改**:
1. **迁移 035**:`DEFINE FIELD IF NOT EXISTS backstory_secret ON character TYPE bool DEFAULT false;` `DEFINE FIELD IF NOT EXISTS private_operation_secret ON faction TYPE bool DEFAULT false;`
2. **写路径**:
   - `store.add_entity`/character PATCH(app.py CharIn)接受 `backstory_secret: bool=False` 并写入。
   - `store.add_faction`/FactionIn(app.py)/`s3_add_faction`(mcp.py)接受 `private_operation_secret: bool=False` 并写入。
3. **读路径屏蔽**(核心):
   - `GET /entities`(app.py:~156)增 `reveal_secret: bool=False` query 参数;`reveal_secret=False` 且 `backstory_secret` 为真 → 输出时 `backstory="🔒 私密"`。
   - `GET /factions` 同理屏蔽 `private_operation`(增 reveal_secret query 参数)。
   - 复用一个小 helper(如 `_mask_field(row, field, secret_field, reveal)`)避免重复。
4. **前端**:CodexView 角色/势力编辑表单,backstory / private_operation 旁加一个「🔒 私密」勾选框(绑 backstory_secret / private_operation_secret),POST 时带上;展示态若返回 "🔒 私密" 则显示锁标。(保持与现有表单样式一致,紧凑。)

**TDD**(test_app.py):
```python
def test_entities_mask_secret_backstory(store):
    c = _client(store)
    c.post("/characters", json={"id":"role:卧底","name":"卧底","backstory":"其实是敌方卧底","backstory_secret":True})
    masked = c.get("/entities").json()
    e = next(x for x in masked if x["id"]=="role:卧底")
    assert "敌方" not in str(e.get("backstory")) and "🔒" in str(e.get("backstory"))
    revealed = c.get("/entities?reveal_secret=true").json()
    assert any("敌方" in str(x.get("backstory")) for x in revealed)
# faction.private_operation 同构一条
```
