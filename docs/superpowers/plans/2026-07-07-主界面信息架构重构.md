# 主界面信息架构重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline, 强耦合布局重构需连贯 context). Steps use checkbox (`- [ ]`).

**Goal:** 主界面从"3 列 + 每列内嵌竖轨 + 4 套 tab"重构为**四区**(上=应用操作 / 左=一列总纲领树 / 中=详情 / 右=主编)+ **通用对象模板**,且**不破坏任何现有功能**。

**Architecture:** 核心手法 = **重组现有组件到新布局骨架,不重写功能**。ProjectTree / CodexDetail / MaterialX / ChiefDock / WriteLayout / 各 Panel 全部复用,只改它们的**容器与编排**。新增 4 个骨架件:`design-tokens`(视觉真源)、`ObjectFrame`(通用对象模板)、`objectRegistry`(类型注册表)、`navigateTo`(跳转总线)。**旧布局用 feature flag `s3.layout.v2` 并存**,每阶段独立可跑 + 真机走查通过才进下一步,最后才下线旧布局。

**Tech Stack:** React + react-resizable-panels v4(Group/Panel/Separator)+ Vite + 现有组件生态。

**Spec:** docs/superpowers/specs/2026-07-07-主界面信息架构重构-design.md

**⚠ 每阶段收尾铁律(用户明确要求,必守)**:①`npm run build` 绿 ②**pw 真机走查**(build 绿≠运行时 OK——上次循环 import 就是 build 绿却白屏;必 pw 加载确认无白屏、无 console error)③**回归走查**该阶段触及的现有功能(素材库/主编/写作/选择环/Pilot 等)无损 ④commit。不过关不进下一阶段,不偷懒。

---

## File Structure

**新增(骨架件,web/src/layout/)**:
- `layout/tokens.js` — 设计 token 单一真源(色/间距/圆角/字号),导出给 tailwind/inline 用。
- `layout/objectRegistry.js` — 对象类型注册表:`registry[type] = {crumb, tabs, status, DetailComponent, auxTabs}`。新对象类型只在此登记。
- `layout/ObjectFrame.jsx` — 通用对象模板:读 registry,填充 顶栏面包屑+对象tab+状态 / 中央详情 / 右侧辅助。
- `layout/TopBar.jsx` — 动态顶栏:固定左段(Scribe/作品▾)+ 模式切换(写作/图谱/时间线/仪表盘)+ 动态右段(面包屑/对象tab/状态)+ 全局工具(🔔🔍⛶🌙)。
- `layout/nav.js` — `navigateTo(objectRef)` 跳转总线 + `useCurrentObject()` 当前对象上下文。
- `layout/FourPane.jsx` — 四区骨架(左总纲领树 / 中 ObjectFrame / 右主编),react-resizable-panels。

**修改(骨架层)**:
- `App.jsx` — 顶层:feature flag 分流 v1(BinderLayout)/v2(FourPane+TopBar)。
- `BinderLayout.jsx` — v1 保留不动(回退用)。
- `studioDocks.jsx` — 左轨 caps 拆解:tree 归左树、台账按归位表分流。
- `ChiefDock.jsx` / `ChiefSlotContext.jsx` — 主编上下文订阅 + 唯一入口收敛。

**复用不动**:`ProjectTree`、`CodexDetail`、`Materials*`、`SelectionPanel`、`PilotDock`、`InboxPanel`、`PulseBar`、`views/*`(Atlas/Timeline/Insight)。

## Task 2: 对象类型注册表 + ObjectFrame 骨架(阶段1b)

**Files:** Create `layout/objectRegistry.js`、`layout/ObjectFrame.jsx`;Test `web/src/layout/__tests__/objectFrame.test.jsx`(vitest)

- [ ] **Step 1: 写失败测试**——ObjectFrame 给定 type=chapter 的对象,渲染出面包屑+阶段tab+详情占位+右侧辅助tab。

```jsx
import { render } from '@testing-library/react'
import { ObjectFrame } from '../ObjectFrame'
test('ObjectFrame 按 registry 填充 chapter 的插槽', () => {
  const { getByText } = render(<ObjectFrame type="chapter" obj={{seq:1,title:'第1章',word_count:6600}} />)
  expect(getByText('第1章')).toBeInTheDocument()      // 面包屑
  expect(getByText('正文')).toBeInTheDocument()        // 阶段tab之一
})
```

- [ ] **Step 2** 跑失败:`cd web && npx vitest run src/layout/__tests__/objectFrame.test.jsx`。
- [ ] **Step 3: 实现** registry(先注册 chapter/character/material 三类)+ ObjectFrame(读 registry 填插槽;详情/辅助先用现有组件或占位)。registry 契约:

```js
export const registry = {
  chapter:   { crumb:o=>`${o.volume||'卷'} › ${o.title}`, tabs:['大纲','节拍','演绎','草稿','正文'],

  character: { crumb:o=>`设定库 › 角色 › ${o.name}`, tabs:['档案','弧光','关系'],

  material:  { crumb:o=>`素材库 › ${(o.ref_tags||[])[0]||'素材'} › ${o.title}`, tabs:['正文','关键词'],
               status:o=>`被参考${o.recall_count||0}次`, auxTabs:['联想','用在哪'] },
}
```
