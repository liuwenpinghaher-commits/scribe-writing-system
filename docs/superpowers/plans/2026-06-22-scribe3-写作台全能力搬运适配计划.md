# scribe3 写作台 · scribe2 全能力搬运 + 适配计划

> 把 scribe2 web-app 所有能搬的视图/能力搬回 scribe3,**按新本体(事件/三知识帧/限知渲染)适配化改造,不原封照搬**。
> 2026-06-22 · 依据 scribe2 全 UI 编目(5 视图 / 8 右轨 inspector / 44 端点 / TipTap·ReactFlow·recharts·react-table·cmdk)

---

## 0. 适配总原则(scribe3 ≠ scribe2)
scribe2 是**扁平实体模型**(work→character/setting/foreshadow,knowledge 无一等公民);scribe3 是**事件本体 + 三知识帧**(character/proposition/event/knows边/reader帧/promise/motif,多书=一书一DB)。搬运时:
- **保留**:WorkspaceShell 三列壳(已搬)、shadcn 风组件(已有 ui.jsx)、SSE 流式、划词工具、Markdown 渲染、库栈(TipTap/ReactFlow/recharts/react-table/cmdk)。
- **改造**:数据维度从 `work_id` 换成 `?work=<slug>`(已做);"关系图"用 scribe3 的**真知识图**(knows/causal/participates 边)而非扁平 relations;"设定库"覆盖 scribe3 的 character/proposition/event/promise/motif;"质量仪表盘"聚合 scribe3 的双层QC/伏笔超期/因果/知识覆盖;"主编对话"走 **Hermes /v1/responses(scribe3 profile)+ s3_ 工具 + elicitation 待批**。
- **不搬/降级**:scribe2 里依赖其特有后端的(分支合并/段级重建/想象捕获/待决方案 optionsets)——scribe3 无对应,列为可选远期或不做。

## 3. 后端要补的端点(支撑上述)
1. **设定库 CRUD**(REST,复用 MCP 背后的 domain 逻辑,不经 elicitation——前端直接编辑是作者操作):
   `GET/POST/PATCH/DELETE /characters /facts /events /promises /motifs`(均带 `?work=`)。
2. **关系图**:`GET /graph?work=&chapter=` → `{nodes:[{id,type,label}], edges:[{src,dst,rel}]}`(查 knows/causal/participates)。
3. **质量聚合**:`GET /quality?work=` → 每章字数/QC问题数/因果违规/伏笔状态汇总。
4. **主编对话代理**:`GET /chat/stream?work=&msg=`(SSE)→ 代理 Hermes `/v1/responses`(scribe3 profile,instructions=主编人格,工具来自 config)。+ 待批写列表/响应(elicitation 经 mcp_serve permissions 或自建队列)。
5. **意图**:`GET/PUT /intent?work=`。
6. **划词**:`GET/POST/DELETE /annotations /highlights`(带 work+seq)。
7. **抽取**:`POST /extract?work=&seq=` → 候选实体/设定/伏笔。

> 多数 CRUD 复用已有 store/domain;主编对话代理是最大新件(Hermes responses SSE 转发)。

## 5. 分阶段实现(按价值×契合度排序)

### Phase A — 设定库 + 关系图谱 + 仪表盘(数据已有,最契合 scribe3)
- A1 **设定库 CRUD 后端**(`/characters /facts /events /promises /motifs` GET/POST/PATCH/DELETE)+ TDD。
- A2 **CodexView**(react-table 表格 + 分类 tab)+ **EntityEditor**(全字段编辑,按 scribe3 类型映射)。
- A3 **关系图谱**:`/graph` 端点 + **AtlasView**(@xyflow + elkjs,类型着色,按章过滤,点节点进编辑)。← scribe3 是图库,这块最出彩。
- A4 **质量仪表盘**:`/quality` 聚合 + **InsightView**(recharts)。
- A5 AppRail 加视图 tab(写作/设定库/图谱/仪表盘),App 路由这些视图。

### Phase B — 主编对话(agentic 核心)
- B1 **Hermes chat 代理**:`/chat/stream` SSE 转发 Hermes responses(scribe3 profile + s3_ 工具)。
- B2 **Conversation 面板**:SSE 流式 Markdown + 工具时间线折叠 + 待批写(elicitation)approve/reject 卡。
- B3 划词"讨论这段"带引文进对话。

### Phase C — 编辑器 + 写作 UX
- C1 **TipTap 富文本**替换 textarea(SelectionToolbar:讨论/改写/批注/高亮)。
- C2 **本章在场** InScenePanel(participants + focalizer 知识)。
- C3 **北极星 intent**(喂 discipline brief)。
- C4 **命令面板 ⌘K**(cmdk)。

### Phase D — 抽取/捕获(可选)
- D1 **ExtractPanel**(抽角色/设定/伏笔候选入库)。
- D2 大纲树 Navigator 增强(卷/新增章)。
- D3 素材/想象捕获(若需要)。

每阶段:TDD(后端 pytest + 前端 `npm run build`)+ 真机验证 + 提交。Phase A 先做(数据现成、最契合、最出彩)。

## 6. 不搬清单(诚实)
- 分支合并 / 段级重建 / 想象捕获 / 待决方案 optionsets:scribe3 无对应范式,远期或不做。
- scribe2 的"工具时间线/scribe-card"对话内嵌格式:Phase B 按需简化适配。

## 7. 一句话
**先搬最契合 scribe3 的三块(设定库 CRUD 表格+编辑器 / 关系图谱=真知识图 / 质量仪表盘),再搬 agentic 主编对话(Hermes responses 代理+elicitation 待批),再补富文本编辑器+划词+本章在场+北极星+命令面板;全部按事件本体/三知识帧适配,不照搬扁平模型。Phase A 起步。**
