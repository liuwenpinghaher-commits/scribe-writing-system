## Task P2-E2 — char_state 时点快照注入续写 prompt
**Files:** `scribe3/app.py`(chat_write GET+POST 的 instructions 构造)、`scribe3/tests/test_app.py`
**现状**:`char_state_at` 合成的角色弧光快照只被"手动查询框"和 mcp 消费,**续写 prompt 不注入角色当前弧光** → 生成第N章时模型不知道角色此刻能力/性格。
**改**:仿照已有的 `_voice_anchor_block`(声音锚),加 `_arc_state_block(st, focalizer, chapter)`:当 focalizer 设定时,取 `store.char_state_at(focalizer, chapter)`,把非空的 abilities/relations/personality/当前 arc_phase 压成紧凑块注入 instructions(`## 本章焦点者弧光状态\n能力:… 关系:… 性格:… 阶段:…`)。在 `chat_write`(GET)与 `chat_write_post`(POST)两处都注入(紧接 `_voice_anchor_block` 之后)。None/空守护,块为空则不注入。
**TDD**(test_app.py):
```python
def test_arc_state_block_injects_snapshot(store):
    store.add_char_state(character_id="role:甲", chapter=2, change_type="ability",
                         summary="习剑", after_state={"ability_snapshot":{"御剑":"初成"}})
    from scribe3.app import _arc_state_block
    block = _arc_state_block(store, "role:甲", 5)
    assert "御剑" in block and "弧光" in block
    assert _arc_state_block(store, "", 5) == ""        # 无焦点者不注入
```

## Task P2-E1 — reader_knows 自动钩子(戏剧反讽真跑起来)
**Files:** `scribe3/ingest.py`、`scribe3/store.py`、`scribe3/tests/test_ingest.py`(或 test_store)
**现状**:`reader_knows` 读侧闭环(dramatic_irony)但**写侧只有手动 s3_record_knowledge + seed_demo**,无"叙述揭示→自动 reader_knows"钩子 → 真机近乎空表 → 戏剧反讽恒空。
**改**:ingest 是"读定稿抽知识"的唯一自动入口——正文里揭示的命题,读者读到了即"读者已知"。在 `ingest_chapter`/`apply_delta` 写入命题(fact)时,**同时**为这些命题写 reader_knows 边(since_chapter=该章 seq)。即:ingest 在第 N 章新建/确认的每条 fact,自动 `add_knowledge(knower="reader", proposition=fact, since_chapter=N)`(复用现有 reader 写路径,READ store 看 reader_knows 怎么写)。注意幂等:同 ingest_seq 重跑不重复堆叠(与现有 purge_ingest 机制一致)。
**TDD**(test_ingest.py):跑一段 ingest(用现有 ingest 测试夹具/喂一个 delta),断言被 ingest 的命题在 `dramatic_irony` 的 reader 帧里出现(此前为空)。或更直接:ingest 后 `store.load_knowledge()` 含 knower=="reader" 的边指向该 chapter 抽出的 fact。
