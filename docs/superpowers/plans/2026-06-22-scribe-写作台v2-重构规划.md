# scribe2 写作台 v2 重构规划

> 配套《故事本体 v2 全局重构方案》的创作层规划
> 2026-06-22 · 依据 2 路并行 authoring-UX 调研(Novelcrafter/Sudowrite/ink·Inky/Aeon/Inform-Epistemology + CHI·IUI·ICIDS 论文,逐条带证)+ ui-ux-pro-max 规范

---

## 0. 核心论断

底层换成事件本体后,**写作台不再是"敲正文 + 注入上下文",而是"作者设计 fabula 事件 → 选 focalizer 冻结知识帧 → 系统按知识帧渲染 sjuzhet → 作者校订 → 回写结构"的双表面创作环境。**

一句话:**写作台 = 一个"结构面(设计发生什么)+ 散文面(渲染怎么讲)"双表面环境,知识帧在两者之间做中介;限知/一致性/伏笔/反讽从"事后闸"变成"创作时可见的约束与查询"。** 这恰好落在全部竞品的接缝上——Plottr 只规划不生成、Sudowrite/Novelcrafter 生成但结构层是自由文本、没有一个工具把"POV 知识帧""伏笔超期""因果断裂"做成创作时一等对象。**这正是 scribe2 的护城河,且后端骨架(discipline_check/fix_leak/knowledge_ledger/foreshadows)已具备。**

## 1. 范式裁决:写作台 = model-then-render 的双表面环境

"结构与散文如何协同"有四种范式,代价曲线清晰:

| 范式 | 代表 | 协同方式 | 致命弱点 |
|---|---|---|---|
| 共享基底 | Scrivener 软木板 | 三视图是同一文档序列的投影,拖卡=重排正文 | 分支/结构表达弱 |
| 空间图 | Twine / Final Draft Beat Board | 节点=passage,正文藏盒里 | 图会"说谎"(动态关系不画边);大库杂乱;**误导性对称诱导过度搭建** |
| 内联标记 | ink(weave/divert) | 散文为默认表面,流程织入同一文件 | 需学语法;无鸟瞰图 |
| **先建模后渲染** | **Inform 7** | 世界=事实/规则库,散文挂为属性+规则输出 | **最强分离;但易"仿真饿死散文"** |

**scribe2 落点 = model-then-render(本体即世界库)**——这是最强分离,也最匹配"事件/状态/POV/知识"做底座。
**已知坑 + 解药**:model-then-render 易沦为"带笨拙界面的数据库"(Emily Short)。解药 = 抄 **Inky 的双栏 + 双向源映射**:左结构、右实时散文,**渲染出的每一句可点回它来自的结构对象**(alt-click 高亮源),让结构以"可往返的实时播放轨"呈现,而非静态图。+ 借 ink 的"weave 默认就接得上"思想——让**结构合法性成为编辑器的结构性默认**,而非事后校验。

> 调研实证:[ink weave 鲁棒性(已逐字复核)](https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md) · [Inky 双栏 alt-click 回源](https://www.inklestudios.com/ink/web-tutorial/) · [model-then-render 易饿死散文](https://emshort.blog/2018/07/10/mailbag-world-simulation-plug-ins/) · [双表面漂移=头号失败模式](https://pulsegeek.com/articles/twine-vs-ink-for-branching-dialogue-which-fits-you/)

## 3. 创作环(ontology-native,6 步)

```
1.设计fabula  →  2.冻结知识帧  →  3.渲染sjuzhet  →  4.校验(查询)  →  5.回写结构  →  6.QC兜底
  排Event卡       选focalizer      单Event→多候选     因果/伏笔/POV/    矛盾即调和+      dedup/discipline/
  因果挂接        算known集合      局部接受+紫标      反讽 实时flag     抽取入库        leak 降为建议
  校验因果完整    =渲染硬约束      双层steer                          (喂下一章=紧凑state)
```

**1. 设计 fabula(结构面)**:把本章要发生的事排成 Event scene-card。强 schema(经 craft 多源验证):**POV · 目标 Goal · 冲突 Conflict · 结局 Outcome(枚举 Yes/Yes-but/No/No-and-furthermore)· 价值转 Value-shift**;挂 `causal_in/out` 边、`motivated_by_goal`。核心 5 字段默认、其余可选(`progressive-disclosure`——字段太多作者会跳过)。系统即时校验:`causal_in` 空(除开篇)或 `motivated_by_goal` 空 → 行内提示(`inline-validation`)。

**2. 选 focalizer + 冻结知识帧(知识帧 UX,§4.2)**:选本场视角角色 → 系统算 `known = 目击∪被告知∪推断` → 显示"他此刻知道什么" → **作为渲染 prompt 的硬约束注入**。这是 POV 泄露结构性消失的关键:渲染老道时只喂他的 known 集,帧里没有"焦三给娘治眼"→ 物理上写不出。

**3. 渲染 sjuzhet(散文面,§4.3)**:单 Event → [渲染] → 1–N 候选卡 → 作者 Insert 一个(AI 文本紫色标记)→ 选区局部重写;双层 steer(每事件指令框 + 文内 [方括号])。系统只把 `known` 子集 + 周边 + 显式相关知识条目喂生成。

**4. 校验(查询,非判官,§4.5)**:实时显示 因果断裂/伏笔超期/POV 穿帮/反讽点。反讽 = `KNOWS(reader,F) ∧ ¬KNOWS(focal,F)` 的布尔投影,直接复用知识层。

**5. 回写(散文→结构)**:两条腿——(a) **矛盾即调和**:渲染后检测散文与 Fact/plan 冲突,修一侧并更新 KnowledgeEdge/Fact;(b) **抽取入库**:从定稿抽 Event/Fact/Knowledge delta 回库(smart-import)。**喂下一章的是更新后的紧凑 state,不是原始全文**(界定漂移)。

**6. QC 兜底(渲染层质检)**:移植已验证的 `dedup_chapter`/`discipline_check`/`fix_leak`——但**降为"建议"而非"拦截"**(critique 有噪声),因为限知已在生成前结构性保证,QC 只兜机械质量(复读/双高潮/声音崩)。

## 4. 核心交互详解

### 4.1 结构面:Event scene-card
- 卡片字段驱动 prose(不是自由文本):POV/Goal/Conflict/Outcome/Value-shift + 因果边 + motivated_by_goal。
- 拖拽改归属/顺序(Plottr 式);把一个 Event 拖到另一个上 → 生成持久因果边(Final Draft Flow Line 式)。
- 区分 Scene(目标/冲突/灾难)与 Sequel(反应/两难/决定)两种卡型(K.M. Weiland)。
> [GMC/Outcome 枚举](https://icefallpress.livejournal.com/31380.html) · [Scene/Sequel](https://www.helpingwritersbecomeauthors.com/scene-structure/) · [因果边作为对象 Final Draft](https://www.finaldraft.com/blog/how-to-use-final-draft-the-beat-board)

### 4.2 知识帧 UX(全场最关键、市面最空白)
能力阶梯:散文工具(一 POV+上色+过滤,知识在脑里)→ Aeon(participant/observer 显式+单角色过滤,**仅第一手**)→ **Inform+Epistemology(per-perceiver 可见 + `is unknown` + 作者期 `EPISTAT` 查询)** → 研究系统(完整主观信念可背离可传播)。

**scribe2 目标对标 Inform-level 并超越**:
- **focalizer 选择器**:本场选视角角色(一场一 POV = head-hopping 的结构护栏)。
- **「他此刻知道什么」检查器**:Inform `EPISTAT` 式——列出该角色截至本章的 known 集合 + 每条的**来源标签(目击/被告知/推断/谎言)**。这是连 Aeon 都没做到的"第二手知识"(角色从信里得知 ≠ 穿帮)。
- **冻结为渲染硬前置**:渲染该场前,known 集合即被锁为生成约束,而非事后 critique。
- 复用 scribe2 已有 `character_known`/`knowledge_ledger`/`record_knowledge` 后端骨。
> [Inform per-perceiver "can be seen by Helen"](https://ganelson.github.io/inform-website/book/WI_6_13.html) · [Epistemology seen/familiar/known + EPISTAT](http://inform7.com/extensions/Eric%20Eve/Epistemology/source.txt) · [Aeon participant/observer 仅第一手](https://help.aeontimeline.com/article/20-key-concepts) · [Talk of the Town 五现象 观察/告知/误记/谎言](http://www.gameaipro.com/GameAIPro3/GameAIPro3_Chapter37_Simulating_Character_Knowledge_Phenomena_in_Talk_of_the_Town.pdf) · [深POV=知识过滤器/head-hopping](https://nownovel.com/how-to-write-deep-pov/)

### 4.3 散文面:渲染 + 局部接受 + 回链
- **多候选**(Number of Cards 1–6)→ Insert 一个 → **AI 文本紫色直到被编辑**(provenance UX)→ **可撤销**(`undo-support`)。
- **局部重写**:选区(设最小阈值,如 ≥4 词)→ Rephrase/扩写/Show-not-Tell/自定义 → **只替换选区**,绝不整章重生。
- **双层 steer**:每事件一个自由指令框(语气/节奏 + Tone 预设)+ 文内 `[放慢][扩写对话]` 内联命令。
- **每句回链结构**(Inky):alt-click 渲染句 → 高亮其来源 Event,防双表面漂移。
- **加载反馈**(ui-ux-pro-max `progressive-loading`/`loading-buttons`):生成 >300ms → 骨架屏/进度,**不阻塞输入**(`no-blocking-animation`)。
> [Sudowrite 多候选/紫标/Insert](https://docs.sudowrite.com/using-sudowrite/write/pvxUvbQqYybfEosqx1sXjY) · [Novelcrafter `/`→scene beat、[方括号]内联、选区≥4词](https://www.novelcrafter.com/help/docs/write/text-replacement-prompts) · [Wordcraft 动词集](https://dl.acm.org/doi/fullHtml/10.1145/3490099.3511105)

### 4.4 上下文注入 UX
- **每设定条三态 Always / 命中检测 / Never**(Novelcrafter)+ name/alias 自动检测 + exclusion list 压误检 + relations 带关联条目。
- **context-bar 可见**(NovelAI):色块分来源 + token 占比——长篇作者最需"知道喂了什么"。
- **差异化机会**:目前头部工具检测压倒性是**字面 name/alias 匹配**,无人做**语义 RAG 召回设定**——scribe2 有 SurrealDB + 向量,这是差异化点。
> [Novelcrafter AI Context 三态](https://www.novelcrafter.com/help/docs/codex/anatomy-codex-entry) · [NovelAI Lorebook + Context Bar](https://docs.novelai.net/en/text/lorebook/)

### 4.5 校验面:实时 flag(查询非判官)
- **因果断裂**:Event `causal_in` 空 → Aeon 式 badge 计数 + 红图标 + inspector 高亮。
- **伏笔超期**:promise 带 `open/closed` + setup 锚 + 必需 payoff 锚;章末标 `OPEN`、payoff 距 setup 超阈值告警——**任何商业工具都没有**(Plottr 官方明示"Automatic Warnings: No")。scribe2 已有 `list_foreshadows_status` 后端。
- **POV 穿帮**:`fix_leak`/`discipline_check` 的 knowledge_leak 判项作为兜底 flag。
- **反讽点**:`KNOWS(reader,F) ∧ ¬KNOWS(focal,F)` 内联标记,提示"让焦三安心而读者已知有毒"。
- **arc 曲线**(可选):TaleBrush 式画命运线驱动/校验(Reagan 六种情感弧)。
> [Plottr 手动无告警](https://plottr.com/plot-devices/) · [Sanderson Promise/Progress/Payoff](https://www.brandonsanderson.com/blogs/blog/brandon-sandersons-2025-guide-to-plot-lecture-2) · [Aeon 违例UI badge+红图标](https://help.timeline.app/article/142-dependencies-and-constraints) · [Causality "tells you when you break your own rules"](https://www.hollywoodcamerawork.com/causality.html) · [TaleBrush 命运线](https://johnr0.github.io/publications/TaleBrush_CHI2022/)

### 4.6 主编 chat(本体感知)
- 继续走 Hermes skill(scribe-novel),但**建议锚定到结构对象/文本片段**(AnchoredAI:防整段复制的 automation bias);定位"dramaturg/副驾"。

## 6. 差异化护城河(无竞品做到,scribe2 后端已有骨)
1. **POV 知识帧做成创作时可见约束**(仅 Inform 研究级有;Novelcrafter/Sudowrite 全无)——scribe2 有 `character_known`。
2. **伏笔超期/缺铺垫自动告警**(Plottr 明示无)——scribe2 有 `list_foreshadows_status`。
3. **戏剧反讽 = 可计算查询**(无人做)——scribe2 有读者帧雏形 audience_knows。
4. **因果 link 作为可编辑边 + 违例实时呈现**(仅学术 IPOCL)——scribe2 重构后有 causal_in/out。
5. **语义 RAG 设定召回**(头部工具仍字面匹配)——scribe2 有 SurrealDB 向量。
> 学术线(IPOCL→SIG→plot units)给"对象模型",商业线(Aeon/Causality)证"实时告警可出货",**二者无人统一**——这是护城河。

## 7. mixed-initiative 作者掌控契约
- **核心契约**:轻推结构/体验,**绝不夺走作者的选择**(drama manager 共识;现实工具均"作者主导、系统建议",final authority 在人)。
- **可设旋钮(MICC)**:Initiative / Evaluation(谁能 accept-reject)/ Final Decision / Pace。
- **三个必做原语**:多建议 / accept-reject-edit / 换种子重生。
- **可编辑抽象层级**(Dramatron):logline→Event→POV/事实→散文 任一层可 Regenerate/Continue/Edit,改上游级联下游。
- **隐式校准**:用**编辑距离=帮助度**(Creative Help)自动调建议强度。
- **故意保留摩擦**(desirable difficulty / AnchoredAI):建议锚到片段制造"deliberation 暂停点",防过度委派。
- **定位副驾保署名感**:Dramatron 数据——77% 觉得真协作但**仅 46% 有 pride**;系统越能干越易不认领。
> [MICC 7旋钮](https://arxiv.org/html/2401.05999v1) · [Dramatron 84%有用/46%pride](https://deepmind.google/research/publications/13609/) · [AnchoredAI 锚定防过度依赖](https://arxiv.org/html/2509.16128) · [Creative Help 编辑距离](https://asgordon.github.io/publications/ICIDS15.PDF)

## 8. UI/UX 规范要点(应用 ui-ux-pro-max)
- **加载**:生成 >300ms → 骨架/进度,不阻塞输入;按钮 async 时 disable+spinner。
- **多候选/接受部分**:候选卡 + 紫色 provenance + 可撤销(undo toast)。
- **表单(scene card)**:可见 label、错误近字段、`progressive-disclosure`(核心5字段默认)、blur 校验非每键。
- **层级**:尺寸/间距/对比建立层级,非颜色;散文面 primary;每屏一主 CTA。
- **校验 flag**:图标+文字非纯色(`color-not-only`);destructive(删 Event)用 danger 色+确认+可撤销。
- **可访问/响应**:键盘可达、focus ring、窄屏折叠为抽屉(散文优先)、min-h-dvh。
- **动效**:150–300ms、transform/opacity、`prefers-reduced-motion`;候选切换 crossfade。

## 10. 风险与反面教训(调研实证)
1. **model-then-render 会"仿真饿死散文"**——必须保散文面 primary,别让结构编辑挤掉文字打磨;Inky 双向回链是解药。
2. **双表面漂移是头号失败模式**——回写闭环 + 每句回链 + 喂紧凑 state 防漂移。
3. **结构图"误导性对称"诱导过度搭建**——用"默认就接得上"把合法性做进结构本身,别靠漂亮的图。
4. **LLM 长文必漂移**(中段/高熵段集中)——喂更新后 state 非全文。
5. **别承诺语义 RAG 却只做字面**(但语义 RAG 是差异化机会);**别承诺"私有微调你的声音"**(先把样本 few-shot+描述符做扎实)。
6. **一致性检查业界只覆盖时序/逻辑**;伏笔回收/POV穿帮/反讽无人自动化=机会但需自建判定(scribe2 已有 discipline_check/fix_leak 基础)。
7. **渲染默认字数可调**(太长模型跑偏,Novelcrafter 默认 400);**QC 做"建议"非"拦截"**(critique 噪声坑)。

---

## 11. 明确不做
- 不做全 live 多角色 prose 模拟(碎裂/不保证戏剧性/贵)。
- 不把空间图当主创作面(漂移/过度搭建)。
- 不靠初稿自律防 POV 泄露(实测预防~67% 不可靠)——靠创作时知识帧硬约束 + 兜底 pass。
- 不把 QC 做成硬拦截(噪声;做建议)。
- 不堆砌 scene-card 字段(作者会跳过;核心 5 字段默认)。

---

## 12. 一句话
**写作台 v2 = 双表面 ontology-native 环境:结构面设计 fabula 事件(强 schema scene-card + 因果边),选 focalizer 冻结知识帧并作为渲染硬约束,散文面把 fabula∩知识帧 渲染成 sjuzhet(多候选+紫标+选区局部重写+每句回链结构),校验面把因果/伏笔/POV/反讽做成实时查询 flag,回写闭环把定稿抽回结构。限知/一致性/伏笔/反讽从"事后闸"变成"创作时可见约束与查询";作者全程掌舵、系统当副驾。后端骨架(知识账本/伏笔状态/纪律闸/外科修)已具备,这些正是无竞品做到的护城河。**
