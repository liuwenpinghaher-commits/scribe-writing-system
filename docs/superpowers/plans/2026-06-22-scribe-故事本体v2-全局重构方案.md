# scribe2 全局重构方案:故事本体 v2

> 事件本体 + 双时间轴(发生/讲述) + 三知识帧 + 多视图投影
> 2026-06-22 · 依据 4 路并行学术级调研(计算叙事学 / 故事引擎 / 时间·认知 KR / 工具架构),逐条带证、互相印证

---

## 0. 核心论断(一句话)

把底层从**"实体清单 + 章节流"** 重构为 **"事件本体 + 双时间轴 + 三知识帧"**——这一套**单一原理**同时根治本会话暴露的全部老大难(POV 泄露、设定漂移、双高潮/复发、泳道装不下),并让它们**从"事后闸救"变成"结构上不会犯"**;UI 是这套本体的多视图投影,泳道只是其中一个视图。

**关键认知(全行业 + 学术共识,被四份调研反复坐实):**
1. **fabula(发生了什么)与 sjuzhet(怎么讲)是两个独立对象**,后者 = 前者的"选择 + 重排 + 渲染"。[Cheong&Young, Riedl&Young, Bal, Genette, Curveship]
2. **限知渲染靠【查询】、不靠【事后判官】**——渲染前先按视角角色的知识帧投影出"可见子集",只把它喂给生成。判官只配兜底。[Sabre, Curveship, 聚焦理论]
3. **状态层用 append-only 双时态事实日志(event sourcing)**,改稿=追溯写,绝不就地覆盖。[Fowler, SQL:2011, Datomic, XTDB]
4. **纯模拟产出的是流水账,不是故事**——本体给地基,戏剧层(伏笔/反讽/北极星)仍需作者智能塑形。[Tarn Adams, James Ryan, Façade]
5. **一个数据模型 → 多视图投影**,默认表视图,图谱按需且默认本地化,泳道降级为时间线布局。[Notion, Aeon Timeline, Obsidian]

## 1. 本体:四层 + 一条红线

### 1.1 红线——持续体 / 发生体(BFO·DOLCE)
故事里"存在的东西"分两个**存在范畴**,不可混在一层:
- **持续体(continuant / endurant)**:无时间部分、在其存在的每一刻整个在场——**角色 / 物件 / 地点 / 阵营**。跨章保持同一身份。
- **发生体(occurrent / perdurant)**:有时间部分、在时间中展开——**事件 / 场景 / 过程**。占据章节区间。
- **状态(quality)**:依赖持续体、随时间索引地 inhere 于恰好一个宿主——这就是为什么"角色状态"必须挂在角色上**并按故事时刻索引**(DOLCE:用"quality 之变"而非"实体的时间部分"表征实体之变 → 改 fluent 值发一条新事实,不给角色切时间片)。

→ **四类一等公民,各司其职,不混**:`Entity`(持续体)/ `Event`(发生体)/ `Fact`(quality,随时间索引)/ `KnowledgeEdge`(某 knower 对某 Fact 的视角)。

### 1.2 四层本体
```
IV. 戏剧/目的层(为什么是故事而非流水账)
     Goal · Plan · Throughline(贯穿线) · Promise→Payoff(伏笔) · Value · Theme/北极星
        ▲ 作者智能在此塑形(本体不自动产出戏剧性)
III. 叙述层 sjuzhet(怎么讲)         —— 与世界层正交的第二条时间轴
     Scene/Beat:经某 focalizer、按某 presentation_order、渲染选定的 Event;
     参数 = Genette 的 order / duration / frequency / focalization / narrator
II. 认知层(谁知道什么)              —— 世界之上的模态叠加
     KnowledgeEdge:每个 agent(+reader) 的 belief base(可错、非闭包),随事件更新
I.  世界层 fabula(客观发生,唯一事实源,按 story-time)
     Entity(持续体) · Event(发生体,事件原语) · Fact(状态@时间,双时态) · CausalLink(因果)
```

### 1.3 一等公民类型表(综合 SIG/Drammar/OntoMedia/NKRL/Trabasso)
| 类型 | 层 | 关键属性 |
|---|---|---|
| **Entity** | I | id;子类 Character(有意图,带 belief/goal)/ Item / Place / Faction;traits(可观察 vs 私密) |
| **Event** | I | 见 §2.2;参与者(role 化)/时空/前条件/后效果/因果/motivated_by_goal;is_intentional;is_executed(未执行=被挫败=冲突) |
| **Fact(State)** | I | 命题化的世界/心理条件,双时态(valid/tx),caused_by_event;靠惯性持续 |
| **CausalLink** | I | from/to;type:physical / enabling / motivation / psychological(连贯性的实证基础:因果连接数越多越被判重要) |
| **KnowledgeEdge(Belief)** | II | knower → proposition;polarity(可假=误信)/certainty/since·until_chapter/acquired_via |
| **Goal** | IV | owner;mode=attain/maintain/leave/avoid;父子;状态;typed(健康/荣誉/财富…) |
| **Throughline** | IV | 贯穿线=一串因果相连的 Event/Beat;角色弧光/母题/伏笔/设定线皆其子类 |
| **Promise→Payoff** | IV | 被开启、必须闭合的张力;= 受约束的 prolepsis(把某 Event 的揭示提前到 discourse 早处、锁住其因果不变) |
| **Discourse/Scene** | III | focalizer / narrator / presentation_order / anachrony(analepsis/prolepsis) / duration / frequency |
| **Value · Emotion** | IV | 价值卷入→伦理张力;OCC 情感由"目标达成/受威胁"appraisal 得出 |

## 2. 数据模型(落到 SurrealDB 图)

SurrealDB 的图边是带类型/方向/属性的真实表(`RELATE a->knows->b SET ...`)——天然承载本体的关系层,补上 Novelcrafter"关系无语义"的短板。

### 2.1 世界状态 = append-only 双时态事实日志(不是可变状态表)
```jsonc
Fact {                  // 一条事实一行,追加写,绝不就地改
  entity_id,            // role:焦三 / item:尸丹 / place:乱岗
  attribute,            // fluent:location / hp / 拿着尸丹 / alive
  value,
  valid_from,           // 故事内生效起点(章/场)——事件演算 Initiates 点
  valid_to,             // 故事内失效(null=惯性持续)——Terminates 点
  tx_from, tx_to,       // 草稿版本(改稿可回溯;null=当前草稿有效)
  caused_by_event       // 哪个 Event 初始化了它(因果链)
}
// 查"第 N 章实体 X 的状态" = valid_from<=N AND (valid_to=NONE OR valid_to>N) AND tx_to=NONE
// 作者第20章决定"国王第5章就死了" = valid-time 过去的追溯写,不破坏已写章节
```
- **双时态**:valid time(故事内时间=章) ⟂ transaction time(创作/草稿版本)。两轴绝不混。
- **fluent + 惯性**:值一旦被事件设定,持续到下一个改它的事件,无须逐章重写;`Releases` 处理"生死未卜"(暂时豁免惯性)。
- **Allen 13 区间关系**给重叠的弧/场景排序("中毒区间 during 宴会区间","A线 overlaps B线")。

### 2.2 事件原语 Event(字段级)
```jsonc
Event {
  id, type,                       // "取丹"/"对峙"/"死";细类如 ACE 33 子类 / Propp 功能
  is_intentional: true,           // Action(角色意图驱动) vs UnintentionalProcess
  is_executed: true,              // false=被挫败的意图=冲突的结构签名(CPOCL)
  participants: {                 // role 化的格槽(n 元,勿退化成二元三元)
    SUBJ, OBJ, SOURCE, BENF, MODAL, TOPIC, CONTEXT
  },
  location, story_time,           // 世界时间(OWL-Time 区间)
  preconditions: [Fact谓词],      // STRIPS:须成立的状态
  effects:       [Fact谓词],      // 改变的状态(→自动生成 Fact)
  causal_in:  [{from, type}],     // 谁的 effect 满足了我的 precondition
  causal_out: [{to,   type}],     // physical|enabling|motivation|psychological
  motivated_by_goal,              // IPOCL 硬约束:每个角色动作须挂在该角色某目标上
  affect_impact, value_impact     // 驱动张力(可选)
}
```
**硬约束(生成时 schema 校验,不靠事后 critique)**:每个 Event 必须有 `causal_in`(除开篇)且 `motivated_by_goal` 非空。这把"连贯性"从噪声大的 LLM 评审前移成结构拒绝条件(绕开本会话记下的 critique 噪声坑)。

### 2.3 知识 = 双时态信念边(belief base,可错、非闭包)
```jsonc
KnowledgeEdge {                   // role --[believes]--> proposition(指向 Fact)
  knower_id,                      // role:焦三 / reader:读者 / world:真相
  proposition_id,
  polarity,                       // believes-true / believes-false(=误信) / uncertain
  certainty,                      // 0..1(KD45 不强制 0/1)
  since_chapter, until_chapter,   // valid:何时获知 / 何时遗忘被纠
  tx_from, tx_to,                 // 草稿版本
  acquired_via                    // saw / told_by / inferred / overheard
}
```
- **知识 vs 信念用对逻辑**:世界真相=S5(factive,真);角色信念=KD45(可错、可假——误信是合法状态,是悬疑/欺骗的全部燃料)。
- **belief base 而非 belief set**:只存"显式知道的命题",**不存演绎闭包**——角色不自动知道逻辑后果(读者能推出凶手、角色没串起来=悬念可行)。
- **看见即知道(事件驱动更新)**:Event 落库时算 witnesses(在场/可观察者),只给他们追加 KnowledgeEdge;无知是默认(没边=不知道);听说沿 `told_by` 边二跳扩散、certainty 衰减、可失真为 false belief。

### 2.4 三知识帧 = 同一命题底座上的三种 knower 投影(不建三个库)
| 帧 | knower | 逻辑 | 戏剧功能 |
|---|---|---|---|
| 世界真相 | world(=Fact 表本身) | S5 | 一致性裁判、伏笔账本 |
| 角色信念 | role:X(KnowledgeEdge) | KD45 | 误信、动机、欺骗 |
| 读者已知 | reader(KnowledgeEdge,单调累积) | — | 悬念、惊奇、反讽 |

**戏剧反讽 = 可计算查询,不是人脑事后判断**:
```
dramatic_irony(F, 章C) := KNOWS(reader,F,C) ∧ ¬KNOWS(focal_char,F,C)
```

## 3. 生成范式:fabula → sjuzhet 渲染(老大难在此结构性消失)

**三层硬分离,且"渲染只读"用代码强制(不靠纪律)**——教训:Inform 的 Carry-Out/Report 分离只是约定、编译器不拦,大系统里约定必破。
```
事件本体层(唯一改状态入口)→ 事件日志 fabula → 渲染层(只读 fabula∩知识帧 + spin)→ 散文
```
> 这正是 scribe2 现有 **B3「写工具入队待批 / 只读工具放行」(WRITE_GATED + execute_write 唯一落库点)** 的原则——把"渲染/叙述"明确归到只读那侧即可对齐。

**生成一章 = 渲染既定 fabula 事件的 sjuzhet**:
1. 取本章要讲的 Event 子集 + presentation_order(可非时间序→闪回/伏笔)。
2. **限知投影(查询,非判官)**:`visible = 本章 focalizer 的 KnowledgeEdge`;只把 visible 喂给生成。focalizer 没有边的事实=他不知道=不渲染。
3. spin 参数(Genette):order/duration/frequency/focalization/narrator。
4. 戏剧反讽点 = 渲染前先查 `KNOWS(reader,F) ∧ ¬KNOWS(focal,F)`,标给生成("让焦三安心,而读者已知酒中有毒")。

**为什么三个老大难结构性消失:**
| 老大难 | 旧:事后闸 | 新:结构上不会犯 |
|---|---|---|
| POV 泄露(老道知道治眼) | 判官检测+外科修 | 渲染老道时取**他的知识帧**,帧里没有"焦三给娘治眼"→ 物理上写不出 |
| 设定漂移(尸丹配方前后不一) | 锁定指令+一致性闸 | `Fact` 单一真相,查询而非重编→漂移不可能 |
| 复发/双高潮(偷塞第二高潮) | 纪律闸截断 | 模型渲染**既定 fabula 事件**,情节不在它手里→偷不进 |

## 4. 一致性/连贯 = 可跑的查询(不是人工校对)
- **时间悖论**:"X 在 ch5 valid_to=死亡,却在 ch8 有 location 事件"→ 违反惯性,报错(事件演算 Clipped/Trajectory)。
- **因果完整**:每个 Event `causal_in` 非空 + `motivated_by_goal` 非空,否则拒绝。
- **伏笔账本**:reader 帧记"已埋/未回收"命题区间,Allen `before/meets` 校验"埋设 before 回收"。
- **情绪/张力当资源**(Ceptre):愤怒/信任是可积累、被消费的资源,攒够 N 才兑换成剧烈事件——因果可审计、节奏可调(改 N 改烈度),别用脆弱布尔触发。

## 5. UI:本体的多视图投影

**单一事实源,视图 = 保存的 `(layout, filters, sorts, visibleFields, groupBy)`,改任一视图数据全局同步,绝不复制。**

| 数据形态 | 视图 | 职责 |
|---|---|---|
| 属性(批量对比/筛选/批改) | **表 Table(默认落地页)** | 一眼总览大数据集——直接解决"展现不出更多数据" |
| 关系(谁认识谁/属于谁) | 图谱 Graph(按需镜头) | 结构/聚类/桥接节点 |
| 时序(何时/并行/因果) | 时间线 Timeline(分 lane) | **泳道降级到这里**:每 lane=一角色弧/一剧情线 |
| 叙事顺序 ≠ 时间顺序 | Narrative/Outline | 闪回/插叙的章节装配,与年表解耦 |
| 事件 × 实体(谁在场) | 矩阵 Matrix | 抓"一人同时两地"连续性错误 |
| 状态流转 | 看板 Board | 草稿→定稿、按维度分布 |
| 一个实体全部 | 页 Page | 富详情 + 反链 |

**关键决策(反直觉但被反复验证):默认视图=表,不是图谱。** 图谱只适合探索关系结构、大库下必然"毛球"。

**图谱防毛球七招**:不灌全图;默认聚焦 20–50 节点;search-then-expand / 本地图按 hop 深度;按类型/谓词过滤;分组上色;社区折叠;中心性定节点大小 / DOI-fisheye。

**自动链接 + 反向链接(Novelcrafter + Obsidian 范式)**:
- `name + aliases` 扫正文 → 命中加细下划线 + 悬浮预览卡 + 建反向索引。
- 反链分 **Linked(已确认)/ Unlinked(检测到未链,待确认)**,按来源分桶(正文/摘要/设定/对话)。
- **Unlinked mention → 进 B3 待批队列**,人确认后才落成正式 edge——既自动又不脏库,与现有写审批闸完美契合。

## 7. 迁移路径(增量,绝不大爆炸)
现有数据**全部能投影**到新本体,旧能力照跑、新能力渐开:
- **P0 不动**:entities/settings/motifs/foreshadows/characters 继续用;新本体在旁并行。
- **P1 引入 `Event` 表 + 双时间轴**:把 chapter 拆成"叙述节点(sjuzhet)"并挂到 Event;`char_state`→`Fact`(双时态);`knowledge_ledger`→`KnowledgeEdge`。旧表作为投影源。
- **P2 限知渲染查询化**:`build_writing_context` 的角色注入改为"按 focalizer 的 KnowledgeEdge 投影 visible 子集"——判官退为兜底。
- **P3 一致性查询化**:时间悖论/因果完整/伏笔账本做成 SurrealDB 查询。
- **P4 UI 多视图**:落 `View=(layout,filters,sorts,visibleFields,groupBy)` 抽象 + 表视图(默认)+ 图谱(防毛球)+ 时间线(泳道降级于此)。
- **P5(可选)假信念**:只对"剧情靠它"的少数事实 fork per-character false belief(误会/欺骗),默认不做。

每步 TDD + 全量回归 + 真机验证 + 提交。

## 8. 风险与反面教训(调研实证,务必记住)
1. **纯模拟=流水账**:涌现产出"然后…然后…",不是故事。**必须有作者/戏剧层塑形**(伏笔/反讽/北极星);本体只给地基,不替代作者智能。[Tarn Adams 自承"够用而已";James Ryan"素材几乎总缺故事结构"]
2. **前瞻式 drama management 不可一般化、可能比不管还差**(搜索空间指数爆炸,浅采样退化贪心)。→ 用**反应式 beat 选择 + 张力弧 + 事后 story-sifting**,别赌"搜索未来剧情选最优"。[Nelson&Mateas, Anchorhead 实测]
3. **"渲染只读"必须代码强制**,不能靠约定(Inform 教训)。
4. **假信念(误会/欺骗)很贵**,与"部分知识(限知视角)"是两回事——先确认你只要限知(便宜)还是真要误信(贵,单独立项);别一上来上 Talk-of-the-Town 全套。
5. **嵌套心智("A 以为 B 以为")默认不深做**(Versu 故意不做),要做再上 Sabre 的可嵌套 believes。
6. **手写内容组合爆炸**:稀疏因果独立的场景 + 参数化重讲(spin)是对抗爆炸的关键,别追密集因果链。

## 9. 明确不做(scope 纪律)
- 不做全 live 多角色 prose 模拟(文笔碎裂、不保证戏剧性、贵)——意图 agent 仅作不对称信息 set-piece 工具。
- 不建三个知识库——一份命题底座 + knower 维度。
- 不把图谱当默认视图、不把泳道当设定库骨架。
- 不存 belief 闭包、不默认无限嵌套 ToM、不默认 per-agent 全量世界副本。

---

## 10. 一句话
**把底层重构成"事件本体(持续体/发生体分明)+ 双时间轴(发生 valid / 讲述 tx)+ 三知识帧(真相 S5 / 角色信念 KD45 / 读者已知)+ 渲染层只读地把 fabula∩知识帧 投影成 sjuzhet"——POV 泄露/漂移/复发从"事后闸救"变成"结构上不会犯",一致性/伏笔变成可跑的查询,UI 是这套本体的多视图投影,泳道只是时间线视图的一个布局。本体给扎实地基,戏剧性仍由作者智能在戏剧层塑形。**
