# scribe3 开发标准 · Hermes + SurrealDB 内核

> 后续所有能力开发的统一标准。配套《scribe3 改造计划》。
> 目的:任何人(含未来的 agent)加新能力,都按这套配方长,不漂移、不绕底座。

---

## 0. 三条不变量(最高纪律,任何能力不得违背)

1. **SurrealDB = 唯一真相**。世界状态(实体/事件/事实/知识/伏笔/章节)只存 SurrealDB;**改它只能经写门控 MCP 工具的 execute 单一落库点**。任何代码不得在工具门控外直接写库。
2. **Hermes = agent 平台**。生成/编排/批准/体检全经 Hermes(Responses/MCP/skill/elicitation/cron),**主编 agent 不直接碰库、只调 MCP 工具**。Hermes 不当"可替换 LLM 网关",要用足它的扩展能力。
3. **渲染层只读**。渲染 = `fabula ∩ 知识帧` 投影成 sjuzhet,**绝不回写世界**;限知靠**渲染前的知识帧投影查询**,不靠事后判官。

> 违反任一条 = 架构债。Code review 第一关就查这三条。

---

## 1. 分层与目录

```
scribe3/
  ontology.py      本体类型(Entity/Event/Fact/KnowledgeEdge)——纯数据,无 IO
  store.py         SurrealDB 连接 + 单点写(execute_write)+ schema 迁移
  domain.py        领域逻辑(纯函数,operating on store)——TDD 主战场
  knowledge.py     知识帧投影 project_frame + see_event(看见即知道)
  render.py        build_render_prompt(fabula∩帧) + render(→Hermes completion)
  verify.py        find_leaks / causal_complete(只读判官,可跑查询)
  mcp.py           FastMCP server:读工具放行 / 写工具发 elicitation
  llm.py           Hermes 客户端(completion;移植已验证)
  hermes_skills/scribe-novel-v2/SKILL.md   主编 playbook(渐进披露)
  migrations/      SurrealQL DEFINE 脚本(版本化)
  tests/           pytest(逻辑测试不碰网/不碰 Surreal;集成测试用 Surreal fixture)
  .venv/           独立 venv(与 scribe2 隔离)
web-app-v2/        写作台 v2 前端(端口 3311)
```

**依赖方向(单向,不得逆流)**:`mcp → domain/render/verify → knowledge → store/ontology`。`render` 依赖 `knowledge`(投影);谁都不依赖 `mcp`。

## 2. 加一个能力的标准配方(7 步)

每个新能力按此走,缺步即不合标准:

1. **SurrealDB schema**(`migrations/NNN_*.surql`):`DEFINE TABLE ... SCHEMAFULL`(核心)或边 `TYPE RELATION`;字段带 `TYPE/ASSERT/DEFAULT`;需检索加 `DEFINE INDEX`(向量 HNSW / 全文 BM25);需"写入即派生"加 `DEFINE EVENT`。
2. **domain 纯函数**(`domain.py`):先写 **失败测试**(TDD),再实现操作 store 的函数。逻辑(投影/校验)能不碰 Surreal 就用内存结构测(快、绕中文路径 panic)。
3. **MCP 工具**(`mcp.py`):**读** → `readOnlyHint=true` 直接放行;**写** → 登记 `WRITE_GATED`,执行前发 `elicitation/create`,批准后走 `execute_write` 单点落库(见 §4)。
4. **skill**(若是创作 playbook):写进 `scribe-novel-v2/SKILL.md`,大规则拆 `references/`(渐进披露,控 token)。
5. **cron**(若是周期体检):`hermes cron create` + 前置 `script` 从 Surreal 取数注入,agent 只判断,`[SILENT]` 仅异常通知。
6. **前端视图**(若需反应式):一条 `LIVE SELECT`(或物化视图上的 LIVE)驱动表/图/时间线,改一处处处同步。
7. **测试**(贯穿):后端 pytest 全绿;前端真检查 `npm run build` / `tsc -b`(**禁用空操作 `tsc --noEmit`**)。

## 3. SurrealDB 规约

- **SCHEMAFULL 为核心表默认**(防 LLM 写脏);可变/半结构元数据用 `FLEXIBLE TYPE object`。
- **节点表 = 名词单数**(`character`/`event`/`proposition`);**边表 = 动词**(`knows`/`causal`/`participates`),`TYPE RELATION FROM x TO y`,**边上挂关系元数据**(confidence/since_chapter/ctype)。
- **关系建模取舍**:轻量单向归属用 `record<t>` 字段;带语义+属性+需双向遍历用 RELATE 边表。
- **双时态自建字段**(原生未发布):`valid_from_chapter` + `valid_to_chapter`(故事内,null=惯性);`draft_version` + `tx_at`(草稿)。审计/回放用 `DEFINE TABLE ... CHANGEFEED 30d INCLUDE ORIGINAL`,**不依赖 alpha 的 VERSION**。
- **三帧 = 查询不建库**:world=全表真相;角色=`->knows->proposition`;reader=knower=reader 的边。
- **检索**:语义 `embedding` + HNSW + `<|K,COSINE|>`;关键词全文 BM25。维度与索引 `DIMENSION` 严格一致。
- **派生靠 EVENT/COMPUTED**(写事件→自动建边),别让应用层重算。
- **迁移版本化**:`migrations/NNN_name.surql`,只增不改历史脚本;新字段给 `DEFAULT` 兼容旧数据。
- **写库只在 store.execute_write**:任何其它模块不得 `db.query("CREATE/UPDATE/DELETE...")`。

## 4. Hermes 规约

- **工具面来自 config,不来自请求体**:主编要的工具固化进 `mcp_servers.scribe3` /(可选)`platform_toolsets.api_server`;**别在 `/v1/responses` 请求体传 `tools`(不生效)**。
- **MCP 读/写分明**:读工具 `readOnlyHint=true`;写工具进 `WRITE_GATED` 集合,**唯一落库点 execute_write**;幂等 + 越权挡(防孤儿待批行)。
- **写待批走 elicitation**:写工具执行前发 MCP `elicitation/create`(form-mode,requested_schema 描述待批内容)→ Hermes 弹批准 → accept 才写,超时/decline=**fail-closed**。**全系统一套批准,不并存自建 REST 待批。**
- **工具命名空间**:scribe3 工具名加前缀 `s3_`(防与 scribe2 同挂撞名)。
- **skill 渐进披露**:SKILL.md Tier1 只 name+description;大规则放 `references/` 用 `skill_view` 按需读(总量 <~36k token)。
- **模型路由**:主编大模型(doubao)+ **auxiliary 小模型**(标题/压缩/QC判官)分离控成本;**启用 `fallback_model`**(主模型限流即切)。
- **token 纪律**:稳定内容(世界观/skill)放 prompt 头部吃 5m 缓存,易变(本章状态)放尾部。
- **体检走 cron / 并行走 kanban**:周期质检=cron+前置脚本;分卷分章并行=Hermes kanban(`auto_decompose`),别自建调度。多 agent 写流给可信内部写设批准豁免(`subagent_auto_approve=false` 否则卡)。
- **记忆分工**:世界观→SurrealDB;Hermes memory(2200 字符)只放作者偏好/项目元信息;跨会话推理检索用 session FTS。
- **两条 loop 别融合、共享下层**(Hermes 双 Loop 的可迁移教训):scribe3 的 **agentic 主编路**(Responses/AIAgent,优化创作交互与质量)与**确定性渲染+QC 流水线**(优化批量吞吐与可复现)目标函数不同,**不强行收敛成一个超级 loop**;上层按场景定循环策略,**下层共享 = MCP 工具 + execute_write 单点 + SurrealDB**。(Hermes 本身就是这么切:`run_agent.py` 的 AIAgent 与 RL rollout loop 各自循环、共享 `handle_function_call` 工具调度。)
- **技能自进化(主编越写越好)**:craft/流程发现经 `skill_manage(patch)`(模糊匹配、**小补丁非重写**)沉淀进 `scribe-novel-v2`;**走审批 + `skills_guard` 安全扫描 + git 可回滚;只沉淀【流程】不沉淀【剧情事实】**(事实进 SurrealDB,§0 不变量1)。后台复盘自动触发,但创建/删除确认作者意图。这是把手工挖的 craft 修法变可自维护资产的正道。

## 5. 知识帧纪律(限知渲染的铁律)

- **渲染前必投影**:`render_scene` 内先 `project_frame(focalizer, chapter)`,**只把帧内事实拼 prompt**;帧外私密(secret + leak_markers)绝不进 prompt。
- **一场一 POV**:head-hopping 的结构护栏;换视角必换场景/章节边界。
- **判官只兜底**:`find_leaks`/`discipline_check` 是第二道(craft 验证:别指望初稿自律),不是主防线;**主防线是结构性投影**。
- **看见即知道**:事件落库 → 在场者(participants)自动获 `knows` 边(EVENT 触发或 see_event);无知是默认(没边=不知道)。

---

## 6. 测试标准(TDD,Rigid)

- **先写失败测试,看它失败,再写最小实现**(red-green-refactor)。无失败测试不写生产码。
- **逻辑测试不碰网/不碰 Surreal**:投影/校验/prompt 构造用内存结构测(快;并绕开中文路径「写作 3.0」让 surreal v3 子进程 panic 的坑)。
- **集成测试用 Surreal fixture**:`conftest` 起内存 SurrealDB(纯 ASCII cwd + 净化环境,见 scribe2 conftest 范式),测 store/MCP 端到端。
- **真机验证**:涉及生成/渲染的能力,跑一次真机 Hermes 验证(如纵切片 demo 暴露的"元叙述"缺陷只有真机能发现)。
- **前端真检查 `npm run build` / `tsc -b`**;`tsc --noEmit` 是空操作(假绿),禁用。
- **连贯性/泄露做成查询测**:causal_complete/find_leaks 既是运行时校验也是测试断言。

## 7. 命名与隔离约定(汇总)

| 项 | scribe2(旧) | scribe3(新) |
|---|---|---|
| SurrealDB NS/DB | scribe / main | **scribe3 / main** |
| MCP FastMCP 名 / server_label | scribe / scribe2 | **scribe3 / scribe3** |
| 工具名前缀 | (无) | **`s3_`** |
| skill | scribe-novel | **scribe-novel-v2** |
| Hermes profile | 默认 | **scribe3** |
| venv | scribe/.venv | **scribe3/.venv** |
| 端口 前/后 | 3310 / 3320 | **3311 / 3321**(strictPort) |

**隔离纪律**:scribe2 不动直到 scribe3 达 parity;换系统=换 Hermes profile(工具面始终自洽,不串话);`hermes update` 单独立项、隔离验证三契约(Responses SSE / scribe MCP 挂载 / elicitation+mcp SDK≥1.11)再升。
