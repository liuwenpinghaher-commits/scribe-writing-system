# 素材库重构:从"死料仓"到"主编的联想记忆系统" · 设计文档(定稿)

- **日期**:2026-07-07(含批判性再审修订)
- **状态**:设计定稿,转实施计划(writing-plans)
- **心智模型一句话**:素材不是"资料条目",是**主编大脑里的长期联想记忆**——写作的每个环节都能被相关地唤起、借鉴,并留下"为什么参考"的溯源。
- **设计基准**:最优,不是最简。
- **再审修订摘要**(v2,经调研):① B1 关键词通道从"SurrealDB 原生 BM25"改为 **jieba 预分词 + SurrealDB BM25 组合**(原生 tokenizer 无 CJK 分词,对中文不可用);② 召回补 **query 聚焦 / 字数预算与放置 / 抄袭用手法摘要** 三项质量控制;③ 补 **召回门控 / 章级缓存 / 限知不约束素材 / 强度时间衰减 / 联想边上限 / 冷启动供给**。

## 1. 背景与问题

### 1.1 现状(素材 `material` 系统)

- **数据层**:`material` 表(migrations/055_material.surql + migrations/060 补 `emotion_module`),字段 `title/body/kind/tags/source`,6 类 kind(研究/参考/片段/灵感/笔记 + `emotion_module`),每书独立 DB。
- **后端 CRUD**:app.py:1029+ 镜像 motif/promise 的 GET/POST/PATCH/DELETE。
- **前端**:web/src/Materials.jsx,`MaterialList/MaterialNew/MaterialDetail`,只暴露 **5 类**(缺 `emotion_module`),搜索是客户端 substring 过滤。
- **使用路径**:普通 5 类素材唯一用法是详情页"插入到草稿"+ 手动敲章号;`emotion_module` 经 brief.py `emotion_module_recall` 章前召回。

### 1.2 病根诊断(技术实质)

1. **死料仓**:5 类普通素材写作链路里**零自动召回**,只能手动搬运。
2. **前后端割裂**:`emotion_module` 后端能存能召回,前端 Materials.jsx MATERIAL_KINDS 不含它 → 用户看不见、建不了。
3. **重复未复用**:设定库(codex)已有成熟的 `detect_mentions` + `select_injection`(brief.py:367-436)与整套召回栈(`semantic_recall`/`hybrid_recall`/`graph_recall`, store.py:781-853),素材完全没接。
4. **组织贫弱**:只有 kind(固定枚举)+ tags(自由串)+ source,搜索靠客户端 substring。
5. **休眠 bug**:`emotion_module` 召回依赖 `target_emotion` 参数,但**全仓无任何调用方传入非空值**(app.py:406、app.py:1434 都不传)→ 唯一的自动召回链**从未触发**。

### 1.3 用户痛点(已确认)

全选"建了 AI 用不上 / 分类组织太弱 / 交互繁琐割裂",并补充:**导入方式单一**(要多格式 + 进度条)、**双向引用追溯**、**核心洞察**——"素材是大脑记忆,主编在写作各环节像用自己的记忆一样参考";素材是**参考/借鉴**(风格/剧情/手法)而非事实,要**带溯源标** + 主编**说明为什么参考**;召回要**关键词 + 语义 + 图**多路。

## 2. 目标与心智模型

### 2.1 心智模型:素材 = 主编的联想记忆

| 记忆特征 | 唤起方式 | SurrealDB 能力 | 现状 |
|---|---|---|---|
| "意思相近就想起" | 语义相似 | 向量 HNSW | ✓ 已有,素材未接 |
| "提到这个词就想起" | 关键词/短语 | 全文 BM25(jieba 预分词) | ✗ 要建 |
| "由此及彼的联想" | 关联网络 | 图 RELATE | ✗ 现用数组,要图化 |

### 2.2 设计原则

1. **最优非最简**:以"对这个记忆系统最好"为唯一取舍标准。
2. **参考 ≠ 事实**:素材是"借鉴参考"(可改写、反抄边界),设定库是"必守事实",在 prompt 里**分区分性质**。
3. **自然唤起,无人为模式**:不给素材贴 always/detected 之类的人工模式标签;相关就唤起。记忆"强度"由被参考次数**自然涌现**,唯一人工干预是正向的"钉核心记忆"(pin)。
4. **贯穿写作全流程**:设定/目标/大纲/节拍/演绎/草稿/正文 + 主编对话,每个环节都能唤起记忆。
5. **可解释 + 双向溯源**:每次召回带"为什么"理由,记录素材↔章双向溯源(到章)。
6. **充分利用 SurrealDB 三模态**:向量 + 全文 + 图,而非单一向量。
7. **不帮倒忙**(再审新增):召回受门控、预算、缓存约束——素材注入绝不稀释掉更关键的设定/简报,空库/无命中时不空转烧钱。

### 2.3 成功标准

- 任一写作环节(含主编对话),相关素材能被自动/按需唤起并借鉴,且能看到"为什么参考"。
- 素材可多格式导入,长文自动切分为多条记忆,带进度与预览确认。
- 素材以记忆网络(图)+ 列表两形态浏览;支持关键词/语义/图三通道检索。
- 双向溯源可查。
- 现有素材零丢失,`emotion_module` 割裂修复,休眠召回链激活。

## 3. 最佳实践与调研结论

- **NovelAI Lorebook**:关键词激活注入。→ 采纳"关键词唤起"通道。
- **Sudowrite / Novelcrafter**:自动检索 / 手动挂载 + 自动检测引用。→ 采纳"写作时自动召回 + 作者可控 + 溯源可见"。
- **RAG for 创意写作**([AI Story RAG](https://dev.to/diskcleankit/build-your-own-ai-story-generator-with-rag-part-1-understanding-rag-223p)):检索 **style examples**,学"怎么写"而非事实,生成原创而**不照抄**。→ 印证"参考≠事实";防照搬无硬机制,靠 prompt 引导 + 手法摘要。
- **长上下文稀释 / lost-in-the-middle**([AttentionRAG](https://arxiv.org/html/2503.10720v1)):上下文过长注意力分散,关键证据被稀释,模型忽略中间。→ 素材注入必须**严格预算 + 讲究放置 + query 聚焦**。
- **SurrealDB 全文 CJK**([SurrealDB FTS](https://surrealdb.com/docs/surrealdb/models/full-text-search) / [CJK BM25 issue](https://github.com/lancedb/lancedb/issues/2329)):原生 tokenizer 无 CJK 分词,中文整句变一个 token、零匹配。→ **jieba 预分词 + SurrealDB BM25** 组合。
- **markitdown**([microsoft/markitdown](https://github.com/microsoft/markitdown)):PDF=pdfminer.six、DOCX=mammoth,纯 Python 无系统依赖;用 `markitdown[pdf,docx]` 精装。

## 4. 架构总览

```
[存储层 ①]  material(向量 embedding / 全文 tokens+BM25 / 图 RELATE) + 记忆强度 + material_reference 溯源
     ↑ 建索引/建边                                   ↓ 唤起(门控+缓存)
[召回层 ②]  material_recall:聚焦 query → 三通道 → RRF → 强度加权 → LLM 重排+理由 → 预算裁剪
     ↓ 注入(参考语义分区 + reason,严格字数/放置)      ↑ 溯源反哺强度
[消费层 ②]  三注入点:_assemble_write_instructions(全生成相位) / _editor_system(对话+enrich) / s3_material_recall(agentic)
[导入 ③]   多格式 → markitdown 解析 → AI 切分打标 → 向量+jieba tokens+联想边 → 落库(SSE 进度 + 预览确认)
[前端 ④]   记忆网络(sigma) + 列表 + 三通道搜索 + 导入界面 + 双向溯源
```

## 5. 设计 ① 记忆存储层

### 5.1 `material` 表(migration OVERWRITE,现有数据零丢失)

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` / `body` / `kind` / `tags` / `source` | (原有) | 保留;`kind` ASSERT 含 6 类(前端补齐 `emotion_module`) |
| `ref_tags` | array\<string\> | **新增**,参考维度(风格/剧情/手法/情绪/桥段…),自由填 + AI 建议 |
| `embedding` | option\<array\<float\>\> | **新增**,512 维 bge 向量 |
| `tokens` | option\<string\> | **新增**,jieba 切 `title+body` 后空格连接(供 BM25;中文分词正解) |
| `pinned` | bool DEFAULT false | **新增**,核心记忆(恒高召回权重) |
| `archived` | bool DEFAULT false | **新增**,归档淡出(不参与召回) |
| `recall_count` | int DEFAULT 0 | **新增**,被参考次数(强度自然涌现) |
| `last_recalled_at` | option\<datetime\> | **新增**,最近被参考时刻(强度时间衰减用) |
| `created_at` / `updated_at` | datetime | 保留 |

> 明确不引入:`recall_mode` 四态、`keywords`/`entities` 数组。

### 5.2 三模态索引

1. **向量 HNSW**(照抄 migrations/003_vector.surql):
   ```sql
   DEFINE INDEX material_embedding ON material FIELDS embedding HNSW DIMENSION 512 DIST COSINE;
   ```
2. **全文 BM25(jieba 预分词 + SurrealDB BM25)**:原生 tokenizer 无 CJK 分词,故中文分词交 jieba,SurrealDB 只做索引与 IDF 打分:
   ```sql
   -- 入库时 jieba 切 title+body → 空格连接写入 tokens;SurrealDB 对已分词文本用 blank tokenizer
   DEFINE ANALYZER material_zh TOKENIZERS blank FILTERS lowercase;
   DEFINE INDEX material_fts ON material FIELDS tokens SEARCH ANALYZER material_zh BM25;
   ```
   → 中文分词正确(jieba)+ DB 级 IDF 打分与索引加速(SurrealDB BM25)。
3. **图 RELATE**:`material->about->entity`(角色/地点)、`material->relates->material`(联想,带 reason+weight)。

### 5.3 记忆强度(自然涌现,非人为模式)

- **参考强化 + 时间衰减**:每次实际参考 → `material_reference` +1 行 → `recall_count += 1` + 更新 `last_recalled_at`。召回加权 = 对数(`recall_count`) × 近期性衰减(久未参考回落)。**防马太效应**:保留少量"探索名额"给未召回过的新素材,不让老素材恒占。
- **pinned**:手动钉核心记忆,恒高权重。
- **archived**:归档,`material_recall` 查询层排除。

### 5.4 联想网络(AI 自动建 + 手动调)

- **入库自动建边**:
  - `relates`:对已有素材语义近邻(HNSW),超阈值建边,记 `reason`+`weight`。**防爆炸:每素材只保 top-k(默认 5)近邻边 + 相似度硬阈值**,避免 N² 增长。
  - `about`:素材正文跑 `detect_mentions`(brief.py:355),命中实体建边。
- **手动调**:记忆网络视图可增删边。
- **图召回**:从种子素材沿 `relates`/`about` 扩展一跳取邻居。

### 5.5 `material_reference` 溯源表(双向,到章)

```sql
DEFINE TABLE material_reference SCHEMAFULL;
DEFINE FIELD material_id ON material_reference TYPE string;
DEFINE FIELD chapter     ON material_reference TYPE int;
DEFINE FIELD dimension   ON material_reference TYPE option<string>;
DEFINE FIELD reason      ON material_reference TYPE option<string>;
DEFINE FIELD via         ON material_reference TYPE string;   -- brief / phase:<name> / agentic / manual
DEFINE FIELD created_at  ON material_reference TYPE datetime VALUE time::now() READONLY;
```
正向 `WHERE material_id=$m`;反向 `WHERE chapter=$c`。不做段落级锚。

## 6. 设计 ② 记忆召回与全流程消费

### 6.1 召回引擎 `store.material_recall`

```
material_recall(query, chapter, k=5, mentioned_entities=None,
                budget_chars=..., use_cache=True) -> list[dict]
```

流程:
1. **聚焦 query**(再审):不把长上下文整段当 query(会稀释语义焦点)。从当前环节上下文**提取关键意图/实体**构成短 query(草稿相位取 beats 的动作核心 + 提及实体,而非 synopsis+beats+演绎全拼)。
2. **门控**(再审):素材库为空 / 三通道均无超阈值命中 → **直接返回空,不注入、不调 LLM 重排**(空库/无关时零开销,不稀释、不烧钱)。
3. **三通道候选**:
   - 语义:`material` HNSW `WHERE embedding <|k*3,EF|> $qv ORDER BY dist`。
   - 全文:jieba 切 query → BM25 `WHERE tokens @@ $q ORDER BY search::score(1) DESC`。
   - 图:种子素材沿 `relates`/`about` 扩展 + `mentioned_entities` 关联素材。
4. **RRF 融合**:`_reciprocal_rank_fusion(vec_ids, fts_ids, graph_ids, k=60)`(store.py:135,纯函数复用)。
5. **强度加权**:融合分 × 强度因子(§5.3);`archived` 已在查询层排除。
6. **LLM 重排 + 理由**:融合 top-N(如 8)→ 一次 `hermes_complete` 判定真正值得当前场景借鉴的 + 生成自然语言 `reason`。返回 top-k。
7. **预算裁剪 + 放置**(再审):素材段有**硬字数预算**(默认小,如 ≤800 字),按强度/相关性裁剪;注入位置放在 prompt **靠后但非最末**(避开 lost-in-the-middle,且不盖过 `_final_reminder`)。

失败降级:重排失败 → 回退 RRF 顺序 + 机械 reason;全链 fail-soft 不阻断写作。

### 6.2 参考语义(借鉴非照搬 + 抄袭防范)

- 注入段头:"【参考记忆·借鉴非照搬】以下是与本环节相关的素材记忆,借鉴其手法/风格/思路,**非必守事实**;反抄边界:原文专名/事件顺序/标志台词/独特设定不可照搬,迁移至少改 3 项。"(沿用 brief.py:342-349)
- **抄袭防范升级**(再审):对 `ref_tags` 含"风格/手法"的素材,注入 **AI 提炼的手法摘要**(如"短句白描、以物写情")而非原文长段,从源头降低逐字照搬;"剧情/桥段"类给结构梗概不给原文。摘要在入库时预生成(§7.2 ③),召回直接取用。
- **差异化借鉴指令**:"风格"→借鉴语感节奏;"剧情/桥段"→借鉴结构不搬情节;"手法"→借鉴技法。

### 6.3 全流程消费:三注入点(测绘实证)

| 注入点 | 位置 | 一处覆盖 |
|---|---|---|
| **写作总闸** | `_assemble_write_instructions`(app.py:2088-2147),插 `_outline_block`(:2116)后、`_final_reminder` 前 | 大纲·节拍·演绎·草稿·选择环·pilot·loop **全生成相位** |
| **主编总闸** | `_editor_system`(app.py:1241-1306)加素材段 | 主编对话 + 设定库 enrich |
| **agentic 工具** | 新增 `s3_material_recall`(mcp.py,镜像 `s3_semantic_recall` mcp.py:105) | 主编按需唤起 + 自述理由 |

- **query 来源**:大纲→意图+前情;节拍→synopsis 核心;演绎→场景真相;草稿/正文→beats 动作核心+提及实体;对话→当前消息(均经 §6.1 聚焦提取)。
- **限知不约束素材**(再审):素材是**元层面创作参考**,不是故事内知识,故 `material_recall` **不走 focalizer 限知过滤**(区别于设定注入)。在 `_editor_system` 限知分支下,素材段照常注入。
- **章级缓存**(再审):同章多相位(大纲→节拍→草稿)召回结果**按章缓存**,避免每相位重跑三通道+重排;章内容变化或显式刷新时失效。
- **激活休眠链**:`emotion_module` 并入统一 `material_recall`(情绪卡作 `ref_tags` 含"情绪"参与),不再依赖恒空 `target_emotion`;旧 `emotion_module_recall`(brief.py:304)迁移进统一召回(保持 tests/test_brief.py 绿或同步更新)。

### 6.4 溯源反哺

实际注入 → 写 `material_reference`(chapter/dimension/reason/via)→ `recall_count += 1` + `last_recalled_at`。既服务展示(§8.4)又反哺强度(§5.3)。

## 7. 设计 ③ 导入管线

### 7.1 支持格式
纯文本 txt/md · pdf/docx(markitdown,新依赖)· 网页 url(httpx 抓+markitdown)· 粘贴(现有)。

### 7.2 一站式流水线(上传 → 记忆)
```
上传/粘贴/url
 → ① 解析成 markdown(markitdown[pdf,docx])
 → ② AI 切分:长文按语义/结构切成多条素材(hermes_complete)
 → ③ AI 打标:每条 title + kind + ref_tags + 抽关键词 + 【手法摘要】(hermes_complete,摘要供 §6.2)
 → ④ 生成向量(fastembed) + jieba 切 tokens 建 BM25
 → ⑤ AI 建联想边(relates 近邻 top-k + about 实体)
 → ⑥ 落库
```

### 7.3 端点与进度
- `POST /materials/import`(FastAPI `UploadFile`,无新依赖),接文件/文本/url → `job_id`。
- `BackgroundTasks`(复用 `_enqueue_ingest` 范式 app.py:2757)异步跑,进度写内存/表。
- SSE `GET /materials/import/{job_id}/progress`(复用 httpx-sse):`解析→切分→AI整理 i/n→建索引→建联想边→完成`。

### 7.4 预览确认(作者主权)
AI 切分/打标后**先返回预览**(可改标题/维度、删条、合并)→ `POST /materials/import/{job_id}/commit` 批量落库。

### 7.5 错误处理
单条 fail-soft(报告失败数)· 格式不支持/解析失败明确报错 · 大文件分块 + 大小上限(如 10MB)。

## 9. 技术选型与依赖

### 9.1 新增后端依赖:`markitdown[pdf,docx]`(精装)
统一 pdf/docx/html/url → markdown;底层 pdfminer.six + mammoth,纯 Python 无系统依赖;精装 `[pdf,docx]` 控依赖树/CVE 面。**唯一新增后端依赖**。备选 `pypdf`+`python-docx`+`trafilatura`。

### 9.2 关键词通道:jieba 预分词 + SurrealDB BM25(不是原生全文)

## 11. 错误处理与降级(汇总)

| 场景 | 处理 |
|---|---|
| 空库 / 无超阈值命中 | 门控直接返回空,不注入不调 LLM |
| 召回 LLM 重排失败 | 回退 RRF 顺序 + 机械 reason |
| 召回全链异常 | fail-soft 返回空参考段,写作正常 |
| SurrealDB BM25 排序不符预期 | 降级纯 jieba+Python BM25 计分 |
| 导入单条切分/embedding 失败 | fail-soft 跳过,报告失败数 |
| 导入格式不支持/解析失败 | 明确错误信息 |
| markitdown 依赖过重 | 退备选 pypdf+python-docx+trafilatura |
| 联想边建边失败 | fail-soft,素材仍可用 |
