# 主界面信息架构重构 · 设计文档

- **日期**:2026-07-07
- **状态**:brainstorming 定稿(v1→v4 逐段获批),待转实施计划
- **一句话**:把"3 列 + 每列内嵌竖轨 + 4 套 tab"的杂乱布局,重构成一套**从上到下、从左到右统一贯穿、且一套模板统治所有对象**的信息架构。
- **核心原则**:[[system-wide-thinking]] 全局系统思维——所有元素都从系统整体定位,不做局部补丁。

---

## 1. 背景与问题

### 1.1 用户痛点
"整个页面很乱"——顶部(logo/作品/视图)、左侧功能、打开手稿后的展示,缺一套统一逻辑。要求从上到下、从左到右理顺,且"打开一个手稿之后这些东西怎么展示"要清晰。

### 1.2 现状诊断(Explore 布局地图实证,8 项)
现状是 **react-resizable-panels 的 3 列**(左22%/中52%/右26%),但**每个左右列内部又内嵌一条 56px 竖轨(Rail)**,视觉像 5 区、逻辑很乱:

- **A. 功能tab 与 目录树挤同一栏**:左栏 = `[Rail | 单一内容槽]`,目录树只是 Rail 的 `tree` tab,点别的 tab 树被顶掉消失。
- **B. 左轨混两种心智**:`tree` 是导航器(改中栏),`简报/北极星/帧/演绎/伏笔/母题/检索/校验` 是只读台账(吃"当前章 seq"不吃选中节点)。导航和仪表盘挤一轨。
- **C. 4 套 tab 系统**:顶部 VIEWS(AppRail)+ 左轨 + 中栏 PhaseBar + 右轨。
- **D. 详情被拆中栏+右栏**:正文编辑器在中栏,写作对话 WriteChat 经 Portal 甩到右栏。
- **E. 扩展框+扩展tab 挤右一栏**。
- **F. 主编散落多入口**:右栏 chief tab / portal 的 WriteChat / PulseBar"聊这个" / 收件箱"跟主编聊" / ProactiveGreeting,全靠 window 事件 + sessionStorage 粘合。
- **G. 北极星两处两形态**:左栏 tab `NorthStarPanel`(章级 scorecard)+ 中栏 `NorthStarBar`(作品意图 /intent),同名异义。
- **H. 横切视图抢中栏**:图谱/时间线/仪表盘全画布替换详情 + 自动折叠左栏。

## 2. 设计原则(统一逻辑)

### 2.1 从上到下 / 从左到右
- **顶部** = 我是谁 + 全局(logo / 当前作品 / 全局工具 / 全局通知)。
- **左 → 右** = 我在哪个功能(导航) → 具体哪一项(目录树·常驻) → 详情/编辑(中央) → 主编 + 参考(右侧)。

### 2.2 一套规则统治所有(通用对象模板)
不逐个场景设计。**任何被选中的对象**(章/角色/势力/物件/术语/世界规则/伏笔/母题/命题/素材/未来新类型)都套同一模板,只填充不同。系统自洽、可扩展。

### 2.3 全局系统思维
每个元素都问:它在系统哪个位置?和现有什么有关系(命名/交互/视觉/数据/心智)?会不会冲突或破坏一致性?先融入整体再落地。

## 3. 目标布局架构

### 3.1 四区(顶 + 左总纲领 + 中详情 + 右主编)

> **v2 修订(用户洞察,全局思维)**:原"①功能轨 + ②目录树"是**重复层级**(都在导航手稿/设定/素材),**合并为左边一列完整总纲领树**。分析视图(图谱/时间线/仪表盘)归**顶部模式切换**(应用级)。五区收敛为四区,更简洁。

```
┌──────────────────────────────────────────────────────────────┐
│ 顶: ✍Scribe │ 📖作品▾ │ [写作·图谱·时间线·仪表盘] │  🔔 🔍 ⛶ 🌙 │  ← 整个应用的操作
├───────────┬────────────────────────────┬─────────────────────┤
│ 左·总纲领  │ 中·具体信息(详情/编辑)       │ 右·主编(操作)        │
│ 一列完整树 │ 顶部: 面包屑›对象 + 对象tab   │ 主编对话(常驻默认)    │
│ ▾手稿→卷→章│       + 状态徽章             │ + 参考/校验/存档 tab │
│ ▾设定→分类 │ 编辑器 / 详情               │                     │
│ ▾素材→kind │ (分析模式时: 中央全画布)     │                     │
└───────────┴────────────────────────────┴─────────────────────┘
   左=去哪        中=做什么                    右=谁帮我
```

**原左轨 9 个 tab 归位**(全局思维:按"这信息服务谁"分,不再全挤左轨):

| 原 tab | 归位 | 理由 |
|---|---|---|
| 项目树 | 左·总纲领树 | 合并进左边一列 |
| 简报 / 帧 / 校验 | 右·辅助 tab | 服务"当前这一章",跟主编一起 |
| 演绎 | 中·阶段 tab | 本就是写作阶段(大纲/节拍/演绎/草稿/正文)之一 |
| 伏笔 / 母题 | 左树·设定库 + 仪表盘 | 本身是设定对象;全书统计进仪表盘 |
| 检索 | 顶·🔍 全局搜索 | 语义召回是"搜全书",全局操作 |
| 北极星 | 顶·作品▾ + 仪表盘 | 拆两义:作品意图→作品▾;章级质量分→仪表盘 |

### 3.2 顶栏(动态承载上下文)
- **固定左段**:`✍ Scribe`(字标)· `📖 作品名 ▾`(下拉含**北极星/作品意图**、作品设置、切换作品)。
- **竖分隔线**(划清全局 vs 上下文)。
- **动态右段**(随选中对象变):面包屑`功能›卷/分类›对象名` · `[对象的横向 tab]` · `状态徽章`。
- **全局工具区**(最右):`🔔 收件箱`(badge)· `🔍 搜索/⌘K` · `⛶ 专注` · `🌙 主题`。
- **窄屏退化**:状态徽章收成图标、面包屑省略中段、对象 tab 可溢出滚动。

### 3.3 ① 功能轨(左,纯导航,分两组)
- **内容组**(点了有第②列目录树):手稿 / 设定库 / 素材库。
- **分析组**(点了全画布、**无第②列**):图谱 / 时间线 / 仪表盘。
- 两组间分隔线 + 小组标。原来混在此的 帧/演绎/伏笔/母题/检索/校验(只读台账)**全部移到右侧**(见 3.6)。

### 3.4 ② 目录树(常驻第二列)
- 内容组选中时**常驻显示**,不再是 tab、不被顶掉。
- 手稿→卷/章/场景;设定库→分类/条目;素材库→kind/素材。
- 复用现有 `ProjectTree`(react-arborist),但**拆成随①功能切换的独立列**,而非左轨的一个 tab。

### 3.5 ③ 详情/编辑(中央)
- 按选中对象类型路由(复用现有 `DetailPane` 的 renderDetail):章→编辑器 / 设定叶→CodexDetail / 素材→MaterialDetail / 命题→PropositionDetail / 容器→ContainerOutline。
- 章节的阶段(大纲/节拍/演绎/草稿/正文)**上移顶栏 tab**,中央不再有独立 PhaseBar 头条。
- 分析功能(图谱/时间线/仪表盘)时,中央被该视图全画布接管。

### 3.6 ④+⑤ 右侧(主编 + 当前对象辅助)
- **④ 主编**(常驻默认 tab):唯一对话入口,懂当前上下文(见 §5-B)。
- **⑤ 当前对象辅助 tab**(随对象类型变):
  - 章:参考(素材召回)/ 校验(QC/泄露,即原 review)/ 存档(版本)。
  - 角色:关系图 / 被引用。
  - 素材:联想 / 用在哪(溯源)。
- 原左轨的只读台账(帧/伏笔/母题/检索…)按语义归入此处的辅助 tab。
- **收件箱移出**(升顶栏 🔔,它是全局待办不是当前对象辅助)。

## 4. 通用对象模板(A · 系统地基)

**模板契约**:任何对象 `O` 被选中 → 系统按统一插槽填充:

| 插槽 | 内容 | 来源 |
|---|---|---|
| 顶栏面包屑 | `功能 › 容器 › O.name` | O 的路径 |
| 顶栏对象 tab | O 类型的分面(如章=阶段,角色=档案/弧光/关系) | 按类型注册表 |
| 顶栏状态 | O 的关键状态徽章(字数/存档/首现章…) | 按类型 |
| 中央 | O 的详情/编辑组件 | 按类型路由 |
| 右侧辅助 tab | O 的辅助信息面板集 | 按类型注册表 |

**对象类型注册表**(单一真源,新增类型只在此登记):

```
registry[type] = {
  crumb(o), tabs: [...], status(o), DetailComponent, auxTabs: [...]
}
```
类型:chapter / character / faction / item / term / world_rule / promise / motif / proposition / material。加新类型(如 event)= 加一条注册,布局自动适配。

## 5. 五条系统自洽(B-E) + 七条结构已并入 §3

**七条结构(v3)** 已落进 §3 布局:①左轨只留导航+分组 ②目录树常驻 ③顶栏动态 ④北极星归作品▾ ⑤收件箱升顶栏 ⑥右侧收敛 ⑦四级选中呼应。

**B. 主编懂上下文**:右侧主编订阅"当前选中对象",系统提示注入当前对象上下文(章→写作/角色→讨论角色/素材→借鉴)。收敛现有 window 事件多入口为"唯一主编 + 上下文总线"。

**C. 万物可跳转**:定义全局 `navigateTo(objectRef)` — 任意处对象引用可点→左轨定位+第②列选中+中央打开+顶栏更新。图谱节点/主编提及/参考素材/面包屑/⌘K 全走它。五区连成一张网。

**D. 视觉设计 token 统一**:抽一套 design token(色/间距/圆角/字号/组件),所有区共用。承接已修的设定字段样式统一,推广到全局。

**E. 全状态有姿态**:未选(中央给引导)/加载(骨架)/出错(可重试)/空书(引导建卷章)/专注(收左右)——每态明确样式,不只正常态。

## 6. 迁移与爆炸半径(全局系统思维:不 break 现有)

**关键定性:这是"重组现有组件到新布局骨架",不是重写功能。** 现有功能组件(ProjectTree/CodexDetail/MaterialX/ChiefDock/WriteLayout/各 Panel/PulseBar/DeduceTree…)**保留复用**,只改它们的**容器与编排**。

**涉及文件(爆炸半径)**:
- 骨架层(改):`App.jsx`(顶层)、`BinderLayout.jsx`(三栏→新五区)、`shell.jsx`(Rail→功能轨)、`AppRail.jsx`(顶栏→动态)、`studioDocks.jsx`(左右 Dock caps 重编)、`DetailPane.jsx`(详情路由,基本保留)。
- 新增:`ObjectFrame`(通用对象模板)、`TopBar`(动态顶栏)、`objectRegistry`(类型注册表)、`navigateTo`(跳转总线)、`design-tokens`(视觉)。
- 收敛:主编多入口(`ChiefDock`/`ChiefSlotContext`/WriteChat portal/window 事件)统一为上下文总线。
- 复用不动:`ProjectTree`、`CodexDetail`、`Materials*`、`SelectionPanel`、`PilotDock`、`InboxPanel`、`PulseBar`、各视图(Atlas/Timeline/Insight)。

**不能 break 的现有功能**:素材库全链路(刚上线)、主编对话/写作流程、选择环、Pilot、四阶段编辑、限知/护栏、SSE 实时。迁移后逐一回归。

**风险**:布局是所有功能的宿主,改动面广。用**旧布局可回退**策略(feature flag 或分支),每阶段独立可跑。

## 7. 分阶段实施(writing-plans 细化)

**⚠ 实施铁律(用户明确要求,必守)**:这是大重构、涉及面广,必须**一步一步来**,每一步做完**认真检查**——有没有搞坏原有功能、实现效果是不是最佳,**绝不偷懒**。每阶段:旧布局可回退(feature flag/分支)、独立可跑、**真机走查(build 绿≠运行时 OK,须 pw 验证无白屏/无回归)通过才进下一步**。

1. **设计 token + ObjectFrame 骨架**:抽 token;搭通用对象模板空壳 + 类型注册表(先注册 chapter/character/material 三类)。旧布局并存。
2. **五区骨架**:BinderLayout 改新五区(功能轨分组 + 目录树常驻 + 中央 + 右侧收敛);顶栏 TopBar 动态化(面包屑+对象tab+状态+全局工具)。
3. **对象接入**:把现有详情/tab/辅助按注册表接进 ObjectFrame(章→编辑器+阶段+参考/校验/存档;角色→CodexDetail+档案/弧光/关系;素材→…)。逐类型接、逐类型回归。
4. **主编上下文总线(B)+ 唯一入口收敛**:主编订阅当前对象;收编多入口。
5. **万物可跳转(C)**:navigateTo 总线;图谱/主编/参考/⌘K 接入。
6. **北极星归位 + 收件箱升顶栏**:/intent 收进作品▾;收件箱升顶栏 🔔。
7. **状态姿态(E)+ 专注模式**:补全空/载/错/空书/专注。
8. **端到端回归 + 旧布局下线**:全功能真机走查,确认无回归,移除旧布局。

## 8. 范围与非目标(YAGNI)
**做**:布局骨架重构 + 通用对象模板 + 顶栏动态 + 左轨分组 + 目录树常驻 + 右侧收敛 + 主编上下文/唯一入口 + 万物跳转 + 北极星归位 + 收件箱升顶栏 + 视觉 token + 全状态 + 专注模式。
**不做(本期)**:重写任何功能逻辑(只搬容器);移动端专门适配(仅桌面窄屏退化);新对象类型(用现有 10 类,注册表预留扩展)。

## 9. 测试策略
- **布局回归**:每阶段 Playwright 冒烟(五区渲染/功能轨切换/目录树常驻/顶栏动态/右侧 tab)。
- **功能不回归**:素材库/主编/写作/选择环/Pilot/编辑 逐一真机走查。
- **通用模板**:三类对象(章/角色/素材)套模板一致;加一个 mock 类型验证注册表可扩展。
- **跳转总线**:navigateTo 从图谱/主编/⌘K 各入口跳转命中。
- **视觉**:token 应用后各区一致(截图对比)。
- **build 绿 + 运行时无 TDZ/白屏**(吸取循环 import 教训:build 绿≠运行时 OK,须 pw 真机验证)。
