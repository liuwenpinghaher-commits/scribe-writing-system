# scribe3 写作台重设计:对话驱动写作(design spec)

日期:2026-06-23 · 状态:已与用户敲定核心决策,待复审

## 1. 背景与诊断

scribe3 当前写作台围绕"知识状态机"搭建:用户要**手动操作**「选视角→渲染本场→回写账本」。这是知识工程动作,不是写作动作——小说家打开它不知道怎么写。

老版 scribe2 核实结论(读 `scribe/web-app/src/WriteLayout.tsx`+`Editor.tsx`):右轨**有**「主编对话」cap,但对话只**讨论**;真正改稿靠编辑器另设的「续写/改写」按钮→草稿→接受。**对话与改稿割裂**。

**纠正方向(用户拍板)**:核心模型是**「我提思路,AI 写」**——对话**直接驱动**手稿,把老版割裂的"讨论"与"改稿"合一。限知/知识层那套**有价值、保留**,但退到**后台**自动支撑,不再让用户手动操作。

## 2. 核心模型

> **右轨主编对话是写作主入口。我提思路/提要求 → 主编在中间手稿生成「改写提议」→ 我接受/弃用。也可随时手动改。后台用全书知识数据撑着。**

## 3. 已敲定的关键决策

| # | 决策 | 选择 |
|---|---|---|
| D1 | 改稿方式 | **提议→接受/弃用**(草稿卡,对话触发,不默默覆盖原文) |
| D2 | 限知约束 | **后台软校验**(主编贴视角写;泄露/穿帮右轨红标提示,不挡接受) |
| D3 | 实现路径 | **路径 A 统一对话流**(一个入口,主编自判讨论 vs 动稿) |
| D4 | 旧页 | 现写作台原样保留,改名 **「推演台」**(限知渲染),单独一页;独立「主编」全屏 tab 折叠进新写作台右轨 |

## 4. 布局(新写作台 = 默认页)

```
┌ 顶栏:◀ 第N章 ▶ │ 北极星条(意图常驻·状态色)│ 视角:单嫣(安静设置)│ LIVE ┐
├──────────────────────────────────┬─────────────────────────┤
│ 中区:手稿(TipTap)                 │ 右轨:主编对话(默认 cap)   │
│  · 你手写,或主编「改写提议」草稿卡    │  · 输入:提思路/提要求       │
│    ╭ 主编改写(草稿)──────────╮      │  · 主编流式回话             │
│    │ 新版本散文…   [接受][弃用] │      │  · 工具调用 chip(联查实证)  │
│    ╰──────────────────────────╯      │  · 速答/联查实证 切换        │
│  · 划词 → 「让主编改这段」浮条        │ ┌ 切 cap ─────────────────┐ │
│  · 字数 · 专注模式 · 场景分隔         │ │ 校验·伏笔·设定速查·在场   │ │
└──────────────────────────────────┴─────────────────────────┘
```

右轨默认停在「主编对话」cap;其余 cap(校验/伏笔/设定速查/本章在场/北极星)是**支撑**,切过去看,不打断写。

## 5. 交互流程

### 5.1 讨论 vs 动稿(主编自判)
用户在右轨发一条消息,后端主编(agentic)判定意图:
- **讨论**(「这章节奏如何?」「反派动机够硬吗?」)→ 仅流式回话,中区不动。
- **动稿**(「把这段写冷点」「续写」「本章这样展开:…」)→ 流式回话 + 在中区生成**改写提议草稿卡**。

### 5.2 三种动稿动作(都 → 草稿卡 → 接受/弃用)
1. **提思路从零写**:「本章:单嫣引胡不为夺钉,反被钉认主」→ 主编写整章草稿。
2. **改选区**:中区划选一段 → 浮条「让主编改这段」或在对话里说要求 → 只改这段(提议替换该 span)。
3. **续写**:「接着往下」→ 从光标/章末续,草稿卡接在原文后。

### 5.3 草稿卡生命周期
- 草稿卡显示在中区(整章=覆盖区;选区/续写=就地卡)。
- **接受**:替换对应范围 → 落库(save-chapter)→ 触发后台软校验 → 自动回写(ingest)。
- **弃用**:原文不动,卡消失。
- 接受/弃用前,原文一直在,随时可手动改;草稿卡是**叠加层**不是替换。

### 5.4 划词
中区选中文字 → 浮条:**让主编改这段** / 复制 / 加粗斜体。"让主编改这段"把选区带入对话并聚焦改写。

## 6. 数据架构:一条脊椎,两个台共用

**两个台连同一份 SurrealDB(NS=scribe3 / 本书 DB)。推演台不拥有数据,只是知识层的检视/操作台。主编在后台读同一份。**

主编(agentic,:8643 网关挂 19 个 s3_ 工具)写/改时自动调:

| 时机 | 工具 | 用途 |
|---|---|---|
| 写/改前 | `s3_project_frame(POV,章)` | 取知识帧——主编知道该视角此刻知道什么,软贴视角写 |
| | `s3_list_promises` / `s3_list_motifs` / `s3_semantic_recall` | 伏笔/母题/相关设定当素材纲领 |
| | `s3_dramatic_irony(POV,章)` | 反讽点(读者知/角色不知)有意识地用 |
| | 北极星意图(注入) | 写作纲领 |
| 生成草稿 | render 引擎(`s3_render_scene`) | 「从零写」复用限知渲染 |
| 接受时 | `s3_find_leaks`+`s3_discipline_check`+`s3_causal_complete` | 软校验,红标提示 |

**LIVE 同步的关键含义**:在**推演台**手动改了"单嫣这章才知道X",**主编下次写就遵守**(读同一份帧)。所以:
- **写作台** = 写(主编自动用数据)。
- **推演台** = 校准喂给主编的事实/知识源头(人工操作知识层)。
- 不重复,是分工;改一处两边都变。

## 7. 后台软校验(D2)

接受草稿时(或草稿生成后)自动跑,结果进右轨「校验」cap:
- 确定性 QC(跨段复读/排比开头/升华句)。
- **限知泄露检测**(`s3_find_leaks`:POV 散文里冒出帧外私密的破绽词)。
- 因果完整(`s3_causal_complete`)+ 伏笔超期。
- LLM 纪律判官(`s3_discipline_check`:双高潮/声音崩/解说倾泻)。

**软**=有问题**红标提示但不挡接受**,用户定夺。北极星意图作为主编写作纲领注入(正向约束)。

## 8. 后端

### 8.1 新端点 `/chat/write`(SSE)
- 入参:`{message, manuscript(当前手稿), selection?(选区文本+字符范围), chapter, focalizer}`(POV帧/设定/伏笔/北极星由后端按 work+chapter 取,不由前端喂)。
- 主编(走 :8643 /v1/responses,agentic)自判讨论 vs 动稿。**proposal 回传协议(明确)**:系统提示指示主编——要改手稿时,把新散文放进**围栏**:
  ```
  ⟦PROPOSAL scope=selection|chapter|append⟧
  <新散文>
  ⟦/PROPOSAL⟧
  ```
- `/chat/write` 解析 SSE 流:**围栏外**文本 → `{delta}`(对话回话,进右轨)+`{tool}`(工具调用 chip);**围栏内**文本累积 → `{proposal: {scope, prose}}`(进中区草稿卡)。无需新增 MCP 工具,纯文本协议。
- 复用 `_editor_system` 注入上下文 + 现成 `hermes_responses_events`;新增围栏状态机解析。

### 8.2 接受流(不新增端点,扩 save-chapter)
接受 = 前端把 proposal 按 scope 应用进编辑器 → `POST /save-chapter`(**扩展**:落库后顺带跑软校验返回 QC 结果 + 触发 `ingest` 知识回写)。前端拿校验结果刷新右轨「校验」cap。弃用 = 前端丢弃 proposal,不调后端。

### 8.3 复用
render(从零写/续写的生成引擎)、critique.py(确定性 QC + 纪律判官)、ingest.py(回写)、verify.py(因果)——全现成,主要是接线 `/chat/write` 的意图判定与 proposal 协议。

## 9. 旧页迁移(D4)

- 现 `WriteLayout`(选视角→渲染→帧)**原样**保留,组件可重命名 `DeduceLayout`,VIEWS tab 文案改「推演台」(副:限知渲染)。
- 新 `WriteLayout`(对话驱动)= 默认「写作台」。
- 独立「主编」ChatView tab **移除**,其 agentic 能力并入新写作台右轨「主编对话」cap(避免重复;ChatView 组件改造成 cap 形态)。

**Tab 结构**:`写作台(对话驱动)` · `推演台(限知渲染)` · `设定库` · `图谱` · `仪表盘`。

## 10. 组件分解

前端(scribe3/web/src):
- `WriteLayout.jsx`(重写为对话驱动):顶栏(章/北极星条/视角)+ 中区(ProseEditor + 草稿卡叠加)+ 右轨(主编对话 cap + 支撑 caps)。
- `editor/DraftCard.jsx`(新):草稿卡(整章/选区/续写三态)+ 接受/弃用。
- `editor/ProseEditor.jsx`(现有):加"划词→让主编改这段"动作 + 选区上报。
- `WriteChat.jsx`(由 ChatView 改造):右轨 cap 版主编对话,onProposal 回调把提议送中区。
- `NorthStarBar.jsx`(新):顶栏北极星条。
- 旧 `WriteLayout` → `DeduceLayout.jsx`(改名,逻辑不动)。

后端(scribe3):
- `app.py`:新 `/chat/write` SSE(围栏状态机:分流 delta/tool/proposal)+ 扩展 `/save-chapter`(落库后跑软校验 + 触发 ingest,返回 QC)。
- `llm.py`:复用 `hermes_responses_events`;新增 `_editor_write_system`(在 `_editor_system` 上加 ⟦PROPOSAL⟧ 围栏指令)。
- 软校验:复用 critique.py(QC+纪律判官)/verify.py(因果)/mcp 的 find_leaks。

## 11. 测试口径(TDD)

- 后端:`/chat/write` 讨论分支(只 delta)、动稿分支(出 proposal);`/accept-proposal` 落库+软校验触发(monkeypatch LLM)。限知泄露检测在接受流被调用。
- 前端:`npm run build` 绿;草稿卡接受替换/弃用不动原文;划词上报选区。
- 真机:提思路→主编出整章草稿→接受→落库→推演台看帧已更新(脊椎共用验证);故意诱导泄露→右轨校验红标。
- 输出质量:限知软校验能抓到 POV 写帧外私密。

## 12. 不做(YAGNI)

- ❌ 行内 char-diff 逐处接受(D1 已选草稿卡;中文散文行内红绿太碎)。
- ❌ 限知硬锁(D2 选软校验)。
- ❌ 打字机居中滚动(后续)。
- ❌ 多书 agentic 切库(沿用现状:agentic 以 db=main 主参照库;多书 agentic 是后续独立项)。

## 13. 开放风险

- **主编"自判讨论 vs 动稿"的准确率**:靠提示词 + 结构化返回约定;判错时用户可显式说"改稿"。需真机调提示。
- **proposal 的 scope 定位**(selection range 对齐):选区按字符偏移传,接受时按偏移替换;手稿在生成期间被手动改过则需校验偏移失效→回退为整章提议。
- **agentic 写作延迟**:doubao 流式较慢;草稿卡显"主编书写中…"流式占位。
- **db=main 限制**:agentic 主编暂只对主参照书;其他书走软上下文注入(非 agentic 工具)。
