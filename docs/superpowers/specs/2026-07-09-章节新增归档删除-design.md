# 章节新增、归档、删除设计

## 目标

补齐“我如何新增或者删除章节”的完整闭环：作者可以在手稿二栏、卷工作台和章工作台中自然新增章节；删除默认进入可恢复的归档；永久删除只在危险区执行，并展示影响范围。

## 设计原则

- 章节 `seq` 是故事时间轴主键，不重排、不复用。新增章默认使用历史最大 `seq + 1`。
- 删除章默认是归档，不硬删正文、版本、反哺记录或引用。
- 已归档章不出现在手稿目录、全书大纲、项目树、统计字数和常规质量台账中。
- 永久删除必须先取影响清单，再带 `confirm_impact_token` 调用 DELETE。
- 卷删除语义保持不变：删除卷只把章移到未分卷，不删除章。
- 四栏契约不变：栏1入口、栏2目录、栏3详情、栏4主编。

## 后端接口

- `POST /chapters`
  - 入参：`title?: string`, `volume?: string | null`
  - 行为：创建空正文章，标题默认为 `第N章`，如传 `volume` 则归入该卷。
  - 返回：`{status:"created", seq, title, volume}`

- `POST /chapters/{seq}/archive`
  - 入参：`reason?: string`
  - 行为：设置 `archived=true`, `archived_at=time::now()`, `archive_reason`。

- `POST /chapters/{seq}/restore`
  - 行为：清除归档状态，章重新出现在目录和统计中。

- `GET /chapters/{seq}/impact`
  - 返回正文、版本、主编对话、素材引用、伏笔触及、母题触及、关系触碰、事件、scorecard 等影响计数，以及确认 token。

- `DELETE /chapters/{seq}`
  - 无 token 或 token 不匹配时返回 `409 + impact`。
  - token 匹配后永久删除章和章拥有的派生记录。

## 前端交互

- 手稿二栏顶部显示“新建章”，当前选中卷时新章落入该卷，否则落入未分卷。
- 卷行提供轻量“+章”入口，不替代卷选择。
- 卷详情“本卷章节”标题旁提供“新建章”。
- 章工作台顶部提供“归档章节”按钮。点击后弹出确认，说明“可恢复，不删除正文和引用”。
- 已归档章暂不做常规列表入口，后续可加“归档箱”。本轮先保证恢复 API 和永久删除后端闭环。

## 数据模型

新增迁移 `072_chapter_lifecycle.surql`：

- `chapter.archived bool default false`
- `chapter.archived_at option<datetime>`
- `chapter.archive_reason option<string>`

常规读路径统一过滤 `archived=true`。

## 验证

- Store：新增章不复用归档章号；归档后从 outline/stats/project_tree 隐藏；恢复后可见。
- API：新增、归档、恢复、永久删除 token 门禁。
- Web：二栏和卷工作台新建章会调用真实 API 并选中新章；章工作台归档会刷新树。
- 回归：`npm test`、`npm run build`、后端定向 pytest、浏览器四栏验收。
