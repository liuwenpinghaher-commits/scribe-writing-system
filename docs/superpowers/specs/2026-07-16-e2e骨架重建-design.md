# Scribe3 E2E 测试骨架重建 · 设计 Spec

日期:2026-07-16
关联:U-011(静默降级 fail-hard)、实际使用问题台账 U-001~U-011、静默降级审计清单

---

## 1. 背景与动机

U-011 收官后做完备性对抗检查,抓出 **6 个漏网**(2 个连审计都没发现),其中最关键的一条(组装崩在开流前→前端只见"连接中断")是靠**临时 TestClient 脚本**实证的,**没固化成测试**——下次重构一改就会悄悄破。这暴露了现有 e2e 的结构性问题。

### 现有三层 e2e 的四个病灶

1. **模拟文本绕过真实链路**:`tools/e2e_test.py:327` 明写"用固定文本代替 LLM 调用",测的是 store 层 CRUD + 正则统计,**完全绕过 app.py 端点/SSE/检测器**。U-011 修的组装链、fail-loud、6 漏网,一个都不在它视野。
2. **e2e 自己在假绿**:断言是 `print ✅/❌` 计数,`main()` 里设定验证失败只打印"⚠️有失败项"却**不 `exit(1)`**。U-011 要消灭的静默降级,长在了测试自己身上。
3. **零负路径**:全 happy-path,没有一条"坏 store → 该报错"的断言。
4. **前端 `qa_*.mjs` 全 stale**:24 个脚本都是 Jul 5 的一次性批次验收,无统一入口、无 CI 挂钩,坏了没人知道;且 `qa_b2` 会改生产库《纸命》`book_c256380e` 第 4 章(违反"绝不碰生产库"红线)。

### 关键定位结论

现有**单元/组件测试其实很强**——限知泄露 34 个(reveal_isolation 20 + context_security 14)、fail-loud 断言 77 处、留痕/失忆一串。骨架重建**不该重造它们**,而要补上它们结构上够不到的两层:

- **L1 端到端串联**:没有一条真正从 `建书→填设定→写章→检测器→报错到界面→质量` 走通全链路的测试。
- **L2 前端最后一厘米**:后端 error 帧 → 前端到底有没有显示红字?这个契约零 e2e。第四轮审计"前端最后一厘米断头×6"正是此盲区。

---

## 2. 目标与非目标

**目标**
- 补 L1(端到端串联)+ L2(前端最后一厘米)两层。
- 把 U 系列问题外推成**六类失效模式**,每类负路径 e2e 钉死,**每 PR 自动**挡回归。
- 真调档验真集成(真 Hermes 回流格式/工具链路),nightly / 本地一键。
- 清理旧资产(假绿脚本 + stale 前端脚本)。

**非目标**
- 不重造现有单元/组件测试(它们保留)。
- 不追求"真调 LLM 每 PR 自动"——公共 runner 无凭证/不确定/慢贵,物理不可行。

---

## 3. 架构:两档

```
真调档   nightly / 本地一键(make e2e-real)
  真起 后端:3321 + 前端:3311 + 真 Hermes 网关
  → Playwright 真机走完整写作路径(独立临时书,绝不碰《纸命》)
  → 断言:链路通 / fail-loud 触发 / 护栏红字到界面 / 字数范围
    (不钉正文内容——真调不确定,同 prompt 每次输出不同)

确定性档  每次 PR / GitHub CI
  真打 端点/SSE/组装/检测器/store(临时库)
  → 只 mock LLM 边界(固定回流 / 可编程故障注入)
  → 断言:六类失效模式的负路径全部钉死
```

**替身边界原则**(hexagonal / test-double 理论):测试替身**只放在系统与"慢/贵/不确定"外部依赖的唯一交界处**(LLM 网关),内部端点/组装/检测器/store 全真。

## 4. 失效模式矩阵(发散的产物)

把 U-011 遇到的问题,系统化外推到所有同类失效模式,每类一条 e2e 钉死:

| # | 失效模式 | 台账来源 | e2e 负路径断言 | 现有覆盖 |
|---|---|---|---|---|
| 1 | **静默降级/假绿** | U-011, U-001 | 注入故障(坏 store/检测器炸)→ 断言 error 帧带原文 / error 字段 / 红字,**而非静默正常** | 77 处单元基础,缺端到端串联 |
| 2 | **写了读不到** | U-002,U-004,U-005 | 写入后立即读回(round-trip):设定/留痕/MCP 列表 写完必须可见、不崩(RecordID 序列化) | 部分单元,缺全链 |
| 3 | **限知泄露** | U-003 | 限知场景:焦点角色不知道的秘密不得进 prompt/正文;检测器真触发 | 单元强(34),缺端到端 |
| 4 | **工具面越界** | U-006,U-003 | 探针:默认网关零工具面、各 profile 白名单;写作模型无 reveal 钥 | reveal_isolation 已覆盖,e2e 冒烟复核 |
| 5 | **集成断裂** | U-008,U-007 | 真调档验真集成;确定性档 mock 边界 down → fail-loud 报到界面**非 500 白屏** | 缺 |
| 6 | **失忆/对话记忆** | U-009,U-005 | 两轮对话:第二轮断言模型能引用第一轮(history 真注入) | test_chat 有基础,缺前端串联 |

### 每类的具体 e2e 场景(确定性档)

- **① 静默降级**:`llm_stub.fail(...)` 或 monkeypatch store 某读取崩 → 打 `/chat/stream`、`/check`、`/qc`、`/save-chapter` → 断言响应含 error 帧/字段带**真实异常原文**,而非静默正常返回。钉死 U-011 的 6 漏网(含"组装崩→原文进前端")。
- **② 写了读不到**:主编审批写入世界规则/势力 → 立即 `/project-frame` 或 MCP 列表读回,断言可见且**不 RecordID 崩溃**;设定写入 → 实时刷新端点读回。
- **③ 限知泄露**:填秘密事实(focalizer 不知情)→ 写含该秘密的正文 → `/check` 断言 `leaks` 非空且检测器真跑(非 `leaks_error`);组装 prompt 断言不含越权秘密。
- **④ 工具面越界**:调 `app._gateway_security_violations` 探针 → 断言默认网关零工具面、profile 白名单;写作 profile 无 `*_reveal`。
- **⑤ 集成断裂**:`llm_stub.fail(ConnectionError)` 模拟网关 down → 打 agentic 端点 → 断言 SSE error 帧优雅收尾(done 帧),**前端拿到的是可显示的错误而非 500 白屏**。
- **⑥ 失忆**:两轮 `/chat/stream`,第一轮回选项,第二轮断言 `llm_stub` 收到的 `history` 含第一轮内容(模型真看得见)。

## 6. 共享 harness(去重心脏)

### 6.1 `llm_stub`(确定性档核心)

统一 LLM 边界替身,终结"各测试各自 monkeypatch"。API 草案:

```python
class LlmStub:
    def reply(self, text): ...              # 下次流式回这个(正常路)
    def fail(self, exc): ...                # 下次调用抛这个(测 fail-loud)
    def responses(self, events): ...        # agentic 事件流
    @property
    def last_history(self): ...             # 断言模型收到的 history(测失忆⑥)

@pytest.fixture
def llm_stub(monkeypatch):
    stub = LlmStub()
    monkeypatch.setattr("scribe3.llm.hermes_complete_stream", stub.complete_stream)
    monkeypatch.setattr("scribe3.llm.hermes_responses_events", stub.responses_events)
    return stub
```

### 6.2 `full_stack`(端点全链路)

```python
@pytest.fixture
def full_stack(store, llm_stub):
    """TestClient(app) 绑定临时 store + LLM 替身。真打端点全链路,只 LLM 是替身。"""
    import scribe3.app as app_mod
    app_mod.set_store(store)
    from fastapi.testclient import TestClient
    return TestClient(app_mod.app)
```

## 7. CI 挂钩(诚实版)

- **确定性档 → 每 PR 全自动**:文件落在 `scribe3/tests/e2e/`,现有 CI 的 `pytest scribe3/tests` **自动就收,workflow 一行不改**。
- **前端 L2(最后一厘米)→ 进公共 CI**:`frontend_smoke.mjs` 用 Playwright + **mock-LLM 的真后端**(独立临时库)——不需真网关,能进公共 CI。落实"前端真机进 CI 独立临时书"。接 CI 的 `frontend` job(新增 `npm run e2e:ci` 步骤,起后端子进程 + headless)。
- **真调档 → nightly(交底)**:公共 GitHub runner **没 Hermes 凭证,真调物理跑不了**。落地为:
  - `make e2e-real` / `scripts/e2e_real.sh` 本地一键(你机器有凭证,随时跑);
  - `nightly.yml` 骨架建好,真调 job 设 `if: secrets 存在才跑`,留给日后接 self-hosted runner 或本地 cron。**公共 CI 不会假装能真调**。

## 8. 断言策略

- **确定性档**:钉**负路径行为**(error 帧带原文/error 字段/红字/round-trip 可见/无泄露/白名单/history 可见)。因 LLM 是固定桩,可断言精确结构。
- **真调档**:钉**结构与链路**,**不钉正文内容**(真调不确定)。可断言:请求成功、SSE 帧序完整、fail-loud 正确触发、护栏红字真出现在 DOM、字数在合理范围、检测器真运行。质量维度(环境/心理/动作描写密度)从 `tools/e2e_test.py` 迁移为**软报告**(打印趋势,不做硬断言,避免脆测)。

## 10. 验收标准

1. 六类失效模式**各至少一条确定性 e2e 绿**,`pytest scribe3/tests/e2e -q` 全通过。
2. 确定性档随现有 CI `pytest scribe3/tests` **每 PR 自动跑**(已验证收集到)。
3. 前端 L2 冒烟 `npm run e2e:ci` 本地跑通(mock-LLM 真后端 + 断言红字到界面)。
4. 真调档 `scripts/e2e_real.sh` 本地一键跑通完整旅程(真网关,你机器)。
5. U-011 的 6 漏网**每个都有对应确定性 e2e 钉死**(尤其"组装崩→原文进前端")。
6. 旧资产清理完成(`tools/e2e_test.py` + 24 `qa_*.mjs` 删除,有用部分已迁移),全回归绿。

## 11. 风险与权衡

- **真调档无法进公共 CI**:物理约束(无凭证)。缓解:本地一键 + nightly 骨架留 self-hosted 接口。已与作者交底,非偷懒。
- **前端 L2 进 CI 的时间成本**:起后端子进程 + headless Playwright,单条冒烟约十几秒~分钟级。缓解:只跑 1 条最短"报错到界面"路径,不跑完整旅程。
- **删除旧资产的破坏性**:已授权;有用部分先迁移并验证绿再删;git 历史可追溯。
- **确定性档 mock LLM 的固有局限**:测不到真实 Hermes 回流格式变化——这正是真调档存在的理由,两档互补。
