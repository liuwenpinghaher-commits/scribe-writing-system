# P0 修复:数据完整性 + 限知/私密边界 + 数据损坏类 bug

> 承接《数据字段生命周期审计》(docs/audits/2026-06-27)。本 spec 只做 **P0 批**(最高价值、边界清晰、数据/安全相关);P1/P2(清债、接线死字段)后续另开。

## 范围与非目标
- **做**:7 项 P0/clear-bug 修复(下列)。
- **不做**:接线死字段、命名漂移收口、声音指纹进 prompt、图谱多边可视化等 P1/P2(留待下批)。不重构架构。
- **一个需你拍板的软决策**(见 §4):MCP 召回工具对 secret 的处理强度。spec 取**保守默认**(加 `is_secret` 标志、保留 value 维持主编全知),可改硬屏蔽。

## 修复项

### 1. 🔴 ingest 解析失败不再清空本章知识(数据丢失)
**现状**:`parse_knowledge_delta`(critique.py:312)解析失败时吞异常返回空 delta;`apply_delta`(ingest.py:23-26)**先 `purge_ingest(seq)` 删本章既有 ingest 产出,再写空** → 一次解析失败=本章知识被清空且不重建,且 `applied:0` 与"本就无新知识"不可区分。
**目标**:
- `parse_knowledge_delta` 解析失败时返回**可区分的失败信号**(如返回 `None`,或抛特定异常),不再静默返回空 delta。
- `ingest_chapter`(ingest.py:64)解析失败 → **不调用 `apply_delta`(不 purge)**,返回 `{"applied": -1, "parse_failed": True, "delta": null}`。解析成功(即便内容空)→ 正常 apply(幂等 purge+重写)。
- `_bg_ingest`(app.py:952)对解析失败/异常**写一个可查状态**(或至少 warning 升级为带 seq 的明确日志),不再纯静默。
**验收**:解析失败时本章既有 ingest 命题/knows 边**不被删**;`ingest_chapter` 返回 `parse_failed=True`;parse 成功但空内容仍正常 purge+重写。pytest 覆盖三种情形。

### 2. 🔴 `GET /graph` 不泄露私密原文
**现状**:`store.graph()`(store.py:754)对 secret fact 输出 `(f.value or "")[:18]` 进节点 label → 私密短句整句上 wire。
**目标**:secret fact 的 label 输出占位(如 `"🔒 私密"` 或该命题的 `attribute` 名),**不输出 value 任何片段**;保留 `secret:true` 标志供前端着色。
**验收**:`/graph` 返回里 secret 节点 label 不含 value 文本。pytest:用 luanshi_leak_world,断言 secret 命题节点 label 无明文。

### 3. 🔴 删 `graph_recall` 死定义 + 保 secret 信号
**现状**:`store.graph_recall` 定义两次(store.py:451 与 480),Python 取后者(480),**生效版丢了 `secret` 字段**,下游无从屏蔽。
**目标**:删 451 死定义;生效版(480)的返回**带上 `secret`/`is_secret` 标志**(若现无)。
**验收**:`graph_recall` 单一定义;返回项含 secret 标志。pytest 断言。

### 4. 🔴 MCP 召回工具暴露 secret 标志(保守默认)
**现状**:`s3_semantic_recall`/`s3_hybrid_recall`/`s3_graph_recall`/`s3_dramatic_irony`/`s3_project_frame`(mcp.py:71/91/99/114/201)明文返回 secret `value` 且无 `is_secret` 标志 → 主编 agent 无从得知哪些是私密,可能误带进限知续写。
**目标(保守)**:这些工具返回的每条 fact **附 `is_secret` 布尔标志**(value 仍返回,维持"主编全知联查"设计)。这样主编/下游能识别私密、避免误用入正文。
> **软决策**:若你要**硬屏蔽**(限知场景下 value 也置空/打码),告诉我,改为按 focalizer 上下文屏蔽。默认只加标志、不删 value。
**验收**:上述工具返回含 `is_secret`。pytest 断言 secret 命题带标志。

### 5. 🔴 focalizer 切章恢复 + 不抹 title(限知护栏绕过 + 标题丢失)
**现状**:WriteLayout 加载章节只 `setProse`,不 `setFocalizer(ch.focalizer)`(WriteLayout.jsx:109)→ 切章丢失持久化视角;`persist()` 恒传 `title=''` 且空 focalizer(:127)→ 打开旧章再存会**抹掉 title 与 focalizer**,且 `/save-chapter` 因 focalizer 空跳过泄露检测(app.py:982)。
**目标**:
- 加载章节时 `setFocalizer(ch.focalizer || '')`(`api.chapter` 返回含 focalizer)。
- `persist()` 传**当前真实** title(从已加载章节保留,或至少不覆盖为空——传 `undefined`/原 title)与当前 focalizer。
**验收**:切到设了 focalizer 的章 → 顶栏视角下拉正确回显;保存不再抹 title/focalizer;限知章保存触发泄露检测。截图 + 行为验证。

### 6. 🔴 删 app.py 重复路由(字段经 REST 写不进)
**现状**:`/world-rules`(app.py:317/448/497)、`/factions`(343/477/518)、`/setting-completeness`(361/539)各定义 2-3 次,FastAPI 用首个;能收全字段(limitations/exceptions/established_chapter/known_members/first_mention_chapter)的后续 handler 是死代码。
**目标**:每组保留**能收全字段**的那一版(把首个换成全字段版,或合并),删其余重复定义。确保 `test_consistency` 写端点白名单仍对齐。
**验收**:每路由单一定义且能写全字段;`POST /world-rules` 能写 limitations 等。pytest 断言往返。后端全绿。

### 7. 🔴 设定 CRUD:name 加 UNIQUE + 编辑改 UPSERT(造重复行)
**现状**:`faction/world_rule/item/term` 的 name 无 UNIQUE,前端"编辑"走 `POST`(CREATE,CodexView.jsx:404-407)→ 每次编辑新增重复行;`delete WHERE name` 一次删光同名。
**目标**:
- 迁移 034:给四表的 name 加 UNIQUE 索引(若现有重复数据,先去重或用非 unique + store 改 UPSERT)。**优先方案**:store 的 add_* 改 `UPSERT ... WHERE name=$n`(幂等),前端编辑沿用但语义变为覆盖;若加 UNIQUE 风险高(旧库已有重复),则只改 store UPSERT,不加 UNIQUE。
- 实现者先查 main 库这四表有无重复,据此选"UNIQUE+去重"还是"仅 UPSERT"。
**验收**:同名设定编辑两次只剩一行(覆盖),不再造重复。pytest:add 同 name 两次 → 一行。
