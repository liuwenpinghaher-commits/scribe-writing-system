# Scribe3 PC UI 系统整修设计

- 日期：2026-07-10
- 状态：设计已确认，待用户审阅规格后进入实施计划
- 决策：以“方案 3：现有系统专业化整修”为主，有限吸收“方案 1：统一对象工作台”
- 平台：仅 PC；不承担手机和平板适配
- 交付边界：保留现有四栏、业务功能和 API，不进行全站路由或对象注册表大重构
- 提交边界：本规格只形成文档，不 commit

## 1. 结论

这次不推倒现有产品，也不把 UI 改造成另一套软件。

现有四栏模型已经具备正确骨架：

```text
入口 → 常驻目录 → 对象详情 / 正文 → 主编 / 扩展信息
```

本期工作以系统性精修为主：统一视觉语言、组件、密度、状态、可访问性和页面节奏；只处理会直接破坏一致性或可信度的结构问题，包括重复章节导航、章节阶段与辅助页混杂、四栏选择状态不一致、静态演示数据冒充真实数据，以及 `ObjectFrame` 未进入生产视觉路径。

最终目标不是“看起来换了主题”，而是：现有功能不搬家，用户仍认得原来的操作路径，但整个系统像一个成熟、克制、可信的专业写作产品。

## 2. 已确认的范围

### 2.1 本期做

- 保留 PC 四栏布局，统一其尺寸、分组、收起、恢复和视觉边界。
- 保留现有一级入口，不强制收缩为“手稿 / 设定库 / 素材库”三个入口。
- 将现有入口按“内容 / 工艺 / 检查”分组，降低八个平级入口的认知负担。
- 全面统一浅色、深色、字体、间距、圆角、边框、阴影、动效和状态色。
- 改造共享 UI 原语，并逐步替换页面中的裸控件和伪按钮。
- 删除章节内重复导航，章节只保留一套上一章 / 下一章入口。
- 将章节阶段收敛为“大纲 → 节拍 → 演绎 → 草稿 → 正文”。
- 将简报、关联、北极星、校验等放回辅助信息层，不再伪装为写作阶段。
- 将 `ObjectFrame` 接入为统一视觉外框，但不进行完整对象注册表重构。
- 让入口、目录、详情和右栏从同一选择状态投影，避免显示不同对象。
- 移除静态业务数量；没有真实数据源时隐藏数量或明确标注为演示。
- 补齐加载、空、错误、离线 / 降级、保存中、保存成功和危险操作状态。
- 修复键盘不可达、嵌套交互控件、缺少标签、缺少焦点恢复等问题。
- 对作品库、写作台、设定库、素材库、工艺能力、全局视图、搜索、校验和右栏进行一致性整修。

### 2.2 本期不做

- 不做手机、平板、触屏版导航，也不引入移动端 Drawer / Sheet。
- 不把全部一级入口重组为三个入口。
- 不实现完整 URL 路由、深链接和浏览器历史位置模型。
- 不建立新的全量 `WorkspaceLocation` 架构。
- 不重写现有业务 API、数据库模型、写作逻辑或 Hermes 运行路径。
- 不把全部对象详情改造成完整注册表驱动。
- 不新增业务功能，不借 UI 整修扩展需求。
- 不覆盖当前工作区中尚未提交的 Context Memory / `ContextSnapshot` 在途实现。

## 3. 当前代码基线

本规格以 2026-07-10 当前磁盘代码为准，旧文档只作为历史背景。

### 3.1 生产布局路径

```text
App
└── AppRail
    └── BinderLayout（V2 默认）
        └── FourPaneShell
            ├── Rail
            ├── DirectoryPane
            ├── DetailPane
            └── RightDock
```

- `FourPaneShell` 已经是生产四栏宿主，并负责目录和右栏宽度、收起与恢复。
- `AppRail` 同时承载作品入口、章节阶段插槽、横切视图和主题，层级仍然过密。
- `ObjectFrame` 目前只连接 `objectRegistry`，尚未进入真实详情渲染路径。
- `RightDock` 继续承载主编、选择环、版本、Pilot 和收件箱。
- 当前工作区正在引入 `ContextSnapshot` / `NavigationIntent`；UI 整修必须复用并验证它，不能另起第二套选择状态。

### 3.2 已证实的主要问题

| 维度 | 当前问题 | 本期处理 |
|---|---|---|
| 信息层级 | 顶部阶段、左入口、章节导航、正文工具栏和右栏同时争夺注意力 | 重新分层，不搬业务功能 |
| 章节工作台 | `ChapterStudio` 外层章导航与 `WriteLayout` 内部导航重复 | 只保留对象标题栏中的一套章导航 |
| 阶段语义 | 简报、关联、北极星与真正写作阶段并列；演绎在左侧能力入口 | 五阶段收敛，辅助信息归位 |
| 对象框架 | `ObjectFrame` 与 `objectRegistry` 没有生产调用 | 只接统一视觉外框，不做全注册表重写 |
| 字体密度 | 大量 10px、11px、12px 辅助文字，存在未定义字号使用 | 最低 12px，建立语义字号 |
| 控件 | 共享按钮高度 24 / 28 / 32px，页面仍有大量裸控件 | PC 紧凑但可用的统一尺寸和状态 |
| 颜色 | 部分 `faint`、`ok`、`warn`、`danger` 组合未达到普通文字 4.5:1 | 重建语义色并逐主题实测 |
| 交互语义 | 可点击 `div` / `span`、嵌套按钮、无关联表单标签 | 使用原生语义控件和共享组件 |
| 数据可信度 | 工艺目录存在静态配置、硬编码数量或空操作 | 只展示真实数据；无数据源则隐藏或明示 |
| 全局视图 | 图谱、时间线等存在鼠标 / Canvas 单一路径 | 增加可聚焦列表或文本等价路径 |

## 4. 设计原则

### 4.1 保留心智，不保留混乱

用户仍按原来的四栏从左向右工作；入口和主要功能不消失。需要删除的是重复层级、重复导航和无法解释的视觉噪声。

### 4.2 内容比装饰重要

正文、目录、对象关系和主编协作是主角。颜色、圆角、阴影和动效只用于表达层级和状态，不用于制造“高级感”。

### 4.3 一种行为只有一套交互

- 章节导航只有一套。
- 搜索只有一个结果系统。
- 一个对象的当前选择只有一个真相源。
- 相同的保存、错误、删除和重试行为使用相同组件。

### 4.4 真实优先

空数据就是空数据，错误就是错误，降级就是降级。禁止用静态数量、示例按钮或模糊文案营造“功能已完成”的假象。

### 4.5 PC 专业密度

本产品不是移动 App，也不是营销页面。允许使用 12–14px 的紧凑 UI 字体和 30–36px 控件，但必须保证对比度、焦点、键盘操作和足够点击区域。

## 5. PC 主框架

### 5.1 总体布局

```text
┌──────────────────────── 全局栏 44px ──────────────────────────┐
│ 作品 │ 图谱·时间线·洞察 │ 当前状态 │ 搜索 │ 主题 │ 系统状态 │
├──────┬──────────────┬──────────────────────┬─────────────────┤
│入口栏│   常驻目录    │     对象详情 / 正文   │  主编 / 扩展信息 │
│ 56px │  240–320px   │       弹性主区域      │   300–380px    │
└──────┴──────────────┴──────────────────────┴─────────────────┘
```

### 5.2 尺寸基准

| 视口 | 入口栏 | 目录默认值 | 右栏默认值 | 中央详情目标值 |
|---|---:|---:|---:|---:|
| 1280px | 56px | 240px | 320px | 约 660px |
| 1440px | 56px | 264px | 336px | 约 780px |
| 1600px | 56px | 280px | 360px | 约 900px |

- 最低正式验收窗口：1280×720。
- 主要视觉验收窗口：1440×900 和 1600×900。
- 目录和右栏可收起、恢复和拖动。
- 目录、右栏宽度与收起状态按作品保存。
- 中央正文仍使用可读行宽，不随面板无限拉宽。
- 小于 1280px 不作为正式布局目标；不能因此破坏 1280px 以上的 PC 密度。

### 5.3 全局栏

全局栏只表达应用级和作品级状态：

- 左侧：SCRIBE3 字标、当前作品和作品切换。
- 中部：图谱、时间线、洞察等横切视图。
- 右侧：搜索 / `⌘K`、主题、连接 / 保存异常等系统状态。
- 章节阶段不再挂在全局栏中。
- 顶部搜索是快捷入口：它打开并聚焦左侧“搜索”工作区，不创建第二套结果页。
- 当前对象的标题、阶段和操作属于第三栏内部，不污染全局层。

### 5.4 第一栏：入口

现有入口保留，按三组呈现：

```text
内容
  手稿
  设定库
  素材库

工艺
  演绎
  伏笔
  母题

检查
  搜索
  校验
```

- 栏宽继续保持 56px，不增加第二套文字侧栏。
- 组间使用稳定分隔和空隙，不靠不同颜色制造分组。
- 图标全部来自 Lucide，同一层级使用同尺寸、同描边。
- 当前入口同时使用背景、左侧指示条和 `aria-current` 表达，不能只靠颜色。
- 图标按钮有可见 Tooltip、`aria-label` 和键盘焦点。
- 入口本身不展示硬编码业务数量。

### 5.5 第二栏：目录

每个入口共享同一种目录框架：

```text
目录标题 + 数量 / 状态
搜索或筛选
主要操作
────────────────
目录内容
```

- 标题、搜索、筛选、新建按钮和加载状态位置固定。
- 手稿保留卷 → 章 → 场景层级。
- 设定库保留分类 → 条目层级。
- 素材库保留素材类型 → 素材层级。
- 工艺与检查目录只展示真实 API 数据。
- 每个入口分别记忆展开、滚动、筛选和最后选择位置。
- 目录项整行可选，但行内更多菜单、归档等操作必须是独立按钮，禁止嵌套交互元素。
- 当前项、悬停项、键盘焦点项和含未保存内容项必须可区分。

### 5.6 第三栏：对象详情

`ObjectFrame` 作为视觉外框接入真实详情路径：

```text
对象路径 / 类型
对象标题 + 状态 + 主要操作 + 更多
对象页签或章节阶段
────────────────────────────
现有 DetailComponent / Editor
```

- 本期不要求所有对象改成完整注册表驱动。
- `DetailPane` 仍负责业务详情路由；`ObjectFrame` 只统一标题、状态、页签和空 / 错误边界。
- 章、角色、素材优先接入；其他对象使用同一外框逐步覆盖。
- 容器对象仍可显示 `ContainerOutline`，但要使用相同标题和状态规范。
- 未选对象时显示清晰引导，不在中央留下无意义空白。
- 未知对象类型必须显示可恢复错误，不能只有“未知对象类型”一行小字。

### 5.7 第四栏：主编与扩展

保留现有 `RightDock` 业务能力，不改变 API：

- 主编始终是默认页签。
- 选中章节时显示选择环、版本和 Pilot。
- 收件箱保留，但与对象级工具用分隔和标签明确区分为“全局”。
- 不适用于当前对象的页签不显示。
- 当前页签在切换对象后失效时，自动回到主编并说明原因，不显示空壳。
- 页签顺序稳定；不能因请求返回顺序改变。
- 右栏崩溃继续由错误边界隔离，不能拖垮正文。
- 右栏收起后在第三栏右上角保留明确恢复按钮。

## 6. 章节工作台

### 6.1 五阶段

```text
大纲 → 节拍 → 演绎 → 草稿 → 正文
```

- 演绎继续复用现有能力和数据，不重写业务逻辑；只是从心智上归入章节阶段。
- 简报、关联、北极星属于辅助信息，不再作为阶段。
- 阶段切换使用语义化 Tabs，具备 `role="tablist"`、`aria-selected` 和方向键操作。
- 阶段状态按作品 / 章节合理保存，不能用跨作品共享值污染新作品。

### 6.2 单一章节导航

- 上一章、当前章、下一章放入对象标题栏。
- 删除 `WriteLayout` 内部的第二套章节导航。
- 下一章必须受真实末章边界约束，不能无限递增到不存在章节。
- 归档进入“更多”菜单，保持危险操作与日常导航分离。
- 章切换时保留未保存保护；用户取消后停留原章。

### 6.3 正文层级

正文阶段最多保留四层：

```text
对象标题栏
阶段栏
正文工具栏
正文画布
```

- 本章参考素材默认收进可展开辅助条，不再永久占用完整一行。
- 北极星、Pulse、Memory 等信息合并为一个“写作上下文”入口或右栏辅助，不继续堆叠横条。
- 正文工具栏只放直接作用于文本的功能：视角、护栏、检查、保存等。
- 保存状态与字数放入标题栏状态区，避免重复出现。
- 正文保持现有衬线字体、约 17.5px 字号、1.9 行高和约 42rem 行宽。

## 7. 视觉系统

### 7.1 风格

设计方向为“理性编辑网格 + 温润纸张”：

- 保持内容密集，但避免拥挤。
- 暖白纸面、墨色正文、克制绿色强调。
- 不使用 AI 紫色、粉色渐变、玻璃拟态、霓虹或大面积 Bento 卡片。
- 面板主要依靠留白和 1px 分隔线建立层级。
- 阴影只用于菜单、Popover、Dialog 和拖浮层。

### 7.2 语义色候选

| Token | 浅色 | 深色 | 用途 |
|---|---:|---:|---|
| `canvas` | `#F3F1EC` | `#141816` | 工作台背景 |
| `surface` | `#FBFAF7` | `#1B211E` | 面板 |
| `raised` | `#FFFFFF` | `#222925` | 浮层 |
| `ink` | `#1D2420` | `#EEF1ED` | 主文字 |
| `muted` | `#5F6963` | `#B7C0BA` | 次级文字 |
| `faint` | `#65706A` | `#8F9A93` | 非正文辅助信息 |
| `line` | `#D8D4CB` | `#38423D` | 边框与分隔 |
| `brand` | `#2F6B5D` | `#74B29E` | 选择与主要操作 |
| `brand-on` | `#FFFFFF` | `#102019` | 品牌底色上的文字 |
| `success` | `#2F6B4F` | `#78C49B` | 成功 |
| `warning` | `#825615` | `#E8B768` | 警告 |
| `danger` | `#9D3838` | `#F08B8B` | 危险与错误 |

这些值是设计候选，不因写进文档就视为已通过。实施阶段必须逐一计算实际前景 / 背景组合：

- 普通文字至少 4.5:1。
- 大文字和有意义的图形至少 3:1。
- 禁止通过 `text-faint/60` 一类透明度继续压低正文可读性。
- 浅色和深色分别验证，不允许以“反相后应该能看”为依据。

### 7.3 字体

| 角色 | 字体 | 字号 / 行高 |
|---|---|---|
| UI 元数据 | Inter + Noto Sans SC | 12 / 16 |
| UI 辅助 | Inter + Noto Sans SC | 13 / 18 |
| UI 正文 | Inter + Noto Sans SC | 14 / 20 |
| 对象标题 | Inter + Noto Sans SC | 16 / 22，600 |
| 区域标题 | Inter + Noto Sans SC | 20 / 28，600 |
| 页面标题 | Inter + Noto Sans SC | 24 / 32，600 |
| 长文正文 | Source Serif 4 + Noto Serif SC | 17.5 / 1.9 |

- 删除 10px、11px 文本角色。
- 12px 只用于非关键元数据、Badge 和紧凑表头。
- 禁止使用未在主题中定义的 `text-fNN`。
- 字数、版本、时间、章号使用等宽数字。
- 正文段宽控制在 60–75 个拉丁字符的等效阅读长度。

### 7.4 间距、圆角与阴影

- 基础间距：4 / 8 / 12 / 16 / 24 / 32px。
- 圆角：6px（小控件）、8px（常规控件）、12px（面板 / Dialog）。
- 面板不使用悬浮卡片效果。
- `shadow-sm` 只用于选中层、菜单和必要浮层。
- Dialog 使用统一 Scrim 和层级 Token。
- 建立固定 z-index：内容 0、粘性标题 10、Popover 40、Dialog 100、Toast 200。

### 7.5 动效

- Hover / 选择：120–180ms。
- Popover / Dialog：180–220ms。
- 只动画 `opacity` 和 `transform`，不动画面板宽高造成连续重排。
- 收起大面板可以使用一次有意义的空间过渡，但必须可打断。
- 支持 `prefers-reduced-motion`；JS 平滑滚动和图谱动画也必须读取该偏好。

## 8. 组件系统

### 8.1 尺寸

| 组件 | PC 尺寸 |
|---|---:|
| 紧凑文字按钮 | 30px 高 |
| 常规按钮 | 34px 高 |
| 主要按钮 | 36px 高 |
| 图标按钮 | 32×32px |
| 输入框 / Select | 36px 高 |
| Tabs | 32px 高 |
| 目录行 | 最低 32px |
| 菜单项 | 最低 32px |

- 视觉图标可以是 14–18px，点击区域不能等于图标大小。
- 小于 32px 的紧凑操作只允许出现在高密度行内，并满足 WCAG 24px 目标尺寸或足够间距。

### 8.2 必备共享组件

- `Button` / `IconButton`
- `Input` / `Textarea` / `Select`
- `Field` / `Label` / `Description` / `FieldError`
- `Tabs` / `TabList` / `Tab`
- `DirectoryHeader`
- `ObjectHeader` / `ObjectFrame`
- `AsyncState`：loading / empty / error / degraded / success
- `Dialog` / `ConfirmDialog` / `Popover` / `Tooltip`
- `Toast`
- `StatusBadge`
- `EmptyState`

### 8.3 组件状态

所有交互组件必须具有：

- 默认
- Hover
- Active / Pressed
- Selected
- Keyboard Focus
- Disabled
- Loading
- Error（适用时）

禁止用颜色作为唯一差异。选中态至少还要有背景、描边、字重或形状变化之一。

## 9. 导航与状态

### 9.1 UI 投影模型

本期不新建完整 URL 路由模型，但 UI 必须围绕一份一致状态投影：

```text
entry
selectedObject
detailFacet
rightTab
globalView
directoryStateByEntry
layoutStateByWork
contextRevision
```

- 当前在途 `ContextSnapshot` / `NavigationIntent` 是优先复用对象。
- `sel` 可以作为兼容输入，但不能与 Snapshot 各自独立决定不同栏位。
- 409 `stale_context` 对齐后，入口、目录、详情和右栏必须在同一 revision 更新。
- 不允许只更新 `entry` 而保留旧详情，或只换详情而不定位目录。

### 9.2 入口与目录状态

- 每个入口独立保存目录滚动、展开、筛选和最后选中项。
- 切换入口再返回时恢复原状态。
- 同一作品保存宽度与折叠状态；切换作品后使用该作品自己的偏好。
- 阶段和右栏页签不得跨作品无条件共享。

### 9.3 跨入口跳转

章节素材引用、图谱节点、时间线事件、主编提及和搜索结果必须走同一跳转函数：

```text
target → 计算目标入口 → 定位目录 → 选中对象 → 打开详情 → 更新主编上下文
```

- 无法定位时保留原位置并显示可恢复错误。
- 跳转到全局视图时缓存写作位置；退出全局视图时原位恢复。
- 顶部搜索和 `⌘K` 只触发现有搜索工作区，不维护第二份结果状态。

## 10. 页面级整修

### 10.1 作品库

- 利用 PC 宽度建立清晰的页面标题、最近作品和作品网格，不把全部内容挤在左上角小区域。
- 作品卡采用真实按钮 / 链接语义。
- 删除操作进入独立更多菜单，禁止在主按钮内部嵌套可点击 `span`。
- 新建作品是唯一主要操作。
- 空作品库提供建立第一部作品的明确行动。
- 加载失败提供重试，不把失败当成空列表。

### 10.2 手稿目录与章节

- 卷、章、场景的缩进、展开、当前项和归档状态统一。
- 新建卷 / 章靠近目录标题；行内只保留低频更多菜单。
- 章元数据使用真实阶段和字数，不展示推断性占位。
- 章节标题栏统一上一章 / 下一章、状态、字数和更多操作。

### 10.3 设定库

- 继续使用“设定库”，与“素材库”保持语义区分。
- 新建与编辑字段统一使用 `Field` 体系。
- 可编辑值不能再依赖可点击 `div`；进入编辑必须是按钮或明确输入状态。
- 自动保存显示“保存中 / 已保存 / 保存失败”，失败不能静默。
- 角色、势力、物件、术语、规则、伏笔、母题等使用同一对象标题和字段节奏。

### 10.4 素材库

- 保留素材作为非正典参考记忆，不与设定对象混名。
- 导入、筛选、搜索、详情、来源和“用在哪”遵循统一标题与状态组件。
- 来源、创建方式、引用章节等 provenance 信息使用稳定元数据区。
- 素材网络必须保留降级提示，并增加可聚焦列表 / 文本等价路径。

### 10.5 演绎、伏笔、母题

- 目录数量只能来自真实 API。
- 没有实时数量时不展示数量，而不是写死“4 / 19”等示例。
- 筛选和同步按钮必须有真实行为；未实现则隐藏或明确标记不可用原因。
- 演绎既可从左侧工艺入口进入，也能从章节五阶段进入；两者打开同一数据和详情，不形成两套演绎状态。

### 10.6 搜索与校验

- 顶部搜索、`⌘K` 和左侧搜索入口最终指向同一工作区。
- 查询和筛选放在第二栏，结果与上下文放在第三栏。
- 点击结果走统一跨入口跳转。
- 校验条目支持定位正文；定位失败时说明“文本已变化”，不能画到错误位置。
- 错误级别不能只靠红 / 黄 / 绿表达，必须附图标和文字。

### 10.7 图谱、时间线与洞察

- 继续作为全局视图，不改变数据能力。
- Canvas / WebGL 视图旁提供可搜索、可键盘操作的列表或文本摘要。
- 选中节点后使用同一对象详情或右栏上下文。
- 图例、筛选、时间尺度和当前选中状态位置统一。
- 深色主题通过语义 CSS 变量取色，不在组件里散落硬编码 Hex。
- 失败显示重试，降级显示仍可使用的内容。

### 10.8 右栏

- `ChiefDock` 保持唯一主要对话入口。
- 主编当前上下文必须与第三栏对象一致。
- 选择环、版本恢复和 Pilot 保留现有业务语义。
- 危险版本恢复继续使用确认 Dialog；完成后必须刷新正文和版本列表。
- Pilot 的运行、暂停、卡住、停靠和错误状态统一用 `StatusBadge` 和 `AsyncState`。
- 收件箱 Badge 只显示真实数量，加载失败不能悄悄显示 0。

## 11. 表单、弹层与反馈

### 11.1 表单

- 每个输入有可见 `label`，并通过 `htmlFor` / `id` 关联。
- 帮助文字长期可见，不依赖 Placeholder 承担说明。
- 校验在失焦或提交后触发，不在用户每输入一个字时持续报错。
- 错误放在对应字段下方；多个错误时提供摘要并聚焦第一个错误。
- 只读与禁用在视觉和语义上区分。

### 11.2 Dialog / Popover

- 全部使用共享 `Dialog` / `ConfirmDialog`。
- 具备 `role="dialog"`、`aria-modal`、焦点陷阱、Escape 关闭和关闭后的焦点恢复。
- 有未保存内容时，关闭必须确认。
- 危险主要操作与取消按钮保持稳定位置。

### 11.3 Toast 与状态反馈

- 成功 Toast 3–5 秒自动关闭。
- 错误 Toast 不只写“失败”，必须说明原因和恢复方式。
- Toast 使用 `aria-live`，但不抢占键盘焦点。
- 长任务优先使用局部进度或持续状态，不用短暂 Toast 掩盖运行状态。

## 12. 加载、空、错误和降级

统一使用 `AsyncState`：

| 状态 | 行为 |
|---|---|
| loading < 300ms | 保持旧内容或静默等待，避免闪烁 |
| loading ≥ 300ms | 显示局部 Skeleton / 进度 |
| empty | 解释为什么为空，并给出下一步 |
| error | 显示原因、影响范围和重试 |
| degraded | 展示仍可用内容并说明缺失能力 |
| stale context | 对齐到最新 revision 并提供明确提示 |
| saving | 禁用重复提交，显示保存中 |
| saved | 短暂明确确认，不持续占用注意力 |

- 禁止把网络错误解释为“对象可能已删除”。
- 禁止 `catch(() => {})` 让关键失败完全无声；非关键轮询失败可以静默，但必须有整体连接状态。
- 请求失败不得清空用户尚未保存的表单或正文。

## 13. 可访问性与键盘

- 普通文字对比度至少 4.5:1，有意义 UI 图形至少 3:1。
- 全部功能可通过键盘完成。
- Tab 顺序严格按“全局栏 → 入口 → 目录 → 详情 → 右栏”。
- 提供“跳到正文 / 详情”快捷链接，避免每次穿过全部导航。
- Tabs 使用方向键，目录树使用标准树形键盘模型。
- 图标按钮必须有可访问名称和 Tooltip。
- 可点击容器改成 `button` / `a`，或完整实现等价键盘语义。
- 焦点不能被 `outline: none` 隐藏；焦点环在浅色和深色均清晰。
- 打开 Dialog 后焦点进入 Dialog，关闭后回触发点。
- 页面 / 对象切换后焦点进入对象标题，而不是回到文档顶部。
- 图谱、时间线、热力图提供列表、表格或文本摘要作为等价路径。
- 支持 `prefers-reduced-motion`。
- 200% 浏览器缩放下关键功能仍可访问；允许用户收起目录和右栏，不要求四栏同时保持原比例。

## 18. 风险与控制

| 风险 | 控制方式 |
|---|---|
| UI 整修覆盖正在进行的 Context Memory 改动 | 实施前复核 diff；不覆盖在途文件；以现有 Provider 为基础 |
| 移动阶段 / 辅助页导致 Provider 或 Portal 断开 | 只移动容器，保留数据组件；每个页面单独浏览器验证 |
| 共享 Token 一次替换造成暗色大面积回归 | 浅色 / 深色逐组件迁移，保留旧 Token 兼容期 |
| 缩小控件密度损害可访问性 | PC 最低 32px 点击区，24px 规则与间距实测，完整键盘路径 |
| WebGL / Canvas 不响应主题 | 继续从 CSS 变量读取真色，并在主题切换后刷新渲染 |
| 删除静态数量后页面显得空 | 使用真实空状态和说明，不用假数字填充 |
| build 绿但运行时白屏 | 每阶段真实浏览器和控制台作为停止条件 |

## 19. 设计决策记录

已确认：

1. 只做 PC。
2. 以方案 3 为主，方案 1 只取必要部分。
3. 保留现有四栏、业务功能和 API。
4. 不强制只留三个一级入口。
5. 接入 `ObjectFrame` 视觉外框，不进行完整注册表重构。
6. 修复重复导航、状态不一致和静态假数据。

8. 视觉采用理性编辑网格、温润纸张和克制绿色。
9. 1280px 是最低完整 PC，1440–1600px 是主要优化范围。
10. 设计完成后先审阅规格，再制定实施计划；本阶段不 commit。
