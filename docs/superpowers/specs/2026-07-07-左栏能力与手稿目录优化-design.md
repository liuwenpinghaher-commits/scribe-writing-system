# 左栏能力与手稿目录优化 · 设计文档

日期: 2026-07-07

状态: brainstorming 方案文档 v1, 待用户确认后进入实施计划

## 1. 结论

采用 **左栏能力入口 + 左栏二级目录 + 栏3详情/工作台 + 右栏主编上下文**。

本轮不再把复杂能力压到顶栏,也不把伏笔、母题、搜索、校验挪到右栏作为唯一入口。顶栏只承载全局视图和当前章阶段。左侧负责“我要进入哪个工作域”和“我要处理哪个对象”,中间负责完整编辑与详情,右侧负责主编、选择环、存档、Pilot、收件箱等辅助上下文。

核心修正有两点:

1. “项目”统一改名为 **手稿**。手稿二级目录按 **书级工具 / 卷 / 章 / 场景** 组织,支持章节很多时稳定浏览。
2. 章选择、快速跳章、过滤入口放入 **左栏二级目录的 sticky 顶部**,不放在详情区或右栏底部,避免章节过多时沉底。

## 2. 设计依据

- Apple Human Interface Guidelines 的 split view / sidebar 思路:leading pane 适合放顶层集合和导航,详情在相邻面板展开。
- Apple outline views:文本型层级内容适合放在 split view 的 leading side。
- Material Design navigation rail:主导航 rail 适合承载 3-7 个主要目的地,更复杂的目的地下钻应进入展开 rail / drawer / side pane。
- VS Code 的 Activity Bar + Side Bar + Editor 心智:左侧是能力入口,相邻侧栏是该能力的二级目录,编辑区承载详情。
- NN/g progressive disclosure:一级暴露主要能力,复杂内容逐级展开,避免把所有信息同时堆到一个面板。

参考链接:

- https://developer.apple.com/design/human-interface-guidelines/split-views
- https://developer.apple.com/design/human-interface-guidelines/sidebars
- https://developer.apple.com/design/human-interface-guidelines/outline-views
- https://m3.material.io/components/navigation-rail/overview
- https://www.nngroup.com/articles/progressive-disclosure/

## 3. 信息架构

目标结构:

```text
┌────────────────────────────────────────────────────────────────────┐
│ 顶栏: 作品切换 | 图谱 时间线 仪表盘 | 章阶段: 大纲 节拍 草稿 正文 简报 限知帧 北极星 │
├──────────┬──────────────────────┬──────────────────────────┬──────────────┤
│ 栏1      │ 栏2                  │ 栏3                      │ 栏4          │
│ 能力入口 │ 二级目录/对象列表      │ 详情/编辑/能力工作台       │ 主编/辅助上下文 │
│          │ sticky 当前定位/选择器 │                          │              │
└──────────┴──────────────────────┴──────────────────────────┴──────────────┘
```

职责边界:

| 区域 | 职责 | 不做什么 |
|---|---|---|
| 顶栏 | 全局视图、当前章阶段、作品切换、主题 | 不承载有二级目录的复杂能力 |
| 栏1 | 一级能力入口 | 不展开长列表 |
| 栏2 | 当前能力的二级目录、过滤、当前定位、对象选择 | 不渲染对象完整详情 |
| 栏3 | 选中对象详情、章工作台、演绎工作台、伏笔/母题/搜索/校验详情 | 不再就地展开容器列表 |
| 栏4 | 主编、选择环、存档、Pilot、收件箱、当前 focus 摘要 | 不作为伏笔/母题/搜索/校验的唯一入口 |

## 4. 栏1: 能力入口

左侧一级入口按“作者真实工作域”组织:

```text
内容
- 手稿
- 设定
- 素材

工艺
- 演绎
- 伏笔
- 母题

检查
- 搜索
- 校验
```

默认顺序为:

1. 手稿
2. 设定
3. 素材
4. 演绎
5. 伏笔
6. 母题
7. 搜索
8. 校验

其中“手稿”替代原来的“项目”。“项目”是工程管理词,对作者不够直观;“手稿”能直接表达这里管理的是正文结构、卷、章、场景和书级大纲。

## 5. 栏2: 二级目录

栏2必须常驻,只随栏1入口切换内容。点栏2条目只刷新栏3,不能把栏2替换掉。

### 5.1 手稿目录

手稿入口下,栏2分为固定顶区和可滚动目录区:

```text
手稿
┌ sticky 顶区 ─────────────────────┐
│ 当前: 第 23 章 · 草稿              │
│ [跳章输入] [只看未完] [当前卷]      │
└──────────────────────────────────┘

书级
- 全书大纲
- 北极星
- 进度

卷
▾ 第一卷
  - 第 1 章
  - 第 2 章
▸ 第二卷
▸ 第三卷

未归卷章节
- 第 98 章
```

设计规则:

- sticky 顶区永远可见,承载当前章、快速跳章、过滤、当前卷定位。
- 目录主体滚动,卷可折叠,章数量再多也不会影响顶区。
- 有卷时按卷分组,无卷时直接显示“章节”分组。
- 场景属于章的下一级,默认不展开;需要时在当前章下展开,避免大书列表过长。
- 书级工具保留在手稿目录顶部,但必须紧凑,不能抢占长目录空间。

### 5.2 设定目录

设定入口下,栏2显示设定分类:

```text
设定
- 角色
- 势力
- 物件
- 术语
- 世界规则
- 命题
```

点分类后栏2显示该分类条目列表,栏3显示选中条目详情。新增入口保留在分类列表顶部或底部的固定按钮,不挤占详情区。

### 5.3 素材目录

素材入口下,栏2显示素材类型和素材列表:

```text
素材
- 笔记
- 片段
- 资料
- 灵感
- 外部引用
```

搜索和筛选留在素材栏2内部,素材详情在栏3。

### 5.4 演绎目录

演绎不是顶栏阶段,而是左栏能力。原因是它有明确二级目录,包括场景真相和涉及角色,不适合被压平成一个顶栏按钮。

```text
演绎
┌ sticky 顶区 ───────────┐
│ 当前章: 第 23 章        │
│ [切章] [同步当前章]      │
└────────────────────────┘

- 场景真相
- 角色限知
  - 柳怀玉
  - 小翠
  - + 添加涉及角色
- 冲突与误判
- 可公开信息
```

点二级项后,栏3渲染对应 `DeduceStage` 工作台分面。这样保留演绎的“树状推导”心智,同时不给顶栏制造复杂下拉。

### 5.5 伏笔目录

```text
伏笔
- 本章要收
- 本章新埋
- 超期未收
- 仍悬
- 已回收
- 全书伏笔
```

点分类后,栏2显示伏笔条目列表;点条目后,栏3显示伏笔详情、证据、埋收窗口、关联章节和修复动作。

### 5.6 母题目录

```text
母题
- 本章触及
- 本卷主母题
- 全书母题
- 证据不足
- 过度重复
```

点母题条目后,栏3显示母题详情、出现章节、证据片段、和当前章的使用建议。

### 5.7 搜索目录

搜索仍放左栏,但语义召回不是小面板,而是完整工作流:

```text
搜索
┌ sticky 搜索框 ───────────────┐
│ 按意思搜: 炼丹复活             │
│ [全书] [设定] [正文] [素材]     │
└──────────────────────────────┘

结果
- 设定命中
- 正文命中
- 素材命中
- 最近搜索
```

搜索结果列表在栏2,选中结果在栏3展开上下文、命中理由、跳转目标。

### 5.8 校验目录

```text
校验
- 本章总览
- 复读
- 跨章复读
- 整句重复
- 排比句式
- 情感直说
- AI 腔
- 张力检查
- 限知泄露
```

点校验类型后,栏2显示命中列表;点具体命中后,栏3显示命中上下文、定位、解释、修复建议和接受/忽略操作。

## 6. 选择区上移方案

“选择区”不再跟随详情内容向下滚动,而是成为栏2的 sticky 顶部区域。

手稿入口下,选择区包含:

- 当前对象:当前卷、当前章、当前阶段。
- 快速跳转:章号输入、上一章、下一章。
- 过滤:当前卷、未完成、有问题、含伏笔、含母题。
- 状态:草稿/正文/已终选等简短徽章。

演绎、伏笔、母题、搜索、校验入口下,sticky 顶区改为该能力的上下文选择:

- 演绎:当前章、同步当前章、切章。
- 伏笔:当前章/全书、状态过滤。
- 母题:当前章/本卷/全书。
- 搜索:搜索框和范围筛选。
- 校验:当前章、检查范围、重新检查。

这样每个能力都有自己的“不会沉底的操作头”,并且不污染栏3详情和右栏主编。

## 7. 栏3详情路由

栏3只做详情和完整工作台:

| 栏1入口 | 栏2选中 | 栏3显示 |
|---|---|---|
| 手稿 | 章/场景 | `ChapterStudio` |
| 手稿 | 全书大纲 | `ContainerOutline` 全书大纲 |
| 手稿 | 北极星 | 书级 `NorthStarPanel` |
| 设定 | 设定叶 | `CodexDetail` / `PropositionDetail` |
| 素材 | 素材条目 | `MaterialDetail` |
| 演绎 | 场景真相/角色 | `DeduceStage` 对应分面 |
| 伏笔 | 伏笔条目 | 伏笔详情工作台 |
| 母题 | 母题条目 | 母题详情工作台 |
| 搜索 | 搜索结果 | 召回详情 + 跳转 |
| 校验 | 命中项 | 命中详情 + 修复建议 |

容器节点不在栏3展开列表。容器只负责驱动栏2目录,栏3最多显示空态提示“选择目录条目查看详情”。

## 8. 右栏保留内容

右栏保留:

- 主编
- 选择环
- 存档
- Pilot
- 收件箱

右栏可以感知当前选中对象,展示简短上下文摘要,但不承载伏笔、母题、搜索、校验、演绎的完整工作台。

理由:

- 右栏宽度小,适合对话、辅助、决策和版本类信息。
- 伏笔/母题/搜索/校验需要列表、命中详情、证据、定位和操作,放右栏会挤压信息。
- 演绎有二级目录和角色限知树,天然属于左栏钻取链路。

## 9. 顶栏归位

顶栏保留两类入口:

1. 全局视图:图谱、时间线、仪表盘。
2. 当前章阶段:大纲、节拍、草稿、正文、简报、限知帧、北极星。

演绎从顶栏阶段移出,进入左栏能力。若需要保留快捷入口,只能作为“跳到左栏演绎并同步当前章”的快捷按钮,不能作为独立渲染入口。

## 10. 实施边界

本方案是信息架构重排,不是业务重写。

保留:

- `FourPaneShell` 的 entry/item 两级选中思路。
- `DirectoryPane` 常驻目录。
- `DetailPane` 作为栏3路由权威。
- `RightDock` 的主编、选择环、存档、Pilot、收件箱。
- 旧三栏 flag 关闭路径。

新增或改造:

- `EntryRail`: 从“手稿/设定/素材”扩展为“手稿/设定/素材/演绎/伏笔/母题/搜索/校验”。
- `DirectoryPane`: 增加按能力分发的二级目录,并支持 sticky 顶部选择区。
- 手稿目录模型:从 project tree 派生卷、章、场景,并以卷折叠组织。
- 演绎目录:把 `DeduceTree` 纳入栏2,栏3承载 `DeduceStage`。
- 伏笔/母题/搜索/校验:从旧 `LeftDock` 小面板升级为栏2目录 + 栏3详情。

不做:

- 不删除左栏能力。
- 不把复杂能力塞进右栏作为唯一入口。
- 不把二级目录压进顶栏 dropdown。
- 不重写后端数据模型。
- 不下线旧三栏,直到完整回归通过。

## 11. 验收标准

视觉与交互:

- 栏1中出现手稿、设定、素材、演绎、伏笔、母题、搜索、校验。
- 不再出现“项目”作为主入口文案。
- 手稿入口下,栏2显示 sticky 当前定位/选择区,并按卷/章组织。
- 章节列表滚动时,sticky 选择区不沉底、不消失。
- 演绎、伏笔、母题、搜索、校验都能按“栏1入口 -> 栏2目录 -> 栏3详情”钻取。
- 右栏仍保留主编、选择环、存档、Pilot、收件箱。

功能:

- 点章进入章工作台。
- 点设定叶进入设定详情。
- 点素材进入素材详情。
- 点演绎二级项进入对应演绎工作台。
- 点伏笔行进入伏笔详情。
- 点母题行进入母题详情。
- 搜索结果可在栏3展开并跳转。
- 校验命中可在栏3展开并定位。

兼容:

- 旧三栏 flag 关闭后仍可用。
- 现有 `LeftDock` 能力在迁移前不删除,迁移后有对应新入口和测试覆盖。
- 顶栏全局视图仍可打开。

测试:

- `EntryRail` 测试:一级入口完整,文案为“手稿”而非“项目”。
- `DirectoryPane` 测试:手稿 sticky 顶区存在,卷/章目录可展开。
- 演绎测试:场景真相和角色限知仍可选中。
- 伏笔/母题测试:点击条目会选中详情对象。
- 搜索/校验测试:列表和详情分列渲染。
- Playwright 真机走查:手稿、设定、素材、演绎、伏笔、母题、搜索、校验逐入口通过。
- `npm test` 和 `npm run build` 通过。

## 12. 推荐实施顺序

1. 只改文案和入口模型:项目改手稿,栏1保留并扩展能力入口,不删旧能力。
2. 手稿目录改造:sticky 选择区 + 卷/章/场景目录。
3. 演绎迁移:栏1演绎入口 + 栏2演绎目录 + 栏3 `DeduceStage`。
4. 伏笔/母题迁移:栏2分类和条目,栏3详情工作台。
5. 搜索/校验迁移:小面板升级为栏2列表 + 栏3命中详情。
6. 顶栏收敛:演绎从顶栏阶段移出或变成跳转左栏的快捷入口。
7. 全量回归:新四栏和旧三栏都走查。

## 13. 自检

- 无 TBD/TODO。
- 不与“左栏保留演绎/伏笔/母题/搜索/校验”的最新方向冲突。
- 明确解决“选择区章节多时沉底”的问题:选择区固定在栏2 sticky 顶部。
- 明确“项目”改为“手稿”,并定义手稿内卷/章/场景层级。

## 14. 代码落地规格

### 14.1 栏1入口节点契约

`EntryRail` 输出统一 entry 节点:

```js
{
  id: 'entry:manuscript',
  type: 'entry_capability',
  capability: 'manuscript',
  label: '手稿',
  source: tree.manuscript
}
```

内置能力:

| capability | 文案 | source | 栏2分发 |
|---|---|---|---|
| manuscript | 手稿 | `tree.manuscript` | 手稿 sticky 目录 |
| codex | 设定 | `tree.codex` | 设定分类/条目 |
| materials | 素材 | `tree.materials` | 素材类型/条目 |
| deduce | 演绎 | 当前章 `curSeq` | 演绎目录 |
| promise | 伏笔 | 当前章 `curSeq` + ledger | 伏笔目录 |
| motif | 母题 | 当前章 `curSeq` + motif list | 母题目录 |
| search | 搜索 | recall API | 搜索目录 |
| review | 校验 | qc API | 校验目录 |

兼容规则:

- 原 `manuscript_root`、`codex_category`、`material_root` 节点仍可作为栏2/栏3条目使用。
- `EntryRail` 不再直接展示设定分类为一级入口;设定分类下沉到栏2,避免栏1过长。
- 旧三栏 `LeftDock` 不删除,flag 关闭时继续保留原能力。

### 14.2 栏2组件拆分

`DirectoryPane` 作为薄分发器,不承载大段业务逻辑。新增以下局部组件或同目录文件:

| 组件 | 责任 |
|---|---|
| `DirectoryHeader` | sticky 顶区:标题、当前定位、快速操作、过滤 chip |
| `ManuscriptDirectory` | 书级工具 + 卷/章/场景目录 |
| `CodexDirectory` | 设定分类与条目列表 |
| `MaterialDirectory` | 复用 `MaterialList` 或包装其顶部筛选 |
| `DeduceDirectory` | 场景真相、角色限知、冲突误判 |
| `PromiseDirectory` | 本章要收、本章新埋、超期、仍悬、已回收 |
| `MotifDirectory` | 本章触及、本卷主母题、全书母题、证据不足 |
| `RecallDirectory` | sticky 搜索框 + 结果列表 |
| `ReviewDirectory` | 校验类型 + 命中列表 |

`DirectoryPane` props 扩展为:

```ts
type DirectoryPaneProps = {
  entry: EntryNode | null
  sel?: SelectionState
  tree?: ProjectTree
  seq?: number | null
  onSelectItem?: (node: DirectoryItem) => void
  onJumpChapter?: (seq: number) => void
}
```

### 14.3 手稿卷章派生规则

从 `tree.manuscript.children` 派生目录:

- `volume` 节点作为卷。
- `chapter` 节点作为章。
- `scene` 节点作为章内子项。
- 若章不在卷内,归入“未归卷章节”。
- 若没有 volume,显示单一“章节”分组。
- 当前选中章来自 `sel.node.ref` 或 `seq`。

卷章目录必须支持:

- 当前章高亮。
- 点击章调用 `onSelectItem({ id:'ch:<seq>', type:'chapter', ref:seq, label, phase:'outline' })`。
- 点击场景调用 `onSelectItem({ id:'scene:<seq>:<idx>', type:'scene', ref:{ seq, idx }, label })`。
- sticky 顶区中的上一章/下一章调用相邻章。

### 14.4 能力详情节点

为 `DetailPane` 增加能力详情节点:

| node.type | 栏3组件 |
|---|---|

### 14.5 顶栏演绎归位

`ChapterStudio` 顶栏阶段条中移除 `deduce`。如果保留快捷按钮,其行为必须是:

```js
window.dispatchEvent(new CustomEvent('s3-open-capability', {
  detail: { capability: 'deduce', seq }
}))
```

本期推荐直接移除顶栏 `演绎`,让左栏成为唯一主入口。
