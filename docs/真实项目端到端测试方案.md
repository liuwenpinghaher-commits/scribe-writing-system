# 真实项目端到端测试方案 · 乱世铜炉

> 目标：用真实业务流程验证 scribe3 系统的设定库→推演台→写作台全链路，达到与原文同等质量

---

## 一、总体架构

```
阶段1：通读原文 → 提取设定数据 → 填充设定库（与主编对话）
  ↓ 验证：设定完整度≥90，与原文一致性100%
阶段2：推演台设计10章（事件/知识帧/伏笔/弧光）
  ↓ 验证：每章事件链完整，限知帧正确，伏笔状态机闭环
阶段3：写作台生成10章（每章≥6000字，与主编对话驱动）
  ↓ 验证：质量对比原文（风格/密度/一致性/OOC）
阶段4：问题修复 + 回归验证
```

---

## 二、阶段1：通读原文 + 设定填充

### 2.1 通读范围
- 原文：引子 ~ 第10章（约10万字，4184行中的前1500行）
- 提取维度：角色/地点/势力/世界规则/物品/术语/事件/关系/伏笔/弧光

### 2.2 提取清单（逐项对照原文）

| 维度 | 预期数量 | 提取字段 | 原文依据 |
|------|---------|---------|---------|
| 角色 | 15-20个 | 名字/重要度/外貌/性格/前史/能力/弱点/动机/恐惧 | 引子~第10章出场人物 |
| 地点 | 8-10个 | 名字/描述/地理/标志物 | 三水村/梧桐村/奈何谷/碧玉潭等 |
| 势力 | 5-8个 | 名字/意识形态/领袖/成员/公开面目/私下运作 | 严台山/青叶门/乌家/六连山等 |
| 世界规则 | 6-8条 | 名字/源头/能力/代价/限制/例外 | 灵龙镇煞钉/牛泪水/犯查/定神符等 |
| 物品 | 8-10件 | 名字/类别/描述/状态/持有者/特殊属性 | 镇煞钉/炼真经/天周盘/竹笛等 |
| 术语 | 10-15条 | 名字/类别/定义/别名 | 寒妇/犯查/还丹/画井为狱等 |
| 事件 | 15-20个 | 类型/章/参与者/效果/因果/目标 | 每章关键事件 |
| 角色关系 | 10-15条 | 源/目标/关系类型/起止章 | 师徒/盟友/敌对/夫妻等 |
| 伏笔 | 5-8条 | 内容/埋设章/状态 | 原文已埋伏笔 |
| 弧光 | 8-12条 | 角色/章/类型/摘要/前后状态/触发事件 | 角色质变点 |

### 2.3 执行方式
1. 逐章阅读原文（每次读500行）
2. 用主编对话(`/chat/stream`)讨论提取的设定：
   - "根据第1章内容，帮我整理梧桐村的设定"
   - "胡不为的性格标签应该是什么？"
   - "这个世界还缺什么规则？"
3. 通过REST API写入设定库
4. 每写完一个维度，用`/setting-completeness`验证

### 2.4 验证标准
- [ ] 设定完整度 ≥ 90分
- [ ] 角色数 ≥ 15，每个有外貌+性格+前史+动机
- [ ] 世界规则 ≥ 6条，每条有源头+代价+限制
- [ ] 事件覆盖引子~第10章全部关键情节
- [ ] 角色关系图连通（无孤立节点）
- [ ] 弧光时间线覆盖主要角色质变点
- [ ] 与原文交叉验证：随机抽10条设定，人工核对原文

## 三、阶段2：推演台设计

### 3.1 设计目标
基于已填充的设定，设计10章的fabula（事件层），包括：
- 每章2-4个事件（含参与者和效果）
- 每章选1个focalizer，设计知识帧
- 埋设3-5条伏笔
- 记录角色弧光质变点

### 3.2 执行方式
1. 用主编对话讨论章节大纲：
   - "基于现有设定，设计第1章的事件链"
   - "这章用谁的视角？他知道什么？"
2. 通过API写入事件/伏笔/弧光
3. 用推演台验证限知帧正确性

### 3.3 验证标准
- [ ] 10章事件全部落库，每章有focalizer
- [ ] 知识帧正确：focalizer不知道的私密不在帧中
- [ ] 伏笔状态机：埋设→触发→回收，有章号追踪
- [ ] 弧光：每个主角至少2个质变点
- [ ] 因果链完整：`causal_complete`无断裂

---

## 四、阶段3：写作台生成

### 4.1 生成目标
- 10章正文，每章 ≥ 6000字
- 通过与主编对话驱动写作（"写第1章，视角是胡不为"）
- 每章走完整写作环：浸泡→渲染→QC→存稿→ingest

### 4.2 执行方式
1. 主编对话触发写作：`/chat/write` SSE流
2. 渲染使用限知帧（只喂focalizer知道的事实）
3. 存稿后跑QC（复读/排比/升华）+ find_leaks
4. ingest回写知识账本
5. 下一章渲染反映新知

### 4.3 质量对比维度

| 维度 | 原文指标 | 生成目标 | 对比方法 |
|------|---------|---------|---------|
| 字数 | 均约3000-5000字/章 | ≥6000字/章 | 字数统计 |
| 环境描写密度 | ~1.0‰ | ≥0.8‰ | 关键词频率/千字 |
| 身体动作密度 | ~1.2‰ | ≥1.0‰ | 关键词频率/千字 |
| 心理活动密度 | ~0.6‰ | ≥0.5‰ | 关键词频率/千字 |
| 感官描写密度 | ~2.2‰ | ≥1.5‰ | 关键词频率/千字 |
| 句长 | ~25字/句 | 20-30字/句 | 句子统计 |
| 限知正确性 | N/A | 0泄露 | find_leaks=0 |
| OOC违规 | N/A | ≤1/章 | check_ooc |
| 设定一致性 | N/A | 0冲突 | validate_setting |

### 4.4 验证标准
- [ ] 10章全部生成，总字数 ≥ 60000字
- [ ] find_leaks = 0（无限知泄露）
- [ ] OOC ≤ 3处/全书
- [ ] validate_setting 无high级冲突
- [ ] 风格5维度对比达标
- [ ] 人工抽读3章，与原文风格主观对比

## 五、阶段4：问题修复 + 回归验证

### 5.1 预期问题类型
- LLM生成质量不达标 → 调整prompt/soak
- 设定不一致 → 修正设定库
- 限知泄露 → 检查知识帧/ingest
- API报错 → 修复后端bug
- 前端交互问题 → 修复UI

### 5.2 修复流程
1. 发现问题 → 记录问题描述+复现步骤
2. 修复代码/设定 → 验证修复
3. 回归测试 → 确认无新问题
4. 继续下一环节
